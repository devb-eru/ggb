# GGB 공개 데모 정의

## 1. 기준선

| 필드 | 값 |
| --- | --- |
| 상태 | ACCEPTED_WITH_PLAYTEST_GATE |
| 목표 마일스톤 | `M2_DEMO_COMPLETE` |
| 잠정 콘텐츠 락 | 2026-11-20 |
| 공개 수준 | Steam Next Fest와 일반 사용자에게 공개 가능한 품질 |
| `build_flavor` | `demo` |
| 플레이 가능 종료점 | D4 완료 |
| 종료 에필로그 | D5 `demo_stinger` 프레젠테이션, 약 60~90초 |
| 마지막 콘텐츠 경계 | `SAVE_D5_COMPLETE` |
| 예상 플레이 시간 | `DEMO_COMPACT` 60~100분과 `DEMO_EXTENDED` 130~210분 비교 후 확정 |

공통 제품 약속은 [제품 계약](product_contract.md)을 따른다. 데모 공개 범위와 종료 방식은 [GGB-DEC-2026-0004](decisions/GGB-DEC-2026-0004_Next_Fest_데모_공개_범위.md), [GGB-DEC-2026-0009](decisions/GGB-DEC-2026-0009_데모_종료와_저장_승계.md)을 함께 적용한다.

예상 시간은 외부 약속이 아니다. 버티컬 슬라이스와 1장 알파에서 두 편집안을 비교하고 완주율, 반복 피로, D5 도달률과 구매·찜하기 의향으로 최종 범위를 결정한다.

## 2. 콘텐츠 경계

```text
P1
→ A~C 정상 리셋과 영구 정보
→ D0~D4 플레이
→ D5 위장 필터 해제 스팅어
→ SAVE_D5_COMPLETE
→ 데모 종료 화면
```

- D5 스팅어는 본편 D5와 같은 `D5_COMPLETION`을 쓰되 `presentation_variant=demo_stinger`로 핵심 박리 장면만 60~90초 재생한다. 이동, 퍼즐, 관계 선택과 E1 조사는 없다.
- D5는 데모 플레이타임에서 3장으로 계산하지 않는다.
- `SAVE_D5_COMPLETE`를 데모에서 불러오면 `DEMO_END_SCREEN`으로만 재개한다. 데모 종료 화면은 기본 게임 상점, 찜하기와 피드백 동선을 제공한다.
- 데모 registry는 E1 이후 사건, F구간과 엔딩을 실행할 수 없다.
- 데이터가 빌드에 포함되더라도 허용 event set 밖의 진입은 차단하고 검증 오류를 남긴다.

## 3. 지원 범위

| 항목 | 필수 기준 |
| --- | --- |
| OS | Windows 10/11 64-bit |
| 언어 | `ko-KR`, `en-US` |
| 기준 해상도 | 1920x1080 가로형 |
| 최소 레이아웃 | 1280x720 |
| 확대·DPI | 2560x1440, 3840x2160, Windows 100~200% |
| 화면 모드 | 테두리 없는 창, 창 모드, 전체 화면 |
| 입력 | 마우스 전용·키보드 전용 필수 경로 |
| UI·텍스트 배율 | UI 90~220%, 텍스트 100~200% |
| 음성 | 없음 |
| 필수 접근성 | 재지정 입력, 대화 기록, 다중 감각 단서, 모션·글리치 완화, 포커스 복원 |
| 임시 아트·사운드 | 노출 필수 에셋의 20% 이하 |

게임패드, 터치와 콘솔은 데모 지원 범위가 아니다. 색상, 소리 또는 모션 하나만으로 필수 정답을 전달하지 않는다.

임시 리소스 비율은 공개 데모에서 실제로 노출되는 필수 에셋 manifest를 기준으로 계산한다. 행 개수가 아니라 [에셋 manifest](asset_manifest.md)의 `unit_count`를 사용한다.

```text
임시 리소스 비율
= sum(unit_count where is_placeholder=true)
  / sum(unit_count for eligible rows)
  x 100

eligible rows:
  build_scope = demo_full
  required = true
  status != CUT
```

사용되지 않는 파일, 개발 도구용 파일, 중복 원본은 분모에서 제외한다. 한 행이 표정·상태 여러 개를 묶으면 실제 검토 단위 수를 `unit_count`에 반영한다. 각 에셋에는 `asset_id`, 사용 사건·공간, 임시 여부, 담당자, 검토자와 교체 목표일이 있어야 한다.

## 4. 저장·재개

### 4.1 데모 내부

- 진행 슬롯 3개와 슬롯별 자동 저장·백업을 제공한다.
- P6, 각 정상 리셋 완료, A2, J1, J2, J3, D4와 D5 완료 지점에서 저장한다.
- 퍼즐 조작 중 임의 저장은 제공하지 않고 검증된 단계와 안전 재개점만 기록한다.
- 대화 기록은 NORMAL_RESET과 저장·불러오기 뒤에도 유지한다.
- 저장 중 종료 요청은 커밋 완료 또는 롤백 뒤 처리한다.

초기 저장 지점과 사용자 동작은 [제품 계약](product_contract.md#7-저장재개-사용자-계약), 직렬화 상세는 [데이터 계약](data_contract.md)을 따른다.

### 4.2 저장 헤더

데모 저장은 최소 다음 호환 정보를 가진다.

```yaml
schema_version: 1
design_revision: "v0.4-state-r12"
game_version: "0.0.0-dev"
build_id: ""
build_flavor: "demo"
content_revision: ""
content_boundary_id: ""
source_app_id: ""
```

기획 문서 버전과 런타임 저장 버전을 같은 필드로 사용하지 않는다.

### 4.3 정식판 승계

- 정식판은 데모 저장을 자동으로 덮어쓰지 않는다.
- 읽기 전용 검사 뒤 슬롯, 플레이 시간, 언어와 콘텐츠 경계를 미리 보여 준다.
- 호환 가능한 저장만 새 슬롯 또는 사용자가 승인한 슬롯으로 가져온다.
- migration과 재로드 검증이 끝나기 전 원본 데모 저장을 삭제하지 않는다.
- 미지원 저장은 이유, 보존 위치와 새 게임 선택지를 표시한다.
- Steam Cloud 공유 여부는 AppID 생성 뒤 실기 검증 전까지 미확정으로 둔다.
- 승인된 가져오기가 끝난 본편 슬롯에서만 `SAVE_D5_COMPLETE`의 재개 목적지를 `D6_FREE_INSPECTION`으로 변환한다. 데모 원본은 계속 `DEMO_END_SCREEN`을 가리킨다.

## 5. Steam 공개 방식

별도 데모 상점 페이지를 만들지 않고 기본 게임 Coming Soon 페이지의 데모 버튼을 사용한다. Steam 데모는 기본 게임과 연결된 별도 AppID·depot·빌드로 운영한다.

```text
기본 게임 AppID / Coming Soon 상점
└─ 데모 AppID / build_flavor=demo / boundary=SAVE_D5_COMPLETE
```

Next Fest에서도 같은 범위를 유지한다. 기본 게임은 출시 후보 품질을 목표로 하지만 전편 콘텐츠를 데모 AppID에서 공개하지 않는다.

## 6. 완료 조건

### 콘텐츠·기능

- [ ] 새 게임에서 D4 완료까지 필수 경로를 진행하고 D5 스팅어 뒤 종료 화면에 도달한다.
- [ ] E1 이후 사건과 엔딩이 데모에서 실행되지 않는다.
- [ ] 선택된 플레이타임 편집안의 계측 근거가 있다.
- [ ] 실패, 영구 정보와 숏컷이 같은 반복 노동으로 느껴지지 않는다.
- [ ] 노출 필수 에셋 기준 임시 리소스 비율이 20% 이하다.

### 플랫폼·접근성

- [ ] Windows 10/11 64-bit에서 설치, 실행, 저장, 불러오기와 종료가 정상 동작한다.
- [ ] 마우스만으로 필수 경로를 완주한다.
- [ ] 키보드만으로 필수 경로를 완주한다.
- [ ] 1280x720과 UI·텍스트 200%에서 필수 UI가 잘리지 않는다.
- [ ] 색 제거, 음량 0, 모션 감소를 동시에 사용해도 필수 진행이 가능하다.
- [ ] 음성 없이 모든 정보가 전달된다.

### 언어·저장

- [ ] 한국어와 영어에서 진행 조건, 선택 결과와 UI가 동일하게 동작한다.
- [ ] 확인한 대사와 선택지를 현재 언어의 대화 기록에서 다시 읽을 수 있다.
- [ ] 초기 안전 지점, 정상 리셋, HARD FAILURE와 D5 종료 저장을 복구한다.
- [ ] 데모 저장 가져오기 성공·거절·손상·슬롯 충돌 경로를 검사한다.
- [ ] `P0`, `P1` 문제가 없고 알려진 `P2`는 영향과 우회 방법이 기록된다.
