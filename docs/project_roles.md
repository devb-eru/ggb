## 2. 가용시간과 계획 용량

주 7일·56시간을 공통 가용시간으로 가정하지 않는다. 한 사람이 여러 역할을 맡아도 시간은 역할별로 누적하지 않고 하나의 개인 용량으로 계산한다.

- 개인별 실제 가용시간은 해당 주 시작 전 확인된 값만 사용한다.
- 공개 저장소에는 개인 사정이나 세부 근무시간을 기록하지 않고 GitHub Project에 주간 `capacity`와 기간만 기록한다.
- 확인되지 않은 주말 작업과 초과 근무는 계획 용량에 넣지 않는다.
- 각 개인의 확인된 가용시간 중 최대 70%만 신규 제작에 배정한다.
- 나머지 30%는 회의·검토·수정·차단 대응·휴식에 둔다.
- 최소 주 1일은 작업 배정을 전제로 하지 않는 날로 유지한다.
- 2주 연속 실제 투입이 확인 용량의 90%를 넘으면 다음 주 신규 배정을 줄이고 마일스톤을 재산정한다.

현재 개인별 확정 가용시간은 저장소에서 검증되지 않았다. 따라서 [마일스톤](milestones.md)의 제작 날짜는 `PROD_01_VERTICAL_SLICE` 완료와 실제 capacity 입력 전까지 `PROVISIONAL`이다.

## 3. 의사결정과 검토

- 프로젝트 관리자: `beru`
- 영역 내 1차 판단: 해당 팀장
- 여러 영역에 영향을 주는 결정: 해당 팀장들과 협의 후 `beru` 승인
- 별도 검토자가 있으면 작업 담당자와 검토자를 분리한다.
- 인력상 분리가 어렵다면 자기 검토를 허용하되 체크리스트와 QA 근거를 남긴다.
- Steam 제출 빌드와 외부 공개 빌드는 가능하면 작업 담당자 외 한 명이 재검증한다.

개인 이메일과 Discord 계정은 공개 저장소에 직접 기록하지 않고 비공개 운영 설정이나 외부 협업 도구에서 관리한다.

### 4.1 GitHub 대리 반영

`gatam`, `210`, `nana`, `NOne`이 Discord로 전달한 결과물은 `beru`(`devb-eru`)가 저장소에 반영한다.

- 작업 항목이나 PR 설명에 실제 제작자, Discord 전달 메시지와 전달일을 기록한다.
- 커밋 작성자가 `beru`여도 제작자를 `contributor: 이름`으로 남긴다.
- `beru`는 파일 출처, 사용 권리, 대상 작업 ID와 기본 동작 여부를 확인한 뒤 반영한다.
- 내부 제작물은 [기여자 권리 증거 기준](contributor_rights.md)의 비공개 서명 참조가 확인되기 전 배포 승인하지 않는다.
- 수정 요청과 승인 결과는 원 작업 항목에 연결한다.
- Discord만 원본 보관소로 사용하지 않는다. 수신한 원본은 Git/LFS 또는 별도 백업 위치에 보존한다.

- 참여자가 필요하면 팀장이 구성원에게 세부 작업을 나누되, 이슈의 최종 책임자는 한 명만 유지한다.
