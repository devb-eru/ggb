# 전편 연속 캠페인 회귀 검증

최종 갱신: 2026-09-19
실행 인자: `--full-campaign-smoke`

## 목적

개별 장면용 상태 fixture를 이어 붙이는 대신, 새 게임 상태에서 생성한 한 저장 슬롯을 프롤로그부터 E_HUB까지 계속 사용한다. 그 시점의 수정하지 않은 저장 상태를 LOW·MID·HIGH·ALL 네 독립 슬롯으로 분기하고, 각 슬롯에서 지정된 관계 사건을 실제 세션 행동으로 해결한 뒤 F3까지 진행한다. 각 경로는 F3가 제품 규칙에 따라 보존한 재선택 원본으로 별도 사본을 만들고 현실·잔류 엔딩을 각각 완료한다.

이 검사의 핵심 질문은 다음과 같다.

1. 앞 장의 실제 저장 위치와 영구 정보가 다음 장의 진입 조건으로 이어지는가.
2. 정상 리셋과 최초 파열 리셋이 각각 의도한 물리 상태만 폐기하는가.
3. 관계 사건 완료 수 0명·2명·4명·5명이 각각 LOW·MID·HIGH·ALL로 결산되며 어느 경로도 F0·F3·두 엔딩을 차단하지 않는가.
4. F0-E의 임시 의도를 `undecided`로 남겨도 마지막 선택 두 개가 모두 같은 권한으로 열리는가.
5. 크레딧 완료와 `SAVE_ENDING_COMPLETE`가 현실 원본 슬롯과 잔류 재선택 슬롯에 각각 남는가.

## 연속 경로

| 구간 | 실제 진행과 저장 검증 |
| --- | --- |
| P1~P6 | 침실 조사, P2 창문, P3 서재, P3B 초상화, P4 차·기억 닻, P5 날씨 모순을 완료하고 첫 수면으로 정상 리셋한다. |
| A1~J2 | 자기 표식을 남기고 수면 뒤 확인한다. B3에서 물리 잠금을 한 번 발생시키고 수면·BSHORT 뒤 정답 위상으로 재시도한다. J2 저장 뒤 서재 내실 위치를 재불러온다. |
| C0~J3 | 서재에서 침실까지 직접 돌아가 수면한다. C4 코팅 경화를 한 번 발생시키고 수면·CSHORT 뒤 세정제를 다시 제조한다. C5 사본을 수면 너머로 보존해 다섯 채널과 J3를 완료한다. |
| D0~D6 | J3 위치에서 침실로 돌아가 수면한다. D1 축 잠금을 한 번 발생시키고 수면·DSHORT 뒤 지하창고를 연다. 태엽 심장과 보조 입력으로 D5를 완료하고 파열 전용 이동·휴식으로 최초 BROKEN_RESET을 실행한다. |
| E1~E2 | 달라진 침실 세 곳을 확인하고 루카 도입과 에드가 보고를 거친다. 관계 보상을 받지 않은 실제 E_HUB 저장을 네 경로의 공통 분기점으로 사용한다. |
| E3~E6 | LOW는 관계 사건을 건너뛴다. MID는 마라 1·루카, HIGH는 마라 1·이리스·루카·에드가, ALL은 다섯 사용인의 관계 퍼즐과 대면 선택을 실제 행동으로 완료한다. J4 BASE/EXPANDED/FULL, 에드가 최소 절차의 조건부 발생, E5 LOW/MID/HIGH/ALL, 마라 2·에드가 후속과 E6를 검증한다. |
| F0~F3 | 방 회로, 시스템 표본, B4·C5·D4 중첩, 기록 역할, A1 자기 표식 인증을 순서대로 해결한다. 임시 의도는 `undecided`이고 최종 결정은 계속 `unset`이다. 아버지 기록, J5, 연구원 대면과 양쪽 장치 조사를 마친다. |
| 두 엔딩 | 네 티어의 원본 슬롯에서 현실 엔딩·현장 수첩·지표·크레딧을 완료한다. 각 F3 보존본으로 만든 독립 사본에서 잔류 원칙·외형·자율성·마지막 저녁·크레딧을 완료한다. ALL은 두 분기 모두 다섯 이름·SUBJECT 권한·서명 인증을 추가로 통과한다. |

## 상태 주입 금지선

- 시작 시 `GameState.reset_for_test()`만 사용한다.
- 프롤로그 이후 어떤 챕터에도 `StateWriter.install_snapshot()`으로 진행 상태를 주입하지 않는다.
- 관계 분기는 실제 E_HUB 스냅숏을 `SaveManager.save_snapshot()`으로 새 슬롯에 그대로 저장한다. 관계 플래그·기록·수치·위치를 변경해서 티어를 만들지 않는다.
- P2~P5는 제품 `PrologueController`의 통합 시나리오 도우미를 사용하며 각 상호작용이 일반 저장을 수행한다.
- A1 이후는 `ChapterOneSession`, `BlackMirrorSession`, `BasementSession`의 공개 진행 행동과 `SaveManager`·`LoadCoordinator`만 사용한다.
- J2, J3, D5, E_HUB, 각 관계 경로, J4, F0, F1 중간, F3, 각 엔딩 완료에서 디스크 저장을 다시 불러온다.
- 두 번째 엔딩은 임의 복제가 아니라 제품의 `capture_f3_reselect`·`create_f3_reselect_slot` 경로를 사용한다.
- 엔딩 감상 프로필은 `user://__test_full_campaign_meta_*`에 격리하고 종료 시 제거한다.

## 검증 명령

```powershell
godot --path game -- --full-campaign-smoke
```

격리 검증 환경에서는 다음과 같이 실행한다.

```powershell
& .tmp-full-game-development/validate_chapter.ps1 -Mode full-campaign
```

성공 표식은 `FULL_CAMPAIGN_SMOKE: PASS`다. 2026-09-19 기준 Godot 4.7.2 Windows 헤드리스에서 네 관계 경로와 엔딩 8개가 통과했다. 같은 변경으로 `BASEMENT_SESSION_SMOKE`도 통과했다. 루트 인증서 저장소 경고 외 `SCRIPT ERROR`는 없었다.

## 이 검사가 입증하지 않는 것

- 운영체제가 전달한 실제 마우스 입력만으로 전편을 완주했다는 뜻이 아니다.
- 운영체제가 전달한 실제 키보드 입력만으로 전편을 완주했다는 뜻이 아니다.
- 관계 사건의 모든 결과 선택·bond/alert 경계 조합을 연속 완주했다는 뜻은 아니다. 두 결과와 경계 조합은 기능별 `BASEMENT_SESSION_SMOKE`가 담당한다.
- 최종 아트, BGM, 효과음, 카메라, 현지화 편집, 목표 플레이타임과 퍼즐 체감 난이도의 완료 증거가 아니다.
- 현실과 잔류를 한 슬롯에 동시에 덮어쓴 것이 아니다. 원본 캠페인과 제품이 만든 F3 재선택 사본을 각각 보존하는 계약을 검증한다.

## 후속 제품 게이트

1. 실제 마우스 전용 필수 경로를 새 슬롯으로 완주한다.
2. 실제 키보드 전용 필수 경로를 새 슬롯으로 완주한다.
3. 각 입력 경로에서 장면별 체류 시간, 실패 횟수, 힌트 사용, 포커스 이탈과 저장 복구를 기록한다.
