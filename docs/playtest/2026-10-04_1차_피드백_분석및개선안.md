- 현재 저장소에는 후기 이후일 수 있는 거울 경로 시각화와 통합 수첩 개발 변경이 있다. 기능 존재, 기본 실행 활성화, 실제 사용성 개선은 서로 다른 판정이다.

## 2. 핵심 판단

**먼저 낮춰야 할 것은 추론의 깊이가 아니라, 무엇을 보고 무엇을 판단해야 하는지 알 수 없는 부담이다.**

후기의 반복되는 문제는 다음 네 가지다.

1. **증거가 충분히 보이지 않는다.** 눌림선·홈·투명지라는 물리 단서를 요구하지만 실제 화면은 문장과 방향 버튼 중심이다.
2. **서로 다른 규칙이 섞여 읽힌다.** 종이의 위쪽 홈, 시계의 XII 뒤 홈, 신호의 +1 시점을 같은 종류의 단서로 해석한다.
3. **행동 목적이 결과보다 늦게 전달된다.** 무엇을 누를지는 알지만 왜 시계망을 작동해야 하는지, 일지와 연결되는지를 이해하기 어렵다.
4. **입력과 서술의 신뢰가 흔들린다.** 밤에도 낮 문구가 나오고, 읽는 중 눌리는 버튼과 메뉴의 반응이 일관되지 않는다. 의도된 이상 현상까지 구현 오류처럼 보일 수 있다.

따라서 권장 순서는 `입력·문구 신뢰 복구 → 재료 식별과 기능성 도식 → 행동 동기·결과 연결 → 사람 대상 난도 재측정`이다. 장문 설명 추가나 일괄 난도 하향부터 시작하지 않는다.

### 유지할 장점

- B3-A의 네 위치 분류는 이해 가능했다. 역할 분류 자체를 없앨 근거가 없다.
- C3 세정제는 적정 난도이고 풀이가 명확하다고 평가됐다. **5:1:2와 투입·혼합 절차는 유지**한다.
- C4 경로 조작 자체는 괜찮다고 평가됐다. 핵심은 순서를 고른 이유를 읽게 하는 것이다.
- J1은 총시도로 통과할 수 있었다. 이 문제를 해결하기 위해 조각 수나 오답 페널티를 늘리지 않는다.
- 수면에 의한 물리 리셋, 영구 정보, 숏컷, 관계 비차단, 두 엔딩의 중립성과 `24-3`의 메타퍼즐 연결은 보존한다.

## 4. 입력과 화면 신뢰부터 복구

### 4.1 FB01: 대사 중에도 메뉴의 의미는 바뀌지 않아야 한다

확인 근거: [프롤로그 컨트롤러](../../game/scripts/prologue/prologue_controller.gd)의 `_open_menu()`, `_unhandled_input()`과 [1장 컨트롤러](../../game/scripts/chapters/chapter_one_controller.gd)의 `_open_menu()`.

현재는 대사·선택 중 메뉴가 열리지 않고, 대사 중 `ui_cancel`이 `_advance_dialogue()`를 호출한다. 사용자가 누른 키가 무엇인지는 미상이지만, 메뉴로 기대한 입력이 대사를 넘길 수 있는 구조는 확인된다. [메타 UI의 일시정지 계약](../meta_ui_flow.md)과도 대조해야 한다.

권장 수정:

1. 일반 대사 중 메뉴 버튼 또는 메뉴 키는 일시정지 메뉴를 연다. 대사 진행은 전용 확인 입력으로 남긴다.
2. 메뉴를 열 때 문장 위치·스크롤·선택지·포커스를 보존한다. 단순 열람·닫기로 문장을 소비하거나 선택을 확정하지 않는다.
3. 최상위 팝업 안의 Esc는 그 팝업만 닫는다. 선택 중 Esc를 `선택 취소`로 유지해야 하는 장면은 화면 메뉴 버튼과 명시적 도움말을 제공한다. 같은 입력이 아래 대사까지 전파되면 안 된다.
4. 저장 확정 중에도 메뉴 표시 자체는 허용하되, 로드·종료 같은 파괴적 이동만 커밋/롤백 후 실행한다. 긴 무반응으로 대체하지 않는다.
5. 기존 통합 수첩의 대사 중단·복귀와 본편 커서를 재사용한다. 검토 중 추가된 `a00ef59`는 v2 저장의 프롤로그 P1~R1 대사, P3/P4 질문, 출발·취침 확인의 재시작 복원을 구현했다. 이를 다시 만들지 않는다. 구형 저장, 본편 선택 모달·별도 조사 본문, 실제 메뉴 입력을 통한 복귀는 별도 범위로 검사한다. 커서 구현만으로 대사 중 메뉴 차단이 해소되지는 않는다.

인수: 대사 중 메뉴를 열고 닫은 전후 문장·선택·게임 상태가 같다. 마우스와 키보드 모두 메뉴에 접근할 수 있다. 타이틀 이동·재시작의 실제 저장 위치를 정확히 안내하고, 대사/효과/보상이 중복 실행되지 않는다.

### 4.2 FB06: 읽는 중 배경 버튼이 반쯤 작동하지 않게 한다

확인 근거: `B1_BOARD`는 `_open_schedule_board()`를 직접 호출하고, 그 함수는 대사 여부 확인 없이 `_show_recorded_choice()`에 진입한다. 반면 실제 `_do()`는 `_interaction_blocked()`에서 대사 중 실행을 막는다. 일반 대화 레이어 전체는 `MOUSE_FILTER_IGNORE`이며, 화면 전체 차단기는 선택 대사용으로 별도 존재한다.

따라서 **창은 열리지만 선택 결과는 실행되지 않는 경로가 정적으로 가능**하다. 현재 입력 방식별 재현은 아직 하지 않았으므로 저장 변경이나 기록 손상까지 확정하지 않는다.

- 대사·조사 문서를 읽는 동안 월드 버튼과 퍼즐 입력을 비활성화한다. 메뉴·수첩처럼 허용한 중단 UI만 예외다.
- `_open_schedule_board()`를 포함한 직접 창 열기 경로에도 공통 입력 소유권 검사를 적용한다. 실제 상태 변경 함수의 가드는 그대로 유지한다.
- 클릭 차단만으로 끝내지 않고 Tab·Enter·단축키·드래그 해제도 검사한다.
- 문서 읽기 중에는 연결 버튼을 회색 상태와 `문서를 닫은 뒤 비교`처럼 이유가 보이는 상태로 둔다. 유효한 클릭처럼 눌렸다 돌아오는 효과를 주지 않는다.
- 문서를 닫으면 같은 연결 버튼으로 포커스를 돌려준다. 눌리지 않는 상태를 무기한 남기지 않는다.

인수: 에드가/루카/마라 문서를 읽는 중 연결 버튼을 입력해도 모달·퍼즐 상태·선택 기록이 변하지 않는다. 문서를 닫은 뒤에는 정상적으로 한 번 실행된다.

### 4.3 FB03: 밤의 빛을 의도된 모순으로 읽게 한다

현재 `_inspect_bedroom()`은 P4 완료 후 `P6_INSPECT_WINDOW`를 선택한다. 하지만 [프롤로그 콘텐츠 생성기](../../game/scripts/tools/seed_notebook_prologue_v1.gd)는 `NB_PR_P6_INSPECT_WINDOW`의 `source_text_id`를 `P1_INSPECT_WINDOW`로 연결한다. [현재 생성 데이터](../../game/data/notebook/prologue_v1.json)에도 낮의 정원·햇빛 문구가 그대로 있다. 함수 이름만 밤으로 나누어서는 해결되지 않는다.

권장: P5의 날씨 모순과 저녁의 고정된 바깥빛은 유지하되, 주인공이 시간 차이를 인식하는 별도 관찰을 쓴다.

> 관찰: 복도 등은 저녁빛인데, 창밖의 정원은 아침처럼 밝다. 가지 끝의 새도 같은 높이에 걸려 있다.
>
> 주인공의 생각: 아까 본 풍경과 너무 똑같아. 내가 오래 바라보지 않았던 걸까?

이 문장은 개작 예시다. 실제 밤 배경이 어둡게 제작되어 있다면 `이미지에서는 밤인데 문장만 낮`이라는 새 충돌을 만들지 말고, 바깥빛 정지 여부부터 연출 정본과 맞춘다. 이번 후기만으로 시뮬레이션 설명이나 큰 진실을 앞당기지 않는다.

인수: P1과 P6의 화면·문장·수첩 원고가 각 시점에 맞는다. 한·영 문구와 새 자료 버전을 함께 반영하고, 기존 기록 원문은 소급 변경하지 않는다.

## 5. 문장과 자료를 읽을 수 있게 정리

### 5.1 FB02: 연필 압흔은 관찰부터 설명한다

현재 문장인 `내가 쓰기 전부터 다음 장까지 이어져 있다`는 현재의 미작성 상태, 과거의 필기, 장 사이 압흔을 한꺼번에 압축한다. 이는 문법 해석에 대한 불확실성이지 반드시 의도된 심리적 불안은 아니다.

개작 예시:

> 관찰: 저택 그림 다음은 빈 페이지다. 글씨는 없는데, 종이를 비스듬히 기울이자 눌린 선이 드러난다. 한 장을 더 넘겨도 같은 자국이 남아 있다.
>
> 주인공의 생각: 여기에도 무언가 적었던가? 그림을 그린 기억은 나는데, 이 자국은 낯설어.

`미래의 내가 쓴 흔적`으로 확정하지 않는다. 조사 확대에서는 작은 사선 그림자·윤곽선과 `종이 눌림`이라는 비색상 단서를 제공한다. 이것이 J1 종이 단서를 읽는 첫 학습이 되게 한다.

### 5.2 FB04: 정정 대상은 대시계 점검 시간이라고 명시한다

확인 근거: [1장 세션의 DOCUMENTS](../../game/scripts/systems/chapter_one_session.gd)와 [1장 대사 카탈로그](../../game/data/dialogue/chapter_one/chapter_one_text.tres)의 `CH1_B1_TEXT_EDGAR`.

정답 시간창은 유지하면서 다음처럼 개작하는 것을 권장한다.

```text
업무 장부
아침 인사 뒤: 외부 서고 감독.
오후 차 회수 확인 뒤: 서쪽 대시계 점검.
점검 시간 정정: 오후 차 회수 직후부터 저녁 종 직전까지.
저녁 종이 울린 뒤: 기록 내실로 복귀, 장부 정리.
```

- `정정`은 바로 앞의 **대시계 점검 업무**에만 붙인다. 내실 복귀 행과 시각적으로 묶지 않는다.
- 루카의 전달 장소·서명 장소와 마라 1의 청소 종료 기록으로 같은 빈 시간창을 교차 확인한다. 장부 한 장에 `내실 비어 있음` 정답을 직접 써 주지 않는다.
- 주인공의 추론 예시: `이건 복귀 시간이 아니라 점검 시간의 정정이네. 루카가 잔을 가져간 곳도 대시계실이었어.` 이는 두 자료를 실제 확인한 뒤에만 제시한다.
- 유연한 시간제를 유지한다. 벽시계 실시간 카운트다운이나 놓치면 리셋하는 제한을 추가하지 않는다.
- 일반 일정과 B2의 비정기 방문을 구분한다. 예상된 공백 중 에드가가 돌아오는 것은 심리적 사건이며, 발각 시 대화 후 재합류하는 기존 비실패 규칙을 지킨다.

인수: 정답을 알려 주지 않고도 참가자가 `언제, 어디에, 어떤 업무로 없는가`와 `언제 내실로 돌아오는가`를 각각 설명한다.

### 5.3 FB05: 조사·생각·발화를 문장과 UI 모두에서 구분한다

현재 `_feedback()`은 화자가 없으면 `주인공`으로 처리한다. 문서 원문·객관적 상태·추론이 같은 인물 발화처럼 보일 수 있다. 색만 바꾸어 해결하지 않는다.

| 정보 종류 | 표시 제안 | 문체와 예시 | 주의점 |
| --- | --- | --- | --- |
| 눈앞의 관찰 | `관찰` / 오브젝트명 | `홈 안쪽에 흑연 가루가 남아 있다.` | 아직 확인하지 않은 사실은 쓰지 않음 |
| 내적 추론 | `주인공 · 생각` | `바늘은 멈췄는데, 떨림은 지나가네.` | 추측을 사실처럼 저장하지 않음 |
| 실제 발화 | 화자 이름·기존 초상화 | `“보고 싶은 책이 있으십니까?”` | 생각과 다른 인용 형식 |
| 문서·물건 원문 | 문서 제목·발견 장소 | `에드가 업무 장부 / 대시계 점검란` | 문서를 주인공이 말한 것으로 취급하지 않음 |
| 조작·저장 안내 | 별도 상태 영역 | `배치만 확인했습니다. 신호는 보내지 않았습니다.` | 세계관 속 독백과 섞지 않음 |

내부 표현 종류는 `observation / thought / spoken / document / system`처럼 명시하는 방향을 검토한다. 기존 저장 스키마에 바로 필드를 추가하라는 확정안은 아니다. 통합 수첩의 종류·원문 ID·표시 문맥과 연결하고, 이전 기록의 실제 발화 여부를 추측해 일괄 재분류하지 않는다.

## 6. J1~J3 자료 체계와 도식 보완

### 6.1 FB07: J1은 문장 총시도가 아니라 물리 단서를 배우는 자리다

현재 화면은 세 문장 조각, 앞/뒤, 순서 초기화·확인으로 구성된다. 판정은 `[0, 1, 2]` 및 앞면 여부다. 실패 문구는 눌림 자국을 말하지만 화면에 그 연속성을 비교할 도식이 부족하다.

권장 구성:

- 조각마다 문장과 별개로 `찢어진 가장자리`, `서로 이어지는 압흔`, `앞뒤 식별점`을 표시한다.
- 1번 말미와 2번 시작의 눌림선 연결을 실제로 대조할 수 있게 한다. 3번은 끝점·마침표 이후 빈칸을 유지한다.
- 앞뒤 뒤집기에 따라 잉크 번짐과 압흔의 관계가 변한다. 정답 면만 글자를 크게 하는 방식으로 대신하지 않는다.
- 확대·앞뒤·자리 교환은 클릭 및 키보드 버튼으로도 제공한다. 수첩에서는 관찰한 자료만 읽기 전용으로 비교한다.
- 오답은 `둘째 조각과 앞 조각의 눌림선이 어긋남` 같은 관찰로 돌려준다. 첫 검사부터 전체 순서나 다음 정답을 자동 배치하지 않는다.

인수: 참가자가 첫 두 조각의 순서를 설명할 수 있다. 세 조각의 6가지 순서와 8가지 앞뒤 조합을 검사해 도식과 판정이 충돌하지 않는다. J1에는 일일 잠금·강제 수면을 추가하지 않는다.

### 6.2 FB10: B5/J2는 그림이 문제 본체다

후기의 대상은 진행 순서상 B5/J2로 추정한다. 현재 `_build_inner()`의 J2 분기는 긴 홈·분기·문단을 텍스트로 설명하고 회전 방향만 표시한다. C4의 도식이 존재하더라도 J2 자료 대조를 대체하지 않는다.

권장 구성:

1. 바탕인 **일지 두 번째 페이지**와 위에 얹는 **열세 번째 종 파형 투명지**를 이름과 출처로 구분한다.
2. 긴 시작 홈, 두 갈래 눌림, 문단을 감싸는 잔향 윤곽을 직접 겹쳐 본다. 위쪽·아래쪽 기준표시는 회전 상태와 함께 움직인다.
3. 맞지 않는 곳은 실제 선의 어긋남으로 표현한다. 비교 결과는 어긋난 특징을 설명하되 완성된 배치를 대신 만들지 않는다.
4. 성공 후 `일지의 홈과 공명통에서 옮긴 파형이 같은 모양이었다`는 발견을 짧게 남긴다.

인수: 모든 지원 회전에서 화면의 맞음/어긋남과 세션 판정이 같다. 음소거·색 제거 상태로도 동일한 특징을 비교할 수 있다. 보이지 않은 문장이 수첩 비교만으로 먼저 해금되지 않는다.

### 6.3 FB13: J3의 탁본 명칭과 자료 정체부터 해결한다

현재 J3는 `C5 투명지를 빈 테두리에 놓고 세 기준점 비교`라고 지시하지만 결과·실패 설명에서는 `탁본`이라고 부른다. C5의 실제 동작은 드러난 거울 원도를 수첩으로 옮기는 것이다. 시계에서 흑연으로 뜬 탁본과 다른 자료다.

다음 명칭을 권장한다.

| 사건 | 플레이어용 고정 명칭 | 출처 / 무엇을 옮겼는가 | 용도 |
| --- | --- | --- | --- |
| J1 | 일지 압지 조각 | 기록 내실 책상 / 눌린 문장 | 문장·앞뒤 복원 |
| B3-A | 침실·대응접실·외부 서고·대시계의 **배선 탁본** | 각 시계 / 배선·나사·가장자리 | 시계 연결·역할 추론 |
| B4 | **열세 번째 종 파형 투명지** | 대시계 공명통 / 신호의 기록 | J2·C4·F0의 시간/형태 자료 |
| C5 | **거울 회로 투명지** | 검은 거울 아래 원도 / 회로·세 기준점 | J3·D0-A·F0의 공간 자료 |
| D0 | **저택 평면도** | 서재 책상 이중 바닥 / 저택 배치 | D0-A에서 C5와 대조 |

`탁본`은 처음 획득할 때 `종이를 대고 흑연으로 문질러 홈의 모양을 옮긴 것`이라고 동작으로 소개한다. B4는 단순 소리를 문지르는 것이 아니라 공명통에 남은 파형을 옮기는 절차임을 보여 준다. 이후 C5까지 탁본으로 통칭하지 않는다.

J3 수정안:

1. C5 완료 때 종이가 수첩에 들어가는 짧은 표시와 이름을 제공한다. 목표의 관련 자료 버튼은 실제로 획득한 `거울 회로 투명지`를 연다.
2. J3 화면에 빈 페이지 테두리와 그 투명지를 함께 표시한다. 현재 `j3_overlay`가 설정하는 열람 상태만으로 그림이 보였다고 간주하지 않는다.
3. 처음 놓은 방향에서는 세 기준점이 모두 맞지 않는 **모순 관찰**을 보여 준다. J3에서 정확한 좌우 반전·회전 해법까지 해결하지 않는다. 실제 공간 변환 퍼즐은 D0-A의 역할이다.
4. 네 문장 조각의 압흔·앞뒤 연결도 표시한다. `방향 불신 → 낮은 심장 → 기준점 셋 → 세 점으로 입구를 판별`이라는 의미 흐름은 보조 근거로 사용한다. 압흔을 언급하는 오답에는 화면상의 비교 지점이 있어야 한다.
5. 자료 설명과 복원 결과를 읽은 뒤 `이걸 집의 배치와 비교하려면 평면도가 필요해`라는 다음 의문으로 연결한다. D0의 도면 발견을 미리 완료하지 않는다.

문구 예시:

> 관찰: 검은 거울에서 옮긴 회로 투명지를 일지의 빈 틀에 놓는다. 침실 창, 온실, 대시계를 가리키는 세 점이 한꺼번에 맞지는 않는다.
>
> 주인공의 생각: 선을 잘못 옮긴 걸까, 아니면 바라본 방향이 다른 걸까? 저택의 평면도와 비교해 봐야겠어.

인수: 도입 설명 직후 참가자가 어떤 자료를 어디서 얻었는지 지목한다. J3의 24개 문장 순서에 대해 가시 단서와 판정이 일치한다. 실패·재조사에 시간 제한이나 강제 리셋이 없고, 복원 후 D0-A의 추론 과제는 남는다.

## 7. 시계 퍼즐: 세 종류의 판단을 분리

### 7.1 FB08: 종이 방향은 종소리로 풀게 하지 않는다

후기에서는 `XII 뒤 홈`, `열두 번 이후 떨림`, `바늘 멈춤`으로 종이의 위쪽 방향을 추측했다. 그러나 현재 [ClockNetworkPuzzle](../../game/scripts/data_types/clock_network_puzzle.gd)은 다음을 별도로 검사한다.

| 판단 | 현재 정답 또는 규칙 | 플레이어에게 필요한 증거 |
| --- | --- | --- |
| 네 카드의 역할 위치 | 대응접실 / 외부 서고 / 대시계 / 침실 | 시작·통과·출력·단절된 선 |
| 종이 방향 | 네 조각의 회전값 모두 0° | 각 조각의 가장자리 홈·비대칭 나사와 점검판 기준 |
| 앞뒤 | 외부 서고만 뒷면 | 뒷면 흑연·선 방향·연결 접점 |
| B3-B 전달 시점 | +1 | 정상 종 완료 뒤 남은 칸·빈 홈 |

현재 UI는 방향 이름과 `굵은 시작선 →` 같은 문양 설명을 텍스트 카드로 표시한다. 힌트에 나사와 가장자리 비교가 있더라도 **비교할 도형이 없으면 힌트가 사실상의 정답 지시가 된다.**

권장 개선:

- B3-A에서 종이 네 장과 점검판을 기능성 선 도형으로 표시한다. 회전하면 홈·나사·선도 실제로 함께 회전하고, 외부 서고는 앞뒤 모양이 달라진다.
- `종이 모서리 기준 홈`과 `XII 뒤 추가 신호 홈`은 이름·위치·모양을 다르게 한다. 동일한 `홈` 아이콘으로 재사용하지 않는다.
- 방향 도움말은 `종이 기준점과 점검판을 비교`라고 설명한다. 종이 윗방향이 곧 시계의 XII나 신호의 진행 방향이라는 오해를 끊는다.
- 침실이 망에서 제외되더라도 방향을 판정하려면 보관/점검 칸의 비대칭 고정점이 화면에 있어야 한다. 그 근거를 만들지 못한다면 제외 조각의 방향 판정 제거를 별도 기획 변경으로 검토한다. 우선안은 기존 정답을 유지하고 근거를 제공하는 것이다.
- 카드의 나열 순서와 실제 배선의 공간 방향을 혼동시키지 않는다. 특히 `외부 서고 뒷면 선은 서쪽`이라는 문구를 그대로 둔 채 출력 카드를 오른쪽에만 놓아 선이 거꾸로 보이게 하지 않는다. 역할 슬롯과 물리 연결 도면을 구분하고, 정답 배치에서 실제 포트 연결을 먼저 증명한다.
- 처음 실패하면 위치/종이 방향/앞뒤 중 어떤 범주가 어긋났는지 보여 준다. 매번 여러 규칙을 동시에 바꾸게 하지 않는다.

정답은 우선 유지한다. 신규 도식은 판정 코드에서 직접 전체 정답을 미리 그리는 답안 화면이 아니라, 관찰 가능한 원자료와 플레이어 배치를 보여 주어야 한다.

인수: 네 회전과 앞뒤의 모든 지원 조합을 대조해 숨은 방향 조건이 없다. 정답 조합만 성공하는 기존 유일해와 시각적 연결이 일치한다. 성공자에게 `왜 침실이 제외인가`, `왜 서고를 뒤집었는가`, `종이 방향과 신호 시점은 어떻게 다른가`를 설명하게 한다.

### 7.2 FB09: 시계망은 지시 이행이 아니라 기억 검증 실험이다

J1 뒤 목적을 다음처럼 짧게 연결한다.

> 주인공의 생각: 이 글은 내가 어제를 기억하는지 묻고 있어. 장난이라면, 확인할 수 있는 단서까지 남기진 않았겠지. 여기 적힌 시계의 흔적부터 찾아보자.

네 탁본을 연결한 뒤:

> 주인공의 생각: 바늘이 멈춘 시계도 떨림을 넘기고 있었어. 시간을 맞추는 장치가 아니라, 무언가를 전하는 길일지도 몰라.

작동 뒤:

> 관찰: 마지막 종 뒤에 한 번 더 울린 떨림이 공명통 표면에 자국을 남긴다.
>
> 주인공의 생각: 일지에 있던 빈칸이 이런 뜻이었구나. 이 모양을 옮겨 두면 다음 페이지와 비교할 수 있겠어.

아직 거울 신호의 정확한 기능을 알기 전이므로 `거울을 열기 위해 시계를 작동한다`고 먼저 설명하지 않는다. 알 수 있는 것에서 다음 검증을 선택하는 흐름을 만든다.

- 목표 표시는 `왜 / 지금 확인할 것 / 관련 자료`의 짧은 구성으로 바꾼다.
- 추가 대화는 최초 전환 때만 1~3문장으로 제공한다. 반복 루프에는 완료 지식과 현재 남은 질문만 요약한다.
- 성공 후 설명은 플레이어가 검증한 연결과 결과를 정리한다. 사후 해설로만 퍼즐을 이해하게 해서는 안 된다.

## 8. 세정제와 검은 거울

### 8.1 FB11: C3의 난도는 유지하고 외부 메모 의존만 줄인다

좋은 평가의 이유는 총량·비율·순서라는 규칙과 결과가 연결되기 때문이다. 이를 다른 퍼즐의 정보 전달 기준으로 삼는다.

- 조합 화면에 이미 읽은 마라 1 청소 기록과 루카 약품 라벨 바로가기를 둔다.
- 8단위 조건, 첨가제 비율, 투입 순서를 구분해 재열람한다. 미확인 자료를 자동 수집하지 않는다.
- 검증 성공 전에는 정답 5:1:2를 계산해 주지 않는다. 성공 후에만 검증 공식으로 보관한다.
- 단위와 재료명은 병·라벨·버튼·수첩에서 같게 쓴다. 부엌 이동이나 수첩 닫기로 계량 상태가 바뀌지 않는다.
- 자유 입력 메모 기능은 이번 권장 범위에 추가하지 않는다. 확정된 통합 수첩의 자료 고정·두 자료 비교를 우선 활용한다. 아직 기본 실행에서 사용할 수 없다면 구형 수첩의 관련 원문 바로가기로도 먼저 개선할 수 있다.

### 8.2 FB12: 시적인 문장은 경로의 완전한 설명서가 아니다

플레이어가 제시한 해석 중 `긴 떨림 = 직선 진입`과 `잔향 = 바깥 고리`는 방향이 맞다. 그러나 **두 번의 짧은 반사**는 시간상 두 신호를 뜻하며, 곧바로 공간의 짧은 분기 하나만을 뜻하지 않는다. `긴 분기`까지 잔향에 묶어 해석하도록 두면 현재 정답과 근거가 어긋난다.

현재 정답은 `직선 진입 → 짧은 분기 → 긴 분기 → 고리 시계 방향`이고, C4는 회전 90°·반전 없음·고정 여부를 별도로 검사한다. 이 값을 바꾸기 전에 증거를 보강한다.

| 자료에서 읽을 것 | 회로에서 확인할 것 | 권장 보강 |
| --- | --- | --- |
| 긴 진입파 | 하단 진입점과 직선 | 같은 시작 표식, 겹침/어긋남 비교 |
| 두 반사파 | 짧은 가지와 긴 가지, 두 응답 | 두 신호를 따로 확대. 첫 가지의 막힌 끝과 되돌아오는 경로, 긴 가지의 고리 연결을 관찰 가능하게 표시 |
| 잔류파 | 마지막 폐쇄 고리 | 한쪽으로만 이어지는 겹친 홈/이음매로 시계 방향의 근거 제공 |

위의 추가 접점·홈은 **제작 제안**이다. 현재 원도에서 실제로 확인된 사실로 서술하지 않는다. 도식·원문·판정이 같은 규칙을 설명하도록 묶어서 제작한다. 필요하면 두 반사 사이의 귀환 순서를 도식으로 보강하되 별도 현실 시간 제한은 만들지 않는다.

계획 단계를 명확히 나눈다.

1. `경로 배치`: 내가 가정한 순서를 놓음. 되돌릴 수 있음.
2. `마른 천으로 시험`: 선택한 경로의 응답을 확인. 재료·코팅 손상 없음.
3. `검증한 닦기 순서를 수첩에 기록`: 기존 `계획 확정`의 의미. 별도 신규 정답을 요구하지 않음.
4. `젖은 천으로 실행`: 실제 코팅에 적용. 실패 시 당일 물리 손상과 수면 재준비 규칙 적용.

이미 [빛 경로 피드백](../mirror_route_feedback_status.md)이 구현되어 있다. 같은 기능을 새로 만들지 않는다. 현재 선택한 구간까지만 재생하고 첫 오류에서 멈추는 기존 동작을 유지하면서, **시험 전에 읽을 수 있는 근거**와 시험 결과 사이를 연결한다. 정답 전체를 미리 자동 재생하는 도움으로 바꾸지 않는다.

인수: 참가자가 짧은 두 신호와 두 공간 분기를 구분하고, 순서와 고리 방향의 근거를 설명한다. 계획 기록만으로 젖은 천이 실행되지 않는다. 읽기 전용 재생·수첩 열람이 재료나 실패 횟수를 바꾸지 않는다.

## 9. FB14: 스토리 전환을 의문·검증·발견으로 연결

대사를 많이 넣는 것 자체가 해결책은 아니다. 다음 표처럼 **이미 본 현상과 앞으로 확인하려는 질문**을 잇는다. 예시 문장은 검토 초안이며 주인공의 이름·나이·성격을 새로 확정하지 않는다.

| 전환 | 플레이어가 이미 아는 것 | 새 행동의 이유와 보상 |
| --- | --- | --- |
| P6 → A1 | 같은 아침, 물건의 초기 상태 | `내가 어제를 기억하는지 확인하고 싶다` → 자기 표식 실험 |
| A2 → B1/B2 | 수첩 표식은 남음, 접근하기 어려운 일지 존재 | `저 일지에도 반복의 흔적이 있을까` → 조용히 조사할 시간 찾기 |
| J1 → B3 | 일지가 어제의 기억과 세 시계 기능을 암시 | 문장이 실제 저택과 맞는지 확인 → 시계망·추가 진동 발견 |
| B4 → J2 | 공명통에서 파형을 기록 | 다음 페이지의 눌림과 비교 → 종은 신호라는 이해 |
| J2/C0 → C3/C4 | 신호, 보존 처리된 검은 표면, 손상 위험 | 아래를 보고 싶지만 단서를 지우고 싶지 않음 → 안전한 세정과 마른 시험 |
| C4/C5 → J3 | 익숙한 장식 아래 다른 구조와 세 기준점 | 거울 회로가 저택의 어디를 뜻하는지 확인 → 평면도가 필요하다는 발견 |
| J3 → D0-A | 그대로는 맞지 않는 방향, 낮은 심장 | 저택 배치와 자료의 방향을 직접 검증 → 지하 접근 단서 |

짧은 감각을 먼저 넣고 해석은 뒤에 둔다. 예: `종이의 홈을 따라가던 손이 멎는다` 뒤에 `왜 움직이지 않는 시계에서 떨림이 오지?`를 둔다. 불확실성이 스토리의 진실에 남게 하고, 어떤 버튼이 무엇을 하는지는 명확히 한다.

선택적 `왜 이걸 조사하지?` 재정리 버튼은 확인한 사실·현재 의문·다음 검증만 보여 준다. 미래 정보, 미획득 문서, 정답 해설은 보여 주지 않는다. 이 선택에 호감도나 엔딩 편향을 붙이지 않는다.

## 12. 2차 플레이테스트와 통과 기준

### 12.1 검증 구성

1. 개발자 시점 이동으로 B1/J1/B3/J2/C4/J3의 집중 기능 회귀를 수행한다. 시험마다 코드·콘텐츠 버전, 저장 형식, 개발 옵션을 기록한다.
2. 같은 빌드의 기본 실행과 `--ggb-dev-notebook-v2` 실행을 나누어 검사한다. 개발 옵션의 개선을 일반 실행의 완료로 발표하지 않는다.
3. 기존 후기 작성자에게는 원래 막힌 부분이 해소됐는지 재검사를 요청한다. 이미 정답을 아는 참가자이므로 신규 난도 지표에 합산하지 않는다.
4. [기존 플레이테스트 계획](../player_experience_and_playtest.md)의 슬라이스 표본 12명(핵심 6·인접 4·비대상 2)을 기준으로 신규 참가자 검증을 진행한다. 먼저 소수로 결함을 찾을 수 있지만 이를 정식 표본 통과라고 하지 않는다.
5. 새 게임부터 최소 J3 이후 D0 진입까지 이어서 진행한다. 중간에 테스트 진행자가 해설하지 않는다. 참가자 요청 시 힌트를 제공하고 단계·시점을 기록한다.

### 12.2 관찰 질문

- B1: `지금 어느 시간대를 찾고 있고, 장부의 무엇이 바뀐 건가요?`
- J1: `이 두 조각은 왜 이 순서인가요?`
- B3-A: `종이의 홈 방향과 시계의 역할을 각각 무엇으로 판단했나요?`
- B3-B: `지금 시계망을 작동해서 무엇을 확인하려 하나요?`
- J2: `어느 종이를 어느 자료 위에 올리고 있나요?`
- C4: `이 경로의 첫째·둘째 분기 순서와 고리 방향을 고른 이유는 무엇인가요?`
- J3: `사용 중인 자료를 어디서 얻었고, 다음에는 무엇과 비교해야 하나요?`

이 질문 자체가 플레이 도중 정답 방향을 알려 주지 않도록 원칙적으로 시도 후 또는 중단 후 묻는다. think-aloud에서는 `지금 어떤 생각을 하고 있나요?`처럼 중립 질문만 사용한다.

## 13. 최종 권장안과 확인할 정보

## 15. 콘텐츠 개정 후속 상태

[2026-10-07 콘텐츠 개정·변경 비교](2026-10-07_1차_피드백_콘텐츠개정및변경비교.md)에 따라 FB02~05·07~14의 원고·비교 단서·자료명·행동 동기를 상세 기획 정본에 반영했다. FB01 메뉴와 FB06 문서 열람 중 입력은 코드 범위여서 제외했다. FB05는 원고의 발화 종류를 구분한 것이며 실제 대사창 UI 수정은 포함하지 않는다.

이 문서는 2026-10-04의 분석 근거와 당시 실행판 관찰을 보존한다. `11. 구현할 때 함께 맞춰야 할 대상`의 코드 참조는 미수정 실행판을 설명하는 것이며 새 원고가 런타임에 배포됐다는 뜻이 아니다. 비교 그림은 제작 명세를 확정했고 이미지 자산·게임 화면의 배치 변경은 미실행이다. 실제 개선 효과와 최종 난도는 2차 플레이테스트 전까지 미검증이다.
