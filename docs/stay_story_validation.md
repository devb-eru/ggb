# 잔류 중앙홀·식탁·마지막 장면

검증 결과: 격리 Godot 4.7.2에서 `BASEMENT_SESSION_SMOKE: PASS`, `FOUNDATION_SMOKE: PASS`. 숫자 복원 수정 후 두 문장의 작성 표시를 화면에서 재확인했다. 스크립트 오류는 없으며 Windows 인증서 저장소 경고는 별도 환경 경고다.

## 구현 범위

`EDS_CENTRAL_HALL → EDS_DINING_ROOM → EDS_TABLE_OBJECTS → EDS_FINAL_FRAME → CREDITS_STAY`를 연결했다. 크레딧은 다음 구현 경계다.

중앙홀의 대시계·일정표·현관문·카펫·호출끈을 선택 조사한다. 호출끈은 실제로 다섯 공용 채널을 선택하는 메뉴를 열며 선택이 이동·응답을 강제하지 않는다. 조사를 전부 생략해도 식당에 갈 수 있다. 30~90초는 플레이 타임 목표이며 강제 대기 시간이 아니다.

식탁은 LOW/MID/HIGH/ALL과 개별 관계 완료 여부에 따라 좌석·행동 설명을 바꾼다. 모든 조합에서 다섯 이름이 남는다. 얼룩·차·계절·이름표·레이피어는 개별 관계 완료/미완료와 유효 outcome을 반영한다. 이리스 고백은 기존 읽기 전용 계산기를 사용하고 사적 고백을 공개 반복하지 않는다. 차 온도 변경은 별도 표시 상태이며 보상·정답이 아니다.

## 수첩과 마지막 장면

두 문장은 플레이어가 각각 눌러 써야 한다. 어느 문장을 먼저 쓰더라도 저장 순서는 다음과 같다.

> 내일도 같은 날일 수 있다.
> 하지만 같은 선택일 필요는 없다.

두 문장 완료 시 `OBJ_STAY_NOTEBOOK`을 기록한다. 다른 식탁 오브젝트는 엔딩 조건이 아니다. 마지막 장면 진입에는 세 원칙 완료도 확인한다.

처음 2초는 양옆에 서 있는 과거 구도로 묘사한 뒤 각자의 자리·행동 설명으로 바뀐다. 마지막 확인 뒤 `CREDITS_STAY`로 진행한다. 현재 좌석 이동·감각·서명 분리는 텍스트 기반이며 실제 캐릭터 이동·암전·팬 음향·금속 냄새를 표현하는 최종 리소스 연출은 미완성이다.

## 표시와 저장

외형 재선택 및 조사 시 프레임 표시는 중앙홀·식탁에서도 유지한다. 시설 골격은 임시 선이며 완성 원화가 아니다.

조사·문장·차·마지막 장면 초는 `loop_state.event_local_states.STAY_STORY`에 저장한다. 완료 오브젝트와 노드는 ending_run에 기록한다. 최종 결정·관계는 바꾸지 않으며 `SAVE_ENDING_NODE`로 재개한다. 크레딧 완료·프로필 seen은 아직 쓰지 않는다.

### 숫자 복원 오류 수정

JSON 로드에서 문장/기억 원칙 번호가 실수로 복원되면 정수 입력과의 배열 멤버십 비교가 어긋날 수 있었다. 재클릭 시 중복과 완료 조건 손상이 생기지 않도록 `StayStory.progress`와 `StayCharter.progress`에서 유효 번호를 정수·집합으로 정규화한다. 저장 후 같은 항목을 다시 눌러도 개수가 증가하지 않는 회귀 검사를 추가했다.

## 검증 범위

- 관계 32개 조합에서 다섯 이름 유지.
- 문장 선택 순서 두 가지의 동일 배열 및 선택 조사 없는 최종 진행.
- 중앙홀 조사·통신 선택, 식탁 반응, 차 선택, 부분 저장 재개.
- 문장과 기억 원칙의 로드 후 재클릭 중복 방지.
- 두 문장 누락 거부, 첫 2초 완료 조건, 크레딧 경계 저장 재개.
- 관계·최종 결정 불변. 화면 캡처 `user://stay_table.png`.

실제 좌석 애니메이션과 모든 bond/alert 연기, 음향·접근성·해상도 조합의 전수 QA는 별도 작업이다. 두 크레딧, 엔딩 메타·재선택 사본·갤러리, 전편 통합 검증과 최종 리소스가 남아 있다.
