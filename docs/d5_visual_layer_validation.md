# D5 개발용 전환 레이어 검증

## 목적

D5 최종 에셋이 없는 상태에서도 필터 박리 타임라인, 접근성, 시선 선택과 교체 경계를 검증한다. 이 레이어는 최종 아트가 아니며 저장·퍼즐 판정과 분리되어 있다.

## 표현

- 10초 HOLD 진행률에 따라 배선, 벽지 박리 경계, 창문 없는 천장의 밤하늘, 다섯 진단 투사를 순서대로 노출한다.
- 데모는 기존 60초 스팅어 진행률에 같은 레이어를 사용한다.
- 에드가는 수직 잠금선, 마라 1은 대각선 자국, 루카는 이중 맥박, 이리스는 꽃잎 후광, 마라 2는 겹친 액자로 구분한다.
- 각 투사는 서명색과 비색상 문양을 함께 사용한다.
- CHK_D4_REACT 반응자가 있으면 그 채널을 먼저 강조한다. 플레이어가 D5_FOCUS_OWNER를 고르면 시선 대상이 우선한다.
- 표준 모션은 선택 채널의 약한 맥동만 사용한다. reduced와 static에서는 맥동 없이 정적 단계 전환만 사용한다.

## 교체 계약

- 노드 메타데이터 asset_id는 D5_TRANSITION_DEVELOPER_LAYER다.
- is_placeholder와 final_asset_pending은 true다.
- 최종 마스크·투사·밤하늘 에셋은 d5_transition_art.gd의 그리기 구현을 교체하되 controller의 present(progress, owner, motion_mode) 호출 계약을 유지한다.
- 레이어는 GameState나 SaveManager에 쓰지 않는다.

## 검증

- Godot 4.7.2 임포트에서 스크립트 등록과 파싱을 확인했다.
- `BASEMENT_SESSION_SMOKE: PASS`. HOLD 진행률, 동결 반응 강조, 다섯 비색상 문양, 선택 시선 강조, 관계·저장 불변을 확인했다.
- Windows Compatibility 렌더러에서 1280x720 정적 완료 상태를 캡처했다. 다섯 투사와 밤하늘 틈이 화면 안에 있고 마라 1 강조 및 각 문양이 서로 겹치지 않는 것을 육안 확인했다.
- 접근성 프로필은 레이어 생성 때 읽는다. HOLD의 프레임 갱신은 이미 적용한 모션 모드를 재사용하며 프로필 파일을 매 프레임 읽지 않는다.
- 최종 리소스 품질, 색보정, 저사양 성능, 전체 카메라 연출은 별도 검증 대상이다.
