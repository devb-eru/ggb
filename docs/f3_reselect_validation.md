# F3 독립 재선택 사본 저장 기반

## 동작

- `SAVE_F3_COMPLETE` 본편 저장 성공 후 같은 슬롯 폴더에 `f3_reselect.json`을 별도로 보존한다. 기존 본편 체크섬·헤더·스냅숏 형식을 재사용한다.
- 임시 파일 검증 후 기존 사본을 백업하고 교체한다. 읽기는 기본 파일, 임시 파일, 백업 순서로 검증하며 미래 runtime schema를 만나면 거절한다.
- 사본에는 F3 완료, 미확정 선택, 최종 수면 잠금, 현재 빌드, 원본 슬롯 ID가 필요하다. 엔딩 이후 상태를 F3처럼 되감아 만드는 방식은 사용하지 않는다.
- `create_f3_reselect_slot`은 무작위 식별자의 별도 재선택 슬롯을 생성한다. 호출자가 기존 슬롯을 목적지로 지정할 수 없으며 충돌 시 거절한다.
- 복제 시 `reselect_used`만 true로 변경하고 F3 당시 관계·기록·임시 의향을 보존한다. 슬롯 공통 엔딩 프로필은 변경하지 않는다.
- 사본 저장 실패는 현재 본편 저장을 롤백하지 않으며 실패 안내를 반환한다. 사본 없는 기존 완료 슬롯의 F3 상태를 추측하지 않는다.
- 테스트용 사본 정리는 `__test_` 슬롯에만 허용한다.

## 검증 범위

- basement-session 회귀 테스트에 F3 사본 생성, 새 슬롯의 정규 로더 통과, 미확정 선택·관계 보존, 원본 progress 바이트 불변 확인을 추가했다.
- 유효 스냅숏 검증과 체크섬 검증은 실제 게임 저장 구현을 사용한다.
- JSON의 숫자형은 정규 로더와 동일하게 정규화한 뒤 검증·관계 비교한다. 정규화 전 float/int 비교로 유효한 사본을 거절하던 초기 결함을 수정했다.

## 남은 작업

- 크레딧 뒤 재선택 확인 UI, 재선택 중 종료 후 재진입 메뉴, 원본 슬롯을 구분하는 화면 표기는 아직 연결 전이다.
- 현재는 저장 기반 API만 추가되었다. 플레이어가 메뉴에서 이 기능을 실행할 수 있다고 안내하지 않는다.
- 새 게임으로 기존 슬롯을 덮어쓸 때 이전 F3 사본을 폐기하는 수명 관리가 필요하다. UI 연결 전에 해결해야 하며 현재 사본을 단순히 존재 여부만으로 노출해서는 안 된다.
- 기존 사본 보존·갱신 정책, 장애 주입과 실제 강제 종료 QA는 후속 작업이다.
