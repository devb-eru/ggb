# Data Contract

이 문서는 기획 문서, Godot 저작 데이터, 사용자 저장 데이터 사이의 연결 규칙이다. 제품에 노출되는 저장·재개 약속은 [제품 계약](product_contract.md), 세부 타입·상태·사건 계약은 [`ideas/md/v04/17_상태변수_이벤트ID_Godot데이터구조.md`](../ideas/md/v04/17_상태변수_이벤트ID_Godot데이터구조.md)를 따른다. 저장 헤더나 생명 주기가 충돌하면 최신 `GGB-DEC`와 제품 계약을 우선하고 문서 17을 같은 변경 단위로 동기화한다.

## 1. Source Of Truth

```text
기획 원본 Markdown
→ Godot 저작 Resource
→ 사용자 저장 JSON
```

| 계층 | 경로 | 형식 | 책임 |
| --- | --- | --- | --- |
| 기획 원본 | `ideas/md/v04/` | Markdown·Mermaid·YAML 예시 | 사람이 읽는 사건·퍼즐·서사 정본 |
| 제품 계약 | `docs/product_contract.md` | Markdown | 빌드·입력·접근성·저장 UX 정본 |
| 구현 계약 | `ideas/md/v04/17_*.md` | Markdown | 타입·writer·저장·검증 정본 |
| 저작 데이터 | `game/data/` | `.tres` 중심 | 게임이 읽는 정적 사건·대사·퍼즐·registry |
| 게임 코드 | `game/scripts/` | GDScript | Resource 실행·상태 쓰기·저장 |
| 사용자 진행 | `user://saves/` | JSON | 슬롯별 진행·루프·파열·엔딩 실행 |
| 사용자 프로필 | `user://profile/` | JSON | 접근성·입력·엔딩 열람 메타 |

- 게임은 기획 Markdown을 직접 파싱하지 않는다.
- `.tres`는 빌드에 포함되는 읽기 전용 저작 데이터다.
- JSON은 실행 중 변경되는 사용자 데이터다.
- 장면 경로·NodePath 대신 안정된 ID를 사용자 저장에 기록한다.

## 2. Data Folders

```text
game/data/
├─ events/
├─ dialogue/
├─ puzzles/
├─ states/
├─ maps/
├─ object_reactions/
│  └─ event_parts/
├─ color_signatures/
├─ avatar_visual_profiles/
├─ world_phase_visual_profiles/
├─ accessibility/
└─ registries/
```

| 폴더 | 내용 |
| --- | --- |
| `events/` | 사건 정의, 노드, 선행 조건, 결과, 재개 정책 |
| `dialogue/` | 사용인·시스템·엔딩 텍스트 ID와 대사 |
| `puzzles/` | 검증 단계, 힌트, 실패, checkpoint |
| `states/` | enum·state path·기본값 정의 |
| `maps/` | location·연결·잠금 registry |
| `object_reactions/` | canonical 오브젝트 상태별 반응 |
| `object_reactions/event_parts/` | P2~P5처럼 사건 안에서만 유효한 자식 핫스폿 반응 |
| `color_signatures/` | 다섯 인격 데이터 서명 |
| `avatar_visual_profiles/` | 캐릭터 대표 외형 |
| `world_phase_visual_profiles/` | S0~S5·R0 표현 상한 |
| `accessibility/` | UI·핫스폿·표시 기본값 |
| `registries/` | ID·상태 경로·canonical 오브젝트·사건 자식 핫스폿·텍스트·저장 지점 색인 |

JSON·CSV를 임시 저작 형식으로 사용할 수 있으나 빌드 전 정식 Resource 또는 registry로 변환하고 같은 검증기를 통과해야 한다.

## 3. ID Rule

### 3.1 기획 ID와 데이터 ID

| 기획 표기 | 데이터 표기 | 파일 |
| --- | --- | --- |
| `B3-A` | `B3_A` | `event_b3_a.tres` |
| `C2-1` | `C2_1` | `event_c2_1.tres` |
| `F0-D` | `F0_D` | `event_f0_d.tres` |
| `CLR-04` | `CLR_04` | `color_stage_clr_04.tres` |

- Markdown은 기획 ID를 사용할 수 있다.
- Resource·변수·저장은 정규화된 데이터 ID만 사용한다.
- 파일명은 소문자 snake_case다.
- `EDGAR_B2`, `SERVANT_ED_*` 같은 문서 별칭을 실행 registry에 넣지 않는다.
- canonical 오브젝트는 `object_id`, 사건 자식 핫스폿은 전역 유일한 `interaction_part_id`로 식별한다.
- canonical 부모가 없는 자식 핫스폿은 `event_context`, `location_id`, `production_id`를 함께 가져야 한다. `production_id`는 제작 역추적용이며 저장 키가 아니다.

### 3.2 ID 안정성

- 발급된 ID의 의미를 다른 콘텐츠에 재사용하지 않는다.
- 폐기 ID는 `deprecated`와 `replacement_id`를 남긴다.
- 같은 ID가 둘 이상의 category에 등록되면 빌드를 차단한다.
- 런타임에서 하이픈·underscore 별칭을 동시에 검색하지 않는다.

## 4. State Rule

| 상태 루트 | 수명 | RESET | 저장 |
| --- | --- | --- | --- |
| `meta_progress` | 슬롯 영구 | 유지 | 진행 JSON |
| `loop_state` | 현재 루프 | NORMAL_RESET 부분 초기화 | 진행 JSON |
| `fracture_state` | D5 이후 영구 | 유지 | 진행 JSON |
| `reset_state` | 리셋 트랜잭션 | 완료 뒤 idle | 진행 JSON |
| `ending_run` | 엔딩 실행 | 해당 없음 | 진행 JSON |
| `ending_meta` | 사용자 프로필 | 영향 없음 | 별도 profile JSON |
| `accessibility_settings` | 사용자 프로필 | 영향 없음 | 별도 profile JSON |

주요 원칙:

- 방·오브젝트 위치·당일 도구는 물리 리셋 대상이다.
- 사건 전용 도구·부분 진행은 `loop_state.event_local_states.EVENT_ID`에 두고 NORMAL_RESET에서 초기화한다.
- 수첩 지식·일지·실패 정보·관계·잔류 기억은 영구 유지한다.
- 확인한 대화 기록은 `meta_progress.dialogue_history`에 두고 모든 세계 리셋에서 유지한다.
- D5 뒤 첫 수면만 S3를 생성하며 이후 휴식은 현재 물리 상태를 보존한다.
- 파생값은 저장하지 않고 원본 상태에서 다시 계산한다.
- UI·resolver·대사 코드는 진행 상태를 직접 쓰지 않는다.

## 5. Godot Type And Serialization

| 논리 타입 | Godot 4.7 | JSON |
| --- | --- | --- |
| ID·enum | `StringName` | string |
| 순서 목록 | `Array[StringName]` | array |
| 논리 집합 | 중복 없는 `Array[StringName]` | 정렬된 string array |
| 레코드 | `Dictionary` 또는 Resource | object |
| 정적 정의 | `Resource` | 사용자 저장 안 함 |
| 선택 전 | enum `unset`·`unresolved` | string |
| 대상 없음 | 빈 `StringName` 또는 null | schema 지정 방식 |

Godot 4.7에는 `Set[StringName]` 내장 타입이 없다. 논리 집합은 추가·로드·저장 때 중복을 제거하고 저장 전에 사전순으로 정렬한다. 순서가 의미인 사건 노드와 퍼즐 단계는 정렬하지 않는다.

## 6. Writer Ownership

```text
EventManager
→ StateWriter
→ GameState revision
→ SaveManager
```

- 모든 진행 쓰기는 선언된 state path와 writer 권한을 검사한다.
- 영구 효과가 둘 이상인 사건은 atomic group으로 커밋한다.
- 관계 사건은 완료 플래그·기록·사용인 상태·관계 delta·event history를 함께 쓴다.
- 접근성 프로필 writer는 진행 상태를 수정할 수 없다.
- SaveManager는 상태를 결정하지 않고 확정 snapshot만 직렬화한다.

## 7. Save And Profile

```text
user://saves/{slot_id}/progress.json
user://saves/{slot_id}/progress.bak.json
user://saves/{slot_id}/progress.tmp.json
user://saves/{slot_id}/f3_reselect.json
user://profile/ending_meta.json
user://profile/accessibility.json
user://profile/input_map.json
```

버전:

```text
progress.schema_version = 1
progress.design_revision = "v0.4-state-r12"
accessibility.accessibility_profile_version = 1
ending_meta.ending_meta_profile_version = 1
```

첫 팀·외부 배포 저장 형식은 `schema_version=1`에서 시작한다. 기존 기획 문서의 schema 12는 런타임 이관 번호가 아니라 열두 번째 상태 모델 개정이며 `design_revision`으로만 추적한다. 실제 배포한 저장 형식이 바뀔 때만 `schema_version`을 올리고 입력·출력 fixture를 보존한다.

진행 헤더 최소 계약:

```yaml
save_header:
  schema_version: 1
  design_revision: "v0.4-state-r12"
  game_version: "0.0.0-dev"
  build_id: "local-dev"
  build_flavor: "demo"
  content_revision: "unlocked"
  content_boundary_id: "SAVE_J1_COMPLETE"
  source_app_id: "local"
  engine_version: "4.7"
  slot_id: "slot_01"
  save_point_id: "SAVE_J1_COMPLETE"
  transaction_id: "SAVE_TX_000001"
  created_at_utc: 0
  updated_at_utc: 0
  checksum_algorithm: "sha256"
  checksum: ""
```

`design_revision`이나 `engine_version` 하나만으로 호환을 허용하지 않는다. 최소한 `schema_version`, `build_flavor`, `content_boundary_id`, `source_app_id`와 checksum을 함께 판정한다.

### 7.1 대화 기록

[GGB-DEC-2026-0006](decisions/GGB-DEC-2026-0006_대화_기록_영속화.md)에 따라 대화 기록은 진행 슬롯에 명시적으로 저장한다. 보존·통합 수첩의 목표 계약은 [DEC-0012](decisions/GGB-DEC-2026-0012_통합_수첩_범위와_기록_보존.md)와 [구현 계획](../ideas/md/v04/issues/validation/notebook_history_review_plan.md)을 적용한다. 아래 예시는 이전 기록의 논리 필드 설명이며 신형 archive의 완전한 직렬화 예제가 아니다. 현재 게임은 transcript 저장을 사용하며 새 저장 계층의 실제 연결 상태는 [구현 현황](../ideas/md/v04/issues/validation/notebook_history_implementation_status.md)을 따른다.

개발 옵션의 authored 기록은 `content_id + content_version + variant_id + 공개 segment`를 고정한다. 현재 언어 재열람은 정확히 같은 의미 버전만 사용하고, 없으면 저장 당시 원문임을 표시한다. 변수는 해당 segment가 선언한 공개 값만 받고 정수 공개 값은 첫 저장부터 JSON 수 표현으로 고정한다. 새 대화·힌트 관찰은 실제 표시문과 일치해야 하며, 사건 작성 원고는 7.1.1절을 따른다. 기존 버전 원고의 덮어쓰기나 문자열 역검색으로 출처를 추정하지 않는다. 현재 이 계약의 실제 연결 대상은 [NP01~NP03 프롤로그, NP04 1장 표시, NP05 등록 선택창, NP06 1장 원고, NP07 거울, NP08 지하, NP09 파열/휴식/기상/보고 등록분, NP10~NP14 다섯 사용인 핵심 관계, NP15 저녁/접근 등록분, NP20 단계 힌트](../ideas/md/v04/issues/validation/notebook_content_mapping_status.md)이며 다른 생산자의 임시 `unmapped`는 인수 완료로 세지 않는다. 선택 문구 확정 기록은 입력 의향의 증거이고, 뒤이어 실행하는 출발·수면 등 게임 상태 저장의 성공을 뜻하지 않는다.

공개 변수의 선택적 `enum:<이름>` 형식은 해당 의미 버전의 `enums[이름][ko-KR/en-US][토큰]` 명칭을 사용한다. 두 언어의 허용 토큰 집합은 같고 비어 있지 않아야 하며, 토큰·번역문은 비어 있지 않은 문자열이어야 한다. 선언하지 않은 enum·토큰·번역문 자체·숫자/객체 입력은 거절한다. 저장에는 당시 공개한 토큰만 들어가고 표시문은 한 번만 치환한다. 값 속 중괄호는 추가 변수로 해석하지 않는다. enum이 없는 기존 카탈로그는 기존 계약을 유지한다. 과거 의미 버전 전체를 구할 수 없으면 저장한 완전한 원문과 fallback 안내를 사용한다.

NP04는 `loop_state.event_local_states.CHAPTER_ONE.last_feedback.notebook_feedback`에 명시적인 문단별 descriptor 목록을 선택적으로 보존한다. 이는 미표시 대사의 관찰 증거가 아니며 사건 진행과 함께 저장한 표시 원고 식별자다. 대화창에서 실제로 표시한 문단만 archive 관찰로 생성한다. 필드 없는 과거 피드백을 텍스트 ID나 한국어 본문으로 소급 매핑하지 않는다. 시계 배치의 공개 변수는 `matched` 또는 `position` 정수만 허용하며, 미래 정답이나 현재 상태로 재계산하지 않는다. 게임 사건 저장 응답 유실은 transaction과 전체 영속 값 일치를 확인한 경우에만 성공으로 인정한다.

2026-10-10 구형 피드백 재표시 계약: 공통 ChapterOneSession 커밋은 이후 새로 작성하는 `last_feedback`에 `producer_contract_version: 1`을 남긴다. 구형 archive 모드에서 표식/descriptor 없는 값의 단순 초기화는 원래 피드백을 교체하거나 신형 표식을 붙이지 않는다. 이후 v2 이관 시에도 처음부터 신규 대사였던 것으로 재분류하지 않기 위해서다. v2에서는 버전 표식과 authored descriptor가 모두 없는 구형 값만 `legacy_feedback_origin`에 원래 피드백 전체·archive의 `source_origin_id`·정규 JSON SHA-256을 보존한다. 이는 저장 내부의 출처 일관성 표식이며 외부 서명이나 신규 콘텐츠 ID가 아니다. 신형 값에서 descriptor가 누락되어도 구형으로 재분류하지 않는다. 거울/지하 초기화의 단순 전달은 출처를 유지하고 새 행동은 이를 물려받지 않는다.

구형 원문을 실제 표시할 때만 `history_context.legacy_feedback_replay`의 출처/문단 번호와 결정적 표시 토큰을 검증한 뒤 `record_class: legacy`·`legacy_feedback_source` 원문 출처로 append한다. 초기화만으로 문단을 관찰했다고 기록하지 않으며, 기존 `unmapped`나 기존 이관 기록도 소급 수정하지 않는다. 구형 `text_id`로 최신 번역을 재생하지 않는다. 과거 사건/장/장소를 알면 그대로 보존하고 모르면 `LEGACY`/`LEGACY_UNKNOWN`으로 둔다. 다른 UI 언어의 재표시도 기존 UID/첫 언어/원문을 덮어쓰지 않는다. 새 사실·자료 획득을 붙이거나 출처/텍스트/화자/토큰을 바꾼 요청은 저장 전에 거부한다. 관찰과 커서의 원자 저장·책갈피/비교 보호·일반 대사 한도 밖 보존은 기존 archive 계약을 사용한다. debug 엄격 모드의 신규 ID 거부나 전체 생산자 인수 면제와는 구분한다.

producer 버전 표식이 존재하면 JSON 정수 값 `1`만 지원한다. 미지원 값이나 문자열/불리언은 초기화 저장 전에 거부하며 구형 또는 현재 버전으로 조용히 낮추지 않는다. root/save 형식의 미래 버전 보호를 대신하는 규칙은 아니다.

NP05의 등록 선택창은 표시와 각 입력의 콘텐츠 ID/종류를 명시한다. 첫 번째 버튼이라는 이유로 취소하지 않으며 실제 읽기 확인·의향 선택·단순 재생/닫기를 구분한다. 표시 및 선택 토큰과 언어·사건 문맥을 생성 시 동결하고 저장 실패 시 콜백 실행을 막는다. 선택 기록의 저장은 이후 gameplay 커밋의 성공 증거가 아니다. 슬롯/로드 epoch/출처/분기/namespace와 모달 세대를 대조하고, 오래된 창은 새 상태에 기록하지 않고 닫는다. 공개한 부기/경로 segment만 저장하며 아직 읽지 않은 확대 본문을 summary의 관찰로 재열람하지 않는다. 공통 선택창 전체 및 앱 재시작 커서의 완료 여부는 매핑 현황을 따른다.

명시적 취소가 없는 읽기 창의 Esc도 활성 scope에서 표시 저장이 실패했다면 같은 표시 요청을 먼저 재시도한다. 성공 전에는 닫지 않는다. 성공 후의 단순 닫기는 `choice_confirmed`나 `field_read`를 만들지 않는다. 로드 등으로 scope가 무효화된 창의 무기록 닫기와 구분한다.

```yaml
meta_progress:
  dialogue_history:
    next_sequence: 1
    entries:
      - sequence: 0
        line_id: DLG_EDGAR_B1_001
        speaker_id: SERVANT_EDGAR
        choice_id: null
        viewed_locale: ko-KR
        event_id: B1
        viewed_at_utc: 0
        retention: normal
```

규칙:

- 신규 기록은 원 콘텐츠 ID·의미 버전·variant·안전한 변수·실제 공개 segment로 현재 locale에 표시한다. 해당 버전이 없으면 당시 표시 원문과 언어를 fallback으로 쓰며 최신 비밀 본문으로 대체하지 않는다. legacy 원문은 재작성하지 않는다.
- `entry_uid`는 불변 참조 키다. `sequence`는 분기 내 기록 순서이며 과거 복귀로 값이 재사용돼도 다른 기록에 연결하지 않는다. 관찰 기록의 표시 순서와 9.2절 구형 수첩 스냅샷의 저장 순번을 혼동하지 않는다. 원 출처·분기·namespace·load epoch를 구분한다.
- NORMAL_RESET, BROKEN_RESET, 불러오기와 언어 변경에서 유지한다.
- 일반 대사는 최신 2,000개를 유지하고 보호 기록·legacy는 수량 계산에서 제외해 별도로 보존한다. 보호만 2,001개여도 새 일반 기록을 밀어내지 않는다.
- 일반 기록이 실제 정리된 세션은 남은 authored entry에 선택 메타 `session_pruned: true`를 남긴다. 세션 키는 `source_origin_id + event_occurrence_id + conversation_session_id`의 JSON 배열 해시다. 같은 세션의 남은 보호/일반 기록에만 표시하고, 다른 출처·발생·세션으로 전파하지 않는다. 값이 있으면 bool `true`만 허용하며 legacy/unmapped에는 허용하지 않는다.
- 이 메타는 관찰 원문·UID·sequence·보호 이유가 아닌 보존 사실이다. 정리와 같은 저장 후보에 포함하고 실패하면 함께 롤백한다. 조회·필터·언어 변경으로 생성하지 않는다. 필드 없는 기존 schema 2 저장도 유효하며 순번의 공백으로 과거 정리를 추측하지 않는다. 부재는 전체 대화가 보존됐다는 증명이 아니다. 남은 entry가 없는 세션의 본문·제목·삭제 건수나 별도 tombstone은 만들지 않는다.
- 세션 목록과 원문 상세/두 자료 비교에 보존 안내를 본문과 분리해 표시한다. 필터가 표식 entry를 숨겨도 동결한 전체 조회 모델의 같은 세션 근거를 사용한다. 안내는 검색 대상 원문이 아니며 사람 전체에 특정 세션의 정리를 일반화하지 않는다. 분기 복제는 기존 메타를 복사하고, 이전 저장을 열 때 미래 분기의 메타를 합치지 않는다.
- 일지·최종 선택·관계 outcome·단서/가설/인물의 출처와 책갈피·비교 참조가 원문을 보호한다. 참조와 보호 이유는 같은 슬롯 snapshot에서 저장하며 해제는 해당 이유만 제거한다.
- 인물 최초 공개 근거는 9.8절에 따라 후보의 일반 기록 정리 전에 `person_source`로 연결한다. 수첩을 읽는 행위로 링크를 저장하지 않으며, 책갈피를 해제해도 인물 근거 보호는 유지한다.
- 조회/검색/확대는 읽기 전용이다. 고정/비교 명령은 공개된 자료의 참조·보호·기록 메타 revision과 필요한 구형 원문 스냅샷(9.2절)만 변경한다. 세계·관계·퍼즐·현실 `field_read`는 변경하지 않는다.
- 새 게임·삭제는 다른 슬롯과 갤러리를 지우지 않는다. 호환 불가 상태는 원본 보존·명시적 복구 경로로 처리하고 자동 초기화하지 않는다.
- 아직 보지 않은 line이나 후속 선택지는 기록에 생성하지 않는다.

현실 몸 재관찰의 독립 증거는 `meta_progress.knowledge_entries.dialogue_observed_facts`에 둔다. 허용 키는 `BODY_REPEAT:OBJ_REALITY_HAND`, `BODY_REPEAT:OBJ_REALITY_BREATH_MONITOR`, `BODY_REPEAT:OBJ_REALITY_RESTRAINT`이며 값은 `true`만 허용한다. 실제 재관찰 대사가 표시될 때 기존 조사 확인·현재 현실 노드를 검사하고 대사 기록과 함께 저장한다. 저장 실패 시 두 변경을 함께 롤백한다. 갤러리는 이 증거로 재관찰 본문을 보존하되 기존 조사 확인 조건을 우회하지 않는다. 구형 저장의 원문 확인은 읽기 전용 호환 경로로 유지한다.

기본 schema 1 writer는 자동 정리를 켜지 않았다. 개발 옵션으로 활성화한 schema 2 archive는 후보 저장 시 일반 대사 상한과 보호 이유를 함께 계산한다. 공개 기본값 전환은 잔여 인수 완료 뒤 별도로 결정하며, 새 archive 후보 변환만 통과한 것을 전체 슬롯 이관 완료로 간주하지 않는다.

개발 검증 옵션 `--ggb-dev-notebook-v2`에서는 실제 schema 1 -> 2 이관과 신형 archive 저장을 검사할 수 있다. 일반 실행은 schema 1을 유지하며 release에서는 이 옵션을 무시한다. 원본은 checksum 검증 후 `pre_notebook_<checksum>.json`으로 바이트 보존하고, 원본/백업/F3/demo/개발/갤러리의 읽기 입구를 각각 처리한다. 갤러리 원본과 hash ID는 변경하지 않는다. 미래 형식과 백업 충돌은 덮어쓰지 않는다.

신형 검증 모드의 미연결 생산자는 `unmapped` 보존 래퍼이며 authored 완료로 계산하지 않는다. legacy/unmapped에는 자동 정리를 적용하지 않는다. `notebook_commands.gd`의 고정/비교 쓰기는 실제 슬롯 트랜잭션과 개발 옵션의 공통 수첩 UI에 연결한다(9.1절). 자료 고정은 gameplay 상태를 바꾸지 않으며, 실패·응답 소실·낡은 scope/revision을 검사한다. 전체 전환 상태는 구현 현황의 단계별 인수 결과가 기준이다.

### 7.1.1 사건 작성 지식 Revision (개발 검증)

선택 필드 `meta_progress.knowledge_entries.notebook_knowledge`는 `{schema_version: 1, revision, revisions: []}`다. 필드가 없는 구형 원고에는 과거 획득 이력을 만들어 넣지 않는다. 같은 archive 2 snapshot에 실제 획득한 원고와 아래 revision을 함께 저장한다. 일반 실행의 기본 저장 형식은 이 변경으로 승격하지 않는다.

| 필드 | 계약 |
| --- | --- |
| `knowledge_uid` | 카드별 불변 128-bit ID. 같은 knowledge ID의 후속 revision이 공유 |
| `revision_uid`, `previous_revision_uid` | 개별 원고 갱신 ID와 바로 이전 ID. 최초는 이전 ID 빈 문자열 |
| `sequence` | ledger 내부 순서. 단순 표시 변경·재조회·같은 요청 재시도로 증가하지 않음 |
| `metadata` | `knowledge_id`, `category`, `epistemic_state`, `provenance_state`, `lifetime`. 내용 해석과 출처 확인을 구분 |
| `observation_ref` | 실제 획득 원고의 종류/출처/UID/정확한 의미 버전/공개 segment |
| `source_refs` | 원고 자체와 이미 공개된 인용 출처. 각 참조에 `knowledge_source:<revision_uid>` 보호가 일치해야 함 |

NP03 9종 원고는 `document_segment` / `replay_committed`로 획득한다. `event_note_commit`으로 등록한 콘텐츠만 이 공개 방식을 사용할 수 있다. 힌트·문서 뒷면을 수첩 열기로 획득하거나, 기록했다는 사실로 gameplay 읽기 완료를 만들지 않는다. P4 진동은 실제 기록 버튼을 눌렀을 때만 작성한다. 다음에 표시될 대사를 미리 출처로 인용하지 않는다.

NP06 26종도 같은 ledger 계약을 사용한다. A1/A2는 `CH1_SELF_MARK`의 가설/검증 revision이고, 실제 실패와 B4 해결은 `CH1_CLOCK_FAILURE`의 연속 revision이다. J1/J2는 복원 성공으로 작성한 페이지 전체의 `replay_committed` 증거이며 NP04가 한 문장씩 표시한 `displayed` 증거와 별개다. 동일 원고 재조사는 획득을 반복하지 않지만 새로운 실패 실행은 같은 진단이어도 별도 revision이다. 현재 snapshot에서 획득한 출처만 인용하고, legacy의 사라진 이전 값·획득 시각·숨은 역할 정답은 재구성하지 않는다. B4 파형과 실패 해결 원고, 관련 게임 플래그는 한 커밋으로 저장한다. 수첩 소비 화면은 이 공급자 함수를 호출하지 않는다.

NP06에서 같은 행동으로 작성한 복수 원고는 `event_occurrence_id`와 작성 묶음의 `conversation_session_id`를 공유하지만 각 `presentation_token`은 다르다. 뒤이어 실제 표시하는 NP04 대사는 사건 ID를 공유하고 별도의 대화 세션을 연다. 작성 묶음은 대화 재개 커서나 읽음 증거가 아니다.

NP07 17종 사건 원고는 같은 계약으로 기록한다. `MIRROR_COATING`의 관찰/가설, `MIRROR_TRACING`의 원도/대조, `MIRROR_FAILURE`의 실제 실패/해결은 이전 revision을 보존한다. 잠김 상태에서 거절한 재입력은 새 실패가 아니며 정상 수면 뒤 실제 실패는 같은 진단이어도 새 revision이다. 원도에 채널 이름을 선행 작성하지 않고 실제 다섯 채널 대조 후에만 기록한다. C5 대조와 실패 해결은 한 커밋이며 J3 전체 페이지의 사건 작성은 문장별 대화 공개·저자 인증과 별개다.

NP08 8종 사건 원고도 같은 계약을 따른다. `BASEMENT_PLAN`은 미검증 자료 확보와 실제 중첩 검증, `BASEMENT_FAILURE`는 실제 압력핀 잠김과 해결, `BASEMENT_ACCESS`는 직접 검증한 개방, `BASEMENT_HEART`는 실제 보조 입력의 결과다. 수면 뒤 재개방은 과거 검증을 새 획득으로 만들지 않으며, 정상 안정화/보조 조사/확정 원고는 실제 공개된 출처만 연결한다. D4 원고와 필터 상태·D5 반응 선택은 원자 저장하되 미래 반응의 대사를 기록하지 않는다. 데모에서 억제한 결과 대화의 표시 관찰도 만들지 않는다. 지하 확인창은 NP08 콘텐츠로 공통 모달 writer를 사용하고 수첩 재열람/취소/기계 조작 확정을 구분한다.

NP09 11종 사건 원고도 같은 계약을 따른다. D5의 파열 요약, D6 조사, E1 기상/다른 아침, E2 핵심 보고와 조건부 색인은 실제 해당 사건에서 작성한다. 동결한 사용인 반응은 실제 표시 관찰만 출처로 인용하며 시선 선택은 반응 재선정이나 관계 변화가 아니다. E2 보고·색인·관계 허브 개방은 원자 저장한다. 선택하지 않은 질문의 답변이나 구형 진행 플래그만 있는 과거 자료를 선행 생성하지 않는다. 휴식 확인창은 NP09 콘텐츠로 공통 모달 writer를 사용하고 실제 BROKEN_RESET과 구분한다.

ledger와 archive, 호환용 문자열, 사건 진행을 하나의 저장에 넣는다. 실패 후보는 공개하지 않으며 NP03은 대기 요청을 유지하고 NP06~NP17 등록 원고는 사용자 재시도에서 미공개 후보를 다시 만든다. 조회는 쓰기를 실행하지 않는다. 정상 리셋은 ledger/출처를 보존하며, 의미 갱신은 이전 원고를 덮어쓰지 않는다. JSON의 정수 표현은 archive와 ledger 참조를 함께 정규화하고 소수 순번은 거부한다. 미래 ledger schema는 checksum 이후 호환 불가로 반환하여 원본/백업을 덮어쓰지 않는다. 현재 공급 범위와 실행 근거는 [생산자 연결 현황](../ideas/md/v04/issues/validation/notebook_content_mapping_status.md)을 따른다. 엔딩 후속 원고와 새 카드 UI는 아직 후속 작업이다. J5 획득은 아래 NP17 계약을 따른다.

J4 복원 시 선택한 문단 descriptor를 `last_feedback`에 저장하고 실제 표시한 한 줄만 별도 `displayed` 관찰로 기록한다. 전체 원고의 `replay_committed`는 대사 전체 열람을 뜻하지 않는다. 출처 없는 옛 인용은 `original_only_segments`의 문자열 그대로 표시하며 문자열 역검색 번역을 하지 않는다. 조사 종료 확인창은 당시 완료/기록 수·미완료 조합·예상 시간·최소 접근 경고만 선언 변수/segment로 고정한다. 목록·취소·확정·후속 게임 저장과 E3_4M 보상 없음은 서로 다른 계약이다. 이 연결은 프로세스 재시작 시 표시 커서 복원을 구현한 것이 아니다.

NP16 `core_v1.json`의 122개 정의는 F0-A~E 결과·정적/가변 화면·작성자/임시 의향 입력·원고를 분리한다. 규칙이 내보낸 명시적 증거 키와 허용 변수만 descriptor로 만들며 실제 표시한 문단만 관찰한다. 방/방위/역할/표식은 언어 독립 토큰이고 수치 변수는 JSON 왕복 뒤 정수로 복원한다. 표본 이름표는 추적 본문을, 조사점 이름은 조사 완료를, 자료의 과거 사건 언급은 그 사건을 직접 목격했다는 사실을 대신하지 않는다.

`queue_descriptor`는 scope 안에서 descriptor와 표시 언어별로 요청을 구별한다. 재그리기는 같은 요청을 쓰고 다른 공개 값은 새 토큰으로 보존한다. 실패한 요청은 원래 값으로 명시적 재시도하며 자동 입력으로 우회하지 않는다. 이 캐시는 현재 실행 범위이고 내구성 있는 재시작 커서는 별도다.

세 중첩 자료의 `visual`은 의미 버전별 경로/마커/선/고리/변환 기준의 동결 메타데이터다. 관찰의 선언 변수는 당시 변환 상태다. 향후 비교 렌더러는 이 둘로 표시하고 현재 퍼즐 상태나 정답으로 과거 그림을 재생성하지 않는다. 시각 자료 확대·비교 소비 UI는 아직 구현 전이다.

`ANON_PURPLE_RESIDENT_INDEX`, `F0_CURRENT_AUTHOR`, `F0_PROVISIONAL_INTENT`의 원고는 NP16의 단일 body 후보로 기존 공통 writer에서 게임 상태·ledger·archive와 원자 저장한다. 익명 인덱스는 연구원 관계 기록을 지급하지 않는다. 작성자 인증은 선택한 삶의 방향과 별개이고 세 임시 의향 모두 `ending_run.final_decision`을 변경하지 않는다. 출처는 실제 획득/공개한 기존 원고·목록·선택뿐이며, 이후 나올 응답이나 구형 완료 플래그에서 관찰을 추정하지 않는다. 식별 불가능한 옛 A1 표식은 원문 전용 descriptor로 보존한다.

NP17 `final_v1.json`의 66개 정의는 F1 원본/첨부 기록, J5 원고/표시, F2 관계별 발언/질문/누락 요약, F3 양쪽 절차/임시 의향/취소, EDC 확정 반응을 분리한다. 규칙의 명시적 `notebook_keys`만 표시 descriptor로 해석하며 상태 플래그만으로 본문을 소급 공개하지 않는다. 관계 분기·요약 순서·임시 의향은 그때의 원고 ID에 고정하며 재열람 때 다시 계산하지 않는다. EDC 확인창은 NP05와 중복 저장하지 않는다.

J5 전체 원고는 기존 게임이 작성한 7줄을 한 `body/replay_committed`로 보존한다. `f1_write`의 저장 후보에서만 획득하고, 페이지를 열거나 J5 완료 플래그를 로드한 것으로 새 revision을 만들지 않는다. 작성 결과 3문장의 `displayed`는 개별 표시 시점에만 남긴다. 획득한 J1~J4와 현재 작성자 원고, 이미 표시한 원본/페이지 관찰만 추가 출처로 인용하며 이후 작성 결과는 선행 출처가 아니다. 원본·시스템 사후 첨부의 출처 표기는 보존한다.

최종 결정 피드백은 엔딩 진입 이후 표시되더라도 행동 직전 EDC 문맥을 유지한다. 수첩 재열람은 임시 의향·권한·관계·최종 결정을 쓰지 않는다. F3에서 취소한 사실과 EDC에서 확인한 입력, 실제 엔딩 저장 성공은 별도다. 내구성 있는 앱 재시작 커서는 아직 후속 작업이다.

NP18 `reality_v1.json`은 공통 엔딩 진입/전원 인증, 인계, 감각 전환/몸 재관찰, 물리 수첩, 시설 조사와 마지막 시선의 153개 정의·168개 segment를 추가한다. 화면의 제목/상태와 실제 조사 본문은 다른 관찰이다. `reality_notebook.gd`는 `ending_run.current_node_id`와 표시 직전 장소를 캡처한다. NP05 공통 모달의 기존 stage 문맥은 변경하지 않는다. 화면 기록 scope에는 실제 엔딩 노드를 추가하여 같은 `ENDING_SEQUENCE` 내부 전환을 구분한다.

인계 규칙은 `notebook_keys`를 본문과 함께 반환한다. 완료/미완료, 두 관계 결과, 이리스 여섯 공개 분기, 친밀/경계 3단계, 이름 표식 여부는 표시 때 동결한다. 부기 무결성 경고가 있으면 부기를 기록하지 않는다. 몸 재관찰은 기존 `dialogue_observed_facts`와 같은 표시 transaction을 유지하며 갤러리 증거를 대체하지 않는다.

물리 페이지의 `REALITY_<page>`는 `lifetime=physical`이며 가상 수첩 원본이 현실로 이전한 것이 아니다. NP05 페이지 표시 관찰과 `field_read` 게임상 읽기 확인을 분리한다. 읽기 확인 후보에서 요약/펼침 및 그때 공개된 부기만 `document_segment/replay_committed`로 획득하며 필수 읽기 플래그와 원자 저장한다. Esc, 펼침 전환, 구형 읽음 플래그, 단순 재열람은 획득을 대신하지 않는다. 다음 색인 버튼은 현재 페이지를 확인한 뒤 다음 페이지를 표시할 뿐 다음 페이지를 완료하지 않는다.

같은 페이지의 같은 공개 내용 재확인은 revision을 추가하지 않고, 펼친 원고 뒤 요약 재확인은 원고를 요약으로 낮추지 않는다. 실제 새 부기/공개 내용은 이전 revision을 보존하며 갱신한다. 출처에는 같은 페이지의 실제 표시된 NP05 본문/부기와 획득한 연구원 revision만 연결한다. SUBJECT 인계 출처 목록은 색인이지 연구원 원문 자동 지급이 아니다. 게임 저장 실패는 읽기 완료와 자료 획득을 함께 롤백한다.

에어록 취소/진입과 마지막 시선은 실제 보인 선택지/클릭을 따로 기록한다. 시선은 이미 확정한 엔딩을 바꾸지 않는다. 마지막 화면 관찰이 미저장 상태이면 기존 8초 자동 진행의 누적과 tick을 멈추며, 명시적 재시도 뒤에만 재개한다. 일반 UI 목표/이동 안내/서명 지원/오류 안내는 `EXCLUDED_UI`, 내용이 있는 보드·색인·조사 상태는 명시적 관찰이다. 갤러리·기록 재열람에는 쓰기 경로를 추가하지 않는다.

전원 서명 도구의 완료 신호는 게임상 인증 완료와 다르다. 서명 전 화면 기록 저장이 실패하면 도구의 획을 유지하면서 입력을 다시 허용한다. 기록을 성공시킨 뒤 자동 서명 또는 직접 입력으로 재시도하며, 실패한 화면 때문에 서명 도구가 영구 완료 잠금 상태로 남지 않는다.

NP19 `stay_v1.json`은 잔류 기억/표시/자율성 정책, 중앙홀/식탁 조사, 조건부 대사, 착석/마지막 장면, 직접 작성하는 두 문장의 118개 정의·173개 segment를 추가한다. 이미 출판한 21개 카탈로그는 수정하지 않는다. 공통 도입과 전원 인증/서명은 NP18을 그대로 쓴다. `stay_notebook.gd`는 행동 전 실제 엔딩 노드와 장소를 보존하며, 현재 관계로 과거 대사를 재계산하지 않는다.

기억 원칙의 목록과 본문, 식탁 대상의 이름과 발언, 정책 선택지와 확정 클릭은 별도 관찰이다. 미완료 관계의 서술을 완료 발언으로 대체하지 않는다. 검증되지 않은 관계 outcome은 부기를 만들지 않으며 이리스 6개 공개 상태도 기존 규칙을 따른다. 착석 자료는 당시 관계 구성에 해당하는 도입과 각 인물의 한 상태만 저장한다. 전체 정의에 들어 있는 다른 상태는 검색·재열람용 공개 자료가 아니다.

`story_write`는 기존 `STAY_STORY.written`과 `STAY_SENTENCE_0/1`의 persistent 문서 revision을 같은 게임 저장 후보에 쓴다. 선택 문장을 표시하거나 구형 written 플래그가 존재하는 것만으로 문서를 지급하지 않는다. 출처는 현재 archive에 실제 표시/선택된 원문만 연결한다. 같은 문장의 재작성은 revision을 늘리지 않는다. 선택 클릭을 보존했더라도 게임 저장 실패 시 작성 완료·지식 revision은 함께 롤백한다. 재열람은 차 온도·정책·관계·필수 상호작용·엔딩을 쓰지 않는다.

잔류의 마지막 2초 전환은 화면 관찰 미저장 시 누적과 tick을 멈춘다. 명시적 저장 재시도 후 재개하며 새 슬롯/로드 이전의 콜백은 적용하지 않는다. 표시 모드/통신 선택 모달은 공통 기록 모달에 실제 엔딩 문맥을 명시적으로 전달한다. 기존 모달 호출의 기본 문맥은 변경하지 않는다. 크레딧/제작진/갤러리·재선택 UI, 단순 장소/목표/이동 안내, 골격 표시 상태와 조작 도움말은 `EXCLUDED_UI`다. 제작진 명단은 계속 미정이며 새로운 조사 자료로 발급하지 않는다.

NP07/NP08의 정적 퍼즐 표시는 `puzzle_surfaces_v1.json`의 53개 정의·68개 segment로 보완한다. 기존 22개 카탈로그의 의미 버전은 변경하지 않는다. 청소 기록 주변 안내, 현재 배합, 거울 변환/선택 경로, C5 채널의 실제 버튼 표시, J3 조각/배열, 서랍 기준점, 도면 변환, 축의 표시 깊이/밀기 완료, 창고 대상명과 심장 문양/레버 값을 당시 사건·장소에 기록한다. 대상명이 보였다는 이유로 조사 본문이나 사건 작성 원고를 지급하지 않는다.

`notebook_puzzle_surfaces.gd`는 명시적 공개 변수만 전달한다. 축을 민 뒤 화면에서 숨겨진 깊이는 기록하지 않는다. J3 조각 표시/배열은 J3 복원 완료가 아니다. 숫자는 저장 JSON의 정수/실수 표현과 무관하게 같은 표시를 만들며, 깊이 홈은 소수점 없이 1·2·3으로 표시한다.

공통 화면 기록 큐는 ChapterOneController에서 한 번 시작하고 파생 화면의 실제 표시 완료 뒤 저장한다. E/F/엔딩에서 대체되어 보이지 않는 C/D 중간 화면은 stage 허용 목록으로 제외한다. 같은 표시 재그리기는 중복 기록하지 않으며, 표시 저장 실패 뒤 게임 상태 변경은 명시적 재시도까지 보류한다. 슬롯/로드 문맥이 다른 예약 콜백은 적용하지 않는다. 수첩 안의 세정제 양 비교표는 기존 단서로 계산하는 읽기 전용 보조 도구로서 `EXCLUDED_UI`이며 체크 변경으로 새 관찰·지식·퍼즐 입력을 쓰지 않는다.

NP21의 1장 화면 자료는 `chapter_surfaces_v1.json`의 55개 정의·71개 segment로 기록한다. 기존 23개 카탈로그는 불변이다. 시간표 제목/읽음 표시, 내실 대상명과 에드가 압박, 일지 조각/앞뒤/배열, 당일 탁본과 시계 카드/역할/전달 시점, 잠금과 파형 방향을 명시적 표시 지점에 연결한다. 이름/표시 관찰과 조사 본문, 게임상 자료 획득, 퍼즐 성공은 서로 다른 상태다.

시계 카드에서 보이지 않는 뒷면이나 접힌 드롭다운의 후보는 저장하지 않는다. 실제 연 역할 후보 목록은 `document_segment`이며 서사 선택 동의가 아니다. 후보 창 표시와 현재 역할 배정의 변경은 구분한다. 표면 저장 실패 시 다음 조작을 보류하고 역할 버튼이 게임 상태와 다른 선택을 표시하지 않도록 복구한다. 단순 자리표시는 배정 해제가 아니다. 슬롯/로드/화면 세대가 다른 드롭다운 콜백은 적용하지 않는다.

공통 화면 큐는 실제 1장 stage에서만 이 자료를 기록하며 C/D 이후 파생 화면이 지운 기본 컨트롤러의 임시 자료는 제외한다. 같은 표시 재그리기와 응답 유실은 중복 원문을 만들지 않는다. 문서/조각/배정의 재열람은 지식·일지·관계·시간·물리 상태를 변경하지 않는다. J1과 B3의 정답·물리 규칙은 유지한다. 공통 수첩 소비 UI는 별도 후속이다.

NP21 프롤로그는 `prologue_surfaces_v1.json`의 82개 정의·88개 segment를 별도로 사용한다. 도구/책/이름표 명칭, 실제 창문 상태와 청소 피드백, 책장 배치, 초상화 이름표 부착, 차 순서/손잡이/도구 피드백, 날씨 조사 표시를 실제 표시 지점에서 전달한다. 창문 확대의 header/top/middle/bottom은 같은 관찰에 포함해 번호와 상태의 출처를 잃지 않는다. 미표시 방/초상화 이름/완료 타일과 도달 불가능한 방어 피드백은 기록하지 않는다. 기존 24개 출판 원고는 불변이다.

프롤로그 표시 scope는 저장 namespace·slot·load epoch·origin/branch에 장소·노드·날짜를 더한다. 오래된 화면 세대의 콜백과 다른 슬롯으로의 예약 기록을 차단한다. 표시 실패는 다음 입력을 보류하고 확대 화면 위의 명시적 재시도로 복구한다. 응답 유실·재렌더링은 중복 append하지 않고 실제로 반복한 도구 행동만 새 관찰로 취급한다. 이미 적용한 게임 행동을 재시도하지 않으며 표시·조회는 지식/진행을 변경하지 않는다. 차 준비의 보류된 예약 장면은 성공한 관찰 재시도 뒤 재개한다.

### 7.2 초기 저장 지점

| ID | 생성 조건 | 안전 재개점 |
| --- | --- | --- |
| `SAVE_P6_COMPLETE` | 첫 취침 확정 | NORMAL_RESET 진입 |
| `SAVE_NORMAL_RESET_COMPLETE` | 각 정상 리셋 transaction 완료 | 같은 아침 ROUTE |
| `SAVE_A2_COMPLETE` | 수첩 표시 지속 확인 | B1 진입 |
| `SAVE_J1_COMPLETE` | J1 원자 완료 | B3 준비 |
| `SAVE_J2_COMPLETE` | J2 원자 완료 | 다음 정상 리셋 |
| `SAVE_J3_COMPLETE` | J3 원자 완료 | D0 진입 |

동일 ID의 저장을 반복 생성할 수 있지만 최신 완전 transaction만 현재 진행으로 승격한다. 세계 리셋 도중의 중간 상태를 안전 지점으로 표시하지 않는다.

안전 저장 순서:

1. GameState snapshot을 고정한다.
2. schema와 불변식을 검사한다.
3. 논리 집합·Dictionary를 결정적 순서로 정규화한다.
4. SHA-256 checksum을 계산한다.
5. tmp 파일을 기록하고 다시 검증한다.
6. 기존 progress를 backup으로 보존한다.
7. tmp를 progress로 교체한다.

진행·접근성·엔딩 메타 파일은 서로 독립적으로 migration한다. 하나의 손상이 다른 파일을 덮어쓰거나 되돌리지 않는다.

## 8. Validation

빌드 전 최소 검사:

- 모든 event·node·location·object·text·signature ID가 등록되어 있다.
- 모든 prerequisite와 write state path가 선언되어 있다.
- 사건 category가 금지 상태를 쓰지 않는다.
- 선택 관계 사건이 F0·엔딩 진입을 막지 않는다.
- 논리 집합 배열에 중복·빈 ID가 없다.
- 필수 사건 graph가 entry에서 completion·return까지 도달한다.
- 모든 save point가 안전한 resume node를 가진다.
- 저장 헤더의 flavor·경계가 허용 event registry와 일치한다.
- 대화 기록의 `sequence`가 중복되지 않고 모든 `line_id`, `speaker_id`, `choice_id`가 등록되어 있다.
- 한국어·영어의 placeholder 집합과 타입이 같다.
- 색·음향·모션을 제거해도 필수 상호작용이 남는다.
- 진행 설정 변경 전후 진행 checksum payload가 같다.

오류는 조용히 건너뛰지 않는다. 필수 Resource 오류는 export를 차단하고 선택 Resource 오류는 해당 콘텐츠를 비활성화한 뒤 개발 오류 ID를 남긴다.

## 9. 통합 수첩 읽기 모델 1차

`notebook_query.gd`는 검증된 v2 archive와 `notebook_knowledge` ledger를 받아 하나의 동결된 조회 사본을 소유한다. GameState, SaveManager, 퍼즐 세션을 참조하거나 저장하지 않는다. 이번 변경은 저장 schema·원고 버전·일지 획득 조건을 변경하지 않는다.

- `open`의 scope는 namespace, slot, run_id, source_origin_id, branch_id, load_epoch다. archive 계통과 일치해야 한다. query generation, archive revision, 언어와 공개 정책 버전을 포함한 키가 있어야 페이지·상세·검색을 요청할 수 있다. `close`/재open은 이전 키를 무효화한다. 실제 슬롯 교체 탐지와 close 책임은 아래 게임 호스트에 있다.
- 최소 메타 색인은 저장된 관찰 segment만 대상으로 한다. 콘텐츠 정체성 불일치는 부분 표시 오류로 보고하고 정상 자료는 유지한다. archive/ledger 구조 손상은 조회를 열지 않으며 저장 복구 검사를 우회하지 않는다.
- 현재 `단서/대화/기록/인물` 분류는 실제 지식 revision의 category와 관찰 종류를 사용한다. 인물 보기는 실제 발화한 사용인과 실제 획득한 인물 기록만 연결하며, 구형 본문 문자열에서 인물이나 당시 관계를 추론하지 않는다. 인물별 묶음과 공개 필터는 9.4절을 따른다.
- 완전히 보지 않은 복합 원고에는 전체 제목·요약을 붙이지 않는다. 제목·요약의 개발용 사건 코드도 플레이어 라벨 대신 일반 보관 기록으로 표시한다. 이미 공개된 본문을 임의로 번역·재작성하지 않는다.
- 조회 결과 ID는 원 출처·UID·의미 버전·segment 참조다. 지식 카드 출처는 같은 조회 내 실제 존재하는 참조에만 연결한다. 이전 revision과 반박된 내용은 원본을 보존한 채 기본 목록에서 접으며 명시적으로 다시 열 수 있다.
- 페이지는 50개 이하, 상세는 요청한 한 segment만 렌더링한다. 패널 미리보기도 해당 페이지의 최대 50개에 한정한다. 기존 호환 renderer에는 legacy 한 항목만 전달한다. 전체 대화를 렌더링한 뒤 자르는 경로는 없다.
- 검색은 최대 50개씩 색인을 진행한다. UI는 프레임당 12개씩 요청하고 완성 전에는 검색 중이라고 표시한다. 검색 대상은 공개 제목·요약·화자·장소/출처 유형의 표시명·현재 언어 원문이며 내부 ID, 숨은 뒷면, 미요청 힌트는 포함하지 않는다. 검색 중의 부분 결과를 사용자 커서 아래에서 계속 재정렬하지 않는다.
- 같은 필터 안에서는 OR, 다른 필터 간에는 AND다. 공개된 자료에서만 facet을 만든다. 페이지가 줄면 유효 범위로 조정하고, UID 앵커가 사라지면 다음 정렬 키, 마지막 이전 항목, 빈 상태 순서로 복귀한다.
- 비교는 이미 영속 저장된 `comparison`의 최대 12개 참조 중 A/B 두 개를 선택한다. 좁은 화면에서는 동일한 두 선택을 유지하며 A/B 화면만 바꾼다. 이 UI는 재료 조합 도구나 퍼즐 판정을 호출하지 않는다.
- 읽음·책갈피 추가/해제·비교 묶음 변경·일지/field_read 완료를 읽기 모델에서 쓰지 않는다. 책갈피 필터와 이미 담긴 비교 참조의 읽기는 가능하다. 실제 변경 버튼과 실패 재시도는 `notebook_host`가 `notebook_commands`에 위임한다.

최초 읽기 모델만으로 본편 연결을 완료한 것은 아니다. 이후 메뉴/N키 전환과 타이머 중단은 9.1절, 구형 문자열 수첩 어댑터는 9.2절, 읽음·열람 위치 sidecar는 9.3절, 시각 자료 조회는 9.5절을 따른다. 자유 메모는 범위 밖이며 앱 재시작 후 게임 대화/선택 커서는 잔여 작업이다. 집중 실행 명령은 `--notebook-query-smoke`이며 실제 OS 입력·성능 예산 인수와 구분한다.

### 9.1. 본편 호스트와 참조 저장

개발 옵션 `--ggb-dev-notebook-v2`와 schema 2인 실제 플레이에서 `notebook_host.gd`가 N키/수첩 버튼과 대화 기록 메뉴를 같은 패널로 연결한다. 기본 공개 옵션은 여전히 비활성이다. 수첩 버튼은 기존 모달·대화 레이어보다 뒤의 자식 순서로 배치해 마우스로도 접근할 수 있다. 현실 공간의 N키는 별도 현장 인계 수첩을 유지한다.

| 책임 | 계약 |
| --- | --- |
| 조회 | 동결 사본만 읽는다. 단순 검색·상세·비교·닫기로 새 관찰, 지식, 완료 플래그를 쓰지 않는다. |

| 입력 계층 | 검색 편집의 Esc는 편집만 취소한다. 비교/출처 복귀/상세/검색/닫기 순으로 한 단계씩 처리한다. 휠 펄스는 해제 대기 입력이 아니며 PgUp/PgDn은 현재 본문을 스크롤한다. |

| 보조 도구 예약 | 수첩 닫기 이후의 지연 호출도 실행 직전에 namespace/slot/origin/branch/load epoch와 본편 세션 인스턴스를 재검사한다. 컨트롤러 소유 동작만 실행하며 새 수첩·메뉴 등 입력을 막는 화면이 있으면 이전 요청을 폐기한다. 도구 목록 열기는 힌트 최초 공개나 게임 행동의 승인이 아니다. |
| 저장 | `bookmarks` 50개, `comparison` 12개 한도. 의미 참조와 command UID를 고정하고 기대 GameState revision/scope를 검사한 뒤 원자 저장한다. |
| 실패 | 실제 저장 실패는 원상복구 후 같은 UID로 재시도. 응답 유실은 정확한 저장 payload 확인으로만 복구한다. 외부 변경 revision을 자동 수용하지 않는다. |
| 해제 | 정리 대상이 될 수 있음을 먼저 알리고 취소/확인을 받는다. 확인 전에는 보호 상태가 바뀌지 않는다. |
| 갱신 | 명시적 갱신 또는 성공한 참조 저장 뒤 선택 자료/필터/출처 뒤로 가기/A·B 선택을 보존한다. 언어 변경은 새로운 조회 키를 만든다. |
| 폐기 | 컨트롤러 제거·슬롯/계통/로드 세대 변경 시 모델과 표시를 비운다. 다른 저장을 읽는 옛 컨트롤러는 재개하지 않는다. |
| 도구 | 기존 수첩 원문, 명시적 힌트 요청, C3 수량 계산은 별도 도구다. 진행 중 대화/선택/확대창 위에서는 도구로 원래 흐름을 교체하지 않는다. |

호스트의 집중 검사는 `--notebook-host-smoke --ggb-dev-notebook-v2`다. 구형 문자열 수첩의 통합 검색은 아래 9.2절, 읽음·열람 위치는 9.3절로 확장한다. 갤러리 호스트, 재실행 후 게임 대화/선택 커서와 실제 Windows IME·입력 인수는 별도 잔여 범위다. 메뉴를 연결했다는 이유로 이 범위까지 완료 처리하지 않는다.

### 9.2. 기존 문자열 수첩의 조회와 원문 고정

`notebook_legacy_notes.gd`는 `knowledge_entries.prologue_notebook_entries`의 문자열 배열과 `knowledge_entries.chapter_notebook`의 문자열 값만 읽는다. 원래 컨테이너가 정본이며, 수첩을 열 때 전부 archive로 이관하거나 기록을 다시 획득하지 않는다. `open`에 전달한 knowledge에서 이 두 컨테이너 이외의 상태·숨은 플래그는 조회하지 않는다.

| 항목 | 계약 |
| --- | --- |
| 식별 | 어댑터 버전, `source_origin_id`, 컨테이너, 배열 인덱스/사전 키, 원문 전체로 결정적 UID를 만든다. 같은 주소의 값이 바뀌면 다른 UID이며, 서로 다른 주소의 같은 문장은 임의 병합하지 않는다. |
| 조회 | 단서 탭의 `이전 수첩 원문 / 시점 미상`으로 표시한다. 실제 남은 문자열만 검색하며 내부 사전 키·위치·인물·획득 시점은 검색어 또는 서사 정보로 추정하지 않는다. |
| 언어 | 저장 원문의 공백·줄바꿈·언어를 보존한다. UI 언어를 바꿔도 원문을 역검색하여 번역하지 않는다. 작성 언어와 과거 갱신 시점 미상을 알린다. |
| 정렬 | 시점을 아는 관찰 뒤의 시점 미상 자료로 둔다. 사전의 직렬화 키 순서가 달라져도 안정적인 순서를 유지하지만 이를 획득 순서로 부르지 않는다. |
| 캐시 | 조회 키에는 legacy 투영 UID 목록과 오류 진단의 digest도 포함한다. archive revision이 같아도 원문 마지막 값이 바뀐 새 조회와 섞지 않는다. |
| 명시적 고정 | 책갈피/비교 추가 명령이 현재 scope·GameState revision과 현재 정본의 UID를 재검사한다. 아직 archive에 없는 자료만 원문 스냅샷과 보호 참조를 한 저장 트랜잭션으로 추가한다. |
| 저장 형식 | archive schema 2의 `legacy` 래퍼를 사용한다. 추가 필드 `notebook_legacy_source`는 `{version: 1, container, locator, text_sha256}`이며 exact-key·타입·원문 hash·UID 일치를 검증한다. 내용 참조는 기존 `legacy / content_version: 0 / segment_id: legacy`다. |
| 순번 | archive sequence는 고정 스냅샷의 저장 순번이지 원래 수첩 획득 시점이 아니다. 대화 발생·발화 증거나 새 지식 revision으로 계산하지 않는다. |
| 중복 | 현재 마지막 값과 고정된 원문의 UID가 같으면 한 행만 표시한다. 이후 정본의 값이 바뀌거나 사라져도 고정된 원문은 별도 보존한다. authored 지식과의 연결 증거가 없는 원문은 문장 유사도로 합치지 않는다. |
| 보존 | 기존 미분류 보존 정책을 적용하여 일반 대사 최근 2,000개 상한에 넣지 않는다. 책갈피/비교를 해제해도 legacy 원문을 자동 삭제하지 않는다. 참조 한도 초과 시 원문만 남는 중간 상태를 설치하지 않는다. |
| 실패 | 저장 거절 시 원문 스냅샷과 참조를 함께 원복한다. 같은 command UID로 재시도하며 응답 유실은 실제 저장 payload의 일치로만 복구한다. 이미 덮어쓴 미고정 원문을 옛 조회 참조만으로 복구하지 않는다. |
| 읽기 부작용 | 조회·검색·A/B 교체는 `field_read`, 몸 재관찰, 일지·관계·퍼즐·엔딩 플래그를 쓰지 않는다. 갤러리의 구형 대화 원문 호환 판정에서도 이 전용 스냅샷을 제외한다. |
| 부분 오류 | 잘못된 컨테이너 또는 문자열이 아닌 값은 오류 진단과 정상 원문을 분리한다. 사전/배열을 문자열로 만들어 공개하거나 손상된 슬롯 자체의 검증을 우회하지 않는다. |

기존 전체 원문 도구는 호환 진입으로 유지하지만 통합 검색·고정에는 필수가 아니다. 개인 자유 메모 편집기를 추가한 것이 아니며, 사라진 과거 revision도 재구성하지 않는다. `--notebook-query-smoke`가 어댑터의 읽기·실제 파일 저장/재열람 검사를 함께 실행하고, 실제 호스트 경로는 별도 호스트 검사에 포함한다.

### 9.3. 읽음 표시와 열람 위치 sidecar

`notebook_view_store.gd`는 게임 슬롯과 별개인 편의 파일만 저장한다. 본문·지식·책갈피·비교 묶음의 정본은 계속 게임 snapshot이며 이 파일을 통해 획득하거나 복구하지 않는다. 쓰기 스키마 버전은 `4`, 기본 경로는 `user://profile/notebook_views/`다. 버전 1·2·3 편의 파일은 읽을 수 있고 다음 정상 UI 저장 때 버전 4로 기록한다. 버전 2는 공개 필터, 버전 3은 시각 자료 열람 위치, 버전 4는 출처 왕복의 목록/상세/비교 복귀 모드를 구분한다. 기존 게임 저장 스키마와 동결 원고 버전은 변경하지 않는다.

| 경계 | 계약 |
| --- | --- |
| 영속 범위 | `profile, namespace, slot, run_id, source_origin_id, branch_id`의 여섯 문자열. 정렬 JSON의 SHA-256만 파일 이름에 사용한다. 슬롯 이름을 경로로 직접 쓰지 않는다. |
| 프로필 | 현재 제품의 단일 로컬 프로필은 `local`이다. 운영체제 사용자별 `user://` 분리와 별개다. 다중 프로필 UI는 구현하지 않았으며 향후 호스트의 `view_profile`과 저장 루트로 주입할 수 있다. |
| 런타임 범위 | `load_epoch`는 영속 파일 이름에서 제외한다. 같은 슬롯의 재로드는 같은 UI 상태를 읽되 이미 열린 호스트의 낡은 epoch는 즉시 무효화한다. |
| 과거 판별 | `frontier`는 `archive_revision, next_sequence, last_uid, knowledge_revision, legacy_digest`다. revision/순번이 줄거나 같은 끝 순번의 UID가 다르거나 동일 revision의 원문 digest가 다르면 미래 열람 상태를 모두 버린다. 공식 백업 복구/F3의 별도 branch 분리도 유지한다. |
| 파일 | `version, payload, checksum`만 허용하는 envelope. payload는 `scope, frontier, state`를 담은 정렬 JSON 문자열이며 그 정확한 문자열 hash를 검증한다. checksum은 손상 탐지용이지 사용자 인증이나 접근 권한 증명이 아니다. |
| 교체 | 임시 파일 쓰기·flush·재읽기·schema/hash/직렬화 원문 대조 후 정상 주 파일을 백업하고 교체한다. 잘못된 주 파일로 정상 백업을 덮어쓰지 않는다. 교체 실패 시 기존 백업에서 주 파일 복구를 시도한다. |
| 복구 | 주 파일 손상 시 같은 범위의 정상 백업, 둘 다 손상 시 빈 편의 상태. 새 schema의 주 파일 또는 백업은 덮어쓰지 않으며 쓰기를 비활성화한다. 기록 본문·고정 자료는 게임 snapshot에서 계속 읽는다. |
| 저장 시점 | 화면 변경 후 350ms 유예, 닫기 시 flush. 복원 중의 불완전한 화면이나 scope 무효화 뒤의 상태를 저장하지 않는다. 실패는 수첩 안내와 복귀 후 상태 문구로 알리고 게임 진행 복귀를 막지 않는다. |

`state`의 exact-key 필드는 `seen, groups, general, dialogue`다. 앞의 두 필드는 중복 없는 비어 있지 않은 문자열 배열, 뒤의 두 필드는 빈 사전 또는 다음 열람 구조다. 임의 필드·잘못된 타입·NaN·범위 밖 비율은 거절한다.

| 열람 구조 필드 | 내용 |
| --- | --- |
| `filters` | 현재 읽기 모델이 허용하는 필터만 사용. 복원할 때 더 이상 공개 자료에 없는 facet은 제거한다. 검색 색인이 완료될 때까지 UID 복원을 기다린다. |
| `selected, anchor` | 선택 참조 키, 해당 정렬 키 3개와 비율. UID가 없으면 실제 공개 자료의 가까운 항목 또는 빈 화면으로 이동하고 안내한다. |
| `page, list_scroll, list_anchor` | 페이지·이전 픽셀 위치와 첫 가시 행의 UID/정렬/행 내 비율. 복원 기준은 행 앵커이며 목록 순번만으로 다른 자료를 선택하지 않는다. |
| `scroll, body` | 이전 픽셀 위치와 `{paragraph, fraction}`. 문단은 0부터, 제목 영역은 -1, 비율은 0~1. 글자 배율·UI 언어가 달라져도 문단 상대 위치로 복원한다. |
| `pair, pair_body, comparing, side` | 현재 게임 snapshot의 비교 묶음에서 두 참조·각 본문 앵커·비교 여부·좁은 화면 A/B 위치(0/1). sidecar만으로 자료를 묶음에 추가하지 않는다. |
| `detail, back, focus` | 상세 표시, 최대 32단계의 출처 복귀 참조/본문/포커스, 의미 있는 제어 이름/행 참조. 버전 4의 back 항목에는 선택적으로 `view: {detail: bool, comparing: bool}`을 보관한다. 빈 key는 자료 미선택 목록으로 돌아가는 경계다. NodePath와 기존 노드 객체를 저장하지 않는다. |
| `visuals` | 버전 3의 최대 64개 관찰 참조별 `{zoom, x, y}`. 배율 1~4, 정규화 이동 -1~1이며 유한 수치만 허용한다. 구형 열람 구조에는 없어도 된다. 게임 회전·반전·배선·정답은 저장하지 않는다. |

일반 N/버튼 진입은 `general`, 메뉴 대화 기록은 `dialogue`를 복원한다. 최초 일반 진입은 최근 단서 목록, 최초 대화 기록은 최신 세션의 마지막 발화다. 대화 탭의 방문 위치는 어느 입구에서든 기억하지만 대화 기록 메뉴로 들어와 다른 탭을 둘러본 것은 `general`을 덮어쓰지 않는다. `dialogue` 필터는 항상 대화 탭이어야 한다. 현실 N키는 계속 물리 수첩이다.

`seen`은 정확한 공개 자료/segment 참조 키다. `groups`는 같은 지식 UID/segment의 revision 묶음이며 기존 원문은 출처·컨테이너·주소로 묶는다. 신규 `[신규]`, 구형 시점 미상 `[미열람]`, 이미 본 자료의 새 revision `[갱신]`을 구별한다. 목록 미리보기·자동 초기 선택·복원·숨겨진 비교 자료는 읽음으로 바꾸지 않는다. 직접 상세를 열거나 비교 중 실제 가시 자료를 선택한 경우에만 해당 참조의 배지를 지운다. 목록 정렬·형제 배지·일지/field_read/최초 공개 플래그는 변경하지 않는다. 현재 조회에 없는 참조와 그룹은 편의 상태에서 제외한다.

UI sidecar의 파일 재로드와 컨트롤러 재생성 검증은 진행 중 게임 대화/선택 토큰의 앱 재시작 복원과 다르다. 후자는 아직 후속이다. 본 절 집중 검사는 `notebook_view_smoke.gd`(조회 검사에서 실행)와 실제 `notebook_host_smoke.gd`에 포함하며 실제 Windows 입력 인수를 대신하지 않는다.

### 9.4. 공개 인물·대화 묶음과 필터 탐색

`notebook_browse_labels.gd`는 표시명 사전, `notebook_query.gd`는 동결된 자료의 집계, `notebook_browser.gd`는 필터 초안과 인물/대화 묶음 표시를 담당한다. 표시명 사전에 항목이 있다는 이유만으로 공개하지 않는다. 같은 조회에 실제 남아 있는 값만 라벨과 facet으로 반환하며 미관찰 장소·인물에는 미확인 표시를 사용한다.

| 항목 | 계약 |
| --- | --- |
| 인물 식별 | 실제 화자 또는 명시적으로 획득한 연구원 기록의 매핑만 사용한다. `MARA`는 기존 마라 1 별칭으로 정규화한다. 관계 수치·잠재 고백·미공개 프로필은 조회하지 않는다. |
| 익명 자료 | `ANON_PURPLE_RESIDENT_INDEX`는 신원 미확인 인물 자료로 남긴다. 보라색, 같은 장소, 원문 유사성만으로 마라 2에게 합치지 않는다. 후에 마라 2 기록을 얻어도 별도 근거 없는 익명 자료의 소유자를 소급 확정하지 않는다. |
| 인물 카드 | 실제 보관 부분 수, 발언/기타 자료 수, 공개 장소, 가장 최근 보관 원문의 120자 이하 미리보기다. 최신 문서가 있다면 예전 발언보다 우선한다. 새 전기·감정·관계 평가를 생성하지 않는다. |
| 대화 식별 | `source_origin_id + event_occurrence_id + conversation_session_id`의 복합 키를 사용한다. 세션 ID가 우연히 재사용되어도 다른 발생을 합치지 않는다. 미분류 구형 기록은 UID별로 남긴다. |
| 순서·이동 | 대화 묶음은 최근 보관 순서, 내부는 sequence와 segment 순서다. 인물 목록은 전체 공개 보관 자료에서 가장 이른 관찰 순서이며 새 기록·화면 필터로 순서를 바꾸지 않는다. 진입은 해당 묶음의 마지막 보관 발언이며 발언이 없으면 마지막 보관 부분이다. 이전/다음/마지막 발언 버튼은 같은 발생·세션 안에서만 이동하고 활성 버튼으로 키보드 포커스를 유지한다. |
| 부분 보존 | 수량은 보관 중인 부분 수이지 원래 대화의 총 문장 수나 완료 여부가 아니다. 정리된 일반 발언을 복원하지 않는다. 같은 내용 재청취도 별도 발생으로 둔다. 완결 증거 없는 자동 반복 묶기와 추정 루프/일차 라벨은 추가하지 않는다. |
| 필터 | `chapters, locations, speakers, categories, epistemic, provenance, sources, people, sessions`는 문자열 배열이다. 같은 필드는 OR, 서로 다른 필드는 AND다. 출처 유형 `sources`와 출처 검증 상태 `provenance`는 다르다. |
| 필터 편집 | 공개 facet의 표시명을 사용한다. 적용 전에는 초안만 수정하며 돌아가기/Esc는 취소한다. 상세·비교와 겹치지 않는 스크롤 패널에서 Tab/Shift+Tab, PgUp/PgDn을 사용할 수 있다. 긴 안내는 목록과 함께 스크롤하고 돌아가기/적용과 페이지 이동은 고정한다. 닫기·조회 교체 후 이전 콜백은 무효다. |
| 전체 검색 | 기본은 현재 분류다. 빈 결과에서 사용자가 `획득한 전체 기록에서 검색`을 고르면 `all_sections: true`로 공개 분류만 합친다. 이를 새 자료 공개 권한으로 사용하지 않는다. 복원 때 이 범위를 고려하여 타 분류에만 있는 필터를 지우지 않는다. 상위 탭 전환은 전체 검색/세션 제한을 해제한다. |
| 출처 왕복 | 실제 획득한 지식 revision의 유효 `source_refs`에서만 역방향 관련 기록 링크를 만든다. 원문에서 지식 카드로 이동하고 같은 원문으로 돌아올 수 있다. 숨은 정답·미획득 가설을 연결하지 않는다. |
| 비용·읽음 | 묶음도 한 페이지 최대 50개다. 집계는 원문을 렌더링하지 않으며 인물 미리보기만 가시 페이지의 자료를 읽는다. 묶음을 보는 것만으로 모든 자료를 읽음 처리하거나 게임 상태를 저장하지 않는다. |

적용된 필터는 9.3절 sidecar에 저장한다. 미적용 초안과 임시 탐색 화면은 저장하지 않는다. 필터 확장 당시 버전은 2이며 현재 쓰기 버전과 과거 호환은 9.3절을 따른다. 집중 검사는 `notebook_browse_smoke.gd`를 포함하는 `--notebook-query-smoke`다. 본 확장은 퍼즐 화면 판정·두 자료 비교 한도·일반/보호 보존 정책을 변경하지 않는다.

### 9.5. 시각 자료 재열람과 확대

`notebook_visuals.gd`는 관찰된 콘텐츠 ID·의미 버전·segment를 검사해 읽기 전용 벡터 명세를 만든다. `notebook_visual_canvas.gd`는 단색의 선·원·사각을 그리고, `notebook_visual_viewer.gd`는 열람 배율과 이동만 처리한다. 본편 퍼즐 판정 클래스나 현재 GameState를 호출하지 않는다. 최종 아트 교체가 아니라 기존 퍼즐의 단서 구조를 재열람하는 기능이다.

| 지원 원문, 버전 1 | 공개 조건과 표현 |
| --- | --- |
| `NB_CH1_NOTE_B4 / body` | 파형 기록 사건이 확정한 원문만. 진입·비대칭 반사·잔류 고리의 기록을 점선·사각으로 표시한다. 이후 코어의 공통 기준 마커나 검증된 회전을 붙이지 않는다. |
| `NB_MIRROR_NOTE_C5_INFO / body` | 회로와 다섯 채널을 대조·기록한 원문만. 실선·원으로 반사 원도를 표시한다. 출처·장소 기준은 같은 기록 본문과 함께 읽으며 평면도 정답을 새로 생성하지 않는다. |
| `NB_BASEMENT_NOTE_D4 / body` | 보조 입력 결과가 기록된 원문만. 중앙과 주변 네 포트의 잔상을 표시한다. 이후 중첩의 정답 위치·역할·권한 라벨은 추가하지 않는다. |
| `NB_CORE_SCREEN_C_LAYER_B4/C5/D4 / body` | 해당 자료층을 실제로 본 관찰만. 동결 `core_v1.json`의 경로·마커·고리와 저장된 각도·반전·기준점 변수를 사용한다. 다른 자료층을 함께 가져오거나 현재 게임 입력으로 대체하지 않는다. |
| `NB_PUZZLE_OVERLAY_0~4 / state` | 거울 확대창의 state segment를 실제로 본 경우만. 당시 실선·점선·원·사각과 기록된 배치를 재현한다. 제목만 본 관찰이나 텍스트 보드만으로 그림을 공개하지 않는다. |

확인되지 않은 버전, legacy 문자열, 미획득 참조는 현재 그림으로 대체하지 않는다. 알려진 그림의 저장 변수가 재현 불가능하면 시각 자료 오류를 알리되 원문과 다른 자료의 조회는 유지한다. 원래 카탈로그 25개는 수정하지 않으며 새 그림 표현의 의미를 바꿀 때도 과거 버전의 그림을 덮어쓰지 않는다.

| 열람 동작 | 계약 |
| --- | --- |
| 상세·비교 | 선택한 자료의 미리보기와 선/문양 설명을 제공한다. 비교 묶음의 B4·C5·D4 중 두 개를 선택·교체하며 수첩에서 자동 중첩·판정을 하지 않는다. |
| 확대 | 명시적 확대/축소·네 방향 이동·기본 위치 버튼. 배율은 100~400%로 제한한다. 휠과 드래그는 보조이며 방향키는 자료 영역 포커스에서만 소비한다. |
| 복귀 | Esc 또는 `자료로 돌아가기`는 확대만 닫고 원래 상세/비교·A/B 두 선택·좁은 화면의 선택 면·포커스를 유지한다. 수첩 자체의 닫기는 기존 호스트의 입력 해제 대기를 따른다. |
| 색·문자 | 단색 선 굵기·점선·원·사각과 한국어/영어 설명을 병행한다. 저장 당시 투명도는 글로 알리고 단색 선의 판독성을 유지한다. 투명도를 정답 힌트나 현재 퍼즐 변경으로 사용하지 않는다. |
| 작은 화면 | 확대 화면 내용은 독립 스크롤하며 돌아가기 버튼을 내용 밖에 둔다. 720p/200%에서도 닫기·돌아가기를 유지하고 비교는 기존 A/B 전환을 따른다. |
| 위치 저장 | 의미 참조마다 배율·정규화 이동을 최대 64개 편의 항목으로 보관한다. 한도를 넘으면 이전 편의 위치 하나만 비우며 원문·비교 참조·책갈피는 삭제하지 않는다. 없는 관찰의 위치는 복원하지 않는다. |
| 생명주기 | 조회 키·슬롯/계통이 달라지거나 패널을 닫으면 그림과 콜백을 폐기한다. 큰 전체 자료를 색인이나 목록 미리보기 단계에서 로드하지 않는다. |

`notebook_visual_smoke.gd`의 순수 명세·패널·실제 편의 파일 검사와 호스트의 F0-C 미확정 입력 복귀 검사를 함께 사용한다. 자동 도형 대조/버튼 신호 검사는 최종 아트 검수, Windows 네이티브 입력 완주, 실제 기기 성능 인수를 대신하지 않는다. A1 등 다른 매체는 계획의 후속 점검 범위이며 현재 조사 자료 바로가기는 9.7절을 따른다.

### 9.6. 검색 일치 위치와 원문 표시

`NotebookQuery.search_matches`는 현재 조회의 공개 참조·의미 버전·segment를 먼저 확인한 뒤 본문·제목·요약·공개 화자·장소·자료 유형과 공개 조건을 통과한 유지 범위/반복 안내의 일치 범위만 반환한다. 공백 제거와 대소문자 무시 방식의 일반 부분 문자열 검색이며 정규식이나 답변 생성을 하지 않는다. 각 필드를 독립적으로 검색해 제목 끝과 요약 시작이 가짜 한 문장처럼 일치하지 않게 한다. 실제 본문 안의 줄바꿈은 검색할 수 있다. 동일 segment의 여러 일치 지점은 검색 결과 건수를 늘리지 않는다.

- 명시적으로 결과를 열면 첫 본문 일치 지점, 본문에 없으면 공개 메타데이터의 일치 지점으로 이동한다. 이전/다음 일치 버튼과 `일치 n/m · 본문/제목/장소...` 안내로 같은 자료 안에서 앞뒤 이동한다.
- 검색 중 원문은 `notebook_search_text.gd`에서 문자 그대로 표시한다. BBCode 같은 문자열도 태그로 해석하지 않는다. 일치 부분은 밑줄, 현재 일치는 흰 바탕/검은 글자와 순번 안내를 병행해 색 구분에 의존하지 않는다.
- 본문 전체 길이의 비율로 이동하지 않고, 실제 줄바꿈된 글자 위치를 사용한다. 긴 한 문단과 200% 글자에서도 해당 줄이 화면 안에 오도록 한다. 버튼은 본문 스크롤 밖에 두며 끝에서는 활성 반대 방향 버튼으로 포커스를 옮긴다.
- 재열람 복원과 원문 링크 왕복은 저장한 문단 위치가 우선이다. 자동 복원만으로 첫 검색 결과에 강제 이동하거나 읽음 처리를 하지 않는다. 일치 순번은 파생 UI 상태이며 추가 gameplay/sidecar 필드로 저장하지 않는다.
- 검색 입력 변경·해제, 탭 전환, 자료 교체, 조회 무효화는 대기 중 이동을 취소한다. 숨은 상세/비교/확대 화면 뒤로 포커스를 보내지 않는다. 비교 화면은 원문 강조만 제공하고 정답을 판단하지 않는다.
- 색인 준비 중은 기존 진행 안내를 유지한다. 일치 지점 API 역시 숨은 segment·낡은 조회 키를 거절하고, 이미 저장된 과거 원문 fallback 범위만 사용한다. 원고 25개와 보존 정책은 변경하지 않는다.

인물의 보관 자료상 첫 확인 순서와 실제 최초 만남 시점은 구분한다. 이미 과거 기록이 정리되었거나 legacy만 있는 경우 사라진 최초 시점을 추정하지 않는다. 이후 정상적인 정리로 최초 근거가 사라지지 않도록 9.8절의 출처 보호를 적용한다. 전체 생산자에서 최초 발언이 실제 캡처되는지는 별도 분기 감사 대상이다.

집중 검사는 `notebook_search_smoke.gd`를 포함한 `--notebook-query-smoke`다. 720p/1080p·한영·100/150/200%의 엔진 레이아웃/버튼 검사는 Windows 배율·IME·물리 입력 인수를 대체하지 않는다. 글자별 줄 위치는 [Godot RichTextLabel API](https://docs.godotengine.org/en/stable/classes/class_richtextlabel.html)의 `get_character_line`과 `get_line_offset`을 사용한다.

### 9.7. 현재 조사 관련 자료

컨트롤러는 수첩을 열 때 실제 표시 중인 대사/질문의 고정 `node_id`를 우선 전달하고, 그렇지 않으면 현재 사건 stage를 전달한다. 진행 상태가 다음 사건으로 넘어갔더라도 직전 발언을 읽는 중에는 그 발언의 사건을 사용한다. 분류되지 않은 활성 발언에서 다음 stage를 추측하지 않는다. 조회 모델은 이 문맥을 포함한 캐시 키로 동결하며 GameState·퍼즐 solver를 직접 읽지 않는다.

`notebook_investigation.gd`의 편집상 사건 묶음은 **관련성 규칙**이지 획득 조건·정답 목록이 아니다. 조회에 이미 존재하는 authored 관찰의 `event_id`만 대조하고 실제 지식 revision의 직접 `source_refs`를 추가한다. 전체 원고 카탈로그에서 제목이나 미공개 segment를 생성하지 않는다. 이벤트 ID는 UI에 출력하지 않으며 화면 제목은 항상 일반적인 `현재 조사 관련 자료`다.

| 주요 조사 문맥 | 이미 공개된 자료 중 포함할 범위 |
| --- | --- |
| B3·실패/숏컷 | B1, J1, 네 시계 관찰, B3 시도·실패 |
| C3 | J2, 거울 코팅/청소 가설, C2·C2-1, 이미 수행한 조합 기록 |
| C4·실패 | B4, J2, C3, 신호와 거울 시도·실패 |
| D0·D0-A | C5, J3, 평면도·공간 대조 |
| F0-C | B4·C5·D4와 해당 중첩의 실제 표시·요청한 힌트 |
| F0-D | J4, 실제 공개된 연구원 자료와 에드가 권한, 해당 분류 시도 |
| F0-E | A1·A2의 과거 revision, 현재 주체/임시 의향. J5는 이 묶음에 선별하지 않음 |
| 그 밖의 현재 사건 | 프롤로그 일과, 수첩 실험, 서재, 지하 장치, 파열/보고, 각 관계 사건, 결산, F0-A/B·아버지 기록/최종 확인, 선택한 엔딩의 실제 관찰 |

세부 대응은 코드의 고정 TOPICS/ALIASES를 따른다. 새 stage가 미등록이면 추측해 묶지 않고 바로가기를 비활성화한다. 문맥을 알고 있어도 획득 자료가 없으면 일반 빈 안내만 제공한다. 미획득 예상 개수·잠긴 제목·다음 장소·미고백 의도·미요청 힌트는 표시하지 않는다. 과거/반박된 내용은 관련성이 있으면 제외하지 않고 이전 내용/반박됨 라벨을 붙인다. 정답 상태나 관계 수치로 추천 자료를 좁히지 않는다.

- 버튼을 직접 눌러 한 페이지 최대 50개의 관련 목록을 연다. 기존 탭·검색·필터·일반 목록 페이지는 바꾸지 않으며 해당 제한과 무관하게 실제 공개 자료를 탐색한다. 목록만으로 읽음·최초 공개·필수 읽기를 기록하지 않는다.
- 항목을 고르면 기존 상세 화면으로 이동한다. 출처 링크, 비교에 담기, 시각 자료 확대도 원래 읽기 전용/명시 저장 계약을 그대로 사용한다. 검색과 맞지 않는 관련 자료를 열었다면 일치 없음 안내가 나올 수 있으나 기존 검색어를 지우지 않는다.
- 이전 자료로/Esc는 원래 선택 자료 또는 미선택 목록으로 돌아간다. 비교에서 진입했다면 같은 두 자료와 A/B 면을 유지한 비교 화면으로 돌아간다. 복귀 모드는 즉시 적용하고 문단/포커스 배치만 다음 프레임에 복원하여 빠른 닫기에도 잘못된 모드를 저장하지 않는다.
- 조회가 바뀌거나 탐색 화면을 닫으면 오래된 행 콜백을 폐기한다. 관련 목록의 임시 페이지는 편의 파일에 새 게임 상태로 저장하지 않는다. 선택한 관련 자료와 복귀 경로는 기존 UI 상태에 저장한다.
- 사건 분류가 없는 legacy 원문은 단어/내부 키를 보고 관련 사건으로 추정하지 않는다. 전체 수첩·검색에서 계속 접근한다. 이를 누락된 원문 복원이나 개발 체크포인트의 취득 증거로 이용하지 않는다.
- 현실의 N키는 기존 물리 수첩이다. 과거 기록 메뉴의 관련 자료 열람은 `field_read`나 현실 필수 상호작용을 실행하지 않는다.

`notebook_investigation_smoke.gd`의 주요 퍼즐 매핑/숨은 페이지·힌트 배제/출처/페이지·복귀/실제 UI 파일 검사를 공통 조회에 포함한다. 실제 호스트는 C3·F0-C의 문맥 전달과 미확정 퍼즐 입력 보존을 함께 검사한다. 전체 생산자 분기 인수와 실제 Windows 조작·성능 인수는 별도다.

### 9.8. 최초 인물 근거와 정보 유지 범위

#### 최초 인물 근거

- archive 2의 기존 `source_links`와 `person_source`를 사용한다. 별도 게임/편의 파일 schema를 추가하지 않는다. 관찰 형식 검증은 `notebook_observation_schema.gd`가 담당하며 archive와 콘텐츠 해석 양쪽에서 같은 검증을 사용한다.
- 모든 변경 후보의 `_finish`에서 일반 대사 정리 **전에** 현재 계통에 남아 있는 가장 이른 검증 가능한 사용인 발언을 보호한다. 같은 계통과 정규화된 인물 ID에 대한 결정적 소비자 UID를 사용하며 최대 다섯 인물의 근거를 자동 연결한다. `MARA`와 `MARA1`은 하나다.
- 실제 공개된 segment, 등록된 정확한 콘텐츠 버전과 메타데이터 일치, 공개 화자 이름이 있어야 한다. 미등록/미래 버전, 잘못된 원고 식별, legacy 문자열은 새 인물 근거가 아니다. 익명 보라색 자료를 마라 2로 추정하지 않는다.
- 이미 보존한 최초 링크는 재방문·반복·분기에서 최신 발언으로 옮기거나 다시 만들지 않는다. 첫 발언은 일반 2,000개 quota 밖에 보존하며 나머지 같은 인물의 일반 대사를 전부 보호하는 방식은 아니다. 획득한 연구원 문서는 기존 지식/콘텐츠 보호도 유지한다.
- 구형 v2의 링크 없는 기록은 그대로 유효하고 조회는 읽기 전용이다. 다음 정상 쓰기 후보가 남아 있는 근거를 보호한다. 이미 없어진 원문·순서·다른 슬롯의 첫 만남은 만들지 않는다. 취소/실패한 후보는 원본을 바꾸지 않고 실제 writer의 원자 저장·응답 복구를 따른다.

#### 정보 유지 범위

수첩은 현재 게임 플래그·내부 날짜·진행 stage로 아직 보지 않은 세계 규칙을 설명하지 않는다. 현재 snapshot에 실제 획득한 지식 revision과 검증 가능한 정확한 관찰만 읽는다.

| 공개 근거 | 허용 안내 | 금지/경계 |
| --- | --- | --- |
| P/A1 또는 근거 없음 | 원래 원문·관찰/가설 상태만 | `persistent`를 보고 영구/리셋을 선공개하지 않음 |
| `NB_CH1_NOTE_A2` v1의 획득 revision | 기록 유지와 관찰한 아침의 물리 상태 복귀를 구분 | 현재 모든 오브젝트가 초기화됐다고 단정하지 않음 |
| D5 또는 E1의 기상 예상만 | 앞서 확인한 근거 범위 유지 | 파열·현재 E1 stage만으로 다음 아침 결과를 만들지 않음 |
| `NB_FRACTURE_NOTE_E1_DIFFERENT` v1의 획득 revision | 확인한 휴식 후 세계가 복구되지 않았다는 안내 | 정상 리셋이 일어났다는 안내를 계속 적용하지 않음 |
| E1 근거는 있으나 A2 없음 | 확인한 복구 실패만 | 누락된 기록 유지 실험까지 수행했다고 추정하지 않음 |
| legacy/원고 버전 불명 | 보관 원문만 | 문장 키워드로 유지 범위·반복 횟수·정체를 추정하지 않음 |

안내는 지식 자료의 상세와 A/B 비교에서만 표시한다. `lifetime=persistent`는 기록 유지이지 가설의 정답 인증이 아니며, `physical`은 현장 재확인이 필요한 상태 기록이다. 이전 revision의 `hypothesis/refuted`와 원래 출처 등급을 승격시키지 않는다. 과거 관찰을 현재 오브젝트 상태 조회로 대체하지 않는다.

공개된 유지 범위/반복 안내만 검색·일치 이동에 포함한다. 조회가 바뀌면 근거와 색인을 다시 구성해 과거 저장으로 돌아갔을 때 미래 안내가 남지 않는다. 원문 25개는 변경하지 않으며 새 의미 버전이 추가되면 별도 검토 없이 세계 규칙 근거로 자동 승격하지 않는다. 총 루프 수·미도달 장·연구원 정체·고백은 이 안내가 공급하지 않는다.

참조의 `content_version`은 schema가 허용하는 유한 정수형 실수와 정수를 같은 읽기 키로 취급한다. 예를 들어 JSON의 `1.0`과 메모리의 `1`을 문자열화 차이 때문에 별도 자료로 보지 않는다. 책갈피 표시·필터·비교 묶음·참조 버튼은 같은 정규 키를 사용한다. 문자열 `"1"`이나 소수 버전을 정수로 강제 변환하지 않으며 입력 archive/참조 원본은 변경하지 않는다.

자동 검사는 `notebook_person_retention_smoke.gd`의 정리/구형/분기/실제 저장 실패·응답 소실·재로드와 `notebook_memory_disclosure_smoke.gd`의 A1/A2/D5/E1 경계·한영·검색·200% 패널을 사용한다. 캡처되지 않은 모든 분기, Windows 실제 입력·스크린샷·성능 인수까지 완료했다는 뜻은 아니다.

### 9.9. 자기 표식의 버전 고정 시각 자료

`self_mark_v2.json`은 기존 A1 세 콘텐츠 ID에 **의미 버전 2**를 추가한다. `chapter_one_notes_v1.json`의 버전 1은 수정하지 않는다. 이는 archive/slot/sidecar 스키마 변경이 아니라 새로운 작성 사건의 내용 버전 선택이다. 공통 event-note writer는 호출자가 명시한 버전을 저장하며, 기존 호출의 기본 버전은 1이다. 현재 A1 생산자만 2를 명시한다.

| 작성 선택 | 새로 보존하는 묘사·도식 | 조회 경계 |
| --- | --- | --- |
| 문장 | 작성한 문장과 단위 순서 | 그림은 작성 당시 언어로 유지하고 현재 언어 본문을 별도 제공. 글자 윤곽은 필압을 측정한 원본 필체라고 주장하지 않음 |
| 집 도형 | 지붕, 몸체·창문 셋, 왼쪽으로 기운 문. 지붕 꼭짓점과 문 아래의 강한 획·얕은 눌림 | 모양과 상대 선 굵기, 한영 설명을 같이 제공. 개인 자유 그리기나 실제 필압 센서 데이터가 아님 |
| 모서리 잉크 | 모서리 접촉, 안쪽 접촉, 마지막 점과 고르지 않은 번짐 | 종이 경계는 점선으로 구별하며 표식의 획으로 세지 않음 |

- 본체의 `self_authored_mark={type,text,day}`와 F0-E의 입력·정답 순서는 바꾸지 않는다. A1에서 새 표식을 확정한 실제 트랜잭션이 도식 및 감각 묘사가 포함된 수첩 원문을 한 revision으로 작성한다. 재열람이 새로운 작성 사건을 만들지 않는다.
- 시각 자료의 정의는 정확한 콘텐츠 버전에 묶는다. 현재 `GameState`, 다른 선택 유형, F0-E solver나 최신 카탈로그로 과거 자료를 재구성하지 않는다. 버전 2는 A1 사건에서만 작성되며 A2 이후에는 그 관찰을 읽는다.
- 버전 1·legacy에는 그림/획압 근거가 없으므로 당시 원문만 유지한다. 업데이트·로드·수첩 열람은 버전 2로 승격하거나 임의 그림을 붙이지 않는다. 미등록 버전은 기존 원문 fallback 정책을 적용하며 다른 버전의 그림을 빌리지 않는다.
- 부분 자료/잘못된 화자·콘텐츠 식별/미획득 자료에는 그림을 생성하지 않는다. 보이는 정보만으로 확대·축소·이동·기본 위치·비교가 가능하다. 색, 드래그, 빠른 입력에 의존하지 않는다.
- 확대·고정·비교는 A2의 동일성 검증이나 F0-E의 과거/현재 인증을 실행하지 않는다. A2가 이루어져도 A1 원문·그림은 이전 가설 revision으로 유지되며 후속 revision이 이를 출처로 참조한다.
- 새 작성의 저장 실패는 표식 gameplay 상태와 시각 원문 획득을 함께 롤백한다. 응답 소실 확인·재시도는 같은 커밋을 확인하며 두 번째 표식이나 최신 버전을 중복 획득하지 않는다.

`notebook_self_mark_smoke.gd`를 조회 집중 검사에 포함한다. 실제 세 선택의 한영 A1 작성·수면·A2·슬롯 재로드, F0-E 관련 자료, 그림 언어 보존, 실패/응답 소실, v1/v2/불명 버전, 720p·200% 상세와 비교를 검사한다. Windows 실제 입력·최종 손글씨 아트 검수는 별도 인수다.

### 9.10. 엔딩 보관본의 읽기 전용 수첩

개발 옵션 `--ggb-dev-notebook-v2`에서 타이틀의 엔딩 감상 기록과 크레딧 완료 후 감상 기록에 `이 기록의 수첩`을 제공한다. 기존 장면 페이지와 기본 비활성 정책은 유지한다. 클릭한 보관본 하나만 열며 현재 슬롯·다른 엔딩·개발 체크포인트와 합치지 않는다.

| 경계 | 계약 |
| --- | --- |
| 보관 원본 | `EndingGalleryStore.read_entry`로 64자리 ID, envelope 버전, payload SHA-256을 검증한 뒤에만 읽는다. 파일명/ID/payload/checksum/프로필 참조를 재작성하지 않는다. 손상/미래 버전/누락은 일반 오류로 끝내며 현재 슬롯으로 대체하지 않는다. |
| 구형 기록 | 검증된 snapshot에만 메모리 읽기 어댑터를 적용한다. 미분류 원문을 남기며 실제 공개 증거가 없는 자료·시각 도식·지식 revision을 새로 획득시키지 않는다. |
| 조회 scope | `namespace=gallery`, `slot=payload_hash`, `run_id=gallery-adapter-1:<payload_hash>`, 보관된 origin/branch, `load_epoch=0`. 조회 캐시는 이 scope·언어·공개 정책 버전·조회 세대를 사용한다. |
| 열람 | 공통 네 분류·검색·공개 필터·출처·확대를 사용한다. 현재 조사 stage는 넘기지 않는다. 본편 사건 실행·필수 읽기·최초 공개·퍼즐 판정과 진행 저장은 호출하지 않는다. |
| 비교 | 시작할 때 보관된 비교 묶음을 읽고 열람 세션 안에서 최대 12개를 담아 A/B 두 개씩 교체한다. `gallery` scope에서 실제 조회 가능한 참조만 허용한다. 추가/제거는 임시 배열만 바꾸며 북마크 편집·원본 비교/보호 링크 변경은 없다. |
| 편의 저장 | 기존 버전 4 sidecar를 보관본별 scope로 구분한다. 선택·스크롤·확대·읽음 위치만 저장한다. 임시 비교 참조·비교 모드와 복귀 스택의 비교 모드는 저장하지 않는다. 닫았다 열면 보관 당시 묶음으로 시작한다. |
| 갱신 | 언어 변경은 처음 검증한 frozen snapshot에서 다시 조회하며 열람 중 임시 묶음은 유지한다. 뒤에서 바뀐 슬롯/다른 보관본의 자료를 끌어오지 않는다. |
| 종료 | 기존 화면을 숨기고 입력을 중단한다. 닫기 키/마우스 release 전까지 원래 화면을 재개하지 않으며 타이틀은 감상 목록의 버튼, 크레딧 뒤는 감상 목록으로 돌아간다. owner가 사라지면 과거 화면을 되살리지 않는다. |

`notebook_gallery_host.gd`는 GameState/SaveManager를 참조하지 않는다. 유일한 쓰기는 별도 UI 편의 저장이다. 편의 파일 실패는 기록 열람을 막지 않고 안내하며, 미래 버전 편의 파일은 덮어쓰지 않는다. 게임 저장과 보관 envelope schema는 변경하지 않는다.

검증 범위와 실행 상태는 [갤러리 수첩 검증](gallery_notebook_validation.md)을 따른다. 엔진 내 신호/키 이벤트 검사를 실제 Windows 입력, 화면 캡처 또는 성능 인수로 계산하지 않는다.

### 9.11. 본편 대사 표시 위치의 영속 복원

v2 대화 보관 구조를 사용하는 ChapterOne, BlackMirror, Basement의 공통 대사 큐에 적용한다. 프롤로그 확장은 9.12절을 따른다. 본편 선택 모달과 개별 조사 본문 큐의 앱 재시작 복원까지 완료했다는 계약은 아니다. 기존 legacy 보관 구조와 수첩 기본 비활성 정책은 유지한다.

| 항목 | 계약 |
| --- | --- |
| 저장 위치 | `loop_state.event_local_states.NOTEBOOK_PRESENTATION`, 현재 쓰기 `schema_version=4`, 기존 대사/프롤로그/모달 `schema_version=1/2/3` 읽기 호환. UI 편의 sidecar나 영구 지식이 아닌 현재 게임 진행 상태다. 물리 리셋의 로컬 상태 정리 대상이며 영구 기록을 삭제하지 않는다. |
| 고정 내용 | 컨트롤러 family, 원본/분기 식별자, 세계 상태 anchor, `reading/finish_pending/completed`, 문장 index, 당시 locale, 대사 큐, 제한된 후속 동작을 보존한다. 각 문장은 원문 descriptor, 화자/텍스트, 사건/대화 session, 동일 presentation token과 연출 메타데이터를 유지한다. |
| 공개 경계 | 대기 중인 다음 문장은 저장돼도 보관 대사/검색/지식으로 공개되지 않는다. 현재 실제 표시 문장만 기존 history writer에 전달한다. `presentation_cursor`는 관찰 snapshot context와 미분류 원문 payload에서 제외한다. |
| 원자성 | 실제 문장 기록과 커서 전진은 하나의 StateWriter/SaveManager 트랜잭션이다. 저장 실패는 두 상태를 함께 롤백하고 표시된 문장을 재시도 대상으로 남긴다. 응답 소실은 디스크 커밋과 전체 snapshot의 동등성을 확인한 경우만 성공으로 복구한다. |
| 재개 | 검증된 커서가 같은 세계·원본·분기와 일치하고 현재 토큰의 관찰이 실제 보관돼 있을 때 같은 index로 복원한다. 이미 기록된 현재 문장은 다시 append하지 않는다. 정확한 descriptor 버전이 있으면 현재 언어로 표시하고 미등록 원문은 기존 문자열을 유지한다. |
| 종료 | 마지막 문장 닫기도 저장 성공 후 실행한다. 후속 동작이 없으면 `completed`, 있으면 `finish_pending`이다. 후자는 재실행 시 마지막 문장만 복원하고 사용자의 다음 입력 없이 동작을 실행하지 않는다. |
| 진행 동작 커밋 | 검증된 pending 큐의 정확한 `_do` 후속 동작 또는 현실 연결 해제의 지정된 완료 동작만 세계 진행과 `completed` 커서를 같은 후보 snapshot에 저장한다. 진행 저장이 실패하면 pending 상태를 유지하고 재실행 후 명시적 재시도를 기다린다. 성공 후 재실행은 이전 대사를 다시 표시하거나 동작을 재실행하지 않는다. |
| 후속 동작 | 저장된 Callable이나 임의 스크립트 경로를 실행하지 않는다. `_do(action, value, false)`, `_show_clock_hint_menu(1..5)`, `_offer_clock_failure_support()`, `_reality_fade()`만 고정 registry에서 복원한다. 인자는 JSON 값만 허용한다. |
| 무효화 | 다른 slot/session/load epoch/namespace/origin/branch의 늦은 UI 입력을 거부한다. 커서 anchor는 대화 보관 내용과 커서 자신만 제외한 게임 상태의 정규화 hash다. 시간·장소·사건 진행이 다른 저장에 예전 큐를 합치지 않는다. |
| 허용된 재기준화 | 정상 backup 복구는 새 branch로 토큰을 유지한다. D5 시선 선택은 같은 대사 큐와 변경된 세계 상태를 함께 저장한다. J2/J3 완료 후 컨트롤러 초기화는 검증된 완료 커서를 새 family에 원자적으로 인계한다. 일반 게임 행동이나 임의 과거 상태에는 자동 재기준화하지 않는다. |
| 장 전환 | J2/J3 플래그가 다음 장을 가리켜도 읽는 중인 이전 장의 유효한 큐가 있으면 그 컨트롤러부터 재개한다. 마지막 문장을 명시적으로 닫은 뒤 다음 장으로 이동하고, 다음 장 재실행에서도 이전 피드백을 반복하지 않는다. |
| 호환·손상 | 큐는 1..128문장, 직렬화 1MiB 이내, JSON 깊이/문자열/컬렉션과 필드를 제한한다. 미래 커서 버전의 primary/backup은 기존 저장으로 덮거나 구형 backup으로 대신 로드하지 않는다. 잘못된 구조는 검증 오류다. |

데모 인계와 F3 재선택은 세계 맥락이 달라지는 별도 진행 분기이므로 일반 커서 carry 대상이 아니다. 새 branch와 세계 anchor에 맞지 않는 이전 큐는 실행하지 않는다. 갤러리는 이 필드를 대화 공개 근거나 게임 재개 지시로 사용하지 않는다.

검증은 [대사 위치 복원 검증](notebook_presentation_validation.md)을 따른다. 단순 모달 재진입과 대화 큐 복원은 구분하며 선택 결과의 자동 실행, 자유 메모, 실제 입력 인수는 이 변경에 포함하지 않는다.

### 9.12. 프롤로그 대사와 선택 확인의 영속 복원

프롤로그의 v2 보관 구조에만 적용한다. `kind=dialogue`와 `kind=choice`, family `prologue_controller`를 추가하며 envelope/archive 버전은 바꾸지 않는다. 이 확장을 본편의 모든 선택 모달이나 조사 화면 커서 구현으로 계산하지 않는다.

| 경계 | 계약 |
| --- | --- |
| 대사 | 실제 표시 문장, 읽는 index, 원문 descriptor, 사건/session/표시 토큰과 허용된 후속 동작을 고정한다. 기존 본편과 같은 `reading/finish_pending/completed`를 쓴다. |
| 질문 | P3 장부 질문, P4 아버지 질문, P1 출발 확인, P6 취침 확인에 `choosing/selection_pending/completed`를 쓴다. 당시 표시한 순서·라벨·제목·질문·포커스와 선택별 토큰을 보존한다. 숨겨진 선택지는 목록에 넣지 않는다. |
| 선택과 결과 | 선택 문구의 기록 성공은 답변·게임 진행 저장 성공이 아니다. 선택 후 진행 저장이 실패하면 디스크에는 원래 선택 목록과 선택 의도만 남는다. 재시작은 목록을 복원하며 사용자가 다시 누르기 전에는 답변이나 취침을 실행하지 않는다. |
| 재시도·변경 | 같은 보류 선택의 재시도는 동일 토큰으로 중복을 방지한다. 다른 답을 선택할 수 있고 A→B→A의 마지막 A는 새 의도다. 과거 선택 기록은 지우거나 성공 결과로 재분류하지 않는다. |
| 원자 저장 | 분리돼 있던 프롤로그 진행·수첩 획득과 최초 표시 대사/커서를 같은 후보 snapshot에 넣는다. 동기 후속 동작의 진행만 먼저 저장하지 않고 다음 표시 또는 완료 커서와 함께 저장한다. 실패는 후보 전체를 롤백하고 응답 유실은 정확한 저장본을 확인한다. |
| 공개 | 선택 커서는 표시 목록과 선택 토큰만 담으며 미선택 답변은 포함하지 않는다. 대사 큐의 아직 안 본 문장은 보관/검색 공개 근거가 아니다. 복원한 문장과 목록을 다시 append하지 않는다. |
| 초기 화면 | 방 구성 중 자동 인사·진행 저장·예약 질문 재개를 억제한 뒤 검증된 커서를 복원한다. 완료한 P3 질문을 낡은 예약 콜백이 다시 열지 않는다. |
| 후속 동작 | 저장된 Callable을 실행하지 않는다. P1 목표, 중앙홀 복귀, P3 질문 재개/표시, P4 맥박/기억/질문/이리스 완료, 정상 리셋, 프롤로그 인계의 고정된 무인자 메서드만 허용한다. 확인창 버튼은 P1/P6와 confirm/cancel의 고정 대응으로 다시 만든다. |
| 리셋·인계 | `PROLOGUE_COMPLETE`가 이미 저장됐어도 미완료 P6/R1 커서가 있으면 프롤로그를 먼저 연다. 명시적 P6 완료 입력 뒤 정상 리셋이 실행된다. R1은 리셋된 물리 기본값으로 영구 수첩을 덮어쓰지 않고 별도 대사 커서를 저장한다. R1 완료 후 본편 인계는 이전 큐를 재생하지 않는다. |
| 낡은 입력 | namespace/slot/load epoch/origin/branch가 달라진 대사·질문·확인 콜백은 거부한다. 리셋 애니메이션을 기다리는 동안 바뀐 scope에서도 기존 슬롯의 리셋을 실행하지 않는다. |
| 조사 화면 | 후속 동작 중 조사 표시 요청은 수집하되 진행 후보 저장 전에 따로 쓰지 않는다. 방 이동의 표시 scope를 갱신하여 이전 방의 큐가 이동을 막지 않게 한다. 개별 확대 창/조사 본문 위치의 프로세스 재시작 복원은 아직 별도 범위다. |

`dialogue_history_writer.append_to_snapshot`은 호출자가 소유한 후보만 변경한다. 호출자는 append 실패 후보를 버리고 성공 후보를 `StateWriter/SaveManager`로 커밋해야 한다. helper 호출만으로 내구성 있는 저장이 된 것으로 취급하지 않는다. 기존 `record`는 같은 helper와 저장 절차를 사용한다.

선택 구조는 정해진 선택 ID의 중복 없는 순서 부분집합과 exact-key 필드만 허용한다. `selection_pending`의 복원에는 목록 토큰과 마지막 선택 토큰의 관찰이 모두 필요하다. JSON 정수형 숫자의 왕복 호환과 기존 schema 1 읽기는 유지한다. 검증 근거는 [프롤로그 복원 검증](notebook_prologue_presentation_validation.md)을 따른다.

### 9.13. 기록된 본편 선택창의 영속 복원

모달의 게임 행동은 성공한 후보에 완료 커서를 함께 저장한다. 이미 읽은 현실 수첩처럼 성공해도 세계 상태가 같을 수 있으므로 anchor 변화만으로 성공/실패를 판정하지 않는다. 게임 저장 실패는 보류 선택을 유지하고, 명시적 같은 답 재시도는 원래 선택 토큰을 사용한다. 다음 현장 페이지 이동 역시 현재 페이지 확인과 완료 커서를 함께 저장한 뒤 새 페이지를 표시한다.

개발 옵션의 `_show_recorded_choice` 경로에 `kind=modal`을 사용한다. 메뉴·개발 도구·기록되지 않는 도움말 창까지 자동 포함하는 계약은 아니다. 본편 확인창, 관계 선택, 현실 수첩 페이지, 거울 경로/겹침 도식은 표시 자료와 함께 복원한다.

| 경계 | 계약 |
| --- | --- |
| 저장 | 표시한 제목·본문·라벨, 원문 descriptor, 당시 사건/session/목록 토큰, 허용한 버튼 동작, 선택 보류 토큰, 마지막 선택 버튼과 도식 상태를 저장한다. 목록 관찰과 커서는 같은 후보에 저장한다. |
| 실행 | 저장된 Callable, Node, 임의 함수명은 실행하지 않는다. `notebook_modal_presentation.gd`의 제한된 메서드·인자 규격으로 컨트롤러 소유 버튼만 재구성한다. 재구성 자체는 게임 행동을 실행하지 않는다. |
| 선택 | 실제 누른 문구와 `selection_pending`은 함께 저장한다. 성공한 선택 기록을 게임 진행 성공으로 간주하지 않는다. 게임 저장 실패 뒤 원래 선택창을 복원하며 자동 재시도하지 않는다. |
| 재시도 | 같은 보류 답은 같은 토큰을 재사용한다. 다른 답을 고른 뒤 돌아온 A-B-A는 새 선택 의도로 기록한다. 이전 선택 기록을 삭제하지 않는다. |
| 닫기 | 단순 닫기는 게임 읽기 확인이나 선택 기록을 추가하지 않고 완료 커서만 저장한다. 저장 실패 시 창을 유지한다. 진행 동작 내부의 창 닫기는 먼저 완료를 저장하지 않는다. |
| 복원 | 같은 세계 anchor/origin/branch와 실제 목록·선택 토큰을 검증한다. 신규 session/선택 토큰을 만들거나 원문을 append하지 않는다. 같은 descriptor의 현재 언어로 표시한다. |
| 자료 | 거울 경로는 실행 전 경로/방향/반전/기준점을 동결하며 현재 퍼즐 상태에서 재추정하지 않는다. 재생 버튼은 기록이나 퍼즐을 변경하지 않는다. 겹침 도식도 같은 원칙으로 재구성한다. |
| 결산·엔딩 | J4 확인 지연은 복원 창에서도 적용한다. 현실 수첩 표시와 읽기 확인은 분리되며 복원/닫기로 페이지 읽음·엔딩 결정을 실행하지 않는다. 수첩 검토 버튼은 통합 수첩을 열어 원래 확인창을 보존한다. |
| 격리 | 슬롯/컨트롤러/로드 세대/namespace/origin/branch가 바뀐 버튼은 거부한다. 직접 파기된 창의 콜백도 세대 검사로 차단한다. |

검증 범위와 잔여 화면은 [본편 모달 복원 검증](notebook_modal_presentation_validation.md)을 따른다. 본문 스크롤의 앱 재시작 위치, 기록 경로 밖의 조사창, 실제 OS 입력 인수는 별도 확인 대상이다.

### 9.14. 비관찰 보조창의 영속 복원

`kind=utility`는 힌트 요청 목록(`hints`), B3 반복 실패 지원(`failure`), C3 세정제 양 비교표(`quantities`)에 한정한다. 본문을 관찰했다고 간주하거나 메뉴 조작을 대화 기록으로 추가하지 않는다. 게임 snapshot의 표시 커서만 저장하며 퍼즐 상태·관계·읽기 완료·영구 기록에는 쓰지 않는다.

| 경계 | 계약 |
| --- | --- |
| 필드 | `utility={type, stage, level, ratio, difference}`의 exact-key 구조. `lines=[]`, `index=0`, `after={}`, `phase=viewing/completed`만 허용한다. 함수명·Callable·본문·숨은 해답을 저장하지 않는다. |
| 복원 | 같은 family/origin/branch/세계 anchor와 현재 퍼즐 단계를 검사한 뒤 컨트롤러의 고정된 세 화면 중 하나를 현재 언어로 다시 만든다. 재생성 자체는 snapshot이나 관찰 기록을 쓰지 않는다. |
| 힌트 | `level=0`은 최초 요청 메뉴. 1~5는 바로 이전 단계의 실제 힌트 관찰이 archive에 있어야 복원·저장할 수 있다. 메뉴 복원으로 다음 힌트를 요청하지 않는다. 기존 H1~H5 원고·강한 도움 조건은 변경하지 않는다. |
| 실패 지원 | 현재 `BF`, 실패 상태 active, 누적 실패 2회 이상일 때만 창을 다시 만든다. 잠금 해제·핀 복구·수면·강한 힌트 요청은 자동 실행하지 않는다. |
| 양 비교 | 두 체크 상태만 저장한다. 실제 원액/안정제/물의 입력값이나 정답 판정을 복원 과정에서 호출하지 않는다. 체크 저장 실패 시 화면도 마지막 성공 상태로 되돌린다. |
| 입력 경계 | 슬롯·로드 세대·세션·화면 세대·namespace·기록 계통·세계 anchor가 다른 버튼과 체크 콜백은 거부한다. 열린 보조창을 다른 메뉴로 덮지 않고 먼저 닫도록 한다. 수첩의 일시중단·복귀는 유지한다. |
| 저장 실패 | 기존 StateWriter/SaveManager 원자 저장을 사용한다. 실패를 완료로 취급하지 않으며 명시적 버튼 재시도로 다시 저장한다. 닫기 저장 실패는 창을 유지하고, 힌트 표시로 넘어가지 않는다. 성공한 닫기 뒤 재실행하면 창을 다시 열지 않는다. |

이 kind의 `observed()` 검사는 화면 본문 관찰이 아니라 복원 자격을 뜻한다. 다른 kind의 실제 토큰 검증은 그대로 유지한다. 통합 수첩 Query·책갈피·비교 보존의 대상 자료를 새로 만드는 예외가 아니다. 개발 수첩 host에서 보조 도구를 처음 여는 검사는 유효한 표시 커서만 snapshot 비교에서 분리하고 나머지 모든 상태를 비교한다.

검증은 [보조창 복원 검증](notebook_utility_presentation_validation.md)을 따른다. 프롤로그 창문 확대, 본문 스크롤·일반 포커스의 프로세스 재시작 복원, 갤러리 탐색 편의 상태는 이번 추가 대상이 아니다.

### 9.15. 프롤로그 창문 확대 상태의 영속 복원

v2 프롤로그의 확대 화면은 `loop_state.event_local_states.NOTEBOOK_WINDOW_INSPECTION`에 별도로 저장한다. 도구 사용 중 대사가 그 위에 열릴 수 있으므로 기존 `NOTEBOOK_PRESENTATION`을 대체하지 않는다. 대사 커서는 schema 4를 유지하고 이 별도 키를 포함한 세계 anchor에 원자적으로 재기준화한다.

| 경계 | 계약 |
| --- | --- |
| 구조 | exact-key `{schema_version: 1, window: 0..2, selected_item}`. 선택 도구는 빈 값 또는 `SOFT_CLOTH/COARSE_BRUSH/WATER/SPANNER`만 허용한다. 키 없음은 닫힌 화면이다. |
| 복원 자격 | 프롤로그가 끝나지 않았고 현재 방이 대응접실이며 선택 도구가 현재 인벤토리에 있을 때만 복원한다. 물리 상태는 저장된 `PROLOGUE.window_states`를 읽는다. |
| 중첩 표시 | 대사 커서와 확대 상태가 함께 있으면 같은 창문·선택 도구 위에 읽던 대사를 복원한다. 대사를 닫아도 확대 창은 그대로이며, 방으로 돌아가는 명시적 후속 동작에서는 닫는다. |
| 읽기 전용 | 방과 확대 창을 재구성할 때 자동 인사·새 관찰·수첩 획득·진행 저장을 억제한다. 현재 언어로 라벨을 표시하지만 청소·드래그·P2 완료를 재실행하지 않는다. 드래그 중 종료했어도 도구 선택만 복원한다. |
| 저장 실패 | 선택 도구 저장 실패는 이전 도구로 되돌리고, 닫기 저장 실패는 창을 유지한다. 청소 진행 저장 실패는 마지막 저장된 물리 상태로 화면을 복구하고 P2 완료로 넘어가지 않는다. 정상 진행은 사용자의 명시적 재입력으로 수행한다. |
| 입력 수명 | namespace/slot/load epoch/origin/branch가 다른 이전 확대 창의 클릭·드롭·도구 선택·닫기 요청을 거부한다. |
| 공개 범위 | 이 키 자체는 자료 획득·관찰 증거가 아니다. 실제 보인 창문 상태와 피드백의 기록 규칙은 기존 프롤로그 생산자를 유지한다. 기존 v1 보관 방식의 복원 범위를 확장하지 않는다. |

검증은 [창문 확대 복원 검증](notebook_window_inspection_validation.md)을 따른다. 일반 본문 스크롤과 키보드 포커스 재시작 위치, 실제 마우스·키보드 인수까지 완료한 것은 아니다.

### 9.16. 호출 화면의 스크롤·포커스 편의 저장

개발 옵션의 v2 호출 화면에 `PresentationViewTracker`를 붙인다. 게임 snapshot의 대사·선택·확대 상태는 앞 절의 정본이며, 이 추적기는 해당 화면의 읽기 위치만 `user://profile/presentation_views`에 저장한다. 수첩 내부의 `notebook_views`와는 다른 저장소다.

| 경계 | 계약 |
| --- | --- |
| 적용 | 프롤로그·본편 대사, 프롤로그 질문/확인, 본편 기록 모달·utility, 창문 확대, 현재 월드 오브젝트 포커스. 임의 설정·메뉴·기록되지 않은 모달을 새 재개 지점으로 만들지 않는다. |
| 저장 내용 | `focus`, 각 scroll의 `offset/fraction`, 당시 `locale/text scale/width/height`. 원문·힌트·선택 결과·Callable·NodePath 실행 지시는 저장하지 않는다. |
| 격리 | local profile, 일반/개발 namespace, slot, run_id, source_origin_id, branch_id로 파일을 나눈다. 살아 있는 추적기는 생성 후 slot/load epoch/origin/branch가 바뀌면 쓰지 않는다. |
| 화면 일치 | layout version, 컨트롤러 family, 세계 anchor, 실제 대사 표시 토큰/선택 표시 토큰 또는 utility 값·창문·장소를 정규화한 hash로 동일 화면을 확인한다. 게임 상태의 JSON 정수 왕복을 같은 방식으로 정규화한다. |
| 포커스 | 현재 화면에서 실제 존재하고 보이며 활성화된 컨트롤만 선택한다. 문장·질문·오브젝트의 의미 키와 모달/확대 창의 고정된 계층 키를 사용한다. 계층 키 배치를 변경하면 tracker의 `LAYOUT_VERSION`을 올려 옛 위치를 폐기한다. 버튼을 누르거나 선택을 확정하지 않는다. |
| 스크롤 | 언어·배율·화면 크기가 같으면 저장된 픽셀 위치, 달라졌으면 가용 스크롤 범위의 상대 위치로 보정한다. 범위 밖은 clamp한다. 번역·재배치 후 동일 문단의 정확한 복원을 주장하지 않는다. |
| 초기 복원 | 레이아웃 준비를 위해 두 프레임 기다린다. 이 사이 실제 키/마우스 버튼 입력이 오면 자동 스크롤·포커스 복원을 취소한다. 기존 접근성 포커스와 명시적 입력을 우선한다. |
| 쓰기 | 위치가 바뀐 뒤 0.25초 단위로 합쳐 쓰며 dirty 상태는 앱 포커스 상실·정상 화면 종료에도 flush한다. 강제 종료 직전의 아직 합쳐 쓰지 않은 편의 상태는 손실될 수 있으나 게임 저장은 별개다. |
| 실패·손상 | 임시 파일·checksum 검증·정상 primary의 backup 후 교체한다. 손상 primary는 검증된 backup으로 복구하며, 유효한 primary의 다른 화면 값을 이전 backup으로 되돌리지 않는다. 미래 버전이 primary/backup/temporary 어느 쪽에 있어도 읽기 복원·쓰기를 차단하고 모든 기존 파일을 보존한다. 미확정 temporary는 현재 버전이어도 복원 후보가 아니다. 현재 버전·손상 temporary는 검증된 새 편의 저장으로 교체할 수 있다. 저장 실패는 상태줄에 알리고 진행을 막지 않으며 다음 위치 변경에서 다시 시도한다. |
| 비용 | 실제 GameState revision이 바뀔 때만 snapshot/anchor를 갱신한다. 위치 변경 자체는 GameState revision·대화 기록·수첩 획득·게임 저장을 쓰지 않는다. 성능 예산 통과 여부는 별도 계측 대상이다. |

문장 커서가 아직 저장되지 않았거나 실제 표시와 다르면 읽기 위치를 복원하지 않는다. 숨겨진 화면·삭제 대기 컨트롤러·열린 통합 수첩에서는 추적을 중단한다. 직접 전달된 키 문자열로 노드를 실행하지 않고 현재 컨트롤 맵에서만 조회한다. 범위와 증거는 [호출 화면 편의 저장 검증](presentation_view_validation.md)을 따른다.

### 9.17. 월드 표시 확인 정보의 원자 저장

v2 월드의 재시작·재선택 재개는 `loop_state.event_local_states.NOTEBOOK_SURFACE_RECEIPT`를 사용한다. 이것은 새로운 지식이나 조사 완료 플래그가 아니라 이미 관찰 writer를 통과한 현재 방문의 표시 식별이다. 대사·확인창 커서는 기존 `NOTEBOOK_PRESENTATION`, 읽기 위치는 별도 편의 파일이 소유한다.

| 경계 | 계약 |
| --- | --- |
| 구조 | schema 1, stable scope, 방문 occurrence/conversation, 표시 지문별 presentation/event/conversation 토큰. 원문은 복제하지 않는다. |
| stable scope | namespace, slot, source origin, branch, location, node, day와 엔딩 current node. 런타임 session 인스턴스·load epoch·view_slot은 저장 식별에서 제외하지만 기존 살아 있는 콜백 거부 조건에서는 유지한다. |
| 표시 지문 | content/version/variant/공개 변수·segment, 실제 표시 본문·언어·화자, 출처 node/chapter/location을 정규화한 SHA-256. JSON 정수 왕복은 동일하게 계산한다. |
| 복원 | 새 컨트롤러 또는 명시적 로드 세대 전환에서만 같은 scope의 토큰을 복원한다. 정상 방 이동으로 다른 scope에 진입한 뒤 돌아오면 새 방문을 만든다. |
| 저장 | 관찰과 표시 확인 정보를 동일 candidate snapshot에 설치하고 기존 writer·원자 저장·실패 롤백을 사용한다. 확인 정보만 먼저 저장하거나 실제 관찰 없이 성공 처리하지 않는다. |
| 재시도 | 같은 표시 토큰을 재사용한다. 저장 실패는 명시적 재시도를 요구하고 확인 응답 유실은 실제 디스크 커밋을 확인한다. 재생성 후에도 이미 성공한 관찰을 새 순번으로 추가하지 않는다. |
| 새로운 표시 | `new_attempt`는 새 발생으로 유지한다. 다른 공개 값·언어·의미 버전은 다른 지문이다. 보관된 원문을 덮어쓰거나 전역 content ID로 서로 다른 방문을 합치지 않는다. |
| 보존 범위 | 현재 활성 표시와 아직 저장을 마치지 못한 요청의 식별만 보존한다. 한 배치 최대 512개를 검증하며 초과 시 임의로 활성 토큰을 버리지 않고 실패를 반환한다. 과거 원문·보호·책갈피·비교 자료는 이 캐시 정리와 무관하다. |
| 구 저장 | 키가 없으면 당시 보였다고 추정하지 않고 현재 실제 보이는 표면을 처음 기록한다. 이후 재개부터 확인 정보를 사용한다. 미래 schema·잘못된 토큰은 snapshot 검증에서 거부한다. |
| 게임 상태 | 표시 확인 정보는 게임 진행용 anchor 계산에서 제외한다. 이 갱신으로 퍼즐·인벤토리·관계·지식·힌트·엔딩·대사 커서를 변경하지 않는다. NORMAL_RESET에서는 다른 loop-local 상태와 함께 제거되고 영구 관찰 기록은 유지한다. 파열 이후는 기존 상태 보존 규칙을 따르되 장소·단계 등 scope가 다르면 재사용하지 않는다. |

실행 근거와 한계는 [월드 표시 재개 검증](notebook_surface_resume_validation.md)을 따른다. 코드 등록만으로 전 생산자·실제 Windows 입력·성능 인수를 완료한 것으로 보지 않는다.

### 9.18. 잔류 외형 표시의 기억 원칙 조사

`EDS_APPEARANCE_CONTROL`의 중립 안내는 기억·결정 보존에 대한 서사 규칙이므로 단순 `EXCLUDED_UI`로 빼지 않는다. 화면에 보이는 안내는 `NB_STAY_APPEARANCE_NEUTRAL_LABEL`, 해당 버튼을 실제 눌러 상태줄에서 본 추가 설명은 `NB_STAY_APPEARANCE_NEUTRAL_DETAIL`의 NP19 authored 관찰이다. 클릭 전 상세는 획득하지 않는다. 명시적 반복 클릭은 새 관찰, 재그리기는 새 클릭이 아니다. 신규 두 ID만 추가하고 기존 118개 ID의 의미 버전 원고는 유지한다.

기존 공통 surface writer로 archive/표시 receipt를 원자 저장한다. 실패는 진행·디스크·관계를 바꾸지 않고 명시 재시도 버튼을 제공한다. 확정 응답 유실은 실제 커밋으로 확인하며 같은 요청을 중복 기록하지 않는다. generation/live scope와 실제 엔딩 노드를 검사해 외부 재로드나 다른 단계의 오래된 콜백을 거부한다. 직접 조사는 표시 모드·기억·관계·엔딩 결정이나 대사 커서를 변경하지 않는다.

신규 설명은 내부 상태명 `S5` 대신 이미 확인한 진실과 현재 기억의 보존을 말한다. 과거 미분류 상태줄을 원문 역검색으로 소급 매핑하지 않는다. 일반 rollout OFF에서는 기존 비기록 상태줄 동작을 유지하며 v2만 신규 관찰을 생성한다. [검증 범위](../ideas/md/v04/issues/validation/2026-10-07_잔류표시원칙_누락조사_수정검증.md)는 NP19 해당 화면과 잔류 suite이며 전편 정적 UI 분류 완료가 아니다.
