# 수첩 지원 화면 입력·큰 글자 검증

## 수정

- 새 힌트 버튼과 세정제 계산 표 진입 버튼에 읽기 배율을 적용했다. 200%일 때 글꼴 크기는 42다.
- 수첩·단계형 힌트 메뉴·세정제 계산 표의 직접 자식 포커스 컨트롤에 앞뒤 순환 경로를 설정했다. 마지막 컨트롤의 Tab은 첫 컨트롤로, 첫 컨트롤의 Shift+Tab은 마지막으로 돌아간다.
- 새 계산 버튼을 추가한 뒤 경로를 다시 구성해 동적 버튼을 순환에서 누락하지 않는다.
- 후보 목록은 기존 스크롤 영역을 사용하며 계산 조건과 닫기는 목록 밖에 유지한다.

## 확인한 증거

Godot 4.7.2의 네이티브 OpenGL 화면을 1280×720으로 캡처해 한국어 글자 200%의 계산 표와 수첩을 확인했다. 수첩의 마지막 계산 버튼까지 화면 안에 표시되며 계산 표는 스크롤로 나머지 내용을 읽는다. 수첩 패널의 하단이 게임 뷰 하단을 넘지 않는지도 자동 검사했다.

`BLACK_MIRROR_SMOKE`에서 `Input.parse_input_event`로 키 눌림·해제를 전달했다. 이는 버튼 신호를 직접 호출하는 것과 별도의 Godot 입력 경로 검사다.

1. 포커스된 비율 체크박스에서 Space로 체크 전환.
2. Tab으로 두 번째 조건으로 이동.
3. 마지막 조건에서 Tab으로 지원 스크롤에 순환.
4. Shift+Tab으로 마지막 조건에 역순환.
5. 글자 200%의 45개 후보 표를 Page Down으로 스크롤.
6. 계산 조건 조작 후 게임 상태가 변하지 않는 기존 검사 유지.

`BLACK_MIRROR_SMOKE`와 `CHAPTER_ONE_SMOKE`가 통과했다. 최초 테스트 작성 중 배율 복원 변수의 블록 범위 오류가 발생했으며, 이를 수정한 뒤 최종 실행에서 스크립트 오류 없이 통과했다.

## 한계

- Windows 실물 키보드·마우스의 전편 완주, 4K·DPI 200%, 영어 전체 화면 검사와 동일하지 않다.
- 공통 `_show_modal`을 사용하는 확인창에도 순환을 적용했다. 별도로 구성한 화면과 Windows 실제 입력을 포함한 전체 게임 보증은 아니다.
- 공통 모달의 제목·선택 버튼도 후속 수정으로 배율을 적용했다. 개별 퍼즐 화면에 직접 만든 텍스트까지 모두 감사한 것은 아니다.
- 실제 고배율 플레이와 화면 경계 검사 범위를 다른 퍼즐·관계·엔딩 화면으로 확장해야 한다.

## 공통 확인창 후속 수정

공통 `_show_modal`에서 본문 외에 제목과 선택 버튼도 읽기 배율을 따른다. 제목과 버튼은 긴 문장을 줄바꿈한다. 150% 이상에서는 확장 배치를 사용하며 낮은 배율로 다시 열면 기본 배치로 되돌린다. 실제 동작은 Godot 4.7.2의 Button `autowrap_mode` 속성을 확인한 뒤 적용했다.

200% 계산 표 캡처에서 제목·닫기·수량·조건이 모두 확대되어 화면 안에 표시되는 것을 확인했다. 테스트는 제목 68, 선택 버튼 42의 글꼴 크기와 기본 배율 복귀 위치를 검사한다. Space·Tab·Shift+Tab·Page Down의 기존 검사도 유지한다.

모든 본문의 길이·언어·선택지 개수 조합에서 화면 경계를 검증한 것은 아니다. 이 변경으로 전체 UI 접근성 완료를 선언하지 않는다.

후속 변경에서 `BLACK_MIRROR_SMOKE`, `PROLOGUE_SCENE_SMOKE`, `BASEMENT_SESSION_SMOKE`가 통과했다. 후반 회귀의 기본 배율 검사는 200% 전편 화면 QA와 구분한다.

## 공통 확인창 키보드 순환

지원 메뉴에만 있던 순환 로직을 공통 모달로 이동했다. 표시 중인 중첩 컨트롤도 탐색하며 숨긴 컨트롤과 비활성 버튼은 제외한다. 기본 버튼 생성 후 지연 호출로 경로를 구성하고, 수첩과 계산 표는 추가 버튼을 넣은 뒤에도 재구성한다. 게임 진행이나 퍼즐 정답에는 영향을 주지 않는다.

프롤로그 취침 확인창에서 Godot 입력 이벤트로 마지막 선택지의 Tab이 본문 스크롤로, Shift+Tab이 마지막 선택지로 돌아오는지 검사했다. 이 탐색 동안 진행 상태가 유지되는 것도 확인했다. 기존 계산 표의 Space·Tab·Shift+Tab·Page Down 검사와 함께 회귀 검증한다. 동적으로 숨김 상태를 변경하는 별도 화면은 변경 직후 순환 경로를 재구성해야 한다.
