# 수첩 지원 화면 입력·큰 글자 검증

## 수정

- 새 힌트 버튼과 세정제 계산 표 진입 버튼에 읽기 배율을 적용했다. 200%일 때 글꼴 크기는 42다.
- 수첩·단계형 힌트 메뉴·세정제 계산 표의 직접 자식 포커스 컨트롤에 앞뒤 순환 경로를 설정했다. 마지막 컨트롤의 Tab은 첫 컨트롤로, 첫 컨트롤의 Shift+Tab은 마지막으로 돌아간다.
- 새 계산 버튼을 추가한 뒤 경로를 다시 구성해 동적 버튼을 순환에서 누락하지 않는다.
- 후보 목록은 기존 스크롤 영역을 사용하며 계산 조건과 닫기는 목록 밖에 유지한다.

## 확인한 증거

Godot 4.7.2의 네이티브 OpenGL 화면을 1280×720으로 캡처해 한국어 글자 200%의 계산 표와 수첩을 확인했다. 수첩의 마지막 계산 버튼까지 화면 안에 표시되며 계산 표는 스크롤로 나머지 내용을 읽는다. 수첩 패널의 하단이 게임 뷰 하단을 넘지 않는지도 자동 검사했다.

`BLACK_MIRROR_SMOKE`에서 `Input.parse_input_event`로 키 눌림·해제를 전달했다. 이는 버튼 신호를 직접 호출하는 것과 별도의 Godot 입력 경로 검사다.

1. 포커스된 비율 체크박스에서 Space로 체크 전환.
2. Tab으로 두 번째 조건으로 이동.
3. 마지막 조건에서 Tab으로 지원 스크롤에 순환.
4. Shift+Tab으로 마지막 조건에 역순환.
5. 글자 200%의 45개 후보 표를 Page Down으로 스크롤.
6. 계산 조건 조작 후 게임 상태가 변하지 않는 기존 검사 유지.

`BLACK_MIRROR_SMOKE`와 `CHAPTER_ONE_SMOKE`가 통과했다. 최초 테스트 작성 중 배율 복원 변수의 블록 범위 오류가 발생했으며, 이를 수정한 뒤 최종 실행에서 스크립트 오류 없이 통과했다.

## 한계

- Windows 실물 키보드·마우스의 전편 완주, 4K·DPI 200%, 영어 전체 화면 검사와 동일하지 않다.
- 포커스 순환은 이 문서의 지원 화면에 한정한다. 전체 게임의 모든 모달에 대한 보증이 아니다.
- 기존 공통 모달의 제목·닫기 등 일부 고정 글꼴은 이번 수정 대상이 아니다. 전체 텍스트 배율 적용 감사가 남아 있다.
- 실제 고배율 플레이와 화면 경계 검사 범위를 다른 퍼즐·관계·엔딩 화면으로 확장해야 한다.
