# 개발용 크레딧과 완료 저장

검증 결과: 격리 Godot 4.7.2에서 `BASEMENT_SESSION_SMOKE: PASS`, `FOUNDATION_SMOKE: PASS`. 마지막 페이지 화면을 시각 확인했다. 스크립트 오류는 없으며 Windows 인증서 저장소 경고는 별도 환경 경고다.

## 구현

`CREDITS_REALITY`와 `CREDITS_STAY`에 개발용 페이지 크레딧을 연결한다. 제작진 표기 정보는 사용자에게 요청했으며 확인되지 않은 이름을 창작하지 않았다. 현재 3개 페이지는 배포용 제작진·라이선스 명단을 대체하지 않는다.

시작, 페이지 확인, 마지막 완료를 분리한다. 현재 페이지 번호와 `credits_started`, `credits_completed`를 본편 슬롯에 저장한다. 다음 페이지 입력은 예상 페이지 번호를 포함하여 중복 입력을 거부한다. 페이지 확인 전 종료하면 같은 페이지부터 이어진다.

크레딧 완료는 `ENDING_POST_CREDITS`와 `SAVE_ENDING_COMPLETE`로 저장한다. 완료 뒤 실제 타이틀 이동 버튼을 제공한다. 아직 구현하지 않은 재선택·갤러리를 동작하는 버튼처럼 표시하지 않는다.

## 불변식

- 확정된 분기와 해당 최종 프레임 완료가 있어야 크레딧을 시작한다.
- 완료에는 시작 플래그, 해당 크레딧 완료 노드, 후속 메뉴 노드가 필요하다.
- 관계·최종 선택은 변경하지 않는다.
- 크레딧을 처음 시작할 때 완료로 처리하지 않는다.
- `ending_meta`의 seen과 `credits_completed`는 별개다.

## 아직 필요한 메타 처리

프로필 `ending_meta`의 파일 저장은 이번 구현에 포함하지 않았다. 명세는 **최종 프레임 직후 엔딩 seen 메타를 먼저 커밋하고 크레딧을 재개**하도록 요구한다. 후속 작업에서 이 경로를 원자 파일 저장·재시도와 연결해야 한다. 현재 페이지 크레딧만으로 엔딩 프로필이 완성됐다고 간주하지 않는다.

F3 재선택 사본, 갤러리와 연습 슬롯, 엔딩 별/ALL 변형 seen, 최종 제작진 및 리소스별 법적 표기, 실제 크레딧 연출·음향·배포 QA도 남아 있다. 새 기본 빌드 공개 여부는 이후 통합 검증과 함께 결정한다.

## 검증 범위

두 엔딩의 최종 프레임에서 크레딧 시작·진행·완료 UI를 실행한다. 조기 완료 및 최종 프레임 없는 시작 거부, 중복 페이지 입력 거부, 페이지 저장 재개, 완료 메뉴, `SAVE_ENDING_COMPLETE`, 관계·선택 불변을 검증한다. 화면 캡처는 `user://ending_credits.png`다.
