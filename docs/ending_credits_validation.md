# 개발용 크레딧과 완료 저장

검증 결과: 격리 Godot 4.7.2에서 `BASEMENT_SESSION_SMOKE: PASS`, `FOUNDATION_SMOKE: PASS`. 마지막 페이지 화면을 시각 확인했다. 스크립트 오류는 없으며 Windows 인증서 저장소 경고는 별도 환경 경고다.

## 구현

`CREDITS_REALITY`와 `CREDITS_STAY`에 개발용 페이지 크레딧을 연결한다. 제작진 인명은 사용자 지시에 따라 **미정**으로 유지하며 확인되지 않은 이름을 창작하지 않는다. 현재 3개 페이지는 배포용 제작진·라이선스 명단을 대체하지 않는다.

시작, 페이지 확인, 마지막 완료를 분리한다. 현재 페이지 번호와 `credits_started`, `credits_completed`를 본편 슬롯에 저장한다. 다음 페이지 입력은 예상 페이지 번호를 포함하여 중복 입력을 거부한다. 페이지 확인 전 종료하면 같은 페이지부터 이어진다.

크레딧 완료는 `ENDING_POST_CREDITS`와 `SAVE_ENDING_COMPLETE`로 저장한다. 완료 뒤 타이틀 이동, F3 상태의 별도 사본 재선택, 감상 기록 버튼을 제공한다. 감상 기록은 확인한 장면·조사 내용을 읽는 기능이며 전체 연출 재생으로 표시하지 않는다.

## 불변식

- 확정된 분기와 해당 최종 프레임 완료가 있어야 크레딧을 시작한다.
- 완료에는 시작 플래그, 해당 크레딧 완료 노드, 후속 메뉴 노드가 필요하다.
- 관계·최종 선택은 변경하지 않는다.
- 크레딧을 처음 시작할 때 완료로 처리하지 않는다.
- `ending_meta`의 seen과 `credits_completed`는 별개다.

## 메타 처리와 남은 범위

초기 페이지 크레딧 구현 이후, 최종 프레임의 엔딩 seen 메타 저장과 실패 재시도가 연결되었다. 현재 회귀는 감상 기록 저장 실패에도 최종 프레임의 본편 저장이 유지되고, 기록 저장 실패 상태에서는 크레딧 시작을 막으며 복구 후 재시도할 수 있는지 확인한다. seen과 크레딧 완료는 별도 상태다. 모든 강제 종료 시점·파일 시스템 장애 조합까지 검증했다는 뜻은 아니다.

F3 재선택 사본과 열람형 갤러리는 연결되어 있다. 갤러리 전체 연출 재생, 연습 슬롯의 제품 범위, 메타 장애·복구 전수 검증, 최종 제작진 및 리소스별 법적 표기, 실제 크레딧 연출·음향·배포 QA는 남아 있다. 새 기본 빌드 공개 여부는 이후 통합 검증과 함께 결정한다.

## 검증 범위

두 엔딩의 최종 프레임에서 크레딧 시작·진행·완료 UI를 실행한다. 조기 완료 및 최종 프레임 없는 시작 거부, 중복 페이지 입력 거부, 페이지 저장 재개, 완료 메뉴, `SAVE_ENDING_COMPLETE`, 관계·선택 불변을 검증한다. 화면 캡처는 `user://ending_credits.png`다.

## 한·영 표시 연결

`ending_credits_texts.gd`는 세 페이지, 현실·잔류 제목, 시작·다음·완료, 메타 저장 오류·재시도 및 크레딧 후 세 진입 버튼의 표시 문구를 제공한다. 페이지 번호와 진행 규칙은 `EndingCredits`를 그대로 따른다. 한국어 마지막 페이지의 오래된 갤러리 미구현 안내를 현재의 열람 기능과 미완성인 전체 장면 재생을 구분하는 문장으로 수정했다.

추가 회귀는 두 엔딩에서 세 페이지 각각을 한국어·영어로 렌더하고 언어 전환 전후 상태 불변을 검사한다. 감상 기록 저장 실패 시 영어 재시도 버튼, 제작진 미정 표기, 세 후속 진입 버튼의 영어 표시도 확인한다.

갤러리와 재선택 메뉴 내부, 전체 열람 자료의 언어 전환은 별도 후속 범위다. 이번 버튼 현지화만으로 해당 메뉴 전체가 번역되었다고 간주하지 않는다.

후속 검증 결과: Godot 4.7.2 Windows OpenGL의 `BASEMENT_SESSION_SMOKE: PASS`. 2560×1600 캡처에서 영어 마지막 페이지와 완료 버튼이 각 영역 안에 표시되는 것을 확인했다. 모든 해상도·배율의 가독성이나 최종 크레딧 연출 검증은 아니다.
