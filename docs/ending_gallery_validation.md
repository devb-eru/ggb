# 엔딩 갤러리 감상 상태 보존 기반

## 구현

- 감상 프로필 저장 후 `user://profile/ending_gallery/{sha256}.json`에 실제 완료 상태를 보존한다. 크레딧 전 자동 저장 및 재시도 경로에 연결한다.
- 파일은 gallery version 1, 원문 JSON payload, SHA-256 체크섬으로 구성한다. 원문 문자열을 검증하므로 JSON 숫자 재직렬화 차이로 체크섬을 다시 계산하지 않는다.
- 전체 상태는 관계·선택·완료한 상호작용을 보존하기 위한 원본 자료다. 플레이 슬롯으로 설치하거나 원본 상태를 수정하지 않는다.
- 크레딧 페이지·완료 여부는 엔딩 차이가 아니므로 보존 사본에서 제거한다. 현재 node는 해당 분기의 최종 프레임으로 고정한다.
- 동일 payload는 같은 파일을 사용한다. 이미 존재하는 손상 파일이나 미래 버전 파일을 자동 덮어쓰지 않는다. 저장 실패는 기존 크레딧 재시도 경로로 보고한다.
- 완료 증거 없는 엔딩은 거절한다. 읽기는 체크섬, 상태 스키마, 최종 프레임 완료를 다시 검증한다. ID는 64자리 16진수로 제한한다.

## 검증

- basement-session에 실제 완료 상태 보존, 중복 저장 ID 일치, 미완료 거절, 경로 이탈 ID 거절, 사용인 관계 보존 확인을 추가했다.
- 감상 프로필과 보존 사본은 두 단계다. 프로필 성공 후 사본 실패 시 프로필 seen은 보존되며 다음 시도에서 사본 저장을 재시도한다.

## 아직 하지 않은 작업

- 초기 저장 기반 이후 타이틀·크레딧 뒤 목록과 읽기 전용 페이지 UI가 연결되었다. 전체 장면 연출 재생은 아직 미완성이다.
- 현재 UI는 본편 상태를 설치하지 않고 보존 상태에서 열람한 페이지를 생성한다. snapshot 안에 원래 존재하던 미조회 기록을 자동으로 공개해서는 안 되며, optional/required 감상 이력으로 대상을 제한한다.
- 과거 seen 플래그만 있고 보존 사본이 없는 경우, 임의 관계나 ALL 장면을 생성하지 않는다.
- 내용상 같은 장면의 세부 상태 차이를 묶는 목록 정책, 손상 사본 복구 UI, 최종 영상·아트 연결은 후속 작업이다.

## 신체 재조사 문장 노출 수정

문제 위치: `ending_gallery_pages.gd`의 현실 신체 확인 페이지. `required_interactions_seen`은 최초 조사를 확인한 증거인데, 기존 코드는 이 값만으로 최초·재조사 문장을 함께 공개했다. 손·호흡 표시기·고정 벨트를 한 번만 조사한 플레이에도 보지 않은 재조사 대사가 노출될 수 있었다.

수정: 최초 조사 완료 플래그를 먼저 확인하고, 재조사 문장은 보존 상태의 `dialogue_history.entries`에 해당 `CH1_HISTORY_TRANSCRIPT` 본문이 실제로 기록되어 있을 때만 덧붙인다. 한국어·영어로 열람한 두 정본을 인정한다. 후속 표시 언어 연결에서도 이 노출 조건은 동일하게 적용한다.

이력이 없는 과거 보존본에서는 재조사를 했다고 추정하지 않는다. 원본 갤러리 파일·플레이 슬롯·체크섬·저장 스키마를 변경하지 않고 페이지 생성만 제한한다. 향후 문구를 개작할 때는 안정적인 이벤트 식별자 또는 과거 문구 대응 정책을 함께 검토해야 한다.

추가 회귀 범위: 세 신체 대상 각각의 최초 조사만 있는 상태, 한국어·영어 재조사 이력, 관련 없는 line_id, 최초 조사 완료 플래그 없는 이력을 검사한다. 페이지 수·노출 본문과 호출 전후 상태 불변을 확인하며 기존 미조회 페이지 차단 및 원본 파일 보존 검사를 유지한다.

검증 결과: 격리 Godot 4.7.2에서 `BASEMENT_SESSION_SMOKE: PASS`. 루트 인증서 저장소 환경 경고 외 스크립트 오류는 없었다. 갤러리 전 항목의 표시 언어·장면 연출 검증 완료를 의미하지 않는다.

## 갤러리 표시 언어 연결

`EndingGalleryPages.build(state, locale)`에 선택적 언어 인수를 추가했다. 생략하면 기존 한국어 출력을 유지한다. 타이틀은 현재 타이틀 언어, 엔딩 이후 메뉴는 현재 대화 언어를 전달하며 같은 페이지 생성기를 사용한다.

연결 범위는 전원 인증·권한 확인·엔딩 도입, 현실 인계·신체 조사·현장 수첩·출입 점검·시설 조사·마지막 시선, 잔류 기억·외형·자율성 합의·중앙홀·식탁·수첩 문장·마지막 자리다. 기존 기상·현장 수첩·잔류·지표 번역 자료를 재사용한다. 전원 인증과 엔딩 도입의 영어 문장은 아래 후속 작업에서 본편 UI에도 연결했다.

타이틀과 엔딩 후 목록의 제목·빈 목록·이전/다음·목록 복귀·분기 이름도 연결한다. 아무 기록이 없는 경우 미감상 장면을 만들어 채우지 않는다. 전체 영상 재생을 지원하는 것처럼 안내하지 않는다.

페이지를 보여 주는 언어는 보존본의 원래 열람 언어와 달라도 된다. 그 대신 공개할 페이지는 완료 노드·실제 조사·확인한 관계 기록·수첩 펼침 이력으로만 결정한다. 언어 전환은 감상 파일이나 본편 슬롯을 다시 저장하지 않는다. 원래 대화 이력의 문장은 열람 당시 언어로 남는다.

추가 회귀는 두 엔딩의 공개 페이지 수·한영 제목/본문 대응·미조회 페이지 및 전원 인증 차단의 언어 간 일치, 실제 엔딩 후 영어 페이지, 타이틀의 영어 이동 버튼·본문/빈 목록을 확인한다. 기존 원본 파일 바이트 보존 및 재조사 노출 검사를 유지한다. 모든 과거 문구 버전·문장 감수·화면 배율·최종 영상 연출까지의 검증은 아니다.

후속 실행 결과: 격리 Godot 4.7.2 headless에서 `BASEMENT_SESSION_SMOKE: PASS`, `START_SCREEN_SMOKE: PASS`. 루트 인증서 저장소 환경 경고 외 스크립트 오류는 없었다. 이번 갤러리 번역은 별도 화면 캡처 검증을 수행하지 않았다.

## 키보드 열람 보완

후속 검사에서 타이틀의 갤러리 ScrollContainer가 포커스를 받을 수 없어 키보드로 긴 기록을 넘기지 못하는 문제를 재현했다. 이전 스크롤 검사는 `scroll_vertical`을 직접 대입했으므로 실제 키 입력을 검증하지 못했다.

수정: 스크롤 영역을 Tab 탐색에 포함하고 포커스가 있는 동안 `ui_page_down`·`ui_page_up` 입력으로 보이는 높이의 80%를 이동한다. 영역이 보이지 않거나 포커스가 없으면 입력을 소비하지 않는다. InputMap의 재지정을 따르며 기본 PageDown 키를 고정 사용하지 않는다. 마우스 스크롤과 기존 페이지 전환·포커스 복귀는 유지한다.

검증은 실제 Godot 입력 이벤트로 Tab 진입, PageDown·PageUp, Ctrl+F11로 재지정한 페이지 이동, 교체된 PageDown 무효화를 확인한다. 이후 페이지 이동 시 스크롤 초기화, 마지막 페이지에서 비활성화되는 다음 버튼의 포커스 복귀, 본편 상태 불변 검사를 실행한다. 테스트용 긴 기록은 레이아웃·입력 검증용이며 게임 콘텐츠나 갤러리 저장에 추가하지 않는다.

시각 검증은 보존된 실제 기록 중 긴 영어 페이지를 Windows 1280×720에서 캡처한다. 모든 기록·배율·키보드 레이아웃 및 OS 수준 전편 완주를 대신하는 검사는 아니다.

Windows 캡처에서 감상 기록 진입 버튼만 이전 언어로 남는 추가 문제를 확인해 타이틀의 언어 갱신 함수에 포함했다. `START_SCREEN_SMOKE`의 headless 및 Windows OpenGL 실행이 통과했고, 1280×720 영어 긴 기록의 스크롤 영역·이전/다음·타이틀 복귀가 패널 안에 표시되는 것을 확인했다. 엔진 인증서 저장소 환경 경고 외 스크립트 오류는 없었다.

## 본편 엔딩 도입과 공유

전원 이름 인증·권한 확인 및 현실/잔류 엔딩 도입의 본문을 갤러리와 본편에서 공유한다. 본편의 위치·목표·확인 버튼·인증 진행 안내·자동 서명·서명 도움말도 한·영으로 제공한다. 원래 한국어 문장을 유지하며 언어를 저장 상태 ID로 사용하지 않는다.

다섯 인격의 인증은 순서대로 읽기 확인을 마쳐야 진행된다. 전원 인증은 기존 관계 완료 조건에서만 나오며 서명은 이미 확정한 선택을 허가받는 시험으로 바꾸지 않는다. 수동 선 긋기와 자동 서명 모두 유지한다. 현실의 다섯 저전력 보존 채널과 잔류의 다섯 활동 의식 채널을 구분하고, S5를 정상 리셋으로 복구하지 않는다.

회귀는 LOW/ALL 및 두 엔딩에서 실제 영어 도입 버튼과 본문, 읽기 확인 전 상태 유지, 중복 확인 거절, 다섯 인증의 저장 재개, 권한 설명, 자동·수동 서명, 다음 단계와 관계·선택·인격 채널 불변을 검증한다. 기존 규칙 함수를 직접 호출하던 인증·도입 테스트를 실제 컨트롤러 조작으로 확장했다. OS 입력 전편 완주와 최종 연출 QA를 대신하지 않는다.

실행 결과: 격리 Godot 4.7.2 headless에서 `BASEMENT_SESSION_SMOKE: PASS`. 루트 인증서 저장소 환경 경고 외 스크립트 오류는 없었다. 본편 도입의 영어 화면 배율별 캡처 검증은 남아 있다.
