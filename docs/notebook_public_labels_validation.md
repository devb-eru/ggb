# 공개 명칭과 기록 안내의 의미 버전 검증

기준: 2026-10-04, develop `29e9c81`. 생산자 감사 PA11 / [GGB-ERR-2026-0026](../ideas/md/v04/issues/items/GGB-ERR-2026-0026_플레이어_문구_내부ID_노출.md)의 첫 수정 범위다. 전체 이슈와 통합 수첩 목표는 `IN_PROGRESS`다.

## 1. 재현과 수정 범위

다섯 사용인의 관계 완료 화면은 `SCREEN.COMPLETE` 원고와 한영 UI 번역에서 `REC_MARA1` 같은 내부 키를 플레이어에게 안내했다. 완료 화면은 실제 월드 관찰 원문으로도 저장되므로, 번역 문자열만 바꾸면 새 화면과 기존 version 1 descriptor가 불일치해 저장을 거부할 수 있다.

다음 다섯 ID에만 의미 버전 2를 추가하고 실제 완료 화면의 생산자가 그 descriptor를 명시적으로 선택한다.

| ID | 공개 명칭 |
| --- | --- |
| `NB_MARA1_SCREEN_COMPLETE` | 마라 1의 연구 기록 / Mara 1's research record |
| `NB_IRIS_SCREEN_COMPLETE` | 이리스의 연구 기록 / Iris's research record |
| `NB_LUCA_SCREEN_COMPLETE` | 루카의 연구 기록 / Luca's research record |
| `NB_EDGAR_SCREEN_COMPLETE` | 에드가 연구 기록 / Edgar's research record |
| `NB_MARA2_SCREEN_COMPLETE` | 마라 2의 연구 기록 / Mara 2's research record |

- 책임·불확실성·자기 결정권에 관한 앞 문장은 유지한다. `SUBJECT`는 실제 권한 이름이므로 유지한다.
- `relationship_labels_v2.json`을 등록하고 COMPLETE 이외의 관계 표면에는 기존 경로를 유지한다.
- 원래 다섯 v1 카탈로그 파일은 바이트 단위로 변경하지 않았다. 과거 기록의 ID·버전·문장·보호·출처를 갱신하거나 삭제하지 않는다.
- 저장 키 `REC_*`, 관계 완료 상태·선택지·보상·퍼즐 답안은 바꾸지 않는다. 일반 표시 전체에 최신 버전을 자동 적용하지 않는다.

## 2. 검사 계약

네 관계 생산자 검사에 공통 `notebook_relationship_label_assertions.gd`를 연결한다.

1. 다섯 ID의 한국어·영어 최신 화면 원고와 version 2 카탈로그를 비교한다.
2. version 1 원고가 계속 존재하는지 확인하고, 실제 과거 observation 구조를 JSON 왕복한 뒤 두 언어로 재생한다. captured text나 의미 버전은 변하지 않아야 한다.
3. version 2 문구를 version 1로 관찰 저장하려는 요청은 거부해야 한다.
4. 실제 관계 진행에서 수집한 완료 화면은 정확한 version 2이며, 당시 표시와 보관 문장·재생 결과에 `REC_`가 없어야 한다.
5. 구 버전 observation을 최신 경로 판정에 넣으면 거부한다.
6. 기존 관계 검사들의 미룸·저장 거부·응답 유실·재로드·반복 행동·미공개 자료·지식/관계 불변 검사를 유지한다.

과거 version 1의 내부 ID 포함 원문은 보존 검사의 대상이다. 이를 신규 플레이 문구 노출 0 조건과 혼합해 원문을 삭제하지 않는다.

## 4. 잔여 작업과 한계

- 첫 수정 시 J4 인덱스 fallback과 현실 인계는 미수정이었다. 후속 수정은 5절에 분리한다. 지하 도면, 코어 자료, 일부 힌트/제목·편집 이력의 내부 ID는 아직 남아 있으며 개별 이슈에서 추적한다.
- raw title 일부는 이미 조회 메타데이터에서 일반 제목으로 대체한다. 카탈로그 정적 검색만으로 실제 제목 노출이나 완전 해결을 판정하지 않는다.
- 한글 조사에 붙은 ID, 동적 변수로 생성되는 ID, 개발자 화면 전용 ID를 구분해야 한다.
- 이번 실행은 실제 컨트롤러/관찰 저장 경로의 자동 검사다. Windows 실제 마우스·키보드·IME·시각 검수나 cold/warm p95 측정이 아니다.
- 변경 후 전체 캠페인/지하 종합 회귀는 이 보고서의 집중 검사와 별도다. 직전 커밋의 전체 PASS를 새 패키지 전체 PASS로 소급하지 않는다.
- rollout 기본 비활성, 여러 자료를 담고 두 개씩 비교, 보호/미분류 기록 별도 보관, 개인 자유 메모 후속 분리 결정을 유지한다.

## 5. J4 인덱스와 현실 인계 출처 후속 수정

기준 develop `acf2f6e`. 앞 절의 실행은 관계 완료 안내 패키지의 결과이며, 아래 변경 후 재실행과 구분한다.

### 5.1 의미 버전과 저장 경계

- J4의 원본 누락 fallback은 획득 여부를 그대로 두고 `에드가 · 획득한 기록 인덱스`처럼 이름을 표시한다. 임의의 옛 본문은 번역·재구성하지 않는다.
- `NB_J4_DOCUMENT`와 다섯 `NB_J4_DISPLAY_READ_*_INDEX`에 버전 2를 추가한다. 새 합성 문서의 인덱스만 새 발화 버전을 쓰며 기존 인용 자료의 버전은 유지한다. 과거 문서로 발화를 구성하면 인덱스도 그 문서의 과거 버전을 사용한다.
- 현실 인계의 확장 확인창과 획득 문서에 버전 2를 추가한다. 출처가 있는 31개 조합을 `mask_01`~`mask_31` enum으로 보존하고, 두 언어 모두 에드가·마라 1·루카·이리스·마라 2 순서로 이름을 표시한다. 획득 0명은 기존 무출처 문장을 유지한다.
- 공통 모달의 생성/복원은 descriptor에 명시된 버전을 조회한다. 모달 선택 자체의 기존 ID와 버전은 변경하지 않는다.
- 읽기 확정 시 실제 표시된 질문의 content ID·버전·segment/변수와 발생/대화/표시 토큰을 보관 기록에서 검증한다. 과거 창 재개는 과거 문서를 획득하며, 최신 상태로 과거 내용을 재생성하지 않는다.
- 과거 확장 문서가 있더라도 명시적으로 새 버전 확장 페이지를 읽으면 새 revision 한 개를 만든다. 동일 버전/내용의 재열람은 중복하지 않고 요약 열람은 확장 문서를 대체하지 않는다.
- 인계 인덱스는 연구원 기록 문서를 새로 만들지 않는다. 존재하는 실제 읽기 질문과 이미 획득한 연구원 자료만 출처로 연결한다.
- 기존 `journal_four_v1.json`, `journal_four_display_v1.json`, `modals_v1.json`, `reality_v1.json`은 바이트 단위로 유지한다. 새 파일은 `record_labels_v2.json`이며 8개 기존 ID에 새 버전만 추가한다.

총 28개 카탈로그, 고유 ID 1,683개, 버전별 정의 1,699개, 정의별 문장 합계 2,517개다. 정의 수를 실제 분기 실행 수로 해석하지 않는다.

### 5.2 검사 보완

J4 문서 검사는 새 문서와 인덱스의 한영 공개 명칭, 과거 버전 원문/번역/발화 재생을 확인한다. J4 화면 검사는 실제 읽기 피드백의 버전과 문구를 확인한다.

첫 화면 재검사는 정렬 표시 130건에서 기존 비교식이 현재 방문의 정상 표시 확인 정보까지 진행 변경으로 오인했다. 실제 차이는 `loop_state.event_local_states.NOTEBOOK_SURFACE_RECEIPT`였다. 이를 무조건 제외하지 않고 `same_surface_gameplay`로 유효한 scope, 실제 authored 관찰로 뒷받침되는 표시 토큰, 과거 기록 보존과 정확한 append/순번을 검증한다. 나머지 게임 상태는 전체 비교한다. 페이지·정렬·관계·소지품·지식·순번·근거 없는 표시 토큰의 일곱 변조 반례를 추가했다.

현실 수첩 검사는 두 언어 각각 32개 획득 조합에서 실제 창 표시와 읽기 확정을 수행한다. 구버전 질문을 실제 저장한 뒤 컨트롤러를 제거하고 슬롯을 디스크에서 다시 로드하여 구 확인창 복원, 구 문서 획득, 위조 토큰 거부, 새 버전 명시 열람과 중복 방지를 검사한다. 인덱스만으로 연구원 문서가 생기지 않는 조건, 이후 관계 상태 변경에도 과거 이름 목록과 UID가 불변인 조건을 유지한다.

구버전 복원 검사에서는 두 시험 준비/판정 오류도 분리했다. 초기화 전 체크포인트에 질문을 바로 붙이면 재로드의 정상 초기화가 `last_feedback.history_context`를 추가하여 커서의 게임 문맥이 달라졌다. 실제 플레이처럼 세션 초기화 후 질문을 저장하도록 준비 순서를 고쳤고, 재로드 이후 전체 snapshot이 같아야 한다는 조건을 추가했다. 또한 읽기 확정은 질문에 해당 지식 revision의 `knowledge_source` 보호 이유를 정상 추가한다. 이를 원문 변조로 취급하지 않고 그 보호 이유 한 개와 검증된 출처 링크만 추가되며 원문/UID/나머지 필드는 불변인지 검사한다. 이후 새 버전 재열람은 옛 질문의 보호 이유까지 그대로 유지해야 한다.

모달 세 단계는 `--notebook-modal-presentation-smoke --cursor-phase=seed/resume/completed --ggb-dev-notebook-v2`로 서로 다른 프로세스에서 실행했다. 이는 공통 모달 재시작 검사이며 구버전 현실 인계 창 자체의 별도 프로세스 검사라고 확대하지 않는다. 조회 하위 수는 3절과 동일하다. 실행 시간은 테스트 비용이며 cold/warm p95나 실제 입력 지연 측정이 아니다.

전체 지하는 `--basement-session-smoke`를 실행하며 v2에만 `--ggb-dev-notebook-v2`를 추가한다. 모드별 별도 APPDATA를 사용한다. 기존 사용자 수정 씬·리소스·플러그인은 패키지에서 제외했다. Windows 루트 인증서 저장소 경고는 남아 있으며, 스크립트/파싱 오류나 단언 실패와 구분한다.
