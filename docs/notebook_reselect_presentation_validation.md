# 재선택 복사본의 표시·열람 위치 복원 검증

기준: 2026-10-04, develop `256eab8`. 통합 수첩 전체 목표는 `IN_PROGRESS`다. 이 문서는 PA08의 실제 재현과 수정 범위를 다루며 전체 생산자·실제 Windows 입력 인수를 대신하지 않는다.

## 1. 확인한 결함

`basement_controller.gd::_resume_reselect`는 복사본을 설치한 뒤 기존 컨트롤러의 슬롯과 세션만 바꾸었다. 정상 진입의 `ChapterOneController._ready → _restore_presentation`을 다시 실행하지 않으므로 저장된 대화 중간·확인창·실패 후 미확정 선택이 나타나지 않았다.

같은 컨트롤러의 `PresentationViewTracker`는 최초 슬롯·load_epoch·기록 분기에 묶여 있다. 다른 슬롯으로 바뀐 뒤 쓰기를 거부하는 것은 올바른 보호 동작이지만, 새 추적기를 만들지 않아 복사본에서도 계속 위치 저장이 차단됐다.

추가한 회귀는 실제 F3 캡처에서 복사본을 생성하고 진행을 저장한 뒤 원본 크레딧 화면의 `_resume_reselect`로 다시 연다. 수정 전 패키지 `C884AD8698A5B7DEBCD9BC2EF91AA8E7A9EA14938B93D11CB58F60E6303B3590`에서 다음 실패를 확인했다.

- 대화 인덱스와 확인창 복원 실패.
- 추적기가 새 슬롯·표시 식별로 전환되지 않으며 위치 저장 실패.
- 확인창 대신 월드 화면을 노출하여 관찰 기록이 추가됨.

초기 검사에는 실패한 화면 교체 뒤 정리 과정에서 이미 분리된 자식을 다시 제거하는 테스트 오류도 있었다. 이 오류와 잘못 가정한 stale-source 검사를 제품 결함 수치로 합산하지 않는다. 정리 시 실제 부모를 확인하고 교체 성공 뒤에만 오래된 출처 콜백을 시험하도록 수정했다. 최초 컴파일 때의 WeakRef 추론 경고도 명시적 타입으로 교정했다.

## 2. 수정 방식

1. 복사본 로드 성공 후 현재 슬롯·세션·load_epoch·원본·분기·namespace를 `_reselect_resume_scope`에 보관한다.
2. 복사본 진입 안내의 닫기 버튼 또는 Esc는 월드를 즉시 노출하거나 모달 완료 커서를 쓰지 않고 `campaign_requested`를 한 번만 요청한다.
3. 기존 bootstrap의 출처 WeakRef 검증을 통과하면 정상 캠페인 진입 경로가 이전 컨트롤러를 교체한다. 새 컨트롤러가 저장된 표시를 복원하고 새 열람 위치 추적기를 소유한다.
4. 다른 로드가 이미 발생했거나 같은 전환을 요청했다면 이전 안내의 콜백을 무시한다. 전환을 기다리는 동안 안내를 계속 유지해 목적지 보드·자동 진행을 앞당기지 않는다.
5. 생성 실패·로드 실패 알림과 단순 갤러리 알림은 기존 닫기 동작을 유지한다. 기존 PA01의 비서사 알림 분리도 유지한다.
6. 실제 재선택 슬롯인데 복원할 표시 커서가 없다면 원본에서 물려받은 `last_feedback`을 재생하지 않고 저장된 월드에서 시작한다. 정상 슬롯의 시작 대사나 유효한 복사본 커서의 복원은 바꾸지 않는다.
7. 복사본 안내 위에 통합 수첩을 열었다면 첫 닫기는 기존 수첩 닫기 경로만 수행한다. 안내를 닫기 전에 컨트롤러가 교체되거나 수첩 호스트가 남지 않도록 한다.

저장된 답변을 자동 실행하지 않으며, 커서와 관찰 토큰은 그대로 복원한다. 트래커의 이전 scope 쓰기 거부 조건을 완화하거나 슬롯 이름만 덮어써서 재사용하지 않는다.

## 3. 검사 범위

`notebook_reselect_presentation_smoke.gd`는 실제 bootstrap 연결과 컨트롤러 재생성을 사용한다.

| 사례 | 핵심 검증 |
| --- | --- |
| F3 기상 장치 대화 중간 | 실제 대사의 같은 인덱스·토큰, 현재 언어 본문, 표시 전 후속 문장 비공개 |
| 잔류 결정 확인창 | 같은 확인창과 토큰, 닫힌 것으로 처리하거나 선택을 실행하지 않음 |
| 선택 기록 뒤 게임 저장 실패 | `selection_pending`과 선택 토큰 유지, 명시적 재시도 전 엔딩 확정 금지 |
| 이미 닫은 확인창 | 완료 커서를 다시 열지 않고 월드로 복귀. 새 월드 관찰은 아래 PA09와 구분 |
| 표시 커서 없는 새 F3 복사본 | 원본의 마지막 대사를 임의로 재생하거나 새 대화 커서를 만들지 않음 |
| 열람 위치 | 이전 슬롯의 트래커 쓰기 거부, 새 트래커의 슬롯·표시 식별, 포커스 복원과 이후 쓰기 가능 |
| 경합 | 같은 닫기 두 번, 안내 표시 뒤 외부 재로드, 교체된 컨트롤러의 뒤늦은 캠페인 요청 |
| 수첩 중첩 | 안내 위 수첩을 먼저 닫으면 같은 컨트롤러의 안내로 복귀하며 게임 snapshot과 복사본 전환 요청을 바꾸지 않음 |

각 사례를 한국어·영어에서 실행한다. 기본 실행은 저장한 언어와 반대 언어로 재진입하며, `--reselect-same-locale` 실행은 언어를 유지한다. 개인 자유 메모나 새 퍼즐 판정은 추가하지 않는다.

대기 중 대화·확인창의 전체 snapshot은 재진입 전후 같아야 한다. 원본 저장 파일은 바이트까지 보존한다. 복사본은 정상 `session.initialize`가 기존 계약대로 다시 저장하므로 파일 바이트 불변을 요구하지 않는다. 대신 체크섬 검증을 통과한 저장 snapshot과 런타임 전체 상태가 같고, 헤더의 트랜잭션·revision·작성/수정 시각·체크섬 외 슬롯·run·버전·저장 경계 등이 모두 같은지 검사한다.

위치 검사는 격리 APPDATA 안의 실제 기본 편의 저장 경로를 사용한다. 첫 수정 검사의 포커스 실패 중 일부는 추적기가 로드를 마친 뒤 테스트가 저장 루트를 바꾸는 fixture 오류였으며, 이를 제품의 포커스 결함으로 보고하지 않는다. 스크롤 오프셋의 일반 재시작 검사는 별도 [호출 화면 위치 검증](presentation_view_validation.md)을 따른다.

재선택 가능한 F3 이후에는 현재 힌트·수량 utility 화면으로 되돌아가는 정상 경로가 없다. 불가능한 utility 진행을 만들어 커버리지로 세지 않는다. utility 일반 복원은 기존 모달 표시 검사 범위이며, 이 수정은 그 복원 함수를 변경하지 않는다.

## 5. 남은 중복 표시 감사

완료 커서로 월드에 돌아오는 경우에는 기존 보드 표시가 다시 관찰로 기록된다. 대기 중 대화·선택을 복원하는 경우에는 발생하지 않는다. 회귀 검사는 이 경우에도 다음을 요구한다.

- 이전 관찰·책갈피·출처 링크·보호 상태를 수정하거나 삭제하지 않음.
- 추가 항목은 실제 목적지의 활성 표면 요청과 관찰 내용이 일치함.
- 지식·관계·엔딩·퍼즐·완료 커서 등 기록 외 snapshot 전체가 같음.

이 조건은 중복 관찰 허용을 새 제품 계약으로 확정하는 것이 아니다. 표시·복원 오류와 별개인 PA09로 추적하고, 동일 언어·동일 segment 중복도 별도 출력한다. 계획의 재렌더링 중복 방지 인수는 미완료다.

공식 이슈는 [GGB-ERR-2026-0025](../ideas/md/v04/issues/items/GGB-ERR-2026-0025_월드_재진입_관찰기록_중복.md)이며 `OPEN · READY`다. 같은 언어의 `completed`, `no_cursor` 재진입에서 `NB_FINAL_EDC_SCREEN_NOTICE`, `NB_FINAL_EDC_SCREEN_REALITY`, `NB_FINAL_EDC_SCREEN_STAY` 세 항목의 버전·변형·segments 중복을 확인했다.

권장 해결: 현재 월드의 공개 영수증을 원자 저장되는 관찰과 연결하고, 같은 슬롯·분기·장소·표시 상태의 재시작에서만 기존 토큰을 복원한다. 실제 새 조사·다른 방 방문 후 복귀·퍼즐 값 변경을 전역 content ID로 합쳐 버리지 않는다. 저장 실패 뒤 미공개 자료를 공개 처리하지 않는 원자성과 분기 격리를 함께 검증해야 한다.
