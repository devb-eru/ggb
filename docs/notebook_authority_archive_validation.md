# 에드가·마라 2 관찰 및 관계 미룸 검증

기준: 2026-10-04, develop `047d6f5`. 생산자 재감사의 PA06을 대상으로 한다. 퍼즐 정답·관계 보상·제품 저장 동작을 변경하지 않고 실제 표시 계약에 맞게 검사를 보완한다.

## 1. 실패 재현과 원인

이전 생산자 감사는 900초 제한으로 종료하여 전체 결과가 없었다. 이번에는 인물·언어·관계 시나리오별 진행 표식과 표면 차단 진단을 추가하고, 격리한 Windows 실행에서 끝까지 재현했다.

- 진단 PCK: `B439C97988C8CE6DAADB79DC2FD60973F52EF7123044A5BC5AEC830C619E8E5D`.
- 로그: `%TEMP%/ggb-authority-diagnostic-20261004/`.
- 종료 결과: FAIL. 표면 기록 단언 2건과 관계 미룸 단언 48건. 스크립트 오류나 미실행 ID/문장 경고는 없었다. 실행 제한을 늘린 사실만으로 PASS로 처리하지 않는다.

### 잘못된 출처 선택 후 가려진 월드

마라 2 출처 선택에서 일부러 다른 사용인을 고르면 의미 있는 오답 상태 문구를 기록한 뒤 원래 선택창이 `selection_pending`으로 복원된다. 게임 입력이 성공하지 않은 선택을 자동으로 다시 실행하지 않는 기존 계약이다. 이때 `dialogue=false`, `modal=true`, `retry=false`인데 테스트의 `_drain()`은 뒤쪽 월드 표면 저장 성공을 요구했다.

검사는 다음을 명시적으로 확인하도록 바꿨다.

1. 오답의 실제 상태 문구가 한 번 관찰된다.
2. 원래 선택창과 미확정 커서가 남는다.
3. 가려진 월드 기록 요청은 거부되고 snapshot 전체가 그대로다.
4. 플레이어의 명시적 취소를 수행한 뒤에만 월드로 돌아가 다음 시도를 한다. 신호의 소유자는 아직 배정되지 않아야 한다.

전역 `_present()`의 실패를 무시하거나 모달 위 기록을 허용하지 않는다. 정상 경로에서 표면 기록이 차단되면 여전히 실패하며 차단 상태를 출력한다.

### 관계 선택 미룸과 표시 커서

대화 기록을 분리한 실제 차이는 `NOTEBOOK_PRESENTATION`의 대화→완료 모달 전환뿐이었다. 관계값·완료 플래그·연구 기록·지식·물리 상태 변화는 없었다.

- 원래 대화 기록의 모든 항목과 순서를 그대로 보존해야 한다.
- 실제 표시된 질문과 취소 선택 두 항목만 추가할 수 있다. occurrence/conversation, 원고 유효성, 증가한 순번과 revision을 확인한다.
- 이어서 유효한 현재 분기·문맥의 완료 모달 커서 하나만 분리하고 나머지 snapshot 전체를 비교한다. 연구원 기록 ledger는 비어 있어야 한다.
- 인물·언어 조합 네 개에서 관계·소지품·지식·대화 순번·커서 누락·미완료·다른 분기 커서의 일곱 변조를 각각 거부한다.

## 3. 같은 패키지의 추가 회귀

관계 수정 패키지와 같은 `4B918745...`로 선택창의 새 프로세스 복원 검사를 실행했다. seed 397개/44.5초, resume 7개/4.6초, completed 4개/4.5초가 모두 종료 코드 0 및 PASS였다. 실제 다른 PID에서 미확정 선택 토큰을 복원하고, 자동 게임 입력 및 중복 관찰 없이 명시적 재시도를 수행했다.

이후 같은 패키지의 지하 전체 v2 검사는 끝까지 실행했지만 14,031개 중 다음 일곱 단언이 실패했다. 로그는 `%TEMP%/ggb-authority-regression-20261004/`다. 실패 뒤 이어지는 기존 모드 검사는 실행하지 않았다.

| 비교 위치 | 실패 수 | 확인 사항 |
| --- | ---: | --- |
| E6 화면 생성 및 취소 | 2 | 표시 이후 비교 기준에 현재 방문 표시 정보가 반영되지 않음 |
| 양 엔딩의 영어 EDC 미리보기 | 2 | 새 언어로 보이는 표면의 표시 정보 변경 |
| 현실 수첩의 영어 페이지 미리보기 | 2 | 새 언어로 보이는 인덱스의 표시 정보 변경 |
| J4 화면 생성 | 1 | 새 방문 표면의 표시 정보 변경 |

이를 내부 추적 PA10으로 분리했다. `_same_observed_display`는 현재 분기에 맞는 유효한 표시 커서와 실제 authored 관찰로 뒷받침되는 `NOTEBOOK_SURFACE_RECEIPT`만 허용한다. 이전 관찰 항목은 전체 보존하고 정확한 append/순번만 허용하며, 이 둘 외 snapshot은 전체 비교한다. E6 취소는 화면 표시가 끝난 시점을 기준으로 비교하여 취소 자체의 변화와 화면 진입 변화를 섞지 않는다.

E6 경로에 지식·인벤토리·관계·순번·허위 표시 토큰·다른 분기 커서·신규 미분류 항목의 일곱 반례를 추가했다. 전역 비교에서 receipt를 무조건 삭제하지 않는다. `_without_presentation`의 다른 호출 지점은 변경하지 않았다.

최종 회귀 패키지: `67B3ABFD9B0273942A83B8DD54D7B945371C8F1FB565D56BA8DCD0EB04CA3373`. 앞 패키지와 제품 코드 및 관계 검사는 같고 지하 회귀 검사만 보완했다. 로그는 `%TEMP%/ggb-authority-regression-final-20261004/`다. import 22.0초, export 8.2초 후 아래 두 전체 검사가 각각 종료 코드 0 및 `BASEMENT_SESSION_SMOKE: PASS`로 끝났다.

| 실행 | 검사 수 | 시간 | 결과 |
| --- | ---: | ---: | --- |
| `--basement-session-smoke --ggb-dev-notebook-v2` | 14,052 | 1,370.4초 | PASS |
| `--basement-session-smoke` | 13,917 | 263.1초 | PASS |

집중 실행 옵션을 사용하지 않았다. 두 실행의 APPDATA/LOCALAPPDATA를 분리했고, D0~D4 퍼즐, J4 관계 완료 조합과 코어, 양 엔딩·현실 수첩·크레딧/재선택, 전체 D5/D6 검사까지 완료했다. 최종 패키지에서 관계 집중 검사를 다시 실행했다고 표기하지 않는다. 제품 코드와 해당 검사 소스가 같은 앞 패키지의 실행 증거를 구분해 보존한다.

v2의 여섯 표시 비교에서 대화 기록과 유효한 표시 커서를 분리한 차이는 모두 `NOTEBOOK_SURFACE_RECEIPT` 내부에 한정됐다. 그 정보가 실제 관찰에 연결되는지와 이전 관찰 보존/순번을 검사했으며, E6의 일곱 반례도 모두 거부했다. 기존 모드의 여섯 비교는 차이가 없었다. E6 취소는 정상 표시 완료를 기준으로 분리해 나머지 상태 불변을 유지했다. 따라서 PA10은 수정·전체 회귀 PASS로 판정한다.

환경의 Windows 루트 인증서 저장소 경고는 모든 통과 실행에서도 남아 있다. 이를 해결한 것으로 계산하지 않는다. 스크립트·파싱·컴파일·리소스 오류는 없었다. 실행 시간은 회귀 비용이며 입력 지연 p95나 장비별 성능 인수 수치가 아니다.

## 4. 남은 전체 인수

PA06의 두 실패 원인과 PA10의 전체 회귀 판정은 위 범위에서 해결했다. 최신 지하 전체 v2/기존 모드 회귀는 완료했다. 22개 생산자 전체 필수/반복/최초 공개/공개 ID 감사, 나머지 조사·탐색 계약 대조, PA09 전 장소 실제 입력 검토, Windows 실제 마우스·키보드·IME·시각 검수와 장비별 성능 인수는 별도다. 개발 rollout 기본 비활성 및 전체 목표 `IN_PROGRESS`를 유지한다.
