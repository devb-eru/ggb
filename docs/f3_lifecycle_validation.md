# F3 사본의 플레이 단위 수명

- 본편 저장 헤더에 선택적 `run_id`를 추가한다. 일반 저장은 같은 ID를 유지하고 실제 새 게임 transaction은 새 ID를 발급한다. 본편 스냅숏 스키마는 변경하지 않는다.
- F3 사본 로드는 현재 primary가 유효하고 현재 플레이에서 F3를 완료했으며, 사본과 현재 primary의 `run_id`가 같은 경우에만 허용한다.
- 따라서 새 게임 후 삭제하지 못한 옛 사본이 남아도 이전 관계·기록으로 재선택할 수 없다. 새 플레이가 F3에 도달한 뒤에도 ID가 다른 옛 사본은 거절한다.
- F3 이전 본편 저장이 성공한 후 기존 사본·임시 파일·백업을 정리한다. 실패한 본편 저장에서는 정리하지 않는다. 정리 실패는 본편 성공을 취소하지 않고 warning_ids로 반환한다.
- 미래 schema 사본이 있으면 사본 세트를 보존하며 경고한다. 향후 버전 파일을 자동으로 지우지 않는다.
- `run_id` 없는 기존 본편은 계속 불러올 수 있다. 다음 정상 저장에서 ID를 부여한다. 출처를 검증할 수 없는 기존 F3 사본은 재선택용으로 사용하지 않는다. F3 상태에서 다시 저장하면 새 사본을 만들 수 있지만 이미 엔딩을 마친 상태를 임의로 F3로 되감지는 않는다.

## 테스트

- start-screen: 새 게임 사본 3종 정리, 남은 파일의 현재 플레이 게이트 거절, 일반 저장 ID 유지, 새 게임 ID 교체.
- basement-session: F3 사본 생성·정규 로드·관계 유지·원본 바이트 보존 회귀.
- foundation: 저장 형식 및 기반 동작 회귀.

## 잔여 범위

- 재선택 UI, 재선택 슬롯 목록·재진입 동작은 아직 미연결이다.
- 사본 출처 검증에는 현재 primary가 필요하다. primary 손상 시 일반 본편 복구를 먼저 실행해야 한다.
- OS 파일 잠금·실제 전원 차단 시험과 최종 UI 경고 표시는 후속 QA 범위다.
