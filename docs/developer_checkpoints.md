# 개발자 모드: 시점·이벤트 바로 이동

## 사용법

Godot에서 `game/project.godot`을 열고 기본 씬을 실행한다. 디버그 실행에서는 타이틀과 플레이 화면 오른쪽 위에 `개발자 · F10` 버튼이 보인다. `F10`으로도 같은 창을 연다.

통합 수첩 또는 엔딩 감상 수첩을 읽는 동안에는 개발자 버튼을 숨기고 F10의 개발자 진입도 중단한다. 수첩의 닫기 버튼과 키보드 입력을 보호하기 위한 예외다. 수첩을 닫으면 다시 진입할 수 있다. F10을 수첩 탐색 키로 재지정한 경우 그 입력은 수첩에 그대로 전달되며, 개발자 도구가 가로채지 않는다. 수첩의 새 데이터 수집·기록 삭제·시점 이동을 자동 실행하지 않는다.

1. 이벤트 ID, 이름 또는 공간을 검색한다. 예: `C4`, `거울`, `P4`, `E3_5`.
2. 목록에서 시점을 선택하고 아래 공간·루프·일지·관계 결산 정보를 확인한다.
3. `선택한 시점에서 새 테스트`를 누른다. 해당 시점의 선행 기록·아이템·퍼즐 상태를 갖춘 실제 게임 화면으로 이동한다.
4. 평소처럼 대화하고 퍼즐을 풀며 다음 이벤트로 진행한다. F10으로 다른 시점으로 다시 이동할 수 있다.
5. 타이틀로 나가거나 게임을 다시 실행한 뒤 `마지막 개발 테스트 이어하기`를 누르면 마지막 자동 저장 위치에서 이어진다.

검색창과 목록, 실행·이어하기·닫기 버튼은 Tab/Shift+Tab으로 이동한다. 목록의 방향키와 Enter를 사용할 수 있고, Esc는 개발자 창을 닫는다. 창이 열린 동안 기존 게임 컨트롤러와 타이머는 정지하고, 닫으면 원래 상태로 돌아간다.

개발 시점 이동은 현재 개발 테스트 슬롯을 선택한 초기 상태로 대체한다. 이미 진행한 개발 테스트를 이어가려면 새 테스트 대신 이어하기를 사용한다. 일반 저장 슬롯 3개는 덮어쓰지 않는다.

## 바로 실행

```powershell
& 'C:/경로/Godot.exe' --path 'C:/Beru/Projects/Games/ggb/game' -- --dev-jump=C4
```

`--` 뒤 인자는 게임에 전달된다. ID가 없거나 잘못되면 현재 진행을 바꾸지 않고 개발자 창에 오류를 표시한다. F10으로 창을 열어 내용을 확인할 수 있다.

## 지원 범위

현재 카탈로그는 89개 시점을 제공한다. 초기 퍼즐은 미해결 상태로 두며, 뒤쪽 이벤트에는 그 시점까지 필요한 기록·아이템·해금 상태가 포함된다.

| 구간 | 대표 ID와 테스트 내용 |
| --- | --- |
| 프롤로그 | `P1`, `P2`, `P3`, `P3B`, `P4`, `P4_MEMORY`, `P5`, `P6`: 일과·차 준비·기억 닻·첫 수면 |
| 수첩·시계 | `A1`, `AS`, `A2`, `B1`, `B2`, `J1`, `B3_A`, `B3_B`, `BF`, `B4`, `B5` |
| 검은 거울 | `C_SLEEP`, `C0`, `C1`, `C2`, `C3`, `C_BELL`, `C4`, `CF`, `C5_INFO`, `J3` |
| 지하·파열 | `D_SLEEP`, `D0`, `D0_A`, `D1`, `DF`, `D2`, `D4`, `D5`, `D6` |
| 사용인 | `E1_ENTRY`, `LUCA_GUIDE`, `LUCA_S2`, `E2_INTRO`, `E_HUB`, `E3_1`~`E3_5` |
| 결산·코어 | `J4`, `E3_4M`, `E5`, `E6`, `F0_A`~`F0_E`, `F1`, `F2`, `F3` |
| 엔딩 선택 | `EDC`, `EDC_LOW`, `EDC_MID`, `EDC_HIGH`, `EDC_ALL` |
| 현실 엔딩 | `EDR_ENTRY`부터 인계·육체 기상·`EDR_FIELD_NOTEBOOK`·시설·지표·`CREDITS_REALITY`까지 각 노드 |
| 잔류 엔딩 | `EDS_ENTRY`부터 기억·외형·자율성 원칙·식탁·`CREDITS_STAY`까지 각 노드 |
| 전원 의식 | `ED_ALL_CEREMONY`: 5인 완료 상태의 현실 분기 의식. 잔류 분기 의식은 `EDC_ALL`에서 잔류를 선택한다. |

관계 미진행부터 5인 완료까지의 엔딩 차이는 `EDC_*`에서 비교한다. 일반 후반 시점은 LOW 기준으로 최초 도달한 상태를 사용한다. 개별 관계 시점은 실제 테스트 경로에서 처음 도달한 상태이므로, 앞서 완료한 다른 사용인이 있을 수 있다. 상세 상태는 게임의 수첩·결산으로 확인한다.

`C4`는 세정제와 신호가 준비되고 경로는 미설정인 상태다. 즉시 회전·고정·분기 선택 및 빛 경로 시험을 할 수 있다. `P4_MEMORY`는 차 준비 여섯 단계를 마친 직후다. `EDR_FIELD_NOTEBOOK`은 필수 페이지를 읽기 전이다.

## 저장과 배포

- 개발 테스트는 실행 중 전체 게임 모드로 전환되며 `user://saves_full/__dev_checkpoint`에 자동 저장한다. 프로젝트 설정 파일은 수정하지 않는다.
- 일반 게임 슬롯과 데모 저장은 유지한다. 타이틀로 돌아가면 진입 전 빌드 모드로 복구한다.
- 개발 테스트의 엔딩 메타·갤러리는 `user://development/profile`에 쓴다. 일반 감상 기록·엔딩 해금과 분리한다.
- 화면 오른쪽 위의 `개발 테스트 · F10` 표시는 테스트 슬롯에서 진행 중임을 나타낸다.
- 편집기 실행 및 debug 빌드에서만 메뉴·이동 API·명령행 진입을 활성화한다. release 빌드에서는 활성화하지 않는다.
- 일반 엔딩 메뉴에서 만드는 재선택 사본도 원본 개발 슬롯의 출처를 확인해 개발용 엔딩 기록을 사용한다.
- 시점 이동마다 새 실행 식별자를 사용한다. 엔딩 본문으로 직접 이동한 경우 그 실행에는 F3 원본이 없으므로 이전 테스트의 재선택 사본을 재사용하지 않는다. 선택 비교는 F10에서 `EDC` 또는 `EDC_*`로 진입한다.

## 데이터 유지보수와 검증

카탈로그 원본은 `game/data/development/checkpoints.json`이다. `developer_checkpoint_generator.gd`는 기존 전편 진행 테스트를 실행해 실제 게임 동작으로 얻은 상태를 수집한다. 새 기능을 개발할 때마다 플레이어가 앞부분을 다시 완료할 필요는 없다.

이벤트 선행 조건이나 저장 설계를 바꾸면 격리된 테스트 프로젝트·사용자 프로필에서 다음 명령으로 재생성하고 생성 파일을 검토한다. 생성기는 전편 테스트용 슬롯을 생성·삭제하고 메모리 상태를 초기화하므로 일반 플레이 실행과 함께 사용하지 않는다.

```powershell
& 'C:/경로/Godot.exe' --headless --path 'C:/격리된프로젝트/game' -- --generate-developer-checkpoints
& 'C:/경로/Godot.exe' --headless --path 'C:/격리된프로젝트/game' -- --developer-checkpoint-smoke
```

생성 성공 시 `DEVELOPER_CHECKPOINTS_GENERATED: 89`, 회귀 검사 성공 시 `DEVELOPER_CHECKPOINT_SMOKE: PASS`가 표시된다. 새 시점 추가 시 개수는 달라질 수 있다.

회귀 검사는 전체 스냅샷의 유효성, 실제 컨트롤러 진입·이벤트 위치, 자동 저장, 거울 퍼즐→C5 진행, F0-E→F1 진행, 현실 수첩 다음 단계, 엔딩 완료와 저장 격리, 잘못된 ID 거부, 테스트 이어하기 및 메뉴 입력을 검사한다. 그래픽 실행에서 `--developer-capture`를 함께 전달하면 `user://developer-panel.png`를 저장한다.

이 기능은 검증된 기준 상태로 특정 시점에 진입하는 도구다. 임의의 변수를 편집하는 콘솔이나 모든 관계 조합을 자동 생성하는 도구는 아니다. A1의 기준 표식은 전편 테스트가 실제로 기록한 집 문양이다.

## 검증 결과: 2026-09-30

- 격리된 Windows Godot 4.7.2 프로젝트에서 89개 시점의 스냅샷 검증, 실제 화면 진입, 자동 저장과 후속 진행 회귀를 통과했다.
- `DEVELOPER_CHECKPOINT_SMOKE: PASS`: headless 실행과 OpenGL 화면 실행 모두 통과했다. 화면 실행에서는 마우스 버튼 입력, Enter 진입, F10 열기, Esc 복귀와 메뉴 캡처를 확인했다.
- 새 시점 이동 시 실행 식별자를 갱신하며, 이전 화면의 지연된 챕터 전환 요청과 이전 실행의 F3 재선택 저장을 재사용하지 않는 것을 검사했다.
- 개발 테스트 이어하기, 저장 실패 시 기존 상태 복구, 일반 슬롯 및 감상 기록 불변성, 개발용 재선택 사본의 엔딩 기록 분리를 검사했다.
- `BASEMENT_SESSION_SMOKE: PASS`: 엔딩 갤러리 경로 변경을 포함한 기존 지하 이후 세션 회귀를 통과했다.
- `scripts/validate_docs.ps1`과 `git diff --check`를 통과했다.
- 실행 환경에서 루트 인증서 저장소 읽기 경고가 발생했으나, 최종 개발자 모드 검사에 스크립트 오류는 없었다. 모든 시점부터 두 엔딩까지 각각 완주한 시험이나 모든 해상도·배율 조합 검증을 뜻하지는 않는다.
