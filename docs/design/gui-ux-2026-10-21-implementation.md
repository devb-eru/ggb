# GUI 적용 기록 · 2026-10-21

사용자 요청: 기존 GUI 설계 대화와 `outputs/ui-assets-2026-10-21/images`를 Godot 전체 UI에 적용한다. 로비는 보드 이미지보다 `gui-ux-2026-10-20/title-preview.html`을 우선한다. 대화 조회는 단일 턴 크기 한도로 실패했으며, 사용자가 로컬 명세 기준 진행을 확인했다.

## 적용

- 로비: HTML의 메뉴 위치(왼쪽 13%, 너비 29%), 오른쪽 원본 주인공, 별도 배경, 고정 클릭 영역. 배경 12/8px, 인물 반대 방향 4/3px 시차. 모션 감소·정적 설정·창 포커스 상실에서 정지한다. 10월 24일 후속 적용으로 새 게임·불러오기·설정·첫 실행 창 뒤에서도 메인 배경과 시차를 유지한다.
- 기존 슬롯·새 게임·덮어쓰기·이어하기·감상·가져오기·종료 기능을 유지한다. 메뉴는 큰 글자에서 스크롤하고 포커스를 따라간다. 유효 저장이 없으면 이유를 표시한다.
- 공통 이미지: `design_theme.gd`가 텍스처·아이콘을 캐시하고 패널·버튼·선택지·체크박스·스크롤바·슬라이더·검색창·저장 슬롯에 연결한다. 원본 텍스트를 그림에 굽지 않는다.
- 수첩: 단서/대화/기록/인물의 왼쪽 책갈피, 밝은 종이와 어두운 잉크. 펼친 책은 비율을 유지한다. 큰 글자·좁은 화면에서는 한 페이지로 바꾸며 기존 A/B 전환을 유지한다. 도구는 본문과 별도로 스크롤한다.
- 통합 수첩을 일반 실행에 연결했다. 검증된 기존 저장의 변환은 기존 SaveManager 경로를 사용한다. 제작용 registry의 승인 상태는 바꾸지 않았다.
- 공통 챕터 HUD: 왼쪽 메뉴·위치, 오른쪽 인벤토리, 왼쪽 아래 수첩. 대화 본문 왼쪽 여백을 줄이고 하단 그라데이션·별도 이름 장식·선택지 이미지를 적용했다. 대화 중 아이템 입력을 막고 레일을 어둡게 표시한다.
- 에드가·마라 2·이리스·주인공은 제공된 원본 레이어를 사용한다. 제공되지 않은 인물과 퍼즐의 근거 도형은 기존 리소스를 사용한다.
- Esc는 대사를 넘기지 않고 메뉴를 연다. 메뉴에서 돌아올 때 대사·선택 및 포커스를 유지한다.
- 지도: 공간 명세의 방·연결도를 데이터로 분리했다. `meta_progress.knowledge_entries.visited_rooms_v1`에 방문한 방을 보존하며, 이동과 같은 저장 트랜잭션에서 커밋·실패 시 롤백한다. 일반 리셋·저장 불러오기 뒤에도 유지한다. 다른 층은 확인한 공간이 있을 때만 표시하며 순간이동은 추가하지 않는다. 현재 위치는 검은 점이다. 기존 저장은 실제 관찰 장소와 현재 위치만 복원하며, 과거의 미기록 방문을 추측하지 않는다.
- 타이틀 설정과 첫 실행에서 한국어/영어를 선택하고 프로필에 보존한다. 진행 저장은 바꾸지 않는다. 변경 뒤 여는 이야기부터 선택한 언어를 사용한다.
- 200% 첫 실행 화면은 제목·시작 버튼을 고정하고 내용만 스크롤한다. 원래 씬의 unique-name 참조와 모달 포커스 순환을 유지한다.

## 자산 재현

`scripts/prepare_ui_design_assets.py`는 선택본 63개의 SHA-256을 확인하고 원본 PNG 및 캐릭터 네 장을 프로젝트로 복사한다. 거의 투명한 생성 여백을 제외하는 `runtime_bbox`를 기록한다. PNG 원본은 바꾸지 않는다. Godot는 이 영역을 잘라 논리 크기의 텍스처를 캐시한다. 원본 명세의 단순 alpha>0 bbox는 일부 버튼에서 실제 형태 바깥의 노이즈까지 포함했다.

폰트는 로고에 시스템 Georgia, 본문에 Godot의 한국어 폴백을 사용한다. 폰트 파일을 새로 배포하지 않는다.

에셋 manifest와 지도 JSON은 `FileAccess`로 읽으므로 Windows export preset의 include_filter에 두 파일을 명시했다. 기존 preset의 다른 설정은 유지한다. 이번 검증은 에디터/런타임 검증이며 새 Windows 배포 빌드를 제작하지 않았다.

## 검증 경로

- `game/scripts/tests/design_ui_audit.tscn`: 실제 UI 캡처, 좌우 구성, 시차 중 클릭 영역 고정, 모션 감소, Esc 보호, 인벤토리 입력 차단, 세로 책갈피 검사.
- 기존 `--start-screen-smoke`: 슬롯·설정·키·음향·접근성·포커스 회귀. 새 스크롤 메뉴의 실제 노출을 검사하도록 레이아웃 경로를 갱신했다.
- 기존 `--notebook-migration-smoke`: legacy 저장·보존·실패 복구 검사.
- 기존 `--notebook-query-smoke`: 검색·비교·읽던 위치·필터·인물·감상 수첩 검사.
- 기존 `--full-campaign-smoke`: 프롤로그부터 엔딩까지의 저장/진행 회귀.
- `discovered_rooms_smoke.gd`: 대사 없이 방문한 방의 실제 파일 재로드, 일반 수면 리셋 후 유지, 저장 실패 시 이동/방문 동시 롤백, 미해금 이동의 비공개, 프롤로그 저장 후보의 불변성 검사. `design_ui_audit.tscn`에서 함께 실행한다.

초기 캡처와 로그는 `outputs/ui-implementation-2026-10-21/`에 모았다. 최신 통합 검사는 `outputs/ui-design-audit-2026-10-24/`에 보고서와 캡처를 저장한다. 검사 데이터는 격리된 APPDATA에서 실행하며 실제 플레이 저장을 사용하지 않는다. 엔진의 인증서 저장소 경고 및 검사 인스턴스 간 개발 MCP 포트 충돌은 UI 파싱/판정과 구분한다.

Godot 4.7.2 검증 결과: 타이틀 smoke PASS, 캠페인 전체 smoke PASS, 수첩 query smoke PASS(6,837 checks), 저장 migration smoke PASS(저장 안전 381 checks 포함). 캡처 audit는 좌우 배치·모션 감소·Esc·입력 보호·언어 보존·지도 비공개 범위·200% 배치·씬 참조를 확인한다. 로그에 PASS가 있어도 별도 GDScript 오류가 있는 실행은 통과 근거에서 제외하고 수정 후 재검사했다.

후속 제목·방문 보존 적용 뒤 타이틀 smoke와 전체 캠페인 smoke를 재통과했다. 방문 기록 smoke PASS 및 최종 캡처 audit `ok: true`를 확인했다. 200% 메뉴 끝의 1px 잘림은 포커스 스크롤에 여백을 확보해 수정했다. 한국어·영어 제목과 200% 제목, 지도 캡처를 육안 확인했다.
