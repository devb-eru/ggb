# D6 조사와 두 휴식 경로

검토일: 2026-09-13

## 구현 범위

D5 이후 본편에 전용 D6 화면을 연결한다. 기존 저장이 지하창고나 태엽 심장실에서 재개되면 드러난 서비스 통로로 이동하는 입력을 제공한다. 이미 침실에 있는 기존 저장은 침실 화면으로 재개한다.

`H0_SERVICE_SPINE`의 벽지·표지·진단 잔상·비상 캡슐 표면·수첩을 선택 조사한다. 서로 다른 조사 ID를 `knowledge_entries.D6_objects_seen`에 중복 없이 저장하고 수첩에 감각 문구를 남긴다. 두 대상 이상을 조사하면 목표에 수면 절차 안내를 다시 표시한다. 조사 개수와 관계값은 진행 게이트가 아니다.

- 침실: 통로 → 침실 → 수면 확인, 또는 통로로 돌아가 추가 조사.
- 캡슐: 통로의 상호작용 → 수면 확인. 별도 탐색 지역으로 등록하지 않는다.
- 확인창 기본 선택은 ‘조금 더 본다’. 취소에는 상태 변경이 없다.
- 확인창은 침실의 이불 아래 곡면과 캡슐 금속 위 투사 질감을 다르게 서술한다. 공통 경고는 현재 파열 상태를 기준으로 수면 전환이 시작되며 결과는 미확인이라고 명시한다. 세계가 정상으로 초기화된다고 약속하지 않는다.
- 확정한 경로는 `loop_state.event_local_states.D6.fracture_rest_route`에 `bedroom` 또는 `emergency_capsule`로 저장한 뒤 기존 BROKEN_RESET을 요청한다. 수면 전 재실행에서는 선택이 유지된다. 첫 파열 수면의 물리 전환 뒤에는 로컬 경로를 지우며 영구 분기로 보존하지 않는다. 조사 기록은 별도의 수첩 정보다.
- 이전 개발 저장의 `knowledge_entries.D6_rest_route`는 초기화 시 제거한다. 아직 첫 파열 수면 전이고 유효한 값이면 기존 로컬 값을 덮어쓰지 않고 로컬 경로로 변환한다. 이미 파열 수면을 마친 저장에는 새 경로를 만들지 않는다.
- 두 경로 모두 같은 침실의 E1로 이어진다. 첫 파열 수면은 기존 리셋 코디네이터가 실행하며 별도 리셋 구현을 만들지 않는다.

D6에서는 과거 일과·장치 조작을 거부한다. 데모는 기존 종료 차단을 유지한다. D5 완료 저장·본편 가져오기 규칙을 변경하지 않는다.

## 검증 범위

격리 프로젝트의 Godot 4.7.2 import 및 `BASEMENT_SESSION_SMOKE` 최종 실행 PASS. 초기 실행에서 발생한 수면 조건 타입 추론 오류는 명시적 bool 선언으로 수정했다. 최종 실행은 인증서 저장소 경고 외 SCRIPT ERROR가 없다.

후반 세션 회귀에 실제 D6 버튼 진입, 다섯 조사점·수첩 재조사 중복 방지·수면 안내·저장 재로드, 이전 일과와 미확인 캡슐 수면 거부, 취소 불변성, 두 휴식 경로의 E1 합류, 수면 전 로컬 경로 재로드와 수면 후 제거·관계 보존 검사를 추가했다.

최종 통로·캡슐 아트, 이동 연출, D6 영어 전체, 실제 OS 입력 완주와 3~8분 조사 플레이타임 검증은 남는다. 도입 안내와 버튼·감각 텍스트를 연결한 단계이며 전체 장면 완성 판정이 아니다.

### 과거 개발 저장 호환 검사

2026-09-13 격리 headless `BASEMENT_SESSION_SMOKE` PASS. 아래 호환 검사와 기존 데모·본편·관계·엔딩 회귀를 함께 실행했다.

과거 필드 형식을 재현한 일곱 fixture를 `SaveManager.save_snapshot`으로 기록하고 `LoadCoordinator`로 읽어 실제 `BasementSession.initialize` 변환을 거친다. 침실·캡슐 변환, 상충하는 새 로컬 값 우선, 로컬 추가 필드 보존, 잘못된 값 제거, 첫 수면 이후 두 과거 값의 제거를 검사한다. 변환 후 재로드·재초기화가 같은 결과를 유지하는지도 확인한다.

잘못된 슬롯 경로를 주입한 초기화 실패에서는 변환 전 선택이 보존되어야 하며, 경로 복원 후 캡슐 선택으로 변환되어야 한다. 이는 저장 계층을 이용한 합성 과거 형식 검증이며 실제 사용자 저장 표본이나 디스크 단절·강제 종료 전 조합을 대체하지 않는다.
