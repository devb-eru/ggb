# Windows 입력 방식별 전편 완주 검증

최종 갱신: 2026-09-19

## 목적

자동 세션 호출이나 진행 상태 fixture 대신 Windows에서 실행 중인 실제 Godot 게임 창에 한 종류의 입력만 전달해, 새 게임부터 엔딩 후 화면까지 필수 경로를 완주할 수 있는지 확인한다. 마우스와 키보드는 서로 다른 새 사용자 프로필과 저장 슬롯을 사용한다.

이 검증은 사용자와 합의한 현재 개발 중단선의 마지막 단계다. 최종 아트·BGM·SFX 교체와 해당 리소스를 전제로 한 연출 보강은 리소스 공급 뒤 재개한다.

## 실행 조건

| 항목 | 마우스 전용 | 키보드 전용 |
| --- | --- | --- |
| 실행 환경 | Windows, Godot 4.7.2 창 모드 | Windows, Godot 4.7.2 창 모드 |
| 격리 프로필 | `GGBInputValidationMouseRun` | `GGBInputValidationKeyboardRun` |
| 시작 상태 | 최초 실행 접근성 확인 전 | 최초 실행 접근성 확인 전 |
| 허용 입력 | 포인터 이동·좌클릭 | `Tab`, 방향키, `Enter` |
| 본편 모드 | `--ggb-dev-full --input-validation` | `--ggb-dev-full --input-validation` |
| 관계 경로 | LOW, 완료 0명 | LOW, 완료 0명 |
| 엔딩 | 현실 | 현실 |
| 최종 상태 | `POST_CREDITS` | `POST_CREDITS` |

`--input-validation`은 격리 검증 복사본에만 둔 부트스트랩 옵션이다. 자동화 도구가 게임 창을 직접 포커스하지 못하는 환경에서 포커스 상실 일시정지만 무시하며, 퍼즐 정답·진행 조건·저장 데이터는 변경하지 않는다. 운영 프로젝트와 배포 빌드에는 이 옵션 및 검증용 런타임 애드온을 포함하지 않는다.

## 입력 전달과 관찰 경계

- 입력은 실제 Windows Godot 프로세스에 런타임 프로토콜의 `inject_mouse_motion`, `inject_mouse_click`, `inject_key`로 전달했다.
- 마우스 경로에는 키 입력을, 키보드 경로에는 마우스 입력을 보내지 않았다.
- 화면 트리, 표시 여부, 포커스 소유자와 컨트롤 사각형은 다음 입력 대상을 찾기 위한 읽기 전용 관찰에만 사용했다.
- 진행 플래그, 퍼즐 값, 저장 상태를 메서드 호출로 변경하지 않았다.
- 이는 운영체제 `SendInput`이나 사람이 물리 장치를 조작한 시험이 아니다. Godot의 실제 입력 이벤트 처리, 포커스 이동, 버튼 활성화와 장면 전환을 통과했다는 증거다.

## 공통 완주 경로

두 경로 모두 다음 내용을 처음부터 순서대로 수행했다.

1. 최초 접근성 확인, 새 게임, 슬롯 1 선택.
2. P1~P6의 침실 조사, 창문 청소, 서재·초상화, 차 준비, 첫 수면과 정상 리셋.
3. A1~J2의 자기 표식과 영구 정보 확인. B3을 의도적으로 실패해 잠금·수면·BSHORT를 거친 뒤 재해결.
4. C0~J3의 세정제 제조와 거울 회로. C4를 의도적으로 실패해 코팅 경화·수면·CSHORT를 거친 뒤 재해결.
5. D0~D6의 지하창고와 태엽 심장. D1을 의도적으로 실패해 축 잠금·수면·DSHORT를 거친 뒤 D5 10초 고정과 BROKEN_RESET 수행.
6. E1~E2 조사 뒤 관계 사건을 완료하지 않은 LOW 경로로 J4 BASE, 에드가 최소 절차, E5 LOW와 E6 진행.
7. F0-A~E를 해결하고 현재 권한은 `undecided`로 남김. F1, J5, F2, F3를 거쳐 현실 엔딩을 명시적으로 선택.
8. 다섯 사용인 인계, 신체 확인, 현실의 현장 수첩, 출구 상태, 지표의 마지막 시선, 크레딧을 거쳐 `POST_CREDITS` 도달.

## 결과

| 검증 | 결과 | 성공 표식 |
| --- | --- | --- |
| 마우스 전용 | PASS | `PASS MOUSE-ONLY FULL PLAYTHROUGH: POST_CREDITS REALITY LOW` |
| 키보드 전용 | PASS | `PASS KEYBOARD-ONLY FULL PLAYTHROUGH: POST_CREDITS REALITY LOW` |

두 실행 로그에서 루트 인증서 저장소 경고 외 `SCRIPT ERROR`는 없었다. 프로세스 종료 전 실행 파일 경로와 시작 시간을 대조했으며 검증용 Godot 프로세스를 남기지 않았다.

## 발견 결함과 수정

### J4 지연 활성화 버튼의 Tab 순환 누락

J4 조사 종료 확인창은 오입력 방지를 위해 `기록을 정리한다`를 0.5초 뒤 활성화한다. 모달 최초 구성 시 비활성 버튼이 Tab 순환 목록에서 제외됐지만, 활성화 뒤 포커스 이웃을 갱신하지 않아 `Tab`만으로 해당 버튼에 도달할 수 없었다. 방향키로는 이동할 수 있어 완주 자체는 가능했으나 공통 키보드 계약과 맞지 않았다.

`BasementController._enable_j4_confirm()`이 버튼을 활성화한 직후 `_cycle_modal_focus()`를 다시 호출하도록 수정했다. 현재 포커스를 강제로 이동하지 않으면서 표시 중이고 활성화된 모든 버튼의 `focus_neighbor_top`·`focus_neighbor_bottom`을 다시 연결한다.

## 판정과 남은 범위

다음 항목은 완료로 판정한다.

- 전편 영문 진행
- 관계 LOW/MID/HIGH/ALL 경로와 두 엔딩 자동 연속 회귀
- Windows Godot 창의 마우스 전용 필수 경로 완주
- Windows Godot 창의 키보드 전용 필수 경로 완주

다음 항목은 이번 중단선 밖에 남긴다.

- 최종 아트·BGM·SFX 교체
- 최종 리소스에 맞춘 카메라, 타이밍, 감각 연출 보강
- 목표 플레이타임과 퍼즐 체감 난이도의 사람 대상 실측
- 다중 해상도·DPI·장시간 저장·강제 종료 조합
- 운영체제 `SendInput` 및 물리 장치 조작을 이용한 출시 전 교차 확인

크레딧 제작진 명단은 사용자 지시에 따라 미정으로 유지한다.
