## 2. 목적

20~30분 버티컬 슬라이스에 실제로 보이거나 조작되는 아트 범위를 빠짐없이 제작한다. 대표 샘플 몇 장이 아니라 아래 편집 경로를 처음부터 끝까지 실행할 수 있는 공간, 오브젝트, 퍼즐 조작부, UI와 반응 상태가 납품 대상이다.

```text
VS01_OPENING_RECAP
→ A1
→ NORMAL_SLEEP → NORMAL_RESET
→ A2
→ VS01_B3_CONTEXT_FIXTURE
→ B3_A
→ B3_B 확정 물리 실패 → BF
→ NORMAL_SLEEP → NORMAL_RESET
→ VS01_EDGAR_MEMORY_REACTION
→ BSHORT
→ B3_B 성공
→ VS01_S2_PREVIEW
```

검증 목표:

1. 같은 침실이 리셋 전후 물리적으로 같은 장면처럼 보이는가.
2. 수첩의 흑연 표시만 남아 세계와 주인공의 연속성이 분리되는가.
3. 외부 서고에서 조사, 읽기, 잠긴 문, 퍼즐 진입이 서로 다른 시각 언어로 읽히는가.
4. B3-A의 회전·반전·연결 검증과 B3-B의 역할·위상·비가역 실행이 색 없이 구분되는가.
5. 실패 뒤 물리 잠금, 다음 아침의 복원, 숏컷 복귀와 성공이 같은 오브젝트의 다른 상태로 명확히 이어지는가.
6. 에드가가 기억하면서도 공격하거나 장치를 빼앗지 않는 태도가 표정·자세·배치로 전달되는가.
7. S2 미리보기가 정식 폭로를 선행하지 않으면서 고딕 외피 아래 기계성을 예고하는가.
8. 실제 제작·수정·승인 시간을 측정해 데모 잔여 에셋 공수를 산정할 수 있는가.

## 4. 범위와 완전성 규칙

### 4.1 포함

- 정식 조작 공간 3종과 `BSHORT` 몽타주에 보이는 대응접실 크롭 1종.
- 조작 공간 안의 모든 활성 상호작용 영역과 상태 변형.
- 이동문·잠긴 문·읽기 자료처럼 퍼즐이 아니어도 클릭 가능한 대상.
- B3-A·B3-B의 모든 조작부, 사전 검증, 실행 확정, 실패, 복원, 숏컷, 성공 상태.
- NORMAL_RESET 전환, 에드가 대표 하위 세트, 수첩·대화·기록·퍼즐 UI.
- 1280x720~4K, 90~220% UI, 키보드 전용, 색 제거, 모션 감소 검증 산출물.

### 4.2 제외

- P1~P6 전체 프롤로그와 정식 B1·B2·J1 진행.
- `M1_LIBRARY_INNER`, C 이후 공간, D5 파열과 엔딩.
- 마라 1·루카·이리스·마라 2의 캐릭터 세트.
- 에드가 캐릭터 초상 10종·자세 6종 전체의 완료 판정.
- 주인공의 최종 체형·정확한 나이·이름을 전제로 한 character sheet.
- `M2_UPPER_HALL`, `M1_CENTRAL_HALL`, `M1_WEST_HALL`의 이동 화면. 본 버티컬 슬라이스에서는 문 선택 뒤 컷으로 전환하며 해당 공간을 보여 주지 않는다.
- 최종 색채 설계 확정, 홍보 일러스트, 엔딩 전용 에셋.

### 4.3 누락 방지 규칙

1. 이 문서의 공간 배치표에 없는 클릭 가능 대상은 버티컬 슬라이스에 추가하지 않는다.
2. 배경 소품은 `DECORATIVE`, 클릭 대상은 `INTERACTIVE`, 이동은 `NAVIGATION`, 읽기 자료는 `READABLE`로 표시한다.
3. `DECORATIVE`를 클릭 가능하게 바꾸면 의뢰 개정 번호와 오브젝트 카드가 먼저 추가돼야 한다.
4. 독립 `asset_id`가 없는 작은 조작부도 `VSART_*` 부품 ID와 부모 에셋, 상태, 내보내기 레이어를 가진다.
5. 오브젝트의 외형 변화는 기본 그림에 덧칠하지 않고 상태 레이어로 분리한다.
6. `M1_PARLOR`는 1.0~1.8초의 비상호작용 몽타주다. 그 장면에서 클릭·정지·읽기를 제공하지 않는다.

## 7. 오브젝트 명세

### 7.1 아트팀용 상태 용어집

상태 ID는 파일명·데이터 연결·검수 추적을 위해 유지한다. 아트팀 회의, 작업 보드와 피드백에서는 한국어 표시명을 먼저 쓰고 필요한 경우에만 괄호 안에 상태 ID를 병기한다.

```text
권장 표기: 기본 대기(idle), 문서 펼침(spread), 점검표 선택(maintenance_selected)
지양 표기: idle 상태 주세요, maintenance_selected 수정
```

새 상태가 필요하면 임의의 영문 값을 먼저 만들지 않고, 한국어 표시명·필요한 화면 변화·부모 오브젝트를 합의한 뒤 상태 ID를 발급한다.

#### 공통 상태

| 상태 ID | 아트팀 표시명 | 화면에서 확인할 변화 |

| 항목 | 요구 |
| --- | --- |
| 부모 에셋 | `ART_OBJ_BEDROOM_BED` |
| 외형 | 낮고 넓은 고딕 목제 침대, 조각된 목제 프레임, 직물 캐노피와 두꺼운 이불. 구체 색상은 아트팀 제안 |
| 핵심 인상 | 안락하지만 천 아래 지지면이 지나치게 단단함. 의료 캡슐로 단정할 단서는 금지 |
| 상태 ID | `idle`, `focus`, `inspect_pressure`, `sleep_confirm`, `cancel_return`, `post_reset` |
| 변형 | 취침 때 이불이 몸 무게만큼 내려앉고, 리셋 뒤 같은 주름·같은 함몰로 복귀 |

| 납품 분리 | 프레임, 이불, 캐노피, 함몰 그림자, 조작 초점 덧씌움, 전경 침대 기둥 |

### 7.9 에드가 반응 오브젝트·캐릭터 범위

에드가는 최고령 책임자, 컨트롤 프릭, 정갈하고 무뚝뚝한 비서 인상이다. 용 계열의 뿔·꼬리와 레이피어가 있으며 모든 대사는 다나까체다.

| 상태 ID | 아트팀 표시명·얼굴·자세 | 숨은 의도 | 사용 위치 |
| --- | --- | --- | --- |
| `neutral` | 무표정. 시선 수평, 입매 닫힘, 레이피어 세움 | 규칙이 유지되면 감정을 감춤 | 시작·일반 조사 |
| `report` | 보고. 수첩·시계 확인, 정확한 손짓 | 사건을 통제 가능한 항목으로 바꿈 | B3 진입·결과 보고 |
| `guarded` | 경계. 꼬리·어깨 긴장, 문 옆으로 비켜섬 | 막고 싶지만 개입 규칙과 애착이 충돌 | 실패 뒤 재대면 |
| `startled` | 동요. 손·꼬리가 얼굴보다 먼저 굳음 | 이전 실패를 기억한다는 누수 | `VS01_EDGAR_MEMORY_REACTION` |
| `interact` | 상호작용 자세. 칼집·손잡이로 선을 가리킴 | 위협 없이 정보 위치를 안내 | 서재·대시계 |

- 레이피어 날끝을 주인공이나 UI 선택지에 향하지 않는다.
- 경계 자세(`guarded`)는 출입구·시계·수첩 상호작용 영역을 완전히 가리지 않는다.
- 에드가의 정본 테마색은 참고 자료로만 제공한다. 구체 색상·명도·채도·적용 면적은 아트팀이 제안하며, 기억 서명은 수직선·각인·낮은 시계음 대응으로도 식별돼야 한다.
- 회색조에서도 뿔, 꼬리, 레이피어, 직선 자세로 식별돼야 한다.

### 7.10 UI 오브젝트

#### `UI_DIALOGUE`

- 이름판, 본문, 진행 표시, 선택지, 시스템 알림을 분리한다.
- 화면 하단을 기본 영역으로 쓰되, UI 배율 200%에서는 본문을 위쪽으로 확장할 수 있다.
- 에드가 캐릭터 초상은 왼쪽·오른쪽 중 한 위치를 팀 합의 뒤 고정하며, 현재 상호작용 영역을 가리면 자동으로 반대편에 배치한다.
- 선택지는 `잠든다`·`조금 더 둘러본다`, `시험`·`실행`처럼 위험도가 다른 행동을 크기나 색으로 편향하지 않는다.

#### `UI_DIALOGUE_HISTORY`

- 화자, 사건, 최초·반복을 필터링할 수 있는 목록과 상세 화면을 제공한다.
- 아직 보지 않은 분기 문구는 제목·길이로도 추측할 수 없게 숨긴다.
- 감각 자막은 대사와 다른 아이콘·`감각` 라벨을 사용한다.

#### `UI_NOTEBOOK`

- 탭은 관찰·가설·검증·실패 기록·인물·서명 순이다.
- A1·A2 비교 화면은 왼쪽 `전날 표시`, 오른쪽 `같은 아침의 물리 초기화`를 병렬 배치한다.
- BF는 맞은 단계와 틀린 범주만 보여 주고 잠긴 정답 전체를 공개하지 않는다.
- BSHORT에서는 검증된 역할과 다시 선택할 위상을 분리한다.

#### `UI_PUZZLE_COMMON`

- 가리킴(`hover`), 조작 초점(`focus`), 선택(`selected`), 비활성(`disabled`), 유효하지 않음(`invalid`), 확정(`confirmed`)을 독립 상태로 제공한다.
- 드래그 대신 선택→대상 선택, 회전 버튼, 앞/뒤 버튼, 키보드 방향키 경로를 제공한다.
- 1280x720·200% UI에서 퍼즐 본체, 확인·취소, 힌트 진입이 동시에 사용 가능해야 한다.
- 위험한 `현재 설정으로 작동한다`는 2단 확인을 갖지만, 기본 조작 초점(`focus`)은 안전한 `약한 시험 진동`에 둔다.

## 9. 식별·명도·접근성

### 9.1 색채 운영 원칙

- 이 의뢰서는 HEX 값, 색상명, 명도·채도 수치와 적용 면적을 고정하지 않는다.
- 캐릭터 정본의 테마색은 정체성 참고 자료이며, 실제 화면의 배색·광원·재질색은 아트팀이 공간별로 제안한다.
- 색은 분위기와 빠른 인지를 보조할 수 있지만 퍼즐 정답, 위험도, 선택 우선순위를 단독으로 전달하지 않는다.
- 기획 검수에서는 특정 색의 사용 여부보다 식별성, 시선 흐름, 상태 차이와 접근성 대체 표현을 확인한다.
- 색채 시안은 최소 2개가 아니라 아트팀이 필요하다고 판단한 수량만 제안하고, 불필요한 변형 제작은 요구하지 않는다.

| 대상 | 반드시 전달할 의미 | 아트팀 자율 범위 | 색 이외의 필수 식별 요소 |
| --- | --- | --- | --- |
| 에드가의 데이터 서명 | 통제·잠금·정렬 | 색상·명도·채도·적용 면적 | 수직 잠금선, 낮은 시계음, 레이피어의 직선 실루엣 |
| 주인공의 지속 정보 | 사용인 데이터와 다른 개인 기록 | 종이·필기구·UI 배색 | 흑연 압흔, 종이 섬유, 손글씨, 필기음 |
| 조작 초점(`focus`) | 현재 조작 대상 | 외곽 강조의 색·재질·광량 | 외곽선, 모서리 표식, 대상 명칭 |
| 유효하지 않음(`invalid`) | 현재 조합 불가 | 경고 강조 방식 | 끊긴 윤곽, 금지 표식, 상태 라벨 |
| 확정(`confirmed`) | 입력이 저장됨 | 완료 강조 방식 | 도장, 노치, 고정 위치, 확인 문구 |
| S2 데이터 누수 | 고딕 외피 아래 기계층 노출 | 기계층의 색·반사·광원 | 이중 윤곽, 체결부, 재질 경계, 기계음 |

### 9.2 필수 접근성 확인 자료

- 색 제거·회색조 확인 이미지.
- 적록·청황 구분 저하 모의 확인 이미지.
- 90%, 100%, 150%, 200%, 220% UI 배율별 확인 이미지.
- 모션 감소 설정의 정적 전후 화면.
- 음량 0에서도 B3-A/B3-B 성공·실패가 구분되는 확인 이미지.

## 10. 레이어·상호작용 영역·내보내기 계약

### 10.1 공간 명세표 필수 열

논리 좌표는 의뢰서와 공간 명세표에 기록하지 않는다. 아트팀은 아래의 상대 배치 설명과 앞뒤 관계로 구도를 제안하며, 실제 상호작용 판정 영역은 구현 단계에서 확정한다.

| 아트팀 표기 | 기술 식별자 | 작성 기준 |
| --- | --- | --- |
| 장소 ID | `location_id` | §6의 공간 ID |
| 에셋 ID | `asset_id` | 자산 대장의 정식 ID |
| 부품 ID | `part_id` | 오브젝트 내부 분리 부품 ID |
| 분류 | `classification` | 이동·상호작용·가독 자료·장식 분류 |
| 화면 내 상대 위치 | `relative_placement` | 왼쪽·중앙·오른쪽, 전경·중경·후경, 인접 오브젝트와의 관계 |
| 레이어명 | `layer_name` | §6 공통 깊이 레이어 ID |
| 앞뒤 순서 | `z_order` | 같은 레이어 안의 가림 순서 |
| 기본 조작 초점 순서 | `default_focus_order` | 키보드·패드 이동 순서 |
| 캐릭터 가림 규칙 | `character_occlusion_rule` | 캐릭터·대화창과 겹칠 때의 처리 |
| 상태 ID | `states` | §7.1 용어집에 등록된 상태 ID |
| 부모 에셋 ID | `parent_asset_id` | 부품이 소속된 상위 에셋 |
| 비고 | `notes` | 전환, 변형, 모션 감소 등 추가 조건 |

### 10.2 파일명

```text
<asset_id>__<part_id>__<state>__rNN.png
<asset_id>__room_sheet__rNN.csv
<asset_id>__layer_guide__rNN.png
```

파일명 안의 `room_sheet`, `layer_guide`, `state`는 자동 연결을 위한 고정 식별자다. 아트팀 문서와 폴더 제목에는 각각 `공간 명세표`, `레이어 안내`, `상태`로 병기한다.

예시:

```text
ART_OBJ_BEDROOM_WINDOW__glass__post_reset_clean__r01.png
ART_PUZ_B3_B_PANEL__VSART_B3B_SEAL_PIN__bent_left__r01.png
ART_BG_M1_LIBRARY_OUTER__room_sheet__r01.csv
```

### 10.3 납품 묶음

| 묶음 | 요구 |
| --- | --- |
| 편집 원본(`source`) | PSD·KRA 등 편집 가능한 원본, 숨김 레이어 포함, 폰트·브러시·텍스처 출처 |
| 게임 적용본(`runtime`) | 투명 PNG 또는 합의한 Godot 입력 형식, 투명 여백 정리 정보와 피벗(배치·회전 기준점) |
| 공간 명세표(`room_sheet`) | 상대 배치, 상호작용 영역, 조작 초점 순서, 배치 기준, 가림, 안전 영역 |
| 오브젝트 명세표(`object_sheet`) | 부품별 외형·상태·크기·피벗·애니메이션 프레임 |
| 확인 이미지(`preview`) | 1920x1080, 1280x720, 4K, 200% UI, 색 제거, 모션 감소 |
| 상태 연출 모음(`state_reel`) | 도입→리셋→A2→실패→리셋→숏컷→성공→S2 예고 순서 영상 또는 연속 프레임 |
| 공수 산정(`estimate`) | 공간·오브젝트·퍼즐·UI·캐릭터별 신규 제작·수정·검토 시간과 재사용률 |
| 권리 자료(`rights`) | 실제 제작자와 `RIGHTS-YYYY-NNNN` 비공개 증거 참조 |

승인 전 편집 원본과 게임 적용본을 같은 파일로 덮어쓰지 않는다. 개정 번호는 `r01`부터 올리고 반려 시 새 파일을 만든다.

## 12. 검수 체크리스트

### 12.1 공간

- [ ] 네 공간 모두 배치표의 부품이 빠짐없이 보인다.
