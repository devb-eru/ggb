## 2. 목적

버티컬 슬라이스에 필요한 한국어 원문 후보를 하나의 구조화된 정본으로 작성한다. 대사뿐 아니라 플레이어가 오브젝트를 클릭하고, 수첩에 표시하고, 퍼즐 부품을 획득·배치·회수하며, 실패·숏컷·성공을 겪을 때 표시되는 모든 텍스트를 포함한다.

이 배치에서 검증할 질문:

1. 플레이어가 NORMAL_RESET과 디스크 저장을 문구만으로도 구분하는가.
2. 수첩의 표시와 실패 정보가 남는 이유를 과도한 설명 없이 이해하는가.
3. B3-A에서 검증한 정보와 B3-B에서 바꿔야 할 위상을 구분하는가.
4. 에드가가 실패를 기억하면서도 즉시 장치를 빼앗지 않는 이유가 인물 성격과 시스템 규칙 양쪽에서 납득되는가.
5. 클릭·획득·사용·거부·첫 조사·반복 조사 문구가 세계의 감각과 짧은 일화를 축적하는가.
6. 실제 문자열 수, 한국어 분량, variant 작성·검수 시간을 측정할 수 있는가.

## 5. 편집 경로와 정보 공개선

```text
VS01_OPENING_RECAP
→ A1
→ NORMAL_SLEEP·NORMAL_RESET
→ A2
→ VS01_B3_CONTEXT_FIXTURE
→ B3_A
→ B3_B 실패·BF
→ NORMAL_RESET
→ VS01_EDGAR_MEMORY_REACTION
→ BSHORT
→ B3_B 성공
→ VS01_S2_PREVIEW
```

### 5.1 이 배치에서 말해도 되는 것

- 세계의 물리 배치가 잠든 뒤 같은 아침으로 돌아왔다.
- 주인공 수첩의 연필 표시와 정리된 지식은 남는다.
- 에드가는 이전 loop의 큰 소리·파손·주인공 반응을 희미하게 기억한다.
- 에드가는 아가씨의 일을 대신 수행할 수 없고 경고·확인 횟수에 한계가 있는 듯 행동한다.
- 대시계의 고딕 표면 아래 다른 재질과 규칙적인 신호가 있다.

### 5.2 이 배치에서 직접 말하지 않는 것

- 세계가 시뮬레이션이라는 정답.
- 사용인이 연구원의 인격 데이터라는 사실.
- 아버지가 연구원을 통 속의 뇌로 만들었다는 사실.
- 현실 지구의 상태, 냉각 장치와 두 엔딩.
- C5가 아닌 preview를 정식 S2 진입으로 해석하게 하는 시스템 문구.

## 7. 원문 레코드 계약

납품 CSV의 모든 행은 다음 필드를 가진다.

```text
draft_id,request_id,content_item_id,content_type,ko_KR,speaker_id,
source_event_id,location_id,object_id,trigger,condition,emotion,
hidden_intent,register,variables,max_lines,max_width_class,spoiler_tier,
state_reads,state_writes,repeat_policy,notes
```

### 7.1 필드 규칙

| 필드 | 규칙 |
| --- | --- |
| `draft_id` | `DRAFT_VS01_0001`처럼 배치 안에서 유일. runtime ID 아님 |
| `request_id` | 모든 행에 `REQ-CNT-2026-0001` |
| `content_item_id` | 위 17개 항목 중 하나 |
| `content_type` | `dialogue`, `monologue`, `inspect`, `acquire`, `use`, `deny`, `hint`, `readable`, `notebook`, `system`, `caption`, `choice` |
| `speaker_id` | `SERVANT_EDGAR`, `SUBJECT`, `SYSTEM` 중 하나 |
| `source_event_id` | 정식 ID 우선. build wrapper이면 `VS01_*`임을 notes에 표시 |
| `trigger` | `click`, `acquire`, `place`, `remove`, `confirm`, `state_enter`, `first_inspect`처럼 실제 행동 |
| `condition` | 읽는 상태를 bool식이나 의미 토큰으로 기록. 무조건은 `always` |
| `state_reads` | 문구 선택에만 사용한 상태. `none` 허용 |
| `state_writes` | 본문 표시로 쓰는 상태. 순수 반응은 `none`; 이벤트 완료는 정본 플래그만 |
| `repeat_policy` | `once`, `first_repeat`, `per_loop`, `state_variant`, `always` |
| `emotion` | 표면 감정과 실제 감정이 다르면 `surface:*;subtext:*` |
| `max_lines` | 200% UI에서 한 페이지 최대 줄 수. 넘으면 page 분리 |
| `spoiler_tier` | `always`, `seen_only`, `state_locked`, `never_in_history` |

## 8. 이벤트별 작성 지침

### 8.1 VS01_OPENING_RECAP

- 프롤로그를 요약 설명하지 않고 창빛·침구 주름·새소리가 전과 같다는 주인공의 짧은 감각으로 시작한다.
- 에드가는 정갈한 다나까체로 당일 과업을 길게 나열하지 않는다.
- 이 빌드가 중간에서 시작한다는 개발자 안내가 필요하면 서사 문장과 분리된 `SYSTEM`, `never_in_history`로 쓴다.
- “꿈이었다”나 “시간이 되감겼다”를 확정하지 않는다.

### 8.2 A1·A2 수첩

| 상태 | 반드시 포함할 정보 | 피할 문구 |
| --- | --- | --- |
| A1 blank | 남길 표시는 짧고 본인이 알아볼 수 있어야 함 | 플레이어 대신 문구 의미를 과하게 결정 |
| A1 written | 연필선뿐 아니라 종이의 눌린 홈 | 마법처럼 빛나는 영구 표시 |
| A2 retained | 방은 원래대로인데 표시와 압흔은 남음 | `SAVE COMPLETE`와 같은 저장 표현 |
| repeat | 이미 확인한 사실을 한 문장으로 축약 | 매 loop 첫 발견 독백 반복 |

표시의 실제 문구는 짧은 도형·선과 1~4어절 정도로 제안한다. 주인공의 이름·생년·정확한 나이를 사용하지 않는다.

### 8.3 NORMAL_SLEEP·NORMAL_RESET

필수 UI 의미:

```text
잠든다: 현재 하루의 물리 상태를 끝내고 다음 아침으로 간다.
조금 더 둘러본다: 취소하고 방으로 돌아간다.
디스크 저장: 진행 데이터를 보관하며 하루를 끝내지 않는다.
```

- 첫 수면 확인문은 결과를 알려주지 않아도 되지만 reset을 경험한 뒤의 확인문은 “방 안의 물건은 아침 상태로 돌아간다”는 정보를 제공한다.
- commit 뒤 시스템 문구는 저장 완료음·세이브 슬롯 문구와 용어를 공유하지 않는다.
- 강제 종료 복구 문구는 “마지막으로 확정된 아침에서 이어집니다”처럼 복구 지점을 알려준다.

### 8.4 B3-A

필요한 상호작용:

- 외부 서고 중계 시계 첫 조사와 뒤판·panel 열기.
- 탁본 조각 선택·회전·반전·배치·회수.
- 맞는 연결, 연결 불가, 아직 비어 있는 연결.
- 로컬 재시도. NORMAL_RESET과 다른 범위임을 명시.
- 검증 완료와 `B3_RUBBING_SET` 확보.
- 1차·2차 힌트. 1차는 조작 규칙, 2차는 연결부 형태를 가리킨다.

힌트는 B3-B의 역할·위상 정답을 제공하지 않는다. “색이 같다”는 표현 대신 선 끝, 노치, 문양 방향과 연결 여부를 사용한다.

### 8.5 B3-B

필요한 상호작용:

- 기준·중계·출력·제외 역할의 조사명.
- 역할 배치·교체·제거.
- +1 위상 이동과 현재 위상 상태.
- 실행 전 summary와 `실행한다`·`다시 확인한다`.
- 검증된 역할과 아직 선택인 위상을 문장 구조로 분리.
- 실패 뒤 당일 panel 잠김.
- 다음 loop에서 역할은 접고 위상만 다시 시험한다는 숏컷 안내.
- 성공 뒤 열세 번째 종과 S2 preview.

실행 확인문은 겁을 주는 “정말로?”보다 결과 범위를 정확히 말한다. 예: 역할과 위상을 실제 시계망에 적용하며, 작동 뒤에는 당일 배치를 되돌릴 수 없다는 정보가 필요하다.

### 8.6 BF 실패 기록

수첩은 다음 세 칸으로 작성한다.

| 칸 | 내용 |
| --- | --- |
| 관찰 사실 | 어느 relay가 열두 번째 종에서 작동했고 봉인핀이 파손됐는지 |
| 아직 모르는 것 | 역할 배치 전체가 틀렸는지, 위상만 틀렸는지 즉시 단정하지 않음 |
| 다음 loop에 바꿀 수 있는 것 | B3-A 검증 결과를 유지하고 B3-B 위상 입력을 달리할 수 있음 |

“실패했다”만 반복하지 않고 금속이 식지 않는 감각, 손끝에 남은 진동과 잠긴 panel의 물리 상태를 짧게 쓴다.

### 8.7 에드가 기억 반응

#### 조건

```yaml
source_memory: MEM_EDGAR_B3_FAILURE_01
state_reads:
  - residual_memory.EDGAR.B3_FAILURE
  - servants.EDGAR.alert
  - short_events_seen.VS01_EDGAR_MEMORY_REACTION
state_writes:
  - short_events_seen.VS01_EDGAR_MEMORY_REACTION
forbidden_writes:
  - puzzle solution
  - B3 completion
  - route lock
repeat_policy: once_per_slice_profile
```

#### 공통 핵심

- 에드가는 파손음, 열두 번째 종 직후 주인공이 멈춘 위치, 봉인핀이 휘었다는 사실을 기억한다.
- 전날을 직접 고백하지 않고 “또”, “이번에는” 같은 한 단어가 먼저 새어 나온 뒤 정정할 수 있다.
- 아가씨의 과업을 대신할 수 없다는 표층 역할과 개입 예산 때문에 장치를 압수하지 않는다.
- 실제 감정은 같은 실패를 다시 볼 두려움과 통제 욕구다.
- 마지막에는 답을 말하지 않고 “손잡이보다 눈금을 먼저 확인하십시오” 정도의 관찰 방향만 남길 수 있다.

#### 관계·경계 variant

| 조건 | 표층 태도 | 정보량 | 종료 |
| --- | --- | --- | --- |
| alert low | 실수처럼 기억이 샘, 곧 보고체로 정리 | 공통 핵심 100% | 옆으로 비켜 길을 남김 |
| alert high | 규칙 위반을 돌려 경고, 질문을 되묻음 | 공통 핵심 100% | 재발 시 보고하라고 하나 장치는 열어 둠 |

두 variant의 퍼즐 정보량은 같아야 한다. high가 더 적은 정보를 주거나 진행을 막아 관계 수치가 난이도가 되지 않게 한다. 에드가는 예외 없이 다나까체를 사용한다.

### 8.8 BSHORT

- “해결한 단계 건너뛰기”와 “전체 자동 해결”을 구분한다.
- 수락하면 이동·탁본 준비·검증된 역할만 짧은 montage 문구로 접는다.
- 거절하면 직접 이동할 수 있고 불이익이 없다.
- B3-B 위상 선택 직전 플레이어에게 조작을 반환한다.
- 반복 시에는 설명을 축약하되 숏컷이 소비되거나 사라졌다고 표현하지 않는다.

### 8.9 성공·S2 preview

- 성공 문구는 `정답입니다`보다 실제 결과를 묘사한다.
- 열세 번째 종은 열두 번째와 다른 간격·무게로 느껴져야 한다.
- 주인공은 안도보다 고딕 홈 아래 차가운 이음새, 팬 진동, 남색 수직선이 원래부터 있었다는 감각에 반응한다.
- `simulation`, `diagnostic`, `android`, `researcher`를 사용자 노출 원문에 사용하지 않는다.
- 종료 시스템 문구는 “버티컬 슬라이스 종료”로 별도 표시하고 대화 기록에 남기지 않는다.

## 11. 선택지·문체 규칙

### 11.1 주인공

- 이름과 정확한 나이를 쓰지 않는다.
- 감각→신체 반응→짧은 판단 순으로 쓴다.
- 공포를 매번 “무섭다”로 명명하지 않는다.
- 선택지는 질문·회피·관찰처럼 행동 방향을 보여 주고 성격을 선악으로 고정하지 않는다.

### 11.2 에드가

- 예외 없이 `~입니다`, `~입니까`, `~하십시오` 다나까체.
- 무뚝뚝하고 간결하며 호칭은 상황에 맞게 `아가씨`를 사용한다.
- 통제 욕구는 장황한 협박보다 위치·시간·순서를 정확히 말하는 방식으로 드러낸다.
- 기억이 새어도 갑작스러운 반말·축약·친근체를 사용하지 않는다.

### 11.3 시스템·UI

- 조작 결과와 범위를 먼저 쓴다.
- `오류`, `실패`만 표시하지 않고 무엇이 유지되고 무엇이 잠겼는지 말한다.
- 취소·뒤로·직접 진행은 불이익이 없는 선택으로 표현한다.
- NORMAL_RESET, 로컬 재시도, 디스크 저장, 강제 종료 복구를 서로 다른 용어로 유지한다.
