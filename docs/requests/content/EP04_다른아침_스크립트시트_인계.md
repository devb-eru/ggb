## 3. 핵심 계약

### 3.1 파열 수면과 단발 리셋

- D6의 침실과 비상 캡슐은 감정 해석만 다르고 모두 `FRACTURE_SLEEP`로 합류한다.
- `FRACTURE_SLEEP`는 `NORMAL_RESET`, 정상 `loop_index` 증가와 `SYS_MEMORY` 재실행을 금지한다.
- `BROKEN_RESET_ONCE`는 S3 생성, 필터 `BROKEN`, 완료 플래그, `SYS_SYNC`와 전환 횟수 1을 같은 트랜잭션으로 확정한다.
- 중단 재개는 같은 transaction ID로 처리하며 이미 확정한 S3 생성은 no-op이다.
- 수첩, 연구원 기록, 사용인 bond·alert·잔류 기억과 짧은 반응 이력은 보존한다.

### 3.2 E1 3-of-4

- 침대, 창문, 거울, 호출끈은 각각 최초·반복·E2 이후 반응을 가진다.
- 선택지는 별칭 문자열이 아니라 실제 Runtime 선택 노드 ID로 판정한다.
- 반복 클릭은 `mandatory_e1_observations`에 중복 추가하지 않는다.
- 서로 다른 3종에서 `E1:complete`와 `KN_E1_RESET_DID_NOT_RESTORE`를 확정한다.
- 네 번째 조사는 `e1_all_objects_seen` 감상 플래그만 쓰며 관계·결산·메인 가드에 관여하지 않는다.

### 3.3 E2 관계 허브 인계

- 다섯 사용인은 관계 상태와 무관하게 모두 등장한다.
- 세 질문은 순서 독립이며 생략 시 종료 분기에서 필수 사실을 한 번씩 요약한다.
- 관계 씨앗은 결정적 우선순위로 최대 하나만 짧게 회수하고 새 관계값을 쓰지 않는다.
- E2 완료는 `E2_INTRO:complete`, `relationship_hub_open`, 다섯 목적지 핀만 기록한다.
- 관계 사건 0명 상태에서도 `CNT-EP05:E_HUB`, J4와 두 엔딩으로 가는 메인 경로를 차단하지 않는다.

### 3.4 파열 이후 휴식

- `POST_BROKEN_REST`는 시간 구간과 피로만 갱신한다.
- 세계 상태, 오브젝트, E3 수리 결과, 사용인 위치와 관계 상태를 초기화하지 않는다.
- 이후 휴식에서 `NORMAL_RESET`과 S3 재생성을 호출하지 않는다.

1. 콘텐츠 팀은 `08_Content_QA`의 30항목을 실제 플레이 흐름으로 검수하고 담당자와 날짜를 기록한다.
