## 4. EP03 전용 보완

### 4.1 D1 HARD FAILURE

- D1의 비가역 입력 실패는 `meta_progress.failure_knowledge += D1:active`를 `failure_commit`으로 기록한다.
- 장치는 당일 재실행할 수 없으며 `SYS_NORMAL_RESET`을 거친다.
- 다음 진입에서 `EP03_ROUTE_ENTRY`가 D1 active failure를 읽고 `DSHORT`로 보낸다.
- `DSHORT`는 서재 중첩과 이동만 줄인다. 새 D1 입력은 플레이어가 직접 선택한다.

### 4.2 D4 성공과 D5 전환

- D4는 `A1·B1·C2`, `XII+1`을 만족한 플레이어 성공이다.
- `SAVE_D4_COMPLETE`는 D4 완료 뒤, D5 시작 전에 별도 경계로 둔다.
- D5는 실패·죽음·게임 오버가 아니라 위장 필터 표현층을 제거하는 일방향 전환이다.
- D5 완료는 `D5_complete`, `camouflage_filter_state=DISABLED`, `world_phase=FILTER_EXPOSED`를 같은 event commit으로 기록한다.
- D5에서는 `BROKEN`과 `broken_reset_triggered`를 쓰지 않는다.

### 4.3 데모·본편 인계

- demo와 full은 같은 `D5_COMPLETION`과 `SAVE_D5_COMPLETE`를 공유한다.
- demo는 `DEMO_END_SCREEN`으로 재개하고 D6 Resource를 실행하지 않는다.
- full은 `D6_FREE_INSPECTION`으로 재개한다.
- `build_flavor`가 없거나 잘못되면 D5 완료 상태를 보존한 채 안전 중단한다.
- 이 경계는 `14_Transition_Contract`에서 아홉 행으로 따로 관리한다.

4. Godot import 단계에서 `14_Transition_Contract`의 원자성, rollback, build registry 허용 범위를 다시 검증한다.
5. D5 이후 `BROKEN_RESET_ONCE`는 EP04 책임이며 EP03 State Effect에 추가하지 않는다.
