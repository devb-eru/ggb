# GGB 콘텐츠 원문 공통 계약

## 1. 레코드 schema

승인 전에는 `content_item_id`와 `draft_id`, 승인 뒤에는 별도 `line_id`를 사용한다. 에피소드 문서의 `CNT_EP*_*`는 제작 묶음 ID이며 runtime ID가 아니다.

```text
draft_id,request_id,package_id,content_item_id,content_type,
document_id,interaction_id,subnode_id,reaction_id,caption_id,audio_asset_id,
ko_KR,speaker_id,source_event_id,location_id,object_id,trigger,condition,
emotion,hidden_intent,register,variables,max_lines,max_width_class,
spoiler_tier,advisory_tag,build_flavor,knowledge_id,owner_id,outcome_id,
state_reads,state_writes,repeat_policy,notes
```

| 필드 | 규칙 |
| --- | --- |
| `source_event_id` | v0.4 정본 사건. 문서 표기 `B3-A`는 데이터에서 `B3_A`로 정규화 |
| `speaker_id` | `SUBJECT`, `SERVANT_EDGAR`, `SERVANT_MARA1`, `SERVANT_LUCA`, `SERVANT_IRIS`, `SERVANT_MARA2`, `SYSTEM`, `DOCUMENT` |
| `trigger` | `enter`, `click`, `acquire`, `use`, `deny`, `state_change`, `timer`, `dialogue_choice`, `puzzle_feedback`, `caption` 등 |
| `state_reads` | 문구 선택에 필요한 정본 상태만. 추측 값·미래 상태 읽기 금지 |
| `state_writes` | 사건이 허용한 writer 범위만. 순수 반응은 `none` |
| `repeat_policy` | `once`, `first_repeat`, `per_loop`, `state_variant`, `always`, `protected` |
| `document_id` | 정식 ID 미발급 문서는 `DRAFTDOC_EP##_...`로 쓰고 승인 시 registry 발급 |
| `interaction_id` | 세부 클릭은 `DRAFTINT_EP##_...`; 정식 사건·오브젝트 ID를 대체하지 않음 |
| `caption_id` | `CAP_*` 오디오 의미 단위와 일대일. loop 자체가 아니라 상태 변화에 연결 |

## 2. 문체 기준

### 주인공

- 이름과 정확한 나이를 쓰지 않는다.
- 감각→신체 반응→짧은 판단 순서를 기본으로 한다.
- 공포를 매번 “무섭다”라고 명명하지 않고 압력·온도·소리의 거리·호흡·피부 감각을 사용한다.
- 선택지는 행동 방향을 말하며 선악·용기/비겁으로 평가하지 않는다.

### 에드가

- 항상 `~입니다`, `~입니까`, `~하십시오` 다나까체.
- 정갈하고 무뚝뚝한 최고령 책임자·비서 인상. 통제는 시간·순서·위치를 정확히 지정하는 방식으로 드러낸다.
- 관계가 높아져도 반말로 바뀌지 않는다.

### 마라 1

- 유연한 말투와 `~슴다`를 사용하고 표정·감정 변화가 크다.
- 호쾌하고 엉뚱한 실수는 가능하지만 비하어·무능력 조롱으로 쓰지 않는다.
- 심각한 수리·배신 장면에서는 예능 반응이 사실 전달을 덮지 않는다.

### 루카

- 말줄임표가 많고 머뭇거리지만, 필요한 순간에는 끝까지 말하고 행동한다.
- 소심함을 유아화·무능력으로 쓰지 않는다. 쥐 귀·땀은 긴장 표현이지 개그 벌칙이 아니다.

### 이리스

- `우후후`와 보호자다운 부드러운 말투. 사고방식에는 그 시절을 놓지 못한 어린 고집이 있다.
- 주인공을 죽이고 싶었던 감정은 아버지에게서 받은 구조적 억울함과 보호 기억의 왜곡에서 나온다. 질투·로맨스·단순 악의로 쓰지 않는다.
- D5 이후 고백은 관계에 따라 `추론만 가능/부정/유보/간접/비공개 직접/공개 직접`으로 달라진다.

### 마라 2

- 느낌표와 말꼬리 잡기, 과장된 자신감이 많고 매우 영리하다.
- 자기 이름과 기억 소실 공포를 직접 도움 요청 대신 허세·반복 확인으로 드러낸다.
- 성적·유혹적 뉘앙스를 사용하지 않는다.

## 3. 공통 variant

| 축 | 값 | 적용 |
| --- | --- | --- |
| 첫/반복 | first, repeat, exhausted | 모든 조사·문서·오브젝트 |
| 루프 실패 | first_fail, fail_2, fail_3, fail_4_plus | B3-B·C4·D1, 필요 시 힌트 강도만 변화 |
| bond | 0~1, 2~3, 4~5 | 사용인 개인 표현; 필수 사실 동일 |
| alert | 0~1, 2~3, 4~5 | 경계·완곡함·거리; 진행 차단 금지 |
| 관계 완료 | incomplete, complete, outcome_a, outcome_b | E3·F2·엔딩 후속 |
| 결산 | LOW, MID, HIGH, ALL | J4·E5·F2; 선택지 잠금 금지 |
| F0 의향 | reality, stay, undecided | F0-E의 현재 문장; F1로 동일 합류 |
| 최종 선택 관계 | reaffirmed, revised, formed | F0 의향과 EDC 조합 6경로 |
| 빌드 | demo_stinger, full_transition | D5 이후 표시만 분리 |

## 4. 상호작용 문구 최소 세트

상호작용 가능한 대상은 적용 가능한 상태를 빠짐없이 작성한다.

| 상태 | 필수 문구 |
| --- | --- |
| 첫 조사 | 감각·기능·현재 가능 행동 |
| 반복 조사 | 새 정보 없음 또는 상태 변화 요약 1문장 |
| 획득 | 무엇을 얻었고 당일/영구 중 어디에 보관되는지 |
| 사용 가능 | 대상과 예상 결과, 비가역이면 확인 문구 |
| 사용 불가 | 이유와 필요한 정보/도구; 가짜 퍼즐 암시 금지 |
| 입력 무효 | 무엇이 맞지 않는지, 상태 손실 여부 |
| 상태 변화 | 실패·복원·수리·관계 outcome 뒤 달라진 점 |
| 리셋 전후 | 사라진 물리 흔적과 남은 영구 정보 구분 |
| 접근성 | 색·소리·방향을 문양·명칭·상태 문구로 대체 |

## 5. 문서·수첩 기준

- 필수 문서는 퍼즐 정답 전체를 한 번에 말하지 않고 관찰 가능한 사실과 인간적 일화를 함께 둔다.
- 진행 무관 일화도 허용하며 UI가 “쓸모없음”으로 평가하지 않는다.
- 일지 J1~J5는 아버지의 설명이 곧 진실이라는 식으로 쓰지 않고, 연구원 기록·기계 로그·주인공 낙서와 대조할 여지를 둔다.
- 현실 수첩은 아버지 개인 일기가 아니라 아버지와 연구원들이 남긴 공동 인계 문서다. 생존 지침, 시설 상태, 각자의 손글씨와 책임의 불일치가 함께 남는다.
- 잔류 헌장은 기억·외형 표시·자율성을 각각 별도 동의 항목으로 쓴다.

## 6. 접근성·감각 자막

- 자막은 `[쿵]`만 쓰지 않고 대상·거리·변화를 적는다.
- 방향성 cue는 `왼쪽/오른쪽`만으로 끝내지 않고 공간명·발생 대상을 함께 표시한다.
- 음악 loop와 반복 앰비언스는 시작·상태 변화 때만 표시한다.
- 호흡·심박·저주파 감소에서도 첫 호흡과 퍼즐 진행은 자동 성공 또는 시각 정보로 보장한다.
- 200% UI에서 대사 기본 3줄, 문서 페이지는 짧은 단락과 명시적 다음 페이지를 사용한다.

## 7. 원문 검수

1. 사실·감정·숨길 정보·스포일러 단계 검토.
2. skeleton CSV의 trigger·condition·state 읽기/쓰기·repeat 검토.
3. 기능 문구와 퍼즐 피드백 작성.
4. 대사·관계 overlay 작성.
5. 문서·수첩·일화 작성.
6. 감각 자막·UI 문구 연결.
7. 말투·정보량·선택 편향·접근성·200% UI 검수.
8. 승인 후보에 `line_id` 발급 준비와 유형·화자·사건별 집계.
