# 대화 기록 연결 현황

검토 기준: `47e6557`의 공통 기록 구현과 후속 엔딩 읽기 패널 연결. 전편 완료 판정이 아니라 제품 기준 중 대화 기록의 적용 범위와 남은 작업을 정리한다.

후속 통합 수첩 작업은 [단계별 구현 현황](../ideas/md/v04/issues/validation/notebook_history_implementation_status.md)에서 추적한다. 기존 조회 복구와 장 문맥 캡처를 추가했으며, 아래 transcript 저장·재번역·커서 재개 한계는 새 저장 계층 연결 전까지 유지된다.

실제 저장 이관과 책갈피/비교 메타데이터 명령은 개발 검증 옵션에서 연결했다. 일반 실행은 기존 형식이며, 미연결 콘텐츠를 신형 authored 기록으로 가장하지 않는다. 원문 ID 매핑·새 수첩 UI·앱 재시작 커서는 여전히 미완료다. `--notebook-migration-smoke`는 원본 보존·실패 복구를 검사하며, 실제 마우스/키보드 인수를 대체하지 않는다.

후속 NP20 연결로 개발 옵션에서는 단계 힌트 60종을 실제 콘텐츠 ID/의미 버전으로 저장하고 현재 언어로 재열람한다. 요청하지 않은 단계는 기록하지 않으며, legacy 원문은 그대로 보존한다. [생산자 연결 현황](../ideas/md/v04/issues/validation/notebook_content_mapping_status.md)의 나머지 경로를 포함한 전체 매핑은 미완료다. 아래 기존 transcript 제한은 일반 실행과 미연결 경로에 해당한다.

### 엔딩 읽기 패널

- 물리 수첩의 요약만 열면 펼친 본문을 선행 기록하지 않는다. 다음 색인의 이름은 화면에 보이는 탐색 버튼이므로 남지만 해당 페이지의 본문은 열기 전까지 남지 않는다.
- 요약/펼침 전환과 다음 색인 클릭은 실제 누른 탐색 문구로 남는다. 이는 관계·엔딩 선택이나 해당 페이지 읽기 완료의 증거가 아니다.
- `읽기 확인 후 닫기`는 본문 기록 저장에 성공한 뒤 기존 `field_read` 트랜잭션을 실행한다. 페이지를 연 사실과 진행상 읽기 확인은 별도이며, 기존 필수·선택 페이지 조건은 유지한다.
- 저장 실패 시 페이지와 진행 상태를 유지하고 같은 버튼으로 재시도한다. 교체되거나 닫힌 페이지의 오래된 버튼 콜백은 진행을 바꾸지 않는다.
- 두 절차의 요약창은 두 설명을 함께 기록하며 현실·잔류 의향, 확정, 관계 값을 바꾸지 않는다. 복귀 버튼은 선택 답변으로 남기지 않는다.
- 감상 기록 갤러리의 페이지는 이 기록 함수로 바꾸지 않는다. 엔딩 완료 후 열람은 계속 읽기 전용이다.

## 저장과 표시

- 프롤로그와 `ChapterOneController` 계열의 표시 함수에서 표시 직후 기록한다. 미표시 문장은 기록하지 않고 동일 대화 실행에서 같은 문장을 다시 그릴 때 중복 추가하지 않는다.
- 공통 `dialogue_history_writer.gd`는 `meta_progress.dialogue_history`의 `next_sequence`로 순번을 할당하고 `StateWriter`·`SaveManager`로 저장한다. 프롤로그는 기존 슬롯의 저장 지점을 유지하며 새 슬롯만 `SAVE_NEW_GAME`을 사용한다. 챕터 세션은 `_save_point(state)`를 사용하며 퍼즐·아이템을 수정하는 커밋 훅을 재실행하지 않는다.
- 실패하면 상태를 롤백하고 현재 문장 또는 선택창을 유지한다. 진행·선택 버튼으로 재시도하며 기록 저장 성공 후에만 해당 동작을 실행한다.
- 표시된 질문·선택지 목록과 클릭한 문구는 별도 항목이다. 프롤로그에서 숨겨진 선택지는 제외한다. 관계 선택창의 명시적 보류는 취소 문구로 남기며 신형 기록에서는 `choice_cancelled`로 구분한다. 단순 UI 복귀·신호 재생은 선택 답변으로 남기지 않는다. 첫 버튼의 위치로 취소 여부를 추정하지 않으며 닫힌 선택창의 이전 버튼 콜백은 실행하지 않는다.
- 확정 클릭 기록은 사용자가 누른 문구의 기록이며, 그 뒤 실행되는 게임 상태 저장의 성공을 뜻하지 않는다. 실제 관계·엔딩 확정 여부는 해당 상태와 트랜잭션 결과가 기준이다.
- 열람은 상태 설치·저장을 호출하지 않는다. 엔딩 완료 후 열람은 저장 파일 바이트 불변까지 검사했다.
- 공용 형식은 `CH1_HISTORY_TRANSCRIPT`와 문자열 변수 `speaker`, `text`다. 이 ID는 원래 대사의 콘텐츠 ID가 아니다.
- 기록은 읽었던 언어의 화자·본문을 보존한다. UI 언어를 바꿔도 과거 본문은 재번역하지 않는다. 원문 ID·문장 구간·변수 기반 재번역은 후속 작업이다.
- 대화 커서 재개는 미구현이다. 마지막 피드백을 재표시하면서 재열람 기록이 추가될 수 있다. 다른 상호작용으로 같은 대사를 다시 보는 것도 새 열람이다.

### 현실 몸 재관찰 증거

- 현실 `EDR_BODY_CHECK`에서 이미 확인한 손/호흡 표시기/고정 벨트를 다시 조사해 재관찰 대사가 실제 표시되면 `meta_progress.knowledge_entries.dialogue_observed_facts`에 오브젝트별 `BODY_REPEAT:OBJ_REALITY_* = true`를 남긴다.
- 대사와 동일한 기록 transaction에서 저장한다. 실패 시 대사와 증거가 함께 롤백되고 다음 진행을 막는다. 다른 오브젝트의 최초 조사나 임의 UI 재열람으로 증거를 만들 수 없다.
- 갤러리는 증거가 있으면 보관 대사 문자열 없이 재관찰 내용을 보존할 수 있다. 다만 해당 오브젝트의 기존 게임상 조사 확인 조건도 계속 필요하다. 증거는 조사 완료를 대신하지 않는다.
- 구형 저장에 증거가 없다면 기존의 한국어/영어 transcript 원문 확인을 유지한다. 이 호환 경로는 일반 기록 정리 활성화 전에 저장 이관에서 별도로 처리해야 한다. 조회 시 원본을 변경하지 않는다.

## NP18 현실 엔딩 연결 (개발 옵션)

## 후속 작업

### 공통 읽기 계층 추가 (2026-10-03)

`notebook_query.gd`와 `notebook_panel.gd`에 네 분류, 공개 segment 검색, 장/책갈피/이전 revision 필터, 50개 페이지, 상세/출처 왕복, 다중 묶음의 A/B 두 자료 비교를 추가했다. 이 초기 단계는 실제 발언 조회였으며, 이후 인물별 묶음은 아래 공개 탐색 절에서 확장했다. 목록의 원문 미리보기도 최대 50개만 렌더링한다.

프로필/슬롯/분기/로드 세대와 조회 키, 구형 원문·부분 표시 오류, 숨은 문서 부분 제외, 실제 확인한 사용인만 표시, 작은 화면의 목록/상세 및 A/B 전환을 자동 검사한다. 1차 패널 단계에서는 본편 메뉴/N키에 연결하지 않았으며, 이후 연결 상태는 아래 호스트 절을 따른다.

### 본편 연결과 자료 고정

`notebook_host.gd`를 통해 개발 옵션을 켠 v2 실제 플레이의 수첩 버튼/N키와 대화 기록 메뉴를 공통 패널에 연결한다. 진행 중 문장, 질문, typed 확인창을 재생성하지 않고 원래 컨트롤러를 숨김/중단한다. 닫으면 같은 포커스와 입력으로 돌아간다. B2 대기와 J4 확인 지연은 남은 시간을 유지하며, 앱 포커스/개발자 메뉴의 중단 사유와 구분한다.

책갈피 추가·해제와 비교 묶음 편집을 실제 `notebook_commands` 원자 저장에 연결했다. 실패 원상복구·동일 UID 재시도·응답 유실 확인·외부 revision 충돌을 구분한다. 해제는 정리 가능성을 설명하고 확인을 받는다. 여러 자료를 담되 A/B 두 자료만 비교하며, 읽기/교체 자체로 퍼즐을 판정하지 않는다. 개인 자유 메모는 구현 범위에 넣지 않는다.

기존 장별 힌트 요청과 C3 수량 계산, 구형 수첩 전체 원문 도구는 호환 진입으로 유지한다. 현실 수첩 N키는 실제 게임 수첩이고, 대화 기록 메뉴는 이미 관찰한 자료를 재열람한다. 기존 문자열 수첩의 통합 조회와 읽음·열람 위치는 아래 후속 절을 따른다. 자동 검사와 잔여 항목은 [구현 현황](../ideas/md/v04/issues/validation/notebook_history_implementation_status.md)에 기록한다. 갤러리와 앱 재시작 후 게임 대화/선택 커서·실제 Windows 입력·성능 인수도 남았다.

### 기존 문자열 수첩 원문 통합

기존 프롤로그 배열과 장별 사전의 마지막 문자열을 단서 탭에서 검색·조회하고 책갈피/비교에 담을 수 있다. 본편 호스트가 동결한 정본을 전달하며 단순 열람은 저장을 쓰지 않는다. 작성 언어·획득/갱신 시점을 추정하지 않고 원문 그대로 표시한다. 내부 키나 다른 knowledge 상태를 공개하지 않는다.

명시적으로 담을 때만 해당 원문과 보호 참조를 같은 트랜잭션으로 저장한다. 저장 실패·응답 유실·한도·낡은 scope/revision을 검사하고, 나중에 마지막 값이 바뀌어도 보존 원문은 유지한다. 현재 원문과 저장 스냅샷이 같으면 목록을 중복 생성하지 않는다. 고정 스냅샷은 일반 대화 2,000개 quota와 분리하며 엔딩 갤러리의 몸 재관찰 증거로 쓰지 않는다.

정확한 형식과 보존 계약은 [데이터 계약 9.2절](data_contract.md#92-기존-문자열-수첩의-조회와-원문-고정)을 따른다. 이 단계는 구형 마지막 값의 접근 복구이며 사라진 과거 원고의 복원이나 전 생산자 매핑 인수 완료가 아니다.

### 읽음 표시와 마지막 열람 위치

개발 옵션의 실제 수첩에 신규/미열람/갱신 배지와 별도 UI 저장을 연결했다. 직접 연 자료나 비교에서 실제 보이는 자료만 읽음으로 표시하며, 목록 미리보기와 자동 복원은 읽음이나 게임상 최초 공개를 만들지 않는다. 배지 변경 때문에 목록을 다시 정렬하지 않는다.

일반 N/버튼 진입과 메뉴 대화 기록의 마지막 위치는 독립적이다. 최초 대화 기록은 최신 세션의 마지막 발화, 이후에는 직접 보던 문장으로 돌아간다. 필터·페이지·자료/segment UID·문단 상대 위치·출처 복귀·A/B 선택·포커스를 보존하고, 없는 자료는 실제 공개 이웃 또는 빈 상태로 복귀한다. 검색 복원은 색인 완료를 기다린다.

별도 `user://profile/notebook_views/` 파일은 프로필/빌드/슬롯/실행/계통/분기를 구분한다. 현재 로컬 프로필은 하나이며 다중 프로필 UI를 추가한 것은 아니다. 과거 snapshot에는 미래 UI 상태를 들여오지 않는다. 손상은 백업 또는 빈 편의 상태로 복구하고, 알 수 없는 새 형식은 덮어쓰지 않는다. 저장 실패가 게임 본문·고정 자료·진행 복귀를 막지 않는다.

형식과 경계는 [데이터 계약 9.3절](data_contract.md#93-읽음-표시와-열람-위치-sidecar)을 따른다. 파일 재읽기와 같은 슬롯의 컨트롤러 재생성으로 UI 복원을 검사했다. 이는 진행 중 게임 문장/선택 토큰의 앱 재시작 복원, 읽기 전용 갤러리 호스트, 시각 자료 확대/이동 완료를 뜻하지 않는다. 기본 개발 옵션 비활성과 자유 메모 후속 분리는 유지한다.

### 공개 인물·대화 묶음과 필터 탐색

실제로 발언한 사용인과 획득한 연구원 기록을 인물별로 모아 보관 부분 수·공개 장소·최신 원문을 표시한다. 익명 보라색 인덱스는 신원 미확인 자료로 남기며 마라 2의 기록을 나중에 얻었다는 이유만으로 합치지 않는다. 미공개 관계·프로필·고백을 추정하지 않는다.

대화 묶음은 출처 계통·실제 사건 발생·세션을 함께 식별한다. 반복 청취와 다른 발생을 임의 병합하지 않고, 내부 발언은 시간순으로 이전/다음/마지막 이동을 제공한다. 표시 수량은 정리 후 남아 있는 부분 수다. 질문·확정 선택·취소 구분은 기존 종류 라벨을 유지한다.

공개 장소·화자·인물·출처 유형·내용/출처 상태 등의 필터를 한국어/영어 표시명으로 제공한다. 미적용 초안은 취소 가능하고, 빈 검색에서는 명시적으로 획득한 전체 자료로 범위를 넓힐 수 있다. 실제 지식 출처에서 원문으로 가는 링크와 반대 방향 관련 기록 링크도 연결했다. 조회만으로 새 관찰이나 일지 완료를 쓰지 않는다.

UI 편의 파일은 필터 확장 당시 버전 2, 시각 자료 위치 도입 당시 버전 3을 사용했으며 현재 버전은 관련 자료 복귀 모드를 더한 4다. 게임 저장 스키마·동결 원고·기본 개발 옵션 비활성은 유지한다. 정확한 계약은 [데이터 계약 9.4절](data_contract.md#94-공개-인물대화-묶음과-필터-탐색), 실행 근거는 아래 구현 현황을 따른다.

### 기록한 시각 자료 재열람

B4 파형·C5 회로·D4 포트 잔상을 각 획득 기록에서 열고, 비교 묶음에 세 자료를 모두 담아 두 개씩 교체할 수 있다. 실제로 봤던 거울 확대창과 코어의 자료층도 해당 버전·segment·당시 변수만 사용해 재현한다. 현재 퍼즐의 정답 배치나 다른 자료층을 끌어오지 않는다. 알 수 없는 과거 버전이나 문자열만 있는 legacy에는 새 그림을 소급 붙이지 않는다.

단독 확대에서 버튼으로 확대/축소·네 방향 이동·기본 위치를 제공하고, 자료 영역의 방향키·휠·드래그를 보조한다. 점선·실선·선 굵기·원·사각과 한영 설명을 사용하므로 색 없이도 읽을 수 있다. 돌아가기는 같은 상세/비교와 A/B 선택·포커스를 보존한다. 배율과 위치는 버전 3에서 도입한 편의 필드에 보관하며 현재 쓰기 버전과 이전 호환은 [데이터 계약 9.3절](data_contract.md#93-읽음-표시와-열람-위치-sidecar)을 따른다.

정확한 공개/저장 경계는 [데이터 계약 9.5절](data_contract.md#95-시각-자료-재열람과-확대)이다. 실제 F0-C 화면의 미확정 회전·반전·기준점 입력을 둔 채 열람·확대·복귀하는 호스트 검사도 추가했다. 자동 검사는 실제 Windows 입력이나 최종 이미지 외형 검수가 아니다.

### 검색 일치 위치 탐색

공개 본문·제목·요약·화자·장소·자료 유형별 검색 범위를 맞추고, 실제 원문 내 일치 위치로 이동하는 이전/다음 버튼을 연결했다. 본문이 길게 줄바꿈되어도 글자 위치를 기준으로 이동하며 문서 끝에서는 가능한 마지막 스크롤 범위 안에서 해당 줄을 보여 준다. 다른 필드를 이어 붙인 가짜 일치는 제외하고, 내부 ID와 숨은 segment는 일치 목록에도 넣지 않는다.

원문은 BBCode로 해석하지 않고 문자 그대로 렌더링한다. 밑줄·현재 일치의 명도 대비·순번/대상 안내를 함께 제공한다. 복원/출처 왕복은 이전 문단 위치를 우선하며 자동으로 첫 일치에 뛰거나 새 지식을 만들지 않는다. 검색/탭/조회가 바뀌면 늦은 이동을 폐기한다. 인물 목록은 전체 보관 자료상 첫 확인 순서로 정렬하고 최근 기록이나 필터로 재정렬하지 않는다. 최초 근거의 이후 정리 방지는 아래 보존 절을 따르며 이미 소실된 과거를 복원하지 않는다.

계약은 [데이터 계약 9.6절](data_contract.md#96-검색-일치-위치와-원문-표시), 검증은 `notebook_search_smoke.gd`와 기존 조회·본문 앵커·본편 호스트 검사를 사용한다. 엔진 레이아웃과 버튼 신호 테스트를 실제 Windows 입력 검수로 부르지 않는다.

### 현재 조사 관련 자료

실제 컨트롤러의 현재 조사 바로가기를 연결했다. 대사·질문은 당시 고정된 사건을 사용하고 그 밖에는 현재 화면의 stage를 사용한다. 저장상 다음 단계가 열렸다는 이유로 아직 말하는 중인 사건의 관련 목록을 다음 단계로 바꾸지 않는다.

별도 목록은 이미 공개된 사건 자료와 직접 출처만 한 페이지 50개로 제공한다. 원래 탭·검색·필터는 그대로 두며, 미획득 자료의 제목/자리/개수나 미요청 힌트는 만들지 않는다. 이전/반박된 내용도 라벨을 붙여 남기고 정답 후보만 골라 주지 않는다. legacy 원문에 사건을 추측해서 부여하지 않는다.

관련 자료를 읽고 돌아오면 원래 목록·상세 또는 같은 A/B의 비교 화면을 복원한다. 미선택 목록으로의 복귀도 편의 파일에 보관한다. 쓰기 버전은 4, 읽기 호환은 1·2·3이다. 작은 화면에서 긴 안내가 목록 높이를 없애지 않도록 안내를 스크롤 안에 배치하고 돌아가기/페이지 조작은 밖에 둔다.

정확한 계약은 [데이터 계약 9.7절](data_contract.md#97-현재-조사-관련-자료)이다. 현실 N키와 필수 읽기, 퍼즐 미확정 입력/판정은 변경하지 않는다. 엔진 내부 버튼·레이아웃 검사는 실제 Windows 조작이나 전체 생산자 분기 인수가 아니다.

### 최초 인물 근거 보존과 기록 유지 안내

정상 저장 후보는 일반 대사 정리 전에 다섯 사용인의 가장 이른 공개 발언을 기존 `person_source`로 보호한다. 첫 발언을 최신 발언으로 바꾸거나 반복마다 인물 링크를 추가하지 않는다. 보관 근거가 있는 새 게임에서는 이후 prune으로 인물 순서가 바뀌지 않으며, 링크 없는 기존 저장은 남아 있는 근거부터 보호한다. 이미 삭제된 발언과 legacy의 이름 문자열은 최초 만남 증거로 재구성하지 않는다. 읽기 전용 수첩 진입은 저장을 실행하지 않는다.

지식 상세·비교에서는 실제 획득한 A2 근거 뒤에만 기록 유지와 현장 상태를 구별한다. D5나 기상 예상만으로 복구 실패를 선공개하지 않고, E1의 다른 아침을 확인한 뒤에 안내를 바꾼다. 이전 가설의 상태를 인증으로 승격하지 않으며 현장 상태의 현재값을 추정하지 않는다. 공개된 안내만 검색할 수 있고 이전 snapshot을 열면 미래의 안내는 사라진다.

A/B 검증에서 발견한 JSON 정수형 참조 차이도 보완했다. 유효한 콘텐츠 버전 `1`과 `1.0`은 같은 조회 키를 사용하고, 책갈피/비교 표시와 참조 버튼의 선택 상태도 일치한다. 문자열이나 소수 버전은 잘못된 참조를 정상 자료로 연결하지 않도록 그대로 구분한다.

계약은 [데이터 계약 9.8절](data_contract.md#98-최초-인물-근거와-정보-유지-범위)이다. 원문·게임 저장 schema·일반 대사 2,000개와 보호/legacy 별도 보존·기본 비활성 정책은 유지한다.

### 자기 표식의 시각 원문

새 A1 작성은 문장·집 도형·모서리 잉크의 고정 도식과 감각 설명을 콘텐츠 버전 2로 보존한다. 세 유형 모두 읽기 전용 상세/확대/두 칸 비교를 사용하며 수면이나 A2 뒤에도 처음 작성한 원문·그림을 유지한다. 문장 그림은 작성 당시 언어를 보존하고 현재 UI 언어의 내용은 본문에서 읽는다. 글자 윤곽을 실측한 필체로 오인하지 않도록 구분한다.

기존 버전 1과 legacy는 근거 없는 필압·번짐을 소급 생성하지 않고 원문만 제공한다. 원래 `self_authored_mark`와 F0-E 정답은 변경하지 않으며, 단순 열람으로 A2나 자기 인증이 실행되지 않는다. 저장 실패와 응답 소실은 기존 원자 트랜잭션을 따른다. 계약은 [데이터 계약 9.9절](data_contract.md#99-자기-표식의-버전-고정-시각-자료)이다.

### 엔딩 보관 수첩

타이틀과 크레딧 완료 뒤의 감상 기록에서 선택한 보관본 하나의 수첩을 열 수 있다. 먼저 원본 checksum을 검증하고 구형 기록은 메모리에서만 읽기 변환한다. 현재 슬롯/다른 엔딩을 합치지 않으며 원본 hash·파일명·본문·보호 링크를 유지한다. 기본 실행은 기존 장면 페이지를 유지하고 새 진입 버튼은 개발 옵션에서만 보인다.

공통 검색·출처·시각 자료 확대와 다중 자료의 두 칸 비교를 제공한다. 갤러리 비교는 열람 중 임시 편집이며 닫으면 버린다. 북마크 변경이나 필수 읽기/퍼즐 판정/게임 저장은 없다. 보관본별 선택·스크롤·읽음 표시는 독립된 편의 파일에만 보관하고 다른 엔딩의 위치를 재사용하지 않는다. 손상 원본은 현재 슬롯으로 대체하지 않으며 편의 파일 오류는 원본 열람을 막지 않는다.

계약은 [데이터 계약 9.10절](data_contract.md#910-엔딩-보관본의-읽기-전용-수첩), 실행 근거는 [갤러리 수첩 검증](gallery_notebook_validation.md)을 따른다.

아래 후속 목록은 전체 인수 잔여 목록이며 읽기 계층 자체의 미구현을 뜻하지 않는다. 전체 최초 공개/반복 분기 감사, 게임 대화/선택의 앱 재시작 커서와 실제 입력/성능 인수는 계속 남아 있다. 단계별 실행 근거는 [구현 현황](../ideas/md/v04/issues/validation/notebook_history_implementation_status.md)의 최신 절을 따른다.

1. 아직 미연결인 선택 UI를 목록화하고 표시·선택 시점을 연결한다. 단순 메뉴 이동과 관계·서사 선택을 구분한다.
2. 선택 클릭 후 게임 상태 저장 실패가 발생했을 때 기록과 실제 결과를 명확히 구분하는 연출을 검증한다. 미공개 분기는 노출하지 않는다.
3. 관계·아버지 기록·엔딩에서 아직 미연결인 별도 본문 패널을 실제 열람 시점에 연결한다. 물리 수첩과 EDC 요약은 연결되었으나 모든 패널을 완료한 것은 아니다. 읽기 전용 갤러리에는 쓰기 경로를 추가하지 않는다.
4. 원문 ID 기반 재번역과 대화 커서 재개 정책을 완성한다. 현재 문자열 기록은 호환 읽기로 보존한다.
5. 장시간 목록의 가독성·페이지 분할·파일 크기·문장별 저장 지연을 측정한다. 기록을 임의로 삭제하거나 개수를 제한하지 않는다.

최종 기준은 [완성본 정의](full_game_definition.md)다. 현재 구현만으로 전편 대사·선택지 기록 기준을 충족한 것은 아니다.
