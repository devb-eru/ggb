# 대화 기록 연결 현황

검토 기준: `47e6557`의 공통 기록 구현과 후속 엔딩 읽기 패널 연결. 전편 완료 판정이 아니라 제품 기준 중 대화 기록의 적용 범위와 남은 작업을 정리한다.

후속 통합 수첩 작업은 [단계별 구현 현황](../ideas/md/v04/issues/validation/notebook_history_implementation_status.md)에서 추적한다. 기존 조회 복구와 장 문맥 캡처를 추가했으며, 아래 transcript 저장·재번역·커서 재개 한계는 새 저장 계층 연결 전까지 유지된다.

실제 저장 이관과 책갈피/비교 메타데이터 명령은 개발 검증 옵션에서 연결했다. 일반 실행은 기존 형식이며, 미연결 콘텐츠를 신형 authored 기록으로 가장하지 않는다. 원문 ID 매핑·새 수첩 UI·앱 재시작 커서는 여전히 미완료다. `--notebook-migration-smoke`는 원본 보존·실패 복구를 검사하며, 실제 마우스/키보드 인수를 대체하지 않는다.

후속 NP20 연결로 개발 옵션에서는 단계 힌트 60종을 실제 콘텐츠 ID/의미 버전으로 저장하고 현재 언어로 재열람한다. 요청하지 않은 단계는 기록하지 않으며, legacy 원문은 그대로 보존한다. [생산자 연결 현황](../ideas/md/v04/issues/validation/notebook_content_mapping_status.md)의 나머지 경로를 포함한 전체 매핑은 미완료다. 아래 기존 transcript 제한은 일반 실행과 미연결 경로에 해당한다.

NP01·NP02도 프롤로그 대사 79개 정의와 질문·출발/취침 확인 14개 정의를 명시적 ID로 연결했다. 실제 표시한 선택지/선택/취소와 해당 답변만 기록하며, 실행 중 동일 질문의 문맥을 함께 보존한다. 첫 리셋 뒤에도 문맥을 프롤로그로 유지하고 야간 재조사는 오전 사건과 구분한다. 일반 메뉴 조작은 제외한다. 수첩 자동 원고·별도 오브젝트 피드백·앱 재시작 커서는 아직 이 완료 범위가 아니다.

### 엔딩 읽기 패널

- 물리 수첩의 요약만 열면 펼친 본문을 선행 기록하지 않는다. 다음 색인의 이름은 화면에 보이는 탐색 버튼이므로 남지만 해당 페이지의 본문은 열기 전까지 남지 않는다.
- 요약/펼침 전환과 다음 색인 클릭은 실제 누른 탐색 문구로 남는다. 이는 관계·엔딩 선택이나 해당 페이지 읽기 완료의 증거가 아니다.
- `읽기 확인 후 닫기`는 본문 기록 저장에 성공한 뒤 기존 `field_read` 트랜잭션을 실행한다. 페이지를 연 사실과 진행상 읽기 확인은 별도이며, 기존 필수·선택 페이지 조건은 유지한다.
- 저장 실패 시 페이지와 진행 상태를 유지하고 같은 버튼으로 재시도한다. 교체되거나 닫힌 페이지의 오래된 버튼 콜백은 진행을 바꾸지 않는다.
- 두 절차의 요약창은 두 설명을 함께 기록하며 현실·잔류 의향, 확정, 관계 값을 바꾸지 않는다. 복귀 버튼은 선택 답변으로 남기지 않는다.
- 감상 기록 갤러리의 페이지는 이 기록 함수로 바꾸지 않는다. 엔딩 완료 후 열람은 계속 읽기 전용이다.

## 저장과 표시

- 프롤로그와 `ChapterOneController` 계열의 표시 함수에서 표시 직후 기록한다. 미표시 문장은 기록하지 않고 동일 대화 실행에서 같은 문장을 다시 그릴 때 중복 추가하지 않는다.
- 공통 `dialogue_history_writer.gd`는 `meta_progress.dialogue_history`의 `next_sequence`로 순번을 할당하고 `StateWriter`·`SaveManager`로 저장한다. 프롤로그는 기존 슬롯의 저장 지점을 유지하며 새 슬롯만 `SAVE_NEW_GAME`을 사용한다. 챕터 세션은 `_save_point(state)`를 사용하며 퍼즐·아이템을 수정하는 커밋 훅을 재실행하지 않는다.
- 실패하면 상태를 롤백하고 현재 문장 또는 선택창을 유지한다. 진행·선택 버튼으로 재시도하며 기록 저장 성공 후에만 해당 동작을 실행한다.
- 표시된 질문·선택지 목록과 클릭한 문구는 별도 항목이다. 프롤로그에서 숨겨진 선택지는 제외한다. 관계 선택창의 명시적 보류는 취소 문구로 남기며 신형 기록에서는 `choice_cancelled`로 구분한다. 단순 UI 복귀·신호 재생은 선택 답변으로 남기지 않는다. 첫 버튼의 위치로 취소 여부를 추정하지 않으며 닫힌 선택창의 이전 버튼 콜백은 실행하지 않는다.
- 확정 클릭 기록은 사용자가 누른 문구의 기록이며, 그 뒤 실행되는 게임 상태 저장의 성공을 뜻하지 않는다. 실제 관계·엔딩 확정 여부는 해당 상태와 트랜잭션 결과가 기준이다.
- 열람은 상태 설치·저장을 호출하지 않는다. 엔딩 완료 후 열람은 저장 파일 바이트 불변까지 검사했다.
- 공용 형식은 `CH1_HISTORY_TRANSCRIPT`와 문자열 변수 `speaker`, `text`다. 이 ID는 원래 대사의 콘텐츠 ID가 아니다.
- 기록은 읽었던 언어의 화자·본문을 보존한다. UI 언어를 바꿔도 과거 본문은 재번역하지 않는다. 원문 ID·문장 구간·변수 기반 재번역은 후속 작업이다.
- 대화 커서 재개는 미구현이다. 마지막 피드백을 재표시하면서 재열람 기록이 추가될 수 있다. 다른 상호작용으로 같은 대사를 다시 보는 것도 새 열람이다.

### 현실 몸 재관찰 증거

- 현실 `EDR_BODY_CHECK`에서 이미 확인한 손/호흡 표시기/고정 벨트를 다시 조사해 재관찰 대사가 실제 표시되면 `meta_progress.knowledge_entries.dialogue_observed_facts`에 오브젝트별 `BODY_REPEAT:OBJ_REALITY_* = true`를 남긴다.
- 대사와 동일한 기록 transaction에서 저장한다. 실패 시 대사와 증거가 함께 롤백되고 다음 진행을 막는다. 다른 오브젝트의 최초 조사나 임의 UI 재열람으로 증거를 만들 수 없다.
- 갤러리는 증거가 있으면 보관 대사 문자열 없이 재관찰 내용을 보존할 수 있다. 다만 해당 오브젝트의 기존 게임상 조사 확인 조건도 계속 필요하다. 증거는 조사 완료를 대신하지 않는다.
- 구형 저장에 증거가 없다면 기존의 한국어/영어 transcript 원문 확인을 유지한다. 이 호환 경로는 일반 기록 정리 활성화 전에 저장 이관에서 별도로 처리해야 한다. 조회 시 원본을 변경하지 않는다.

## 후속 작업

1. 아직 미연결인 선택 UI를 목록화하고 표시·선택 시점을 연결한다. 단순 메뉴 이동과 관계·서사 선택을 구분한다.
2. 선택 클릭 후 게임 상태 저장 실패가 발생했을 때 기록과 실제 결과를 명확히 구분하는 연출을 검증한다. 미공개 분기는 노출하지 않는다.
3. 관계·아버지 기록·엔딩에서 아직 미연결인 별도 본문 패널을 실제 열람 시점에 연결한다. 물리 수첩과 EDC 요약은 연결되었으나 모든 패널을 완료한 것은 아니다. 읽기 전용 갤러리에는 쓰기 경로를 추가하지 않는다.
4. 원문 ID 기반 재번역과 대화 커서 재개 정책을 완성한다. 현재 문자열 기록은 호환 읽기로 보존한다.
5. 장시간 목록의 가독성·페이지 분할·파일 크기·문장별 저장 지연을 측정한다. 기록을 임의로 삭제하거나 개수를 제한하지 않는다.

최종 기준은 [완성본 정의](full_game_definition.md)다. 현재 구현만으로 전편 대사·선택지 기록 기준을 충족한 것은 아니다.
