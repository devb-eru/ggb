# 통합 수첩 지하 회귀와 예약 도구 실행 검증

기준: 2026-10-04, develop `87a50b7`. 전체 수첩 목표는 `IN_PROGRESS`다.

## 확인한 문제와 수정

### 예약된 보조 도구의 실행 경계

`notebook_host.gd`는 수첩에서 도구를 선택할 때 scope를 검사하지만, 수첩을 닫은 뒤에는 원래 Callable을 직접 `call_deferred`했다. 그 사이 슬롯을 로드하거나 세션을 교체하면 예약한 이전 화면의 도구가 실행될 수 있었다. 이는 계획서 9.2절 및 NB-AQ14의 낡은 예약 입력 차단 요구에 해당한다.

- 호출은 컨트롤러 소유 동작으로 제한하고 실제 실행 직전에 슬롯, namespace, 기록 origin/branch, load epoch, 세션 인스턴스를 다시 확인한다.
- 새 수첩이나 메뉴가 열렸으면 이전 예약으로 덮지 않는다. 같은 유효 화면에서 선택한 도구는 한 번 실행한다.
- 조회용 도구 실행은 힌트의 최초 공개·퍼즐 판정·게임 저장을 대신하지 않는다. 힌트 목록 열기와 H1~H5 요청은 별개다.
- 저장 스키마, 원고, 퍼즐 해답, 사용자 편집 씬/리소스는 바꾸지 않는다.

### 기존 지하 회귀 검사의 UI 가정

`basement_session_smoke.gd`에는 옛 수첩 자식 노드, `HistoryTranscript`, 익명 선택 콜백을 전제로 한 검사가 남아 있었다.

- 통합 수첩에서는 실제 대화 탭과 최신 공개 원문의 표시 컨트롤을 읽는다. 기본 모드에서는 기존 transcript 검사를 유지한다.
- 통합 수첩을 닫으면 호출한 메뉴로 돌아오는 것을 확인한 후 메뉴를 닫는다. 조회 전후 전체 게임 snapshot 및 엔딩 저장 파일 불변 검사는 유지한다.
- 보조 도구는 수첩 닫기 후 지연 실행되므로 다음 프레임의 화면을 검사한다.
- 엔딩의 저장 실패 주입은 슬롯명을 손상시키는 대신 저장 서비스만 실패시킨다. 슬롯 불일치는 낡은 UI 거부 조건이므로 이를 디스크 실패와 혼동하지 않는다. 실패 시 문장 유지/전체 snapshot 롤백과 저장 복구 후 명시적 재시도 검사는 유지한다.
- 선택 중복 검사는 저장 가능한 컨트롤러의 명시적 닫기 동작으로 수행한다. 선택 원문 저장, 동작 1회, 닫힌 버튼 재호출 시 snapshot/기록 불변을 확인한다. 제품에 익명 콜백 허용 예외를 추가하지 않는다.
- 표시·닫기 검사에서는 유효한 `NOTEBOOK_PRESENTATION`만 세계 상태 비교에서 분리한다. 원래 검사에서 허용한 대화 기록 외의 관계, 퍼즐, 위치, 읽기 확인 등 모든 필드는 계속 비교한다. 순수 조회·실패 롤백·낡은 버튼 검사는 전체 snapshot 비교를 유지한다.
- 재로드 전에 표시 중인 응답을 마치고 새 로드의 방을 다시 그린다. 원문 보존은 같은 entry UID의 모든 불변 필드로 검사하며, 실제 선택에 따른 출처 보호 이유의 추가를 원문 변경으로 오인하지 않는다.
- 잔류 기억 원칙은 해당 클릭 후 추가된 기록에서 실제 영어 문장을 확인한다. 화면 인덱스도 기록되므로 마지막 항목 하나만 대사로 간주하지 않는다. 기억 원칙·사용인 자율성의 부분 재로드 뒤에는 새 scope의 방을 다시 그린 후 다음 버튼을 누른다.
- 끝나지 않는 `while dialogue_active`는 상한과 진행 여부 검사로 바꿨다. 저장 실패나 낡은 scope로 진행이 거부되면 실패를 보고하고 무한 대기하지 않는다.

### 이미 읽은 현실 수첩의 확인창이 다시 열림

실제 재현 경로: 현장 페이지를 펼쳐 읽고 확인한 뒤 같은 페이지/깊이를 다시 확인한다. 최초 확인은 읽기 상태를 변경하므로 예전 보류 커서의 anchor가 달라지지만, 반복 확인은 성공해도 세계 상태가 같을 수 있다. 기존 공통 선택 처리는 `selection_pending`과 anchor 일치만으로 게임 저장 실패라고 판단하여 성공한 반복 확인창을 다시 열었다.

`chapter_one_controller.gd`의 모달 게임 행동과 `basement_controller.gd`의 다음 페이지 확인은 기존 `_presentation_commit_override`를 사용하여 게임 성공과 `completed` 커서를 같은 원자 저장에 넣는다. 실패 시에는 보류 선택을 그대로 유지한다. 저장 응답 유실 확인, 실제 원문/선택 토큰, 다음 페이지의 명시적 표시와 읽기 확인 분리는 유지한다. UI만 닫거나 게임 결과 없이 커서부터 완료하지 않는다.

집중 검사에는 같은 페이지 확인 성공, idempotent 재확인 중 저장 실패, 실제 JSON 재로드 후 동일 선택 재시도, 완료 커서의 디스크 저장, 완료 후 재로드, 명시적 다음 페이지 이동을 포함한다.

## 실행 방법

Godot 4.7.2 Windows의 격리 APPDATA/LOCALAPPDATA, Windows Desktop Debug PCK, 원본 프로젝트가 없는 빈 실행 폴더를 사용한다.

1. `--headless --path <game> --editor --quit`
2. `--headless --path <game> --export-pack "Windows Desktop Debug" <notebook.pck>`
3. `--headless --path <empty> --main-pack <notebook.pck> -- --notebook-host-smoke --ggb-dev-notebook-v2`
4. 같은 패키지로 `--basement-session-smoke --ggb-dev-notebook-v2`
5. 같은 패키지로 `--basement-session-smoke` (기존 모드)

집중 진단에는 4번 인수 뒤에 `--basement-field-regression-only` 또는 `--basement-stay-regression-only`를 추가한다. 전자는 현장 수첩과 출구까지, 후자는 잔류 원칙·식탁·마지막 장면에서 크레딧 진입까지 검사한다. 앞선 F3 분기 복사본을 생성하지 않는 진단 fixture이므로 크레딧·갤러리 검사를 생략한다. 전체 실행에는 이 인수를 사용하지 않으며 전체 회귀 PASS를 대신하지 않는다.

종료 코드, 필수 PASS 마커, 스크립트/파싱/리소스 오류를 함께 확인한다. 실패한 이전 실행을 최종 성공 결과에 포함하지 않는다.

## 검증 범위와 잔여 작업

호스트 검사는 세정제 양 비교와 힌트 도구 각각의 정상 실행, 예약 후 실제 슬롯 재로드, 슬롯명 변경, 같은 슬롯의 세션 교체, 새 수첩, 새 메뉴를 검사한다. 엔진 신호 구동이며 실제 Windows 마우스/키보드/IME 인수가 아니다.

패키지는 추적된 기준 파일과 이번 수정의 격리 복사본으로 만들었다. 원본 작업 폴더에서 사용자가 별도로 편집한 씬·Resource·프로젝트 설정 및 미추적 플러그인의 조합은 이 패키지 검증에 포함하지 않았다. 해당 파일을 수정하거나 검증 완료로 간주하지 않는다.

지하 회귀는 기존 D0~두 엔딩의 퍼즐·리셋·관계·결산·필드 수첩·갤러리 검사에 새 수첩 UI 대응을 더한 것이다. 지하 구간의 통과만으로 프롤로그~전체 22개 생산자의 모든 필수/반복/공개 분기 커버리지를 증명하지 않는다.

남은 전체 범위: 별도 조사/힌트 창과 스크롤·포커스의 재시작 복원, 전체 생산자 분기 감사, 실제 Windows 입력/시각 검사, 고정 fixture cold/warm 지연·RAM 인수. 자동 검사 프로세스의 총 실행 시간은 입력 p95나 저장 성능 합격 수치가 아니다.
