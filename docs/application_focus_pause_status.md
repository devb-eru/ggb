# 애플리케이션 포커스·최소화 일시정지

## 수정한 문제

기존 bootstrap은 창 포커스를 잃으면 음향과 제목 화면 입력만 중지했다. 플레이 컨트롤러 전체는 일시정지 대상이 아니었고, 복귀 시 숨은 제목 화면으로 포커스를 돌릴 수 있었다. 서재 타이머의 개별 처리만으로 대화·다른 타이머·미확정 클릭까지 보호하지 못했다.

## 현재 동작

- bootstrap은 항상 처리하며, 제목 화면과 실제로 생성한 프롤로그·후속 챕터는 `PROCESS_MODE_PAUSABLE`로 실행한다.
- 포커스 상실 시 게임 트리를 일시정지한다. 타이머와 노드에 연결된 애니메이션이 멈추고, UI에 도달하기 전에 입력을 차단한다.
- 포커스 복귀 후 150ms 회복 시간을 둔다. 그 사이 다시 포커스를 잃으면 이전 복귀 예약으로 재개하지 않는다.
- 포커스 상실 전에 이미 일시정지 중이었다면 복귀 후에도 그 상태를 유지한다.
- 창 최소화는 포커스 알림만 믿지 않고 창 모드도 확인한다. 네이티브 검사에서 최소화만으로 포커스 알림이 발생하지 않는 경우를 발견해 추가했다. 최소화 상태에서는 복귀 예약이 게임을 재개할 수 없다.
- 누르는 중이던 일반 버튼의 시각 상태, 열린 드롭다운, 지원되는 viewport의 드래그를 취소한다. 체크박스의 이미 확정된 값은 바꾸지 않는다.
- 상실·복구 대기 중의 키/마우스 입력과, 상실 전에 누른 입력의 뒤늦은 release·키 반복은 소비한다. 새로 누르는 입력부터 다시 받는다.
- 이전 플레이 컨트롤로 키보드 포커스를 돌린다. 해당 컨트롤이 사라지거나 숨겨졌으면 표시 중인 모달 안의 컨트롤을 우선한다. 숨은 제목 화면으로 보내지 않는다.
- J4 확인 버튼의 짧은 대기 타이머도 게임 일시정지를 따른다.
- 화면 설정의 15초 안전 복구와 음향 관리 노드는 계속 처리한다. 안전 카운트다운은 멈추지 않지만, 포커스를 잃은 동안 설정의 유지 입력은 차단한다.

## 검증

`--application-focus-smoke`는 debug 실행에서만 사용할 수 있다.

1. 실제 production bootstrap으로 프롤로그를 생성해 게임 노드의 처리 모드를 검사한다.
2. 포커스 알림을 주입해 진행·타이머 정지, 150ms 복구, 오래된 예약 무효화, 기존 일시정지 보존을 확인한다.
3. Godot 입력 이벤트로 Enter·마우스 누름/놓기를 전달해 대사와 체크박스의 미확정 입력이 뒤늦게 적용되지 않는지 검사한다.
4. 플레이 중 화면 설정을 열고, 트리가 일시정지된 동안에도 안전 카운트다운이 복구하며 유지 입력은 받지 않는지 검사한다.
5. J4 조사 종료 확인창은 게임이 일시정지된 0.6초 동안 확정 버튼이 계속 비활성이고, 재개한 활성 플레이 시간 0.6초 뒤에만 활성화되는지 검사한다. 이 검사는 smoke 실행 창의 우연한 OS 포커스 상태에 의존하지 않는다.
6. 네이티브 렌더러에서는 실제 창 모드를 최소화·복원하고 게임 일시정지를 확인한다.

최종 APPLICATION_FOCUS 검사는 headless와 네이티브 렌더러 모두 PASS였다. START_SCREEN 네이티브 캡처와 FOUNDATION, PROLOGUE_SCENE, CHAPTER_ONE, BLACK_MIRROR, BASEMENT_SESSION 회귀도 통과했다. 일반 GUI 드래그를 실제로 시작한 뒤 포커스 상실로 취소되는 것도 검사했다. BASEMENT_SESSION의 J4 검사는 입력 유예의 일시정지·재개를 직접 통제해, 비활성 GUI 창에서는 제품 타이머만 멈추고 테스트 대기만 흐르던 비결정성을 제거했다. headless 디스플레이가 보고하는 가상 최소화 상태는 실제 OS 창 최소화로 취급하지 않는다.

포커스 상실/복귀의 여러 경우는 알림 주입으로 검증한다. 실제 Windows의 모든 Alt+Tab 경로, 다중 모니터와 모든 팝업·키보드·드래그 조합의 수동 QA까지 완료했다는 뜻은 아니다. 이 변경만으로 전편 입력 접근성이나 게임 전체 완료를 선언하지 않는다.
