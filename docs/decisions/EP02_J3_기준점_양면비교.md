# J3 기준점과 페이지 양면 비교

2026-11-02 사용자 승인: 시트의 기준점·앞뒤 조작을 추가하고, 정확한 방향 확정은 D0 평면도 비교에 유지한다.

## 역할 구분

J3에서는 침실·온실·대시계가 비교 대상이라는 점을 식별하고, 앞면의 겉보기 일치가 문장 방향과 충돌함을 확인한다. 뒷면까지 대조하면 탁본의 방향을 그대로 믿을 수 없다는 결론에 도달한다.

이 단계는 정밀한 평면도 회전 퍼즐이 아니다. 기준점의 실제 지리적 대응과 정확한 회전값은 D0에서 검증한다. J3는 `basement_overlay_solved`, `basement_axis_depths` 또는 D0 평면도 완료를 부여하지 않는다.

## 조작

1. 탁본을 페이지에 놓는다. 처음 놓았을 때 시트의 모순 안내와 J3 도입 대사를 읽는다.
2. 침실·온실·대시계 기준점을 표시한다. 하나 또는 둘만 대조하면 각각 해당 시트 반응을 읽는다.
3. 앞면에서 세 점을 대조한다. 겉보기의 세 점 일치와 문장 방향이 충돌한다.
4. 페이지를 뒤집어 다시 대조한다. 앞면의 모순을 확인하지 않고 뒷면부터 비교해도 완료되지 않는다.
5. 문장 조각을 집어 들고 원하는 조각 사이에 놓는다. 기존 네 조각의 최종 정순은 유지한다.
6. 기준점·양면 비교와 문장 복원이 모두 끝난 상태에서 기존 J3 성공·영구 기록 장면으로 이어진다.

탁본을 들어 올리면 물리적 배치만 해제한다. 표시한 기준점·이미 비교한 정보·문장 배열은 지우지 않는다. 다시 놓으면 그 정보를 재사용한다. 뒤집기는 정확한 회전값을 인증하지 않는다.

## 상태

`BLACK_MIRROR`의 당일 상태에 다음 값을 추가한다.

| 값 | 의미 |
| --- | --- |
| `j3_trace_placed` | 현재 페이지에 탁본이 놓여 있음 |
| `j3_page_side` | 현재 확인하는 `front` 또는 `back` |
| `j3_reference_points` | 실제로 표시한 `BED`, `GREEN`, `CLOCK` |
| `j3_false_alignment_seen` | 앞면의 겉보기 일치 모순을 대조함 |
| `j3_sides_compared` | 앞면 모순 확인 뒤 뒷면을 대조함 |
| `j3_held_part` | 현재 집어 든 문장 조각. 없으면 `-1` |

현재 탁본 배치·세 개의 서로 다른 기준점·양면 비교와 기존 `j3_order=[0,1,2,3]`을 함께 확인해야 복원된다. 중복 기준점·유효하지 않은 놓기 위치·미완료 복원 시도는 실제 실패 횟수나 물질을 소비하지 않는다. 수면 리셋을 요구하지 않는다.

## 저장과 기존 기록

- 저장 실패 시 작업 중 복사본을 버린다. 기준점이나 조각이 획득된 것처럼 남지 않는다.
- 중간 저장에는 실제 페이지 면·비교 상태·집어 든 조각을 보존한다. 재로드가 자동으로 뒤집기나 놓기를 실행하지 않는다.
- 기존 J3 완료 저장은 다시 풀도록 만들지 않는다. 진행 중인 옛 저장의 기존 문장 배열도 지우지 않는다.
- 기존 overlay 피드백 계약과 정의는 유지한다. 새 게임 UI는 시트 안내를 표시하고, 옛 기록은 당시 버전을 사용한다.
- 페이지 뒤집기에는 출처 없는 임시 대사를 저장하지 않는다. 표시가 필요한 호출 경로는 시트의 평면도 확인 한계 문구를 사용한다.
- 기억 닻은 세 기준점을 실제로 표시한 뒤에만 선택적으로 조사할 수 있다. 퍼즐 조작과 정밀 방향 정답을 기억 대사로 대체하지 않는다.

## 검증

실제 UI·중복 입력·저장 거절·중간 재로드·집어 든 조각 재로드·배열의 밑줄·실제 J3 성공·D0 미해결 유지에 더해, 기록 확인 취소/재로드/저장 거절/재시도와 기억 건너뛰기/재생까지 focused 검사 47개가 통과했다. 두 언어 및 기억 닻 유무의 출처 호환 검사도 통과했다. JSON 조각 번호는 유효한 정수만 정규화하며, 최종 체크포인트는 원문 COMMIT_004까지 끝낸 뒤에 기록한다. 이 기록은 실제 프로젝트 배포 완료를 뜻하지 않는다.
