# EP02 감각 자막과 접근성 연결

## 표시 원칙

- 일반 대사·퍼즐 판정·정보 문서는 감각 자막 설정과 무관하게 유지한다.
- 추가 감각 자막만 기존 프로필의 `captions_enabled`를 따른다. 새로운 설정 enum을 만들지 않는다.
- 실제 성공한 조사·혼합·기록 동작의 결과에만 자막을 붙인다. 읽지 않은 정보나 실행하지 않은 효과를 자막으로 먼저 알리지 않는다.
- 최종 아트·BGM·SFX 제작 또는 교체는 이 변경에 포함하지 않는다. 자막은 현재 텍스트 기반 상호작용의 감각 묘사이며, 최종 음원이 재생되었다는 검증 자료로 해석하지 않는다.

## 실제 연결

| 동작 | 시트 노드 | 조건 |
| --- | --- | --- |
| 안정제 확산 | `EP02_CAP_DIFFUSE` | 실제 확산 동작 저장 성공 |
| 중성 시험 | `EP02_CAP_TEST_OK` | 비어 있지 않은 실제 혼합물이 중성으로 판정됨 |
| 비중성 시험 | `EP02_CAP_TEST_BAD` | 비어 있지 않은 실제 혼합물이 비중성으로 판정됨. 빈 병은 제외 |
| 마라 2 채널 조사 | `EP02_CAP_PURPLE` | 실제 채널 조사 저장 성공 |
| 탁본 기록 | `EP02_CAP_TRACE` | 확인창 승인 및 기록·원문 대화 완료. 취소나 저장 거절 시 제외 |
| 젖은 실행 실패 | `EP02_CAP_HARDEN` | 실제 당일 잠금 발생 |
| 젖은 실행 성공 | `EP02_CAP_OPEN`, `EP02_CAP_COLD` | 실제 표면 개방 발생 |
| 마른 시험 직선 | `EP02_CAP_DRY_ENTRY` | 검증된 경로 접두사 1개 이상 |
| 마른 시험 양 분기 | `EP02_CAP_DRY_BRANCH` | 검증된 경로 접두사 3개 이상 |
| 마른 시험 고리 | `EP02_CAP_DRY_RING` | 실제 마른 시험 완주 |

젖은 실행은 일반 동작 경로와 원문 선택지의 원자 실행 경로 모두 같은 판정·자막 선택 함수를 사용한다. 실패 분류는 유지하며, 코팅의 현재 상태를 과거 영구 정보로 대신 판정하지 않는다.

## 채널 표시

- 다섯 채널의 이름과 텍스트 패턴 설명은 모든 설정에서 남는다.
- `color_pattern_label`: 기존 공용 문양에 서명색과 밝은 윤곽선을 표시한다.
- `pattern_label`: 같은 문양을 단색으로 표시한다.
- `label_only`: 별도의 문양 그림을 숨기고 글자는 유지한다.
- 채널 그림은 기존 D5 공용 문양을 재사용하는 개발용 임시 표시다. 애니메이션이나 필수 색 구분을 추가하지 않는다.
- 실제 문양을 표시하는 설정에만 `EP02_SYS_A11Y_COLOR` 안내를 제공한다.
- 감각 자막을 켠 경우에만 진단 안내에 `EP02_SYS_A11Y_AUDIO`를 제공한다.
- 실제 마른 시험 표시의 모션 설정이 `reduced` 또는 `static`인 경우에만 `EP02_SYS_A11Y_MOTION`을 제공한다.

## 과거 기록

마른 시험 창은 원문·과거 버전을 바꾸지 않고 버전 4를 추가했다. 새 창만 실제 검증 접두사와 현재 접근성 설정에 따라 감각 자막 세그먼트를 선택한다. 저장된 옛 창은 저장 당시의 버전·세그먼트·내용을 유지한다.

## 검증 범위

- focused 진단 검사 128개 통과: 프로필 전환, 실제 다섯 채널 표시, 자막 켜기·끄기, 필수 판정 유지, 검증 접두사별 자막, 기록 취소·저장 실패 복구.
- 전체 동기화 검사 3,285개 통과: 실제 혼합 시험·원문 젖은 실행 선택·조사·수면 리셋·영구 정보·자막 기록.
- Python 생성/원문·과거 버전 보존 검사 13개 통과.
- 실제 OS 입력과 최종 아트·음원 품질은 이 검사의 범위가 아니다.

## 남은 작업

추가 감각 자막·상태 안내와 J3의 승인된 기준점·앞뒤 조작은 구현되어 전체 EP02 동기화 검사 3,347개가 통과했다. 패턴/단색 안내는 실제 서명 모드에, 저소음 안내는 기존 음소거 또는 master/effects=0에 연결한다. 저소음의 정적인 막대는 신호 리듬을 구별하는 개발용 도식이며 최종 음원을 측정한 수치가 아니다. 실제 프로젝트 배포와 최종 통합 검증은 별도로 확인한다.
