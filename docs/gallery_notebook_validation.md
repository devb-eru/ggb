# 엔딩 보관 수첩 구현·검증

기준: develop `cf88973` 이후, 2026-10-03. 전체 수첩 목표 중 읽기 전용 갤러리 호스트 단계다. 자유 메모는 범위 밖이며, 여러 자료를 담고 두 개씩 비교하는 정책을 유지한다.

## 구현

- 타이틀의 감상 기록과 크레딧 완료 뒤 감상 기록에 보관 수첩 버튼을 추가했다. 기존 장면 페이지와 개발 옵션 기본 비활성을 유지한다.
- `notebook_gallery_host.gd`는 검증된 보관본 하나를 frozen snapshot으로 읽는다. 게임 상태/저장 API를 참조하지 않는다. 다른 엔딩·활성 슬롯과 자료를 합치지 않는다.
- 원본 checksum 검증 후 구형 형식을 메모리에서만 변환한다. 보관 ID·파일명·payload·checksum·메타 참조는 수정하지 않는다.
- 공통 네 분류·검색·출처·확대를 사용한다. 퍼즐 판정·필수 읽기·새 관찰 저장은 없다. 북마크는 조회만 하며 자료 비교는 보관된 묶음에서 시작하는 세션 한정 임시 편집이다.
- 비교 최대 12개/표시 두 개의 기존 제한을 유지한다. 현재 보관본에 공개된 참조와 현재 조회 키만 받는다. 언어를 바꾸어도 임시 묶음은 유지하지만 닫으면 폐기한다.
- 편의 파일은 `gallery` namespace와 payload hash/어댑터 버전/원래 계통으로 분리한다. 읽음·위치·확대만 저장하고 임시 비교와 복귀 스택의 비교 모드는 제거한다. 미래 편의 버전은 덮어쓰지 않는다.
- 닫는 동안 키/마우스 release를 기다리고 감상 목록으로 돌아간다. 원래 화면이 제거되면 화면을 되살리지 않고 정리한다.

정확한 필드 계약: [데이터 계약 9.10절](data_contract.md#910-엔딩-보관본의-읽기-전용-수첩).

## 자동 검사

`notebook_gallery_smoke.gd`를 `--notebook-query-smoke --ggb-dev-notebook-v2`에 포함한다. 격리된 완료 엔딩 fixture와 관찰한 원고만 사용하며 fixture 생성은 실제 플레이 인수가 아니다.

| 시나리오 | 확인 기준 |
| --- | --- |
| 현실/잔류 보관본 | 다른 원문 UID·읽음·선택 위치가 유입되지 않음 |
| 조회/북마크 신호 | 원본 자료·보호 링크·GameState 불변, 편집 북마크 없음 |
| 임시 비교 | 12개 제한, 두 칸 교체, 낡은 조회 키/다른 보관본 거부, 언어 변경 유지, 재진입 폐기 |
| 닫기/소유 화면 제거 | release 후 포커스 복원, 제거된 owner 재개 금지 |
| 타이틀 진입 | 선택한 ID로 열고 감상 목록으로 복귀, 빈 목록의 이전 버튼 비활성 |
| 크레딧 뒤 진입 | 실제 컨트롤러 버튼을 사용하고 runtime/슬롯 bytes 불변 |
| 구형/미분류 | 당시 원문 접근 유지, 디스크 형식·hash 불변 |
| 손상/누락/미래 원본 | 열기 거부, 현재 슬롯 대체·원본 수정 없음 |
| 손상/미래 편의 파일 | 원문 접근 유지, 미래 bytes 보존 |

현재 `basement_session_smoke.gd:224/236`은 옛 힌트 버튼과 대사 개수를 가정하고, `:771`은 옛 `HistoryTranscript` Label을 직접 찾는다. 신규 수첩 옵션에서는 이 테스트가 맞지 않아 실패했다. 직전 A1 단계 PCK에서도 같은 힌트 오류와 `:771` null 오류가 재현되었다. 대조 패키지 SHA-256은 `9CD9102FA44380957365779DD31DD659E6AFBC182783A1F1AA67E097CEAAB0EF`다. 이 재현 확인은 25.4초이며 PASS 실행으로 세지 않는다.

권장 조치: 남은 전체 생산자 감사에서 구형 테스트의 화면 접근을 실제 호스트/관찰 ID 기반으로 분리하고, 개발 옵션 전용 필수 경로를 모두 재실행한다. 이번에는 해당 assertion을 삭제하거나 자동 통과로 바꾸지 않았다. 갤러리와 본편 수첩의 집중 검사 통과를 구형 전체 테스트의 통과로 대체하지 않는다.

루트 인증서 저장소 읽기 경고만 환경 경고로 허용했다. 테스트 사본과 별개인 실제 작업 폴더의 사용자 편집 씬/리소스·추가 플러그인은 보존하며 이 자동 검사 범위에 포함하지 않는다.

## 남은 인수

실제 Windows 마우스·키보드·IME, OS 배율/스크린샷, 고정 부하의 cold/warm p95·RAM은 미완료다. 앱 재시작 대사/선택 커서와 22개 생산자의 필수 분기·최초 공개/내부 ID 감사도 별도 남은 작업이다. 이번 호스트 구현은 전체 목표 완료나 기본 활성화 승인이 아니다.

## 기존 장면 페이지와의 구분

이 문서가 이전에 관리하던 `감상 기록: 현장 수첩·출입 점검`의 검증 책임도 유지한다. `ending_gallery_pages.gd`의 기존 페이지 모음은 이번 공통 수첩 호스트와 별도이며 삭제하지 않는다.

- 현장 수첩은 보존된 `FIELD_NOTEBOOK.pages`에 포함된 페이지만 제공한다. 과거의 요약만 있는 저장에서 펼친 본문/관계별 부기를 추정하지 않는 원칙을 유지한다. 현재 페이지 구현은 실제 `expanded_pages`가 있는 경우에만 펼침을 선택한다.
- 전력·외기·수동 해제는 `required_interactions_seen`의 실제 점검 근거를 사용한다. 신체 확인, 수첩, 출입 점검, 시설 조사, 마지막 시선 순서와 미열람 생략을 유지한다.
- 기존 회귀는 수첩 미열람 숨김, 한 페이지 확인 시 한 페이지만 추가, 근거 없는 상세 본문 미공개, 출입 점검 한 항목 추가를 검사한다. 이 검사는 새 호스트의 원문/UID/임시 비교 검사를 대체하지 않는다.
- 최초 문서의 `전체 엔딩 영상·ALL 의식·잔류 합의·수첩 상세 본문 재생 미완료`는 당시 페이지 구현 상태였다. 이번에도 전체 장면 영상 재생을 추가하지 않는다. 실제 관찰 archive가 있는 새 기록의 문장·자료 재열람과, 과거 저장에 없는 원문을 소급 생성하는 일은 구분한다.
