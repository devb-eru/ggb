# GGB 제품 계약

## 1. 문서 상태와 우선순위

| 항목 | 값 |
| --- | --- |
| 상태 | ACCEPTED_FOR_PRODUCTION |
| 기준일 | 2026-07-31 |
| 대상 | 공개 데모, 정식 버전 1.0 |
| 플랫폼 | Windows 10/11 64-bit PC |
| 콘텐츠 정본 | `ideas/md/v04/` |

이 문서는 플랫폼, 빌드 범위, 입력, 접근성, 저장, 언어처럼 데모와 본편이 함께 지켜야 하는 제품 약속의 정본이다. 적용 우선순위는 다음과 같다.

1. 최신 `GGB-DEC` 결정 기록.
2. 본 제품 계약.
3. `demo_definition.md`와 `full_game_definition.md`의 결과물별 추가 조건.
4. `ideas/md/v04/`의 콘텐츠·연출·상태 상세.

하위 문서가 본 계약보다 좁은 기능만 요구하거나 서로 다른 값을 사용하면 본 계약을 따른다. 범위를 축소하거나 뒤집을 때는 새 `GGB-DEC`를 만들고 영향 문서를 같은 변경 단위로 갱신한다.

## 2. 제품 범위

| 항목 | 공개 데모 | 정식 버전 1.0 |
| --- | --- | --- |
| `build_flavor` | `demo` | `full` |
| 시작점 | 프롤로그 P1 | 프롤로그 P1 또는 호환 데모 저장 가져오기 |
| 플레이 가능 종료점 | D4 완료 | EDC 이후 현실·잔류 엔딩 |
| 종료 연출 | D5 위장 필터 해제 스팅어 | 선택한 엔딩과 크레딧 |
| 마지막 콘텐츠 경계 | `SAVE_D5_COMPLETE` | `SAVE_ENDING_COMPLETE` |
| 언어 | `ko-KR`, `en-US` | `ko-KR`, `en-US` |
| 음성 | 없음 | 없음 |
| 임시 필수 에셋 | 노출 필수 에셋 `unit_count` 가중 비율 20% 이하 | 0% |

데모의 D5는 3장 플레이 구간이 아니라 본편 2~3분 전환을 축약한 `presentation_variant=demo_stinger`의 60~90초 비상호작용 에필로그다. 같은 D5 완료 상태를 쓰지만 데모의 `SAVE_D5_COMPLETE`는 `DEMO_END_SCREEN`으로 재개하며, E1 이후 공간, 관계 핵심 이벤트와 엔딩 데이터는 데모 registry에서 실행할 수 없어야 한다.

## 3. 플레이타임 계약

### 3.1 정식판 기준

| 경로 | 목표 범위 |
| --- | --- |
| 필수 진행 | 3시간 30분~5시간 45분 |
| 권장 진행 | 4시간 15분~7시간 30분 |
| 다섯 사용인 핵심 관계 포함 | 4시간 45분~8시간 |

내부 산식은 v0.4 챕터별 필수 예산 214~340분, 권장 관계 2~3명 추가분을 포함한 265~438분, 전원 관계 추가분을 포함한 295~468분을 15분 단위로 바깥쪽 반올림한 값이다. 이는 제작·테스트 목표이며 외부 약속이 아니다. 플레이타임은 읽기 속도와 퍼즐 숙련도에 따라 달라지므로 상점 문구는 플레이테스트 중앙값과 25~75백분위 결과를 받은 뒤 확정한다.

### 3.2 데모 검증 범위

기존 130~210분안은 고정 약속이 아니다. 다음 두 편집안을 같은 핵심 경험으로 비교한다.

| 안 | 목표 | 유지해야 하는 경험 |
| --- | --- | --- |
| `DEMO_COMPACT` | 60~100분 | 첫 리셋, 영구 정보, 실패 후 숏컷, 사용인 기억, D5 스팅어 |
| `DEMO_EXTENDED` | 130~210분 | 프롤로그~D4의 현행 상세 흐름과 D5 스팅어 |

`VERTICAL_SLICE`와 `CH1_ALPHA` 플레이테스트 뒤 완주율, 세션 길이, 반복 피로, D5 도달률과 찜하기 의향으로 한 안을 결정한다. 결정 전에는 외부 상점에 확정 시간을 표기하지 않는다.

| 항목 | 필수 기준 |
| --- | --- |
| 기준 화면비 | 16:9 |
| 기준 해상도 | 1920x1080 |
| 최소 레이아웃 검증 | 1280x720 |
| 확대 검증 | 2560x1440, 3840x2160 |
| Windows 표시 배율 | 100%, 125%, 150%, 175%, 200% |
| 기본 창 모드 | 테두리 없는 창 |
| 추가 창 모드 | 창 모드, 전체 화면 |
| 창 크기 | 변경 가능, 1280x720 논리 레이아웃 아래로 축소하지 않음 |

| 텍스트 배율 | UI와 독립된 100~200% |

16:9 밖의 영역은 비상호작용 장식 또는 여백으로 처리하고, 미발견 방이나 이벤트를 미리 보여 주지 않는다. 화면 모드·해상도 변경에는 15초 확인과 이전 설정 복구를 제공한다.

## 5. 입력 계약

- 필수 진행은 마우스만으로 완주할 수 있다.
- 필수 진행은 키보드만으로 완주할 수 있다.
- 모든 필수 행동은 재지정 가능한 action으로 제공한다.
- 마우스 hover와 키보드 focus는 독립적으로 유지하고 명시적 확정 입력만 소비한다.
- 선택지, 퍼즐, 인벤토리, 지도, 수첩, 대화 기록과 설정에 키보드 포커스 순서와 복귀 지점을 둔다.
- 게임패드, 터치와 콘솔은 1.0 지원 범위에서 제외한다. 관련 문구는 확정 기능처럼 쓰지 않는다.

## 6. 접근성 계약

다음은 데모와 정식판의 공통 출시 조건이다.

- 색상 단서는 문양, 선 패턴, 라벨과 감각 자막 중 하나 이상을 항상 병행한다.
- 음향 단서는 시각 표시 또는 감각 자막으로 대체한다.
- 화면 흔들림, 섬광, 글리치 강도와 자동 이동을 줄이거나 끌 수 있다.
- 자막과 대화 기록은 화자, 선택지, 사건 순서를 보존한다.
- UI 200%, 텍스트 200%에서 필수 버튼·핫스폿·대사가 잘리거나 겹치지 않는다.
- 포커스 상실, `Alt+Tab`, 창 최소화 시 기본적으로 일시정지하고 미확정 입력을 자동 확정하지 않는다.
- 접근성 설정은 슬롯 진행과 분리된 사용자 프로필에 저장한다.
- 첫 실행에서 자막, 텍스트 크기, 모션 감소, 색상 서명 표시 방식을 게임 시작 전에 설정할 수 있다.

스크린 리더 직접 지원은 1.0 필수 범위가 아니다. 다만 텍스트 ID와 포커스 구조는 향후 지원을 막지 않게 작성한다.

## 7. 저장·재개 사용자 계약

### 7.1 슬롯과 저장 방식

- 진행 슬롯은 3개다.
- 각 슬롯은 현재 진행, 이전 정상 저장 백업과 임시 트랜잭션 파일을 가진다.
- 게임은 안전 지점과 리셋 트랜잭션 완료 시 자동 저장한다.
- 임의 퍼즐 조작 중 수동 저장은 제공하지 않는다.
- `저장하고 타이틀로`는 원자 사건·퍼즐 검증 중이 아닐 때 가장 최근 안전 지점까지 확정하고 종료한다.
- 타이틀은 `계속하기`, `새 게임`, `불러오기`, `설정`, `종료`를 제공한다.
- 저장 중에는 표시를 내고, 종료 요청은 커밋 완료 또는 롤백 뒤 처리한다.

세계의 수면 리셋과 디스크 저장은 서로 다른 기능이다. 수면은 세계 물리 상태를 되돌리며, 디스크 저장은 영구 정보와 현재 안전 재개점을 보존한다. UI와 튜토리얼은 둘을 같은 의미의 체크포인트로 표현하지 않는다.

### 7.2 초기 안전 지점

| ID | 생성 시점 | 재개 위치 |
| --- | --- | --- |
| `SAVE_P6_COMPLETE` | 첫 취침 선택 확정 | NORMAL_RESET 진입 |
| `SAVE_NORMAL_RESET_COMPLETE` | 각 정상 리셋 원자 처리 완료 | 같은 아침의 ROUTE |
| `SAVE_A2_COMPLETE` | 수첩 표시 유지 확인 | B1 진입 |
| `SAVE_J1_COMPLETE` | 일지 1단계 영구 복원 | B3 준비 |
| `SAVE_J2_COMPLETE` | 일지 2단계 영구 복원 | 다음 정상 리셋 |
| `SAVE_J3_COMPLETE` | 일지 3단계 영구 복원 | D0 진입 |

D4 이후 저장 지점은 v0.4 문서 17의 저장 지점 정책을 따른다. `HARD FAILURE`는 실패 정보의 원자 커밋 뒤 안전 지점을 만든 다음 수면·리셋 경로로 보낸다.

## 8. 저장 호환 헤더

첫 외부 또는 팀 배포 런타임 저장 형식은 `schema_version=1`에서 시작한다. v0.4 문서의 상태 모델 개정 번호 12는 런타임 저장 버전이 아니다.

```yaml
save_header:
  schema_version: 1
  design_revision: "v0.4-state-r12"
  game_version: "0.0.0-dev"
  build_id: "local-dev"
  build_flavor: "demo"
  content_revision: "unlocked"
  content_boundary_id: "SAVE_J1_COMPLETE"
  source_app_id: "local"
  engine_version: "4.7"
  slot_id: "slot_01"
  save_point_id: "SAVE_J1_COMPLETE"
  transaction_id: "SAVE_TX_000001"
  created_at_utc: 0
  updated_at_utc: 0
  checksum_algorithm: "sha256"
  checksum: ""
```

- `schema_version`: 직렬화 구조 호환성.
- `design_revision`: 어떤 기획 상태 모델에서 생성됐는지 추적하는 정보이며 호환 판정의 단독 근거가 아니다.
- `game_version`: 사용자에게 표시하는 제품 버전.
- `build_id`: 같은 버전 안의 빌드를 구분하는 불변 식별자.
- `build_flavor`: `demo` 또는 `full`.
- `content_revision`: 정적 콘텐츠 registry 개정.
- `content_boundary_id`: 저장이 도달한 공개 콘텐츠 경계.
- `source_app_id`: 데모·본편 AppID 또는 로컬 개발 출처.

실제로 팀원 또는 외부 테스터에게 배포한 저장 형식만 migration 대상으로 지원한다. 공개 전 문서 개정 1~11을 위한 가상 migration 코드는 만들지 않는다.

## 9. 데모 저장 가져오기

정식판 첫 실행 또는 슬롯 화면에서 다음 절차를 제공한다.

1. 데모의 별도 사용자 데이터 경로와 Steam Cloud 사용 여부를 확인한다.
2. 원본 데모 저장을 수정하지 않고 읽기 전용으로 검사한다.
3. checksum, `schema_version`, `build_flavor=demo`, `content_boundary_id`와 지원 버전을 검증한다.
4. 가져올 슬롯, 플레이 시간, 언어와 마지막 경계를 미리 보여 준다.
5. 기존 본편 슬롯과 충돌하면 새 슬롯 가져오기, 덮어쓰기, 취소를 묻는다.
6. 본편 형식으로 복사·migration한 뒤 재로드 검증에 성공해야 완료한다.
7. 실패하면 원본과 기존 본편 슬롯을 보존하고 이유와 새 게임 선택지를 표시한다.

승인된 import는 데모 원본의 재개 목적지를 바꾸지 않는다. 새 본편 슬롯에 복사된 `SAVE_D5_COMPLETE`만 `D6_FREE_INSPECTION`으로 매핑하며, 데모에서 같은 저장을 열면 항상 `DEMO_END_SCREEN`으로 간다.

Steam Cloud의 데모·본편 공유 여부는 AppID 생성 뒤 별도 검증한다. 검증 전에는 자동 공유를 전제로 하지 않는다.

## 10. 대화 기록 계약

- 본문 문자열이 아니라 `line_id`와 선택 이력을 저장한다.
- 언어를 바꾸면 현재 locale의 문구로 다시 해석한다.
- 아직 보지 않은 대사와 선택지는 노출하지 않는다.
- 기록은 슬롯별로 보존하고 NORMAL_RESET, BROKEN_RESET과 불러오기에서 유지한다.
- 새 게임, 슬롯 삭제 또는 호환 불가 초기화에서만 제거한다.
- 기본 최대 2,000개 항목을 보관하며 초과 시 가장 오래된 일반 대사부터 제거한다.
- 일지 복원, 최종 선택, 관계 outcome과 연결된 보호 항목은 자동 제거하지 않는다.

## 11. 현지화 계약

지원 locale은 `ko-KR`, `en-US`다. 번역 원본, 캐릭터 말투, 변수, 글자 제한, 검토 상태와 pseudo-localization은 [현지화 제작 계약](localization.md)을 따른다.
