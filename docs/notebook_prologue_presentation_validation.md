# 프롤로그 대사·선택 복원 검증

기준일: 2026-10-04. 전체 통합 수첩 목표는 `IN_PROGRESS`다. 이번 범위는 프롤로그 표시 커서이며 실제 Windows 입력 인수나 전편 모든 조사 화면 복원은 아니다.

## 변경 범위

- `notebook_presentation.gd`: schema 2, 기존 shared schema 1 읽기, 프롤로그 family와 제한된 후속 동작, 질문/확인 구조 검증. 선택 복원은 목록 토큰과 마지막 선택 토큰을 모두 확인한다.
- `dialogue_history_writer.gd`: detached candidate에 관찰을 추가하는 공통 helper. 게임 진행과 표시 기록을 한 번에 저장할 수 있게 하며 기존 writer의 저장·응답 확인·롤백 계약을 유지한다.
- `prologue_controller.gd`: P1~R1 대사, P3/P4 질문, P1 출발/P6 취침 확인의 위치·토큰 복원. 동기 후속 진행과 다음 표시/완료를 같이 저장한다.
- `bootstrap.gd`: 완료 플래그가 있어도 미완료 P6/R1 화면을 먼저 복원한다.
- 기존 프롤로그 smoke의 저장 실패 주입은 잘못된 슬롯 이름에서 제어된 저장 실패 fixture로 변경했다. 슬롯 변경은 이제 낡은 콜백 차단 경계이므로 저장 실패 재시도와 구분한다.

퍼즐 정답, 대사 원문, 사용자 편집 씬/리소스·오디오, 기본 수첩 활성화 설정은 수정하지 않는다. 실제 저장 실패 후 미저장 표시가 화면에 남으면 재시도를 기다린다. 그 표시를 수첩에 성공적으로 보관했다고 보고하지 않는다.

## 재현 방법

Godot 4.7.2 Windows, 격리 APPDATA/LOCALAPPDATA를 사용한다. `Windows Desktop Debug` PCK를 export한 뒤 소스 프로젝트가 없는 빈 디렉터리에서 실행한다. 실제 사용자 슬롯은 사용하지 않는다.

1. `--notebook-prologue-presentation-smoke --ggb-dev-notebook-v2 --cursor-phase=seed`: 집중 경계를 검사하고 P1/P3/P4/P6/R1의 미완료 슬롯과 기대값을 저장한다.
2. 첫 프로세스 종료 후 같은 격리 프로필에서 `--cursor-phase=resume`: 각각 한국어 관찰을 영어 UI로 복원하고 명시적으로 진행한다.
3. 다시 종료 후 `--cursor-phase=completed`: 닫은 대사·질문이 반복되지 않음을 확인한다.

각 단계는 별도 OS 프로세스이며 테스트가 PID 차이를 확인한다. 조작은 엔진 메서드·신호로 수행하므로 실제 마우스/키보드 완주로 계산하지 않는다.

## 경계별 검사

| 경계 | 검사 |
| --- | --- |
| P1 | 정확한 다음 문장 복원, 미래 문장 비공개, 마지막 대사 완료 후 자동 인사 미재생 |
| 후보 저장 | 다음 문장 저장 실패 시 세계·보관·커서 전체 롤백, 동일 토큰 재시도, 정확한 저장본으로 응답 소실 복구 |
| P3 | 원래 선택 목록 복원, 선택만 저장되고 답변 저장이 실패한 경우 진행 상태 불변, 같은 답 재시도/다른 답 선택, A→B→A 토큰 분리 |
| P3 종료 | 침묵 선택으로 종료한 질문을 예약된 과거 콜백이 다시 열지 않음 |
| P4 | 질문 상태에서 자동 선택 없음, 선택과 답변 표시/진행 원자 저장, 여러 문장 중 두 번째부터 재개, 이리스 인사와 중앙홀 복귀 |
| 확인창 | 출발·취침의 명시적 확인/취소, 완료 전 자동 실행 없음, 이전 load epoch의 버튼 콜백 차단 |
| P6/R1 | bootstrap이 완료 플래그만 보고 읽는 중인 취침 대사를 넘기지 않음, 실제 정상 리셋 후 R1 표시, 완료한 R1 미재생, 새 장의 A1 첫 안내는 정상 표시하고 재로드 시 그 안내를 중복 기록하지 않음 |
| 데이터 | JSON 왕복, shared schema 1 호환, 잘못된 after/choice/lines 거부, 확인창의 필수 confirm/cancel 누락 거부 |
| 기존 회귀 | 프롤로그 원고/조사 표시의 한영·저장·실패 검사, 본편 공통 커서, 마이그레이션/조회 호스트/기존 캠페인을 별도 실행 |

선택 기록은 실제 게임 진행 성공의 증거가 아니다. 재시작 뒤 보류된 선택을 자동 호출하지 않으며 미선택 답변·숨은 분기를 미리 보관하지 않는다. 색/관계/퍼즐 정답 변경은 없다.

콘텐츠 JSON 26개는 실제 저장소의 변경 전 파일과 hash가 같다. 검증 사본의 스크립트 UID 232개에 중복이 없고 문서 검사 295개가 통과했다. 최종 패키지를 만든 이후 검사 대상 코드/UID의 hash가 유지되는지 별도로 대조한다.

개발 중 JSON 숫자형 schema 검사, 완료 질문의 예약 재개, 후속 방 이동 scope, 같은 트랜잭션 안에서 사라지던 P3 침묵 상태/마라 2 이름표 표시를 수정했다. 표시 요청은 진행 후보에 함께 담고 저장 확인 뒤에만 기록 완료로 처리한다. R1 완료를 본편의 완료 큐로 넘겨 새 A1 안내까지 생략하던 경계도 제거하고 bootstrap 회귀 검사를 추가했다. 첫 리셋 뒤 저장 비교는 JSON 수치 표현을 정규화하되 UID·원문·토큰·전체 상태는 그대로 대조한다. 초기 파싱/fixture 실패와 runner의 legacy PASS 마커 오기는 성공 집계에서 제외하고 수정 후 재실행했다.

종료 코드·필수 PASS 마커·스크립트/파싱 오류를 함께 검사한다. Windows 루트 인증서 저장소 읽기 경고는 환경 경고로 분리한다. 검사 프로세스 전체 시간은 입력 응답 p95나 저사양 장비의 cold/warm 성능 측정값이 아니다.

## 남은 범위

1. 본편 선택 모달 및 별도 조사 본문/확대 창의 프로세스 재시작 커서. 프롤로그의 이식으로 완료 처리하지 않는다.
2. 22개 생산자 전체 필수/반복 분기·최초 공개·공개 ID 감사와 기존 지하 smoke의 v2 UI 대응.
3. Windows 실제 마우스·키보드·IME·시각 검수와 고정 fixture의 cold/warm 지연·RAM 인수.

실제 프로젝트에 남아 있는 사용자 변경 파일과 플러그인은 검증 사본에 덮어 넣지 않는다. 이 보고서는 그 편집 환경의 native 실행 결과가 아니며 전체 목표 완료 또는 새 수첩 기본 활성화를 승인한 결과도 아니다.
