# 본편 대사 위치 복원 검증

기준일: 2026-10-04. 전체 통합 수첩 목표는 `IN_PROGRESS`이며 이 문서는 공통 본편 대사 큐 단계만 다룬다.

## 변경 범위

- `notebook_presentation.gd`: 제한된 대사 커서 schema, 세계 anchor, 관찰 토큰 확인, 명시적 분기 인계, 정확한 원문 descriptor를 이용한 재표시.
- `dialogue_history_writer.gd`: 현재 문장 공개와 커서의 원자 저장, 마지막 문장 완료 저장. 큐는 보관 관찰의 context에 포함하지 않는다.
- 공통 ChapterOne 컨트롤러와 상속된 BlackMirror/Basement: 읽는 위치 복원, 중복 append 방지, 로드 이전 콜백 차단. 후속 동작의 자동 실행은 없다.
- Bootstrap과 ChapterOneSession: J2/J3의 미완료 대사 우선 진입, 완료 큐의 다음 장 초기화 인계. 정상 화면 초기화와 함께 저장한다.
- BasementSession: D5 시선 선택 시 이미 표시 중인 큐의 유지. SaveManager: 정상 backup 분기 재발급과 미래 버전 보호.

v2 archive가 있는 본편 저장에서만 새 커서를 쓴다. legacy 쓰기와 기본 수첩 비활성 정책을 바꾸지 않으며, 프롤로그 base의 변경은 공통 화면이 지정 index에서 표시할 수 있도록 한 선택 인자뿐이다.

## 재현 방법

Godot 4.7.2 Windows 런타임, 격리 APPDATA/LOCALAPPDATA, 소스가 없는 빈 실행 디렉터리에서 export PCK를 사용한다. 실제 사용자 슬롯은 테스트하지 않는다.

1. `--notebook-presentation-smoke --ggb-dev-notebook-v2 --cursor-phase=seed`로 schema/실패/분기/컨트롤러 검사를 실행하고 두 번째 문장의 슬롯과 기대값을 저장한다.
2. 첫 프로세스 종료 후 같은 격리 프로필에서 `--cursor-phase=resume`을 별도 프로세스로 실행한다. 실제 `LoadCoordinator`와 컨트롤러를 통해 두 번째 문장·토큰을 확인하고 명시적으로 닫는다.
3. 다시 종료한 뒤 `--cursor-phase=completed`를 별도 프로세스로 실행한다. 완료 큐가 다시 표시되거나 기록되지 않는지 확인한다.

테스트는 프로세스 ID가 달라졌는지 확인한다. 이는 실제 프로세스 재시작 검사지만 OS 마우스/키보드 입력 검수는 아니다. 대사·힌트·D5·장 전환 동작은 엔진 메서드와 신호로 구동한다.

## 잔여 범위

1. 이 단계 이후 프롤로그 대사·질문/확인은 [별도 복원 검증](notebook_prologue_presentation_validation.md)으로 확장했다. 본편 선택 모달과 별도 조사 본문의 영속 커서는 남았다. 공통 대사 큐의 구현을 전편 모든 UI 완료로 계산하지 않는다.
2. 모달에서 선택은 기록됐지만 진행 저장이 실패한 경우의 재확인 정책과 고정 선택 목록/선택 토큰 복원. 저장된 선택을 자동 실행하는 처리는 추가하지 않았다.
3. 22개 생산자의 모든 필수 분기·최초 공개·공개 문자열 ID 감사. 기존 지하 smoke의 새 UI 옵션 미대응 문제도 별도 추적한다.
4. Windows 실제 마우스/키보드/IME와 시각 인수, 고정 fixture의 cold/warm 성능·RAM 인수. 이번 테스트 프로세스 시간은 응답 p95가 아니다.

검증 사본에는 실제 작업 디렉터리의 미커밋 사용자 씬/리소스·추가 플러그인을 덮어 복사하지 않는다. 따라서 아래 결과를 그 편집 환경의 native 실행 결과라고 부르지 않는다.
