# 음향 구현 준비 상태

## 현재 준비 상태

재생 기반과 설정은 구현되어 있다. `game_audio.gd`, `audio_cue_registry.json`, 타이틀·플레이 중 설정을 기준으로 하며 세부 내용은 [음향 런타임](audio_runtime_status.md)을 따른다. 아래 최초 조사와 다음 구현 단위는 당시의 기록이다. 현재 후속 작업에서는 이미 있는 재생 시스템을 새로 만들지 않는다.

게임 음원 파일은 현재 `game/assets`에서 찾지 못했고 등록 cue는 PLANNED·빈 경로다. 승인된 실제 음원을 접수한 뒤 경로·반복 설정을 연결하고, 후속 챕터 cue와 무음 대체 표현, 재생·전환·청취 QA를 진행해야 한다. 음원 누락을 게임 진행 차단 사유로 바꾸지 않는다.

## 최초 조사 근거

- `game/assets`에서 `.ogg`, `.wav`, `.mp3` 게임 음원을 찾지 못했다.
- `game/scripts`와 `game/data`의 파일명 조사에서 전용 음향 재생 시스템·음향 레지스트리를 찾지 못했다. 이는 모든 코드 내부 오디오 호출에 대한 완전한 정적 분석 결과는 아니다.
- `docs/asset_manifest.csv`의 음향 행과 `docs/requests/audio/`의 제작 명세를 기준으로 접수해야 한다. 기존 의뢰 파일과 별도 작업 중인 `suno` 파일은 이번 점검에서 수정하지 않았다.
- 승인된 export만 빌드에 통합하는 `docs/asset_intake.md` 절차를 유지한다. 최종 제작진 크레딧은 미정이다.

## 다음 구현 단위

1. 요청 asset_id와 실제 `res://` 경로, 루프 여부, 용도, 볼륨, 접근성 태그를 연결한다. 승인 상태·라이선스·접수 근거가 없는 음원을 최종 리소스로 표시하지 않는다.
2. BGM·공간음·효과음을 분리하고 볼륨·음소거를 저장한다. 게임 진행 플래그와 음원 로드 성공 여부는 분리한다. 음원 누락으로 퍼즐이나 엔딩 진행이 멈추면 안 된다.
3. 먼저 P4의 두 맥박과 늦은 응답, B3 종 신호, D5 전환, 현실·잔류 종료에 연결한다. 동일 리소스의 무분별한 반복 재생을 방지하고 방 이동·타이틀 복귀에서 정리한다.
4. 무음·심박음 감소 설정에서도 텍스트·문양 단서로 진행할 수 있도록 한다. 포커스 이탈·일시정지 시 연출 시간과 재생 위치 정책을 함께 검증한다.
5. 두 엔딩의 청취 QA, 루프 경계, 음량 균형, 재실행 및 장치 변경을 실제 재생으로 확인한다. 가짜 플레이어 테스트만으로 음향 완료를 선언하지 않는다.

## 확인 대기

팀 승인 음원 제공 예정인지, 개발용 임시 음원 제작까지 포함할지 사용자에게 질문했다. 답변 전에는 최종 음원을 임의 제작·승인하지 않는다. 이 대기는 게임 전체 개발을 막는 것으로 취급하지 않는다.
