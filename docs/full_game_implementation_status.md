### 다음 구현 순서

1. 프롤로그부터 두 엔딩까지 실제 입력 기반 검증을 확장한다. 세션 직접 호출과 저장 fixture를 쓰는 회귀 검사는 필수 입력 경로의 완주 증거와 구분한다.
2. 챕터별 기획 정본·대화 원문·에셋 manifest와 런타임을 대조해 콘텐츠 충실도와 플레이타임을 보완한다. 우선 P4 생명 유지 전조, D5 데모 스팅어, 후반 퍼즐·관계 이벤트의 최종 연출을 확인한다.
3. 최종 에셋·효과음·BGM, 영어 텍스트와 접근성 조합을 완성하고 제품 게이트를 검증한다. 제품 계약상 음성은 범위 밖이며 임의 추가하지 않는다.
4. 데모 가져오기의 제품 슬롯·실제 입력·빈 슬롯 부족·재실행 조합과 공개 본편 빌드를 검증한다. 일반 로드의 다른 flavor 거절 규칙은 완화하지 않는다.

### 최근 반영과 증거의 한계

- 대화 기록: 1장·검은 거울·후반 진행의 공통 대화창에서 실제 표시된 문장을 슬롯에 저장하고 메뉴에서 재열람한다. 엔딩 완료 후에는 읽기 전용 열람을 제공한다. 프롤로그·선택지·별도 본문 패널, 원문 ID 기반 재번역과 대화 커서 재개는 남아 있다. [대화 기록 적용 범위와 검증](dialogue_history_integration_status.md)을 따른다.
- 추가 현지화: 프롤로그 P3~P6의 여러 상호작용과 1장 자기 표식·목표 안내·침실 버튼·시간표 문서·에드가 방문 대사를 한·영 카탈로그에 연결했다. 1장 전체 본문과 후반 영어 지원이 끝난 것은 아니다. 아래의 초기 현지화 메모는 당시 작업 범위다.

- 가져오기: 원본 검증, 새 슬롯 복제, 확인·취소 UI, 실제 bootstrap의 D6 화면 진입·타이틀 복귀를 구현했다. [가져오기 검증](demo_import_ui_validation.md)을 따른다. 제품 슬롯 검색은 테스트 후보 주입으로 대체한 부분이 있어 전체 실사용 QA 완료가 아니다.
- 개발 실행: [본편 개발 실행](full_development_launch.md)의 인자는 프로젝트 파일을 변경하지 않는다. 일반 내보내기 빌드는 이를 사용하지 않는다.
- P4: 개발용 찻잔 그림과 대사에 맞춘 회전·복귀를 추가했다. 정지·움직임 감소 설정을 지원한다. 귀 점멸·주전자 맥박·응답음의 전용 최종 연출은 여전히 남아 있다.
- F0-C: 기준 표식 설명과 한국어 조사점 이름을 표시한다. 정답 변환·추론 조건은 유지한다.
- 현지화: 타이틀·가져오기 외에 P1 도입·침실 조사·퇴실, 아침 일과와 목표, P2 도구·영역 상태·청소 피드백·마라 1 대사, 인벤토리 안내를 한·영 카탈로그에 연결했다. 기존 프롤로그 수첩 기록은 저장 원문을 유지하고 열람 시 번역한다. P3 이후와 공통 UI의 전체 현지화 완료를 뜻하지 않는다. [세부 범위와 검증 한계](prologue_localization_accessibility_status.md)를 따른다.
- 읽기 접근성: 대사·수첩·조사 모달에 더해 P2 확대 창과 인벤토리 슬롯에 글자 배율을 적용했다. 확대 창은 큰 글자용 배치를 사용하며, 인벤토리 목록은 키보드 초점을 따라 스크롤한다. 영어 200% P2 개발 화면을 확인했으나 전체 해상도·DPI·입력 조합은 미검증이다.
- 최근 `START_SCREEN_SMOKE`, `FOUNDATION_SMOKE`, `PROLOGUE_SCENE_SMOKE`, `BASEMENT_SESSION_SMOKE` 통과는 각 테스트 범위의 증거다. 최종 리소스, 전체 접근성, 목표 플레이타임은 미입증이다.

최근 타이틀·챕터 smoke 통과는 개별 회귀 근거다. 제품 정의 전체, 플레이타임, 출시 QA 통과를 뜻하지 않는다. 크레딧 제작진 명단은 사용자 지시로 미정 유지한다. `FULL_00_CONTENT_COMPLETE`와 정식 1.0 완료는 아직 입증되지 않았다.

프롤로그부터 4장, 현실·잔류 엔딩까지가 목표다. 이 문서는 완료 범위를 축소하지 않는다. 최종 기준은 [완성본 정의](full_game_definition.md), [마일스톤](milestones.md), [제품 계약](product_contract.md)이다. 1장 연결은 전편 완료가 아니다.

## 1장 실행 계약

- `PrologueController.campaign_requested`를 통해 첫 수면 뒤 `ChapterOneController`로 연결한다. 저장 불러오기도 `PROLOGUE_COMPLETE`와 진행 상태를 기준으로 연결한다.
- 데이터 리소스 `puzzle_clock_network.tres`는 판정 규칙만 제공하며 변경하지 않는다. 런타임 진행은 `ChapterOneSession`이 복사본을 만들고 `StateWriter`와 `SaveManager`로 저장한다. 저장 실패 시 이전 상태로 복구한다.
- 자동 저장 지점 `SAVE_CAMPAIGN_PROGRESS`는 임의 위치 부활 지점이 아니다. 프로그램 재실행은 마지막 저장 위치를 복구하되, 게임 속 잠은 항상 정상 리셋 절차를 거쳐 같은 침실로 돌아온다.
- 물리 탁본은 `loop_state.inventory`와 `CHAPTER_ONE.rubbed`에 대응한다. 관찰·검증 결과는 영구 정보로 남는다. BSHORT는 순간이동 설정이 아니라 기록한 동선을 축약해 새 탁본을 준비한 결과다.
- 서재 연결문은 J1 이후 내실에서 걸쇠를 조사해야 사용할 수 있다. 잠입 중 발견은 강제 실패나 아이템 회수를 일으키지 않는다.
- 방 이동은 중앙홀과 연결문을 따른다. 최종 공간 기획의 모든 복도·확대 화면을 구현했다는 뜻은 아니다.
- 최근 피드백은 루프 로컬에 저장해 재실행 시 다시 읽을 수 있다. 문장 단위 커서 복구·전체 대화 기록과 동일하지 않으며, 전편 제품 기준으로 별도 보완한다.
- 기존 배경 아틀라스를 재사용한다. 새로운 방의 전용 아트가 완성된 것으로 표시하지 않는다.

## 검증

`scripts/run_godot_foundation.ps1`의 `--chapter-one-smoke` 검사 범위:

1. A1 표식은 작성일에 A2로 판정되지 않는다.
2. 수면은 물리 상태·탁본을 지우고 기록·사용인 기억을 유지한다.
3. 내실 조기 진입·방 사이 임의 이동을 차단한다.
4. 에드가 숨기·대면 모두 일지 조사로 합류하며 반복 조사로 경계를 누적하지 않는다.
5. J1, B3-A, B3-B, BF, BSHORT, B4, B5, J2를 실제 세션 행동으로 진행한다.
6. 시계 역할 4^4 조합과 위상 4개, 총 1,024개 조합에서 정답이 하나다.
7. 실제 시계망 실패는 불러오기로 해제되지 않고 잠을 요구한다.
8. 저장 실패의 상태 롤백, J2 중복 복원 방지, 불러오기·타이틀 복귀를 확인한다.
9. 실제 역할 선택 UI 입력과 재구성 후 키보드 포커스, 수첩 연속 열기를 확인한다.

격리된 프로젝트 복사본에서 Godot import, 기반 시스템, 프롤로그와 1장 검증을 실행한다. `--capture-chapter-one`은 렌더러가 있을 때 시계 역할 화면을 `user://chapter_one_roles.png`로 저장한다. 자동 검사만으로 마우스·키보드 전편 완주, 최종 퍼즐 난이도 또는 플레이타임을 입증하지 않는다.

## 검은 거울 실행 계약

- J2 복원일을 저장하고 다음 수면 이후 C0로 진행한다. 과거 저장에 복원일이 없으면 처음 재개한 날을 기준으로 한 번 잠든다.
- 거울 회랑은 대응접실 남쪽, 청소도구실·주방은 사용인 공용실 쪽 연결문, 색분해실 외부는 기록 회랑에서 접근한다. 색분해실 내부는 아직 열리지 않는다.
- 병에 1단위씩 계량한다. 안전 라벨에 어긋나는 마른 병 투입·미확산 원액은 실행 전에 거부한다. 잘못된 비율은 폐기·재조합, 거품은 기다리기로 복구한다.

- 이는 저장 가져오기 기능이 아니다. 제품 계약의 원본 읽기 전용 검증·슬롯 선택·승인·변환·재로드 UI는 별도 구현 대상이다. 테스트의 상태 주입은 본편 수면 검증용이며 사용자 저장 자동 변환으로 사용하지 않는다.
- full에서 D5 확인 이후 D6으로 진행하고, 같은 침실의 첫 수면이 BROKEN_RESET을 실행한다. 이후 초기화 저장은 `SAVE_BROKEN_RESET_COMPLETE`를 사용해 E1 재개 지점을 유지한다. 이전처럼 `SAVE_FRACTURE_CONFIRMED`로 되돌려 기록하지 않는다.
- 추가 자동 검사는 데모 원본 보존, 별도 본편 슬롯, 헤더 거부, D6→첫 파열 수면→E1 저장·재개, 이후 휴식에서 날짜와 물리 수리 상태를 유지하는 계약을 검증한다. E1 이후 본편 UI·관계 이벤트 완료를 의미하지 않는다.

지하 구간의 `puzzle_basement.tres`는 입력 스냅샷을 변경하지 않고 새 상태·결과를 반환하는 판정 리소스다. `BasementSession`은 D1의 `hard_failure=true`를 DF 기록과 저장·수면 경로에 연결한다. D4의 `filter_off=true`는 위장 필터를 disabled로 변경하며 `SAVE_D4_COMPLETE`로 저장한다. D5 확인 후 demo는 `SAVE_D5_COMPLETE`에서 종료한다. full의 D6/첫 BROKEN_RESET 저장 분기는 검증했으나 본편 배포 설정과 E1 이후 콘텐츠는 미완료이므로 전편 플레이 가능 판정은 아니다.

`--script res://scripts/tests/basement_puzzle_smoke.gd`는 중첩 유일해, 스냅샷 불변성, 축 잠금·검증 깊이 유지, 첫 역방향 경고와 이후 강행, 올바른 방향 전환, 64개 링 조작 횟수 조합, 긴 동치 해법, 고정 해제 제한, XII만으로 필터가 해제되지 않는 조건과 보조 레버 확인을 검사한다. `--basement-session-smoke`는 J3 이후 수면, 방 접근 조건, 실패 저장·불러오기, DSHORT의 깊이만 재준비하고 밀기는 직접 수행하는 계약, D2·D4·D5 저장 경계와 데모 종료를 검사한다. UI 축 조작·확인창의 수첩 기본 포커스도 검사한다. 모든 화면의 최종 아트와 수동 완주 검증을 대체하지 않는다.

1. 구현된 C0~J3를 EP02 전체 원문·오브젝트·힌트와 계속 대조한다. 기초 조작 화면과 최종 연출의 차이를 남은 작업으로 관리한다.
2. full 빌드 설정과 저장 호환을 마련하고 D6의 BROKEN_RESET부터 E1로 연결·검증한다. D0/D4 도면과 기계 시각화, D5 파열 연출을 보완한다.
3. E5·선택 후속·E6의 최종 원문·시각·음향 표현을 보완한다. 관계 상태가 필수 진행을 차단하지 않게 한다.
4. F0-A 회로·F0-B 표본 이후 F0-C~E와 현재 의사 확인의 모든 허용 응답, J5/F2/F3를 구현한다.
5. 두 엔딩과 짧은 후속 스토리, 엔딩 저장·재개를 구현한다.
6. EP00~EP09 전체 이벤트·대사 누락, 제품 계약, 최종 에셋과 현지화·접근성·전편 QA를 감사한다. `FULL_00_CONTENT_COMPLETE`와 1.0을 혼동하지 않는다.

### J4 조사 종료와 네 번째 일지

아래 J4 절의 개발 경계는 후속 E5 구현으로 확장되었다. 최신 경계는 이 문서 마지막 E5 절을 따른다.

본편 관계 허브에서 남은 사건·예상 소요 시간·기록 수·에드가 최소 절차 안내를 확인하고 조사 종료를 선택할 수 있다. 기본 포커스는 계속 조사이며 확정 버튼에는 0.5초 입력 유예가 있다. 취소는 상태를 바꾸지 않는다. 확정하면 미완료 사건을 `superseded`로 보관하고 관계 보상을 지급하지 않는다.

약속→전환→역할 고정→주인공 기동의 네 페이지를 배열한 뒤 모순 문장을 읽어 J4를 복원한다. 오답은 수면 없이 다시 배열한다. 기록 0~1개는 기본, 2~4개는 확장, 기록과 관계 사건 모두 5개 완료한 경우에만 완전 본문이다. 기본 본문만으로 연구원 인격·미완수 약속·주인공 권한을 이해할 수 있다. 에드가 사건 미완료 시 대시계 기계실의 최소 접근 핀 절차를 거치며 기록·관계·완료 수는 변하지 않는다.

`--basement-session-smoke`에서 32가지 완료 조합, 취소 불변성, 배열 오답·재시도, 부분 저장·완료 저장 재개, 세 본문 단계, 최소 절차의 무보상·중복 실행 방지, 실제 확인창 입력 유예를 검사했다. J4 저장은 `SAVE_J4_COMPLETE`를 사용한다. 현재 다음 화면은 명시적인 `E5_PENDING` 개발 경계이며 E5와 E6가 구현되었다는 뜻이 아니다. 최종 페이지 아트·대사 ID·단계별 힌트·시각 QA는 남아 있다. 앞선 에드가 항목의 E3_4M 구현 예정 설명은 이 절의 구현 상태로 대체한다.

### E5 마지막 저녁 초기 구현

아래 E5 절의 개발 경계는 후속 E6 구현으로 확장되었다. 최신 상태는 문서 마지막 절을 따른다.

J4와 에드가 권한 확인 뒤 중앙홀에서 식당으로 진입한다. 목재·생명 유지 프레임 식탁과 좌석 배치를 조사하고 주인공 자리에서 대화를 시작한다. 완료 수 0~5는 LOW·LOW·MID·MID·HIGH·ALL에 대응한다. 에드가→마라 1→루카→이리스→마라 2 순서로 완료 인물의 개인 문장 및 선택 결과를 삽입하며, 미완료 인물은 기능 보고로 제한한다. ALL에만 공동 이름 확인이 붙는다. 이리스의 공개 고백은 발생하지 않는다.

세 공동 질문 중 하나를 고르며 최종 선택·잠정 의향·관계 수치를 쓰지 않는다. 준비 확인의 기본 포커스는 연기이며, 연기하면 식당과 중앙홀을 조사할 수 있다. 확정 시 `e5_locked_in`과 E5 완료 등급·완료 인물 스냅숏을 함께 저장하며 `SAVE_E5_COMPLETE`를 사용한다.

자동 검사는 32가지 완료 조합, 세 질문의 단일 선택, 대화 전 완료 차단, 연기·자유 조사, 부분 및 완료 저장 재개, 관계 보상 불변성, 실제 착석·질문·확인 버튼을 다룬다. 화면 캡처는 `user://e5_confirmation.png`다. 현재는 기존 배경·버튼·감각 서술을 사용하는 초기 구현이다. 전용 좌석 아트, 채널·음향 결산, 전체 대사 ID와 최종 페이싱은 남아 있다. 다음 화면은 `E6_PENDING`이며 MARA2_FU·EDGAR_S3·E6는 아직 연결되지 않았다. 이를 전체 챕터나 엔딩 완성으로 간주하지 않는다.

### E5 후속과 E6 코어 접근

아래 E6 절의 F0_PENDING 경계는 마지막 절의 F0-A 구현으로 확장되었다.

E5 이후 마라 2 사건을 완료했다면 북쪽 기록 회랑의 이름 후속을 먼저 안내한다. 수첩 기록·이름 호명은 bond +1, 장난은 변화 없으며 수첩 기록에만 이름 보존 플래그와 항목을 기록한다. 마라 2의 통합·분리 결과 및 이름 주의 반응이 대사에 반영된다. 보안 기계실의 에드가 점검은 부탁만 bond +1이며 명령·기다림도 문을 연다. 완료·최소 권한, bond·alert에 따라 추가 문장이 달라진다. 각 반응은 완료 이력과 짧은 반응 목록에 한 번만 기록한다.

두 반응 모두 선택 사항이다. 문만 열고 다른 후속 장소를 조사할 수 있으며, 별도 진입 확인의 기본 포커스는 `아직 조사한다`다. F0 진입 확정에만 미확인 후속 반응을 superseded로 보관하고 `H0_CORE_PATH`로 이동한다. E3 완료, E5 결산 스냅숏은 변하지 않는다. F0 진입 이후 되돌아갈 수 없다. E6 자유 조사는 `SAVE_E5_COMPLETE`, F0 최초 진입은 기존 `SAVE_CAMPAIGN_PROGRESS`에 실제 위치·이벤트 상태를 저장한다.

검증 범위: 32가지 완료 조합의 E5→E6→F0 진입, 후속 3종 선택과 초회 수치·중복 방지, 양쪽 건너뛰기, 확인 취소, 저장 재개와 F0 역행 거부, E5 스냅숏 보존, 실제 확인창 포커스. 캡처 파일은 `user://e6_confirmation.png`다. 식당·코어 접근로를 유효한 재개 위치 목록에 추가했다. 현재 목적지는 `F0_PENDING` 개발 경계다. F0 메타퍼즐, J5/F2/F3와 엔딩은 아직 구현되지 않았다. 후속 전용 아트·음향·이동 전환 및 전편 QA는 남아 있다.

### F0-A 네 방의 피드백 회로 초기 구현

아래 F0-A 절의 F0_B_PENDING 경계는 다음 절의 표본 분류 구현으로 확장되었다.

코어 접근로에서 네 타일을 교환하고 각 출력 화살표를 90도씩 회전한다. 외부 대기 입력은 북, 중앙 코어 요청은 서에 고정되어 있다. 고정 회랑 포트의 시계 방향 연결과 각 방의 공급·신경·기억·계절 피드백 기능을 함께 맞춘다. 정답은 북 온실→동 주방→남 침실→서 기록 내실→북 온실이며 내실은 중앙 요청을 함께 제공한다. 최종 정답 배열은 24-3과 동일하다.

약한 신호는 현재 네 연결 경로와 끊긴 출력·수신 기능을 표시하며 올바른 타일 위치를 직접 표시하지 않는다. 오답은 현재 상태를 보존하고 같은 화면에서 다시 조작한다. P1·P4·P5·일지의 방 기능 자료를 재확인할 수 있다. 색 없이 방명·실선/점선 명칭·방위 출력으로 판독한다. 선택한 타일과 출력 방향은 저장하고 재개한다. 통과 시 `f0_room_feedback_loop_solved`와 F0_A 완료 이력을 저장한다.

검증은 24개 배치×256개 출력 방향의 6,144 조합 중 유일해, 관계 0명 경로, 오답 국소 재시도, 부분·완료 저장 재개와 실제 신호 버튼을 대상으로 한다. 캡처는 `user://f0a_network.png`다. 현재 회로는 버튼·명칭 기반 초기 조작이며 고정 회랑 방향을 표시한다. 최종 포트 아트·연결선과 신호 이동 애니메이션, 힌트 단계 및 고난도 플레이테스트는 미완료다. 다음 상태는 `F0_B_PENDING`; 이를 F0 전체 25~40분 퍼즐 완성으로 간주하지 않는다.

### F0-B 시스템 신호 표본 초기 구현

F0-A 이후 네 방별 후보 두 개의 연결 목적지를 조사하고 전송한다. 유지 표본은 외부 대기 수치·생명 유지 유체·현재 생체 신호·지속 기억 인덱스이며, 표현 표본은 꽃향기·차 메뉴·역할 애니메이션·장서 목록이다. 화면 좌우 배치는 방마다 고정 교차하며 랜덤성을 넣지 않는다. 조사 결과는 목적지의 생체·인격 유지 또는 장면 표현 기능을 설명한다.

표현용 데이터는 반환되며 이미 검증한 채널은 유지된다. 세 번째 오답에 분류 기준 독백을 한 번 제공한다. 네 유지 표본 완료 시 `4 CHANNELS VERIFIED / ACCESS DENIED`와 한국어 설명을 표시하고 `f0_system_samples_verified` 및 F0_B 이력을 저장한다. 이는 권한 복원이 아니라 누락된 포트의 단서다. 부분 선택·조사·검증·오답 수는 저장 재개된다.

검증 대상은 후보 조합 16종, 조사 전 전송 거부, 순서 변경, 검증 중복 방지, 세 번째 오답 힌트, 부분·완료 저장 재개, 관계 상태 불변, 실제 조사·전송 버튼이다. 캡처는 `user://f0b_samples.png`. 표본의 실제 시각 파형·연결선·음향은 감각 설명을 사용하는 초기 단계다. 현재 경계는 `F0_C_PENDING`; F0-C~E·J5·F2/F3·엔딩과 최종 시청각·전편 QA는 남아 있다.
