## 0. 목적·범위·참조 우선순위

### 0.1 목적

본 문서는 다음 네 가지를 하나의 제작 기준으로 연결한다.

1. 다섯 사용인의 캐릭터 대표 배색과 실루엣.
2. 인격 데이터의 고정 색상 서명.
3. 포인트 앤 클릭 UI의 정보 전달과 입력 피드백.
4. Windows PC에서 색·소리·움직임을 줄여도 동일하게 진행할 수 있는 접근성.

색상은 분위기를 만드는 연출 수단이지만 필수 진행의 단독 조건이 아니다. 플레이어가 색, 소리, 글리치 중 하나 이상을 사용하지 못하거나 끈 상태에서도 동일한 `event_id`, `signature_id`, 퍼즐 결과와 엔딩에 도달해야 한다.

- 1.0 이후 게임패드·터치·콘솔 지원 여부. 이 입력들은 1.0 범위에서 명시적으로 제외한다.

## 1. 색상 시스템의 의미

색은 장식이나 호감도 게이지가 아니라 인격 데이터가 사용하는 스펙트럼 서명이다.

- 고딕 필터 내부: 의상, 머리, 귀 장식, 초상화 안료로 위장.
- C5 진단 상태: 겹친 기록 채널의 출처로 노출.
- D5 이후: 사용인 몸과 분리된 데이터 잔상으로 노출.
- F0: RESIDENT 기록의 출처 확인에만 사용.
- 엔딩: 독립 인격의 분리·공존·소실 상태 표현.

주인공은 사용인 서명 체계 밖의 SUBJECT다. 주인공 권한과 선택은 흑연, 종이 섬유, 손글씨, 연필음으로 표현한다.

### 1.1 네 종류의 색

| 계층 | 목적 | 사용 예 | 게임 판정 사용 |
| --- | --- | --- | --- |
| 아바타 대표색 | 캐릭터 인상과 실루엣 분리 | 머리카락, 꼬리, 귀, 의상 큰 색면 | 금지 |
| 데이터 서명색 | 인격 데이터 출처 식별 | 진단 칩, 잔상, 기록 채널 | `signature_id`로만 사용 |
| UI 의미색 | 포커스·경고·비활성 등 인터페이스 상태 | 버튼 윤곽, 상태 아이콘 | 상태 ID로 사용 |
| 환경 보정색 | 장면의 시간·심리·세계 상태 | 저택 채도, 현실 회갈색, 파열 대비 | 금지 |

아바타 대표색과 데이터 서명색은 같은 계열일 수 있지만 같은 토큰이 아니다. 에드가의 파란 머리카락은 캐릭터 배색이고, 진단 패널의 남색 수직선은 `navy_lock` 데이터 서명이다.

### 1.2 색 계층 충돌 방지

1. 캐릭터 대표색은 머리카락·꼬리처럼 넓은 면적에 사용할 수 있다.
2. `5~12%` 면적 제한은 고딕 세계의 장치·오브젝트에서 **시스템 판독이 가능한 데이터 서명 표식**에만 적용한다.
3. 캐릭터 의상 전체 면적이나 머리카락에는 `5~12%` 제한을 적용하지 않는다.
4. UI 의미색은 사용인 소유권을 나타내지 않는다. 포커스 색이 보라색이어도 마라 2 이벤트라는 뜻이 아니다.
5. 환경 보정으로 대표색이 변해 보여도 문양·라벨·선 패턴은 유지한다.
6. 서로 다른 사용인의 색이 겹칠 때 새 혼합색을 의미 토큰으로 만들지 않는다.

### 1.3 빨강 사용 규칙

샘플 시트의 붉은 눈과 마라 1의 보조색은 캐릭터 배색이다. 시스템 오류·위험과 동일한 의미로 읽히지 않도록 다음을 지킨다.

| 구분 | 허용 표현 | 필수 병행 | 금지 |
| --- | --- | --- | --- |
| 마라 1 보조색 | 의상 안감, 공구 손잡이, 머리 장식 | 대각선 닦임 문양 | 경고 삼각형과 같은 배치 |
| 캐릭터 눈 색 | 표정·종족 디자인 | 인물명·실루엣 | 오류 상태 점멸 |
| 시스템 주의 | 중립 윤곽+주의 아이콘 | `주의`·원인 텍스트 | 빨강만 표시 |
| 시스템 오류 | 끊긴 프레임+오류 코드 | `오류`·복구 행동 | 캐릭터 눈과 동기 점멸 |

상태 의미는 `warning`, `error`, `blocked` 같은 내부 상태값으로 판정하며 화면 색을 읽어 판정하지 않는다.

## 3. 정보 계층

모든 필수 색 단서는 최소 세 층 중 두 층 이상으로 제공한다.

1. 시각 1: 색.
2. 시각 2: 문양·선 패턴·아이콘.
3. 비시각: 음향 리듬·텍스트 라벨·진동 방향 자막.

퍼즐 판정 로직은 `hue_id`를 정답값으로 사용하지 않고 `owner_id` 또는 `signature_id`를 사용한다.

```text
나쁜 판정: selected_color == purple
권장 판정: selected_signature == MARA2_ARCHIVE
```

## 4. 학습 순서

| 단계 | 이벤트 | 학습 |
| --- | --- | --- |
| CLR-00 | P3B | 이름·색·문양·음향의 1:1 대응 |
| CLR-01 | A2~B | 물리 색은 리셋되지만 수첩의 소유자 표지는 유지 |
| CLR-02 | C5 | 다섯 인격 채널이 한 장치에 겹칠 수 있음 |
| CLR-03 | D5 | 색은 장식이 아니라 몸 밖 데이터 잔상 |
| CLR-04 | E3_5 | 겹친 출처 분리, 체크섬 비교 |
| CLR-05 | F0-D | 색은 RESIDENT 내부 출처만 식별 |
| CLR-06 | E5·F2·엔딩 | 독립된 인격의 공존 상태 결산 |

## 5. 화면 표시 규칙

### 고딕 필터 상태

- 화면 전체 채도를 낮추되 서명색만 과포화하지 않는다.
- 시스템 판독용 서명은 오브젝트·장치 면적의 5~12%에 해당하는 장식으로 제한한다.
- 캐릭터의 머리카락·귀·꼬리·의상에 쓰는 아바타 대표색은 위 면적 제한에서 제외한다.
- 마라 2의 보라는 초상화 액자 안료와 목깃 액자핀에 사용한다.
- 루카의 검정은 배경과 분리되지 않을 수 있으므로 연두 보조점과 이중 맥박선을 항상 병행한다.
- 이리스의 흰색은 배경과 구분하도록 연노랑 윤곽과 얇은 회색 외곽선을 추가한다.

### 파열 상태

- 색 잔상은 몸에서 2~8픽셀 또는 1~3프레임 어긋나게 표시한다.
- 관계가 높아져도 색 자체가 밝아지거나 “좋은 색”으로 변하지 않는다.
- `bond`는 잔상의 안정도와 말의 동기화에만 영향한다.
- `alert`는 선의 닫힘, 중첩, 간헐적 차단으로 표현하되 접근성 단서를 가리지 않는다.

### 코어 상태

- 사용인 색은 기록 출처 칩과 코어 외곽선에 제한한다.
- 선택 버튼, 정답 슬롯, 주인공 권한에는 사용인 색을 사용하지 않는다.
- `CREATOR`, `CUSTODIAN`, `RESIDENT`, `SYSTEM`, `SUBJECT`는 형태와 텍스트로 구분한다.

## 6. UI 컴포넌트

### 서명 칩

표시 요소:

```text
[문양 아이콘] 소유자 이름
선 패턴 미리보기
음향 재생 버튼
상태: 미확인 / 확인 / 손상 / 복원
```

- 색상은 배경이 아니라 아이콘 내부 보조로 사용한다.
- 음향 재생에는 파형 애니메이션과 리듬 자막을 제공한다.
- 미확인 상태도 `???`만 표시하지 않고 “소유자 미확인 기록”이라고 기능을 명시한다.

### 수첩

- 필수 정보는 색 없는 흑연 본문으로 기록한다.
- 사용인 출처는 본문 옆 문양 스탬프로 표시한다.
- 색 필터를 꺼도 스탬프 이름과 선 패턴이 유지된다.
- 리셋 후 새 정보에는 “이번 루프”, 유지 정보에는 “영구 기록” 태그를 붙인다.

### 지도

- 잠긴 문: 자물쇠 형태.
- 시간 조건: 시계 형태.
- 영구 숏컷: 접힌 통로 형태.
- 사용인 이벤트: 고유 문양.
- 색상만으로 완료 여부를 표시하지 않고 `미확인/진행/완료` 텍스트를 병기한다.

### 퍼즐 필터

필터 탭:

| 탭 | 기능 |
| --- | --- |
| 색 | 색 채널 분리 |
| 문양 | 색 없이 고유 문양 표시 |
| 선 | 선 패턴만 고대비 표시 |
| 음향 | 선택 채널 리듬 재생과 파형 |
| 라벨 | 소유자·기능 텍스트 표시 |

E3_5는 어느 한 탭만 강제하지 않고 두 개 이상의 탭을 조합해 해결할 수 있다.

## 7. 접근성 설정

### 색각 보조

| 설정 | 동작 |
| --- | --- |
| 원본 팔레트 | 기본 색+문양 |
| 고대비 팔레트 | 명도차 확대, 배경 채도 감소 |
| 색 제거 | 모든 서명을 흑백 문양·선·라벨로 표시 |
| 사용자 지정 | 각 서명색을 개별 교체 |

색 제거 모드 검증:

- P3B 이름표 정리 가능.
- C5 다섯 채널 식별 가능.
- E3_5 체크섬 분리 가능.
- F0-D 출처 분류 가능.
- 엔딩 관계 상태를 문양 안정도와 자막으로 이해 가능.

### 청각 보조

- 고유 음향마다 리듬 자막을 표시한다.
  - 에드가: `[낮은 한 음, 긴 잔향]`
  - 마라 1: `[대각선으로 긁는 마른 솔]`
  - 루카: `[두 번 맥박, 한 번 응답]`
  - 이리스: `[얇은 유리음 뒤 바람]`
  - 마라 2: `[빠른 세 음]`
- 방향성 단서는 화면 가장자리 방향 표시와 텍스트를 병행한다.
- 음량 0에서도 퍼즐 진행 가능해야 한다.

### 광과민·멀미 보조

- D5 점멸을 점진 마스크 박리로 대체.
- 색 잔상 프레임 지연을 정적 이중 윤곽으로 대체.
- 글리치 화면 흔들림 0~100% 조절.
- 카메라 강제 이동 시 사전 아이콘 표시.
- 빠른 색 반전을 사용하지 않는다.

### 인지 보조

- 수첩에 “관찰/추론/검증”을 구분한다.
- 힌트는 정답 전체가 아니라 현재 변환 규칙부터 공개한다.
- 시간표·루프 정보는 실제 경과 시간보다 사건 완료 조건을 우선 표기한다.
- 실패 후 검증된 하위 단계에 잠금 아이콘을 붙인다.

### 문자·읽기 보조

- 한국어 본문은 한 줄 34자 내외를 권장하고 대화창은 기본 3줄, 최대 4줄을 넘기지 않는다.
- 본문, 화자명, 선택지, 상태 라벨은 각각 별도 텍스트 노드로 제공한다.
- 글자 확대 시 고정 높이 상자에 문장을 잘라 넣지 않고 세로 확장 또는 스크롤을 허용한다.
- 이탤릭, 장식 필기체, 전각 영문은 필수 정보 본문에 사용하지 않는다.
- 숫자 `0`, 영문 `O`, 숫자 `1`, 영문 `I`가 구분되는 UI 글꼴을 사용한다.
- 화면 낭독 순서는 `영역명 → 대상명 → 역할 → 상태 → 설명 → 가능한 행동`이다.
- 툴팁에만 존재하는 필수 정보를 두지 않는다.

### 운동·입력 보조

- 필수 퍼즐에 빠른 더블 클릭, 연속 클릭, 드래그 속도, 정확한 마우스 궤적을 요구하지 않는다.
- 드래그 조작은 `선택 → 목적지 선택` 방식으로 대체할 수 있다.
- 길게 누르기는 `토글` 또는 `한 번 누르기`로 바꿀 수 있다.
- 키 반복 속도와 관계없이 방향키 1회 입력은 포커스 1칸만 이동한다.
- 마우스가 움직였다는 이유로 키보드 포커스를 빼앗지 않는다.
- 키보드 전용 조작으로 메인 흐름, 관계 이벤트, 두 엔딩을 모두 완료할 수 있어야 한다.

### 화면 읽기 방식

Windows 화면 읽기 연동 방식은 구현 단계에서 확정하되 모든 UI는 다음 필드를 제공해야 한다.

```yaml
accessible_ui:
  accessible_name: "서재 안쪽문"
  role: button
  state: locked
  description: "J1 일지 복원 뒤 열 수 있습니다."
  action_label: "잠금 이유 확인"
  live_region: polite
```

- `accessible_name`에 색 이름만 쓰지 않는다.
- 상태 변화는 동일 문장을 반복 낭독하지 않고 바뀐 부분만 알린다.
- 주변 환경 자막과 메뉴 낭독이 겹치면 메뉴를 우선하고 환경 자막은 대기열에 둔다.
- 화면 낭독 미지원 빌드에서도 같은 텍스트를 시각 UI와 감각 자막으로 확인할 수 있어야 한다.

## 10. 관계와 색의 분리

- LOW를 탁한 색, HIGH를 밝은 색으로 표현하지 않는다.
- 완료는 색의 “정상화”가 아니라 선과 목소리의 동기화로 표현한다.
- 미완료 사용인도 인격으로서 고유 색을 잃지 않는다.
- 전원 완료 장면은 다섯 색을 섞어 하나로 만들지 않는다.
- 잔류 엔딩에서도 사용인 색은 주인공의 흑연 표시를 침범하지 않는다.

### 11.2 D5 안전 규칙

- 성공 표기 `SYNC COMPLETE`를 파열보다 먼저 텍스트로 보여 준다.
- 붉은 실패 X, 체력 손실, 재시도 버튼을 사용하지 않는다.
- 초회 HOLD 구간에도 일시정지·설정·대사 로그를 허용한다.
- 화면 흔들림은 0.4초 이하 한 번이며 멀미 감소에서는 제거한다.
- 광과민 보호에서는 점멸을 점진적인 텍스처 박리와 진단 라벨 변화로 대체한다.

### 11.3 E5·F2 결산 표현

| 등급 | 색상 사용 | 비색상 필수 표현 |
| --- | --- | --- |
| LOW | 채널이 각자 몸 주변에 고립 | 사용인은 서 있고 기능 라벨 중심 |

- LOW를 탁하거나 나쁜 색으로, ALL을 밝거나 선한 색으로 표현하지 않는다.

- F2 필수 사실 태그는 `PROMISE`, `CONTINUOUS CONVERSION`, `RELEASE UNAVAILABLE NOW`, `FORCED ACTIVATION`, `OUTSIDE UNKNOWN`, `SUBJECT AUTHORITY` 텍스트로 제공한다.
- 질문을 생략하면 `F2_MANDATORY_RECAP`이 누락 태그만 읽는다.

## 12. 엔딩 상호작용 접근성

### 12.1 ED_ALL_CEREMONY 필기

### 12.2 현실 연결 해제·호흡

- 첫 호흡은 자동 성공한다.
- 버튼 연타, 정확한 리듬, 마이크 입력, 호흡 유지 QTE를 사용하지 않는다.
- 기본 흔들림은 0.2초 이하이며 멀미 감소에서 제거한다.
- 검은 화면은 최대 4초이며 화면 읽기에는 `가상 연결 해제 중` 상태를 즉시 알린다.
- 소리 없이도 `압력 → 금속 맛 → 눈꺼풀 무게 → 첫 호흡`의 감각 순서를 텍스트로 제공한다.
- 숨소리 과민 설정에서는 실제 호흡음을 낮추고 파형·짧은 자막으로 대체한다.

### 12.3 현실 수첩

| 기능 | 규격 |
| --- | --- |
| 필수 열람 | 표지와 `첫 72시간` 요약만 |
| 긴 원문 | 별도 확대 패널, 필수 진행과 분리 |
| 화면 읽기 | 작성자→제목→요약→원문→뒤로 순서 |
| 색 제거 | 작성자 이름·기능 아이콘·문양 탭 병행 |
| 저시력 | 본문 확대 200%, 줄 간격 1.5, 가로 스크롤 금지 |
| 인지 보조 | `지금`, `첫날`, `나중` 세 시간 묶음 요약 |
| 동적 인계 | `SUBJECT_HANDOFF_PAGE`에 `프린터 출력물` 라벨 상시 표시 |

시뮬레이션 수첩과 현실 수첩은 서로 다른 아이콘·object_id·헤더를 사용한다. 표지 촉감의 유사성만으로 같은 물건처럼 안내하지 않는다.

### 12.4 현실 공간

- 신체 확인은 손·호흡 표시기·고정 벨트 중 고유 2종으로 완료한다.
- 포커스 순서는 캡슐 탈출에 필요한 물체를 따르되 특정 2종을 강제하지 않는다.
- 출구 패널의 전력·외기·수동 개폐는 색 대신 상태명과 아이콘으로 구분한다.
- 멀리 보이는 신호는 자동 확대·진동 유도·보상 아이콘을 사용하지 않는다.
- 선택 조사를 생략해도 마지막 화면과 메타 커밋에 도달한다.

### 12.5 S5 외형 표시

| 모드 | 기본 표현 | 접근성 보정 |
| --- | --- | --- |
| `layered` | 고딕 외피와 시설 골격 동시 표시 | 윤곽 복잡도·투명도 슬라이더 |
| `contextual` | 평소 고딕, 조사 시 시설 골격 | 전환 페이드 제거·즉시 라벨 |

- 두 모드는 언제든 바꿀 수 있으며 엔딩·관계·대사 결과가 같다.
- `contextual`에서도 `FILTER: DISPLAY ONLY`, `MODEL`, 실제 센서값 라벨을 숨기지 않는다.
- 광과민 보호에서는 레이어 전환에 점멸·스캔라인을 사용하지 않는다.
- 인지 보조에서는 `고딕 보기`, `구조 함께 보기`라는 보조 표시명을 병기한다.
- S5는 기존 중앙홀·식당에 적용되는 `world_phase`이며 새 공간처럼 길 찾기를 다시 학습시키지 않는다.

## 14. 공통 오브젝트 감각·핫스폿 접근성

### 14.1 감각 정보 우선순위

같은 순간 여러 반응이 겹치면 아래 순서로 한 채널씩 정리한다.

| 순위 | 정보 | 시각 | 음향·자막 |
| --- | --- | --- | --- |
| 1 | 안전·시스템 전환 | 확인창·명시적 상태명 | 단일 경고음·전체 자막 |
| 2 | 활성 퍼즐 입력·오답 | 조작 대상 윤곽·단계 번호 | 입력음·오답 원인 자막 |
| 3 | 공간 잠금·이동 | 문양·방향 화살표·잠금 이유 | 잠금음·목적지명 |
| 4 | 영구 정보·실패 정보 | 수첩 아이콘·정보 등급 | 기록음·핵심 문장 |
| 5 | 사용인 관계 overlay | owner 문양·부위 라벨 | 서명음·화자명 |
| 6 | 세계 상태 감각 | 표면·온도·압력 묘사 | 환경음·감각 자막 |
| 7 | 반복·장식 반응 | 최소 포커스 | 축약 문구 |

- 높은 순위가 낮은 순위의 상태 쓰기를 취소하지는 않는다. 낮은 순위 표현만 현재 문장 뒤로 미룬다.
- 서로 다른 owner 색이 겹치면 색 혼합으로 의미를 만들지 않고 문양 칩을 나란히 둔다.
- 중요 정보는 색, 음향, 글리치 중 어느 하나에만 담지 않는다.

### 14.2 오브젝트 포커스 규격

| 항목 | 기본 | 접근성 설정 |
| --- | --- | --- |
| 최소 클릭 영역 | 44×44 논리 px | 큰 타깃 56×56 논리 px |
| 키보드 포커스 | 화면 동선 순서 | 역할 우선 순회 선택 가능 |
| 포커스 표시 | 2px 윤곽+명칭 | 4px 고대비+문양+역할명 |
| 겹친 대상 | 가장 높은 역할 1개 | 대상 목록 팝업 제공 |
| 첫 조사 | 작은 점 표식 | `처음 조사` 텍스트 병행 |
| 반복 조사 | 표식 없음 | `이미 확인` 텍스트 선택 표시 |

`SYSTEM_GATE`, `MAIN_PUZZLE`, `NAVIGATION_LOCK`, `ENDING_REQUIRED`는 역할 아이콘과 텍스트를 함께 표시한다. 아이콘 모양만으로 기능을 구분하게 하지 않는다.

**논리 px는 1920×1080 기준 UI 좌표**다. Windows 배율이나 게임 UI 배율이 변해도 실제 클릭 판정이 캐릭터 스프라이트 안쪽으로 줄어들지 않게 별도 `hit_shape`를 사용한다.

### 14.4 의도하는 감각 연출

- S0는 정갈한 표면 아래 작은 온도·소리 모순을 둔다.
- S1은 RESET 뒤 같은 사물이 지나치게 정확히 돌아온 불편을 만든다.
- S2는 색상 서명과 기계적 리듬이 고딕 외형 사이로 겹쳐 보이게 한다.
- S3는 외형이 무너지는 충격보다, 익숙한 물건의 기능을 이제 이해해 버린 심리적 압박을 우선한다.
- S4는 정보 밀도를 높이되 F3의 두 가능성을 같은 밝기와 거리로 제시한다.
- S5는 편안함과 불편한 진실이 공존하도록 고딕·시설 레이어를 함께 남긴다.
- 현실은 공포 점프보다 무게, 통증, 건조함, 느린 호흡처럼 시뮬레이션에 없던 저주파 감각으로 구분한다.

### 14.5 금지 연출

- 선택을 유도하는 현실의 차가운 청색 대 잔류의 따뜻한 황색 이분법
- 높은 alert에서 화면을 강제로 가리거나 입력을 빼앗는 감시 효과
- 신체 조사 동의 전에 부위를 확대하거나 잠금 핫스폿을 노출하는 연출
- 글리치·점멸만으로 중요한 문장이나 퍼즐 정답을 숨기는 연출
- 반복 클릭마다 음량·화면 왜곡을 누적해 플레이어를 벌주는 연출
- 낮은 관계 인물의 이름·좌석·기능 채널을 소실시키는 연출
- 먼 신호, 빈 보존대, 현관 경계를 생존·탈출의 확정 답으로 연출하는 방식

### 14.6 설정 데이터

```yaml
object_accessibility_adapter:
  settings_source: user_profile.accessibility_settings
  reads:
    - large_hotspots
    - show_role_labels
    - show_first_repeat_labels
    - overlap_picker
    - color_signature_mode
    - sensory_subtitles
    - reduce_glitch
    - reduce_motion
    - repeat_audio_reduction
```

어댑터는 별도 설정 복사본을 저장하지 않는다. 설정은 반응 선택 조건이나 진행 결과를 바꾸지 않으며, `reduce_glitch=true`이면 글리치 대신 정적 분할선·타임코드·상태 라벨을 사용한다.

### 14.7 접근성 QA

- [ ] 색상 서명을 전부 회색조로 바꿔도 5인 owner와 SUBJECT를 구분한다.
- [ ] 음량 0에서 시계·맥박·3음 신호의 횟수와 간격을 자막으로 읽는다.
- [ ] 모션 감소에서 거울 지연·창문 반복·S5 레이어 전환의 의미가 유지된다.
- [ ] 200% UI와 큰 타깃에서 required 핫스폿이 화면 밖으로 밀리지 않는다.
- [ ] 겹친 핫스폿 목록에서 활성 퍼즐 입력이 첫 항목이지만 다른 조사도 닫은 뒤 접근 가능하다.
- [ ] 반복 음향 감소가 첫 영구 정보 획득음을 없애지 않는다.
- [ ] 엔딩 두 장치·두 분기 버튼의 면적·거리·명도가 동등하다.

2. 16:10·21:9 이상에서는 월드 카메라가 새 공간이나 미리 배치한 이벤트를 노출하지 않는다.
3. 남는 좌우 영역은 저택 벽지·시설 프레임 같은 비상호작용 장식 또는 검은 여백으로 처리한다.
4. 시스템 메뉴와 자막은 전체 창의 안전 영역을 사용할 수 있지만 월드 핫스폿은 16:9 게임 프레임 안에 둔다.
5. 4:3에 가까운 좁은 창에서는 좌우를 자르지 않고 16:9 프레임을 축소하며 위아래 여백을 허용한다.
6. 해상도 변경 중 선택지·퍼즐 입력·저장 커밋을 취소하지 않는다.

안전 영역:

```text
전체 창
└─ 5% 외곽 안전 여백
   └─ UI 안전 영역
      └─ 16:9 월드 상호작용 프레임
```

### 15.3 스케일과 DPI

- UI 배율은 `100 / 125 / 150 / 175 / 200%` 프리셋과 미세 조정 `90~220%`를 제공한다.
- 텍스트 배율은 UI 배율과 별도로 `100~200%`를 제공한다.
- Windows 표시 배율과 게임 UI 배율을 곱한 뒤 1회만 레이아웃 계산한다. 아이콘·글자를 이중 확대하지 않는다.
- 200% 글자에서 대화창은 세로로 확장하고 월드 필수 핫스폿을 덮으면 화면 상단·하단 중 빈 영역으로 이동한다.
- 픽셀 아트가 아닌 UI는 고해상도 벡터 또는 충분한 원본 크기로 준비한다.
- 1px 선 패턴은 확대·축소 시 사라질 수 있으므로 최소 2 논리 px를 보장한다.

### 15.5 포인터·키보드 공존

- 마우스 포인터가 멈춰 있는 대상은 `hover`, 키보드가 선택한 대상은 `focus`다.
- `hover`와 `focus`가 다를 수 있으며 마우스 미세 이동으로 포커스를 강제 이동하지 않는다.
- 입력 장치가 바뀌어도 열린 설명, 퍼즐 단계, 대화 선택지를 닫지 않는다.
- 키보드 포커스는 좌상단부터 단순 순회하지 않고 `필수 진행 → 현재 퍼즐 → 이동 → 정보 → 관계 → 장식` 순서를 기본으로 한다.
- 역할 우선 순회를 끄면 화면상의 좌→우, 상→하 순서를 사용한다.
- 커서는 기본, 조사, 이동, 잠김, 드래그 가능 상태를 형태와 텍스트 툴팁으로 구분한다.
- 커서 크기는 `100 / 125 / 150 / 200%`를 제공하며 커서 색만으로 상태를 구분하지 않는다.

### 15.6 Windows 생명 주기

- `Alt+Tab`, 창 최소화, 포커스 상실 시 게임을 자동 일시정지한다. 설정에서 배경 실행을 허용할 수 있다.
- 포커스 상실 직전의 퍼즐 입력은 확정 전 상태로 보존하며 자동 선택으로 처리하지 않는다.
- 창을 닫을 때 미저장 진행이 있으면 종료 확인창을 띄운다.
- EDC 원자 커밋 중 종료 요청이 오면 커밋 완료 또는 롤백 뒤 종료한다.
- 해상도·창 모드·UI 배율 변경은 15초 확인 타이머와 `이전 설정으로 복구`를 제공한다.

- 이리스의 흰색·성녀형 외관을 도덕적 선함의 증거로 사용하지 않는다.
- 마라 2의 흡혈마 요소와 미확정 외형 연령을 성적 연출에 사용하지 않는다.
- 관계 LOW에서 캐릭터의 대표색·종족 특징·이름을 제거하지 않는다.

### 17.3 관계값 시각화 제한

- `bond`는 색의 밝기·채도·아름다움을 바꾸지 않는다.
- `alert`는 붉은 경고광으로 바꾸지 않는다.
- `bond`가 높으면 말과 입 모양, 소품 전달, 잔상 프레임이 더 정확히 동기화된다.
- `alert`가 높으면 몸과 출입구 사이 거리, 닫힌 자세, 문장의 망설임으로 경계를 표현한다.
- `bond`와 `alert`가 모두 높으면 동기화는 정확하지만 소품을 쉽게 내려놓지 않는 양가 상태로 표현한다.
- 관계 수치 자체는 기본 UI에 숫자나 게이지로 노출하지 않는다.

| 대화창 | 화자·대사·선택 | 하단 | 빈 상단으로 이동 가능 |
| 현재 목표 | 필수·권장·선택 구분 | 좌상단 | 접기·확대 패널 |
| 수첩 알림 | 영구·이번 루프 정보 | 우상단 | 대기열 요약 |
| 대상 툴팁 | 이름·행동·잠금 이유 | 포인터 인접 | 화면 안쪽으로 자동 반전 |
| 핫스폿 목록 | 겹친 대상 선택 | 대상 근처 | 중앙 목록 모드 |
| 퍼즐 패널 | 단계·입력·힌트 | 중앙 | 세로 스크롤, 고정 확인줄 |
| 감각 자막 | 환경음·리듬·방향 | 화면 하단 위 | 대화창과 겹치면 상단 |
| 시스템 확인 | 저장·분기·종료 | 중앙 | 한 열 배치 |

### 18.2 상호작용 상태

| 상태 | 윤곽·형태 | 텍스트 | 음향 | 판정 |
| --- | --- | --- | --- | --- |
| `available` | 얇은 역할 윤곽 | 행동 동사 | 없음 | 입력 가능 |
| `hover` | 윤곽 1단 확대 | 대상명+행동 | 짧은 선택음 선택 | 입력 가능 |
| `focus` | 이중 윤곽+포커스 표식 | 역할+단축키 | 포커스 이동음 선택 | 입력 가능 |
| `pressed` | 80ms 안쪽 수축 | 행동 진행 | 단일 확인음 | 입력 1회 소비 |
| `blocked` | 끊긴 윤곽+잠금 | 이유+해제 단서 | 낮은 닫힘음 | 상태 쓰기 금지 |
| `disabled` | 윤곽 없음, 설명 가능 | 현재 사용 불가 | 없음 | 순회 제외 가능 |
| `completed` | 체크 문양 | 완료·반복 조사 | 완료음 최초 1회 | 반복 반응 |
| `new_info` | 수첩 모서리 표식 | 새 영구/루프 정보 | 기록음 | 정보 큐 기록 |
| `error` | 프레임 단절+오류 아이콘 | 원인+복구 행동 | 오류 리듬 | 정답값 변화 없음 |

색각 모드와 관계없이 위 상태의 형태·텍스트가 유지된다. `pressed` 애니메이션을 끈 경우 확인 아이콘을 300ms 정적으로 표시한다.

### 18.3 대화 UI

- 화자명은 인물명, 고유 문양, 기능 라벨 순으로 표시한다.
- 인격 기록과 현재 아바타 음성이 겹치면 `현재: 에드가`, `기록: 운영 연구원`처럼 출처를 분리한다.
- 말줄임표와 `!`는 캐릭터 말투로 보존하되 화면 낭독이 구두점을 과도하게 읽지 않도록 낭독용 문자열을 별도로 둘 수 있다.
- 자동 진행 속도는 글자 수가 아니라 문장 단위 최소 표시 시간으로 계산한다.
- 대사 로그에는 화자, 위치, 사건, 선택 결과를 기록하고 색상·표정만으로 전달한 필수 의미를 한 줄로 보완한다.
- 선택지는 한 번에 최대 5개를 권장한다. 초과하면 목록 스크롤과 현재 위치를 표시한다.
- 관계 선택지에 하트·호감 상승 예고를 표시하지 않는다.

### 18.4 퍼즐 UI

1. 상단: 현재 퍼즐명과 목적.
2. 좌측: 확보한 영구 정보.
3. 중앙: 현재 입력 장치.
4. 우측: 변환 규칙·검증 상태.
5. 하단: 되돌리기, 초기 상태 보기, 힌트, 나가기.

- 되돌리기가 불가능한 물리 변형은 실행 전에 `이 루프에서는 되돌릴 수 없습니다`를 표시한다.
- 위 확인은 실패 경고가 아니라 리셋 기믹의 규칙 안내다.
- 실패 뒤에는 무엇이 초기화되고 무엇이 유지되는지 같은 화면에서 알려 준다.
- 이미 검증한 하위 단계는 숏컷 상태로 접되 플레이어가 펼쳐 다시 볼 수 있다.
- 색 필터 탭을 바꿔도 선택한 슬롯과 입력 순서는 유지한다.

### 18.5 엔딩 선택 UI

- F3 첫 포커스는 중앙 SUBJECT 수첩대다.
- 두 장치는 같은 크기·거리·정보량·확인 횟수를 사용한다.
- 마우스를 어느 장치 위에 두고 F3에 진입했더라도 자동 선택하지 않는다.
- 현실은 푸른색, 잔류는 따뜻한색처럼 선악·진위 판단을 유도하는 대비를 금지한다.
- 확정 확인창은 선택한 절차명, 확실한 정보, 불확실한 정보, 취소 가능 여부를 같은 순서로 읽는다.

## 19. 타이포그래피·아이콘·자막 규격

### 19.1 1920×1080 기준 글자

| 용도 | 기본 크기 | 최소 | 확대 |
| --- | ---: | ---: | ---: |
| 대화 본문 | 24px | 20px | 200% |
| 선택지 | 22px | 20px | 200% |
| 화자명·영역 제목 | 20px | 18px | 200% |
| 목표·수첩 본문 | 18px | 16px | 200% |
| 상태·버튼 라벨 | 18px | 16px | 200% |
| 장식 텍스트 | 16px | 필수 정보 사용 금지 | 150% |

- 글자와 배경의 내부 목표 대비는 일반 본문 `4.5:1`, 큰 글자·두꺼운 아이콘 `3:1` 이상으로 잡는다.
- 위 수치는 제작 검수 목표이며 색상만으로 상태를 구분해도 된다는 뜻이 아니다.
- 고딕 장식 글꼴은 제목에만 사용하고 본문은 명확한 고딕계 또는 산세리프 UI 글꼴을 사용한다.
- 한글 조합, 조사, 말줄임표가 줄 첫머리에 고립되지 않도록 줄바꿈을 검수한다.

### 19.2 아이콘

- 아이콘은 24px에서 내부 구멍과 방향이 구분되어야 한다.
- 사용인 문양은 서로 다른 외곽 형태를 갖는다.
- 잠금, 오류, 위험, 완료 같은 의미 아이콘은 캐릭터 문양과 다른 프레임을 사용한다.
- 아이콘 단독 버튼에는 항상 툴팁과 `accessible_name`을 제공한다.
- 선택된 탭은 채움, 상단 표시선, `선택됨` 상태 중 두 가지를 사용한다.

### 19.3 자막

| 자막 종류 | 표기 예 | 위치 |
| --- | --- | --- |
| 화자 대사 | `에드가: 문은 닫혀 있습니다.` | 대화창 |
| 인격 기록 | `기록·운영 연구원: ...` | 대화창 별도 헤더 |
| 환경음 | `[서재 안쪽에서 일정한 구두음]` | 감각 자막 |
| 데이터 리듬 | `[ARCHIVE: 빠른 세 음, 마지막 음 누락]` | 대상 방향 가장자리 |
| 감각 묘사 | `[금속 맛이 혀끝에 남는다.]` | 중앙 하단 |
| 방향성 | `[왼쪽 복도에서 유리음]` | 방향 화살표+텍스트 |

- 화자별 자막색은 선택 사항이며 이름·문양을 항상 병기한다.
- 배경 자막은 최대 2줄, 대화와 동시에 나타날 때는 대기열 또는 반대쪽 영역을 사용한다.
- 반복 환경음은 첫 전체 문장 뒤 `같은 소리가 반복됨 ×3`으로 축약할 수 있다.
- 숨소리·심박음 민감 설정을 켜면 실제 음량을 낮추고 중립적인 텍스트로 바꾼다.

## 20. 광과민·멀미·심리 압박 강도 규격

| --- | --- | --- | --- |
| 전체 화면 점멸 | 사용하지 않음 | 동일 | 점진 마스크 |
| 국소 고대비 전환 | 초당 2회 미만, 1초 이내 | 제거 | 정적 프레임 단절 |

| 색 잔상 어긋남 | 2~8 논리 px | 0px | 정적 이중 윤곽 |
| 프레임 지연 | 1~3프레임 | 0프레임 | 타임코드 차이 |

### 20.2 심리·감각 곡선

| 구간 | 감각 설계 | 심리 목표 | 완화 지점 |
| --- | --- | --- | --- |
| P | 창의 온도와 날씨가 조금 다름 | 설명하기 어려운 어색함 | 일상 대화·마라 1 반응 |
| A~B | 같은 배치·문장이 지나치게 정확 | 반복이 편의가 아니라 감시처럼 느낌 | 수첩의 영구 정보 확인 |
| C | 거울 반사·소리·표면 기능 불일치 | 자기 감각을 믿기 어려움 | 원인을 퍼즐 규칙으로 바꿈 |
| D | 태엽 심장 성공 뒤 위장 필터 해제 | 실패한 듯한 충격과 세계 상실 | `SYNC COMPLETE`, 재시도 UI 없음 |

| F | 아버지의 기록과 현재 선택 병치 | 정답 없는 책임 | 확실·불확실 정보의 대칭 |
| 엔딩 | 현실의 무게 또는 잔류의 이중 외형 | 선택 이후에도 남는 불편 | 핵심 오브젝트의 짧은 후속 이야기 |

심리적 압박은 입력 방해나 허위 실패 메시지로 만들지 않는다. 플레이어의 감각이 흔들릴 때 시스템 규칙과 진행 상태는 더 명확하게 보여 준다.

| 프리셋 | 글리치 | 흔들림 | 점멸 | 환경 자막 | 숨·심박음 |
| --- | --- | --- | --- | --- | --- |
| 기본 | 100% | 100% 상한 내 | 안전 제한 | 핵심만 | 기본 |
| 완화 | 50% | 25% | 제거 | 상세 | -6dB |
| 최소 | 정적 대체 | 제거 | 제거 | 전체 | 음향 대체 가능 |

프리셋 변경은 즉시 미리보기하되 메인 장면을 재생하지 않는다. 설정 화면 안의 짧은 안전 샘플을 사용한다.

## 21. 접근성 설정과 저장 계약

### 21.1 설정 범주

```yaml
accessibility_settings:
  display:
    window_mode: borderless
    ui_scale: 1.0
    text_scale: 1.0
    cursor_scale: 1.0
    high_contrast_ui: false
  signatures:
    mode: color_pattern_label
    pattern_strength: 1.0
    custom_colors: {}
  subtitles:
    dialogue: true
    sensory: true
    speaker_labels: true
    directional_labels: true
    background_repeat_reduction: true
  motion:
    reduce_motion: false
    reduce_glitch: false
    photosensitivity_protection: true
    camera_shake: 1.0
  interaction:
    large_hotspots: false
    overlap_picker: true
    show_role_labels: true
    hold_as_toggle: false
    keyboard_role_order: true
  reading:
    screen_narration: false
    reading_speed: 1.0
    simplify_loop_summary: false
```

`custom_colors`에는 `signature_id → 표시색`만 저장한다. 퍼즐·이벤트 데이터의 `hue_id`, `owner_id`, `signature_id`는 변경하지 않는다.

### 21.2 저장 범위

| 데이터 | 저장 위치 | 새 게임 영향 | 세이브 슬롯별 여부 |
| --- | --- | --- | --- |
| 창 모드·해상도 | 로컬 사용자 설정 | 유지 | 공통 |
| UI·글자·커서 배율 | 로컬 사용자 설정 | 유지 | 공통 |
| 색상·문양 모드 | 접근성 프로필 | 유지 | 공통 |
| 자막·낭독 | 접근성 프로필 | 유지 | 공통 |
| 모션·글리치 | 접근성 프로필 | 유지 | 공통 |
| 힌트 공개 단계 | 진행 세이브 | 새 게임 초기화 | 슬롯별 |
| 퍼즐 검증 상태 | 진행 세이브 | 새 게임 초기화 | 슬롯별 |
| 관계·엔딩 | 진행 세이브 | 새 게임 초기화 | 슬롯별 |

접근성 프로필을 삭제해도 진행 세이브가 손상되지 않아야 한다. 읽을 수 없는 설정값은 기본값으로 복구하고 진행 데이터는 그대로 둔다.

### 21.3 첫 실행

첫 실행에서는 긴 설정 마법사를 강제하지 않는다. 시작 화면에서 다음 네 항목을 바로 제공한다.

1. 글자 크기.
2. 색상 서명 표시 방식.
3. 글리치·화면 움직임 강도.
4. 자막·감각 자막.

각 항목은 실제 게임 스포일러가 없는 샘플로 미리 볼 수 있다. `기본값으로 시작`을 항상 제공하고 설정은 게임 중에도 변경할 수 있다.

## 22. Godot 구현 인계 규칙

### 22.1 리소스 책임

| 리소스·서비스 | 책임 | 진행 데이터 쓰기 |
| --- | --- | --- |
| `AvatarVisualProfile` | 대표색, 실루엣, 소품, 종족 부속, 단계별 표현 | 금지 |
| `ColorSignature` | 기존 `signature_id`, 문양, 선, 음향, 라벨 | 금지 |
| `WorldPhaseVisualProfile` | S0~S5·R0의 환경·글리치 상한 | 금지 |
| `AccessibilitySettings` | 사용자 표시·입력·자막 설정 | 설정만 |
| `VisualStateResolver` | 세계·인물·접근성 상태를 최종 표현으로 합성 | 금지 |
| `HotspotAccessibilityAdapter` | 클릭 영역·포커스·겹침 목록 | 금지 |
| `InteractionRouter` | 유효 입력을 이벤트 컨트롤러로 전달 | 허용된 이벤트만 |

`VisualStateResolver`는 `bond`, `alert`, `world_phase`, `signature_id`를 읽을 수 있지만 값을 변경하지 않는다.

### 22.2 아바타 프로필 예

```yaml
avatar_visual_profile:
  owner_id: EDGAR
  avatar_palette_id: avatar_edgar_blue
  silhouette_id: dragon_vertical
  species_features: [dragon_horns, dragon_tail]
  prop_ids: [rapier_authority_key]
  grayscale_cues: [vertical_posture, long_horns, straight_rapier]
  phase_variants:
    S0: edgar_gothic
    S2: edgar_diagnostic_leak
    S3: edgar_exposed
    S4: edgar_core
    S5: edgar_stabilized
```

대표색 HEX는 `AvatarVisualProfile`에, 인격 서명 HEX는 기존 `ColorSignature`에 둔다. 같은 색 계열이어도 파일과 ID를 공유하지 않는다.

### 22.3 표시 합성 순서

```text
월드 단계 기본값
→ 캐릭터 AvatarVisualProfile
→ ColorSignature 출처 표시
→ 이벤트별 일시 오버레이
→ 접근성 대체
→ UI 포커스·상태
```

- 접근성 대체는 마지막 단계에서 필수 정보를 제거하지 않고 표현 방식만 바꾼다.
- UI 포커스는 캐릭터 색과 혼합하지 않고 독립 윤곽 레이어를 사용한다.
- 이벤트 오버레이가 끝나면 프로필 기본값으로 돌아가며 직접 재질값을 남기지 않는다.
- 화면 전환 중 설정을 바꿔도 같은 이벤트를 중복 실행하지 않는다.

### 22.4 Windows UI 노드 규칙

- 월드 핫스폿은 시각 스프라이트와 별도 충돌 도형을 사용한다.
- UI는 `Control` 앵커·컨테이너 기반으로 배치하고 절대 좌표만으로 200% 확대를 처리하지 않는다.
- 키보드 포커스 이웃을 명시하고 숨겨진 노드로 포커스가 이동하지 않게 한다.
- 팝업이 열리면 포커스를 내부에 가두고 닫을 때 원래 대상에 돌려준다.
- 마우스 통과용 장식 노드는 입력을 가로채지 않는다.
- 자막·대화·목표 갱신은 서로 다른 표시 큐를 사용한다.

### 22.5 후속 스키마 동기화

`17_상태변수_이벤트ID_Godot데이터구조.md`의 후속 상세화에서 다음을 반영한다.

- 기존 `AccessibilitySettings`에 창·DPI·문자·커서·입력 보조 필드 추가.
- `AvatarVisualProfile`, `WorldPhaseVisualProfile`, `VisualStateResolver` 계약 추가.
- `object_accessibility`와 전역 접근성 프로필의 기본값 상속 순서 정의.
- `accessible_name`, `role`, `state`, `description`, `action_label`, `live_region` 필드 정의.
- 색상 사용자 지정값이 `signature_id` 판정에 영향을 주지 않는 검증 추가.
