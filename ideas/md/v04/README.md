# GGB v0.4 기획 문서

## 1. 개요

이 폴더는 GGB(가칭)의 v0.4 기획 문서 세트다.

GGB는 멸망 이후 지구의 냉각 시설과 고딕 저택 시뮬레이션을 오가는 심리 서사형 포인트 앤 클릭 어드벤처다. 플레이어는 D5 이전에는 `NORMAL_RESET`으로 비가역 퍼즐을 다시 시도하고, 파열 뒤에는 복구되지 않는 세계에서 이전 루프를 기억하는 다섯 사용인과 관계를 맺는다.

핵심 요소:

- D5 이전 수면에 의한 `NORMAL_RESET`과 D5 이후 단발 `BROKEN_RESET`.
- 리셋 뒤에도 유지되는 수첩·지식·관계·사용인 기억.
- 반복 작업을 줄이는 영구 숏컷.
- 고딕 저택에서 SF 시설로 이어지는 점진적 파열.
- 인간 연구원의 인격을 가진 다섯 사용인.
- 인격 데이터 출처를 나타내는 색상 서명.
- 황폐한 현실과 자각된 시뮬레이션 사이의 최종 선택.

본 폴더의 문서는 프로토타입이나 실행 코드가 아니라 상세 게임 기획을 정의한다. 대상 플랫폼은 Windows PC 데스크톱이며 추후 Godot으로 구현한다.

프로젝트 전체를 처음 읽거나 제작 인계를 받을 때는 [v0.4 통합본](18_GGB_게임기획서_v0.4_통합본.md)에서 시작한다. 범위·우선순위·용어를 바꾸는 작업은 [00 확정사항](00_v04_문서목록_및_확정사항.md)을 먼저 확인하고, 실제 정답·수치·상태 경로는 통합본 §38의 정본 매트릭스를 따라 담당 `01~17` 문서에서 확정한다.

## 5. 핵심 확정사항

### 리셋

- D5 이전 잠들면 같은 침실의 같은 아침으로 돌아간다.
- 물리 상태·시간·인벤토리는 초기화된다.
- 수첩·일지·지식·관계·사용인 잔류 기억은 유지된다.
- HARD FAILURE는 B3-B, C4, D1에만 사용한다.
- D5 완료 뒤 첫 수면은 `FRACTURE_SLEEP → BROKEN_RESET_ONCE`로 이어지며, 이후 휴식은 세계를 초기화하지 않는 `POST_BROKEN_REST`다.
- F3 진입부터 `FINAL_SLEEP_LOCK`이 켜지고 EDC 취소 뒤에도 유지된다.

### 관계

- `bond`와 `alert`는 각각 `0~5`이며 독립값이다.
- 관계 이벤트는 F0나 엔딩 선택지를 잠그지 않는다.
- 연구원 기록 수와 관계 완료 수는 별도 값이다.
- 사용인은 이전 루프를 기억하지만 자기 담당 영역과 직접 목격을 중심으로 기억한다.

### 사용인

| 사용인 | 아바타 | 대표 기능 |
| --- | --- | --- |
| 에드가 | 용 | 운영·보안·코어 |
| 마라 1 | 여우 | 정비·배선·표층 유지 |
| 루카 | 쥐 | 생명 유지·냉각 |
| 이리스 | 인공 천사 | 외부 환경·계절 |
| 마라 2 | 박쥐·흡혈마 | 인격 아카이브·체크섬 |

원래 연구원은 모두 인간이다. 종족 특징은 시뮬레이션 아바타와 기능 인터페이스다.

### 색상 서명

- 색은 인격 데이터의 출처를 나타낸다.
- 캐릭터의 넓은 대표색과 시스템 판독용 데이터 서명은 별도 계층이다.
- `5~12%` 제한은 고딕 오브젝트·장치의 데이터 서명 표식에만 적용한다.
- 색만으로 필수 퍼즐을 풀게 하지 않는다.
- 문양, 선 패턴, 음향, 텍스트 라벨을 병행한다.
- 주인공의 SUBJECT 권한은 흑연·종이·필기음으로 표현한다.

### 엔딩

- 현실 기상과 안정화 잔류 모두 선택 가능하다.
- 관계 완료 수는 엔딩 반응을 바꾸지만 선택지를 잠그지 않는다.
- 현실은 안전을 보장하지 않는다.
- 잔류는 진실 기억을 삭제하지 않는다.
- EDC 확정 뒤에만 전원 완료 의식이 재생되며, 의식 입력은 엔딩 성공 조건이 아니다.
- 현실 엔딩은 다섯 인격을 자동 저전력 보존하고 별도 물리 수첩 `현장 인계 01`을 제공한다.
- 잔류 엔딩은 `S5_STABILIZED_FRACTURE`에서 외형 표시와 사용인 자율성을 가역적으로 조정한다.
- 두 엔딩은 필수 3묶음과 선택 오브젝트를 가진 9~15분 제한형 에필로그다.

## 6. 주요 용어

| 용어 | 의미 |
| --- | --- |
| `NORMAL_RESET` | D5 이전 정상 물리 초기화 |
| `BROKEN_RESET` | D5 이후 고딕 필터 복구 실패 |
| `POST_BROKEN_REST` | BROKEN_RESET 이후 세계를 초기화하지 않는 휴식 |
| `FINAL_SLEEP_LOCK` | F3 진입부터 엔딩 확정까지 모든 수면 라우팅을 차단하는 상태 |
| `LOCAL RETRY` | 수면 없이 현장에서 재시도 |
| `HARD FAILURE` | 당일 물리 상태가 비가역적으로 변해 수면 필요 |
| 영구 정보 | 정상 리셋 뒤에도 유지되는 지식·기록 |
| 검증 부분 | 퍼즐에서 정답임이 확인된 하위 단계 |
| 숏컷 | 검증된 준비·이동·일과의 축약 |
| 잔류 기억 | 사용인이 리셋 뒤에도 보유하는 사건·감정 패턴 |
| 개입 예산 | 사용인이 한 루프에서 사용할 수 있는 질문·제지 횟수 |
| 색상 서명 | 인격 데이터의 소유자 식별 묶음 |
| SUBJECT | 최종 결과를 겪고 선택하는 주인공 권한 |
| S4 | F구간 코어의 권한·출처 상태 |
| S5 | 안정화 잔류 엔딩 전용 상태 |
| 현실 공동 인계 수첩 | 현실 캡슐에 보관된 물리 수첩. 시뮬레이션 수첩과 별개 |
| `ending_run` | 확정 엔딩 분기와 노드 재개 상태 |
| `ending_meta` | 엔딩 열람·갤러리·챕터 선택 프로필 상태 |

`CHK_*`, `REL_*`, `SYS_*`는 모두 별도 플레이 콘텐츠를 뜻하지 않는다. 실제 등록 여부는 [04 이벤트·상태표](04_전체이벤트리스트_상태표.md)를 따른다.

## 8. 문서 작성 원칙

- 최신 확정사항을 이전 문서보다 우선한다.
- 한 문서는 자신이 소유한 영역만 확정한다.
- 선택 이벤트를 메인 필수 게이트로 만들지 않는다.
- 퍼즐 정답 변경은 `24-3`과 `08`을 함께 검토한다.
- 새 이벤트 ID는 `04`와 `17`에 등록한다.
- 색상 단서는 반드시 비색상 대체를 가진다.
- 관계값 변화는 같은 이벤트에서 최초 1회만 적용한다.
- 미확정 설정은 추론해 확정하지 않는다.

## 9. 검증 원칙

문서 수정 후 확인:

1. 상대 링크가 존재하는가.
2. 코드 펜스와 Mermaid 블록이 닫혔는가.
3. 이벤트 ID와 플래그 표기가 일치하는가.
4. 관계 이벤트 미완료 경로가 유지되는가.
5. 실패 뒤 재진입점이 존재하는가.
6. D5 이후 NORMAL_RESET으로 돌아가지 않는가.
7. 색 제거·음량 0에서도 필수 진행이 가능한가.
8. F0-E의 임시 의향이 F2·F3을 편향시키지 않고 EDC에서만 최종 선택과 비교되는가.
9. EDC 커밋 전에 엔딩 의식·에필로그가 시작되지 않는가.
10. ALL 의식과 엔딩 선택 조사가 진행 게이트가 되지 않는가.
11. 현실·시뮬레이션 수첩과 S4·S5 상태가 구분되는가.
12. 엔딩 seen 메타가 크레딧 전에 저장되고 F3 재선택 뒤에도 유지되는가.
13. `00`, README와 `18`이 통합본을 제작 인계·정본 역추적 문서로 동일하게 설명하는가.

## 13. Godot 4.7 데이터·저장 기준

### 정본과 형식

| 대상 | 정본·형식 |
| --- | --- |
| 사건·퍼즐·서사 | `ideas/md/v04/` Markdown |
| 타입·상태·writer·저장 | [문서 17](17_상태변수_이벤트ID_Godot데이터구조.md) |
| Godot 저작 데이터 | `game/data/`의 `.tres` |
| 진행 저장 | `user://saves/{slot_id}/` JSON |
| 사용자 프로필 | `user://profile/` JSON |

게임은 Markdown을 직접 파싱하지 않는다. 자세한 개발 경로는 [데이터 계약](../../../docs/data_contract.md)과 [Godot 규칙](../../../docs/godot_conventions.md)을 따른다.

### 저장 버전

```text
progress.schema_version = 12
accessibility.accessibility_profile_version = 1
ending_meta.ending_meta_profile_version = 1
```

진행·접근성·엔딩 메타는 독립 파일과 독립 migration을 사용한다. 진행 슬롯은 tmp 기록·checksum 검증·backup 보존 뒤 교체한다.

### 실행 책임

```text
입력
→ EventManager
→ StateWriter
→ GameState revision
→ SaveManager
```

- UI·대사·VisualStateResolver는 진행 상태를 직접 쓰지 않는다.
- 관계·파열·EDC처럼 여러 영구 효과가 있는 사건은 원자 그룹으로 커밋한다.
- `EventBus`를 별도 autoload로 중복 등록하지 않는다.
- Router는 상태를 읽어 경로를 정하고 writer 요청만 만든다.

### 타입과 검증

- ID·enum은 `StringName`.
- 논리 집합은 중복 없는 `Array[StringName]`, JSON에서는 정렬된 문자열 배열.
- 순서가 의미인 사건 노드·퍼즐 단계는 정렬하지 않는다.
- 필수 Resource의 ID·참조·writer·graph·save point 오류는 export 차단 대상이다.
- 문서 단계의 GDScript는 프로토타입이 아니라 구현 인터페이스 명세다.
