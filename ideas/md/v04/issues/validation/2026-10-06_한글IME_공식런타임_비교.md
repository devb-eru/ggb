# Windows 한글 IME 공식 런타임 비교

## 목적과 판정 범위

기준 develop `54ac062`. 게임 검색칸과 Steam Godot의 기본 LineEdit에서 사용자 물리 입력으로 확인한 [ERR-0042](../items/GGB-ERR-2026-0042_Windows_한글IME_음절유실.md)의 배포판/버전 차이를 분리한다. 저장 개선 커밋의 자동 회귀나 완성 문자열 주입은 IME 조합 합격 근거가 아니다.

게임 autoload와 저장 로직이 없는 동일 최소 프로젝트를 사용했다. `probe.gd` SHA-256은 `1FA0E4110BDEA95406B4E36A798CB1B6275951E6A4807596425E04DA272A5AB2`이며 코드와 project.godot은 [기존 실기 검토](2026-10-06_두자료비교_및_IME조합_실기검토.md)의 재현 코드와 같다. 각 비교는 별도 임시 프로젝트에서 실행하며 설치된 Steam 엔진·게임 project.godot·사용자 세이브·Windows 입력기 설정을 바꾸지 않았다.

**판정:** 동일 엔진 소스 커밋의 Steam/공식 배포판 양쪽에서 실패했다. Steam 배포판만의 결함으로 설명할 수 없다는 증거다. 엔진의 정확한 원인 코드, Windows 입력기 전체의 정상/비정상, 다른 PC 및 이전 버전의 결과는 아직 증명하지 않는다.

## 공식 4.6.3 비교: 네 입력 조건 성공

[공식 4.6.3 배포 파일](https://github.com/godotengine/godot/releases/tag/4.6.3-stable)을 비교 후보로 준비했다. ZIP SHA-256 `E39986A178D585CE7AC198FB8DE6EA436366DC0CC00E594810C2E3E104C04B90`을 공식 API 값과 대조했다. 실행 파일 SHA-256 `EF90E929BA1A6A4322860285D97F40F4AA349C90329A91B0E8B55B8DF0F4CB00`, 버전 `4.6.3.stable.official.7d41c59c4`다.

같은 probe를 `%TEMP%/ggb-ime-official-463-20261006/probe`에서 실행했다. PID 37556 / 시작 2026-10-06 23:47:29 KST, 같은 OpenGL/장치/드라이버 로그를 확인했다. 사용자 물리 입력에서 "오늘이 온전히 남음"을 확인했고 로그도 `IME_SUBMIT "오늘"` / `IME_TEXT "오늘"`이었다. 동일 PC/최소 프로젝트에서 4.6.3은 성공, 4.7.2는 실패한다는 국소 버전 차이 증거다. 모든 IME 동작이나 다른 PC, 실제 게임의 정상 여부를 뜻하지 않는다.

추가로 `오늘의 일과`, 한영 전환의 `오늘abc내일`, 확정 후 Backspace로 끝 음절 삭제/복원을 요청했다. 마지막 검사는 먼저 Enter로 오늘을 확정한 뒤 Backspace를 수행하도록 바로 보충했다. 조합 중 자모 삭제와 확정 음절 삭제를 혼동하지 않는다. 사용자는 세 조건 모두 정상이라고 답했고 로그의 확정값도 각각 `오늘의 일과`, `오늘abc내일`, `오늘`이다. 이 로그가 각 키의 완전한 OS 이벤트 추적이라는 뜻은 아니며 조합 취소/중간 삽입/포커스 이탈은 미검증이다.

PID/실행 경로/시작 시각을 대조해 이 진단 창만 정상 닫기 요청 후 종료를 확인했다. [4.6.3 원본 입력 로그](2026-10-06_한글IME_공식4.6.3_입력로그.txt) SHA-256은 `CE225B2256A7D8F781926A64332277555FFC7F69E32F2E7988B4034F6AF90ACE`다.

## 게임 호환 검사와 소스 조사

`%TEMP%/ggb-ime-463-game-compat-20261006`에 검증 작업본의 game을 복사하고 기존 `.godot` 캐시는 제외했다. APPDATA도 별도 경로로 분리해 공식 4.6.3 headless editor import와 migration/host/기본 기반 검사를 실행했다. `project.godot`의 4.7 feature 표기는 복사본에서도 수정하지 않았다. import/기능 검사 모두 종료 0. migration의 정규화 26조건·encoder 29조건·저장 안전성 381개, host 548개(내부 async 322개), 기본 기반 PASS다. 단일 host의 프레임 계측은 장비 인수나 버전 간 성능 비교 근거가 아니다.

이 후보에서 Windows Desktop Debug PCK 내보내기도 종료 0. PCK SHA-256은 `462095A2BBBFCB642CFBC05165478D2A079BEF0592FDBEFB68CADE6301AF5308`이며 같은 디렉터리의 `notebook.pck`다. 이는 PCK 생성 증거이며 배포용 EXE/템플릿 패키지 검증이 아니다. 빈 작업 폴더에서 이 PCK의 기본/수첩 모드 자동 캠페인과 재선택 복귀 366개 모두 PASS/종료 0, 해당 실행기와 테스트 프로세스는 종료했다. 실제 입력 완주나 수첩 IME 인수를 자동 캠페인 PASS로 대체하지 않는다.

호환 검사 로그에는 기존 bootstrap의 `GGB expects Godot 4.7.x` 경고가 있다. 현재 정본/프로젝트/런타임 요구는 여전히 4.7이며 경고를 숨기거나 허용 버전 범위를 임의로 넓히지 않았다. 채택 시 bootstrap 상수, project feature, 개발 환경·제품/데이터 계약·검증/성능 문서 및 빌드/템플릿 기준을 함께 검토해야 한다. 과거 4.7 실행 근거의 버전 표기는 소급 변경하지 않는다.

공식 [4.6.3 Windows 소스](https://github.com/godotengine/godot/blob/4.6.3-stable/platform/windows/display_server_windows.cpp)와 [4.7.2 Windows 소스](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/windows/display_server_windows.cpp)의 WM_IME_STARTCOMPOSITION/ENDCOMPOSITION, 두 판 LineEdit의 apply_ime/IME_UPDATE 부분을 읽었다. 이전 조사에서 후보로 언급한 시작 시 `key_event_pos--`는 두 판 모두에 있고, 확인한 LineEdit 구간도 동일했다. 따라서 그 줄만 이번 버전 회귀의 원인으로 지목하거나 제거할 근거가 없다. 비교 API는 파일 목록을 비워 반환해 전체 변경 없음의 근거로 쓰지 않았으며 정확한 원인 commit은 아직 미확정이다.

## 2026-10-07 실제 게임 후보와 사용자 결정

사용자는 **4.6.3 후보로 실제 게임 IME·전체 호환을 검증한 뒤 개발·빌드 기준 채택 검토**를 선택했다. 이는 즉시 다운그레이드나 전체 호환 합격의 승인이 아니다. Steam 설치를 자동 변경하지 않는다.

위 PCK/공식 4.6.3으로 `%TEMP%/ggb-ime-463-native-20261007`의 별도 APPDATA에서 실제 창을 실행했다. 이전에 만든 격리 4.7 슬롯의 main/bak만 복사하고 원본/복사본 SHA-256 일치를 확인했다. 원본 main `843D7C4C2DC83AAB62C4E5155AD9E905712CB117A74408398EC94574C4032F9E`, bak `2EB8C5495C5578A70D3F92667CEE721E9916405F98409CD7878BA764FB7752AB`. 저장 header engine_version은 4.7이며 실제 사용자 슬롯이 아니다.

PID 21736 / 시작 2026-10-07 00:09:34 KST. 실행 직후 살아 있음과 같은 OpenGL 장치 로그를 확인했다. 사용자에게 이어하기 → 공통 수첩 → 검색칸의 물리 `오늘의 일과` 입력을 요청했고 사용자는 "게임·수첩이 열리고 문자열이 온전히 남음"이라고 확인했다. 최소 LineEdit만 아니라 게임의 검색 갱신/포커스 코드와 엔진을 결합한 국소 성공 증거다. 사용자 확인에 근거한 실제 입력 결과이며 자동 주입이나 게임 내부의 text_submitted 로그로 확인한 결과는 아니다.

추가 실제 게임 한영 전환·확정 후 편집·조합 취소·포커스 이탈/복귀 네 조건을 요청했고 사용자는 "네 조건 모두 정상"이라고 확인했다. 확정된 오늘 뒤 가의 조합 취소에서 본문 유실/중복이나 수첩의 뜻밖의 닫힘이 없는지 포함한 요청이었다. 이 네 결과는 사용자 물리 입력/화면 확인에 근거하며 OS 메시지 전수 추적은 아니다. 첫 `오늘의 일과`를 포함한 실제 수첩 다섯 국소 조건의 성공 증거다.

PID/실행 경로/시작 시각을 대조해 이번 격리 게임만 정상 닫기 요청 후 종료를 확인했다. 종료 후에도 이전 격리 슬롯 main/bak 원본 해시는 위 값과 같았으며 native stderr에는 기존 4.7 기대 버전 경고 외 스크립트 오류가 없었다. 모든 이 턴의 검사 프로세스는 종료했다. Windows 입력기 전체/전용 입력 완주/정식 성능 인수를 뜻하지 않는다.
