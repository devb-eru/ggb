## 변경과 보존 경계

기존 `notebook_query.gd::index_step`은 각 공개 행에 `detail`을 호출해 참조 복제·출처 목록·관련 자료·보존 안내·시각 자료 지원 여부까지 구성했다. 검색 색인은 이 중 여덟 공개 문자열만 사용했다.

본문 렌더링을 `_render_body`로, 여덟 공개 필드를 `_search_fields`로 공유한다. 검색은 본문 검증과 필드 투영만 수행하며 상세 보기는 그 결과에 기존 상세 메타데이터를 붙인다. 공개 행 범위, 본문 렌더러, 구형 기록 검증, 언어 fallback, 오류 코드, 검색 필드 순서·소문자화는 유지한다. 상세 전용 관련 자료를 매번 구성하지 않는 것이 목적이며 색인에서 검증을 생략하지 않는다.

`index_step` 진입의 scope/cache key 검증, 한 번에 최대 50개, 프레임 예산, 부분 색인 상태 및 결과 캐시 무효화도 유지했다. 손상된 행은 오류로 남기고 그 행만 검색에서 제외하며 커서는 다음 행으로 진행한다. 저장 schema, 카탈로그, 정책 버전, rollout 기본 비활성은 변경하지 않았다.

## 자동 검증

- 한영 각각 색인 여덟 필드와 상세 결과의 정확한 대응, 행당 1회 렌더링, stale/닫힌 모델 거부, 상세 메타데이터 보존을 추가했다.
- 구형 10,002개 중 잘못된 line_id 1개를 제외한 10,001개가 끝까지 색인되며, 오류 코드는 남고 뒤쪽 정상 원문을 찾는지 검사했다.
- 메타데이터 64,420개, 이전 수첩 73개, view 83개, browse 213개, visual 210개, search 180개, investigation 300개, person 64개, memory disclosure 83개, self mark 270개, gallery 189개 PASS.
- 동일 최종 PCK에서 호스트 375개·비동기 저장 270개·타이틀 회귀 PASS. 호스트 실행 55.5초/타이틀 7.7초는 전체 검사 소요 시간이며 UI 지연 값이 아니다.

## 남은 범위

검색과 첫 표시의 동기 비용은 아직 남는다. 실제 Windows 입력/IME·cold 20/warm 100·메모리·장비별 성능, 본편 생산자 저장, 전편 분기 및 전체 요구사항 감사는 미완료다. 잠금 해제 응답 전에는 승인받은 실제 입력도 재개하지 않는다. 이번 통과를 전체 수첩 완료로 해석하지 않는다.
