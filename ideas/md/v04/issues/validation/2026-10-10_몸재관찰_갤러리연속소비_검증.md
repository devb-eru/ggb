# 몸 재관찰 증거의 갤러리 연속 소비 검증

## 1. 범위와 결론

T17d의 국소 소비 경로를 검증했다. 실제 `EDR_BODY_CHECK` 컨트롤러의 몸 조사 버튼과 대사 기록 writer를 거쳐 저장한 첫 조사/재관찰을, 완료 엔딩 fixture의 capture/read, 보존 한도 정리, 언어별 페이지 생성과 실제 갤러리 호스트에 연결했다. 최종 128조건·저장 경계 18조건, 3,094단언과 세 실행의 독립 검사 5,177확인·8반례 모두 PASS다. 이번 범위에서 새 제품 결함은 발견하지 않았으며 게임 코드·카탈로그는 수정하지 않았다.

실제 Windows 입력과 이번 headless 버튼 callback은 다르다. 사용자의 공식 4.6.3 실제 게임 입력 정상 응답은 [기존 런타임 비교](2026-10-06_한글IME_공식런타임_비교.md)와 [ERR-0042](../items/GGB-ERR-2026-0042_Windows_한글IME_음절유실.md)에 이미 기록되어 있다. 이번 자동 검사나 같은 사용자 응답을 새 물리 입력 횟수로 중복 집계하지 않는다.

## 3. 독립 조건과 실제 동작

| 묶음 | 분모 | 검사 내용 |
| --- | --- | --- |
| 조사→capture→페이지 | 구형/신형 2 × 조사 언어 2 × 재관찰 조합 8 × capture/정리 투영 2 × 표시 언어 2 = 128 | 손·호흡 모니터·고정 장치의 실제 첫 조사 후 선택한 대상만 실제 재조사. 저장 이력 형식을 확인하고 각 공개 본문을 정확히 대조 |
| 재조사 writer 저장 경계 | 오브젝트 3 × 언어 2 × 정상/거부 후 재시도/확정 저장 응답 유실 3 = 18 | 정상 저장과 실패 시 rollback, 실제 디스크 reload, 대상별 독립 증거와 authored 반복 기록 정확히 1개 |
| 실제 갤러리 호스트 | 이력 형식 2 × 조사 언어 2 × 조합 8 = 32 | 보관본으로 호스트 진입, 생성된 행 상세 조회, 갱신·닫기 후 현재 snapshot/revision/load_epoch 및 원본 파일 바이트 불변 |

32호스트 호출은 128페이지 조건의 공급 경로이며 별도의 128호스트 호출로 계산하지 않는다. 18저장 경계는 authored writer만 검사했다. 구형 writer의 저장 실패 전수와 별도 OS 강제 종료는 이번 범위가 아니다.

첫 조사만으로 `BODY_REPEAT:<object>`를 만들지 않는다. 첫 조사만 한 조합의 페이지에는 첫 본문만 나타나고, 실제 재관찰한 조합에만 재관찰 문장이 붙는다. 저장 거부 시 메모리와 디스크의 이력·증거 모두 이전 상태를 유지하며 재시도/응답 유실 확인 후에도 반복 기록은 하나다.

구형 완료 fixture에서는 새 영구 증거 필드를 제거해 과거 형식을 재현한다. `EndingGalleryStore.read_entry`의 이관이 **실제 저장한 구형 반복 원문에서만** 증거를 추출하는지 8조합을 대조한다. 첫 조사 acknowledgment나 엔딩 완료만으로 반복 관찰을 추정하지 않는다. 실제 관찰 meta_progress/required_interactions_seen을 완료 fixture에 옮겼으며 원문을 합성하여 반복 조사처럼 만들지 않았다.

등록된 일반 authored 대사 2,001개를 정리 투영에 추가한다. 실제 오래된 무보호 authored 본문이 제거되고 legacy 원문은 유지되는지 확인하며, 정리 후에도 독립 관찰 증거로 공개 가능한 갤러리 본문이 유지된다. 이 정리는 detached 투영에서 수행했으며 본편의 실제 2,001대사 플레이나 디스크 정리 트랜잭션 전수는 아니다.

각 페이지 조건에는 acknowledgment 제거 시 몸 페이지 비공개, 완료 프레임 제거 시 갤러리 비공개, 완료 잔류 엔딩에 현실 이력/증거를 넣어도 현실 몸 페이지 미생성이라는 반례가 포함된다. 입력 candidate와 현재 게임 상태를 페이지 생성이 바꾸지 않는지도 확인했다.

## 6. 남은 요구

T17d의 위 국소 경로만 완료한다. NP22의 다른 페이지·저장 입구·개발자 경로 전수, 전 생산자 독립 필수 행동·신규/제외 감사, NB-AQ06의 모든 소비자와 보호 원문/출처 이동, 후보 4.6.3 최신 코드 release/템플릿·엔진 채택, 성능 p95·메모리·OS 장애 및 실제 마우스/키보드 전용 전편은 남아 있다. 완료 엔딩 fixture를 자연 전편 도달성이나 두 엔딩 완주로 주장하지 않는다.

[전체 ToDo](notebook_history_TODO.md), [인수 대조](notebook_history_acceptance_matrix.md), [구현 현황](notebook_history_implementation_status.md)에서 각 미완료 항목을 유지한다. develop 전달은 사용자 변경 SHA·선택 stage·동일 Git tree의 독립 검사·문서 검사 후 진행하며, 결과는 ToDo의 전달 항목에 구분해 기록한다.
