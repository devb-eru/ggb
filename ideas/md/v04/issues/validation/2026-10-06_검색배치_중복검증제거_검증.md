## 구현 변경

`notebook_query.index_for_budget`는 한 호출 안에서 네 행씩 처리할 때마다 `index_step`을 호출했다. 그때마다 동일한 scope 키를 JSON 직렬화하고 SHA256으로 만들며 결과 캐시를 비웠다. 호출 시작 시 공개 메서드에서 요청을 검증하고, 동기 내부 루프는 `_index_rows`로 같은 행을 처리하도록 변경했다. 변경된 행이 있을 때 호출 끝에서 결과 캐시를 한 번 비운다.

`index_step`의 공개 진입 검증, 행 수 제한과 결과는 유지한다. `index_for_budget`의 기본 4,000us, 250~8,000us 제한, 네 행마다 시간 확인도 유지한다. 본문 검증·공개된 검색 필드·손상 행 처리·오래된 요청 거부는 생략하지 않는다. 이 함수에는 await/외부 콜백이 없고 모델이 동결되어 있어 같은 동기 호출 내부에서 scope가 전환되지 않는다.

측정용 `notebook_performance_probe.TimedQuery`는 실제 예산 호출에 걸린 시간 합계/최대와 호출 횟수를 기록한다. 실제 게임 조회에는 계측 서브클래스를 사용하지 않는다.

## 기능 검증

한영 fixture에 대해 다음을 추가했다.

- 예산 호출당 요청 키 검증 1회와 앞으로 진행하는 색인.
- 새 색인 뒤 부분 검색 캐시 무효화.
- 기존 행 제한 방식과 공개 검색 필드 및 부분/최종 페이지 결과 동일성.
- 오래된 키, reopen 이전 세대와 닫힌 모델의 거부 및 상태 불변.
- 완료된 색인의 재렌더링 없음, 입력 원장/지식 원장 불변.

Godot 4.7.2 headless import/export와 `--notebook-query-smoke --ggb-dev-notebook-v2` PASS. query 4,728개, 검색 180개, view 224개와 기존 browse/visual/공개 기억/자료 출처/갤러리 회귀가 포함된다. 검사 수를 전체 요구 커버리지로 해석하지 않는다. 실행 로그는 `%TEMP%/ggb-query-batch-20261006`에 있다. 기존 Windows 인증서 저장소 경고 외 script/parse 오류는 없다.

처리 합계는 동기 색인 호출 내부의 벽시계 시간이며 운영체제 스케줄링을 포함할 수 있다. 전체 검색에는 200ms debounce, 호출 사이 프레임 대기와 화면 갱신이 포함된다. 두 값을 빼서 전부 순수 프레임 대기라고 단정하지 않는다. 한 호출이 네 행 뒤 시간 예산을 확인하므로 약간의 초과는 허용된 기존 동작이다.

## 실제 입력 재개 시도와 남은 범위

사용자가 잠금 해제·입력 가능 상태를 응답한 뒤 별도 격리 게임을 실행했다. 키보드 새 게임, 기본 설정 선택과 빈 슬롯 화면까지 관찰했다. 다음 Return은 자동 안전 검토가 이전 물리 Escape 중단 상태를 이유로 거부했다. 추가 UI 입력을 보내지 않고 실행 경로/격리 인자를 확인해 이번 검증 프로세스 PID 36716만 종료했다. 사용자 편집기는 유지했다. 이전 중단 해제와 입력 재개 확인을 다시 요청했으며 새 인수 항목을 완료 처리하지 않는다.

정식 cold 20/warm 100, 네 fixture와 장비별 인수, 실제 OS 입력/IME/확대/전편 완주, 전체 동기 저장과 패널 공개 지연이 남아 있다. T20/T21/T22/T23/T24 및 ERR-0027은 미완료, rollout OFF를 유지한다.
