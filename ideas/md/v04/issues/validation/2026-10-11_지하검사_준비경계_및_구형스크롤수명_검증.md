## 2. 확인된 원인과 수정

### 2.1 수첩 준비와 닫기

검사기는 통합 수첩 열기 직후 아직 준비되지 않은 모델/탭을 읽었다. 닫기를 요청한 뒤에도 model job 완료를 기다리지 않고 다음 관계 모달을 열어, 열려 있는 수첩의 live guard가 선택 기록을 거부했다. 메뉴·최신 대사·관계 선택/미룸·엔딩 후 기록의 기존 의미 단언을 유지하고 실제 `_opening`/표시/작업·닫기 완료를 제한 시간 안에서 기다린다. timeout·준비 실패는 명확한 실패이며 후속 모달을 진행해 PASS로 바꾸지 않는다.

### 2.2 로드 후 현실 수첩 화면

통합 수첩을 열지 않는 현실 수첩 단독 기준 검사도 194실행 단언에서 출구 전환 실패를 보였다. 각 페이지 읽기 후 `load_and_install()`로 load epoch를 바꾸고도 이전 controller를 그대로 사용한 것이 원인이다. `field_finish`의 오래된 표시 소유자 보호 로직은 그대로 유지한다.

후보는 실제 로드처럼 controller를 새로 구성한다. v2에서는 화면에 이미 표시된 자료의 기록 준비를 먼저 완료하고 기준 snapshot을 잡는다. 이전 소유자의 클릭이 그 snapshot을 바꾸지 않음, 새 화면에 완료 버튼이 있음, 정상 물리 출구 전환과 출구의 필수 상태 확인 버튼 생성을 함께 검사한다. 다음 버튼이 없으면 해당 단계에서 명시적으로 실패하고 중단해 null 버튼 오류로 전파하지 않는다.

최종 단독 결과: 203단언/native 0/PASS. 단독 실행은 전체 지하 회귀가 아니다.

### 2.3 구형 스크롤 복원의 수명

실제 PrologueController를 통해 정상/세대 변경/닫기/즉시 삭제/삭제 예약/분리/재진입/대상 교체/숨김/스크롤 삭제의 10조건을 검사했다. 기준본은 16단언 중 분리·재진입·대상 교체·숨김 네 실패와 즉시 삭제·삭제 예약의 WeakRef 두 개 누수를 보였다.

제품 `prologue_controller.gd`의 `_restore_history_scroll()`은 Node에 소속된 `await process_frame` 대신 one-shot frame signal을 연결한다. tree 이탈은 `_history_generation`을 만료시키고 callback은 현재 표시/대상·소유자 수명을 검사한다. 정상 저장 위치 42 복원은 유지한다. 최종 고정 소스에서 CLI `ko_KR`/`en_US` 두 실행은 각각 10조건·16단언/native 0/verbose 무누수다. 동일한 10조건을 실행 두 번의 20개 고유 조건으로 확대하지 않는다.

## 4. 실패 시도와 집계

1. 첫 작은 검사기를 SceneTree 직접 script로 실행해 자동 로드 `GameState`가 등록되기 전 compile 실패가 났다. 정지한 특정 소유 PID를 확인하고 종료했으며 이 실행을 제품 실패/통과에 합산하지 않는다. 정상 scene 진입으로 교정했다.
2. 첫 화면 교체 후보는 새 출구 전환을 통과했지만 추가 stale-click 기준이 아직 미확정인 표시 자료의 기록 준비까지 포함해 실패했다. 실제 표시 준비를 완료한 뒤 전체 snapshot을 비교하도록 교정했다. 원문·기록 필드를 지우거나 일부 세계 상태만 비교해 실패를 우회하지 않는다.
3. 초기 작은 수명 후보 PASS는 제품 controller는 같아도 테스트 파일이 최종 필드 후보와 다른 소스다. 최종 제품 265개 스크립트 지문에 맞는 실행만 최종 성공에 포함한다.
4. 이전 [기상 출처 검증](2026-10-11_기상출처_침실정본화_검증.md)의 전체 지하 개발 38실패·기본 종료 누수는 당시 근거로 유지한다. 이번 새 실행의 PASS로 원래 실패 로그를 바꾸지 않는다.
5. 전체 지하 검사는 내부에서 여러 차례 한국어/영어를 직접 전환하며 한국어 기준 fixture도 포함한다. 따라서 기본/개발 두 실행의 내부 한영 단언을 검증 범위로 삼는다. CLI 언어만 바꾼 네 반복을 전편 영어 경로·물리 입력 인수로 간주하지 않는다.
