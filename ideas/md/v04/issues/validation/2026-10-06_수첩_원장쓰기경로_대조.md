# 수첩 원장 쓰기 경로 대조

- 기준: develop `8e226a1`.
- 대상: T19의 호출 경로 분류. 실행 분기 전수 검사와 구분한다.
- 판정: 확인한 원장 갱신 경로의 소유자를 아래와 같이 연결했다. 새 제품 결함을 확정하지 않았다. 전 분기의 도달성·미실행 수는 미확인이다.

## 조사 방법과 한계

`game/scripts`의 테스트/도구를 제외하고 `dialogue_history` 대입, `chapter_notebook` 쓰기, `append_observation`, `append_to_snapshot`, `record_viewed_line`, `KNOWLEDGE.acquire` 및 각 NOTES 어댑터 호출을 검색했다. 검색 결과에서 최종 쓰기 함수와 호출자의 후보 상태·저장 연결을 읽었다. 문자열 검색을 완전한 GDScript 호출 그래프나 모든 alias/동적 호출의 증명으로 취급하지 않는다.

## 미매핑 fallback

`dialogue_history_writer.append_to_snapshot`은 신형 history에서 `notebook_content`가 있으면 `CONTENT.observe` 후 `ARCHIVE.append_observation`을 호출한다. descriptor가 없으면 `append_unmapped`로 원문을 보존한다. 따라서 게임이 계속 진행되거나 원장 형식 검사가 통과했다는 사실만으로 신규 미매핑 0을 주장할 수 없다.

생산자 실행 검사에서 실제 생성한 행의 `record_class`, producer/node/variant/segment와 필수 호출 목록을 대조해야 한다. 기존 authored 행만 추려 검사하면 fallback 누락을 숨길 수 있다. 이전 저장의 미분류 자료를 삭제하거나 fallback 자체를 무조건 차단하는 방식으로 이 요구를 해결하지 않는다.

## 소스 경로 표기

등록 JSON의 source_file을 대조하면 프롤로그 수첩 9개 의미 버전은 `game/scripts/prologue/prologue_controller.gd`로 저장소 기준을 쓰고, 나머지는 `scripts/...`로 게임 폴더 기준을 쓴다. 양쪽 모두 실제 파일을 가리킨다. 모든 경로 앞에 game을 붙이면 앞의 9개를 잘못 누락으로 판정한다.

감사 시 `game/` 시작은 저장소 기준, `scripts/` 시작은 게임 폴더 기준으로 명시적으로 해석한다. 다른 형식은 추측하지 않고 별도 확인한다. 이 감사 편의를 위해 과거 카탈로그의 식별 메타데이터를 덮어쓰거나 의미 버전을 임의 변경하지 않는다.

## 남은 실제 검증

1. 위 입구별 플레이어에게 노출되는 행동·선행 조건·방·원래 stage를 독립 필수 경로로 열거한다. 방어용 잘못된 입력과 자연 도달 경로를 구분한다.
2. 각 경로의 실제 생성 tuple 및 authored/unmapped/legacy를 대조한다. 직접 쓰기 검색 수를 이벤트/필수 분기 수로 환산하지 않는다.
3. 실패·재시도·중단·재방문에서 공개하지 않은 후속 대사/문서가 생성되지 않는지 확인한다. 기존 검증 자료는 유지하고 미확인 조건을 추가한다.
4. NP22 본편 비오염, 실제 Windows 입력, 성능 인수는 별도 완료 조건이다.

이번 결과는 정적 경로 분류이며 게임 실행 검사를 새로 수행한 것이 아니다. 전체 목표와 T19는 진행 중이다.
