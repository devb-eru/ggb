# 프롤로그 통합 후보 비동기 저장 검증

## 범위

- 시작 기준: develop `dd7c7b36a75cbd509ff0b77d61ac4dd32d5748e5`.
- 공식 Godot `4.6.3.stable.official.7d41c59c4` 후보의 새 격리 TEMP 프로젝트와 전용 APPDATA에서 실행했다. 실제 세이브·사용자 Steam 설치·제품 엔진 기준은 변경하지 않았다.
- 제품 수정: 프롤로그 컨트롤러, SaveManager, notebook_save_worker, dialogue_history_writer와 새 prologue_save_candidate. 새 helper의 `.gd.uid`는 TEMP import에서 생성한 값으로 별도 보존한다.
- 개발 옵션 `--ggb-dev-notebook-v2 --ggb-dev-notebook-async`에서 프롤로그 표시 대사와 통합 진행 후보, 마지막 대사의 커서 및 대화 뒤 일과 완료 저장을 비동기로 연결했다.
- 기존 동기 API의 반환형·선택창·게임 명령은 유지한다. 순수 후보 준비 함수는 기존 동기 경로와 worker가 공유한다.
- 제품 4.7·rollout OFF·ERR-0027 IN_PROGRESS를 유지한다. 전체 프롤로그 비차단 인수, 전체 생산자/실기·정식 성능·엔진 채택 완료가 아니다.

## 원자성 계약

프롤로그는 대사만 저장하지 않는다. 다음 항목을 하나의 후보에 묶는다.

| 항목 | 처리 |
| --- | --- |
| 일과·장소·시간·인벤토리 | controller가 현재 자료를 고정하고 worker가 detached snapshot에 반영 |
| 단서·사용인 소개·기억 닻 | 기존 marker 규칙과 notebook_knowledge acquire를 같은 후보에서 실행 |
| 창문 조사 위치·선택 도구 | 기존 WINDOW_KEY 규칙을 유지 |
| 보류된 현장 설명 | 현재 action에서 수집한 surface의 정확한 원문·언어·context를 후보에 포함 |
| 표시 대사·커서 | 같은 후보의 사실/진행 상태를 바탕으로 cursor를 만들고 관찰을 append |
| 대화 뒤 진행 완료 | action 결과와 completed cursor를 같은 후보로 저장 |
| 리셋 후 R1 인계 | 떠나는 프롤로그의 새 물리 기본값이 이미 저장된 영구 기록/진행을 덮지 않도록 기존 보호 유지 |

worker에는 game/UI Node나 현재 번역 상태를 전달하지 않는다. 언어, scope, progress, pending notes, inventory와 presentation spec의 데이터를 고정한다. 전체 snapshot 검증과 고유 임시 파일 flush/readback, main/bak/일반 tmp의 실제 바이트 SHA, revision/load_epoch/root/flavor 검증은 기존 비동기 저장 계약을 따른다. 최종 승격 후에만 live snapshot을 설치한다.

controller는 저장 서비스·슬롯/분기/epoch scope·언어·장소·progress·pending notes와 표시 token/index의 소유권을 완료 시 다시 확인한다. pending 중 다음/선택 callback·메뉴/수첩/세계 상호작용은 진행하지 않고 본문 스크롤은 허용한다. 실패하면 대사와 미확정 단서를 재시도할 수 있다. 대화 뒤 진행 저장 실패는 마지막 내구 `finish_pending` 표현으로 복구하며, 명시 입력 뒤 action을 재실행한다. 인계 signal은 completed cursor의 내구 성공 이후 한 번만 보낸다.

## 실패 시도와 재현 자료

[원자료 43파일](evidence/2026-10-10_prologue_async/manifest.json)에 최종 세트와 중간 실패를 함께 보존했다. 마지막 manifest 자체를 제외한 42개 파일의 바이트/해시를 검사한다. 엔진 바이너리·실제 테스트 세이브·APPDATA는 Git에서 제외한다.

- 첫 집중 검사: 완료 뒤 관찰한 현장 설명 때문에 전체 기록 수가 늘어나는 정상 동작을 잘못 실패로 판정했다. 총수 대신 UID/원문과 대사 token을 검사하도록 정정했다.
- 두 번째 집중 검사: R1 caller line에는 아직 token이 없는데 검사 lambda가 caller에서 읽어 script error가 났다. `_show_dialogue`가 실제 생성한 표시 행의 token을 고정하고 신규 행의 출처 검사까지 추가했다. 제품을 완화하지 않았다.
- 첫 cursor_reload: 기존 검사의 단계 이름은 resume인데 래퍼가 reload를 넘겨 `unknown phase`로 종료 1. 원본 래퍼·그때의 receipt/로그를 남기고, 새 프로필에서 올바른 seed/resume/completed를 검사했다. 잘못된 실행을 복귀 PASS로 계산하지 않는다.
- 원자료에 포함된 초기 prologue/seed PASS는 원본 래퍼 SHA로 검증하며, 최종 resume/completed는 수정 래퍼 SHA로 검증한다. 같은 게임 코드와 다른 검사 도구 세대를 혼합 소스로 숨기지 않는다.

재실행 도구는 `scripts/run_notebook_prologue_async_audit.ps1`, 기존 경로의 `scripts/run_notebook_prologue_compatibility.ps1`, 독립 검사기는 `scripts/audit_notebook_prologue_async.ps1`이다. 손상 반례는 원로그 누락/바이트 변경/native 실패/조건 누락/조건 중복/혼합 제품 소스다.
