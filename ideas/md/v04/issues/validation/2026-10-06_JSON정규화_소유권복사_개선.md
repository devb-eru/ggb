# JSON 정규화 소유권 복사 개선

## 변경과 안전 경계

기준 develop `ba78254`. SaveManager의 파일 읽기에서 방금 JSON.parse로 생성한 상태도 정규화 전에 다시 전체 deep copy를 하던 부분을 개선했다. 파싱 결과는 이 호출만 소유하고 JSON은 객체 공유 참조를 표현하지 않으므로 그 트리 안에서 기존 정규화를 수행한다.

- 일반 `StateSnapshotValidator.normalize`와 `NotebookMigration.adapt_verified`는 기존대로 caller의 원본을 복사한다. GameState·저장 후보·worker의 공유 상태는 이 경로를 유지한다.
- 내부 `_normalize_owned`와 `_adapt_owned_verified`의 제품 호출은 SaveManager의 독점 JSON 파싱 결과뿐이다. 테스트도 각각 새 JSON 파싱 결과를 사용한다.
- 모든 header/schema/design/checksum 검사, 원장·상태 검증과 구형 이관은 유지한다. 정규화 규칙·오류 순서·저장 형식·실패 복구 규칙은 변경하지 않는다.
- 호출을 넘는 검증 캐시나 파일 검증 생략은 없다. 소유권 없이 쓰면 원본 변경 위험이 있으므로 이 내부 경로를 일반 caller에 확대하지 않는다.

## 기능 검증

기본/구형 자료 두 종류와 고정 대용량 fixture 네 종류, 손상 자료 일곱 종류를 promote OFF/ON으로 검사했다. 총 26조건의 기존 복사 경로와 owned 경로의 수락/거부·전체 출력·오류 순서가 일치했다. 일반 caller 입력 불변과 출력 독립성을 유지하고, owned 성공 결과는 파싱 트리와 동일 객체여서 두 번째 전체 트리를 만들지 않는지도 검사했다.

손상 조건은 root 누락, meta 배열, servant 오형식, history null, 잘못된 순번, 미래 ledger와 cursor다. 모든 가능한 손상 형식 전수를 뜻하지 않는다. 기존 encoder 바이트·서명 29조건, 저장 안전성 381개를 포함한 migration 및 host 548개(내부 비동기 저장 322개) PASS. 구형/신형 보존, 실패·응답 유실·복귀 검사는 기존 suite를 유지했다.

최종 후보 PCK `%TEMP%/ggb-owned-normalize-candidate-20261006/notebook.pck` SHA-256 `F12A45B0CD4F555FAE67ABDEBC8AD886F42233A594A7E56F740F001FEF6B0413`. import/export·migration·host 종료 0. 올바른 옵션으로 재실행한 재선택 366개와 기본 기반 검사도 PASS/종료 0이다. 재선택은 `--ggb-dev-notebook-v2`를 사용하고 기본 기반 검사는 기본 모드로 실행했다. 최종 로그는 `reselect_fixed.out.log`, `foundation.out.log`이며 관련 실행 프로세스는 모두 종료했다.

## 실행기 오류와 남은 작업

추가 실행기에 존재하지 않는 `--notebook-async-save-smoke`를 넣어 타이틀만 실행된 시도는 PASS가 아니다. 해당 격리 PID를 확인해 종료했다. 비동기 검증 근거는 실제 host suite에 포함된 322개 검사다. 재선택 suite의 처음 시도도 필요한 개발 옵션을 빠뜨려 tracker가 없는 기본 모드에서 실패했으므로 합격 근거에서 제외했다. 올바른 옵션의 재실행 로그는 기존 실패 로그와 별도로 보존한다. 집계 PowerShell의 빈 pipe 구문 오류도 수정 후 재실행했으며 측정 원자료는 변경하지 않았다.

정식 cold 20/warm 100·프레임·메모리·실제 입력, 본편 생산자 저장의 남은 지연과 IME 수정은 별도 미완료 항목이다. 기본 rollout OFF 및 기존 자료 보호 정책은 유지한다.
