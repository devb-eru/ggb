# Snapshot 아카이브 중복 검증 제거

## 기준과 범위

- 기준 develop `a353700307e85f390fe87de21ffeb86ac8717094`.
- `StateSnapshotValidator`는 대화 기록에서 `ARCHIVE.validate()`를 호출한 뒤 지식 원장에서 다시 전체 아카이브를 검증했다.
- 지식 원장 검증이 성공한 경우에만 같은 호출의 대화 기록 구조 검증을 재사용한다. 원장 오류가 있으면 기존 대화 기록 검증을 생략하지 않는다. 구형/unmapped payload의 검증도 유지한다.
- 호출 간·파일 간 검증 캐시를 도입하지 않는다. 수정된 상태, 손상 파일, 미래 버전 및 저장 확정 검사를 건너뛰지 않는다.

## 성능 측정 입력 보완

기존 성능 probe는 fixture의 archive만 snapshot에 넣고 ledger는 넣지 않았다. 이 때문에 원장이 있는 실제 저장 경로의 중복 검증을 측정하지 못했다. probe가 같은 fixture ledger도 저장하도록 수정한 뒤 그 상태를 공통 기준으로 전후 비교한다. 과거 ledger 없는 표본과 직접 비교하지 않는다.

고정 fixture 네 종류·한영 각각 cold 1/warm 3의 탐색이며 정식 cold 20/warm 100 인수는 아니다. 입력 hash와 원자료를 보존하고 측정 PASS는 기능 보존과 구분한다.

초기 warm 0 실행은 첫 표시·검색만 수행했으므로 저장 시간 근거로 사용하지 않는다. probe의 저장은 warm 반복 안에 있으므로 수정 전 보관 PCK와 최종 PCK를 warm 3으로 다시 실행한다.

## 검증 계획

- 지식 원장 suite: 중복 전체 검사 기준 경로와 정상/손상 archive·원장/출처·구형 payload의 오류 결과 동일성을 대조한다.
- 원장 성공일 때 대화 기록의 구조 검사가 중복되지 않으며, 실패/원장 미존재일 때 전체 기록 검사로 돌아가는지 검사한다.
- 기존 실제 원장 획득·재시도·보존·이관/백업/미래 버전/저장 실패 회귀를 유지한다.
- 동일 입력의 전후 실제 저장/로드 표본과 코드 결과를 남긴다. 전체 저장은 여전히 동기식이며 검색/UI 및 실제 입력 인수를 완료한 것으로 처리하지 않는다.

## 중간 실패의 구분

신규 구형 payload fixture의 첫 실행은 digest 대신 일반 문자열을 이관 함수에 전달해 실패했다. 다음 실행은 snapshot 검증 대상이 아닌 `variables` 형식을 손상시켜 거부를 잘못 기대했다. 최종 fixture는 유효한 SHA-256 식별자를 사용하고 구형 payload의 필수 `line_id`를 비운다. 이 경우 아카이브 구조는 통과해도 기존 payload 검증이 거부해야 한다. 두 실패는 테스트 준비/기대 오류이며 제품 결함으로 분류하지 않는다.

측정 래퍼는 정상 완료한 PowerShell 스크립트 뒤의 잔여 `$LASTEXITCODE`를 검사해 수정 전 측정을 잘못 실패로 보고했다. 원자료의 실패 목록 0·8개 자식 종료 코드 0·기능 PASS 및 실제 저장 세 표본/로드 한 표본을 확인했으며, 수정 후 측정은 같은 명시적 결과 검사를 사용했다. 프로세스 실패와 래퍼 판정 오류를 구분한다.

## 최종 기능 결과

- 최종 import/export와 지식 원장/이관 suite 종료 코드 0, `NOTEBOOK_KNOWLEDGE_SMOKE: PASS`, `NOTEBOOK_MIGRATION_SMOKE: PASS`.
- 신규 snapshot 조건 16개에서 기존 중복 재검증 경로와 수락 여부·오류 배열 순서가 같고 호출자 데이터가 불변이다. 원장 성공/미존재/실패, 출처·보호·형식 손상과 구형 필수 ID 거부를 포함한다.
- 지식 원장 suite의 실제 획득·저장 응답 유실 재시도·고밀도/출처·구형 표시 검사를 유지했다. 이관 suite에는 저장 안전성 159개 검사가 포함된다.
- 같은 최종 PCK의 개발 rollout 플래그 없는 기반 회귀 `FOUNDATION_SMOKE: PASS`, 종료 코드 0. 기본 모드를 별도로 확인했으며 기본 비활성 정책을 바꾸지 않았다.
- 최종 PCK SHA256: `D508401F37DA1E030677CF71861E23425573E9690CEF2733BBF9E18AB2F0AEF2`.
