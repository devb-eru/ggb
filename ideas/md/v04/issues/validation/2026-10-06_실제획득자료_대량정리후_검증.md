# 실제 A1~J2 획득 자료의 대량 정리 후 출처 소비

## 1. 기준과 범위

- 요구: 계획의 출처/보존 계약, NB-AQ06, ToDo T26k.

- 기존 순수 보존/합성 반증 검증과 구분하여, 실제 session 획득 함수가 만든 A1~J2 원장·시계 실패/해결의 출처 그래프를 정리·저장·출처 열람까지 이어받는다.

## 2. 획득과 부하의 구분

기존 NP06 suite는 표식 3종 작성/수면/A2 확인, 실제 시간표 읽기/결론, J1 복원, 탁본/배치, 시계 실패 기록, 수면과 숏컷, 신호/파형과 실패 해결, J2 복원을 실행한다. 실패의 역할/위상 일부는 기존 `_set_clock` fixture이며, 모든 퍼즐을 실제 UI로 자연 도달한 완주가 아니다.

각 언어의 J2 획득 직후 실제 원장을 그대로 가져온다. 실패 해결 revision이 이전 실패의 observation_ref를 실제 source_refs에 인용하는지 확인한다. 모든 지식의 UID·revision·본문·인용 출처를 별도로 만들어 대체하지 않는다.

등록된 `NB_PR_DUTY_1` 표시 관찰을 템플릿으로 만들고 고유 entry_uid/presentation_token/sequence를 가진 합성 일반 대사 2,003개를 추가한다. 대량 입력은 수동 버퍼 구성으로 준비하고 최종 archive 유지/검증·실제 저장 경로를 통과시킨다. 본편의 모든 writer 호출을 2,003회 실행한 것은 아니다.

## 3. 검사 계약

1. `ARCHIVE.maintain`이 실제 초과 일반 기록을 정리해야 한다. 정리 목록이 비어 있으면 실패다.
2. 보호 지식과 별도로 일반 무보호 기록이 정확히 2,000개 남아야 한다.
3. 실제 전체 원장이 정리된 archive를 대상으로 KNOWLEDGE.validate를 통과해야 한다.
4. 모든 revision의 자기 관찰과 source_refs가 정리 전/후 resolve되고, observation·sequence가 동일해야 한다.
5. 이전 실패와 해결 기록 두 참조를 비교 목록에 고정하고 실제 슬롯에 저장한다.
6. LoadCoordinator로 디스크 JSON을 복원한다. 전체 persisted snapshot이 동일해야 한다.
7. 저장 전 후보를 대신 쓰지 않고, 복원된 GameState의 archive와 원장을 query.open에 직접 넘긴다.
8. 모든 지식 detail의 epistemic 상태가 해당 revision의 당시 메타데이터와 같아야 한다. 해결 뒤 과거 실패를 최신 상태로 덮어쓰지 않는다.
9. 모든 출처 링크가 중복/자기 링크 제외 규칙대로 존재하고 실제 detail로 이동 가능해야 한다.
10. 비교 목록이 이전 실패·해결의 정확한 두 reference_key를 유지해야 한다. 자동 퍼즐 판정은 수행하지 않는다.
11. 공통 panel의 실제 해결 detail에서 이전 실패 출처 Button을 찾아 pressed signal을 실행한다. 이전 UID를 열고 이전 인식 상태를 유지해야 한다.
12. 조회/버튼 이동 이후 현재 GameState와 실제 원장은 불변이어야 한다.

일반 대사 부하 자체의 provenance·공개 시점은 합성 fixture 계약이다. 실제 획득/인용 그래프의 보존을 증명하지만 전 생산자의 공개 시점·모든 출처 공급을 증명하지 않는다.
