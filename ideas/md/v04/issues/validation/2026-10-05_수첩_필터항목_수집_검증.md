# 수첩 필터 항목 수집 비용 검증

기준 develop: `fd819c9a445a6ab0e78813ed39d00c83cd12f5e2`.
[ERR-0027](../items/GGB-ERR-2026-0027_대용량_수첩_표시검색저장_지연.md) 후속이다. 첫 화면과 필터 갱신의 불필요한 비용을 제거했으며, 전체 수첩 성능이나 Windows 입력 인수 완료는 아니다.

## 1. 원인

[notebook_query.gd](../../../../../game/scripts/systems/notebook_query.gd)의 `facets`는 일치한 행마다 9개 필터 필드를 모으면서 `value not in values[field]`로 기존 배열 전체를 검색했다. 이전 기록은 각각 별도 대화 묶음을 가지므로 L10000에서 서로 다른 세션 값이 계속 늘어난다. 이 경우 중복 확인 비용이 항목 수의 제곱에 비례할 수 있다.

[notebook_panel.gd](../../../../../game/scripts/ui/notebook_panel.gd)의 `_refresh`는 장 목록을 구성하기 위해 이 함수를 호출한다. 검색 결과가 부분 갱신되거나 페이지가 바뀌어도 같은 비검색 필터 결과를 반복 수집했다. 첫 수집의 알고리즘 비용과 불변 결과 재수집을 각각 분리해 해결했다.

## 2. 변경

- 중복 확인에 필드별 사전을 사용한다. 반환 배열은 기존 순서대로 처음 나타난 값을 append하므로 정렬·선택 값·세션 순서가 바뀌지 않는다.
- 검색어가 없는 동일 필터 결과는 모델당 최대 4개만 보관한다. 가득 차면 가장 먼저 들어간 항목을 제거한다.
- 반환 배열은 캐시와 분리된 깊은 복사본이다. 호출자가 결과를 수정해도 이후 필터 결과나 읽기 모델을 바꾸지 못한다.
- 검색어가 있는 요청은 저장하지 않는다. 검색 색인이 일부만 준비된 상태와 이후 진척을 혼동하지 않는다.
- 캐시 조회 전에도 모델 준비 상태·조회 키·필터 형식을 검사한다. 닫기 및 새 모델 구성 시 캐시와 계측 카운터를 초기화한다.
- 캐시는 필터 값만 가지며 본문·이미지·별도 저장 파일을 만들지 않는다. 기록 보존 한도, 공개 범위, 번역/원문, 세션 분류와 저장 schema를 변경하지 않는다.

기존 수첩의 불변 읽기 모델 내부에서만 재사용한다. 같은 revision이라는 이유만으로 다른 archive를 검증 없이 받아들이는 캐시가 아니다.

## 5. 재현·패키지

최종 PCK SHA-256: `D8870F7137ADEEAC3F2EF35C98489D88A692EC00559F9BE52276DBBD97E03A0E`.

```text
--headless --path <격리된 빈 경로> --main-pack <최종 notebook.pck> --
--notebook-performance-probe --ggb-dev-notebook-v2
--nb-perf-fixture=NB-PERF-L10000 --nb-perf-locale=ko-KR --nb-perf-warm=3
```

로그는 `%TEMP%/ggb-notebook-facets-before-20261005`, `facets-after`, `facets-final` 접두의 같은 날짜 폴더에 있다. 최종 import 27.0초, export 9.8초, query 64.1초, probe 25.9초로 모두 종료 코드 0/PASS였다. 이는 각 테스트의 전체 실행 시간이다. 스크립트·리소스 오류는 없었고 기존 Windows 루트 인증서 읽기 경고는 남아 있다.

같은 최종 PCK의 `%TEMP%/ggb-notebook-facets-regression-20261005`에서는 일반 호스트 375개와 비동기 저장 270개가 67.4초, 타이틀이 8.7초로 종료 코드 0/PASS였다. 비동기 검사의 프레임 진척 단언 수는 작은 후보가 즉시 완료되는지에 따라 달라질 수 있다. 이번에는 실제 Windows 창을 표시하거나 OS 입력을 보내지 않았다.

## 6. 남은 인수

모델 검증·복제·메타데이터 구성과 첫 정렬/레이아웃, 검색 색인 및 저장 시작/완료의 동기 비용은 남아 있다. 본편 생산자 미열거 분기, 실제 Windows 입력/IME·확대 UI, 장비별 cold 20/warm 100·메모리와 전체 계획 감사도 미완료다. 이번 캐시의 최대 항목 수 검사는 실제 RAM 예산 측정을 대신하지 않는다.

ERR-0027과 전체 목표는 IN_PROGRESS, rollout 기본 비활성 유지. Windows 잠금 해제 응답을 기다리는 실제 입력 검증은 이 headless 검사로 대체하지 않는다.
