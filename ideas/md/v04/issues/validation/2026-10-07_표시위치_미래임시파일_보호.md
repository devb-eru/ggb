# 표시 위치 편의 저장의 미래 임시 파일 보호

## 근거와 수정 범위

기준 develop `b6000e0a62fc191ead1ff32f7feddeeeb5277c1e`. 계획서의 미래 저장 형식 보존 및 진행/편의 상태 분리 규칙을 실제 호출 화면 위치 저장소와 대조했다. `presentation_view_store.gd`는 수첩 내부 `notebook_view_store.gd`와 별도이며, ERR-0044 수정이 자동으로 적용되지 않았다.

`load_view`/`save_view`에서 main/backup만 미래 버전을 확인하고 temporary는 새 WRITE로 덮는 문제가 있었다. [ERR-0047](../items/GGB-ERR-2026-0047_표시위치_미래임시파일_덮어쓰기.md)으로 등록했다. 이제 세 파일 모두 reader가 미래 버전으로 판별하면 빈 편의 상태·writable false 또는 save false를 반환하고 원본을 보존한다. temporary는 복구하지 않는다. 게임 저장, 표시 커서, scope/identity, schema/checksum 및 일반 primary/backup 우선순위는 변경하지 않는다.

## 재현 행렬

| 축 | 값 |
| --- | --- |
| namespace | full / development / gallery |
| 미래 파일 위치 | main / backup / temporary |
| 나머지 main/bak | 없음 / 정상 현재 버전 / 손상 |
| 미래 파일 | 현재 VERSION + 1의 JSON envelope, 보존 확인용 문자열 |
| 단언 | load 불가·빈 view, load 후 파일 경로/SHA 불변, save 거부, save 후 경로/SHA 불변 |

27조건과 정상 sibling fixture 준비 단언을 검사한다. 추가로 현재 temporary 단독 비채택·읽기 비변경, 현재 temporary 새 저장 교체, 손상 temporary와 정상 main의 저장을 검사한다. 같은 suite의 기존 실제 화면 추적기·읽기 위치·진행 상태 불변 검증도 유지한다.

수정 전 seed 181개 단언 중 미래 temporary 9조건에서 각 세 단언, 총 27개 실패/종료 1. load 자체가 파일을 바꾸지 않는 단언은 통과했다. [수정 전 출력](evidence/2026-10-07_presentation_future_before.out.log), [stderr](evidence/2026-10-07_presentation_future_before.err.log).

## 최종 검증

- Steam Godot `4.7.2.stable.steam.ed1daf0bf`, Windows headless.
- 사용자 APPDATA 대신 신규 GUID 임시 APPDATA, 임시 프로젝트의 두 수정 스크립트만 사용한다.
- seed: `--presentation-view-smoke --ggb-dev-notebook-v2`, 181개 PASS/종료 0.
- 독립 프로세스 resume: 같은 격리 APPDATA, `--cursor-phase=resume`, 6개 PASS/종료 0.
- 독립 프로세스 scaled: 같은 격리 APPDATA, `--cursor-phase=scaled`, 3개 PASS/종료 0. 이 이름의 phase는 새 문장 위치 비상속을 확인하며, 실제 배율 변경 검사는 seed의 `_cases_view` 안에서 수행된다.
- 합계 190개 단언이며 미래 보호 추가분은 seed 중 122개다.

[seed 출력](evidence/2026-10-07_presentation_future_after_seed.out.log), [resume 출력](evidence/2026-10-07_presentation_future_after_resume.out.log), [scaled 출력](evidence/2026-10-07_presentation_future_after_scaled.out.log). stderr 원본도 같은 이름으로 보존한다. 세 정상 실행에는 기존 루트 인증서 저장소 읽기 오류만 있으며 script/parse 오류는 없다. 모든 자식 PID 종료를 확인했다.

테스트 최초 작성에서 예약어 `namespace`를 반복 변수로 사용해 파싱이 실패했다. 해당 실행은 종료하고 변수명을 수정한 뒤 제품 오류 27개를 재현했으며, 구문 실패를 제품 회귀의 실패 수나 성공 근거에 포함하지 않았다.

## 한계와 남은 일

파일 생성 fixture를 사용하는 결정적 회귀이며 실제 신형 클라이언트·OS 강제 종료·동시 프로세스 쓰기는 아니다. reader의 기존 파일 크기·JSON 판별 한도 내 미래 버전 보호를 확인했다. 일반 게임 snapshot 미래 형식 및 다른 저장소의 모든 지원 행렬을 완료했다는 뜻이 아니다. NP21 전수, 생산자 전수, 성능 인수, 실제 전편 입력과 4.6.3 채택은 남겨 둔다. rollout OFF 및 제품 기준 엔진은 변경하지 않는다.
