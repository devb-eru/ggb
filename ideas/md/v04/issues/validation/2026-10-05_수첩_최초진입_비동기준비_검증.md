## 2. 검증 구성

신규 [최초 진입 검사](../../../../../game/scripts/tests/notebook_opening_smoke.gd)는 실제 C3 controller를 사용한다. 기존 [호스트 검사](../../../../../game/scripts/tests/notebook_host_smoke.gd)의 fixture 구성만 공유하고 최초 진입 직후의 상태를 따로 검사한다.

- 한국어/영어 설정에서 정상, 대화 기록 진입, 반복 갱신, 언어 변경, revision 변경/재시도, reload, slot, session, profile, 닫기 버튼, Esc, 눌린 키 유지/해제, 직접 제거, L10000의 14조건씩 실행한다.
- 준비 전에는 모델·본문이 공개되지 않고 controller가 정지돼 있는지 확인한다.
- 오래된 후보 폐기, 안전한 경우에만 세계 복귀, 최신 언어/진입 탭 유지, 고정 명령 거부를 검사한다.
- 모든 조건에서 게임 snapshot과 본 저장 파일 바이트가 불변인지 확인한다. 열람 위치용 별도 파일은 게임 저장과 구분한다.
- L10000의 모든 공개 행을 동일 입력의 동기 모델과 대조한다. 동기 비교 모델은 worker 대기 이후에 계산하여 프레임 진행 측정을 가리지 않는다.
- 공통 테스트 대기 도구는 실제 worker 완료를 프레임 단위로 기다린다. 제품의 테스트 전용 동기 모드나 검증 생략을 추가하지 않는다.
- 기존 생산자 15개 파일, 기존 챕터/프롤로그 검사 4개 파일의 진입/재열람 경로도 준비 완료 뒤 검사하도록 수정한다. 새로 비동기가 된 하위 검사의 호출부도 기다린다.

## 4. 성능 한계

L10000 보완 표본은 영어/한국어에서 각각 시작 호출 약 3,242/4,118ms, 완료 처리 약 1,600/1,434ms였고 worker 대기 중 392/365프레임이 진행됐다. 전체 공개 행은 동기 모델과 같았다.

이는 **모델 준비 중 장면 프레임이 진행된다는 근거**이지, 즉시 열림이나 첫 반응/최대 프레임 예산 합격 근거가 아니다. 시작 경로에는 슬롯 확인·snapshot 복사·기본 UI 구성이 남고 완료 시 Control 구성도 동기다. 이 계측만으로 어느 단계가 몇 ms인지 분리해 단정하지 않는다. 이전의 warm 갱신 수치와 직접 속도 향상률을 계산하지 않는다.

절전 복귀 후 별도 최신 실행에서는 영어/한국어의 시작 호출이 916.316/911.745ms, 완료 처리가 313.233/367.834ms였고 worker 대기 중 102/99프레임이 진행됐다. 다른 실행 부하의 단일 표본이므로 위 표본과 직접 성능 개선률로 비교하지 않는다. 여전히 예산 미달 가능성과 동기 구간을 남긴다.

## 5. 연동 중 발견한 복귀 오류

[ERR-0035](../items/GGB-ERR-2026-0035_완료화면_로드후_무대사이동_거부.md)는 완료된 표시 커서를 복원할 때 현재 controller의 저장 범위가 연결되지 않는 오류다. 새 controller에서도 재현했으며, 검증된 커서 복원의 완료/utility/modal 분기 전에만 현재 범위를 연결하도록 수정했다. 무대사 행동의 오래된 범위 거부 조건은 삭제하지 않았다.

결산 테스트의 합성 fixture 재사용은 테스트 소유 범위를 명시하도록 보완하고 실제 디스크 reload는 새 controller를 생성하도록 변경했다. 세 controller의 한영 무대사 이동과 두 퍼즐의 로드 후 재입력을 기존 복귀 검사에 추가했다. 최종 검사는 통과했으며 같은 변경에서 수정과 근거를 함께 반영한다.
