# 본편 수면·기상 후보 비동기 저장 검증

- 작업: T21m-b. 기준 develop `20d442fe2caa25594d9e86b92f3759c74ea85a65`.
- 범위: 1장, 검은 거울, 지하 정상 수면과 D6 침실·비상 캡슐, 파열 후 휴식. 개발 v2/async 옵션에서만 활성화한다.
- 플랫폼·런타임: Windows 격리 TEMP 프로젝트, 공식 Godot `4.6.3.stable.official.7d41c59c4`. 제품 엔진 계약/Steam 설치와 기본 rollout OFF는 변경하지 않는다.
- 이번 검사는 HEADLESS 콜백·worker·실제 디스크 저장이다. 물리 입력, 전편 자연 완주, 별도 프로세스 재개, 성능 예산 통과를 뜻하지 않는다.
- 전달 완료: develop `7e51898b386bbf4c8cc8734f890062e5022c59f3`, tree `2d495dd65ad7efa77fc8cfd65dc9d188aa26ca29`의 선택 124파일을 commit/push했다. 동일 tree 아카이브의 독립 4,909확인/6반례·449문서/76이슈 PASS, 원격 SHA와 사용자 변경 17개 SHA/미추적 보존을 확인했다. 전체 목표 완료 선언이 아니다.

## 1. 수정 내용

| 위치 | 수정 |
| --- | --- |
| `chapter_one_session.gd` | 정상/보류 수면 async 진입, 기상 대기 receipt, 기존 초기화 체인의 비공개 draft, 기상 저장만 재시도 |
| `basement_session.gd` | D6 침실·확인한 캡슐·파열 후 휴식 분리, final sleep lock/데모 제한 유지, draft 동안 부가 저장 hook 차단 |
| `chapter_one_controller.gd` | pending 동안 메뉴/이동/수첩/중복 수면 차단, 에드가 timer 일시 정지, 실패 때 명시 재시도 |
| `basement_controller.gd` | 기존 D6 확인·전환 후 async 호출. reset 완료 후 wake 실패해도 D6 화면을 성급히 E1로 교체하지 않으며 retry는 재연출 없이 저장부터 재개 |
| `dialogue_history_writer.gd` | 기존 공통 worker 경로에 wake 후보 저장 API 추가 |
| `save_manager.gd` | wake 요청 자료형 검사, 기존 storage/source/epoch/revision/guard·ACK 확인 계약 공유 |
| `notebook_save_worker.gd` | family/reset receipt 대조, 기상 허용 필드·일지 복원일·E1 최초 정보·기존 원장/원문/참조/정리 순서 검증 |

일반 reset은 기존 8개 내구 단계 다음에 별도 wake 후보를 저장한다. 초기화가 계층별로 두세 번 `_commit`을 호출해도 draft만 갱신하며 live revision과 디스크는 바꾸지 않는다. 최종 wake 후보 저장 성공 뒤에만 설치하고 기상 피드백을 표시한다. E1 관찰은 기상 후보에 포함하되 기상 화면의 대사는 기존 표시 writer가 담당한다.

wake 저장 실패 시 세션은 완료된 reset의 transaction·epoch·revision을 보존한다. 같은 세션의 명시 retry는 wake 저장만 실행한다. epoch/revision이 교체되면 옛 세션의 retry는 거부하며 새로운 로드/세션 복귀 경로가 필요하다. 이 후자의 별도 프로세스·UI 수명 인수는 T21m-c에 남긴다.

파열 후 휴식에는 reset worker 자체가 없으며 day_index, 물리 수리, reset receipt를 유지한다. 동기 기본 수면 API는 기존 동작을 유지하지만 비동기 실행/기상 retry 대기가 있는 동안은 중복 진입을 거부한다.

D6 컨트롤러는 실제 휴식 확인 버튼과 전환 콜백·실패 모달 retry 버튼을 호출했다. 6초 전환의 시간 경과는 명시 callback 인자로 가속했으며 실제 Windows 입력이나 벽시계 시간 시험이 아니다. 기타 경로는 실제 `_sleep_now` 콜백 진입을 검사하며 전체 취침 선택 UX와 자연 완주는 별도다.

모든 경로에서 원래 사용인 관계/잔존 기억, 관찰 UID/내용, archive origin/branch, 실제 책갈피와 비교 참조를 대조했다. 내구 전 E1 flag/관찰이 live에 설치되지 않음, 실패 뒤 자동 retry 없음, 완료 후 pending 해제·timer 복귀, reset 8회와 wake 1회(기상 거부 때 wake만 2회)를 검사했다.

- [근거 manifest](evidence/2026-10-10_campaign_sleep_async/manifest.json): 모든 보관 파일의 경로·바이트·SHA-256.
- [소스 기준](evidence/2026-10-10_campaign_sleep_async/source.json): 변경 7개 전후 SHA와 검사한 격리 프로젝트/공식 엔진.
- [세션 최종 원자료](evidence/2026-10-10_campaign_sleep_async/final-session/run.json), [컨트롤러 최종 원자료](evidence/2026-10-10_campaign_sleep_async/final-ui/run.json).

- 독립 감사: `scripts/audit_notebook_campaign_sleep.ps1 -EvidencePath <근거 경로> -SelfTest`. 코드 265개 지문, 7개 변경 전후, native 완료·엔진·runner/harness·원자료·사례 좌표/worker 횟수와 반례 거부를 확인한다. 과거 근거는 해당 commit 아카이브에서 검사해야 하며 최신 제품 지문으로 소급하지 않는다.

중간 `session-first`의 검사 스크립트 형식 추론 오류, `session-final`/`session-corrected`의 검사 fixture 원장 경로 오류, `session-third`의 후보 원장 기본값/부당 정리 fixture 실패 및 `current-session`의 일반 기록이 보호 대상으로 선택된 실패를 보존했다. 보호 없는 과거 P1 관찰을 실제 writer로 생성해 마지막 fixture를 교정했다. `current-session` 실행 중 외부 runner/harness 수정도 겹쳤으므로 해당 receipt의 runner 지문을 실행 코드의 확정 증거로 인정하지 않는다. 그 관찰은 실패 이력 보존용이다. `session-second`/`ui-first`의 이전 국소 성공을 보강한 최종 소스의 합격으로 재집계하지 않는다. 이후 코드와 runner/harness를 고정한 `final-*` 원자료만 이번 합격 근거다.

## 4. 후속 범위

- T21m-c: 별도 프로세스 중단/재개, owner·SaveManager 수명/종료, 최신 수정본 실제 수면 입력.
- 초기 세션 `initialize`, 일반 본편 행동·surface flush·모달/수첩 종료·단독 저장은 여전히 동기 경계가 남는다. 본편 전체를 비동기화했다는 의미가 아니다.
- 22개 생산자/소비자의 필수 분기 독립 커버리지, 정식 성능·지원 장비/해상도, 마우스/키보드 전용 완주 및 엔진 채택/rollout 인수는 계속 미완료다.
- 사용자가 정상 확인한 기존 실제 IME 다섯 국소 조건은 역사적 실기 근거로 유지한다. 이번 headless 소스의 새로운 물리 입력 성공으로 계산하지 않는다.
