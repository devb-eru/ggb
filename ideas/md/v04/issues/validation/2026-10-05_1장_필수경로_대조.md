# 1장 기록 생산자 필수 경로 대조

- 기준 develop: `1b456fccee5a0bba8da7a42b0c1648278aab836c`.
- 연결: [전체 ToDo T11b](notebook_history_TODO.md), [앞선 관찰 추적](2026-10-05_1장_기록생산자_실행추적.md).
- 범위: NP04/NP06 호출 조건에서 필수·반복·제외 경로를 구분하고 기존 검사의 빈 부분을 보강한다. 모든 상속/재방문 경로 감사는 아직 완료가 아니다.

## 발견과 조치

1. 기존 NP04 suite의 시간표 조사 fixture에는 `KN_B1_LIBRARY_WINDOW=true`가 미리 들어 있었다. 콘텐츠 존재 검사는 통과하지만 최초 B1 조사와 B1에서 B2로 넘어가는 대사의 발생 노드를 증명하지 못했다. 제품 결함이 아니라 검사 범위 누락이다. `_first_schedule_context`에서 해당 플래그를 제거하고 문서 4종 실제 읽기, 시간대 정답 입력, 상태 전환 뒤 표시까지 검사한다.
2. `_reject`는 `ok=false/text/text_id`만 반환하고, controller의 `_feedback`은 상태 라벨에 표시한 뒤 반환한다. 정상 대화와 달리 새 관찰·지식·표시 커서를 만들지 않는다. 기존 suite에는 이 계약의 직접 검사가 부족했다. 28종의 거부 조건에 한영 56개 검사를 추가했다. 각 검사는 게임 스냅샷과 revision의 불변, 대화 비활성, 비어 있지 않은 상태 문구와 내부 문자열 ID 비노출을 확인한다.
3. 데이터의 광역 허용 node 목록은 호출부의 자연 발생 경로 목록이 아니다. 이전 카탈로그/기록은 변경하지 않는다. 아래 표에서 성공 경로, UI 상태 안내, 정상 조작 중 무대사 행동, 인위적 guard fixture를 구분한다.

## 제외 검사 해석

이번 28종은 `_guard_exclusions`에 독립된 이름/입력/fixture/예상 text_id로 지정했다. 결과에서 `EXCLUDED_UI`로 집계하지만 authored 콘텐츠 수에 합산하지 않는다. 일부 잘못된 입력은 방어 조건 검사이며 실제 UI가 잘못된 값을 보낸다는 뜻이 아니다.

책상 복원 순서·앞뒤, 파형 각도 불일치 같은 즉시 조작 피드백은 현재 상태 라벨에만 나타나는 계약을 검증한다. 시계 봉인핀 실패처럼 영구 실패 지식이 필요한 사건은 `ok=true` 사건 결과의 NP04/NP06 기록으로 처리하며 이 제외 집합에 넣지 않는다. 거부 결과를 모두 서사 실패로 간주해 수첩을 생성하지 않는다.
