## 재현

PowerShell 7에서 저장소 루트를 기준으로 실행한다.

```powershell
./scripts/audit_notebook_producer_inventory.ps1 -SelfTest
./scripts/audit_notebook_producer_inventory.ps1
```

런타임 `notebook_content.gd`의 `CATALOGS`에 등록된 JSON만 읽는다. 해당 선언의 JSON 호환 배열을 파싱하며, 지원하지 않는 선언 형식은 중단한다. 디렉터리의 미등록 파일을 자동으로 포함하지 않는다. 각 카탈로그의 SHA256을 결과에 남긴다.

동일 ID의 과거/최신 의미 버전을 별도 집계한다. 동일 ID·버전 중복, 허용되지 않은 생산자, AUTHORED_ID가 아닌 행, 공개 소유자·소스 메타데이터 누락, 빈/중복 문단, 한영 제목·요약·본문 누락을 거부한다. 번역의 의미적 품질, 소스 심벌의 실재성 및 실행 연결은 별도 감사 대상이다.

## 해석 규칙

- 위 합계는 게임 이벤트 수, 필수 실행 분기 수, 테스트 단언 수가 아니다.
- 동일 문단이 여러 노드/variant/상태에서 공개될 수 있으므로 카탈로그 문단 수를 필수 분기의 분모로 사용하지 않는다.
- 한영 누락 0은 텍스트 필드 존재 검사다. 모든 화면의 번역·잘림·내부 ID 비노출 검사가 완료됐다는 뜻이 아니다.
- NP22는 갤러리/개발 소비 경로다. 등록 ID 0은 새 본편 관찰 생산 금지 계약과 양립하지만, 비오염 동작의 증거는 별도 실행 검사에서 확보해야 한다.
- `runtime_coverage=NOT_AUDITED`는 이 집계 도구가 실행 근거를 읽지 않았다는 뜻이다. 이미 수행한 개별 회귀를 무효화하지 않는다.
- `legacy_count`, `excluded_count`, `unmapped_runtime_count`, `unexecuted_required_branches`는 **null(미확인)**이다. 0으로 치환하거나 100%로 계산하지 않는다. 실제 저장 파일·제외 목록·독립 필수 호출 경로·실행 tuple 대조가 필요하다.

## 입력 검증 후속 보완

기준 develop `de61e85`. 초기 집계 도구는 `contents` 누락을 빈 순회로 처리할 수 있었고 `format_version`을 확인하지 않았다. 게임의 `notebook_content.gd._load`에는 해당 형식 거부가 이미 있어, 런타임 결함이 아닌 감사 도구의 과소 집계 위험이다.

- JSON 루트/contents/버전 맵/행의 객체 형식과 정수 format_version 1을 검사한다. 누락과 명시적인 빈 contents 객체를 구분한다.
- 빈 버전 맵·0번 버전·비객체 행을 거부한다. locale 전체가 빠져도 정상 누락 진단을 반환한다.
- SelfTest를 손상 fixture 17개로 확장했다. 명시적 빈 카탈로그와 정상 다중 버전도 통과한다.
- 보완 후 실제 29개 카탈로그 결과가 기존 JSON과 전체 일치함을 확인했다. ID/버전/문단 합계와 기존 카탈로그 SHA256은 변경되지 않았다.
- 이 보완은 실행 호출 경로의 완전성을 검증하지 않는다. T19의 남은 범위는 그대로다.
