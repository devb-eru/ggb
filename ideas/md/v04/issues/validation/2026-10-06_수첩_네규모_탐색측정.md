## 실행 조건

`scripts/measure_notebook_performance.ps1`을 네 fixture·한영, `-ColdRuns 1 -WarmRuns 3`으로 실행했다. 기존 최종 기록 검사에 사용한 export PCK이며 제품 코드는 같은 기준이다. 실행별 격리 APPDATA·빈 runtime 디렉터리·숨겨진 headless Godot 프로세스를 사용했다. 실제 사용자 세이브와 입력은 사용하지 않았다.

8개 프로세스의 종료 코드/기능 검증과 fixture 지문 일치가 통과했다. 일반 기록 상한이 보호/legacy를 밀어내지 않는지, 미공개 뒷면·미요청 힌트 검색 비노출, 입력 fixture와 live state 불변 및 실제 슬롯 저장/복원이 포함된다.

cold는 새 OS 프로세스이며 파일 캐시를 비운 것이 아니다. fixture 생성/파싱 이후 query 측정을 시작한다. warm은 같은 프로세스의 모델 작업 3회이며 실제 키보드·debounce·화면 공개를 포함하지 않는다. 장비 등급은 NOT_CLASSIFIED다.

## 해석과 다음 수정 우선순위

1. **전체 동기 저장(T21)**: L10000에서 최대 약 2.71초다. 최근 비동기 책갈피 저장 경로의 완료 dispatch와 이 수치를 혼동하지 않는다. 이 probe는 `SaveManager.save_snapshot`의 전체 동기 쓰기를 호출한다. 본편 사건 저장 경로의 UI 응답을 위해 후보 준비·검증·쓰기의 이동과 완료 후 확정 처리를 우선 검토한다. 바이트 대조·미래 버전 보호·원자 승격·성공 응답 시점은 생략할 수 없다.
2. **첫 검색(T20)**: L10000의 1.30~1.35초에는 검색 대기와 증분 인덱싱·화면 갱신이 포함된다. warm 검색 모델 최대 약 44~46ms와 구분한다. 이미 색인된 검색만 빨라졌다는 이유로 첫 검색 요구를 완료 처리하지 않는다.
3. **패널 공개(T20)**: 한국어 약 276~296ms, 영어는 대형 fixture 약 228ms와 나머지 약 63ms로 차이가 있다. 폰트/레이아웃·페이지 구성 등 세부 구간을 분리하기 전 원인을 확정하지 않는다. 두 process_frame 대기가 포함된 측정이며 순수 함수 CPU 시간은 아니다.
4. **query 생성**: L10000 약 634~640ms. 직접 모델 probe의 소요 시간이며 실제 notebook_host에서는 준비를 worker에 맡긴다. 이 값을 모두 메인 스레드 정지로 표현하지 않는다.
5. **요약 캐시**: L10000 저장 직후 inspect 최대 약 33ms. 요약 개선만으로 전체 저장이나 최종 인수를 완료 처리할 수 없다.
