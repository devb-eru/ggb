# 구형 본문 단일 조회 검증

- 기준: develop `0fe5ed7`.
- 대상: T20k / [ERR-0027](../items/GGB-ERR-2026-0027_대용량_수첩_표시검색저장_지연.md).
- 결과: 단일 본문 경로 구현과 기능 회귀 PASS. 해당 렌더 경로의 비용 감소 확인, 전체 성능 인수 미완료.
- 원자료: [계측 JSON](2026-10-06_구형본문_단일조회_계측.json).

## 원인과 변경

색인 내부에서 본문 렌더링과 공개 검색 필드 생성 시간을 따로 측정했다. L10000 변경 전 한영 표본에서 본문은 색인 처리 시간의 약 68~69%를 차지했다. 구형 기록마다 한 항목짜리 전체 이력 객체, 원문 복제, 메타데이터 결과와 배열을 만들고 변수 검사도 중복 수행했다.

`DialogueRepository.render_legacy_body`는 단일 legacy/unmapped 원문의 본문만 반환한다. 분류·payload·순번·ID·화자·변수 검증을 수행하고 원문을 직접 읽는다. payload를 수정하지 않는다. 전체 이력의 순서 검사와 오류 배열은 기존 `render_history`에 유지한다. 두 조회 경로는 `_render_legacy_payload`의 ID/화자/변수 검사와 치환 함수를 공유한다. `get_text`의 기존 오류 우선순위와 locale fallback도 유지한다.

수첩은 구형 본문을 이 경로로 읽으며 오류를 기존 `NB_QUERY_LEGACY_RENDER`로 보고한다. 구형 수첩 메모의 별도 처리, authored segment 검증, 공개 필드, 검색 시간 예산과 자료 보존 규칙은 유지한다. 저장 형식과 writer는 변경하지 않는다.

## 기능 검증

- 등록된 구형 ID 525개 × 한영의 1,050조건에서 단일 본문/전체 이력/기존 getter의 표시 동일성과 payload 불변 확인.
- 정확한 transcript 원문, integral JSON 순번, unmapped 원문 조회 확인.
- 잘못된 ID·화자·변수, 음수/소수/문자열/null/무한대/NaN 순번 및 malformed/authored 입력 거부.
- 기존 10,002개 구형 fixture의 손상 행 비노출·오류 유지·후속 정상 검색, 공개 뒷면/미요청 힌트 비노출 유지.
- query 6,879개 및 기존 검색 180개·view 224개·browse/visual/기억 공개/갤러리 회귀 PASS.
- `--dialogue-history-smoke` PASS: 기존 이력 화면의 부분 오류, 분류 필터·스크롤·한영 확대·복귀와 원문 불변 검사 유지.

검사 수는 실행 부하에 따라 예산 배치 횟수가 달라질 수 있어 고정 커버리지 분모로 사용하지 않는다. 1,050조건은 카탈로그 표시 대조이며 생산자 전체 호출 분기나 전편 완주를 뜻하지 않는다.

실행 로그: `%TEMP%/ggb-search-body-after-20261006`. Godot 4.7.2 headless import/export PASS, 기존 인증서 저장소 경고 외 script/parse 오류 없음. 이 PCK는 `3AE925C11EDEC03545E65E1F95E674D90D41E6A25B58C0BA30DD06975FADC8C3`이다. 후속 PCK에는 측정용 경로 비교 기능만 추가했으며 제품 코드와 query 테스트는 같다.

## 같은 프로세스의 본문 경로 비교

`--nb-perf-body-path-comparison=1`로 같은 repository와 같은 10,000개 구형 기록을 단일 본문→전체 이력→전체 이력→단일 본문 순으로 처리했다. 모든 원문을 배열로 대조하여 동일성을 확인하고 호출 구간을 측정했다. 한영 프로세스의 종료 코드 0과 결과 JSON ok=true를 확인했다.

| 언어 | 단일 본문 두 표본 ms | 전체 이력 두 표본 ms |
| --- | ---: | ---: |
| ko-KR | 328.906 / 319.371 | 588.963 / 600.689 |
| en-US | 410.241 / 470.528 | 765.769 / 635.699 |

이 비교는 공통 검증을 사용하는 현재 두 조회 경로의 객체 생성/복제 비용을 분리한다. 변경 전 전체 구현의 p95나 실제 검색 UI 인수를 측정한 것은 아니다. 표본 범위에서 단일 본문이 빠르지만 authored 렌더링·공개 필드 생성·프레임 대기·UI 갱신은 별도로 남는다.

처음 실행한 임시 래퍼는 실제 출력에 없는 `NOTEBOOK_PERFORMANCE_PROBE: PASS` 문자열을 찾도록 잘못 작성되어 첫 한글 실행을 실패로 보고했다. 실제 JSON은 ok=true였지만 이 실행을 최종 근거로 세지 않았다. `NOTEBOOK_PERF_RESULT` JSON과 프로세스 종료 코드를 확인하도록 고쳐 두 언어를 재실행했다. 래퍼 오류이며 게임 기능 오류로 등록하지 않는다.
