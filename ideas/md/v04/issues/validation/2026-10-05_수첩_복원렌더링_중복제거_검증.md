# 수첩 복원 렌더링 중복 제거 검증

- 기준 develop: `a9b341b3c1afade95d055c2676aae11764f37f21`.
- 대상: [ERR-0027](../items/GGB-ERR-2026-0027_대용량_수첩_표시검색저장_지연.md)의 최종 UI 교체 비용, [전체 ToDo](notebook_history_TODO.md) T21b.
- [전후 원자료](2026-10-05_수첩_복원렌더링_중복제거_검증.json). 최초 열기·전체 성능 인수 완료가 아니며 rollout 기본 비활성, 이슈 IN_PROGRESS를 유지한다.

## 1. 재현

기존 `restore_view → _complete_restore`는 첫 페이지를 만든 뒤 선택 자료의 페이지, 스크롤 앵커의 페이지를 다시 만들었다. 비교 자료도 기본 묶음, A 선택, B 선택, 최종 표시에서 각각 다시 구성했다.

기존 query fixture와 실제 Panel을 상속한 호출 계수 검사에서 다음 12조건을 확인했다.

- UI 언어: 한국어/영어.
- 글자 크기: 100%/200%.
- 복원 모드: 자료 상세/목록/비교.
- 페이지 1과 선택·비교 상태를 저장하고 같은 상태를 복원한다.

수정 전 12조건 모두 **목록 3회·비교 영역 4회**였다. 목록/비교 각 1회 조건 24개가 실패해 query 러너 종료 코드 1을 확인했다. 페이지·선택·비교·읽음 처리에 대한 나머지 새 단언은 통과했다. 이는 24개의 서로 다른 제품 결함이 아니라 같은 중복 렌더링의 재현이다.

## 2. 수정

| 경로 | 변경 | 유지하는 계약 |
| --- | --- | --- |
| 복원 | 공개된 최종 선택·페이지·스크롤 앵커를 먼저 결정한 뒤 목록 1회 구성 | 링크로 들어간 분류 밖 출처, 사라진 자료의 가까운 이웃, 목록 UID/문단 상대 위치 유지 |
| 비교 | 묶음·A/B 선택을 준비할 때 그리기를 미루고 마지막에 1회 구성 | 기존 두 칸 교환·없는 자료의 fallback·복원 시 읽음 미발생 유지 |
| 검색 대기 | 부분 검색 화면은 유지하되 검색 완료 시 복원과 별도의 목록 갱신을 중복 호출하지 않음 | 부분 결과를 최종 결과로 확정하지 않으며, 사용자 행동이 오래된 복원을 취소 |
| 목록 미리보기 | `query.preview`로 검증된 본문만 조회 | 상세와 같은 본문 검증·fallback·당시 언어. 불필요한 출처 링크/관련 자료/시각 자료 metadata는 만들지 않음 |
| 모델 교체 | 고정 편집 상태를 새 상세 생성 전에 적용 | 같은 상세를 편집 가능 상태로 다시 그리는 작업 제거. 고정 저장 완료 경계는 유지 |
| 테마 | 같은 글자 크기의 테마 재사용 | 실제 크기 변경 시 새 테마 적용, 언어 라벨 갱신 유지 |

목록에 보이는 100자 미리보기 정책은 원래 그대로다. 저장된 본문을 자르거나 원문·일반 2,000개/보호/기존 기록 보존 정책을 바꾸지 않았다. 파일 포맷과 퍼즐·대화 이벤트는 변경하지 않는다.

## 3. 회귀 검사

- 12조건 모두 목록 1회·비교 영역 1회. 복원 후 페이지/선택/두 자료/비교 모드 일치, 새 읽음 행동 없음.
- 기존 링크 뒤로 가기·정확한 링크 포커스, 페이지 중간 UID와 상대 스크롤, 누락된 자료/필터의 fallback, 압축 비교 B면 유지.
- 검색 색인 완료 대기, 100%→200% 본문 문단 위치, 사용자 입력의 지연 복원 취소, sidecar 손상/쓰기 실패 검사를 유지.
- 작성 기록 fixture의 한영 미리보기 본문·fallback·당시 언어가 상세와 일치하고 불필요한 metadata가 없는지 확인.
- 기존 원문 미리보기 일치, 손상 원문 표시 오류 유지, 없는 항목·오래된 키·닫힌 모델 거부.
- 실제 호스트의 비동기 고정/해제·재시도·닫기·scope/언어 변경·L10000 전체 공개 행 동일성 회귀.

`preview`도 준비 여부·모델 키·항목 존재를 검사하며 동일 `_render_body`를 호출한다. 표시 오류가 있는 행을 삭제하거나 검증을 우회하지 않는다.

## 4. 실행과 계측

| 최종 실행 | 결과 | 러너 전체 소요 |

| import / export | PASS | 38.0초 / 11.0초 |
| query 및 하위 회귀 | PASS, 주 검사 4,675개, view 143개 | 141.7초 |
| host 및 비동기 저장 | PASS, host 494개, 저장 270개 | 135.3초 |

저장 검사 수에는 worker 준비 중 프레임이 실제 경과했을 때만 추가되는 단언이 있으므로 직전 269개와의 차이를 새 기능 검사 하나로 해석하지 않는다. metadata 64,420개 등 하위 결과는 원자료에서 별도로 확인한다. 서로 다른 검사 수를 전체 완료율로 합산하지 않는다.

모든 최종 실행은 종료 코드 0/필수 PASS. Windows 루트 인증서 저장소 읽기 경고는 유지됐고 SCRIPT/파싱/리소스 오류는 없었다.

| 탐색 항목 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 12조건의 목록 구성 수 | 각각 3회 | 각각 1회 |
| 12조건의 비교 영역 구성 수 | 각각 4회 | 각각 1회 |

12조건은 기존 query fixture의 UI 언어/크기/모드 조합이며 장비별 정식 성능 fixture 검사는 아니다. UI 영어 설정 검사와 모든 원문의 영어 번역 인수도 구분한다. 호출 시간은 프레임을 기다리기 전 복원 메서드의 벽시계 시간으로, GPU/실제 입력 지연이나 p95가 아니다.

별도 L10000은 [직전 비동기 갱신 보고서](2026-10-05_수첩_비동기모델갱신_검증.md)와 같은 검사 경로다. 이번 시작 241.486ms, 준비 중 206프레임, 관측 최대 프레임 간격 113.911ms, 동기 모델 구성만 1585.699ms였다. 각 1회이고 실행 부하가 달라 보장된 속도 향상률을 제시하지 않는다. **수정 후에도 약 506ms의 완료 처리와 최대 약 1.04초의 복원 표본은 미해결 지연**이다.
