# 수첩 진입 중 저장 손상과 명시 재시도

## 범위

- 기준 develop: `a2c049874169007705c3e8ad29acd95c8a84552a`.
- [전체 계획](notebook_history_review_plan.md)의 저장 범위 검증·부분 오류·읽기 전용·복구 요구를 확인한다.
- 기존 첫 진입 suite의 14개 시나리오에 `disk_invalid`를 추가한다. 슬롯 이름이나 load epoch 변경만으로 저장 파일 손상을 대신하지 않는다.
- 사용자 저장이 아닌 격리 APPDATA의 `__test_notebook_host` 슬롯만 사용한다. 본파일·백업의 원래 바이트와 백업 존재 여부를 먼저 보관한다.

## 순서와 기대값

1. 정상 슬롯에서 수첩 열기를 요청하고 모델 준비 worker를 시작한다.
2. 완료 결과를 게시하기 전에 테스트 소유 본파일과 백업을 모두 잘못된 JSON으로 바꾼다. `inspect_slot()`이 unavailable인지 확인한다.
3. worker 종료 후 실제 host `_process()`로 결과를 처리한다. 숨긴 panel과 미준비 공개 모델을 유지하고 오류/재시도 화면을 보여야 한다.
4. 손상된 상태에서 재시도를 눌러도 새 worker·화면 게시·참조 쓰기를 시작하지 않아야 한다. 게임 전체 snapshot은 그대로여야 한다.
5. 원래 본파일·백업 바이트를 복구한다. 원래 백업이 없었다면 이 테스트가 만든 백업만 제거한다.
6. 실제 슬롯 재검증 후 재시도 버튼을 눌러 정상 준비를 완료한다. 요청 탭·언어·참조 편집 상태는 기존 성공 조건을 따른다.
7. 본파일·백업 바이트와 존재 여부, 게임 상태가 원래와 동일한지 확인한다. 호스트가 읽기 중 자동 복구 저장을 수행한 것으로 처리하지 않는다.

이 과정은 한영 각각 실행한다. 기존 닫기·Esc·키 유지·삭제·세션/슬롯/프로필 변경·revision 변경·언어 변경·대용량 행 보존 검사를 유지한다.

## 한계

- 저장 내용이 손상되는 시점은 테스트가 제어한다. 실제 OS 파일 잠금·디스크 분리·전원 차단을 재현한 것은 아니다.
- 두 후보가 모두 손상된 경우다. 정상 백업 fallback과 다른 run의 정상 슬롯 교체 검증을 대체하지 않는다.
- UI 입력은 headless 신호 실행이며 실제 마우스/키보드 완주가 아니다.
- 처음부터 손상되어 열기 요청 자체가 거부되는 경우와 준비 시작 후 손상은 별개다.
- 제품 코드 변경 여부 및 검증 결과에 맞춰 ToDo만 갱신하며 전체 목표는 계속 진행 중이다.
