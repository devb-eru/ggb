# 통합 수첩 계획서 재검토

## 1. 결론과 검토 범위

**보완할 사항이 있다.** 기록 보존, 최초 정보 공개, 저장 이관의 실행 규칙부터 정리해야 한다. 화면 구성의 방향은 유지할 수 있지만 현재 계획만으로 구현하면 책갈피 유실, 다른 분기의 기록 혼입, 아직 읽지 않은 정보 노출을 막는 책임이 불명확하다.

- 검토 대상: [장별 대화 기록 검토와 통합 수첩 시스템 계획](notebook_history_review_plan.md), `f157d36`의 297행 문서.
- 코드 근거: `7bb4b7e`의 저장·대화·수첩·갤러리 구현. `f157d36`은 계획서만 추가한 커밋이다.
- 방법: 원 계획의 전 절·NB-R01~10·NB-Q01~20을 코드와 기존 계약에 대조했다. 실행 테스트나 플레이테스트는 하지 않았다.
- 상태: 아래 18개 항목은 모두 `OPEN / 권장안 미반영`이다. 원 계획서와 게임 코드는 수정하지 않았다.
- ID: `NB-P01~18`은 이 재검토의 로컬 식별자다. 공식 GGB-CNF/ERR 발급이나 구현 완료를 뜻하지 않는다.
- P1: 데이터·정보 노출의 핵심 계약을 구현 전에 결정해야 함. P2: 구현 상세화에서 해소할 기능·인수 조건. P3: 기존 판단의 정확성을 바로잡을 사항.

기존 코드 문제 10개를 다시 세지 않았다. 이번 항목은 그 문제를 해결하기 위해 작성한 **계획의 모순·누락·잘못된 해석**이다.

## 2. 보완 항목

### NB-P01 / P1 / 책갈피 보존과 읽기 전용 저장 계약의 충돌

- 원 계획: 197~200행은 책갈피가 기록 삭제를 막는다고 한다. 210·219행은 책갈피를 별도 편의 저장으로 두고 저장 실패가 진행에 영향을 주지 않게 한다. NB-Q08(269행)은 책갈피에도 snapshot 불변을 요구한다.
- 문제: 책갈피가 별도 저장에만 있으면 대화 writer가 언제 이를 신뢰해 prune할지 정해지지 않는다. 반대로 `retention`을 즉시 변경하면 snapshot 불변 조건과 충돌한다.
- 재현 조건: 책갈피 표시 후 편의 저장 실패 또는 강제 종료, 다음 대사 append에서 해당 normal 항목 정리. UI는 고정됐다고 보였지만 대상 원문이 사라질 수 있다.
- 권장안: 필터·스크롤·신규 배지는 편의 저장, **내구성 있는 책갈피 참조와 보존 이유는 같은 슬롯 저장 트랜잭션**으로 관리한다. 성공 전에는 `저장 중`, 실패 시 `다시 시도`로 표시한다. `snapshot 전체 불변`을 `퍼즐·관계·진행 불변, 기록 메타데이터 변경 허용`으로 정확히 고친다.
- 완료 조건: 북마크 저장 실패·핀 해제·prune가 연속돼도 성공 표시한 책갈피 대상이 유실되지 않고 기본 보호 이유가 유지된다.

### NB-P02 / P1 / 세이브 복귀 뒤 동일 순번이 다른 대사를 가리킬 수 있음

- 원 계획: 199행은 순번으로 원문을 참조하고, 208·218행은 sequence와 슬롯 ID·저장 세대로 결합한다고 한다. 저장 세대의 정의는 없다.
- 근거: [save_manager.gd](../../../../../game/scripts/autoload/save_manager.gd) 107~115행의 `run_id`는 일반 저장에서 유지된다. 이전 snapshot을 복원하면 `next_sequence`도 이전 값이다. 서로 다른 재진행은 같은 순번에 다른 대사를 만들 수 있다.
- 문제: 존재하지 않는 참조만 숨기는 것으로는 부족하다. 순번 120이 여전히 존재하지만 다른 선택 대사일 수 있다. demo/full은 같은 `slot_01` 이름도 사용한다.
- 권장안: 대화마다 저장되는 불변 `entry_uid`를 두고 순번은 정렬 전용으로 쓴다. 새 표시에는 새 UID, 저장·불러오기에는 동일 UID를 유지한다. 조회 범위는 저장 네임스페이스·run_id·기록 출처를 포함한다. 구형 이관은 반복 실행에도 같은 UID가 되도록 원본 식별자를 기준으로 매핑한다.
- 완료 조건: 같은 슬롯의 과거 세이브에서 다른 답을 골라도 이전 책갈피가 새 대사를 가리키지 않는다. 같은 이름의 demo/full 슬롯도 섞이지 않는다.

### NB-P03 / P1 / 이관 대상이 현재 진행 슬롯에 치우침

- 원 계획: 225행은 컨테이너·마이그레이터·백업을 함께 바꾼다고 하지만 입력 형식과 진입 경로별 처리가 없다.
- 근거: [save_manager.gd](../../../../../game/scripts/autoload/save_manager.gd) 209~243행은 demo import, 246~340행은 F3 재선택 저장, 360~399행은 schema·design_revision·checksum 검사를 처리한다. [ending_gallery_store.gd](../../../../../game/scripts/systems/ending_gallery_store.gd) 13~25·50~69행은 snapshot 전체를 문자열로 보존하며 payload 해시를 파일 ID로 사용한다.
- 문제: 현재 progress만 이관하면 구형 F3 재선택·갤러리·개발 체크포인트에서 새 기록 형식과 검증기가 어긋난다. 갤러리 원문을 덮어쓰면 기존 파일 ID와 checksum도 맞지 않는다. 현재 loader는 다른 schema를 바로 거절한다.
- 권장안: progress/main·backup·F3 복사본·demo import·갤러리·개발 fixture별 이관표를 만든다. 구형 형식으로 checksum 검증 후 복사본을 변환·신형 검증·원자 저장한다. 갤러리는 원본 해시 파일을 유지하고 읽기 어댑터를 사용하거나 새 ID 보관본과 대응표를 만든다. 미래 schema는 자동 덮어쓰지 않는다.
- 완료 조건: 각 진입 경로의 구형 fixture, 중단 이관 재시도, 백업 복원, 미래 버전 거부를 별도로 통과한다. 기존 갤러리 항목도 계속 읽힌다.

### NB-P04 / P1 / 획득·처음 읽기·단순 재열람을 구분하는 규칙 부족

- 원 계획: 181·186행은 권한 있는 항목의 요약 밖 원문도 검색한다. 192행은 아직 펼치지 않은 원문을 대화 기록에 넣지 않는다고 한다. NB-Q08은 수첩 조회의 snapshot 불변을 요구한다.
- 문제: 문서를 소지했지만 뒷면·확장 본문은 아직 읽지 않은 경우, 어떤 내용이 검색 가능하며 최초 펼침을 누가 기록하는지 불명확하다. 검색 미리보기나 비교 화면이 최초 조사 절차를 건너뛸 수 있다.
- 권장안: 항목마다 `보유`, `공개 허용 부분`, `실제로 표시한 부분`, `게임 조사 완료`, `UI 신규 해제`를 분리한다. **검색·추천·링크·미리보기는 이미 표시했거나 사건이 재열람 대상으로 영구 확정한 부분만** 사용한다. 단순 보유·첫 열람 가능 여부로 미공개 본문을 색인하지 않는다. 본편에서 이미 읽은 내용 재열람은 read-only, 수첩에서 첫 읽기를 허용한 콘텐츠는 기존 정보 writer의 명시적 표시 이벤트로 처리한다. 기존 사건의 실제 조사·기록 행동을 대체할 수 있는지는 항목별로 명시한다.
- 완료 조건: 앞면만 읽은 문서의 뒷면 키워드는 검색 결과·건수·원문 스니펫·비교에 나타나지 않는다. 신규 배지를 지워도 일지 복원이나 필수 읽기가 완료되지 않는다.

### NB-P05 / P1 / 출처 연결 대상이 일반 로그 정리로 없어질 수 있음

- 원 계획: 149·154·209행은 대화·단서·원문 연결을 요구하지만 226행의 normal prune와 참조 무결성 규칙을 연결하지 않는다. 228행의 `중요한 단서 원문` 범위도 정의되지 않았다.
- 문제: 책갈피와 일부 보호 대사만 유지하면 평범한 관찰 카드의 출처 대사가 정리돼 `원문 보기`가 끊길 수 있다. 비교 트레이·반증 근거·인물 요약도 같은 문제가 생긴다.
- 권장안: 출처 참조에는 기록 종류·불변 ID·내용 버전을 포함한다. 사건상 필요한 원문은 독립 콘텐츠와 획득 증거로 보존하고, 대화 인용은 참조되는 동안 보호한다. 선택적 오래된 대사를 정말 제거하는 경우 `정리된 기록` 안내로 처리하며 다른 순번으로 연결하지 않는다. 모든 참조 소비자를 prune 이전에 검사한다.
- 완료 조건: 2,000개 초과 후 단서·가설·인물·비교·책갈피·갤러리 각각의 출처 이동을 검사한다. 일반 대화 정리가 퍼즐 자료를 없애지 않는다.

### NB-P06 / P1 / 문자열 ID 전환만으로 과거 내용의 동일성이 보장되지 않음

- 원 계획: 84·208·214행은 line_id와 당시 분기 변수로 과거 대사를 재현한다. 정보 항목에는 content_revision이 있지만 대화에는 원문 버전과 variant 식별이 없다.
- 문제: 같은 line_id의 문구가 패치에서 다른 의미로 수정되거나 동일 문서의 복원 단계가 갱신되면, 이미 읽은 과거 내용이 새로운 내용으로 바뀔 수 있다. 화자·권한 같은 숨은 변수를 재해석에 사용하면 미공개 사실을 노출할 수도 있다.
- 권장안: 발화·문서에 `content_version/variant_id`, 당시 공개한 필드와 안전한 변수 허용목록을 둔다. 의미 변경은 새 ID/버전으로, 단순 오탈자·동일 의미 번역 수정은 명시한 호환 정책으로 처리한다. 과거 버전을 제공할 수 없으면 안전한 보관 원문 또는 설명을 사용하고 최신 본문을 무조건 대신 넣지 않는다.
- 완료 조건: 관계 변화·F1 인증·언어 변경·콘텐츠 패치 뒤에도 과거 당시 드러나지 않은 문장이 생기지 않는다.

### NB-P07 / P2 / 대화 세션과 반복 접기 단위가 데이터에 없음

- 원 계획: 145~147행은 사건별 세션과 동일 세션 반복을 접지만 208행에는 사건 발생 회차와 세션 ID가 없다.
- 문제: 같은 루프에서 같은 사건을 두 번 보거나, 대화 사이에 메뉴·힌트·조사가 끼면 event_id와 loop_index만으로 경계를 정할 수 없다. `최근 세션`, 반복 수량, 선택 결과의 소속이 구현마다 달라진다.
- 권장안: `event_occurrence_id`, `conversation_session_id`, `entry_kind`(대사/표시 선택지/선택 확정/취소/자료/힌트)를 추가한다. 정상 재열람과 실제 사건 재발생을 구분하고 내용·선택·공개 범위가 같은 경우만 반복을 접는다. 중간 저장·불러오기는 같은 발생 회차를 잇는다.
- 완료 조건: 같은 사건의 동일 루프 재방문, 리셋 후 재방문, 다른 선택, 저장 실패 재시도에서 세션 경계와 중복 여부가 기대대로 나온다.

### NB-P08 / P2 / 개인 메모가 조회 기능에 섞였지만 저장·수명 설계가 없음

- 원 계획: 158행에서 개인 메모 작성을 추가했지만 206~211행의 데이터 표와 구현 단계에는 본문·초안·작성자·이력·한도가 없다.
- 문제: 메모는 원본 게임 정보를 변환해 보여 주는 기능이 아니라 새 사용자 데이터다. 현재 `knowledge_entries`에 넣으면 공식 가설과 혼동되고, 편의 캐시로 두면 삭제·복구 때 잃을 수 있다.
- 권장안: 첫 통합 수첩 범위에서는 **자료 고정·기존 가설 조회만 제공하고 자유 메모 작성은 후속 선택 기능**으로 분리한다. 포함하기로 정하면 별도 영구 사용자 노트, 자동 초안 저장, 길이·개수 제한, 삭제 복구, plain-text 렌더링, IME와 슬롯 이관을 정의한다. 사용자 메모가 정답 검증이나 SUBJECT 인증 입력으로 쓰이지 않게 한다.
- 완료 조건: 구현 범위표에서 포함/제외가 확정되고, 포함 시 앱 종료·실패·슬롯 복제 후 메모 보존 테스트가 있다.

### NB-P09 / P2 / 루프·장·출처 라벨 자체의 공개 시점이 빠짐

- 원 계획: 116·145·155·208행은 루프, 영구/이번 루프, 실제 출처와 장 필터를 사용한다. 183행은 미래 내용의 검색 노출만 제한한다.
- 문제: 주인공이 반복을 증명하기 전 `루프 2 / 영구 기록`을 기본 라벨로 보여주면 A1·A2의 발견을 UI가 먼저 설명한다. 실제 화자 ID나 전체 장 개수·연구원 역할을 그대로 표시하는 것도 같은 문제다. 내부 day_index와 BROKEN_RESET 이후 휴식의 의미도 다르다.
- 권장안: 원본 식별자는 유지하되 별도 표시 정책으로 P~A1은 `기록 순서 / 앞선 기록`, A2 이후는 밝혀진 범위의 반복 표기, D5 이후는 확인한 변화만 노출한다. 표면 이름·인격 정체·자료 출처는 각각 공개 조건을 둔다. 미도달 장의 개수와 빈 필터 항목도 숨긴다.
- 완료 조건: 새 게임·A1·A2·D5·E2 전후 스크린샷과 검색 결과에서 서사 공개 순서가 유지된다.

### NB-P10 / P2 / 힌트 최초 공개와 검색·추천의 경계가 없음

- 원 계획: 168행은 관련 자료와 양 비교 도구를 다루지만 기존 H1~H5의 최초 요청·공개 저장·재열람 경로는 없다. 힌트는 292행의 후속 콘텐츠 작업에만 언급된다.
- 근거: [chapter_one_controller.gd](../../../../../game/scripts/chapters/chapter_one_controller.gd) 588~609행에 단계형 힌트가 있고, [문서 16](../../16_색상연출_UI_접근성규칙.md) 21.2절은 힌트 공개 단계를 진행 세이브에 둔다.
- 문제: 힌트가 일반 단서 검색에 포함되면 미요청 해답을 노출할 수 있고, read-only 수첩 원칙만 적용하면 최초 힌트 공개를 저장할 곳이 없다.
- 권장안: 이미 요청한 힌트는 `도움 기록` 하위 필터에서 재열람한다. 처음 여는 다음 단계는 현재 퍼즐의 별도 `생각 정리` 요청으로 처리하고 공개 증거를 저장한다. 최근/추천/검색은 미공개 힌트를 인덱싱하지 않는다. 기존보다 높은 단계는 명시적 버튼으로 요청한다.
- 완료 조건: H1만 본 슬롯에서 H2~H5 본문이 검색되지 않고, 재로드 후 H1만 공개 상태로 유지된다.

### NB-P11 / P2 / 수첩 자료 형식과 비교 용량의 정의 부족

- 원 계획: 138~157행은 원문과 두 자료 비교를 제공하지만 도면·파형·투명지·A1 손글씨의 표현 및 확대·이동 상태를 명시하지 않는다.
- 근거: [core_overlay.gd](../../../../../game/scripts/systems/core_overlay.gd) 4행의 F0-C 자료는 B4·C5·D4 세 종류다. 기존 수첩 관련 자료 묶음도 세 개 이상을 포함한다.
- 문제: 텍스트 카드 두 개만으로 구현하면 이 게임의 시각 단서 재열람 편의가 제한된다. 다만 F0-C는 별도 퍼즐이므로 `두 칸 때문에 퍼즐을 풀 수 없다`는 결함으로 단정하지 않는다.
- 권장안: 텍스트/이미지/벡터·파형/다중 페이지 자료 유형과 읽기 전용 확대·이동·기본 위치 복구·설명 텍스트를 정의한다. 자료 묶음은 세 개 이상 담되 동시에 두 개를 보고 교체하는 방식으로 시작한다. 퍼즐 화면 복귀 시 원래 회전·배선·재료 입력은 그대로 둔다.
- 완료 조건: B4/C5/D4를 키보드로 교체·확대·출처 복귀할 수 있고, A1의 표식 형태와 압흔 정보를 색이나 축소 그림에만 의존하지 않는다.

### NB-P12 / P2 / 목록 정렬·검색·신규 해제의 결합 규칙 부족

- 원 계획: 115~118행은 최근 갱신/열람순, 139행은 50개 페이지, 141행은 마지막 위치 복구, 191행은 상세 진입 시 신규 해제를 요구한다.
- 문제: 최근 열람순 목록에서 항목을 열면 정렬이 바뀌고, 신규 필터에서는 현재 항목이 즉시 사라질 수 있다. 검색 범위·필터 AND/OR, 장/본문 전환, 같은 대사를 여러 탭에서 찾는 경우의 집계 단위도 정해지지 않았다.
- 권장안: 열람 중 목록은 조회 스냅샷에 고정한다. 신규 해제나 새 정보는 배지에 반영하고 목록 재정렬은 돌아오거나 새로고침할 때 한다. 필터는 서로 AND, 같은 필터의 다중 선택은 OR, 검색은 지정한 탭 범위라는 기본값을 명시한다. 항목 ID 기반 앵커와 조회 버전을 쓰고 사라진 항목은 가까운 유효 항목으로 복귀한다.
- 완료 조건: 51번째 항목 열기, 신규 필터에서 읽기, 언어/정렬 변경, 페이지 사이 새 기록 발생에도 선택이 엉뚱한 항목으로 이동하지 않는다.

### NB-P13 / P2 / 입력 우선순위와 첫 진입 정책이 모호함

- 원 계획: 76행은 첫 실행을 전체 최신 대화로, 141행은 최근 추가 목록으로, 234행은 메뉴 대화 바로가기로 설명한다. 235~238행은 N·Esc·IME 처리의 전체 우선순위를 정하지 않는다.
- 문제: 호출 경로별 기본 위치가 불명확하다. 검색창에서 N을 입력할 때 수첩이 닫히거나 IME Esc가 원래 선택지를 취소할 수 있다. 상세+검색+비교가 함께 열린 상태의 Esc 우선순위도 없다.
- 권장안: N 최초 진입은 최근 단서, 메뉴 대화는 마지막 대화 위치(없으면 최신), 출처 링크는 대상 상세, 현실 N은 물리 수첩으로 명시한다. IME 조합·텍스트 편집 → 활성 팝업 → 상세/검색 → 수첩 → 호출 화면 순으로 입력을 소비한다. 수첩 닫기 키는 텍스트 입력 중 작동하지 않게 한다. 관찰 필수 장면·파열 연출·엔딩에서 열 수 있는 경계도 표로 만든다.
- 완료 조건: 검색창에 n/N을 입력하고 IME Escape·Enter를 사용해도 닫힘·원래 선택 확정이 없다. 모든 진입점의 이전 화면·포커스가 복원된다.

### NB-P14 / P2 / 보존 상한의 예외가 일반 기록을 모두 밀어낼 수 있음

- 원 계획: 226~227행은 보호가 2,000개를 넘으면 상한 예외를 허용하고 미분류 legacy는 prune하지 않는다.
- 문제: 보호가 2,000개 이상이면 normal을 정리하는 단순 구현은 새로 본 일반 대화까지 곧바로 지울 수 있다. 전부 legacy인 장기 세이브에는 이관 완료의 의미와 용량 관리가 없다. `동일 반복 접기`는 저장량을 줄이지 않는다.
- 권장안: 보호 예외와 별도로 최근 normal 창을 유지하는 규칙을 승인 계약에 명시한다. 예시 권장값은 normal 최근 2,000개, 보호·legacy는 별도 페이지 보관이며, 기존 전체 2,000개 계약 변경으로 취급한다. 승인 전에는 기계적으로 삭제하지 않는다. 무손실 장기 보관·페이지 단위 로드로 해결하고, 한계 도달 시 진행이나 원문을 조용히 버리지 않는다.
- 완료 조건: 보호만 2,001개인 상태에서 새 일반 대사를 읽어도 직전 대화가 보인다. 대형 legacy를 강제로 normal로 바꾸지 않는다.

### NB-P15 / P2 / 원문 ID·요약·출처 매핑 제작 범위가 누락됨

- 원 계획: 84행은 새 기록을 원본 ID로 전환하고 215행은 기존 데이터에서 어댑터로 카드를 만들며, 292행은 콘텐츠 의뢰에 연결한다고만 한다.
- 근거: [dialogue_history_writer.gd](../../../../../game/scripts/systems/dialogue_history_writer.gd)는 현재 단일 transcript ID를 쓰며 [chapter_one_session.gd](../../../../../game/scripts/systems/chapter_one_session.gd) 410~413행은 수첩 항목을 문자열로 덮어쓴다. 모든 실제 문장이 이미 안정적인 ID·이력·장소를 가진 것은 아니다.
- 문제: 어댑터가 없는 원문 ID나 과거 개정·발견 순서를 만들어낼 수 없다. 일지·관계·힌트·선택·물리 수첩 중 어디까지 공급해야 시스템이 완성되는지 인수 범위가 없다.
- 권장안: 화면에 기록되는 모든 생산자에 대해 `현 저장 경로 → 원문 ID/variant → 화자/사건/장소 → 공개 조건 → 단서 카드 → 보존 등급 → 담당` 대응표를 먼저 만든다. ID 전환 완료 구간과 안전한 legacy 대체 구간을 표시한다. 과거에 없는 발견 시점·수정 이력은 미상으로 둔다.
- 완료 조건: 프롤로그부터 두 엔딩까지 화면 기록 생산자의 누락 건수를 보고할 수 있고, 신규 콘텐츠가 매핑 없이 추가되면 검사에서 잡힌다.

### NB-P16 / P2 / 단계별 선행 조건과 회귀 통과 기준 부족

- 원 계획: 248행의 1단계에서 올바른 장 매핑을 완료하지만 사건 메타데이터는 2단계에 있다. 252행은 접근성·통합 검증을 마지막 단계로 모으고, NB-Q01~20에는 대부분 정상 경로만 있다.
- 문제: 정확한 사건 캡처 없이 화면 필터만 고치거나, UI를 완성한 뒤에야 입력·저장 실패를 발견할 수 있다. 기존 스모크와 신규 스키마 테스트를 어느 단계에서 통과해야 하는지도 불명확하다.
- 권장안: 1단계를 조회 복구와 최소 사건 발생 정보 전달까지, 2단계를 전체 형식·이관·보존으로 구분한다. 매 단계에 단위/통합/마우스·키보드 인수를 배치한다. 3단계 전에는 권한 필터와 불변 식별자, 4단계 전에는 출처 보존이 완료돼야 한다. 새 렌더러 전환 전 구형 읽기 경로와 병행 검증하고 저장 이관 후 구형 바이너리로 임의 다운그레이드하지 않는다.
- 완료 조건: 아래 3절의 추가 테스트와 기존 기록 스모크의 중복 방지·부분 오류·재로드 조건을 단계별로 연결한다.

### NB-P17 / P2 / 성능 목표에 측정 기준과 데이터 조건이 없음

- 원 계획: 256행의 200/100/400ms는 측정 전 제안이다. 139행의 페이지 제한은 UI 행 수만 제한한다.
- 문제: 한 페이지를 그리기 전에 전체 로그를 렌더링·복제한다면 50개 제한으로 느린 최초 열기를 해결하지 못한다. 기준 PC·콜드/웜·p95·데이터 길이·보호 비율이 없어 통과 판정도 재현되지 않는다.
- 권장안: [성능 예산](../../../../../docs/technical_performance_budget.md)의 장비 계층과 빌드·렌더러·저장매체를 기록한다. 2천 normal/1만 legacy/보호 초과/긴 한영 본문을 고정 fixture로 만들고 최초 열기와 필터·검색을 분리 계측한다. 권한 범위 필터 → 최소 메타 색인 → 선택 페이지 본문 해석 순서를 정한다. 언어·슬롯·공개 범위·콘텐츠 버전 변경 시 캐시를 무효화한다.
- 완료 조건: 목표값은 동일 조건의 p95로 보고하며 원문 저장·로드 시간, 메모리 증가, 입력 프레임 정체를 함께 남긴다. 측정 전에는 성능 통과라고 하지 않는다.

### NB-P18 / P3 / 기존 테스트를 승인 계약과 충돌한다고 단정한 표현

- 원 계획: 83행과 290행은 과거 영어 보존 테스트와 ID 기반 현재 언어 표시를 계약 충돌로 기술한다.
- 근거: [basement_session_smoke.gd](../../../../../game/scripts/tests/basement_session_smoke.gd) 1772~1795행은 언어를 바꿔도 저장된 항목이 그대로 있는지 검사한다. 새 조회 화면이 반드시 영어로 표시되어야 한다는 검사는 아니다.
- 문제: `저장 원본 불변`과 `현재 언어 표시`는 양립할 수 있다. 진짜 차이는 현행 저장 본문이 문자열이라는 구현 형태와 승인된 ID 저장 계약이다. 표현을 그대로 따르면 유효한 원본 보존 테스트를 없앨 수 있다.
- 권장안: `저장 표현 전환에 따른 테스트 상세 조정 필요`로 정정한다. 저장된 관찰 사실·원문 보존 검증은 유지하고, 별도의 현재 언어 렌더링 검증을 추가한다. 이미 저장된 legacy 원문을 삭제하거나 번역문으로 덮어쓰지 않는다.
- 완료 조건: 언어 변경 전후 저장 항목 동등성, 새 ID 기록의 현재 언어 표시, legacy 원문 표기가 각각 독립적으로 검증된다.

## 4. 우선순위와 개정 순서

1. **저장·정보 공개 계약부터 확정:** NB-P01~06. 이 단계가 없으면 UI 개선 중 데이터 유실·분기 혼입·스포일러 방지를 검증할 수 없다.
2. **기능 범위와 데이터 생산을 확정:** NB-P07~11·P14·P15. 개인 메모의 포함 여부, 세션 단위, 힌트, 시각 자료, 보존 예산을 결정한다.
3. **화면 동작과 구현 인수 기준을 상세화:** NB-P12·P13·P16·P17. 호출별 초기 위치·입력 우선순위·목록 안정성·성능 환경을 명시한다.
4. **검토 문구 정정:** NB-P18. 원본 보존 테스트를 삭제하지 않는다는 점을 먼저 고친다. 실제 문서 개정 시 1번과 함께 반영할 수 있다.

## 5. 검토 범위에서 추가 결함으로 세지 않은 사항

- 기존 6개 분류를 4개 상위 분류로 묶는 것 자체는 제안으로 명시되어 있으므로 계약을 이미 위반한 구현으로 취급하지 않았다.
- 두 자료 비교만으로 F0-C를 풀 수 없다고 판단하지 않았다. 계획은 게임 판정 도구와 읽기 전용 비교를 분리하고 있으며, 세 자료 재열람의 편의가 보완 대상이다.
- 스크린 리더 직접 지원은 [제품 계약](../../../../../docs/product_contract.md)에서 1.0 필수가 아니다. 실제 지원 검증 전 선언하지 않는다는 계획 문구는 유지할 수 있다.
- 50개 책갈피·50개 페이지라는 수치는 제안값이다. 그 수치 자체보다 데이터 보존과 성능 검증 방법을 문제로 삼았다.
- 코드를 실행하지 않았으므로 실제 UI 멈춤·저장 손상·성능 저하가 재현됐다고 주장하지 않는다. 본문은 그러한 실패를 막기 위해 **계획에 추가해야 할 계약**을 설명한다.
