# 갤러리·개발 소비 scope 대조

## 기준과 요구

develop `c2bb71d`, 검토 계획 16절 NP22: 갤러리/개발 소비는 새 본편 관찰을 만들지 않고 보관 payload·원본 어댑터·scope를 분리한다. T17의 NP21 정적 보드·오브젝트 전체 제외/누락 감사와 구분한다.

## 재현·수정

집중 검사 52개에서 7개 단언 실패를 재현했다. 두 build flavor와 재선택 슬롯의 개발 출처 네 namespace 기대 중 4개, provenance 변경 양방향 2개, 같은 슬롯·원장 ID의 namespace별 편의 경로 격리 1개다. 실제 정보 유출의 재현이 아니라 namespace 계약 오류의 재현이다.

추가로 commands의 scope 토큰에도 같은 슬롯명 전용 판정이 있었다. host만 수정한 중간 상태에서 commands 일치 단언 4개가 실패했다. 이 재현을 확인한 뒤 namespace 정책을 commands의 공통 helper로 묶어 host 생성·생존 확인·commands 쓰기 토큰이 같은 provenance를 사용하도록 수정했다.

namespace 판정은 기존 개발 슬롯 접두사 또는 debug의 `reselect_source_slot_id` 개발 체크포인트 출처를 사용한다. 원본 개발 엔딩 프로필의 판정과 일치시킨다. 이전 full 편의 파일은 보존하고 자동 이관하지 않는다. 파일 저장 경로의 build_flavor 자체를 바꾸는 작업은 아니며 새 복사본의 slot/run/branch는 유지한다.

`notebook_save_worker._prepare_with_storage`에도 독립된 슬롯명 판정이 있었다. 이를 남기면 새 development 토큰과 worker의 full 토큰이 달라 자료 고정 저장이 거부된다. 정상 harness의 비동기 developer_copy 시험에서 commit/summary/live commit 세 단언 실패를 재현했다. 순수 namespace 함수를 worker에도 적용해 전달된 snapshot의 출처로 계산하며 live Node/씬 접근은 추가하지 않았다. 최종 정책 검사 68개와 비동기 저장·재로드 20개 PASS다. 초기 비동기 harness의 preload는 autoload 등록 전 GameState를 찾지 못해 실패했으므로 등록 후 deferred load로 수정하고 그 실패는 제품 재현으로 세지 않았다.

초기 시험 harness에 타입 추론 오류와 SceneTree 등록 순서 오류가 있어 컴파일/실행에 실패했다. 120초 watchdog으로 시험 프로세스만 종료한 뒤 harness를 수정했다. 공유 정책 리팩터링 중 `namespace`를 변수명으로 쓴 초안도 예약어 parse 오류로 실패해 `namespace_id`로 수정했다. 두 실패를 정상 재현/성공 결과에 포함하지 않으며, 이후 최종 코드로 회귀를 다시 실행한다. 정상 harness에서 수정 전 7개 실패, 중간 commands 4개 실패, 최종 68개 PASS/종료 0을 확인했다.

## 검증 상태

- 집중 `notebook_scope_smoke.gd`: namespace 16조합과 commands 일치·live scope·원장 불변·편의 경로 검사, 최종 68개 PASS. fake 서비스의 분류 검사이며 실제 F3 파일 생성 검사와 구분한다.
- 기존 `developer_checkpoint_smoke.gd`: 실제 개발 F3 capture/copy/load 후 수첩 namespace development·복사본 고유 slot/run·commands development 단언 추가, 종료 0/PASS.
- worker 추가 수정 전 query 6,863개(68개 scope·갤러리 232 포함) 종료 0/PASS. 최종 순수 정책은 독립 68개로 다시 확인했다. worker 추가 수정 후 host 548개(비동기 340개 포함) 종료 0/PASS. 검사 시점/범위를 구분하고 서로 중복 합산하지 않는다. 단일 headless 성능 표본은 인수 PASS가 아니다.
- Godot 4.7.2 Steam, 숨긴 headless 검사, 격리 APPDATA. 환경의 root certificate store 오류는 별도이며 인증서/네트워크 성공 근거로 삼지 않는다.

개발 회귀의 일반 슬롯/프로필 fingerprint 비교는 격리 초기 환경에서 수행했다. 기존 유효 일반 슬롯·갤러리를 미리 채운 상태의 전수 byte 보존 행렬을 대체하지 않으므로 이 조건은 후속 T17b에 남긴다. 갤러리 suite 자체는 시험으로 생성한 유효 캡처 두 개를 실제 열고 비교해 파일 불변을 검사한다.

전체 전편 OS 입력·IME 후보 기준 채택·정식 성능 인수·NP21 전수 분류 및 NP22의 미리 채운 일반 데이터 보호 행렬은 아직 미완료다. 이번에는 ERR-0045의 namespace·명령·worker 일치와 확인한 소비 경로를 검증했다.

증거 파일은 `evidence/2026-10-07_scope_*.log`에 보관한다. baseline은 초기 7개 실패, commands_baseline은 추가 4개 실패, worker_baseline은 비동기 3개 실패를 각각 담는다. policy_final/worker_final/host_final/developer_final/query는 위 검사 시점별 정상 결과다. 재실행은 격리 APPDATA에서 `--notebook-host-smoke`, `--developer-checkpoint-smoke`, `--notebook-query-smoke`에 `--ggb-dev-notebook-v2`를 붙인다. 실제 마우스·키보드 전편 입력으로 세지 않는다.
