# 수첩 저장 구간 프로파일

## 기준과 목적

- 기준 develop `f5b733e23b296726e32fec00ff2b84823f4ba5de`.
- snapshot 중복 검증 제거 뒤에도 저장 수 초가 남았다. 다음 변경을 전체 저장 근거에 맞추기 위해 실제 저장 함수의 주요 구간을 계측한다.
- 제품 `SaveManager` 구현은 변경하지 않는다. 테스트의 선택형 subclass가 같은 super 함수를 호출하고 시간만 수집한다. 기본 측정은 기존 autoload를 사용한다.

## 측정 계약

| 구간 | 의미 | 합산 주의 |
| --- | --- | --- |
| `total_ms` | 실제 `save_snapshot` 호출 전체 | 영속 성공 반환까지의 시간 |
| `read_and_validate` | main/bak/tmp 파일 읽기·검증 | 각 호출은 별도 표본 |
| `validate_text_nested` | 해당 읽기 내부의 JSON/체크섬·이관/상태 검증 | 부모 읽기 시간에 포함됨. 별도로 더하지 않음 |
| `encode_payload` | canonical payload·서명·최종 직렬화 | 읽기/승격과 겹치지 않음 |
| `commit_prepared` | 백업·본파일 교체·tmp 승격 | 읽기 검증이나 payload 생성 제외 |
| 미분류 잔여 | 전체에서 비중첩 읽기/encode/commit 합계를 뺀 값 | 후보 준비·쓰기/flush·후속 처리·계측 비용이 섞임. 특정 함수 비용으로 단정하지 않음 |

`start_ms`는 같은 저장 호출 시작 대비 시간이다. 호출 순서와 중첩을 원자료로 보존한다. 측정 subclass의 자체 요약 캐시를 사용해 저장 뒤 inspect/load도 같은 관리자에 연결한다. 실제 파일 승격/검증·보존·실패 판정은 그대로다.

## 실행

```powershell
./scripts/measure_notebook_performance.ps1 -GodotPath <godot.exe> -PackPath <notebook.pck> -ColdRuns 1 -WarmRuns 3 -ProfileSaveStages -OutputDirectory <new-empty-directory>
```

- 네 fixture·한영 각각 새 프로세스, 실제 저장 3회씩 총 24회와 로드/내용 동일성 검사.
- `-ProfileSaveStages`는 `--nb-perf-save-profile=1`을 전달하며 계측 결과를 `save_stage_profile`에 기록한다.
- warm 0의 계측 요청은 경로 확인/디렉터리 작성 전에 거부한다. warm 0에는 저장 반복이 없기 때문이다. 해당 거부 검사 PASS.
- 계측 실행은 항상 `sampling_complete=false`이며 정식 성능 인수에 합산하지 않는다. 일반 실행 대조는 옵션 없이 N2000 한국어 저장 1회를 수행하고 profile 배열이 빈 값인지 확인한다.

## 남은 인수

- 실제 OS 입력·고정 장비 cold 20/warm 100·프레임/메모리 인수는 아니다.
- 저장 구간 근거가 나오기 전 개선율이나 주 병목을 미리 확정하지 않는다. 전체 기능·생산자·성능 및 기본 rollout 상태는 유지한다.

## 결과와 다음 개선 지점

- 최종 import/export 종료 코드 0. 네 fixture·한영 8개 프로세스의 기능 PASS, 실제 저장 24회와 로드 8회 및 입력/게임 불변 확인.
- 각 저장에 encode/commit이 정확히 한 번 존재하며 상위 구간은 겹치지 않고 전체 시간 안에 들어간다. 모든 nested text 검증은 파일명이 같은 정확한 부모 읽기 호출에 포함됨을 원자료에서 확인했다.
- 옵션 없는 N2000 한국어 대조 1회 기능 PASS, `profiling_mode=STANDARD` 및 빈 profile 배열. warm 0 계측 거부도 PASS.

다음 구현은 다음 순서로 진행한다.

1. `encode_payload`의 반복 전체 직렬화를 제거할 수 있는지 검토한다. 기존 canonical 서명·최종 바이트 동일성·구형/신형 로드·checksum 거부를 먼저 입증하며 형식을 변경하지 않는다.
2. 가장 큰 읽기·검증과 미분류 잔여를 더 분리한다. 잔여 전체를 후보 검증 비용으로 간주하지 않는다. 미래 버전/손상/백업 검증을 캐시나 생략으로 숨기지 않는다.
3. throughput 개선으로도 UI 예산을 만족하지 못하면 실제 본편 저장의 준비 단계 비동기화·stale/중단/확정 경계를 검토한다. 기존 수첩 참조 worker만으로 본편 저장이 비동기라고 주장하지 않는다.

이는 순차 단일 탐색 실행이며 첫 저장은 빈 슬롯, 뒤 저장은 main/backup이 늘어난 조건이다. 같은 steady-state 표본이나 정식 p95가 아니다. CPU 부하/캐시/계측 비용 영향이 있어 앞선 비계측 실행과 성능 개선율을 비교하지 않는다. ERR-0027과 전체 T20/T21/T24는 미완료다.
