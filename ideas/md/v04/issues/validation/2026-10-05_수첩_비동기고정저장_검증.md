# 수첩 자료 고정의 비동기 저장 검증

기준 develop: `2d970c7dc5b1b97e2d9d9b11541cd877e9aeb05a`.
대상은 [ERR-0027](../items/GGB-ERR-2026-0027_대용량_수첩_표시검색저장_지연.md)의 **수첩 책갈피·비교 자료 고정/해제** 경로다. 전체 저장·조회 비차단화나 성능 인수 완료가 아니다. 전체 목표와 오류 상태는 IN_PROGRESS, 개발 rollout 기본 비활성은 유지한다.

## 1. 구현 경계

| 단계 | 실행 주체 | 허용 / 금지 |
| --- | --- | --- |
| 요청 | 메인 스레드의 SaveManager | 현재 snapshot 복제, 명령 ID·revision·load epoch·슬롯·저장 루트·호스트 guard 캡처. 서비스당 후보 1개 |
| 준비 | 별도 Thread와 전용 worker | 본파일/백업 실제 바이트 검증, 독립 snapshot의 참조 변경·검증·직렬화, 명령 전용 임시파일 쓰기·재검증 |
| 준비 중 | 수첩 / 다른 게임 상태 작성자 | 읽기 UI는 유지, 고정 변경 중복 입력은 제한. 다른 저장·로드는 허용하며 후보를 stale로 만듦 |
| 확정 전 | 메인 스레드 | 취소, 호스트·세션·프로필, revision/load epoch, 저장 루트와 빌드 범위, 원본/백업/임시파일 바이트 지문 재확인 |
| 확정 | 메인 스레드 | 확인과 파일 승격·GameState 설치 사이에 await 없음. 영속 성공 후에만 고정 상태 반영 |
| 정리 | 메인 스레드 | 종료한 Thread join, 해당 명령 임시파일만 제거, 작은 완료 결과 최대 8개 보관 |

worker에는 활성 GameState, 호스트, UI를 넘기지 않는다. worker 내부에서 생성한 저장 도우미 Node는 SceneTree에 넣지 않고 같은 worker에서 해제한다. 콘텐츠 초기화 완료 표시는 카탈로그 구축 후 mutex 안에서 발행하고, 공유 정규식 사용도 보호한다. 스레드 안전성 검사를 끄지 않는다.

임시파일은 `progress.notebook_<command_id>.tmp.json`이다. 기존 동기 저장의 임시파일과 분리한다. 새 스키마나 별도 수첩 저장 파일은 만들지 않으며 원문·보호 이유·고정 변경은 동일 snapshot으로 저장된다.

정상 본파일만 복구 백업을 대체할 수 있다. 손상 본파일에서 정상 백업을 사용했다면 그 백업의 run ID를 유지한다. 승격 실패 시 기존 검증된 본파일을 복구하고, 성공 응답만 소실된 경우 transaction과 snapshot이 실제 저장된 것을 재검증한 뒤 성공으로 처리한다. 실패를 무조건 성공으로 바꾸지 않는다.

이것은 게임 프로세스 안의 저장/로드 충돌을 검사하는 계약이다. 외부 프로그램의 동시 파일 쓰기를 막는 프로세스 간 잠금이나 전원 손실에 대한 추가 보장은 도입하지 않았다.

## 2. 수첩 동작

- 고정 버튼을 누른 뒤 즉시 성공 표시를 하지 않는다. 저장 안내를 표시하고 추가 고정 입력을 막는다.
- 저장 중 닫기를 누르면 원래 장면을 재개하지 않고 저장 완료를 기다린다. 성공하면 원래 포커스·장면으로 복귀한다.
- 실패하면 수첩을 열어 둔 채 재시도/취소를 제공한다. 재시도는 동일 명령 ID를 사용하며 기존 고정 상태가 유지된다.
- 슬롯·세션·로드·프로필이 달라졌거나 호스트가 제거되면 준비된 후보를 적용하지 않는다.
- 앱 종료 시 진행 중 worker를 join하고 후보를 폐기한다. 종료 시 대기가 발생할 수 있으며 즉시 중단 가능한 디스크 I/O를 구현한 것은 아니다.
- 기존 동기 `save_snapshot`과 테스트용 동기 명령은 유지한다. 실제 수첩 호스트만 새 API를 우선 사용한다.

## 5. 실행 기록과 미완료

최종 로그: `%TEMP%/ggb-notebook-async-final-20261005`. 명령은 export PCK를 빈 runtime에서 실행한 `--notebook-host-smoke --ggb-dev-notebook-v2`다. 저장 안전성은 독립 실행 옵션이 아니라 `--notebook-migration-smoke`에 포함된 검사다.

| 최종 실행 | 결과 / 전체 테스트 실행 시간 |
| --- | --- |
| import / export | PASS / 23.9초, 10.5초 |
| host + 비동기 저장 | PASS / 132.9초, 호스트 375개·비동기 269개 |
| migration + 저장 안전성 | PASS / 20.6초, 저장 안전성 138개 |
| query + 하위 검사 | PASS / 169.6초, 주 검사 1,411개·메타데이터 64,420개·갤러리 189개 등 |
| 기존 모드 foundation | PASS / 14.6초 |

모두 종료 코드 0과 필수 PASS를 확인했다. 위 시간은 사용자 동작 지연이 아니라 전체 테스트 실행 시간이다. 스크립트·리소스 오류는 없었지만 Windows 루트 인증서 저장소 읽기 경고는 남아 있다. 경고를 성공 로그에서 숨기지 않는다.

동일 최종 PCK의 추가 회귀 `%TEMP%/ggb-notebook-async-regression-20261005`도 종료 코드 0/PASS였다. 타이틀 14.4초, 개발 체크포인트 89.4초, v2 foundation 11.1초, 기존 대화 기록 6.9초다. 기존 동기 저장 공통 헬퍼 분리로 인한 회귀를 함께 확인했으며, 전체 본편·모든 관계 분기·실제 OS 입력 완료로 확대 해석하지 않는다.

선행 실패도 보존한다. `async-initial`은 worker의 예약어 지역 변수 문법 오류로 중단했고 수정했다. `async-second`는 승격 실패 시 백업이 이전 정상 본파일로 갱신되는 기존 계약을 테스트가 잘못 가정해 실패했으며 그 기대값을 교정했다. `async-third`의 호스트는 PASS였다. `async-verified`의 호스트·migration·query·foundation은 PASS지만 존재하지 않는 독립 safety 옵션 실행을 종료했으므로 해당 러너 전체를 PASS로 세지 않는다. 최종 러너에서는 그 옵션을 제거했다.

남은 작업:

1. 첫 모델 구성·검색·성공 후 refresh 지연과 시작 snapshot 복제/최종 설치 비용을 계측·개선한다.
2. 본편 대화·사건 등의 동기 저장 경로에는 새 수첩 API를 기계적으로 적용하지 않는다. 각 생산자의 영속 성공 시점과 콜백 수명을 먼저 설계한다.
3. 장비별 cold 20/warm 100, p95/최대·RAM, 실제 Windows 키보드/마우스·IME·200% UI를 검증한다.
4. 실제 Windows 입력은 잠금 해제 응답 대기 상태다. 이번 자동 검사는 그 공백을 대체하지 않는다.
5. 생산자 22종의 미열거 분기와 전체 계획 인수는 여전히 남아 있다.

스레드 설계 참고: [Godot 스레드 안전 API](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html), [Thread](https://docs.godotengine.org/en/stable/classes/class_thread.html), [Mutex](https://docs.godotengine.org/en/stable/classes/class_mutex.html). 활성 SceneTree 접근 금지, worker join, 공유 상태 동기화 원칙만 참고했으며 실제 통과 근거는 위 테스트다.
