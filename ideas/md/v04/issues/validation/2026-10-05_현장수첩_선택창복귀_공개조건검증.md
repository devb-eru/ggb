## 3. 확인한 계약

1. 질문/본문을 관찰 기록에 먼저 저장한다. 열람 표시만으로 물리 수첩의 읽음 상태를 완료하지 않는다.
2. 확인 또는 다음 장 선택 답변은 HISTORY 저장으로 남기되, 이어지는 실제 게임 저장을 정확히 한 번 거절한다.
3. 게임 저장이 실패하면 `selection_pending` 커서를 유지한다. 물리 진행·지식·관계·읽음 상태는 변경하지 않는다.
4. 상태 비교는 원래 archive 항목을 보존하고 추가 관찰과 유효한 출처로 뒷받침된 화면 receipt만 허용하는 기존 비교기를 사용한다. 임의로 진행 필드를 삭제해 비교하지 않는다.
5. 실제 테스트 슬롯에서 load하고 controller를 제거·재생성한다. 원래 답변 토큰과 페이지를 복원하며 읽음 처리나 다음 장 이동을 자동 재실행하지 않는다.
6. 명시 재시도는 저장 성공 응답 유실에서도 정확한 페이지와 요약/전문 읽음 상태를 적용한다.
7. 확인 재시도는 페이지를 닫는다. 다음 장 재시도는 정확히 다음 페이지를 열며 마지막 뒤표지에서 표지로 돌아가는 경우도 검사한다.
8. Esc 취소는 물리 읽음 처리를 수행하지 않는다. 이미 기록된 시도 답변은 삭제하거나 성공 기록으로 바꾸지 않는다.
9. 재시도/취소 뒤 원래 답변은 한 개로 동일하게 유지된다. 이전 callback은 다시 읽음 처리하거나 페이지를 넘길 수 없다.

## 4. 비공개 조건

각 사용인 페이지에서 완료 플래그가 false인 상태에 유효 outcome을 두거나, 완료 플래그는 true지만 outcome을 알 수 없는 값으로 둔다. 요약과 전문 각각에서 모든 `addendum_<outcome>` 참조를 조회할 수 없으며 실제 표시 본문에도 부기 접두문이 나타나지 않는지 검사한다. 본문 자체는 정상적으로 읽을 수 있어야 한다.

이 검사에서는 연구원 전체 상태를 임의로 완료시키지 않는다. 기존 `_field_choices`가 다루는 정상 완료 결과의 부기 표시와 함께 확인해 항상 감추는 구현도 통과시키지 않는다. 다만 모든 손상 저장 형태를 전수 검사한 것은 아니다.

## 6. 남은 범위

- 같은 프로세스 내 디스크 load/controller 재생성이다. 이 144경로를 별도 OS 프로세스 종료·재시작한 결과는 아니다.
- 실제 Windows 입력·IME·포커스·접근성 및 성능 인수는 별도다.
- 이번 행렬은 게임 저장 실패에 집중한다. 모든 페이지별 질문/답변 저장 실패, 전체 출처 마스크·관계 조합과 실패의 곱집합까지 검증하지 않았다.
- 이미 읽은 페이지의 재확인 계약은 기존 `notebook_modal_presentation_smoke::_idempotent_field_read`의 별도 근거로 유지하며 이번 실행에서 그 suite를 재실행하지 않았다.
- 전체 NP05 감사의 최종 대조와 다른 생산자, 엔딩 전후 경계는 T12~T19에 남긴다. 전체 목표 완료로 체크하지 않는다.
