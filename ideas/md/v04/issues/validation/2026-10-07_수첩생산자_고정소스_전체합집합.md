# 수첩 생산자 고정 소스 전체 합집합

## 목적과 범위

- 기준 develop: `962a8c8043567d9819b12a699e19de70d9ebe23c`.
- T19i는 이전 T19d~h 결과의 총수를 더하지 않고, 추적을 연결한 21개 suite를 **같은 스크립트/카탈로그**로 새로 실행하는 작업이다.
- Steam Godot 4.7.2 headless, 새 TEMP 프로젝트, suite별 격리 APPDATA/LOCALAPPDATA. 사용자 데이터·설치된 엔진·제품 요구 버전을 변경하지 않는다.
- 실행 중 game/scripts와 카탈로그를 수정하지 않는다. 변동이 생기면 해당 소스 결과를 별도 묶음으로 취급하며 오래된 trace를 섞지 않는다.
- NP01~21의 실제 확정 원장/문단·언어 관찰과 NP22의 소비·관리 책임은 다르다. 등록량 0인 NP22를 무작위로 채우거나 관찰 생산 완료로 보고하지 않는다.
- 카탈로그의 문단/언어 분모는 필수 node/variant/행동 분기 전체의 분모가 아니다. 신규 미매핑·구형 fixture·의도적 UI 제외·미실행 분기를 별도 감사한다.
- 전체 목표/실제 전편 입력/정식 성능/4.6.3 채택/rollout 인수는 이번 묶음 완료 여부와 별개다.

## 완료 조건

1. 새 프로젝트에 복사한 모든 GDScript 경로/각 SHA와 29개 등록 카탈로그가 제출 작업본과 일치한다.
2. 각 suite의 native 종료 0, 정확한 PASS, 오류 없는 stdout/stderr(기존 인증서 경고 제외), 유효한 공통 trace와 원본 바이트 SHA receipt를 확인한다.
3. 집계 도구로 중복 제거한 경로 tuple와 생산자별 최신 등록 문단/언어 관찰/미관찰을 출력한다. 등록량은 독립 inventory와 대조한다.
4. 같은 로그 중복 입력 불변, 이전 소스 혼합 거부, 잘못된 로그/receipt/tuple 거부를 재검증한다.
5. 표본 legacy/unmapped는 신규 발생 0으로 해석하지 않는다. 구형 피드백 예외는 [T19h 진단](2026-10-07_수첩생산자_거울지하파열힌트_합집합.md)과 실제 표본으로 연결한다.
6. 원자료·집계 JSON·검사 범위/한계·ToDo를 보존하고 develop commit/push 뒤 Git 아카이브에서도 로그/receipt/지문과 집계를 검증한다.

독립 행동 분기·정적 제외 대조는 위 실행 결과와 이어서 감사하되 근거가 부족하면 미완료로 남긴다. 통과하는 검사만 골라 같은 소스 전체가 통과한 것처럼 보고하지 않는다.

## 표본과 제외 감사

`content`의 표본은 authored 1,300 / legacy 765 / unmapped 188이다. [구형 마지막 피드백 진단](2026-10-07_수첩생산자_거울지하파열힌트_합집합.md)의 15개 구형 체크포인트와 descriptor 없는 시작 피드백을 포함한다. 다른 20개 trace 표본의 legacy/unmapped는 각각 0이지만 표본 0을 전체 신규 미매핑 0으로 해석하지 않는다. 표본 수를 여러 실행 사이에 더하거나 고유 생산 수로 바꾸지 않는다.

[공통 기록 입구/관리 UI 대조](2026-10-07_수첩_기록입구_관리UI제외대조.md)에서는 모든 등록 문단을 관찰한 이번 검사 밖의 보조 저장 실패 경계에서 ERR-0050을 찾았다. 등록 문단 분모와 필수 행동 분모를 분리해야 하는 실제 근거다. `required_branch_coverage=NOT_AUDITED`, 신규 미매핑/UI 제외 전수/생산자별 legacy 총수는 `null`로 유지한다.
