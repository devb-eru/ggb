# 수첩 편의 설정 미래 임시 파일 보호

## 범위

기준 develop `757bb00`. 계획 15절의 미래 형식 보존과 UI sidecar 안전성을 대조하면서 [ERR-0044](../items/GGB-ERR-2026-0044_수첩편의설정_미래임시파일_덮어쓰기.md)를 확인했다. 수첩 필터·읽음·위치의 편의 설정만 대상이며 슬롯 본문/책갈피와 별도다. NP21/22 전체 감사나 엔진 후보 채택을 완료했다는 의미가 아니다.

## 재현과 해결

- `notebook_view_store.gd`의 두 입구는 main/backup만 검사했다. temporary 미래 버전은 정상 main이 있거나 없거나 손상된 세 경우 모두 저장에 의해 대체됐다.
- 수정 전 집중 검사 52조건 중 9개 단언 실패: 각 세 경우의 read-only 기본 위치, 저장 거부, 세 후보 전체 바이트 보존.
- load/save 모두 temporary의 미래 형식을 검사한다. temporary를 반환 가능한 확정 데이터로 채택하지 않는다. 본문·공개 권한이나 본편 원장은 변경하지 않는다.
- `notebook_view_smoke.gd`의 기존 미래 형식 검사를 temporary까지 확장하고, 독립 `notebook_view_future_smoke.gd`를 query suite에 연결했다.

## 검증 결과

Godot `4.7.2.stable.steam.ed1daf0bf`, 숨긴 headless 프로세스, 격리 APPDATA에서 실행했다. 제품 요구 버전은 유지하며 4.6.3 후보를 실제 설치에 적용하지 않았다.

- 수정 후 집중 검사 첫 실행 52조건 PASS. 그 다음 정상 임시 파일만 남았을 때도 미확정 설정을 채택하지 않는 단언을 추가한 최종 53조건 PASS.
- 미래 형식 main/backup/temporary 각각 × main 정상/없음/손상 9조건. 읽기 전용 안내, 오류 ID, 존재 파일 목록·전체 바이트 보존을 확인했다. main 대상에서는 그 파일을 미래 형식으로 교체하므로 정상/없음/손상 준비 상태 차이는 최종 미래 main에 흡수된다.
- 현재 형식의 유효 임시 파일은 main을 대체해 읽히지 않으며, 임시 파일만 존재해도 기본 위치를 반환한다. 새 정상 저장은 가능하다.
- 전체 query 회귀 종료 0 / `NOTEBOOK_QUERY_SMOKE: PASS`, query 6,835검사. 기존 view 227·갤러리 232 및 통합된 미래 편의 설정 52검사를 포함한다. query 실행 중 마지막 독립 53조건의 정상 temporary-only 단언을 추가했으므로 두 실행 버전/검사 수를 구분하며 중복 합산하지 않는다.
- 실행 환경은 `Failed to read the root certificate store`를 출력했다. 네트워크·인증서 검증 성공으로 취급하지 않으며 이는 파일 검사 단언/종료 결과와 별도다.

증거: [수정 전](evidence/2026-10-07_view_future_baseline.log), [최종 집중 검사](evidence/2026-10-07_view_future_final.log), [query 회귀](evidence/2026-10-07_view_future_query.log). 전체 회귀 재실행은 격리 APPDATA와 프로젝트 복사본에서 `Godot --headless --path <project> -- --notebook-query-smoke --ggb-dev-notebook-v2`를 사용한다. 독립 검사는 `notebook_view_future_smoke.gd.new().run()` 반환의 ok/errors와 종료 코드를 확인한다.

집중 시험 파일은 생성한 `user://__test_view_future_<ticks>` 아래에서만 정리한다. OS 전원 차단·동시 쓰기·디스크 포화 인수는 이번 fixture 검증에 포함되지 않는다. 전체 수첩 인수는 미완료다.
