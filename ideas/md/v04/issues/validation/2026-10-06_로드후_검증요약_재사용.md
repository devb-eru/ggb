# 로드 후 검증 요약 재사용

- 기준: develop `bffc62d`.
- 관련: T20의 캐시 없는 로드 이후 첫 수첩 진입.

## 변경

`SaveManager.load_slot`의 본파일 전체 읽기와 복구본을 본파일로 복사한 직후의 전체 읽기에서, 실제 검증된 텍스트 지문과 작은 요약을 함께 수집한다. 이미 도입한 선택적 요약 수집 API를 사용한다.

실제 로드의 JSON·checksum·schema/design·snapshot 검증, 기존 원본 보존 및 백업 분기 처리 순서는 유지한다. 요약 캐시는 전체 snapshot 읽기를 대체하지 않는다. 후속 inspect도 실제 바이트를 읽어 지문을 비교하며, 변조 시 전체 검증으로 돌아간다.

## 새 검사

`notebook_save_safety_smoke.gd::_test_loaded_summary_cache`:

1. 정상 본파일 및 손상 본파일의 백업 복구 두 경로를 구성한다.
2. 비어 있는 캐시를 가진 새 저장 관리자 인스턴스로 로드한다.
3. 후속 inspect에서 run_id와 읽기 경로가 정확하고 추가 전체 검증이 없는지 확인한다.
4. 요약 조회가 파일을 쓰지 않는지 확인한다.
5. 본파일을 변조한 후에는 캐시를 거부하고 백업을 검증하는지 확인한다.

기존 구현에서 정상 로드 후 추가 전체 검증 없음 단언이 실패했고 수정 후 통과했다. 오류 수정이 아니라 동일 검증 결과의 제한적 재사용 개선이다.

`notebook_opening_smoke.gd`에는 `large_loaded`를 추가했다. NB-PERF-L10000 저장 후 요약 캐시를 비우고 정상 로드한 다음 첫 진입을 계측한다. 원본 snapshot 전체 동등성과 공개 행 동일성, 준비 중 화면/포커스 계약을 확인한다. **같은 프로세스에서 캐시를 비운 검사이며 실제 OS 재시작 검사가 아니다.**

## 잔여 범위

캐시가 없는 최초 로드 자체는 전체 검증을 수행하므로 비용이 남는다. 비동기 writer와 현재 SaveManager의 캐시 연결, snapshot 준비/최종 화면 구성, cold/warm 반복 측정과 실제 Windows 재시작·입력 검증은 미완료다. ERR-0027 및 전체 목표는 진행 중으로 유지한다.
