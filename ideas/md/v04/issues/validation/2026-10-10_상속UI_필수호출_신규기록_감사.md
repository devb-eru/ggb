## 1. 문제와 작업 범위

기존 C4/D0 공통 버튼 30조건은 다른 C/D 단계의 동일 버튼 노출을 보증하지 않았다. 카탈로그의 광역 허용 node를 모든 필수 실행의 분모로 사용하지 않고, 실제 controller의 방 구성·override와 session의 action guard를 먼저 대조했다.

이번에는 C 구간 10단계와 D5 전 7단계에서 공통 행동이 실제 버튼으로 남는 경우, 전용 퍼즐로 교체되어 호출 경로가 아닌 경우를 나눴다. 등록 문단 표본과 달리 **행동 직전 원장과 행동 표시·저장 이후 원장의 차이**로 신규 기록을 세었다.

제품 코드·카탈로그·엔진·기본 rollout은 변경하지 않았다. 테스트는 `scripts/tests`에 두고 격리 프로젝트의 별도 장면으로 실행하여 기존 `res://scripts/**/*.gd` 264개 코호트를 유지했다.

## 3. Fixture와 신규 기록의 분리

- 개발 시점 snapshot의 진행 선행 지식은 유지하고 시험 장소만 지정한다. 원장은 빈 v2 원장으로, 지식 출처 ledger와 `chapter_notebook`은 비워 첫 자료 획득을 시험한다.
- 내실의 attention/inspected/edgar_state는 0/빈 목록/absent로 명시하여 조사 가능한 조건을 검사한다. 경계별 방문·숨기 조건 전체를 이 검사로 완료 처리하지 않는다.
- fixture 설치 자체는 실제 SaveManager로 저장한다. 실제 버튼을 누르기 전 표시 원장을 별도로 확보하며, 이번 조건에서는 그 표본 기록이 모두 0개였다.
- UI callback의 pressed 신호를 실제 생성된 버튼에서 발생시킨다. `_do`나 session action의 우회 호출로 성공을 만들지 않는다. 대사를 끝까지 표시하고 표면 저장을 완료한 뒤 delta를 구한다.
- 원장 identity는 `source_origin_id + entry_uid`다. 이미 있던 기록의 본문/관찰 불변과 보존을 확인한다. 유효한 protection_reasons 변화만 본문 불변 비교에서 제외한다.
- 첫 획득은 NP06 출처를 요구하고, 재조사에서는 이미 획득한 같은 자료를 다시 만들 필요가 없으므로 새 NP04 표시를 요구한다. 이번 검사에서 자료 중복 대신 새로운 대화 사건이 남는다.
- 실제 발생 stage/CHAPTER_2/location 및 관찰 언어를 검사하고 한영 재열람을 수행한다. 과거 자료 재조사로 journal_stage가 낮아지지 않아야 한다.
- 매 행동의 확정 원장과 실제 슬롯을 다시 읽은 원장이 같아야 한다. 화면 재그리기는 원장을 추가하거나 바꾸면 안 된다.
- 교체된 부모 버튼과 폐기된 부모 정적 문구는 실제 표시 관찰이 아니어야 한다. 이 144조건은 모든 관리 UI 제외 감사가 아니라 특정 교체 화면의 비공개 검사다.

빈 원장 fixture이므로 legacy 이관·구형 자료의 보존을 별도로 증명하지 않는다. 개발 시점에서 장소를 지정한 **국소 dispatch**이며 자연 진행의 전체 도달성이나 물리 마우스/키보드 입력 검사가 아니다.

## 5. 검사 도구의 초기 실패

첫 `--script` 방식은 의존 controller를 파싱할 때 GameState autoload 식별자가 등록되지 않아 컴파일에 실패했다. 해당 소유 프로세스만 종료했으며 native -1 원자료를 보존했다. 일반 프로젝트 초기화 후 실행되는 별도 Node 장면으로 바꿔, 같은 제품 소스에서 새 실행 전체를 수행했다. 실패 로그는 최종 PASS나 등록 관찰 합집합에 포함하지 않는다.

실행 전 해시 guard의 첫 대조는 SHA 대소문자 표현 차이를 파일 변경으로 잘못 판정했다. 원본/작업 소스/격리 복사본/아카이브의 실제 SHA는 같았다. SHA 비교를 대소문자 비구분으로 정정했으며 파일이나 기존 guard를 덮어쓰지 않았다. 두 건 모두 **테스트 도구/명령의 오류**이고 제품 결함으로 집계하지 않는다.

아카이브 문서 검사 래퍼도 처음에는 Write-Host의 정보 스트림을 캡처하지 않아 실제 429문서 PASS를 실패로 오인했다. 임시 래퍼에서 정보 스트림까지 캡처해 다시 확인했다. 문서 validator·제품 코드·합격 조건은 변경하지 않았다.
