## 범위와 결과

- 시작 기준: develop `4fad14207424a62a90c919bad2925a775ce299ed`.
- 공식 Godot `4.6.3.stable.official.7d41c59c4` 후보의 격리 TEMP 프로젝트에서 실행했다. 사용자 Steam 설치·실제 세이브·프로젝트 엔진 기준은 바꾸지 않았다.
- 제품 변경: SaveManager, notebook_save_worker, dialogue_history_writer, chapter_one_controller 네 파일. 기존 동기 writer 반환형과 호출부는 유지한다.
- 개발 실행 옵션: `--ggb-dev-notebook-v2 --ggb-dev-notebook-async`. 추가 옵션이 없으면 기존 공통 대화 경로다. 기본 rollout OFF·제품 기준 4.7은 그대로다.
- 집중 검사 72조건·870단언, 저장 안전성 381, 호스트 548(내부 참조 비동기 341) PASS/native 종료 0. 이전 소스의 내부 342와 이번 실행의 341을 같은 수로 바꾸거나 합산하지 않는다.
- 독립 원자료/소스/분모 검사 1,809확인·손상 반례 6개 PASS. 이 숫자는 실기 입력 횟수나 전체 생산자 분기 수가 아니다.
- 전체 T21·정식 성능·전편 실기/엔진 채택은 미완료다. ERR-0027은 IN_PROGRESS다.

## 저장 계약

1. 시작 시 main/bak/일반 tmp의 실제 전체 바이트 SHA, game revision/load_epoch, 저장 root/flavor와 호출자가 소유한 detached snapshot을 고정한다.
2. worker는 살아 있는 game/UI를 받지 않는다. 고정 snapshot에 기존 엄격 ID·사실·본문 검증과 원장 추가 또는 커서 설치를 수행한다. 일반 tmp는 호환성 보호 대상이지 채택할 확정 세이브가 아니다.
3. main/bak/일반 tmp를 다시 읽고 시작 SHA와 비교하며 전체 저장 형식 검증을 수행한다. 고유 `progress.history_<command>.tmp.json`을 쓰고 flush 후 다시 읽어 전체 검증·snapshot 일치를 확인한다.
4. main thread는 worker 실행 중 process_frame을 계속 진행한다. 완료 시 소유 UI/대사 토큰/언어/세션/슬롯, revision/epoch/root/flavor, 파일 SHA와 임시 바이트를 재확인한다.
5. 최종 승격과 live snapshot 설치 사이에는 await가 없다. 저장 전에 live 원장을 임시 성공으로 설치하지 않는다. 승격 응답 유실은 정확한 transaction/snapshot의 디스크 확인으로만 복구한다.
6. 실패·취소·오래된 결과는 설치하지 않는다. 중복 token은 기존 entry UID를 유지한다. 같은 저장 서비스의 동시 참조/대사 작업 및 같은 슬롯의 동기 저장은 pending 동안 거부한다.

worker 준비와 최종 승격을 분리했지만 시작의 snapshot 복사/파일 SHA와 최종 파일 재확인·live 설치는 main thread에 남는다. 서비스 제거 시 기존 `_exit_tree`는 worker 종료를 기다린다. 서비스 제거/게임 종료의 비차단 완료나 OS 정전·파일 잠금 인수로 확대하지 않는다.

## 공통 대화 UI

- ChapterOne, BlackMirror, Basement의 상속 공통 대화에 적용한다. 프롤로그의 통합 진행 저장 및 선택 모달은 아직 적용 범위 밖이다.
- 대사를 표시하면 저장 pending 상태가 되며 다음 대사·완료 처리와 수첩 열기를 막는다. 저장 안내는 관리 문구이며 이야기 원문에 추가하지 않는다.
- 성공 후에만 해당 표시 index를 recorded로 인정한다. 마지막 대사의 완료/finish_pending 커서도 따로 내구 저장한 후 기존 완료 callback을 실행한다.
- 저장 실패 후 다음 버튼은 재시도할 수 있으나 미저장 상태에서 대사를 넘기지 않는다. 재시도 성공 시 오류 안내를 해제한다.
- 표시 대사 교체, 언어 또는 저장 서비스 교체 시 과거 결과는 현재 대사를 완료시키지 않는다. 대사 본문의 PageUp/PageDown 경로는 유지한다.
- 이 검사에서 사용한 실제 Button callback/Control은 HEADLESS다. 실제 Windows 키·마우스·Alt+Tab·렌더러/DPI 검사와 다르다.

## 실패 시도와 원자료

[원자료 묶음](evidence/2026-10-10_history_async/manifest.json)에 최종 집중/이관/호스트 receipt·stdout/stderr·최종 결과와 고정 소스 정보를 보존한다. 실제 세이브·엔진 바이너리·APPDATA는 Git에 넣지 않는다.

- `focused`: harness의 동적 Dictionary 변수에 타입 추론 실패. 정확한 소유 프로세스만 종료했으며 실패 receipt/로그/그때의 GD를 보존했다.
- `focused-fixed`: `NB_PR_DUTY_1`의 허용 node는 PG인데 fixture가 P1을 사용해 엄격 콘텐츠 검증에 정상 거부되었다. UI 30조건은 통과했으나 전체 실행은 FAIL이다. 빠른 거부 시간을 성능 개선으로 집계하지 않는다.
- `focused-final`: fixture를 PG로 수정하고 실패마다 정확한 오류 ID 검사를 추가한 뒤 native 0/PASS를 확인했다. 제품 ID 검증을 완화하지 않았다.
- 독립 검사기 첫 실행: 중복 fixture JSON의 첫 commit을 두 번째 no-op으로 오해한 검사 가정을 정정했다. 제품/원로그는 바꾸지 않았으며 최종 독립 검사는 해당 기록 형식과 harness 단언의 경계를 명시한다.

재실행 도구는 저장소 `scripts/run_notebook_history_async_audit.ps1`, 독립 검사기는 `scripts/audit_notebook_history_async.ps1`이다. 세 native receipt의 264개 게임 스크립트 지문과 현재 제품 소스를 대조하며 한영 72조건의 중복/누락, 원로그·harness/runner SHA를 검사한다. 반례는 원로그 누락·바이트 변경·native 실패·조건 누락·조건 중복·혼합 소스의 여섯 가지다.
