공통 버튼 15종 화면 조합 × 한영 = 30개 실행을 요구한다. 시간표와 탁본은 기존 지식 ledger가 비어 있는 checkpoint fixture로 최초 자료 획득도 검사한다. 원래 진행 지식은 유지하므로 현재 stage는 C4 또는 D0여야 한다.

각 실행에서 다음을 확인한다.

- 버튼이 실제로 존재하고 대화가 끝까지 표시된다.
- 새 대사/수첩 자료는 authored 기록이며 NP04/NP06 생산자 구분을 유지한다.
- 공통 콘텐츠 이름이 CH1로 시작하더라도 node는 C4/D0, chapter는 CHAPTER_2, location은 클릭한 원래 장소다.
- 문단의 관찰 언어가 실행 언어와 일치하고 같은 의미 버전으로 한국어/영어 재열람이 가능하다.
- 이전 자료를 조사했다고 journal_stage를 되돌리지 않는다.
- 실제 표시 전 수집된 부모 화면의 폐기된 정적 자료를 관찰로 쓰지 않는 기존 검사도 유지한다.

## 화면 교체 조건

BlackMirrorController::_build_inner는 `c5_info_complete`가 없거나 journal_stage가 3 이상이면 부모 조사 구성을 사용한다. J3 복원 조건이 충족된 구간에서만 J3 조각 퍼즐로 바뀐다. 따라서 C4에서 INNER_desk가 없다고 요구하면 잘못이다. BasementController::_build_inner는 지하 평면도·서랍 퍼즐로 대체한다.

큰 시계실의 B3 조작은 거울 controller의 C구간 종 재생으로 교체되므로 이번 공통 탁본 대상으로 넣지 않았다. 부모 API 호출 가능성만으로 UI에 존재한다고 가정하지 않는다.

## 검사 자체의 수정

1. 첫 실행에서 C4 서재도 부모 조작이 없다고 잘못 가정했다. override의 조건부 부모 호출을 확인해 C4는 존재·실행, D0는 비노출로 수정했다.
2. Godot의 locale 반환은 ko_KR/en_US, 관찰의 저장 규약은 ko-KR/en-US이다. 밑줄/하이픈을 정규화해 비교하도록 수정했다. 언어 자체를 무시하거나 검사를 제거하지 않았다.
3. 기존 _present는 loop_state 전체가 동일해야 한다고만 검사해, 일부 후반 정적 화면의 정상 표시 receipt 저장도 실패로 판정했다. 기존 `notebook_state_assertions.gd::same_surface_gameplay`를 적용했다. 이 검증은 유효한 receipt와 그것을 뒷받침하는 실제 관찰, 이전 관찰/sequence/revision 보존을 확인하고 나머지 전체 상태를 비교한다. 임의의 상태 변경을 허용하는 제외 목록을 새로 만들지 않았다.

첫 실행은 위 세 가지 검사 오류, 두 번째 실행은 세 번째 비교식 때문에 실패했다. 수정한 최종 소스를 별도 PCK로 다시 검증한다. 이전 실패를 제품 오류 해결 실적으로 집계하지 않는다.
