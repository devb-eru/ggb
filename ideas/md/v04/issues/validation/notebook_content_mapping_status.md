- 재열람은 같은 의미 버전의 현재 언어를 사용한다. 버전/번역을 구할 수 없으면 당시 원문과 안내를 표시한다. 기존 저장을 최신 문장으로 덮어쓰지 않는다.

## 4. 버전 변경 규칙

`seed_notebook_hints_v1.gd`는 최초 원고 생성 도구이며 기존 파일 덮어쓰기를 거부한다. 출시·저장에 사용한 버전 1을 최신 코드로 재생성하지 않는다. 의미가 달라지면 새 버전을 추가하고 공급자의 descriptor를 명시적으로 변경하며, 과거 버전은 보존한다. 같은 버전의 원고와 실제 표시문이 달라지면 개발 검증 저장은 오류를 반환한다. 오류를 감추기 위해 새 원문을 legacy/unmapped로 자동 전환하지 않는다.

### 표시·출처·보존

- `_prologue_line`에서 명시적 원고 ID와 현재 방을 함께 캡처한다. 다음 사건으로 상태가 넘어가도 원 대사의 사건/장소를 바꾸지 않는다. 첫 리셋의 세 문장도 프롤로그 문맥을 유지한다.
- P1 창문 설명을 밤에 다시 사용하는 경로는 `NB_PR_P6_INSPECT_WINDOW`로 분리한다. 원문이 같아도 관찰한 사건은 다르다.
- 남은 일과는 실제 미완료 조합별로 ID가 다르다. 한국어 작업명 문자열을 영어 문장에 끼워 넣지 않고, 같은 공개 조합을 해당 언어로 읽는다. 완료하지 않은 일을 과거 완료로 만들지 않는다.
- 대사의 기억·모순·일지·서명 단서 원문은 `content:clue_source`, 선택창은 `content:choice_context`, 선택한 문구는 `content:choice`로 보호한다. 자료 카드의 `source_links` 연결 자체는 NP03 등 후속 작업이다.
- P3/P4 질문은 표시된 header/prompt/선택지만 segment로 저장한다. 확정 문구와 실제 표시된 후속 답변은 별도 관찰이다. 질문과 확정, 해당 답변은 실행 중 같은 대화 세션을 공유한다. 선택하지 않은 답변은 공개하지 않는다.
- P1/P6 확인창의 버튼 및 취소 키는 확정과 취소를 다른 `entry_kind`로 기록한다. `choice_confirmed`는 누른 의향의 증거이며 후속 게임 상태 저장 성공을 대신하지 않는다. 취소는 출발·수면을 실행하지 않는다.
- 저장 실패 시 현재 문장/선택창과 토큰을 유지한다. 재시도는 같은 관찰 하나를 확정하고 다음 동작을 진행한다. 교체·닫힌 모달의 오래된 콜백은 세대 값 검사로 거절한다.
- 현재 실행 중의 세션 연결이다. 앱 재시작 후 표시 커서·이전 세션 재개는 아직 미구현이며 새 관찰을 과거 커서로 가장하지 않는다.

### 원고 보존과 검증

실제 develop 폴더의 프롤로그·공통·1장 `.tres`와 작업 사본의 `localized_text`를 Godot ResourceLoader로 비교해 의미 내용이 일치함을 확인했다. 사용자의 재직렬화·UID·씬 변경은 덮어쓰지 않았다. 기존 대사 본문·질문 답변·퍼즐 정답은 바꾸지 않았다. 새 카탈로그는 이 검증된 원문의 버전 1을 동결하며, 이미 배포한 버전을 재생성하지 않는 규칙은 힌트와 같다.

`--notebook-prologue-smoke --ggb-dev-notebook-v2`는 실제 컨트롤러·버튼·확인창에서 93 ID × 2 언어 = 186 조합을 실행한다. 일과 7조합, P3 두 답변/침묵, P4 세 답변은 분기 fixture이며 한 플레이에서 세 질문을 허용한 변경이 아니다. 모든 실제 표시 기록이 authored인지 검사하고, 누락 ID를 이름별로 실패 보고한다. 선택지 일부만 표시한 경우의 미공개 segment 참조 거절, 저장 실패 후 취소·확정 재시도, 닫힌 확인창 콜백, 첫 리셋/실제 슬롯 재로드, 현재 언어 재열람의 상태 불변도 검사한다. OS 마우스·키보드 완주나 앱 재시작 커서 인수는 아니다.

최종 연결 후 에디터 import, 프롤로그 집중 검사, 일반/신형 프롤로그 회귀, 기존 힌트 60종, 신형 1장·대화 기록, 저장 이관이 통과했다. 전편 자동 경로는 일반 약 95초·신형 약 137초로 각각 정상 종료했다. Windows Desktop Debug 설정으로 `.pck`를 내보내고, 원본 프로젝트가 없는 별도 경로에서 `--main-pack`으로 실행한 186 조합도 통과했다. 카탈로그가 패키지에 포함되고 실제로 읽히는 근거이며 Windows release 실행 파일·OS 실제 입력·성능 인수의 대체 근거는 아니다. 모든 검사는 필수 PASS, 종료 코드 0, 스크립트 오류 없음을 함께 확인했다. 남은 환경 경고는 Windows 루트 인증서 저장소 읽기 실패다.

### 이 범위에 포함하지 않는 것

- 메뉴·설정·인벤토리 조작 안내·선택 포커스 화살표·`확인함` UI 장식은 `EXCLUDED_UI`다. 선택지의 실제 문구는 별도 segment로 포함한다.
- `_add_notebook`의 자동 기록은 아래 NP03에서 별도로 연결한다. 대화창 밖의 단서성 오브젝트 피드백은 NP21로 남긴다. 대사 연결로 다른 생산자를 완료 처리하지 않는다.
- 기존 legacy 항목을 신규 원고와 비교해서 ID를 소급 발급하지 않는다. 일반 실행은 기존 transcript 저장, 개발 옵션은 새 authored 저장을 사용한다.

## 6. NP03 사건에서 작성하는 수첩

원고: [prologue_notes_v1.json](../../../../../game/data/notebook/prologue_notes_v1.json). 공급자는 `_add_notebook`에 원문 대신 명시적인 `NOTE_P_*`를 전달한다. 기존 한국어 문자열 목록은 호환용으로 유지하며, 그 문자열을 역검색해서 과거 작성 시각·장소·ID를 추정하지 않는다.

| 지식 ID | 실제 획득 소유자 | 공개 경계 |
| --- | --- | --- |
| `NOTE_P_DUTIES` | 신규 프롤로그 초기화 | 처음 일과 목록을 작성할 때만. 기존 PROLOGUE/영구 원고가 있으면 소급 발급하지 않음 |
| `NOTE_P_IMPRESSIONS` | P1 수첩 조사 | 실제 조사한 흔적만 |
| `NOTE_P_BIRD` | P2 세 번째 창 상단 조사 | 반복 궤도를 관찰한 시점 |
| `NOTE_P_WINDOWS` | P2 창 세 개 완료 | 닦은 결과와 기존 관찰 문구 |
| `NOTE_P_JOURNAL` | P3 기계 도면집 배치 | 장부 발견. 잠긴 내부 내용은 공개하지 않음 |
| `NOTE_P_SIGNATURES` | P3B 이름표 정리 완료 | 이미 사건에서 제공하는 다섯 문양 설명 |
| `NOTE_P_PULSE` | P4 진동 기록 버튼 | 진동을 보기만 하면 획득하지 않음. 기록 동작 필요 |
| `NOTE_P_WEATHER` | P5 관찰 기록 완료 | 모순 관찰만. 원인·현실 진실 자동 해석 없음 |
| `NOTE_P_SLEEP` | P6 수면 확정의 저장 | 저장 실패 시 수면 완료와 기록을 함께 취소 |

각 콘텐츠 ID는 `NB_` + 지식 ID, 의미 버전은 1이다. 원고 9종 × 한국어/영어 18조합이다. 기존 `NOTE_P_TEA`는 실제 `_add_notebook` 생산자가 없으므로 등록하지 않는다. 기억 닻 플래그만으로 없던 수첩을 새로 작성하지 않는다.

### 자료와 영속성

- 새 자료는 일반 대사가 아닌 `document_segment`이며 공개 증거는 `replay_committed`다. 사건이 정확한 원고를 영구 작성한 증거이며 대화창 표시·게임상 문서 읽기 완료·수첩 열람 완료를 의미하지 않는다.
- `knowledge_entries.notebook_knowledge`의 schema 1 ledger에 불변 `knowledge_uid`, `revision_uid`, 이전 revision, 작성 순서, 내용/출처 상태, 자료 수명, 원고 참조와 출처 참조를 기록한다. 이번 9종은 관찰/자기 작성 출처 식별/영구 자료다. UI에 수명·루프 정보를 언제 보여 줄지는 별도 공개 정책을 따른다.

- 이후 원고가 바뀌면 이전 내용을 덮어쓰지 않고 새 의미 버전과 revision을 추가한다. 모듈의 갱신·반증 계약 시험은 시험용 원고이며 실제 J1~J5/가설 생산자를 연결했다는 뜻이 아니다.
- 원고/ledger/출처 보호/기존 문자열과 사건 진행은 하나의 StateWriter/SaveManager 커밋이다. 후보만 만든 상태는 획득 성공이 아니다. 실패 재시도는 동결한 요청의 토큰·출처·언어를 유지하며, 슬롯/로드/분기가 바뀌면 거절한다.
- 수첩 열기는 저장을 실행하지 않는다. 개발 모드에서는 확정된 기록만 읽고, 미저장 요청이 있으면 안내한다. 타이틀 이동의 저장이 실패하면 화면을 떠나지 않는다.
- P6 실패는 해당 수면 요청과 진행만 이전 값으로 되돌리며, 먼저 실패해 대기 중이던 다른 기록은 남긴다. 정상 리셋 후 떠나는 프롤로그 컨트롤러의 초기 일과가 영구 원고를 덮어쓰지 않는다.
- 미래 ledger schema는 checksum 검증 후 호환 불가로 처리한다. 과거 백업으로 임의 복귀하거나 미래 본문/백업을 덮어쓰지 않는다.

### 식별과 표시 계약

- ID는 `NB_CH1_` + 명시적 생산자 ID다. 기존 원고 ID는 접두사를 그대로 보존하므로 `NB_CH1_CH1_B1_TEXT_EDGAR`처럼 보일 수 있다. 문자열·언어·현재 진행 플래그를 역검색하여 과거 ID를 추정하지 않는다.

- `last_feedback.notebook_feedback`에는 버전/variant/문단별 변수 descriptor를 저장한다. 사건 저장이 완료됐다는 사실만으로 대사 관찰을 생성하지 않는다. 대화창이 문단을 표시할 때에만 각 `line_01` 등의 관찰이 생긴다.

- 획득 콘텐츠는 `NB_CH1_NOTE_*`, `document_segment/replay_committed`, `body` 하나다. 사건이 수첩에 실제 작성한 원고이며 대화창 표시나 수첩 읽기 완료를 뜻하지 않는다. 일반 대사와 별도의 revision·출처 보호가 생긴다.

- B4의 해결 원고는 실제 파형 기록으로 실패 상태가 해결된 사건을 요약한 신규 수첩 이력이다. 실패 자체를 없었던 일로 반증하지 않으며 기존 실패 원문을 덮어쓰지 않는다. 이 원고가 별도 대사를 발생시키거나 퍼즐 판정을 대신하지 않는다.

### Revision·트랜잭션

- 변화 없는 문서·탁본 재조사와 이미 검증한 배선/시간창의 재확인은 같은 원고의 새 revision을 만들지 않는다. 관찰 대사를 다시 본 경우 NP04가 새 관찰을 남길 수 있지만 지식 갱신과는 별개다.
- 새로운 실패 실행은 같은 진단이라도 새 시도이므로 불변 revision을 추가한다. 당일 잠긴 시계망에 다시 실행을 요청한 것은 새 실패가 아니며, 기존 실패/잠금 조건 그대로 거절한다.
- source reference는 현재 snapshot에 이미 획득한 원고의 정확한 버전/segment만 인용한다. 문서 catalog에 존재하거나 gameplay 플래그가 켜졌다는 이유로 미획득 자료를 추가하지 않는다. 구형 저장에서는 실제 새로 조사한 자료부터 출처가 연결된다.
- 후보는 행동 호출 안의 snapshot에만 작성한다. 게임 상태·호환 문자열·archive·ledger·출처 보호는 기존 `_commit` 한 번으로 저장한다. 후보 작성 실패/게임 저장 실패 시 부분 획득을 남기지 않으며, 다른 사건으로 누출되는 전역 대기 원고도 없다.
- B4에서는 파형 원고와 실패 해결 revision이 같은 커밋이다. 저장 실패는 파형 플래그·해결 상태·두 revision을 함께 롤백한다. 저장 응답 유실은 실제 transaction/전체 snapshot 검증으로 처리한다.
- 한 행동의 원고들은 같은 사건 발생 ID와 작성 묶음 세션 ID, 서로 다른 표시 토큰을 가진다. 뒤이은 NP04 대사는 같은 사건 발생 ID 아래 별도의 대화 세션에서 실제 표시할 때 기록한다. 원고 작성 묶음을 대화 커서로 사용하지 않는다.
- 실행 중 표시되지 않은 후보는 저장 실패 후 사용자 재시도에서 다시 만들 수 있다. 성공한 저장의 동일 정보 재확인은 dedup하며, 수첩 읽기에는 획득/저장 함수를 호출하지 않는다. 새 공통 수첩 UI의 쓰기 scope/중단 복귀 인수는 별도다.

### 공개와 입력 계약

- `NB_MODAL_*_OPTIONS`는 실제 표시한 제목·본문·선택지만 `options_presented`로 남긴다. 각 선택 원고는 별도의 고정 ID/의미 버전과 `choice_confirmed/choice_cancelled`를 가진다. 첫 번째 버튼이라는 이유로 취소로 간주하지 않는다.
- 모달 생성 시 원 사건/장/장소·언어·표시 토큰·발생 ID·세션 ID를 동결한다. 선택과 취소는 같은 발생/세션 아래 별도 토큰이다. 저장 실패 후 같은 입력을 재시도하면 토큰을 유지하고, 아직 저장되지 않은 입력을 다른 선택으로 바꾸면 새 토큰을 발급한다.
- 표시 기록 저장이 실패하면 선택 콜백을 실행하지 않는다. 선택 기록 저장이 실패해도 콜백을 실행하지 않는다. 선택 기록 저장 성공은 뒤이은 게임 행동의 성공을 뜻하지 않는다. 이후 gameplay 저장 실패를 실제 선택 기록의 삭제로 처리하지 않는다.
- 현재 슬롯·컨트롤러 세션·로드 epoch·원 출처·분기·빌드 namespace와 모달 세대를 확인한다. 닫은 창, 다른 슬롯, 중간 로드의 오래된 콜백은 상태를 변경하지 않는다. 무효화된 창의 Esc는 기록 없이 닫을 수 있다.
- 명시적 취소 버튼이 있는 창의 Esc/N은 그 취소 동작과 같은 기록 경로를 사용한다. 읽기 확인을 첫 버튼으로 둔 현실 수첩에서는 Esc를 읽기 확인으로 변환하지 않는다. 단순 UI 닫기와 포커스 상실로 닫힌 창을 최종 동의로 기록하지 않는다.
- 현실 수첩 요약과 펼친 본문은 서로 다른 표시 정의다. 관계별 부기 10종은 해당 완료/정상 결과일 때만 공개 segment에 포함한다. 인계 출처는 실제 화면에 표시한 공개 기록 ID 문자열만 동결하며 다른 언어 재열람에서 현재 관계를 재조회하지 않는다.
- 현실 수첩의 화면 표시, 펼침 요청, `field_read` 완료는 서로 다르다. 확장/축소·다음 색인 버튼의 기록이 앞뒤 본문을 자동 공개하거나 퍼즐/필수 읽기 조건을 대신 완료하지 않는다.
- 마른 시험은 고정 카테고리의 결과와 입력했던 경로만 저장한다. 선택 순서는 번호별 줄로 표시해 각 구간을 독립 공개 segment로 관리한다. 정답 경로나 아직 선택하지 않은 구간을 채우지 않으며 재생 버튼은 추가 관찰·판정 없이 같은 시각 신호만 재생한다.
- 등록된 원고는 한영 고정 버전이며 source 문구와 실제 표시가 다르면 저장을 거절한다. 생성기는 미공개 제작 오류 수정 이후 동결하며, 배포된 의미 버전은 덮어쓰지 않는다.
