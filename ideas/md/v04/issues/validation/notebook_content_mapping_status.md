### 표시·출처·보존

- `_prologue_line`에서 명시적 원고 ID와 현재 방을 함께 캡처한다. 다음 사건으로 상태가 넘어가도 원 대사의 사건/장소를 바꾸지 않는다. 첫 리셋의 세 문장도 프롤로그 문맥을 유지한다.
- P1 창문 설명을 밤에 다시 사용하는 경로는 `NB_PR_P6_INSPECT_WINDOW`로 분리한다. 원문이 같아도 관찰한 사건은 다르다.
- 남은 일과는 실제 미완료 조합별로 ID가 다르다. 한국어 작업명 문자열을 영어 문장에 끼워 넣지 않고, 같은 공개 조합을 해당 언어로 읽는다. 완료하지 않은 일을 과거 완료로 만들지 않는다.
- 대사의 기억·모순·일지·서명 단서 원문은 `content:clue_source`, 선택창은 `content:choice_context`, 선택한 문구는 `content:choice`로 보호한다. 자료 카드의 `source_links` 연결 자체는 NP03 등 후속 작업이다.
- P3/P4 질문은 표시된 header/prompt/선택지만 segment로 저장한다. 확정 문구와 실제 표시된 후속 답변은 별도 관찰이다. 질문과 확정, 해당 답변은 실행 중 같은 대화 세션을 공유한다. 선택하지 않은 답변은 공개하지 않는다.
- P1/P6 확인창의 버튼 및 취소 키는 확정과 취소를 다른 `entry_kind`로 기록한다. `choice_confirmed`는 누른 의향의 증거이며 후속 게임 상태 저장 성공을 대신하지 않는다. 취소는 출발·수면을 실행하지 않는다.
- 저장 실패 시 현재 문장/선택창과 토큰을 유지한다. 재시도는 같은 관찰 하나를 확정하고 다음 동작을 진행한다. 교체·닫힌 모달의 오래된 콜백은 세대 값 검사로 거절한다.
- 현재 실행 중의 세션 연결이다. 앱 재시작 후 표시 커서·이전 세션 재개는 아직 미구현이며 새 관찰을 과거 커서로 가장하지 않는다.

### 원고 보존과 검증

실제 develop 폴더의 프롤로그·공통·1장 `.tres`와 작업 사본의 `localized_text`를 Godot ResourceLoader로 비교해 의미 내용이 일치함을 확인했다. 사용자의 재직렬화·UID·씬 변경은 덮어쓰지 않았다. 기존 대사 본문·질문 답변·퍼즐 정답은 바꾸지 않았다. 새 카탈로그는 이 검증된 원문의 버전 1을 동결하며, 이미 배포한 버전을 재생성하지 않는 규칙은 힌트와 같다.

`--notebook-prologue-smoke --ggb-dev-notebook-v2`는 실제 컨트롤러·버튼·확인창에서 93 ID × 2 언어 = 186 조합을 실행한다. 일과 7조합, P3 두 답변/침묵, P4 세 답변은 분기 fixture이며 한 플레이에서 세 질문을 허용한 변경이 아니다. 모든 실제 표시 기록이 authored인지 검사하고, 누락 ID를 이름별로 실패 보고한다. 선택지 일부만 표시한 경우의 미공개 segment 참조 거절, 저장 실패 후 취소·확정 재시도, 닫힌 확인창 콜백, 첫 리셋/실제 슬롯 재로드, 현재 언어 재열람의 상태 불변도 검사한다. OS 마우스·키보드 완주나 앱 재시작 커서 인수는 아니다.

최종 연결 후 에디터 import, 프롤로그 집중 검사, 일반/신형 프롤로그 회귀, 기존 힌트 60종, 신형 1장·대화 기록, 저장 이관이 통과했다. 전편 자동 경로는 일반 약 95초·신형 약 137초로 각각 정상 종료했다. Windows Desktop Debug 설정으로 `.pck`를 내보내고, 원본 프로젝트가 없는 별도 경로에서 `--main-pack`으로 실행한 186 조합도 통과했다. 카탈로그가 패키지에 포함되고 실제로 읽히는 근거이며 Windows release 실행 파일·OS 실제 입력·성능 인수의 대체 근거는 아니다. 모든 검사는 필수 PASS, 종료 코드 0, 스크립트 오류 없음을 함께 확인했다. 남은 환경 경고는 Windows 루트 인증서 저장소 읽기 실패다.

### 이 범위에 포함하지 않는 것

- 메뉴·설정·인벤토리 조작 안내·선택 포커스 화살표·`확인함` UI 장식은 `EXCLUDED_UI`다. 선택지의 실제 문구는 별도 segment로 포함한다.
- `_add_notebook`의 자동 기록은 아래 NP03에서 별도로 연결한다. 대화창 밖의 단서성 오브젝트 피드백은 NP21로 남긴다. 대사 연결로 다른 생산자를 완료 처리하지 않는다.
- 기존 legacy 항목을 신규 원고와 비교해서 ID를 소급 발급하지 않는다. 일반 실행은 기존 transcript 저장, 개발 옵션은 새 authored 저장을 사용한다.

### 자료와 영속성

- 새 자료는 일반 대사가 아닌 `document_segment`이며 공개 증거는 `replay_committed`다. 사건이 정확한 원고를 영구 작성한 증거이며 대화창 표시·게임상 문서 읽기 완료·수첩 열람 완료를 의미하지 않는다.
- `knowledge_entries.notebook_knowledge`의 schema 1 ledger에 불변 `knowledge_uid`, `revision_uid`, 이전 revision, 작성 순서, 내용/출처 상태, 자료 수명, 원고 참조와 출처 참조를 기록한다. 이번 9종은 관찰/자기 작성 출처 식별/영구 자료다. UI에 수명·루프 정보를 언제 보여 줄지는 별도 공개 정책을 따른다.

- 이후 원고가 바뀌면 이전 내용을 덮어쓰지 않고 새 의미 버전과 revision을 추가한다. 모듈의 갱신·반증 계약 시험은 시험용 원고이며 실제 J1~J5/가설 생산자를 연결했다는 뜻이 아니다.
- 원고/ledger/출처 보호/기존 문자열과 사건 진행은 하나의 StateWriter/SaveManager 커밋이다. 후보만 만든 상태는 획득 성공이 아니다. 실패 재시도는 동결한 요청의 토큰·출처·언어를 유지하며, 슬롯/로드/분기가 바뀌면 거절한다.
- 수첩 열기는 저장을 실행하지 않는다. 개발 모드에서는 확정된 기록만 읽고, 미저장 요청이 있으면 안내한다. 타이틀 이동의 저장이 실패하면 화면을 떠나지 않는다.
- P6 실패는 해당 수면 요청과 진행만 이전 값으로 되돌리며, 먼저 실패해 대기 중이던 다른 기록은 남긴다. 정상 리셋 후 떠나는 프롤로그 컨트롤러의 초기 일과가 영구 원고를 덮어쓰지 않는다.
- 미래 ledger schema는 checksum 검증 후 호환 불가로 처리한다. 과거 백업으로 임의 복귀하거나 미래 본문/백업을 덮어쓰지 않는다.

### 식별과 표시 계약

- ID는 `NB_CH1_` + 명시적 생산자 ID다. 기존 원고 ID는 접두사를 그대로 보존하므로 `NB_CH1_CH1_B1_TEXT_EDGAR`처럼 보일 수 있다. 문자열·언어·현재 진행 플래그를 역검색하여 과거 ID를 추정하지 않는다.
- `event_id`는 원고를 만드는 사건이고 `node_id/chapter_id/location_id`는 커밋 전 실제 상태다. 같은 공통 조사 동작을 후속 장에서 다시 실행해도 그 장의 관찰 문맥을 유지한다. 허용 노드 목록은 기존 상속 세션의 재조사 범위를 포함하며, 권한이나 퍼즐 성공을 부여하는 조건이 아니다.
- `ClockNetworkPuzzle.inspect_layout`는 기존 결과·정답을 유지하면서 `faults=[{kind, position}]`를 추가 반환한다. `piece/rotation/back/missing`은 분류 코드이며 번역문 파싱으로 결정하지 않는다. 첫 확인에서 공개하지 않은 상세 오류는 기록하지 않는다.
- `last_feedback.notebook_feedback`에는 버전/variant/문단별 변수 descriptor를 저장한다. 사건 저장이 완료됐다는 사실만으로 대사 관찰을 생성하지 않는다. 대화창이 문단을 표시할 때에만 각 `line_01` 등의 관찰이 생긴다.
- J1이 게임상 복원된 뒤 첫 문장만 본 상태에서는 NP04 관찰을 통해 다음 문장을 기록·참조할 수 없다. 별도로 획득하는 NP06 사건 작성 자료/일지 revision은 아래 8절을 따른다. 표시와 원고 획득은 서로 다른 증거다.
- 단서 원문은 `content:clue_source`, 이동/반복 일과 대사는 일반 기록이다. 인용문 안의 에드가 이름을 파싱해 화자를 재작성하지 않고 기존 표시 화자를 유지한다.
- 저장 실패 시 현재 문장과 토큰을 유지해 재시도한다. 게임 사건 커밋도 저장 응답이 유실되면 같은 transaction과 전체 snapshot을 확인한 뒤 성공을 인정한다. 단순히 디스크 파일이 존재한다는 이유로 성공 처리하지 않는다.
- 기존 `last_feedback`에 descriptor가 없으면 원고 ID가 있더라도 소급 매핑하지 않는다. 다시 표시한 원문은 개발 모드에서 `unmapped`로 보존한다. 새 descriptor는 검은 거울·지하 세션의 초기화 전달 과정에서도 그대로 유지한다.
- 저장된 피드백 재표시는 새 관찰이다. 앱 재시작 시 원 대화 커서·표시 토큰을 재개하는 기능은 아직 아니다. 기존 기록을 읽기만 하는 경우에는 상태 변경·ID 소급 발급이 없다.
- 실패한 조작의 상태줄, 보드에 상시 표시된 설명, 확인창 선택지는 이 범위에 넣지 않는다. NP05·NP21에서 공개 내용과 단순 UI를 따로 분류한다.

### 공개·자료 의미

- 획득 콘텐츠는 `NB_CH1_NOTE_*`, `document_segment/replay_committed`, `body` 하나다. 사건이 수첩에 실제 작성한 원고이며 대화창 표시나 수첩 읽기 완료를 뜻하지 않는다. 일반 대사와 별도의 revision·출처 보호가 생긴다.

- 탁본 관찰의 수명은 `persistent`다. 이는 기억/기록의 수명이며 물리 탁본 아이템은 기존처럼 수면 시 사라진다. 읽기나 원고 보존이 물리 재료를 복구하지 않는다.
- 실패 노트는 기존에 작성하던 진단과 꺾인 핀 설명만 포함한다. 내부 판정의 `verified_roles` 전체나 미선택 정답을 조회해서 원고에 덧붙이지 않는다. 마지막 실패만 있던 legacy의 이전 시도 횟수/순서/세부 입력도 추정하지 않는다.
- B4의 해결 원고는 실제 파형 기록으로 실패 상태가 해결된 사건을 요약한 신규 수첩 이력이다. 실패 자체를 없었던 일로 반증하지 않으며 기존 실패 원문을 덮어쓰지 않는다. 이 원고가 별도 대사를 발생시키거나 퍼즐 판정을 대신하지 않는다.

### Revision·트랜잭션

- 변화 없는 문서·탁본 재조사와 이미 검증한 배선/시간창의 재확인은 같은 원고의 새 revision을 만들지 않는다. 관찰 대사를 다시 본 경우 NP04가 새 관찰을 남길 수 있지만 지식 갱신과는 별개다.
- 새로운 실패 실행은 같은 진단이라도 새 시도이므로 불변 revision을 추가한다. 당일 잠긴 시계망에 다시 실행을 요청한 것은 새 실패가 아니며, 기존 실패/잠금 조건 그대로 거절한다.
- source reference는 현재 snapshot에 이미 획득한 원고의 정확한 버전/segment만 인용한다. 문서 catalog에 존재하거나 gameplay 플래그가 켜졌다는 이유로 미획득 자료를 추가하지 않는다. 구형 저장에서는 실제 새로 조사한 자료부터 출처가 연결된다.
- 후보는 행동 호출 안의 snapshot에만 작성한다. 게임 상태·호환 문자열·archive·ledger·출처 보호는 기존 `_commit` 한 번으로 저장한다. 후보 작성 실패/게임 저장 실패 시 부분 획득을 남기지 않으며, 다른 사건으로 누출되는 전역 대기 원고도 없다.
- B4에서는 파형 원고와 실패 해결 revision이 같은 커밋이다. 저장 실패는 파형 플래그·해결 상태·두 revision을 함께 롤백한다. 저장 응답 유실은 실제 transaction/전체 snapshot 검증으로 처리한다.
- 한 행동의 원고들은 같은 사건 발생 ID와 작성 묶음 세션 ID, 서로 다른 표시 토큰을 가진다. 뒤이은 NP04 대사는 같은 사건 발생 ID 아래 별도의 대화 세션에서 실제 표시할 때 기록한다. 원고 작성 묶음을 대화 커서로 사용하지 않는다.
- 실행 중 표시되지 않은 후보는 저장 실패 후 사용자 재시도에서 다시 만들 수 있다. 성공한 저장의 동일 정보 재확인은 dedup하며, 수첩 읽기에는 획득/저장 함수를 호출하지 않는다. 새 공통 수첩 UI의 쓰기 scope/중단 복귀 인수는 별도다.

### 공개와 입력 계약

- `NB_MODAL_*_OPTIONS`는 실제 표시한 제목·본문·선택지만 `options_presented`로 남긴다. 각 선택 원고는 별도의 고정 ID/의미 버전과 `choice_confirmed/choice_cancelled`를 가진다. 첫 번째 버튼이라는 이유로 취소로 간주하지 않는다.

- 현재 슬롯·컨트롤러 세션·로드 epoch·원 출처·분기·빌드 namespace와 모달 세대를 확인한다. 닫은 창, 다른 슬롯, 중간 로드의 오래된 콜백은 상태를 변경하지 않는다. 무효화된 창의 Esc는 기록 없이 닫을 수 있다.

- 활성 scope에서 표시 저장이 실패한 읽기 창은 단순 Esc 닫기에서도 같은 표시 토큰을 먼저 재시도한다. 계속 실패하면 창을 유지한다. 저장에 성공해 닫더라도 `field_read`나 읽기 확인 선택을 만들지 않는다. 이미 무효화된 창의 무기록 닫기와는 구분한다.

1. `MIRROR_COATING`은 관찰에서 가설로, `MIRROR_TRACING`은 미해석 원도에서 다섯 출처 대조로 갱신한다. 이전 revision과 원문을 덮어쓰지 않는다. 가설 작성 뒤 C0를 다시 보면 실제 관찰 대사는 남지만 최신 자료를 초기 관찰로 되돌리지 않는다. C0 원고의 `superseded_by_content_ids`는 실제 획득한 C1 원고가 같은 카드의 최신 revision일 때만 적용한다. 진행 플래그만 있는 구형 저장에서는 관찰 기록을 생략하지 않는다. 원도 단계에서는 backend에 채널 데이터가 있더라도 이름·단서를 자료 본문으로 자동 공개하지 않는다.
2. 배합은 실제 시험지 검증 후에만, 경로 계획은 마른 시험 통과 후 실제 확정 행동에서만 기록한다. 수첩 조회·자료 비교는 검증 행동을 대행하지 않는다. 확보한 청소/약품 기록 및 실제 표시된 경로 segment만 출처로 연결한다.
3. `MIRROR_FAILURE`는 매번 실제 잠김/회수 시 새 revision을 만들며 당일 잠긴 상태에서 거절된 재입력은 새 실패가 아니다. 잠들면 물리 상태만 초기화되고 원고·출처는 남는다. 동일 배합 재제작·문서 재조사는 같은 원고의 revision을 늘리지 않는다.
4. C5 대조 원고와 기존 실패 해결 원고는 한 번에 커밋한다. 기록·ledger·보호·물리 아이템·진행 중 일부만 저장하지 않는다. 실패하면 전체 후보를 폐기하고 응답 유실은 동일 transaction/전체 영속 값으로 확인한다.
5. J3 사건 작성은 복원한 전체 페이지의 `replay_committed`다. 대화 관찰은 실제 넘긴 문장만 `displayed`로 남는다. 페이지 획득이 모든 대사 표시나 저자 인증을 의미하지 않으며 provenance는 `unverified`다.
6. [notebook_event_notes.gd](../../../../../game/scripts/systems/notebook_event_notes.gd)는 NP06/NP07/NP08 공통 후보 작성기다. `source_knowledge_ids`는 현재 가진 최신 revision만, `source_content_ids`는 해당 ID의 실제 archive 관찰 중 최신 항목의 공개 segment만 인용한다. 기록에 없는 출처·미표시 segment를 카탈로그나 진행 플래그로 복원하지 않는다.
7. 원고는 기존 한영 문구를 버전 1에 동결했다. 신규 실패 해결 문장은 앞선 실패를 보존한다는 수첩 요약이며 새 대사/정답이 아니다. 생성기는 기존 파일 덮어쓰기를 거부한다. 일반 실행은 여전히 기존 저장 형식을 쓴다.

### 자료·실패·전환

- `BASEMENT_PLAN`은 도면을 꺼낸 관찰에서 실제 중첩 검증으로 갱신한다. 검증 이후 서랍을 다시 조사해도 최신 자료를 초기 단계로 되돌리지 않는다. 근거는 현재 ledger에 실제 획득한 후속 원고이며 구형 진행 플래그만으로 이전 획득을 추정하지 않는다.
- `BASEMENT_FAILURE`는 순서/깊이/중앙 역방향의 실제 잠김을 불변 revision으로 보존한다. 같은 진단의 다음 시도도 새 revision이다. 당일 잠금 뒤 거절된 입력이나 첫 역회전 경고는 실패 원고를 추가하지 않는다.
- 정상 수면은 압력핀·물리 평면도를 초기화하지만 원고/출처를 보존한다. 실패 숏컷은 기존 규칙대로 확인한 축 깊이만 준비하고 축 밀기는 플레이어가 수행한다. 이미 검증한 개방 절차의 fast path는 물리 문을 다시 열지만 새 검증 revision을 만들지 않는다.

### 표시·획득·상태 전환

1. D4에서 동결한 반응을 D5에서 실제 표시할 때만 해당 사용인의 관찰을 만든다. 다섯 진단 투사 중 시선을 바꾸어도 반응 소유자/관계 값을 다시 선정하지 않는다. 반응이 없는 경우 다른 사용인의 말을 보충하지 않는다.

3. D6 조사 5종은 실제 조사 때 원고·호환 메모·조사 목록을 원자 저장한다. 재조사는 실제 표시 관찰만 늘리고 동일 원고 revision을 만들지 않는다. 휴식 경로는 기존대로 event-local이며 첫 BROKEN_RESET 뒤 만료한다. 영구 원고와 물리/지역 상태를 혼동하지 않는다.
4. 휴식 확인창은 침실과 캡슐의 감각·미확정 결과를 함께 표시한다. 취소와 Esc는 휴식을 시작하지 않으며 확정 기록도 이후 실제 수면 성공과 별개다. 표시/선택 저장 실패는 콜백을 막고 실제 로드 이전 창의 입력은 새 상태에 작용하지 않는다.
5. E1 기상 원고 획득과 대화창의 두 문단 공개는 별개다. 다른 세 오브젝트 조사로 문을 열며 같은 오브젝트 반복은 조사 수를 늘리지 않는다. 세 곳 확인/네 곳 전체 확인의 결과는 서로 다른 ID로 표시한다. 수면/재열람은 이미 수리한 상태나 관계를 다시 실행하지 않는다.
6. E2 보고와 아카이브 색인, 관계 허브 개방은 한 커밋이다. 질문을 건너뛰어도 핵심 보고 작성은 유지하지만 묻지 않은 질문의 답변 관찰/출처는 만들지 않는다. 익명 색인의 본문에는 `MARA2`를 선행 삽입하지 않는다. 실제로 알려진 색인만 소유자를 표시한다.
7. 출처 목록에는 원고 자체의 `observation_ref`가 항상 포함된다. 추가 출처는 실제 획득한 최신 지식과 `source_content_ids`의 최신 표시 항목에 한정한다. 같은 ID의 여러 문단이 별도 관찰이면 마지막 표시 항목의 segment만 인용하는 기존 공통 작성기 계약을 유지한다. 이전 문단 관찰은 archive에서 사라지지 않는다.
8. 영어 E1 기상/짧은 휴식·원고 요약의 번역 누락을 보완했다. 새 NP09 루카 원고의 영어 화자는 실제 화면의 `Luca`다. 프롤로그 카탈로그의 `Luka` 표기를 재사용하지 않으며 기존에 동결한 원고 8개 파일은 수정하지 않는다.
9. 데모의 기존 D5 사건 요약은 작성하되 전체판 대화 14박과 반응을 본 것으로 만들지 않는다. 데모 시간 경과 패널의 관찰은 아래 별도 원고/표시 경로로 기록하며 사건 원고로 대체하지 않는다.
10. `MOVE_CORRIDOR`, `D6_MOVE`, `D6_REST`의 세 단순 이동/휴식 예고 문구는 자동 콘텐츠 보호를 부여하지 않는 일반 대사다. 최근 일반 대사 2,000개 정책을 따르고, 나중에 책갈피/비교/출처로 참조하면 공통 보호 규칙이 적용된다. 파열 단서와 관계 반응·원고·확인창의 보호는 유지한다.

- 새 표시는 기존 사건 원고의 출처 목록을 소급 재작성하지 않는다. 예를 들어 기존 데모 D5 요약은 자신의 참조를 유지하고, 새 데모 장면은 실제 관찰로 따로 보존한다. 새 비교/연결 소비 화면은 후속 구현 범위다.

### 18.1 J4 복원 원고와 식별 가능한 인용

등록 파일: `journal_four_v1.json`. `NB_J4_DOCUMENT` 1개 정의에 19개 조건부 segment를 두며, 한 번에 19개 전부를 공개하지 않는다. 본문·마무리 2개, 알려진 연구원 원고 6개(마라 1의 보존 방식 2종 포함), 이전 원문 5개, 본문 없는 획득 인덱스 5개, 전원 완료 추가 문단 1개다.

- 기록 0~1개는 기본 원고만, 2개 이상은 실제 획득 플래그가 있는 사용인의 원고만 인용한다. 다섯 기록과 다섯 관계 완료가 모두 있어야 마지막 전원 문단을 넣는다. 퍼즐 정답·남은 사건 종료·최소 접근·관계 보상 조건은 변경하지 않는다.
- 식별 가능한 인용은 현재 ledger의 해당 REC revision과 정확한 콘텐츠 ID/버전, 저장 당시 본문을 확인한다. 같은 한국어 문자열을 찾아 ID를 역추정하지 않는다. 알려진 인용은 동결한 원고 버전의 한영 본문을 사용하고 실제 인용한 revision만 외부 출처로 보호한다.
- 식별 정보가 없거나 옛 원문이 현재 REC revision과 다르면 `original_only_segments`로 원문을 보존한다. 재열람은 원문 보존 안내를 제공하며 다른 언어 원고로 대체하지 않는다. 이를 새 REC 획득·관계 완료·과거 작성 시점으로 소급하지 않는다.
- 획득 플래그는 있지만 본문이 없으면 기존의 `REC_* · 획득한 기록 인덱스` 표현만 유지한다. 본문을 복구했다고 가장하거나 현재 카탈로그의 연구원 진실을 채워 넣지 않는다.
- 모든 공개 문단이 원고 자체의 source reference로 보호된다. 첫 문단만 보관하는 단일 본문 writer로 이 원고를 작성할 수 없다. 다른 관계 상태에서 재열람해도 이미 복원한 J4의 문단은 바뀌지 않는다.
- 집중 검사는 한영 140개 문서 조합, 19개 조건부 문단, 전체 본문/개행 동등성, 미획득 인용 제외, 출처 없는 옛 문자열, 잘못된 본문/언어/순서/공개 상태, 동일 revision 재시도와 JSON 재로드를 다룬다. 실제 세션 저장 실패·응답 유실·중복 read 거부와 기록 0개 최소 접근의 보상 불변도 검사한다.

이 원고의 `replay_committed`는 사건이 일지를 작성했다는 증거다. 대화창의 각 문장을 실제 봤다는 증거는 아니며 실제 표시 연결은 다음 18.2절에서 별도로 다룬다. 신규 수첩 UI·프로세스 재시작 커서·실제 OS 입력은 미완료다.

### 표시와 획득

- 규칙이 반환한 명시적 `evidence.key`와 허용 변수로 descriptor를 만든다. 문장 역검색으로 사건을 판별하지 않는다. 한 줄씩 표시하는 결과는 현재 공개한 segment만 남긴다.
- 화면의 변수는 당시 배치·출력·선택·각도·반전·기준점·투명도로 고정한다. JSON 왕복 뒤 정수 토큰을 정규화하며 재열람 때 현재 퍼즐 상태를 읽지 않는다. 같은 방문/언어/descriptor의 재그리기는 기록을 늘리지 않는다.
- 표시 실패는 다음 입력을 막고 명시적 재시도만 허용한다. 실제 입력과 게임 저장 성공은 별개다. 저장 응답 유실은 동일 토큰으로 확인하고 이전 로드 scope의 콜백을 거절한다.
- `ANON_PURPLE_RESIDENT_INDEX`, `F0_CURRENT_AUTHOR`, `F0_PROVISIONAL_INTENT`는 각각 별도 원고·지식 revision이다. 후보 게임 상태와 함께 원자 저장하며, 실제 획득한 J4/A1/작성자 원고와 이미 표시한 목록/선택만 추가 출처로 연결한다.
- 작성자 원고는 아직 표시하지 않은 인증 성공 대사를 선행 출처로 인용하지 않는다. 임시 의향 원고도 선택하지 않은 응답을 포함하지 않는다. 구형 완료 플래그만으로 원고/출처를 새로 발급하지 않는다.
- 알려진 A1 표식은 유형 ID와 정확한 공급 원고가 함께 맞을 때만 동결 번역을 쓴다. 그 외 이전 문자열은 `SCREEN_E_MARK_ORIGINAL`의 `original_only` 본문으로 보존한다. 다른 표식 문구와 닮았다고 의미를 바꾸지 않는다.

### 시각 자료와 제외 UI

`SCREEN_C_LAYER_*`의 의미 버전에는 표시 경로·기준 마커·선 패턴·두께·고리·변환 순서·기준점 오프셋을 `visual` 메타데이터로 동결했다. 관찰에는 해당 버전과 당시 변환 변수만 저장한다. 향후 비교 화면은 이 버전의 도형을 사용해야 하며 현재 퍼즐의 도형이나 정답 상태로 대체하면 안 된다. 이는 비교 렌더러·확대 UI의 완성이 아니다.

회전/재배열/전송/검증 버튼의 일반 조작 문구와 잘못된 API 호출 안내는 `EXCLUDED_UI`다. 실제 의미 있는 실패 진단은 등록 ID로 보존한다. UI에서 표시하지 않는 중간 조작 성공 문구의 앱 재시작 재표시는 공통 커서 정책 후속 감사 대상이며, 현재 연결 완료를 내구성 있는 커서 복구로 간주하지 않는다.

검사: `--notebook-core-smoke --ggb-dev-notebook-v2`. 실제 컨트롤러의 정상/오답·익명/완료·세 표식/세 의향·저장 실패·로드 scope를 검사한다. 별도 원고/경로/표식 배열 행렬은 실제 플레이 완주와 구분한다. 실행 결과는 [구현 현황](notebook_history_implementation_status.md)을 따른다.

- 원칙/채널/표시/온도/자기 문장의 클릭과 후속 게임 저장은 구분한다. 기록 실패는 입력을 막고 게임 저장 실패는 완료 상태를 쓰지 않는다. 응답 유실은 기존 transaction 확인으로 재시도한다.
- 마지막 저녁의 기록 저장 실패는 2초 전환을 멈춘다. 현재 로드와 다른 콜백을 차단하며 읽기 전용 재열람은 어떤 정책/온도/시간도 변경하지 않는다.
- `ending_credits.gd`와 크레딧/후속 메뉴는 `EXCLUDED_UI`다. 제작진 미정, 도구·리소스 안내, 갤러리·재선택은 조사 자료가 아니다. 단순 위치/목표/이동 버튼·표시 모드 상태/골격 조작 안내·오류 UI 역시 제외한다. 실제 합의 선택지와 조사 대상명은 제외하지 않는다.

검사: `--notebook-stay-smoke --ggb-dev-notebook-v2`. 실행 결과는 [구현 현황](notebook_history_implementation_status.md)을 따른다. 앱 재시작 커서, 통합 수첩 UI, OS 입력 인수는 별도다.
