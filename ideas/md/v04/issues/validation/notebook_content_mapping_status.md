각 원고 행에는 생산자·소스 함수/원문 공급자·사건·허용 노드·요청 variant·화자·실제 장소 취득원·공개 소유자·segment·보존 이유·한영 제목/요약/본문·번역 키·담당이 있다. `knowledge_ref`는 비어 있다. 힌트 관찰은 직접적인 공개 증거이며 퍼즐 정답이나 수첩 가설 성공을 만들지 않는다.

- 상태 `AUTHORED_ID`, 의미 버전 `1`, `entry_kind=hint_revealed`, `variant_id=requested_H1`~`requested_H5`.
- 공개 범위는 `body` 하나다. 한 단계 요청으로 다른 단계 본문을 복사하지 않는다.
- 보호 이유는 `content:hint`다. 일반 대사 2,000개 한도와 독립이다.
- 동일 콘텐츠 재요청은 새로운 관찰일 수 있지만, 같은 표시 토큰의 재그리기/저장 재시도는 하나의 관찰이다.
- BF/CF/DF는 힌트 원문 버전을 공유한다. 관찰의 `node_id`, `location_id`, 발생/대화 토큰은 실제 요청 문맥으로 저장한다.
- 재열람은 같은 의미 버전의 현재 언어를 사용한다. 버전/번역을 구할 수 없으면 당시 원문과 안내를 표시한다. 기존 저장을 최신 문장으로 덮어쓰지 않는다.

## 3. 자동 검사 근거

`--notebook-content-smoke --ggb-dev-notebook-v2`, Windows Godot 4.7.2, 격리 APPDATA, headless.

| 항목 | 결과 |
| --- | --- |
| 원고 ID / 언어 | 60 ID, 120 ID-언어 조합 |
| 실제 표시 경로 | 15 노드 × 5 단계 × 2 언어 = 150 요청, 실패 별칭 포함 |
| 미요청 단계 | 메뉴만 열기·H5 직접 요청 모두 선행 단계 미기록 |
| 실패 지원 | 실제 BF 지원 버튼으로 H5 요청, 다른 단계는 공개하지 않음 |
| 현재 언어 | 저장 버전 기준 반대 언어 재열람, 원문/UID 불변 |
| 저장 | 실제 SaveManager 재로드, 실패 롤백/동일 토큰 재시도, 게임 진행 불변 |
| 다중 segment | 시험용 앞면만 관찰, 숨은 뒷면은 표시/참조 불가 |
| 변수 | 미선언 값 거부, 비재귀 치환, 정수 JSON 왕복 후 표시 동일 |
| 잘못된 출처 | 노드·화자·variant·본문 불일치 거부 |
| 누락된 의미 버전 | 당시 원문과 fallback 안내, 최신 버전 치환 없음 |

시험용 `TEST_*` 원고는 본편 카탈로그에 포함하지 않는다. 실제 마우스/키보드, 검색 색인, 성능 검사는 이 결과에 포함하지 않는다. 첫 중간 실행의 테스트 자식 인덱스 오류는 통과에서 제외하고 명명된 본문 컨트롤을 찾도록 수정한 뒤 재검사했다.

연결 후 회귀: 에디터 import, 일반 프롤로그, 신형 모드의 1장·검은 거울·대화 기록, 저장 이관, archive 검사가 모두 통과했다. 전편 자동 경로는 일반 모드 약 126초, 신형 모드 약 180초로 각각 정상 종료했다. 이 소요 시간은 입력 지연·p95 측정값이 아니다. 실행은 종료 코드 0, 필수 PASS, 스크립트 오류 없음으로 판정했으며 환경의 Windows 루트 인증서 저장소 경고는 별도다. 문서 검사도 작업 사본 293개·실제 develop 폴더 301개 기준 통과했다.

## 4. 버전 변경 규칙

`seed_notebook_hints_v1.gd`는 최초 원고 생성 도구이며 기존 파일 덮어쓰기를 거부한다. 출시·저장에 사용한 버전 1을 최신 코드로 재생성하지 않는다. 의미가 달라지면 새 버전을 추가하고 공급자의 descriptor를 명시적으로 변경하며, 과거 버전은 보존한다. 같은 버전의 원고와 실제 표시문이 달라지면 개발 검증 저장은 오류를 반환한다. 오류를 감추기 위해 새 원문을 legacy/unmapped로 자동 전환하지 않는다.

## 5. 미완료 범위

| 생산자 | 상태 |
| --- | --- |
| NP01~NP19 | 문장/문서/선택별 `UNMAPPED`, 연결·공개 범위·번역·분기 실행 검사 필요 |
| NP20 | 명시적 원고/표시/저장/기존 재열람 연결 완료. 새 수첩 검색·비교 UI 인수는 별도 |
| NP21 | 정적 보드·오브젝트 조사/장식/조작 안내 분리 필요 |
| NP22 | 저장·갤러리 읽기 어댑터 검증 완료, 통합 수첩 소비 화면의 scope 인수 필요 |

개발 모드의 신규 미매핑은 `unmapped`로 보존하고 완료 수치에 넣지 않는다. legacy 수는 입력 슬롯마다 다르므로 고정 수치로 집계하지 않는다. 아직 작성하지 않은 콘텐츠는 총 문장 수·미실행 분기 수를 확정할 수 없으며 `미산정`으로 남긴다. NP20의 한영 누락은 0, 전체 프로젝트 번역 누락은 미산정이다. 미매핑 0·필수 분기 미실행 0 검증 전까지 `notebook_rollout`은 기본 비활성이다.
