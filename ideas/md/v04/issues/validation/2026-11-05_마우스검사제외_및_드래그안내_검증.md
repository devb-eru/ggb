# 마우스 검사 제외와 드래그 안내 검증

## 사용자 지시

2026-11-05 사용자가 마우스 진행 검사를 건너뛰라고 지시했다. 추가 마우스 입력을 중단하고 검토 계획·전체 ToDo·인수 대조표에 범위 변경을 반영한다. PASS로 집계하지 않으며 자동 재개하지 않는다. 키보드 전용 입력과 코드·저장·성능 등의 요구는 유지한다.

제외 직전 최신 격리 소스 311스크립트/63data에서 자연 진행 슬롯을 이어 P3B 이름표 5개 배치, P4의 6단계·주방 진동 기록 및 찻잔 기억 도입부까지 진행했다. P6 수면·동일 아침 복귀는 하지 않았다. 기존 `c4abc09e`의 새 게임 시작부터 진행한 이력과 최신 소스에서 이어한 이력을 하나의 동일 소스 전편 완주로 합치지 않는다.

격리 마우스 게임만 PID와 실행 파일 경로를 확인해 종료했다. 종료 스크립트의 추가 시작시각 비교에서는 PowerShell JSON 날짜의 문화권 변환 오류가 발생했으므로 시작시각 검사를 통과했다고 기록하지 않는다. 다른 Godot 편집기나 사용자 세이브를 종료 대상으로 지정하지 않았다.

## 드래그 안내 잔류

[ERR-0079](../items/GGB-ERR-2026-0079_드래그종료_안내문구_잔류.md). P3B 성공 드롭 후 item 제거와 배치는 정상인데 상단 안내가 계속 `드래그 중`으로 남고, 완료 대화와 주방 이동에도 유지되는 것을 제외 지시 전에 관찰했다.

제품 수정은 공통 prologue controller의 status 소유권과 종료 알림 처리다. 후속 `_set_status()`는 소유권을 해제해 해당 드래그가 새 피드백을 지우지 않도록 한다. 선택 아이템·퍼즐 상태·일지·저장 계약은 변경하지 않는다.

## 집중 회귀

`inventory_drag_feedback_smoke.tscn`과 두 검사 스크립트는 실제 inventory slot의 payload builder/start 신호, 대상의 drop 연결을 사용한다. 종료 알림은 `notification(Control.NOTIFICATION_DRAG_END)`로 합성한다. 실제 OS 드래그, 엔진의 종료 알림 전달, 운영 history wrapper·비동기 저장 검증은 아니다.

| 실행 | 결과 |
| --- | --- |
| 초기 검사 진단 | 구형 코드에 없는 선택 필드를 bool(null)로 변환해 검사 runtime 오류. 제품 근거와 분리 |
| 원본 정식 대조 | 244확인, 20실패, native 1, 스크립트 오류 없음 |
| 수정 후보 | 같은 244확인, 0실패, native 0 |

한영 취소·거절·다른 status 소유권, 잘못된 소유자 대화, 이름표 5개 순차 배치와 마지막 대화, 차·창문 피드백 보존을 검사했다. 실제 마우스의 최종 성공으로 보고하지 않으며 이슈는 RESOLVED/REVIEW로 남긴다.

P4에서 일부 첫 드래그가 화면을 갱신하지만 단계를 진행하지 않고 재시도 시 진행하는 관찰도 있었다. 도구·입력 타이밍·UI 갱신 원인은 분리되지 않았으므로 제품 오류로 단정하거나 이번 안내 정리 수정으로 해결됐다고 주장하지 않는다. 마우스 제외 이후 재현 입력도 수행하지 않는다.

## 관련 회귀

최초 관련 검사에는 의도적으로 미분류 raw 문장을 사용하는 fixture에 `--notebook-require-authored`를 잘못 적용해 프롤로그 10단언이 실패했다. 실행 옵션 오류로 분리하고 원로그를 보존했다. 해당 옵션을 제외한 후보의 프롤로그 회귀는 265확인/native 0/PASS다.

같은 옵션의 1장 회귀는 8단언/native 1로 실패했다. 원래 prologue controller로 되돌린 별도 실행에서도 정확히 같은 8실패가 재현됐다. [ERR-0080](../items/GGB-ERR-2026-0080_1장번역복귀_회귀불일치.md)으로 분리하고 실제 재공개인지 최신 시트/fixture 차이인지 조사한다. 이 결과를 전체 관련 회귀 PASS로 포장하지 않는다.

읽기 전용 조사에서 두 1장 실행 모두 371행의 구형 `HistoryTranscript` 접근에서 `null.text` 오류가 확인됐다. 따라서 8단언 이후 검증까지 완료한 실행은 아니다. 표면 영수증과 모달 커서가 생기는 현재 계약을 history만 제외하는 구형 비교가 처리하지 못하는 경로도 확인했다. 정확한 상태 diff와 추가 관찰 수는 로그에 없어 미확정이며, 제품 중복 공개 여부를 단정하지 않는다.

[원자료](evidence/inventory-drag-feedback-20261105/README.md)에 31파일·313스크립트 지문과 정식 원본/후보의 소스 ZIP, 초기 검사 오류·관련 회귀 실패를 구분해 보존했다. 실제 마우스 종료 알림 검증은 사용자 제외 뒤 다시 수행하지 않았다.
