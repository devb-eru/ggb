# 수첩 Writer 엄격 개발 검증

## 범위

기준 develop `f01f4bd`. [ERR-0051](../items/GGB-ERR-2026-0051_신규미등록대사_엄격개발검증_누락.md)의 입구 검증과 감사 실행 옵션을 보완한다. 전체 생산자 필수 분기·구형 피드백 예외 등록·신규 미매핑 0 인수는 이번 좁은 검사와 구분한다.

## 정책

| 조건 | descriptor 없음 | 명시 descriptor |
| --- | --- | --- |
| 일반 schema 없는 기록 | 기존 transcript 계약 유지 | 기존 기본 모드 동작 유지 |
| 신형 archive, 엄격 옵션 없음 | 기존 과도기 unmapped 허용 | 기존 authored 검증 |
| 신형 archive, debug 엄격 옵션 | `NB_PRODUCER_ID_REQUIRED`, 후보/현재 상태·revision·저장 callback 불변 | ID/버전/문단/표시/문맥 검증 후 authored 기록 |

잘못된 descriptor 타입은 신형 writer에서 모드와 무관하게 `NB_CONTENT_DESCRIPTOR`로 반환한다. 빈 사전도 실제 ID가 없으므로 기존 descriptor 검사에서 거부되며 raw로 대체하지 않는다. 콘텐츠의 공개 소유자·보존 계약은 등록 카탈로그의 필수 필드 검증을 사용한다.

엄격 모드는 새 기록 시도에만 적용한다. 구형 archive 조회·이관·원문 보존을 금지하지 않는다. debug 옵션이 없는 제품 경로를 자동 변경하거나 rollout을 켜지 않는다.

## 실행 명령

새 격리 TEMP 프로젝트와 새 증거 디렉터리를 사용한다. `-RequireAuthored`는 Godot에 `--notebook-require-authored`를 전달하며 receipt에 적용 여부를 남긴다.

```powershell
./scripts/run_notebook_runtime_audit.ps1 `
  -EnginePath <검증한_Godot_경로> `
  -ProjectPath <TEMP_격리_game> `
  -EvidencePath <아직_존재하지_않는_TEMP_증거폴더> `
  -Suites @('producer-contract', 'prologue-surfaces', 'final') `
  -RequireAuthored
```

`producer-contract`는 writer 정책을 직접 검사하는 집중 검사이며 등록 문단 합집합의 생산자 suite가 아니다. 원문·생산자 관찰 집계는 `prologue-surfaces`/`final`의 별도 trace로만 수행한다. runner는 native 실패뿐 아니라 script/parse/compile 오류를 실패 처리한다.

## 결함 재현

TEMP: `%TEMP%/ggb-producer-contract-91dcde602d194e01b90e62e9f01e5c14`.

기준 writer에 집중 검사를 추가한 최초 실행은 43단언 중 12단언 실패, native 종료 1이다. 신형 한영 원문의 누락 ID를 거부하지 않고 후보를 변경하며 실제 저장 callback까지 호출했다. 의도한 실패 재현이며 제품 PASS로 계산하지 않는다. 이후 검사에는 잘못된 descriptor 타입 반례를 추가했다.

최초 import에서 Steam self-contained 엔진의 편집기 설정 저장이 권한 때문에 실패했다. 사용자의 설치 설정을 우회 수정하지 않았다. certificate-store 경고도 보존한다. import 종료 0을 모든 환경 경고 해소로 표현하지 않으며, 별도 본편 집중 실행에는 script/parse/compile 오류를 허용하지 않는다.

## 수정 실행

현재 후보 집중 검사: 엄격 v2 45단언, 비엄격 v2 37단언, 엄격 옵션의 일반 모드 41단언 PASS. 두 언어의 ordinary/v2 계약, ID/버전/variant/문단/장소/node/실제 표시 반례, 올바른 원문·보호 정보·동일 token 재시도와 저장 전 거부를 검사한다. 이 수들은 서로 중복된 단언을 포함하므로 고유 경로 수로 합산하지 않는다.

감사 runner의 세 검사도 native 0/PASS다. producer-contract는 같은 45단언의 반복 실행이며 새로운 고유 검증 수로 더하지 않는다. 프롤로그 표면은 164 ID-언어/176 문단-언어·252상태 조건, final은 132 ID-언어/312 문단-언어·익명 자료 최종 선택 12경로/엔딩 후속 4경로를 확인했다. 원본 writer/초기 검사 소스를 별도 프로젝트에 되돌린 반례에서는 runner가 native 종료 1을 실제로 거부했다.

두 실제 관찰 trace의 고유 경로는 1,266개다. sampled archive는 각각 authored 750/2,674, legacy/unmapped 0이지만 원장에 미리 공급된 fixture도 포함하므로 전편 신규 미매핑 0으로 일반화하지 않는다. 신형 writer의 엄격 동작과 전 생산자의 필수 행동 커버리지는 다르다.

적용 작업본과 실제 실행 프로젝트의 세 변경 코드 SHA가 일치하며, 두 trace를 적용 코드로 다시 읽어 PASS다. GDScript 262개 코드 지문은 `caa377b2924f08ce9888855ca32b8af920328ac0fba11cb49212a68de921b161`이다. 수정 전 T19i 소스의 결과와 합산하지 않는다.

## 전달 검증

코드·원자료는 develop `acfe788c3671116c797db5e2468c2a7d48437977`에 보존했다. Git 아카이브를 `%TEMP%/ggb-producer-contract-roundtrip-e722d86193314c879b60686511f2692e/tree`에 풀어 다음을 확인했다.

- 변경 세 코드 SHA가 검사 후보와 일치한다. 재현 당시의 세 소스도 저장한 `before` SHA와 일치한다.
- native receipt 9세트의 종료 코드·완료 여부와 stdout/stderr SHA가 일치한다. 재현/이전 코드 거부의 native 1은 실패 근거이며 PASS로 바꾸지 않는다.
- 감사 runner SHA가 실제 실행한 소스와 일치한다.
- 두 엄격 trace가 아카이브 코드 262개와 카탈로그 지문에 일치하며 고유 1,266경로 대조 PASS다.
- 아카이브 문서 423개·이슈 70개 및 등록 참조 검사 PASS다. 실제 개발 폴더의 사용자 문서를 포함한 검사도 433개 PASS다.

ERR-0051 VERIFIED/DONE, T19k 명시 범위 완료다. 아카이브 검증은 이미 실행한 원자료와 코드의 보존 확인이며 새 전편 실행이나 OS 입력 검증이 아니다.

## 잔여

- 기존 T19i 21검사에는 엄격 옵션을 적용하지 않았다. 해당 로그를 이번 옵션 통과 근거로 재사용하지 않는다.
- 오래된 `last_feedback`는 descriptor가 없을 수 있다. 실제 신규 행동과 구형 재표시의 출처를 명시적으로 구분해야 한다. 임의 bool 예외나 문장 역검색으로 ID를 추측하지 않는다.
- 전 생산자 엄격 적용·필수 분기 대조·개별 UI 제외 전수, 엔진 채택·정식 성능·전편 실제 입력 인수는 남아 있다.
