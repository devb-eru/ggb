## 2. 발견과 수정

### 2.1 초기 R1 생략: ERR-0065

기준 제품의 실제 P6 취침 버튼·확인·대사 진행으로 수면을 시작한다. SaveManager가 idle 후보를 본파일에 승격한 직후 ACK와 live 설치 전에 소유한 격리 자식을 종료했다. 새 Bootstrap의 이어하기가 R1 세 문장을 표시하지 않고 본편을 열었다. native 1과 정확한 생략 단언을 별도 기준 자료로 보존한다.

새 v2 P6 완료 후보에 `PROLOGUE_FIRST_WAKE_REQUIRED`를 함께 저장한다. R1 세 콘텐츠 `NB_PR_R1_WAKE`, `NB_PR_R1_SAME`, `NB_PR_R1_NOTES`의 완료 커서가 내구 확정될 때 `PROLOGUE_FIRST_WAKE_COMPLETED`를 추가한다. 완료 표지를 추가한 **뒤** 앵커를 계산한다. 물리 리셋이 로컬 표시 커서를 지워도 미완료 R1으로 돌아가고, 완료 이후에는 재표시하지 않는다.

Bootstrap의 직접 진입·비동기 리셋 완료·캠페인 개방을 같은 pending 판정으로 연결했다. 표지 없는 구형/개발 체크포인트를 새 첫 기상 미완료로 추정하지 않는다. P6 이전 영구 지식, 기존 원문·UID·책갈피/비교와 사용인 기억은 덮어쓰지 않는다.

### 2.2 프롤로그 회귀 검사 순서: ERR-0067

기존 집중 검사에서 화면 생성 직후의 deferred 초기 표시 저장을 기다리지 않은 채 다음 seed와 테스트 대사를 시작했다. `seed disk and backup` 단언 실패·실패 load의 `snapshot` 접근 오류·native 1을 보존했다. 제품의 writer 충돌 거부를 완화하지 않고 검사 장치에서 화면 요청과 SaveManager 작업의 연속 idle을 확인한다. worker 중 대기 프레임과 idle tail은 구분한다.

보완된 검사 장치로 기존 42조건, 이를 사용하는 선택·surface·자연 행동 회귀를 재검사한다. 실행 중인 제품/검사 파일은 수정하지 않았다. 132좌표 matrix가 종료된 뒤 검사 장치를 변경했고 제품 265개 소스는 그대로 유지했다.

### 2.3 다음 수정: ERR-0066

복귀한 A1의 새 `NB_CH1_WAKE` 문맥이 `M1_BEDROOM`인데 정규화된 화면/상태는 `M2_BEDROOM`이다. 초기 reset의 구형 위치와 candidate 설치 전에 live에서 캡처한 신규 문맥이 원인이다. 과거 원문의 위치를 이관해서 고치는 대신, 새 reset 위치와 새 기상 문맥의 출처를 정규화된 후보로 맞추는 후속 수정이 필요하다. 현재 고정 제품 검사와 섞지 않았다.

### 2.4 증거 비교·실패 판독: ERR-0068

최초 독립 검사가 `90`/`90.0` 재직렬화 차이를 상태 변조로 오판했다. 132좌표의 2,296개 leaf 차이는 전부 같은 값의 Int64/Double 표현 차이였고 실제 값·구조 차이는 0개다. dictionary/array와 유한 숫자의 정확한 값을 재귀 비교하며 int/float 교차 `2^53` 이상·반올림·근사 비교를 거부한다. 문자열/키는 ordinal 비교로 Unicode 정규화 차이까지 유지한다.

다음 감사가 기준 실패에 없는 성공 전용 `run.result.json`을 요구해 중단한 기록도 보존한다. 기준 실패는 실제 native 1 receipt와 stdout의 단일 JSON 오류 요약을 읽는다. 내장 migration의 null 외부 harness는 명시적인 mode와 제품 소스 지문으로 검증하며 다른 외부 harness 누락을 허용하지 않는다. 세 차례 독립 검사 장치 실패는 최종 PASS에 합산하지 않는다. 숫자·형식·원문 비교의 14조건과 기존 6개 증거 변조 반례로 보완을 검증했다.

## 7. 재실행

`scripts/run_notebook_reset_process_audit.ps1`의 seed/resume/verify를 같은 격리 case 경로에 순서대로 실행한다. 제품·evidence 경로는 host TEMP 아래여야 하며 사용자 세이브를 대상으로 하지 않는다. seed의 강제 종료만 정상적인 검사 단계이며 resume/verify의 nonzero/null native를 합격으로 취급하지 않는다.

최종 봉인 자료는 `evidence/2026-10-10_reset_process/bundle.zip`과 `bundle.json`에 수록한다. 외부 임시 경로는 탐색 편의일 뿐 전달 근거가 아니다. 독립 확인 명령:

- 최종 raw 2,706파일, ZIP 17,688,550바이트.
- 최종 ZIP SHA-256: `4f40d1dd6378bf635570b4adff76c67f1bef05d9d237a23f3f9bf115939e4e3d`.
- 첫 실패 봉인 및 각 후속 봉인의 지문은 `before-independent*`와 bundle metadata에서 구분한다. 앞선 native 1/중단을 최종 합격에 합산하지 않는다.

```powershell
./scripts/audit_notebook_reset_process.ps1 `
  -EvidencePath ./ideas/md/v04/issues/validation/evidence/2026-10-10_reset_process `
  -RepoPath . -SelfTest
```

PowerShell 7에서 실행한다. bundle의 바이트/SHA, raw 목록·SHA, 실행된 검사 장치/runner, 동일 제품 소스를 확인한다.

봉인은 격리 APPDATA profile 전체 대신 실행 로그·receipt·검증된 cut/복귀 snapshot·문맥·검사 소스를 수록한다. 별도 프로세스의 실제 SaveManager가 읽고 확인한 결과를 대조하는 근거이며 디스크 이미지나 OS 전원 차단 증거가 아니다.
