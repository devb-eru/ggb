# 프롤로그 자연 행동과 비동기 저장 합성 검증

## 상태

T21l의 명시된 행동 경계·복귀 국소 검증 및 T21l-d 전달 완료. 같은 최종 코드의 자연 검사 1회·기존 회귀 9회·별도 프로세스 12회, 총 22회 native 0/PASS와 독립 13,920확인·6조작 반례 거부를 확인했다. 전체 목표, 정식 성능, Windows 전편 입력, 제품 엔진 채택을 완료 처리하지 않는다. 제품 4.7 기준과 rollout OFF는 유지한다.

## 구현 범위

기준 develop은 `22c84f30f24f3e1c46055d45e06c5fd85eb00ae5`다. 제품 변경은 `game/scripts/prologue/prologue_controller.gd` 한 파일이며, 격리 프로젝트는 265개 제품 스크립트 지문을 각 receipt에 기록한다. 검사 코드는 별도 임시 폴더에서 실행한다. 공식 `4.6.3.stable.official.7d41c59c4` 후보를 사용하지만 설치된 Steam이나 제품 엔진 기준은 바꾸지 않는다.

일반 화면 문구를 기존 `--ggb-dev-notebook-v2 --ggb-dev-notebook-async` 개발 경로에 합친다. 추가 surface 전용 옵션은 더 이상 필수가 아니다. 실제 입력 입구의 행동 중에는 물리 변화·인벤토리·수첩·표시 문구·대사/선택을 모으고, 행동이 끝난 뒤 하나의 후보를 worker에 전달한다. 대사가 없는 입력은 `action` 후보이며 대화 뒤 완료 callback의 `progress` 후보와 구분한다.

실패 action은 동일 후보·관찰 토큰으로 명시 재시도한다. 행동 자체를 재실행하지 않으며 scope/generation/locale/진행/수첩/인벤토리/창문/표시 요청·active 목록의 변경을 거부한다. 초기 동기 진행 저장은 worker에 예약된 표시 요청을 먼저 소비하지 않는다.

초기 진행 저장 자체, 인벤토리 drag-start, 정상 리셋과 다른 본편 단독 저장까지 전부 비동기화한 것은 아니다. 이 잔여 작업은 전체 T21에 유지한다.

원본에서 `_apply_window_tool`은 물리 상태 적용 전 특수 대사를 보여 worker를 시작한다. 뒤의 `_save_progress`가 pending을 거부하면 `_load_progress`로 도구 결과가 되돌아갈 수 있다. [ERR-0057](../items/GGB-ERR-2026-0057_프롤로그_비동기도구행동_저장분리.md)로 관리한다.

검사 정규화에는 기존 `StateSnapshotValidator.same_persisted_value`를 사용했다. 값을 잘라내거나 누락 필드를 비교에서 제외하지 않는다. 첫 검사·진단·회귀 실패와 당시 후보/검사 코드는 성공 자료와 분리 보존한다. 다른 후보의 PASS를 최신 소스로 소급하지 않는다.

최종 컨트롤러 SHA-256은 `84a8c8e618c1c8de1252c541071242b645df6b113484a9ec1b96bbeba8da2567`다. 요청 재시도 guard 보완 전 `a0c20a4d...`, 초기 저장 guard 보완 전 `94c98a56...`의 자료는 역사적 검사이며 최종 22회에 포함하지 않는다.

기존 9회귀는 선택, 동기 프롤로그 232분기, 커서 seed/resume/completed 66/26/16, 저장 안전성 381, host 548(내부 async 342), 공통 async 72조건·870단언, surface로 구성한다. surface 실행은 같은 최종 지문의 먼저 완료된 자료를 복사 보존한 것이며 다시 실행한 것으로 세지 않는다.

독립 검사 13,920확인·6반례 PASS. manifest의 바이트/SHA·전체 코드 분모·native 종료·실행 harness/runner·원로그/결과를 대조했다. 로그 변경, 종료값 변경, 중복 조건, 혼합 소스, 프로필 변경, 프로세스 시간 역전은 모두 거부한다. 성능 예산 합격 검사는 아니다.

## 자연 검사 분모

| 종류 | 한 언어 조건 | 내용 |
| --- | ---: | --- |
| 실제 창문 도구 | 7 | 솔/스패너/천/물/새 관찰, 승격 실패 재시도, 확정 응답 유실 |
| 자연 이벤트 연결 | 8 | P2 완료, 홀→P2 인사, P3 클릭·드롭과 질문, P3B 5명, P4 두 질문, P5 날씨 기록 |

| 실패 후 재시도 문맥 변경 | 8 | locale/scope/generation/progress/notes/inventory/window/requests |
| 합계 | 32 | 한영 각 32조건, 총 64조건 |

고정 이벤트 시작 fixture 뒤 실제 인벤토리/창문/hotspot/choice 신호를 사용한다. P3 드롭은 대상의 `inventory_item_dropped` 신호를 사용한다. OS 마우스·키보드 입력이나 실제 drag-start를 증명하지 않는다.

P3는 발견→질문→답변→질문 복귀→침묵→나머지 책 정리를 연결했다. P4는 여섯 차 단계→전조 대사→명시 맥박 기록→일곱 기억 닻 대사→손잡이 되돌림→질문→이리스 인사→홀 복귀를 실행했다. 후속 이벤트 완료 플래그를 직접 true로 바꾸는 것으로 이 행동을 대신하지 않는다.

## 검증 명령

```powershell
./scripts/run_notebook_prologue_natural_async_audit.ps1 -EnginePath <official-engine> -ProjectPath <isolated-project> -EvidencePath <new-temp-evidence> -Mode full
./scripts/run_notebook_prologue_natural_async_audit.ps1 -EnginePath <official-engine> -ProjectPath <isolated-baseline> -EvidencePath <new-temp-baseline-evidence> -Mode windows -ExpectedFailure
```

`-ExpectedFailure`는 실패를 제품 성공으로 바꾸지 않는다. 명시 native 1·FAIL·완료 분모·스크립트 오류 없음이 일치해야 기준 재현을 보관한다. 최종 후보 성공은 이 옵션 없이 검사한다.
