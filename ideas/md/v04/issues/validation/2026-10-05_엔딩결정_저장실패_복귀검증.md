# 엔딩 결정 저장 실패·복귀 검증

- 기준 develop: `759d2e4a1bca2d2d412f713bcbda3193b242be11`.
- ToDo T12 하위 검증. 기존 엔딩 선택창 표시·취소·질문/답변 저장 실패 검사에 보상 저장 실패 후 디스크 복귀 경로를 추가한다.
- 변경 테스트: `game/scripts/tests/notebook_modal_presentation_smoke.gd`.
- 제품 코드·엔딩 조건·원문·보존 정책은 변경하지 않는다.

## 입력 행렬

| 축 | 값 |
| --- | --- |
| 표시 언어 | ko-KR, en-US |
| 최초 확인한 엔딩 | reality, stay |
| 복귀 뒤 행동 | 같은 선택 재시도, 취소, 취소 후 반대 선택 |

2 × 2 × 3 = 12개 경로다. EDC의 기존 적법한 개발 checkpoint를 사용한다. 최종 권한·장치 조사를 새로 완주한 검사나 F0 잠정 의향의 모든 조합 검사는 아니다.

## 실제 실행 순서

1. 최종 확인창을 열고 표시 기록을 저장한다.
2. 선택 답변은 저장되도록 두고 게임 진행 저장만 거부한다.
3. selection_pending 창 복귀, final_decision/branch의 미확정과 게임 상태 불변을 확인한다. 관찰 기록·표시 cursor 및 실제 관찰로 뒷받침되는 surface receipt만 허용한다. 기존 same_surface_gameplay 검증기로 과거 원문 불변, 신규 관찰 수·revision과 receipt 출처의 일치를 검사한다.
4. 기존 controller를 제거하고 실제 저장 슬롯을 LoadCoordinator로 다시 불러와 controller를 재생성한다.
5. 로드만으로 선택이 실행되거나 원문이 추가되지 않으며, 동일한 답변 토큰이 복귀하는지 확인한다.
6. 복귀 후 명시적으로 재시도하거나 취소한다. 반대 선택 사례는 취소 대사를 마친 뒤 f3_open을 실행해 다시 선택창을 열고 반대 엔딩을 결정한다.
7. 성공 저장 응답 유실도 주입해 커밋 확인을 거친다. 정확한 최종 결정과 최초 답변의 보존/비중복을 확인한다.
8. 이전 선택창 callback을 호출해도 뒤의 결정이 바뀌지 않아야 한다.

취소해도 실제로 표시·선택한 과거 답변을 삭제하지 않는다. 답변 기록은 플레이어의 입력 이력이며 엔딩 실행의 성공 증거와 구분한다. 선택을 바꿀 때 기존 입력 이력이 새 결정으로 덮어써져서도 안 된다.

headless에서 실제 controller와 handler, 저장 파일을 사용하지만 Windows 입력 장치 검증은 아니다. 디스크 재로드는 같은 프로세스에서 수행하며, 아래 기존 seed/resume/completed 검사는 별도 프로세스 회귀다. 두 범위를 혼동하지 않는다.

## 초기 검사 오류

첫 실행은 아직 생성되지 않을 수 있는 branch_committed를 필수 Dictionary 키로 가정해 테스트가 중단됐다. 제품 코드와 같은 미설정=false 규칙으로 접근하도록 수정했다. 이 오류는 게임의 엔딩 저장 실패가 아니라 테스트의 선택 필드 취급 오류다. 대사 진행 루프에는 상한과 완료 단언을 두어 검사 자체가 무한 반복되지 않게 했다.

다음 실행의 12개 상태 차이를 집중 진단한 결과 모두 NOTEBOOK_SURFACE_RECEIPT 추가였다. 행동 직전 정상적으로 관찰한 화면의 출처를 저장하는 동작이므로, receipt를 삭제해 비교하는 대신 기존 엄격한 same_surface_gameplay 검증기로 확인한다. 별도로 관계 값 변조 및 잘못된 receipt 출처를 주입해 두 경우 모두 거부되는지도 검사한다.

첫 전체 seed 실패 뒤 이어진 resume은 seed가 만들지 못한 기대 파일 때문에 추가 오류를 냈다. 이를 독립 제품 결함으로 세지 않으며, 최종 실행기는 선행 단계 실패 시 의존 단계를 실행하지 않도록 했다. 집중 진단은 --ending-recovery-only로 재현할 수 있고 전체 회귀와 구분한다.
