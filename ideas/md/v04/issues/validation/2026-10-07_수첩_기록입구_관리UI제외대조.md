# 수첩 기록 입구와 관리 UI 제외 대조

후속 상태: ERR-0050은 develop `1a70bef`에서 원 대사 보존·별도 UI 경고로 수정하고 집중 회귀·Git 전달 검증까지 완료했다. 아래 `962a8c8`의 실패 재현은 과거 근거로 유지한다. descriptor 없는 신규 writer의 개발 검증 입구는 별도 [ERR-0051 엄격 검증](2026-10-07_수첩writer_엄격개발검증.md)에서 보완하며, 전체 호출부/필수 분기 인수는 계속 남긴다.

## 범위와 판정

기준 `962a8c8`의 생산자 추적 실행과 별도로 기록을 새로 만드는 입구, 기존 원장을 교체하는 관리 작업, 표시만 하는 UI를 대조했다. 함수명 검색 결과뿐 아니라 분리된 후보의 저장·설치와 실제 표시 호출 연결을 확인했다. 아래는 **공통 입구와 이번에 확인한 관리 경계**의 목록이며 각 생산자의 모든 본편 행동/선행 조건을 검사했다는 뜻이 아니다.

T19i의 최신 등록 문단 관찰량을 이 목록의 필수 분기 수로 변환하지 않는다. `EXCLUDED_UI`는 문장 ID를 발급할 대상이 아니지만, 제외 이유와 새 본편 원장 비오염을 확인해야 한다.

## 신규 관찰 입구

경로 기준은 `game/scripts/`이다. 줄 번호보다 함수명을 기준으로 찾는다.

| 입구 | 호출 연결 | 분류와 책임 | 남은 검사 |
| --- | --- | --- | --- |
| `systems/dialogue_history_writer.record` | 실제 표시 줄 → `append_to_snapshot` → `_commit_snapshot` | 현재 표시의 원문·문맥·descriptor·cursor를 후보에 반영한 뒤 저장 | 새 raw 호출의 개발 모드 거부와 구형 예외의 명시적 구분 |
| 같은 파일 `append_to_snapshot`의 descriptor 분기 | `notebook_content.observe` → `notebook_archive.append_observation` | `AUTHORED_ID`; 등록 의미 버전, 문단, 화자, 언어와 실제 표시 일치 검사 | 호출자별 누락/반복/중단 경로는 T11~T16 |
| 같은 파일의 descriptor 없는 분기 | `notebook_archive.append_unmapped` | 과도기 예외; 신규 authored 성공으로 간주하지 않음 | 구형 마지막 피드백과 신규 시스템 안내를 반드시 구분. ERR-0050에서 실제 신규 오류 재현 |
| 같은 파일의 schema 없는 분기 | `history.entries.append(payload)` | 기본 rollout 비활성의 구형 기록 계약 | 구형 정상 모드 회귀를 신형 인수와 구분 |
| `chapters/chapter_one_controller._record_current_history_line` | `_present_dialogue_line`/`_advance_dialogue` → session writer | NP04와 상속 후반 대사. 실제 표시 시점에 한 줄씩 | 발생 전 node, 상속 위치, 실패 후 같은 token 재시도 |
| 같은 파일 `_record_modal_options`, `_recorded_choice_pressed` | 명시 descriptor의 표시 집합/확정 선택 → session writer | NP05 및 해당 후반 소유 생산자. 미선택 답변을 만들지 않음 | 모든 선택창의 저장 실패·중단 조합은 T12 |
| 같은 파일 `_read_clock_hint` | 명시 요청 단계 → descriptor 대사 → 동일 writer | NP20; 메뉴 진입과 힌트 첫 공개를 구분 | 실제 입력/모든 복귀 위치는 별도 |
| `prologue/prologue_controller._record_prologue_text` | 표시 대사/선택/확인창 → writer 또는 후보 기록 | NP01/02; 실제 P 발생 문맥과 공개된 줄 | 전편 OS 입력 검사를 대체하지 않음 |
| 같은 파일 `_persist_prologue_progress` | 표시 요청·자료 획득 → `notebook_knowledge.acquire` 또는 `writer.append_to_snapshot` → 실제 저장 | NP03/21; pending 요청과 실제 확정 원장 분리 | 전 프롤로그 중단 위치 전수는 남김 |
| `systems/notebook_surface_capture._write` | `queue_descriptor`/선택 요청 → session `record_viewed_line` | NP21 또는 내용 소유 생산자; 표시 receipt로 재그리기 중복 억제 | 전체 방 방문/새 행동/재선택 실기 대조 |
| `systems/notebook_event_notes.write` | session의 `_write_note`와 각 `*_notebook` adapter → `notebook_knowledge.acquire` | NP06~19 자료. 정의/원문/기존 출처를 검증하고 revision 획득 | 해당 action에서 실제 자료가 확정되는 시점 전수 대조 |
| `systems/journal_four_notebook.write`, `reality_notebook` 획득 | 합성된 명시 문단·기존 출처 → `notebook_knowledge.acquire` | J4/현실 페이지; 단순 대사 기록과 자료 완료를 구분 | source 조합과 미획득 문단 누출의 잔여 조건 |
| `systems/notebook_knowledge.acquire` | 검증된 관찰 → `notebook_archive.append_observation`와 ledger revision | 출처 실재성/보호/의미 버전 확인. 새 자료 원장 생산 | 신규 공급 코드의 우회 쓰기·누락 검출 계속 필요 |

## 원장 교체와 관리 작업

| 경로 | 바꾸는 것 | 새 본편 대사 생산 여부 |
| --- | --- | --- |
| `notebook_archive` 생성/구형 래핑·분기 복사 | archive 컨테이너, 원 출처와 새 branch | `LEGACY_SNAPSHOT` 또는 분기 관리. 과거 글을 새 공개로 만들지 않음 |
| `notebook_migration` | 검증한 구형 사본 → 신형 컨테이너 | 이관이지 새 본편 action이 아님 |
| `developer_checkpoints.activate` | 격리 개발 snapshot/분기와 저장 슬롯 | 개발 fixture 공급. 실제 플레이 근거로 수입 금지; 이후 실제 새 행동은 별도 |
| `notebook_commands`, `notebook_save_worker` | 책갈피/비교 고정 등 참조·보호 상태 | 기존 관찰 참조만 변경. 새 대사 생성 금지 |
| `notebook_presentation` | 표시 cursor·관찰 증거와 공개 위치 | 원문 공급자가 아님. 완료 cursor가 숨은 대사를 새로 만들면 오류 |
| `ending_gallery_store`, `ending_gallery_pages` | 불변 보관 snapshot과 읽기 어댑터 | NP22 소비. 현재 슬롯/반대 엔딩과 합치거나 조회를 본편 발생으로 기록하지 않음 |

자료 adapter의 `state.meta_progress.dialogue_history = acquired.archive`는 확인된 획득 후보의 설치다. 이 대입을 모두 미등록 대사로 세지 않는다. 반대로 실제 writer가 raw 안내를 받았을 때 단순 UI라는 의도만으로 제외됐다고 주장하지 않는다.

## 의도적 UI 제외

| 경계 | 제외 항목 | 구현상 확인 | 근거/잔여 |
| --- | --- | --- | --- |
| 공통 메뉴/설정/수첩 열고 닫기 | 메뉴 제목, 설정 안내, 필터, 페이지 이동 조작 | plain modal/조회 host이며 대사 writer로 직접 보내지 않음 | 모든 화면의 실제 OS 입력/비오염은 미완료 |
| 기록된 선택창의 `kind=ui` | 일반 UI 닫기/돌아가기 | `_recorded_choice_pressed`에서 authored 선택 기록을 건너뜀 | 서사적 취소 descriptor와 혼동 금지 |
| utility modal | 단순 힌트 메뉴, 수량/실패 보조 안내 | 표시 위치 저장과 실제 힌트 요청 대사 분리 | NP20 새 공개는 별도 명시 action |
| 크레딧 화면 | 제작 도구/페이지/조작 안내 | `_history_enabled`가 크레딧과 이후 관리 화면을 제외 | 보조 저장 실패가 빈 대사를 새로 만들지 않는지 ERR-0050 회귀 |
| 갤러리 메뉴/상세 | 목록·보관 페이지와 재열람 조작 | `_gallery_menu/_gallery_page`는 plain modal. 읽기 전용 수첩 scope | [소비 scope 검사](2026-10-07_갤러리개발소비_scope_대조.md)와 연결; 같은 소스 전수로 합산하지 않음 |
| F3 사본 만들기/이어보기 관리 | 사본 안내, 생성 실패/완료 상태 | `_show_reselect_notice`는 plain modal | 기존 사본 생성 후 관리 안내 수정과 새 ERR-0050은 다른 호출 경계 |
| 본편 성공 후 보조 사본/감상 저장 실패 | 기술 저장 안내 | 기준 소스는 실제 대사로 보내 원문 대체 발생 | **제외 실패**. [ERR-0050](../items/GGB-ERR-2026-0050_보조저장실패_안내가_대사기록을_대체.md), 한영 실제 재현 |

## 독립 필수 분기의 예: F3 저장 경계

| 조건 | 확인해야 할 결과 | 이번 상태 |
| --- | --- | --- |
| 세 대상/요약 미완료 | 최종 확인 거부, 확인 대사/결정 미생산 | 기존 final suite; 이번 별도 새 전수로 세지 않음 |
| 본편 저장과 F3 사본 저장 정상 | 원 확인 대사, EDC, 결정 미정 | 수정 후보 집중 검사 및 기존 suite 회귀 |
| 본편 성공, F3 사본만 실패 | 같은 원 확인 대사, 별도 언어별 UI 경고, 새 시스템 기록 0 | 기준에서 결함 재현. 수정 후보 집중 검사 진행 |
| 본편 저장 실패 | 진행 되돌림, UI 실패. 보조 성공으로 위장 금지 | 기존 저장 실패 회귀; 새 전체 분모 감사는 남김 |
| 대사 기록 저장 실패 | 다음 줄/결정 진행 차단, 같은 표시 token 재시도 | 기존 final suite; 경고 동시 실패 우선순위 추가 확인 필요 |
| 완료 뒤 재로드/재그리기 | 이전 원문/UID/순번 불변, 동일 관찰 중복 없음 | 집중 재로드와 전체 suite를 구분 |

따라서 `F3_OPEN` 등록 문단 한 개를 관찰했다고 위 모든 조건이 통과한 것은 아니다. 다른 생산자의 독립 선행 조건/재시도/관계 분기 목록과 실제 관찰의 대조는 T10/T19에 계속 남긴다. 신규 미매핑 0과 필수 분기 미실행 0을 아직 선언하지 않는다.
