## 확정된 실행과 집계

새 실행 20개와 같은 소스 지하 1개가 모두 통과했다. 순차 실행 부모 프로세스도 native 0으로 종료했으며 필요한 검사 프로세스는 남아 있지 않다. 다음 최종 집계를 확인했다.

1. 21개 receipt의 completed=true, native 0, require_authored=true 및 stdout/stderr 원본 바이트 SHA 일치 PASS.
2. 정확한 PASS 표식, 스크립트/파싱/컴파일/실행 오류 없음과 trace의 같은 264개 소스/29개 카탈로그 지문 PASS. 기존 인증서 저장소 경고만 별도 허용한다.
3. 등록 ID 1,685개/의미 정의 1,736개. 최신 문단 2,477개 × 한영 = **4,954조합 모두 관찰**, 미관찰 0. 고유 7필드 경로 tuple는 **5,134개**다.
4. 독립 inventory의 NP01~22 최신 등록량 대조 PASS. 같은 로그 42개 중복 입력의 고유 경로 집합 불변 PASS. 수정 전 소스의 content 로그 혼합은 `STALE_SCRIPT_CORPUS`로 거부 PASS.

## 원자료와 재검증

- [최종 합집합 JSON](2026-10-10_수첩생산자_동일소스_엄격전체합집합.json), [독립 inventory](evidence/2026-10-10_strict_producers_resume_inventory.json), [receipt·중복·이전 소스 거부 검사](evidence/2026-10-10_strict_producers_resume_checks.json).
- `evidence/2026-10-10_strict_producers_resume_{suite}.out.log/.err.log/.run.json`: 새 20개 실행의 원본 바이트와 native receipt. 예: [권한/아카이브 stdout](evidence/2026-10-10_strict_producers_resume_authority-archive.out.log), [receipt](evidence/2026-10-10_strict_producers_resume_authority-archive.run.json).
- 지하 재사용은 `evidence/2026-10-10_strict_producers_fixed_basement.*` 한 세트다. 기존 지하 반복/비엄격 실행을 새 21개 집계에 포함하지 않는다.
- 명시 순서: basement → fracture → fracture-surfaces → puzzle-surfaces → chapter-one-notes → chapter-surfaces → prologue-surfaces → mara1 → luca → iris → stay → mirror → chapter-one → content → modals → journal-four-display → settlement → core → final → reality → authority-archive.
- 개발 옵션 실행: `scripts/run_notebook_runtime_audit.ps1 -EnginePath <격리 엔진> -ProjectPath <격리 game> -EvidencePath <새 경로> -Suites <위 suite> -RequireAuthored -TimeoutSeconds <1800 또는 3600>`. 실제 순차 실행은 첫 실패에서 중단하도록 구성했다.
- 집계: `scripts/audit_notebook_runtime_union.ps1 -GamePath <해당 tree의 game> -TraceLogs <위 순서의 21개 .out.log>`; 독립 등록량: `scripts/audit_notebook_producer_inventory.ps1 -GamePath <해당 tree의 game>`. 각각 `-SelfTest`도 실행한다. `require_authored=true`는 각 native receipt에서 별도로 확인한다.
- 최초 로컬 검증 도우미의 화면 요약은 OrderedDictionary를 `Select-Object`로 투영해 null을 표시했다. 생성된 JSON은 올바른 값이었으며 원자료/집계 실패가 아니었다. 명시적 PSCustomObject 투영으로 도우미 표시를 수정하고 실제 JSON으로 값과 원자료 SHA를 다시 확인했다. 도우미는 제출 코드/실행 소스 지문에 포함하지 않는다.
- 첫 저장 결과 재대조는 JSON 직렬화 문자열의 객체 키 순서까지 동일성을 요구하여 거부됐다. 객체 키 순서만 비의미적으로 비교하고 배열 순서·모든 키/값·스칼라 타입은 그대로 대조한 구조적 재검증 PASS. 원자료를 수정하거나 배열을 정렬해서 차이를 숨기지 않았다.

## 표본과 전체 인수의 구분

- content 원장 표본은 authored 1,300 / legacy 953 / unmapped 0이다. 다른 20개 표본의 legacy/unmapped도 각각 0이다. 구형 checkpoint와 과거 마지막 피드백을 포함하므로 이전 소스의 legacy 765/unmapped 188과 합산하거나 신규 발생 수로 변환하지 않는다.
- 구형 원문이 정확한 출처의 legacy로 분리된 결과를 확인했지만, 전 생산자의 실제 신규 호출 전수에서 unmapped 0을 증명했다는 뜻은 아니다.
- 합집합의 분모는 최신 **등록 문단 × 한영**이다. 모든 선행 조건·행동·관계·실패/재시도·중단의 독립 필수 분기 분모와 다르다.
- NP22는 조회/관리 소비 책임이다. 등록량 0/0을 소비·제외 경로 전체 완료로 세지 않는다.
- `required_branch_coverage=NOT_AUDITED`, `new_unmapped_count=null`, `excluded_ui_count=null`을 유지한다. 미확인을 0으로 쓰지 않는다.
- 실제 게임 IME 다섯 국소 조건의 사용자 정상 확인은 기존 T22d 근거로 보존한다. 이번 headless 소스의 새 물리 입력으로 반복 집계하지 않는다.

## 남은 작업과 전달 상태

T19l2 동일 소스 엄격 실행·집계는 완료했고 develop 전달 검증은 진행 중이다. 전체 T10~T19의 독립 필수 호출/신규·legacy·UI 제외 대조, NB-Q/NB-AQ 최종 인수, 성능·메모리, 공식 후보의 최신 호환/빌드·채택, 실제 마우스 전용·키보드 전용 전편 완주는 계속 미완료다. 최종 아트/사운드 교체와 개인 자유 메모는 이번 범위에 추가하지 않는다.

### 전달 확인

아직 develop에 제출하지 않았으므로 commit/push·원격 SHA·Git tree 재검증을 완료로 표시하지 않는다. 해당 근거가 확정되면 이 절을 갱신한다.
