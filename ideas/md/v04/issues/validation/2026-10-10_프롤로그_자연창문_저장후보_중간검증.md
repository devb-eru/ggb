# 프롤로그 자연 창문 저장 후보 중간 검증

## 상태와 범위

T21l의 **역사적 중간 검사**. 당시 develop 반영 전 작업본 후보에 대한 기록이며 후속 수정의 최신 판정은 [자연 행동 합성 검증](2026-10-10_프롤로그_자연행동_비동기합성_검증.md)을 따른다. 전체 프롤로그, 별도 프로세스 복귀, Windows 물리 입력, 성능 및 제품 엔진 채택 인수가 아니다. T21k의 별도 surface 옵션 성공을 T21l 완료로 대체하지 않는다.

사용자가 답한 실제 게임 IME 네 조건 정상 결과는 [기존 공식 런타임 비교](2026-10-06_한글IME_공식런타임_비교.md)의 실제 게임 다섯 국소 조건과 동일하다. 새 물리 입력 실행이나 추가 합격 수로 집계하지 않는다. ERR-0042 OPEN, 제품 4.7 기준과 rollout OFF는 유지한다.

## 후보의 의도

일반 surface를 기존 v2/async 개발 경로에 합친다. 입력을 막는 검사 자체가 surface worker를 시작해 실제 행동을 버리거나, 도구 행동이 끝나기 전에 특수 대사 worker가 시작되는 순서를 개선한다.

실제 행동 중에는 저장을 모아 물리 변화, 인벤토리 선택, 수첩 관찰과 새 표시 대사를 한 후보로 준비한다. 대사가 없는 행동은 `action` 후보이며 내구 저장 실패 시 동일 초안과 관찰 토큰으로 명시 재시도한다. 재시도는 물리 행동을 다시 실행하지 않는다. 이 설명은 검증 중인 구현 의도이며 미검증 방 이동·다른 이벤트에도 정상임을 단정하지 않는다.

첫 검사에서 잘못 기대한 `observed`는 유효한 커서 phase가 아니다. 제품 규약은 `reading`이며 `notebook_presentation.observed(cursor, snapshot)`는 대응 관찰 존재를 검사하는 별도 함수다. 정정본은 둘을 함께 검사한다. 첫 원자료와 당시 검사 스크립트는 보존했으며 첫 실패를 제품 오류 또는 PASS로 바꾸지 않는다. 제품 후보는 두 창문 실행에서 동일하다.

두 언어에서 실제 인벤토리 슬롯, 창문 hotspot과 영역 Control의 신호를 사용했다. 직접 물리 상태를 바꾸어 기대 결과를 만든 것이 아니라 고정 시작 fixture 이후 도구 행동으로 변화를 확인했다. OS 마우스·키보드 이벤트 주입이나 전편 자연 완주를 뜻하지 않는다.

확인한 일곱 상황: 거친 솔의 먼지 확산과 첫 대사, 스패너 첫 대사, 천으로 위쪽 먼지 제거, 물로 얼룩 제거·아래쪽 젖음, 세 번째 창문의 새 관찰과 대사, 승격 실패 후 실제 재시도 버튼, 내구 저장 성공 후 응답 유실 복구. 각 상황에서 pending 입력 중복 차단, disk/live 일치, 물리 상태 보존과 새 관찰의 내구성을 검사했다. 실패 후 물리 초안과 수첩 관찰 보존, 암묵 재시도 없음, 도구 행동 1회만 실행되는 조건도 포함한다.
