# 수첩 최초 화면 중복 구성 제거

## 요구와 원인

- 기준: develop `7ada7b91fda84c07cdaf1e1299b316002e0bd036`.
- [전체 계획](notebook_history_review_plan.md)의 이전 열람 위치·읽음 상태·대화 진입·성능 요구와 [전체 ToDo](notebook_history_TODO.md)의 T20/T21에 해당한다.
- 모델 준비는 비동기지만 `NotebookHost._finish_opening()`은 먼저 `panel.present()`로 첫 페이지 목록과 비교 쌍을 만든 뒤 `restore_view()`로 저장 위치를 다시 구성했다. 저장 위치가 없더라도 대화 진입은 `open_latest_dialogue()`로 목록을 다시 만들었다.
- 이전 T21b는 `restore_view()` 내부 중복을 줄였으며, 호출 직전 `present()`에서 만든 임시 목록까지 제거한 것은 아니었다.

## 변경

- `NotebookPanel.present()`에 선택적인 초기 view와 최신 대화 진입 여부를 전달한다. 기존 네 인자 호출은 기존 첫 페이지 동작을 유지한다.
- 저장 view가 있으면 기본 목록을 만들지 않고 복원 경로에서 최종 목록·비교 쌍을 만든다. 지연 레이아웃 복원의 세대 검사와 검색 색인 대기는 유지한다.
- 저장 view가 없는 대화 진입은 최신 공개 대사의 페이지를 먼저 구한 뒤 목록을 한 번 구성한다. 공개되지 않은 문단을 추가로 읽지 않는다.
- 호스트는 참조 편집 가능 여부를 구성 전에 설정한다. 구성 후 설정하면서 선택한 상세를 다시 그리는 일을 피한다.
- 읽음 상태, 도구, 알림, 실제 표시 후 view 저장 연결은 기존 호스트가 계속 담당한다. 복원이 끝나기 전 임시 위치를 저장하지 않는다.

## 검증 설계

`notebook_view_smoke.gd`의 CountedPanel에서 한영 × 100%/200% × 상세/목록/비교/최신 대화/기본 진입, 총 20조건을 실행한다.

- 각 조건에서 최종 목록과 비교 쌍 구성이 각각 한 번인지 확인한다.
- 초기 view는 다른 panel에서 페이지 1의 실제 자료를 표시한 후 capture한 것으로 만든다.
- 복원 후 페이지·선택·비교 자료·비교 모드 일치를 확인한다.
- 최신 대화는 실제 query의 최신 공개 키와 비교하고, 기본 진입은 첫 페이지·무선택을 확인한다.
- 복원이 끝나며 인위적인 material_viewed 신호가 없음을 확인한다.
- 기존 검색 지연·읽음·본문 위치·포커스·자료 연결·비교·게임 상태 불변 테스트를 유지한다.
- 공통 query, opening, host suite를 같은 새 export에서 실행한다. 모델 준비 중 닫기·범위 변경·큰 기록 집합과 저장/복귀도 함께 회귀한다.
