## 확인한 두 자료 비교

이어하기/N으로 기존 비교 화면에 진입하고 목록의 이전 원문을 비교 자료에 담았다. 이전 원문과 현재 문서가 서로 다른 참조로 보존되며 `자료를 담을 때 보존한 원문` 안내를 확인했다. B 후보 드롭다운에서 이전 원문 선택 후 Tab으로 A/B 교환 버튼에 이동하고 Enter로 교환했다. A 이전 원문/B 현재 문서 표시를 확인했다. 임의의 두 자료 조합 전체, 12개 바구니 전체, 전편 키보드 전용 완주를 검증한 것은 아니다.

격리 progress의 일반/보호 이력은 3개, 비교 자료는 2개였다. 현재 문서는 document_segment/body/content_version 1, 이전 원문은 legacy/legacy/content_version 0이다. 같은 source_origin_id지만 서로 다른 uid였으며 종류와 보존 원문을 혼동하지 않았다. IME 실패 뒤 저장 복귀까지 통과한 것으로 기록하지 않는다.

## 실패: 실제 한글 조합

검색칸에서 영문 g 입력/Backspace 후 사용자가 한/영 키로 전환했다. `d → h → s → m → f → Return` 입력은 ㅇ → 오 → 온 → 느 → 늘 → 늘로 관찰됐다. 기대값 오늘과 불일치한다. 사용자의 직접 Ctrl+A → 오늘 → Enter도 음절이 사라진다고 답했으며 실제 화면에는 늘만 남았다.

이후 같은 실행 파일로 기본 LineEdit만 있는 별도 프로젝트를 띄웠다. 사용자가 직접 입력했을 때도 음절이 사라졌다고 확인했다. 로그는 `IME_TEXT "d"`, `IME_TEXT ""`, `IME_TEXT "늘 "`, `IME_TEXT "늘"`이었다. 공백을 포함한 모든 동작 순서가 계측된 것은 아니지만 이전 음절이 확정 본문에 없는 사실은 확인된다. 문자 조합 오류는 [ERR-0042](../items/GGB-ERR-2026-0042_Windows_한글IME_음절유실.md)로 등록했다.

진단 환경: 격리 `%TEMP%/ggb-ime-probe-20261006/appdata`, 표시 창 PID 33348. 처음 sandbox에서 시작한 비표시 PID 41732는 종료했고 실제 입력 근거에 포함하지 않았다. 진단 stderr에는 기존 인증서 저장소 경고만 있었으며 GDScript 파싱 오류는 없었다. 기존 게임과 진단 창의 종료 여부는 아래 종료 기록을 기준으로 한다.

## 최소 재현 프로젝트

진단 `visible.out.log` SHA-256: `E1C0D3F68FCFBD37EB28C7FAA1B888EAE553F0C9E3EFE6D55E2E488E71630D42`.

재현용 코드이며 게임에 반영한 수정이 아니다. autoload 없는 임시 프로젝트에서 실행한다.

```ini
; project.godot
config_version=5
[application]
config/name="GGB IME diagnostic"
[display]
window/size/viewport_width=800
window/size/viewport_height=200
[rendering]
renderer/rendering_method="gl_compatibility"
```

```gdscript
# probe.gd / --path <isolated-project> --script res://probe.gd
extends SceneTree
var field: LineEdit
func _initialize() -> void:
	field = LineEdit.new()
	field.position = Vector2(20, 40)
	field.size = Vector2(760, 80)
	field.add_theme_font_size_override("font_size", 30)
	root.add_child(field)
	field.text_changed.connect(func(value: String): print("IME_TEXT ", JSON.stringify(value)))
	field.text_submitted.connect(func(value: String): print("IME_SUBMIT ", JSON.stringify(value)))
	field.grab_focus.call_deferred()
```

## 원인 조사와 제한

확인한 [실행 버전의 Windows 엔진 소스](https://raw.githubusercontent.com/godotengine/godot/ed1daf0bf/platform/windows/display_server_windows.cpp)는 조합 시작·종료와 WM_CHAR 버퍼 처리를 포함한다. 조합 시작 시 버퍼 감소 등은 추가 계측 후보이지 이번 오류의 확정 원인이 아니다. 수첩의 검색 지연/IME 보호 및 포커스 코드도 읽었으나 수첩만의 재현으로 단정할 근거는 없다.

프로덕션 코드·런타임·Windows 입력기 설정은 변경하지 않았다. 조합 미리보기의 강제 확정은 취소와 중간 편집을 훼손할 수 있어 적용하지 않았다. 한글 IME 수정/인수, Alt+Tab, 전용 입력 완주와 정식 성능 인수는 미완료이며 기본 rollout OFF를 유지한다.

## 종료 기록

실제 관찰한 각 격리 창을 Alt+F4로 닫았다. 이후 PID 31840/33348이 더 이상 실행 중이 아님을 확인했다. 사용자 편집기나 다른 앱을 종료하지 않았다. 게임 stderr는 비어 있었고 진단 stderr의 기존 인증서 경고 외 추가 스크립트 오류는 없었다. 오류 재현과 종료 확인이지 IME 수정 완료나 종료 후 재시작 회귀 통과가 아니다.
