## 구형 표본 출처와 판정

content 표본 765 legacy/188 unmapped를 보고서에서 숨기거나 0으로 바꾸지 않는다.

1. 15개 `LIVE_STAGES` 체크포인트 각각에 원문 51개가 미리 들어 있다. `developer_checkpoints.gd::snapshot_for()`의 검증된 이관은 이들을 legacy로 감싼다. 출처별 고유 표본은 15 × 51 = 765개이며 새 힌트 쓰기 횟수가 아니다.
2. 구형 `CHAPTER_ONE.last_feedback`에는 `notebook_feedback` descriptor가 없다. 실제 controller 초기화가 이 마지막 원문을 보여 주면 `_feedback()` → 원장 writer가 출처 없는 `CH1_HISTORY_TRANSCRIPT`를 명시적으로 unmapped로 보존한다. 본문이나 `text_id`로 authored ID를 추정하지 않는다. 기존 `notebook_chapter_one_smoke.gd::_persistence`에 이 계약의 검사가 있다.
3. 30개 기본 힌트 진입과 150개 저장 재시도에서 각 1개, 수집 대상인 stronger support 8조건에서 각 1개를 포함하므로 188표본과 일치한다. 비적격 support 8조건은 조기 반환해 공통 원장 수집을 하지 않는다. 이는 수집 위치/시작 fixture를 대조한 설명이며 모든 본편 신규 unmapped의 발생 감사는 아니다.
4. 별도 15stage × 한영 진단은 시작 fixture의 unmapped 0/legacy 51개/명시 descriptor 없음과 controller 진입 후 unmapped 1개를 검사한다. 실제 payload/node/언어를 출력해 새 힌트와 분리한다. 재현용 [probe](evidence/2026-10-07_runtime_union_transition_hint_origin.gd)와 [scene](evidence/2026-10-07_runtime_union_transition_hint_origin.tscn)은 원래 game/scripts 밖에 보관하고 TEMP의 `.diagnostics/`로 복사한다. 따라서 여섯 suite의 스크립트 지문을 변경하지 않는다.

진단은 native 종료 0/30조건 PASS, `fixture_unmapped=0`/`fixture_legacy=51`/`has_authored_feedback=false`와 각 진입의 unmapped 1개를 확인했다. 최초 외부 `--script` helper는 autoload 식별자 해석에 실패했고, scene helper의 첫 작성은 추론형 선언 파싱에 실패해 제한 시간 후 해당 검사 PID만 종료했다. 둘 다 진단 코드 문제이며 제품 오류나 성공 근거로 세지 않는다. 정상 project scene 진입 및 명시 `bool` 선언으로 수정한 helper만 최종 증거로 사용한다. 최종 stderr는 기존 인증서 저장소 경고만 포함하며 스크립트 오류는 없다.

현재 새 authored 힌트의 누락/미등록은 검사 범위에서 발견되지 않았지만 전 생산자 신규 unmapped/legacy 수와 UI 제외 전수는 미확인이다. 공통 보고서의 해당 값은 `null`, 필수 분기 전수는 `NOT_AUDITED`를 유지한다. 구형 원문을 조용히 삭제하거나 새 ID로 소급 변환하는 제품 수정은 하지 않는다.

## 재현

```powershell
$suites = @('mirror', 'basement', 'fracture', 'fracture-surfaces', 'puzzle-surfaces', 'content')
./scripts/run_notebook_runtime_audit.ps1 -EnginePath $engine -ProjectPath $tempProject -EvidencePath $newTempEvidence -TimeoutSeconds 3600 -Suites $suites
$base = 'ideas/md/v04/issues/validation/evidence/2026-10-07_runtime_union_transition_'
./scripts/audit_notebook_runtime_union.ps1 -GamePath ./game -TraceLogs @($suites | ForEach-Object { $base + $_ + '.out.log' })
```

원본 stdout/stderr/receipt를 위 접두부의 `.out.log/.err.log/.run.json`으로 보관한다. 기존 `*runtime_union_*.log` Git 줄끝 규칙을 이용해 로그 바이트를 보존한다. 이전 T19d/e/f/g의 소스와 총수를 더하거나 로그를 섞지 않는다.

구형 피드백 진단은 위 probe/scene을 TEMP 프로젝트의 `.diagnostics/hint_origin.gd`와 `.diagnostics/hint_origin.tscn`으로 복사한 뒤 별도 APPDATA/LOCALAPPDATA에서 `--headless --path $tempProject res://.diagnostics/hint_origin.tscn -- --ggb-dev-notebook-v2`로 실행한다. 기본 실행기 suite나 합집합 분모에 이 진단을 넣지 않는다. [진단 stdout](evidence/2026-10-07_runtime_union_transition_hint-origin.out.log), [stderr](evidence/2026-10-07_runtime_union_transition_hint-origin.err.log), [종료·SHA receipt](evidence/2026-10-07_runtime_union_transition_hint-origin.run.json)를 대조한다.

다음은 고정 소스 전체 합집합과 독립 필수 행동 분기/정적 제외 목록의 대조다. 4.6.3 실제 수첩 다섯 IME 국소 조건은 이미 사용자 정상 확인을 별도로 기록했으며 이번 Steam 4.7.2 headless 근거로 대체하지 않는다. 실제 전편·성능·엔진/빌드 채택과 rollout 인수는 계속 남긴다.
