## 실행 환경과 승인

사용자가 이전 중단 이후 실제 입력 검증 재개를 명시했다. `@oai/sky`의 현재 창 목록에서 격리 Godot 실행 파일 소유 창을 하나만 선택하고, 각 입력 뒤 화면을 다시 관찰했다. 실행 중인 사용자 Godot 편집기에는 입력하지 않았다.

- 기준 develop: `6680e7971f1538a2041aa8cdf3fd5eca4238877f`.
- Godot 4.7.2 Steam, OpenGL 3.3 Compatibility, Intel Iris Xe.
- PCK: `%TEMP%/ggb-actual-note-source-retention-loaded-20261006/notebook.pck`.
- 실행 전 확인한 SHA-256: `79DA2FA04014D2A0F5F1738EC5BD6BE7C92C83880A9CA9C3E61E7DD958C1DC59`.
- 빈 실행 경로 및 APPDATA/LOCALAPPDATA: `%TEMP%/ggb-native-resume-20261006`의 `empty`와 `appdata`. 사용자 저장과 분리했다.
- 실행 옵션: `--windowed --resolution 1280x720 -- --ggb-dev-notebook-v2 --ggb-dev-full`.
- 관찰 화면: 1707×1067. 실제 적용 프로필 화면이므로 1280×720 또는 특정 DPI 인수로 세지 않는다.
- 첫 프로세스 PID 13152, 재시작 PID 20432. 두 프로세스 모두 대상 게임 창에 Alt+F4를 보낸 뒤 프로세스 종료를 확인했다.
- 로그: 격리 경로의 `native.out.log`, `native.err.log`, `reload.out.log`, `reload.err.log`. 두 stderr는 비어 있었으며 재시작 로그에 정상 title bootstrap을 확인했다.

## 실제 관찰

| 조작 | 관찰 결과 |
| --- | --- |
| 타이틀 Return, 기본값으로 시작 클릭, 빈 슬롯 1 Return | 침실 첫 대사로 진입 |
| 첫 대사 중 N | 통합 수첩 표시, 오늘의 일과 및 이전 수첩 원문 두 행 |
| 검색칸 클릭 후 완성된 `창문` 문자열 입력 | 검색칸에 한글 표시, 본문 일치 자료 두 행 유지 |
| Ctrl+A 후 `zz_not_found` 입력 | 결과 0개, 빈 결과 안내·필터 해제/전체 기록 검색 버튼 표시 |
| 검색칸에서 Escape | 검색어 지워짐, 두 행 복원, 수첩은 유지 |
| 오늘의 일과 행 클릭 | 위치·자료 유형·관찰 상태·식별된 출처와 본문 표시 |
| 책갈피 추가 클릭 | 저장 성공 안내, 행에 책갈피 표시, 버튼이 해제로 변경 |
| 비교에 담기 클릭 | 저장 성공 안내, 버튼이 비교 목록에서 빼기로 변경 |
| Escape 두 번 | 첫 입력은 목록 포커스로, 다음 입력은 수첩 종료. 침실의 원래 첫 대사 유지 |
| 게임 종료·별도 프로세스 재실행·Return 이어하기·N | 같은 대사와 수첩 자료 상세 복원, 책갈피와 비교 목록에서 빼기 표시 유지 |
| 담아 둔 자료 비교 클릭·A 드롭다운 클릭 | 후보 목록에 오늘의 일과 유지 |
| Down 두 번·Return | 오늘의 일과를 A 자료로 확정, 본문 표시. B는 미선택 유지 |

프로세스 재시작 이후 실제 화면뿐 아니라 격리 `saves_full/slot_01/progress.json`의 `dialogue_history.bookmarks`와 `dialogue_history.comparison`에서 같은 `document_segment/body` 참조를 확인했다. 원장은 `NOTE_P_DUTIES`의 관찰 revision을 유지했다. `comparison_pins`라는 필드는 이 저장 형식에 없으며, 검증에는 실제 `comparison` 필드를 사용했다.

## 증거와 한계

화면 근거는 대화에 반환된 Computer Use 캡처다. 별도 스크린샷 파일을 생성했다고 주장하지 않는다. Godot 접근성 트리는 검색칸을 개별 요소로 노출하지 않았으므로 화면의 테두리·커서·실제 입력 결과로 포커스를 확인했다.

이번에 오류는 발견하지 않았다. 다만 완성 한글 문자열 입력은 키 조합에 의한 IME의 조합 시작·미확정 상태·확정·취소 검증이 아니다. 영어 문자열 입력 역시 영어 로캘 전체 화면 검증이 아니다.

다음은 미완료다: 두 자료 동시 비교·교환 및 복수 후보, 모든 Tab/Shift+Tab 경로, 실제 IME 조합, Alt+Tab, 대형 문서·대량 검색·200% 접근성, 한영 전체 생산자·전편 마우스 전용/키보드 전용 완주와 정식 성능 인수. 혼합 입력 국소 검사를 전용 입력 완주로 계산하지 않는다. T22/T23 및 전체 목표는 진행 중이고 rollout 기본 비활성은 유지한다.
