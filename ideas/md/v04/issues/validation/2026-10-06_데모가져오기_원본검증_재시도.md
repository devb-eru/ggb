## 추가한 검사

`_validate_demo_rejections`에서 다음 원본 9종을 각각 두 번 미리보기 및 실제 가져오기 함수에 전달한다. checksum 변조 조건을 제외한 헤더/상태 변경은 checksum을 다시 계산하여 단순 checksum 거부로 통과하지 않도록 했다.

| 변경한 조건 | 기대 오류 |
| --- | --- |
| 원문 변조 후 checksum 유지 | ERR_SAVE_CHECKSUM |
| 미래 저장 schema | ERR_SAVE_FUTURE_SCHEMA |
| 미지원 design revision | ERR_SAVE_DESIGN_REVISION |
| 다른 원본 slot_id | ERR_IMPORT_SOURCE |
| 원본 build_flavor가 full | ERR_IMPORT_SOURCE |
| 다른 source_app_id | ERR_IMPORT_SOURCE |
| 다른 save_point_id | ERR_IMPORT_BOUNDARY |
| 다른 content_boundary_id | ERR_IMPORT_BOUNDARY |
| d5_complete가 false | ERR_IMPORT_PROGRESS |

매번 정확한 오류를 검사하고, demo 원본 파일 바이트·full 루트의 슬롯 디렉터리 목록·현재 GameState snapshot이 불변인지 확인했다. 읽기 실패 뒤 새 슬롯이 생겨도 성공으로 계산하지 않는다.

기존 `_validate_demo`의 정상 원본을 두 번 가져온다. 두 대상 슬롯이 서로 다르며 관찰 entries/UID/source_origin_id가 같고 branch_id만 각각 새로 부여됨을 확인했다. 기존 원본 보존 검사도 유지한다. 반복 가져오기 자체는 사용자 요청에 따른 독립된 분기 생성이며, 같은 원본의 관찰을 중복 추가하는 방식이 아니다.
