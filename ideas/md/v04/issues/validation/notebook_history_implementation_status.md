## 1단계 변경

1. `DialogueRepository`는 분류가 없거나 알 수 없는 과거 항목을 원본 변경 없이 `LEGACY`로 표시한다. 전체와 조건부 미분류 필터를 제공한다.
2. 오류가 난 항목만 제외하고 정상 기록을 유지한다. 오류 안내·진단 코드·재시도를 제공하며 빈 기록과 구분한다.
3. 장 제목과 전체/재시도/진단 문구를 한국어·영어 레지스트리와 카탈로그에 함께 등록했다. 기록 없는 미래 장은 필터에 만들지 않는다.
4. `dialogue_history_context.gd`에서 사건 stage와 서사 장을 연결한다. J3/D4는 2장, D5~E6은 3장, F0부터 4장이다. 사건 커밋 전에 문맥을 잡고 결과·마지막 피드백에 함께 보존한다. 진행 상태가 먼저 바뀌거나 재로드해도 마지막 대사를 다음 장으로 재분류하지 않는다.
5. 실제 표시 대사와 선택창은 동결한 문맥을 사용한다. 기존 기록을 현재 진행 상태로 소급 분류하지 않는다.
6. 동일 컨트롤러에서 마지막 선택과 장별 스크롤을 복원한다. 빈 화면은 닫기, 정상 화면은 선택된 버튼에 포커스를 준다. 큰 글자는 두 열 배치를 사용한다. 슬롯을 넘는 UID 기반 위치 저장은 아직 아니다.
7. 프롤로그/1장/검은 거울/지하 회귀 검사의 대화 기록 본문·닫기 조회를 의미 있는 노드 이름으로 수정했다. 일반 모달의 구조 검사는 그대로 둔다.

## 확정 범위

- 자유 입력 메모는 후속 기능이며 이번에는 자료 고정·작성된 가설 조회에 집중한다.
- 보존 목표는 일반 대사 최근 2,000개와 보호/기존 미분류 기록 별도 보관이다. 현행 writer에 상한을 먼저 걸어 원문을 삭제하지 않는다.
- 비교는 여러 자료를 담고 두 개씩 교체해 보는 방식이다. 수첩 비교로 퍼즐 입력·성공 판정·현실 수첩 읽기 완료를 변경하지 않는다.
- 위 구현 목표는 완료 보고가 아니다. 저장 이관과 생산자 매핑 인수가 끝나기 전에는 새 저장 형식을 일반 실행에 활성화하지 않는다. 신형 슬롯 검사는 격리된 APPDATA의 개발 옵션에서 수행한다.

## 2단계 데이터 계층

`game/scripts/systems/notebook_archive.gd`는 저장 후보 변환 모듈이다. 일반 실행에서는 기존 형식·원문 보존을 유지한다. 개발 검증 옵션에서는 아래 후보를 실제 저장 경로와 연결한다. 신형 래퍼를 기존 표시기로 읽는 호환 계층도 함께 검증하지만, 이것을 신규 콘텐츠 ID 연결 완료로 세지 않는다.

| 동작 | 구현된 계약 | 남은 연결 |
| --- | --- | --- |
| 신규 기록 후보 | 128-bit UID, 원 출처/분기, 사건 발생·대화 세션·표시 토큰, 버전/variant, 표시한 segment만 수용. NP20 힌트 카탈로그·실제 표시 연결 | 나머지 원 콘텐츠 ID 레지스트리·생산자별 캡처 |
| 같은 표시 재시도 | 같은 토큰/동일 내용은 중복 없음, 같은 토큰/다른 내용은 오류, 낡은 revision 거부. 실제 저장 응답 소실 시 디스크 확인 | 진행 중 발생·표시 커서의 앱 재시작 재개 |
| legacy 변환 | 원본 envelope checksum 검증 후 결정적 UID 생성. 원 필드 전체와 해시별 원본 파일 보존 | 정식 활성화 전 생산자·전체 인수 |
| 자료 참조 | 출처+UID+종류+버전+segment로 해결, 미공개 뒷면/다른 버전/없는 UID 거부 | 카드·시각 자료·검색 scope 연결 |
| 책갈피/비교 | 임시 한도 50/12, 참조와 보호 이유의 후보 계산 및 실제 StateWriter/SaveManager 트랜잭션. 실패 롤백·응답 소실 확인 | 성공/재시도 UI, 여러 자료 중 두 개씩 비교 화면 |
| 출처 인용 | 단서/인물/문서 소비자 UID로 보호. NP03 지식 revision·원고 출처·보호를 원자 저장. 반증·화면 숨김으로 자동 해제하지 않음 | 후속 일지/관계/가설 공급자와 카드 UI |
| 정리 | 보호 이유 재검산 후 일반 최근 2,000개만 유지. legacy/보호는 독립 | 실제 대사 원본 의존성 제거 전 본편 prune 비활성 |
| 분기 복제 | F3·백업·demo/full에서 기존 관찰 UID/원 출처 유지, 새 분기 ID. 개발 자료의 결정적 변환과 갤러리 불변 읽기 | 전체 조회 UI의 scope/sidecar 연결 |

고정 자동 fixture에서 legacy 10,000개 + 보호 2,001개 + 일반 2,001개를 구성했다. 일반 중 가장 오래된 1개만 후보에서 제거되고, 최신 일반/보호/legacy 및 순번은 유지된다. 해당 일반을 고정하면 정리 대상에서 제외되고, 마지막 보호를 해제하면 다시 일반 한도에 포함된다. 이 검사는 논리/불변성 검사이며 저장 지연·RAM·p95 합격 근거가 아니다.

신형 모듈은 문자열 원문을 역검색해 새 ID를 발급하지 않는다. 테스트의 `TEST_*` 콘텐츠는 검사용이며 본편 공급자 매핑으로 세지 않는다. `notebook_content.gd`는 생산자별 공개 변수 선언·segment·variant·화자를 추가 검증한다. 해당 검증이 연결되지 않은 생산자를 완료로 세지 않는다.

### 본편에 연결한 선행 의존성 수정

- `dialogue_observed_facts.gd`: 현실 몸 재관찰 3종의 실제 표시 증거를 대사와 함께 영구 저장한다. current node·현실 분기·이미 확인한 오브젝트를 확인하고, 등록하지 않은 증거나 잘못된 자료형은 거부한다.
- `EndingGalleryPages`: 새 증거가 있으면 transcript가 없어도 같은 재관찰 내용을 표시한다. 구형 저장만 원문 확인 fallback을 사용한다. 게임상 조사 확인 없이 증거만 있는 경우 페이지를 만들지 않는다.
- `dialogue-history-smoke`: 증거+대사 저장 실패 롤백/재시도/재로드, 잘못된 증거 타입 거부, transcript 없는 재열람과 다른 오브젝트 비공개를 검사했다.
- 본편의 실제 몸 조사 버튼과 갤러리 회귀 검사를 `basement_session_smoke.gd`에 추가해 통과했다. 증거 연결 후 foundation/dialogue-history/chapter-one/black-mirror/basement-session/prologue/full-campaign를 다시 실행해 모두 통과했다. 일반 실행의 구형 저장 일괄 이관·본편 prune는 여전히 비활성이다.

## 2단계 실제 저장 경로 검증

### 활성화 경계

- `notebook_rollout.gd`의 개발 옵션 `--ggb-dev-notebook-v2` 또는 전용 `--notebook-migration-smoke`에서만 신형 기본 상태와 구형 슬롯 승격을 활성화한다. release 빌드에서는 옵션을 무시한다. `project.godot`나 사용자 기본 설정을 변경하지 않는다.
- 일반 실행은 envelope schema 1과 기존 transcript를 유지한다. 신형 검증 슬롯은 envelope schema 2 / archive schema 2를 사용한다. 구형 바이너리로 신형 슬롯을 열지 않는다.
- 검증 모드의 미연결 생산자는 `record_class=unmapped`로 분리한다. 기존 형식을 감싼 보존용 경로이며, authored 콘텐츠도 legacy 이관도 아니다. 삭제 한도에 넣지 않으며 최종 매핑 인수에서 완료로 집계하지 않는다.
- 기존 화면은 `display_payload`로 legacy/unmapped 원문을 읽는다. authored는 별도 resolver로 저장 당시 의미 버전의 현재 언어 본문을 읽는다. 네 탭 화면은 아직 연결하지 않았다.

- 대화 실행 중 발생/세션/표시 토큰은 재사용하지만 앱 재시작 커서 복원은 아직 아니다. 검색·새 분류·비교 화면·OS 실제 입력·성능 합격 역시 미완료다.

- 검증기에 ledger 참조와 archive 참조의 동일 JSON 정규화, 없는 revision 소비자·잘못된 연결·소수/비정상 타입 거부를 추가했다. 지식별 참조를 일괄 조회하여 참조마다 archive 전체를 재검증하는 중복도 줄였다.
- 저장 응답 유실 시험에서 기존 사건 배열의 `0`과 JSON 재로드의 `0.0` 때문에 성공한 저장을 롤백하는 문제를 발견했다. 공통 `same_persisted_value`는 전체 구조와 정확한 값을 재귀 대조하며 숫자 표현 차이만 허용한다. bool/숫자 혼동·근사값·누락 필드는 거부한다. 프롤로그와 대화 writer, 고정/비교 명령의 응답 확인에 함께 적용했다.
- 복수 출처 보호는 한 후보에서 일괄 적용한 뒤 일반 한도를 정리한다. 먼저 출처 하나만 보호하는 동안 다음 출처가 삭제되는 중간 상태를 만들지 않는다. 일반 2,003개 중 오래된 두 출처를 함께 인용하는 시험에서 인용 원문과 일반 최근 2,000개를 각각 보존한다.
- 집중 검사: `--notebook-knowledge-smoke`, NP01~03의 `--notebook-prologue-smoke`, 미래 ledger를 포함한 `--notebook-migration-smoke`. 실제 격리 저장 경로 오류 주입·재시도·재로드, 구형 원고·미공개 자료·readonly·revision 불변을 검사한다. 세부 범위는 [생산자 연결 현황 6절](notebook_content_mapping_status.md)을 따른다.

`notebook_panel.gd`는 재사용 가능한 읽기 패널이다. **본편 `_open_notebook`/대화 기록 메뉴의 교체는 아직 하지 않았다.** 기존 별도 수첩·힌트·수량 계산 도구·현실 수첩 N키 경로는 그대로 동작한다. 새 패널을 붙이기 전에 이 경로와 대화/선택 중단·복귀를 호스트에서 함께 처리해야 한다.

책갈피/비교 묶음의 추가·해제 저장 버튼, 자유 메모, 읽음 sidecar, 과거 문자열 수첩을 위한 별도 어댑터, 시각 원도 확대/이동은 이번 패널에 구현하지 않았다. 기존 `notebook_commands` 저장 계약을 우회하는 임시 메모리 고정 기능도 넣지 않았다. 슬롯/갤러리 전환 시 호스트가 모델을 닫아야 하며, 닫힌 모델의 패널은 이전 목록·본문·비교 자료를 비운다.

- 원문 전체와 주소·계통으로 결정적 UID를 만든다. 과거 갱신/획득 시점·작성 언어·장소·인물은 추정하지 않는다. 같은 문장이라는 이유로 별도 주소나 authored 지식과 병합하지 않는다.
- 현재 남아 있는 마지막 값은 검색·상세·50개 페이지·자료 비교에 사용할 수 있다. 정본을 바꾸거나 전체를 archive에 다시 쓰는 읽기 부작용은 없다. 빈 문자열도 임의 삭제하지 않는다.
- 명시적으로 책갈피/비교에 담을 때만 원문 스냅샷과 보호 참조를 같은 저장으로 설치한다. 현재 값과 동일 UID인 고정 원문은 한 행으로 표시하고, 정본이 바뀌면 이전 고정 원문과 새 마지막 값을 구별한다.
- 기존 archive schema 2의 legacy 래퍼에 엄격히 검증하는 `notebook_legacy_source`를 추가했다. 참조 형식과 일반/보호/미분류 quota, 50개 책갈피·12개 비교 한도를 바꾸지 않는다.
- 고정 당시 sequence를 원래 획득 시각으로 표시하지 않는다. 엔딩 갤러리의 구형 대화 본문 판정에서도 수첩 스냅샷은 몸 재관찰 증거에서 제외한다.
- 원문 snapshot hash/UID, 부분 오류, 저장 실패 원복, 같은 command 재시도, 응답 유실 확인, 낡은 참조 및 scope/revision을 검사한다. 개인 자유 입력·초안·삭제 UI는 추가하지 않는다.

## 읽음 표시와 마지막 열람 위치 (2026-10-03)

기준 develop `92c5780` 이후 작업이다. 앞 절의 읽음/UI 커서 sidecar 미완료 항목을 구현한다. 게임 진행 중 대화·선택의 앱 재시작 커서는 이 UI 커서와 다른 후속 범위다. 원고 25개·퍼즐 정답·보존 quota·기본 개발 옵션 비활성은 유지한다.

### 구현 내용

- 신규/미열람/갱신 배지를 정확한 공개 참조와 revision 묶음으로 구분한다. 직접 상세를 열거나 비교에서 실제 보이는 A/B 자료를 선택한 경우만 해당 참조의 배지를 지운다. 목록 미리보기·숨은 비교 자료·자동 초기 선택·복원은 읽음으로 만들지 않는다.
- 배지 변경 시 기존 행의 표시만 바꾸며 목록을 재정렬하지 않는다. 제목·본문·최초 공개·일지/field_read·관계·퍼즐 상태는 변경하지 않는다.
- N/일반 수첩과 메뉴 대화 기록의 마지막 위치를 독립 저장한다. 최초 대화 기록은 최신 세션의 마지막 발화, 재열람은 본인이 보던 문장이다. 대화 메뉴에서 다른 탭을 방문해도 일반 수첩 위치를 덮어쓰지 않는다.
- UID/segment·필터·50개 페이지·첫 가시 행의 상대 위치·본문 문단과 비율·출처 복귀·두 자료 선택/좁은 화면 A·B·포커스를 저장한다. 링크 포커스는 원문 참조로 만든 안정적인 제어 이름을 사용한다.
- 검색 복원은 공개 자료 색인이 끝날 때까지 기다린다. 없는 자료나 더 이상 공개되지 않는 필터는 실제 이웃/빈 상태로 복귀하며 안내한다. 아직 게임에서 획득하지 않은 자료를 sidecar만으로 표시하지 않는다.
- 현재 게임에 별도 다중 프로필 UI가 없으므로 `local` 프로필을 명시한다. OS 사용자/빌드/슬롯/실행/계통/분기 범위를 구분하고 런타임 epoch는 파일 이름에 넣지 않는다. 같은 저장을 새 컨트롤러로 읽어도 UI 위치는 유지한다.
- archive/ledger revision, 끝 순번/UID, 기존 원문 digest로 더 과거인 snapshot의 UI 상태를 비운다. 백업 복구/F3의 branch 분리도 유지한다. 무효화한 실행 중 호스트는 옛 편의 상태를 쓰지 않는다.
- 게임 슬롯과 별도인 `user://profile/notebook_views/`에 schema/hash 검증, 임시 쓰기와 재읽기, 정상 백업 보존을 적용한다. 손상 시 백업/기본값, 미래 형식은 덮어쓰기 금지다. 쓰기 실패를 알리되 세계 복귀·본문·책갈피·비교 참조를 막지 않는다.

계약 정본은 [데이터 계약 9.3절](../../../../../docs/data_contract.md#93-읽음-표시와-열람-위치-sidecar)이다. 편의 데이터에 본문 사본이나 gameplay flag를 넣지 않는다. 개인 자유 메모·시각 원도의 확대/이동 상태는 이번 변경에 포함하지 않는다.

### 검증 범위와 수정 이력

새 `notebook_view_smoke.gd`는 공통 조회 검사에서 실행한다. 실제 파일의 재로드·scope 여섯 필드 분리·과거 frontier·손상/백업/미래 버전·임시 쓰기 실패·잘못된 타입/필터·100%에서 200% 글자 배율/한영 UI 전환·검색 완료 대기·출처 복귀/포커스·중간 페이지 스크롤·자료 소실·세 자료 중 A/B 복원을 포함한다. 실제 호스트 검사는 독립 진입 위치·저장 실패 후 세계 복귀·같은 슬롯 로드 epoch 교체·게임 snapshot 불변까지 포함한다.

초기 검사에서 UI의 소수 문단 비율을 게임 상태의 정확한 수치 비교 함수로 대조해 정상 임시 파일을 거절하는 문제가 나왔다. UI 파일은 strict schema/checksum 검사 후 정확한 직렬화 원문을 대조하도록 수정했다. 게임 상태 검증 함수는 완화하지 않았다. UI 위치의 소수 왕복 오차와 실제 복원 문단도 별도 검사한다. 손상 JSON 검사는 오류를 난사하는 정적 parser 대신 반환 오류를 처리하며, 실패한 실행을 통과로 집계하지 않는다.

추가 검토에서 복원 대기 중 장/책갈피/이전 revision 필터나 A/B 선택을 조작하면 오래된 배치 복원이 늦게 적용될 수 있는 경계를 보완했다. 직접 조작은 복원 세대를 취소하며 새 모델 `present`는 이전 패널의 읽음 메타를 초기화한다. 이 최종 보완 뒤의 집중 검사는 전편 회귀에 사용한 선행 패키지와 구분해 기록한다.
