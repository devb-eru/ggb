## 1단계 변경

1. `DialogueRepository`는 분류가 없거나 알 수 없는 과거 항목을 원본 변경 없이 `LEGACY`로 표시한다. 전체와 조건부 미분류 필터를 제공한다.
2. 오류가 난 항목만 제외하고 정상 기록을 유지한다. 오류 안내·진단 코드·재시도를 제공하며 빈 기록과 구분한다.
3. 장 제목과 전체/재시도/진단 문구를 한국어·영어 레지스트리와 카탈로그에 함께 등록했다. 기록 없는 미래 장은 필터에 만들지 않는다.
4. `dialogue_history_context.gd`에서 사건 stage와 서사 장을 연결한다. J3/D4는 2장, D5~E6은 3장, F0부터 4장이다. 사건 커밋 전에 문맥을 잡고 결과·마지막 피드백에 함께 보존한다. 진행 상태가 먼저 바뀌거나 재로드해도 마지막 대사를 다음 장으로 재분류하지 않는다.
5. 실제 표시 대사와 선택창은 동결한 문맥을 사용한다. 기존 기록을 현재 진행 상태로 소급 분류하지 않는다.
6. 동일 컨트롤러에서 마지막 선택과 장별 스크롤을 복원한다. 빈 화면은 닫기, 정상 화면은 선택된 버튼에 포커스를 준다. 큰 글자는 두 열 배치를 사용한다. 슬롯을 넘는 UID 기반 위치 저장은 아직 아니다.
7. 프롤로그/1장/검은 거울/지하 회귀 검사의 대화 기록 본문·닫기 조회를 의미 있는 노드 이름으로 수정했다. 일반 모달의 구조 검사는 그대로 둔다.

## 확정 범위

- 자유 입력 메모는 후속 기능이며 이번에는 자료 고정·작성된 가설 조회에 집중한다.
- 보존 목표는 일반 대사 최근 2,000개와 보호/기존 미분류 기록 별도 보관이다. 현행 writer에 상한을 먼저 걸어 원문을 삭제하지 않는다.
- 비교는 여러 자료를 담고 두 개씩 교체해 보는 방식이다. 수첩 비교로 퍼즐 입력·성공 판정·현실 수첩 읽기 완료를 변경하지 않는다.
- 위 구현 목표는 완료 보고가 아니다. 저장 이관과 생산자 매핑을 끝내기 전에는 새 저장 형식을 본편에 연결하지 않는다.

## 2단계 데이터 계층

`game/scripts/systems/notebook_archive.gd`는 **아직 본편 writer에 연결하지 않은** 저장 후보 변환 모듈이다. 현재 슬롯의 구조·보존 내용은 그대로다. 이 분리는 구형 원문을 먼저 지우거나 신형 레코드를 구형 화면에 전달하는 중간 배포를 막기 위한 것이다.

| 동작 | 구현된 계약 | 남은 연결 |
| --- | --- | --- |
| 신규 기록 후보 | 128-bit UID, 원 출처/분기, 사건 발생·대화 세션·표시 토큰, 버전/variant, 표시한 segment만 수용 | 원 콘텐츠 ID 레지스트리·생산자별 캡처 |
| 같은 표시 재시도 | 같은 토큰/동일 내용은 중복 없음, 같은 토큰/다른 내용은 오류, 낡은 revision 거부 | 파일 응답 불명확/강제 종료 후 디스크 확인 |
| legacy 변환 후보 | 검증된 원본 digest를 인자로 받아 결정적 UID 생성, 원 필드 전체 별도 보존, 원본 불변 | envelope checksum 검증을 담당하는 모든 읽기 입구·이관 매니페스트 |
| 자료 참조 | 출처+UID+종류+버전+segment로 해결, 미공개 뒷면/다른 버전/없는 UID 거부 | 카드·시각 자료·검색 scope 연결 |
| 책갈피/비교 | 임시 한도 50/12, 참조와 보호 이유를 같은 후보로 계산, 다른 보호 이유 유지 | 실제 StateWriter/SaveManager 트랜잭션·성공 UI |
| 출처 인용 | 단서/인물/문서 소비자 UID로 보호. 반증·화면 숨김으로 자동 해제하지 않음 | 실제 지식 revision 공급자 |
| 정리 | 보호 이유 재검산 후 일반 최근 2,000개만 유지. legacy/보호는 독립 | 실제 대사 원본 의존성 제거 전 본편 prune 비활성 |
| 분기 복제 | 기존 관찰 UID/원 출처 유지, 새 분기 ID, 이후 같은 sequence라도 다른 UID | F3·백업·demo/full·개발·갤러리 입구 |

고정 자동 fixture에서 legacy 10,000개 + 보호 2,001개 + 일반 2,001개를 구성했다. 일반 중 가장 오래된 1개만 후보에서 제거되고, 최신 일반/보호/legacy 및 순번은 유지된다. 해당 일반을 고정하면 정리 대상에서 제외되고, 마지막 보호를 해제하면 다시 일반 한도에 포함된다. 이 검사는 논리/불변성 검사이며 저장 지연·RAM·p95 합격 근거가 아니다.

신형 모듈은 문자열 원문을 역검색해 새 ID를 발급하지 않는다. 테스트의 `TEST_*` 콘텐츠는 검사용이며 본편 공급자 매핑으로 세지 않는다. `safe_variables`의 원시값 타입 검사는 있지만 어떤 값이 서사적으로 공개 가능한지는 생산자 레지스트리가 추가 검증해야 한다.
