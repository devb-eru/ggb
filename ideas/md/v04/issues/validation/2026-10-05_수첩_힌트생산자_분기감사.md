## 감사 경계와 개선

기존 `notebook_content_smoke.gd`는 실제 버튼을 통해 모든 단계 힌트를 표시했지만, 집계 키는 콘텐츠 ID/언어였다. BF가 B3_B와 같은 콘텐츠를 쓰는 경우처럼 정상·실패 노드를 같은 키로 합쳤다. 60개 ID/두 언어라는 총수만으로는 노드별 실행을 증명할 수 없었다.

요구 집합은 등록 카탈로그 전체에서 producer_id가 NP20인 행의 노드·분기·문단·언어를 직접 열거한다. 실행 대상 stage 목록과 별도로 생성하므로 향후 노드/언어/문단이 늘고 테스트 경로가 빠지면 실패한다. 관찰 집합은 descriptor의 예상값이 아니라 실제 커밋된 entry.observation에서 추출한다.

키는 `producer, content, version, node, variant, segment, locale`이다. 미등록 관찰은 UNMAPPED, 요구하지만 보지 못한 조합은 NOT_COVERED로 별도 보고하며 두 집합 모두 비어야 통과한다. 요청한 한 줄만 증가·실제 화면과 캡처 원문 일치·실제 장소·재표시 멱등성·퍼즐/관계 무변경·저장 후 reload 검사는 기존대로 함께 수행한다.

## 현재 화면과 과거 기록 분리

최초 감사 실행은 174개를 모두 현재 표시 대상으로 간주해 24개 누락으로 실패했다. 이는 제품 누락이 아니라 감사 분류 오류였다. 공개 문구가 version 2로 개정된 11개 ID의 과거 version 1을 현재 화면에서 다시 내보내도록 요구했기 때문이다.

현재 생산자가 선택하는 의미 버전만 live 요구 집합으로 분류한다. 나머지 24개 노드/문단/관찰 언어 조합은 독립 과거 archive fixture로 생성하고 JSON 왕복 후 한영 재열람한다. 정확한 이전 문구·fallback 아님·원본 객체 불변을 확인한다. 과거 재열람을 현재 사건 실행 수에 합산하지 않으며, 이전 문구를 새 기록으로 바꾸지 않는다.

## 재현과 근거

[원자료](2026-10-05_수첩_힌트생산자_분기감사.json)에 모든 live tuple과 과거 재열람 키, 카탈로그 SHA-256, 패키지 SHA-256, 최초 감사 오류를 보존했다.

격리 APPDATA/LOCALAPPDATA와 빈 실행 경로에서 export PCK를 `--headless --main-pack <PCK> -- --notebook-content-smoke --ggb-dev-notebook-v2`로 실행한다. Windows Godot 4.7.2 Steam. 최종 import 21.7초, export 8.1초, 검사 89.9초이며 이는 UI 응답 지연이 아닌 실행 소요 시간이다.

종료 코드 0, NOTEBOOK_CONTENT_SMOKE PASS, 스크립트/파싱/리소스 치명 오류 부재를 확인했다. 기존 Windows 루트 인증서 저장소 읽기 경고는 남아 있다. 사용자 세이브/실행 중 게임 창은 사용하지 않았다.
