## 허용 목록과 필수 경로의 차이

NP04/NP06의 기존 version 1 카탈로그는 공통 65개 node_ids를 허용한다. 단, A1 표식 3종의 현재 version 2는 A1 한 노드만 허용한다. 현재 83개 콘텐츠와 이전 A1 정의를 포함한 86개 의미 버전 정의가 존재한다.

이 node_ids 목록은 관찰 메타데이터의 허용 범위이며, 모든 콘텐츠가 65개 노드에서 반드시 발생해야 한다는 뜻은 아니다. 이를 곧바로 노드 × 콘텐츠 × 문단 × 언어의 필수 실행 목록으로 만들면 잘못된 누락 판정이 생긴다.

확인한 실제 호출부:

| 위치 | 확인한 조건/역할 | 감사상 의미 |
| --- | --- | --- |
| chapter_one_session.gd::act 시작 | 행동 전 history_context를 캡처 | 상태 전환 뒤의 stage가 아닌 원래 발생 노드를 기록해야 함 |
| mark | 침실 + A1 + 등록된 MARKS | A1 표식 신규 획득은 A1에 한정 |
| confirm_mark | 침실 + A2 | A2 확인은 기존 카드의 새 revision |
| read_schedule | 공용실 + 지속 확인 + 등록 문서 | 특정 stage 하나보다 장소/지식 조건에 의존; 재방문 경로 고려 필요 |
| routine/move | 표식 보유·접근 가능 방·연결/에드가 상태 등 | 공유/상속 동작을 최초 사건 stage 하나로 무리하게 제한하면 안 됨 |
| chapter_one_notes.gd::write | MARK_IDS 3종만 version 2, 그 외 version 1 | 과거 A1 v1을 새 생산으로 세지 않고 현재 버전 선택을 확인 |
| notebook_event_notes.gd::write | 기존 revision, source graph, 실제 관찰 원문을 검증 | 동일 획득은 중복 revision을 만들지 않으며 이미 공개된 출처만 참조 |

넓은 목록만으로 실제 플레이에서 잘못된 기록이 생성된다고 결론내리지는 않는다. 호출부의 조건과 상속/재방문 경로를 먼저 조사한다. 과거 카탈로그를 임의로 좁혀 저장된 기록의 재열람을 깨뜨리지 않는다.

## 추가한 검사와 결과

각 suite의 실제 저장된 observation에서 `producer/content/version/node/variant/segment/viewed_locale`를 추출한다. 현재 생산자가 선택해야 할 의미 버전과 카탈로그 분기·허용 노드·공개 문단·실행 언어의 일치를 검사한다. 요청 descriptor나 예상 문장으로 관찰을 대신 생성하지 않는다.

| 대상 | 현재 콘텐츠 | ID·언어 | 실제 노드 포함 tuple | 결과 |
| --- | ---: | ---: | ---: | --- |
| NP04 일반 대사 | 57 | 114 | 194 | PASS |
| NP06 수첩 획득 | 26 | 52 | 52 | PASS |

NP04의 기존 문단·언어 수는 190개다. 같은 문단이 다른 실제 노드에서도 관찰되므로 노드 포함 집합은 194개다. NP04에서 관찰된 노드는 A1/A2/AS/B2/B3_A/B3_B/B4/B5/J1, NP06은 A1/A2/B1/B3_A/B3_B/B4/B5/J1이다. 이 목록 밖의 노드를 전부 도달 불가나 미검사 버그로 분류하지 않는다.

기존 suite의 실패/응답 소실·재시도·원문/출처 불변·읽기 전용·리셋·저장/로드 검사를 유지했다. LAYOUT_MISSING/PHASE_UNSET/내실 조사 guard fixture 및 수첩 BF_PHASE_UNSET fixture도 포함되며, fixture를 UI에서 자연 발생한 모든 상태의 증거로 확대하지 않는다.
