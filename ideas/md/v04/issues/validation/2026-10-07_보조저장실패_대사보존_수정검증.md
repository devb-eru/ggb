# 보조 저장 실패 대사 보존 수정 검증

## 문제와 원인

[ERR-0050](../items/GGB-ERR-2026-0050_보조저장실패_안내가_대사기록을_대체.md). 기준 `962a8c8`에서 실제 F3 조사/최종 확인 버튼과 실제 본편 저장을 실행하고 사본 저장만 실패시켰다. 한영 모두 EDC에 정상 도달했으나 안내가 신규 `unmapped` 행 한 개로 남고 authored `F3_OPEN`은 0개였다. 영어에서도 한국어 안내가 대사로 표시됐다.

원인은 `BasementSession._commit`이 보조 저장 오류를 본편 성공 결과의 `text` 교체와 `notebook_feedback` 삭제로 전달한 데 있다. 부모 컨트롤러는 성공 결과를 표시할 대사로 취급한다. 이는 구형 체크포인트의 이미 존재하는 마지막 피드백을 조회하는 예외와 다른 신규 발생 오류다.

## 수정 후보

- 성공한 본편 결과의 원문/화자/descriptor/발생 전 문맥을 그대로 둔다.
- 보조 실패는 `auxiliary_warning`의 제한된 UI 키로만 전달한다. F3 사본/감상 기록 안내 두 키를 한국어·영어로 준비한다.
- 컨트롤러는 상태 영역에 경고를 표시한 뒤 기존 대사 표시 경로를 실행한다. 원문 기록 실패가 발생하면 더 중요한 기록 저장 오류가 경고를 덮어써 진행을 막는다.
- 보조 실패로 본편 성공을 거부하거나 이미 저장한 진행을 되돌리지 않는다. 크레딧의 빈 원문을 가짜 대사로 바꾸지 않는다.
- 카탈로그·게임 저장 형식·최종 선택 규칙·엔진 기준·rollout은 바꾸지 않는다. 두 안내는 `EXCLUDED_UI`다.

T19i 고정 소스 실행과 분리한 TEMP 후보에만 세 파일을 우선 수정했다. 기준 프로젝트는 변경하지 않았다. [기준/후보 파일 SHA](evidence/2026-10-07_sidecar_feedback_source_guard.json)와 final 추적 로그의 후보 코드 지문을 보존한다. 작업본 반영과 Git 전달 검사는 아래 마지막 절에서 확정한다.

### 수정 후보 집중 회귀

[회귀 소스](evidence/2026-10-07_sidecar_feedback_regression.gd), [장면](evidence/2026-10-07_sidecar_feedback_regression.tscn).

| 모드 | 실행 조건 | 결과 |
| --- | --- | --- |
| 개발 수첩 v2 | 한영 × F3 정상/사본 실패, 두 엔딩 크레딧 정상/감상 저장 실패, 원문 기록 동시 실패/재시도 | 14조건 PASS |
| 기본 모드 | 같은 조건, 기존 schema 없는 transcript 계약 | 14조건 PASS |

- v2 F3 정상/사본 실패/원문 기록 실패 뒤 재시도에서 `F3_OPEN`은 한 개, 새 시스템 `unmapped`는 0이다. 화면 보드 등 다른 authored 기록 수와 F3 원문 수는 구분한다.
- 기본 모드는 기존 대사 원문을 기록하지만 보조 안내 문구는 기록하지 않는다. 기본 모드의 legacy 행을 v2 신규 미매핑으로 집계하지 않는다.
- 원문 기록 실패는 UI 경고보다 우선하며 미저장 문단을 다음 줄로 넘기지 않는다. 재시도 성공 후에도 최종 결정은 미정이다.
- 두 엔딩 크레딧 진입의 원문은 계속 빈 문자열이며 가짜 대사/기록을 만들지 않는다.
- 본편/크레딧의 실제 저장 뒤 LoadCoordinator 복귀가 확정 snapshot과 일치한다. 별도 프로세스 재시작이나 물리 입력 검사는 아니다.

### 기존 final suite

수정 후보의 기존 전체 `notebook-final-smoke` PASS, 실제 132 ID-언어/312 문단-언어, 익명 자료 후반 결정 12경로와 두 엔딩 후속 4경로 유지. [stdout](evidence/2026-10-07_sidecar_feedback_final.out.log), [stderr](evidence/2026-10-07_sidecar_feedback_final.err.log), [receipt](evidence/2026-10-07_sidecar_feedback_final.run.json).

T19i의 기준 소스 실행과 이 후보 final의 trace는 소스 지문이 다르므로 하나의 합집합에 넣지 않는다. known 인증서 저장소 경고 외 script/parse/compile 오류는 없었다.

## 전달 상태와 한계

수정 후보 검증 완료, 작업본 반영/commit/push는 T19i 종료 뒤 진행한다. 현재 이슈는 OPEN이며 후보 PASS만으로 VERIFIED를 선언하지 않는다.

이번 경계 수정은 전체 신규 미매핑 0이나 모든 생산자 필수 분기 완료를 뜻하지 않는다. 정식 성능, 실제 전편 입력, 공식 4.6.3 채택과 rollout 인수는 계속 남는다.
