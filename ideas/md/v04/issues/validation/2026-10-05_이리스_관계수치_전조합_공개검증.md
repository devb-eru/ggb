## 독립 기대값

생산 코드의 `confession()`을 호출해서 기대값을 만들지 않는다. 테스트에 아래 두 결과표를 명시하고 선택 보정 뒤 수치로 행을 선택한다.

| 선택 후 호감도 | 선택 후 경계 0~3 | 선택 후 경계 4~5 |
| --- | --- | --- |
| 0~1 | withheld | denied |
| 2~3 | indirect | indirect |
| 4~5 | direct_private | direct_private |

경계가 4 이상이면 별도의 날카로운 목소리 문단이 붙는다. 이 문단은 고백 수준과 독립되어 직접 고백과 함께 나올 수 있다. 특히 초기 경계 3에서 온실 유지 선택 후 4가 되는 조건, 초기 호감 1/3에서 외부값 선택 후 3/5가 되는 조건, 수치 5의 상한을 실제 결과와 비교한다.

## 각 조합의 검증

1. 실제 관계 선택창의 답변 버튼을 실행한다.
2. 선택 저장 직후 연구 기록 한 개·지식 revision 한 개만 있고, 아직 표시하지 않은 고백은 없는지 검사한다.
3. 실제 문단을 진행해 선택한 고백 한 종류와 조건부 경고만 저장되는지 검사한다.
4. 관계 수치·완료·기록 획득·원래 연구 기록 원문을 비교한다. 별도의 전역 고백 상태는 만들지 않는다.
5. 연구 기록 출처를 모두 해석하고, 기록 획득 이후 발화한 사적인 고백을 출처로 소급 추가하지 않았는지 검사한다.
6. 완료 선택 재실행을 거부하고 전체 상태가 같은지 검사한다.
7. 통합 수첩을 열고 닫아도 게임 상태·고백이 변하지 않는지 검사한다.
8. 실제 슬롯을 다시 로드해 전체 snapshot을 대조한다.
9. 이후 관계 수치를 반대로 변경한 fixture에서 과거 응답을 다시 렌더링한다. 원문 불변·다른 고백 추가 없음·읽기 중 상태 쓰기 없음을 확인한다.

기존 문단 공개·비공개 참조 거부·부분 센서 복귀·오답 재시도·미룸·저장 실패/응답 유실·오래된 callback 거부·옛 완료 상태의 기록 비소급 생성 검사는 유지한다. 저장 실패와 모든 수치의 곱집합이나 조합별 별도 프로세스 재시작은 아니다.
