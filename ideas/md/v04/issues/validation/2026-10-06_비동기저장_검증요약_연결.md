# 비동기 저장 검증 요약 연결

- 기준: develop `d16f7c2`.
- 관련: T20/T21. 기존 성공 저장·로드 요약 재사용에서 빠져 있던 비동기 책갈피/비교 저장 경로를 연결한다.

## 구현과 신뢰 경계

`notebook_save_worker.gd`는 검증된 임시 파일에서 작은 요약을 만들고, 이미 반환하던 임시 파일 지문과 함께 반환한다. 현재 슬롯의 작은 표시 메타데이터이며 snapshot을 캐시에 복제하지 않는다.

`SaveManager._finish_notebook_reference`는 기존과 동일하게 취소·guard·revision·load epoch·namespace를 확인하고, main/bak 및 임시 파일의 현재 바이트 지문을 재확인한다. 승격 성공(또는 정확한 확정 저장의 응답 유실 복구)과 현재 상태 설치가 모두 성공한 뒤에만 그 요약을 본파일 캐시에 연결한다.

메인 스레드에서 JSON 재파싱을 추가하지 않는다. 후속 inspect는 실제 바이트를 읽어 지문이 일치할 때만 요약을 사용한다. 상한·크기 제한과 일반 전체 로드 검증도 유지한다.

## 추가 검사

`notebook_async_save_smoke.gd`:

- 정상·백업 기반 저장·성공 응답 유실 복구에서 캐시 지문이 확정 본파일 바이트 지문과 같은지 검사한다.
- 기존 취소·오래된 상태·외부 쓰기·미래 버전·설계 버전·임시 변조·guard·namespace·쓰기 실패·승격 실패 경로에 후보 요약 비공개 검사를 추가한다.
- 대형 비동기 저장 후 요약과 캐시를 지우고 독립 전체 검증한 요약이 정확히 같은지 확인한다.
- 변경 전 성공 경로 세 조건의 신규 요약 연결 단언이 실패했다. 나머지 기능 오류로 집계하지 않는다.
