# 엔진·템플릿 버전 일치 및 Windows EXE 검증

## 기준과 목적

develop `2df859e`. [IME 런타임 비교](2026-10-06_한글IME_공식런타임_비교.md) 다음 단계로 공식 4.6.3 후보의 실제 Windows EXE 빌드 호환을 검사한다. 제품 기준 4.7은 아직 바꾸지 않았으며 사용자 결정은 후보 검증 후 채택 검토다.

## 빌드 오류 수정

[ERR-0043](../items/GGB-ERR-2026-0043_실행엔진과_export_template_버전불일치.md)는 기존 첫 폴더 선택을 4.5.2/4.6.3/4.7.2 fixture에서 재현했다. 이제 실행 파일 `--version`에 맞는 정확한 release/status 폴더, version.txt, windows_debug_x86_64.exe를 확인한다. 없는/다른 버전·marker 누락·debug 누락·잘못된 버전 문자열·경로 시도·Mono는 거부한다. 0 patch의 4.6.stable 표기와 공식/Steam suffix를 구분하며 모든 4.x를 허용하는 방식이 아니다.

`scripts/test_godot_windows_template_policy.ps1`은 PowerShell 7 및 Windows PowerShell 5.1에서 각 정상 3/거부 7조건, 총 10개 PASS다. 이 중 거부는 정확한 디렉터리 없음·marker 불일치·debug 없음·잘못된 버전·경로 시도·Mono·marker 없음이다. 생성 fixture는 가짜 빈 파일이며 실행하지 않는다. GUID 임시 루트만 안전 경로 확인 후 정리했다.

검증 스크립트에 새 runtime 경로/APPDATA를 적용하고 이미 있는 명시 경로는 거부한다. 각 자식 실행은 600초 제한이며 timeout이면 생성한 자기 프로세스만 종료한다. 기존 `-GodotPath` 호출은 유지하고 필요한 경우 `-RuntimeRoot`로 새 격리 경로를 지정한다. timeout 실제 발생/전원 차단 검증은 이번 범위가 아니다.

동일 validation-app 경로 재사용을 실제 스크립트로 시도해 명시 거부와 기존 EXE/PCK hash 보존을 확인했다. 첫 문서 검사는 신규 이슈의 items/README 색인 누락을 보고했으며 해당 행을 추가한 뒤 재검사한다. 스크립트/게임 런타임 오류와 문서 색인 오류를 구분한다.

## 공식 템플릿과 EXE

[공식 Godot 4.6.3 배포](https://github.com/godotengine/godot/releases/tag/4.6.3-stable)의 표준 export_templates.tpz(1,255,918,323 bytes)를 임시 경로에 내려받았다. release API의 SHA-256 `3FBE2C0E2DEC9D537AB9EC97BCF8DA91DCF23357FC51F67092DD068D839290A8`과 전체 바이트 hash를 대조한 뒤 version.txt와 Windows debug/release x64만 추출했다. 설치된 Steam/에디터 템플릿은 변경하지 않았다.

EXE는 `%TEMP%/ggb-ime-463-game-compat-20261006/builds/renderer_candidates/{compatibility,forward_plus}`에 생성했다. runtime/template 원본은 `%TEMP%/ggb-ime-463-templates-20261007`, 격리 APPDATA는 그 아래 validation-app이다. 수정한 스크립트가 공식 `4.6.3.stable.official.7d41c59c4`와 정확한 템플릿 폴더를 출력한 것을 확인했다.

두 EXE 내보내기 및 각각 `--rendering-method gl_compatibility|forward_plus --headless -- --foundation-smoke`는 종료 0/FOUNDATION_SMOKE PASS다. 같은 preset/템플릿이므로 두 EXE hash가 같다. 이는 서로 다른 렌더러로 구운 두 바이너리나 실제 GPU 렌더링 검사가 아니며 실행 옵션별 기본 기능 검사다. CNF-0019의 렌더러/장비 인수를 완료 처리하지 않는다.

기존 bootstrap의 `GGB expects Godot 4.7.x` 경고가 있다. 제품 요구를 아직 변경하지 않아 정상적으로 출력되는 것이며 숨기지 않았다. export pack/Windows EXE 생성과 제품 엔진 채택을 구분한다. release 템플릿은 hash 검증·추출만 했고 release EXE 빌드/실행은 미검증이다.

## EXE의 수첩·갤러리 검사

Compatibility EXE를 소스 없는 새 작업 폴더 `%TEMP%/ggb-ime-463-exe-notebook-20261007`와 별도 APPDATA에서 실행했다. `--notebook-content-smoke` 및 `--notebook-query-smoke` 모두 종료 0/PASS다. query suite 안의 metadata/gallery 검사를 별도 신규 gallery CLI가 있는 것으로 오인하지 않는다.

- 콘텐츠: 힌트 60 ID/120 ID-language, NP20 필수 조합 150/150, 누락 조합 없음. 저장 실패·재시도 150조건과 지원 조건 16개를 검사했다. 전체 22개 생산자 검사를 의미하지 않는다.
- 조회: `NOTEBOOK_QUERY_CHECKS: 6838`, `NOTEBOOK_QUERY_SMOKE: PASS`. 내부 갤러리 232, 검색 180, 조사 300, 인물 보존 64, 기억 공개 83, 자기 표시 270은 하위 검사 수치로 중복 합산하지 않는다.
- 증거: 위 임시 폴더의 `content.out.log`, `content.err.log`, `query.out.log`, `query.err.log`. 제품의 4.7 요구 경고는 남아 있으며 script/parse/compile 오류는 보고되지 않았다.

표준 출력은 [콘텐츠 증거](evidence/2026-10-07_463_exe_content.log), [조회 증거](evidence/2026-10-07_463_exe_query.log)로 보관한다. 복사 원본 SHA-256은 각각 `ACACE8B5C510C7E58D5CE46220D9C72F191A03CE4A0F60C9E6B3C165328915B1`, `C17CEED9F8ED5CFDB977BDA29FCBADCC792C0E10F963C9B8A2E7D6E3D33CBCE5`다. Git 줄바꿈 정규화 시 저장소 blob 바이트 hash와 다를 수 있다. metadata 74,752검사는 카탈로그/조회 fixture 검증이며 실제 컨트롤러 분기 커버리지가 아니다.

대용량 TPZ는 전체 hash 검증·추출 후 해당 파일만 정리했다. 후속 release export 시도는 임시 실행 파일을 찾지 못해 프로세스 생성 전에 종료됐다. 재확인에서도 임시 공식 엔진/템플릿 실행 파일은 없고 debug 후보 EXE/PCK와 결과 로그는 남아 있다. 삭제 원인은 확인되지 않았으며 release 빌드 성공으로 기록하지 않는다. 재개 시 공식 hash 검증 런타임과 release 템플릿을 다시 확보해야 한다. 실제 설치나 사용자 프로젝트 파일은 이 시도로 변경하지 않았다.
