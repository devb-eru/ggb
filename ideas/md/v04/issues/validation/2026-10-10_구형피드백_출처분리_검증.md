## 출처와 표시 계약

| 단계 | 처리 | 금지/보존 |
| --- | --- | --- |
| 새 피드백 작성 | `producer_contract_version: 1` 저장 | descriptor 누락 뒤 재시작해도 구형 예외로 바꾸지 않음 |
| 구형 초기화 | 표식/descriptor가 없는 원문을 출처 해시와 함께 보존 | ID 역검색·현재 장/장소 추정·관찰 선등록 금지 |
| 상속 세션 초기화 | 거울/지하의 단순 전달에서 같은 출처 유지 | 새 행동의 피드백에 과거 예외를 상속하지 않음 |
| 대화 표시 | 원문·문단별 출처 proof/토큰 확인 | `text_id`로 최신 번역을 재생하지 않음 |
| 실제 관찰 저장 | `legacy`와 전체 출처 marker, 커서를 원자 저장 | 새 `unmapped`나 authored ID를 만들지 않음 |
| 반복·언어 변경·분기 복사 | 같은 토큰의 최초 UID/원문/언어 유지 | 다른 원문·화자·문맥·새 사실 주입 거부 |
| 기존 기록 | 기존 legacy/unmapped 불변 | 출처가 없는 과거 원장을 소급 재분류하지 않음 |

`source_id`는 원문·출처 ID·형식의 정규 JSON SHA-256이며 cryptographic 서명이나 외부 신뢰 증거가 아니다. 검증된 슬롯/현재 pending 피드백과 같은 값인지 대조하는 내부 일관성 표식이다. 조회 중 ID를 추론하지 않는다. 전체 archive/root schema는 유지하고 구형 재표시 항목에만 marker를 추가한다. 기존 책갈피·비교·보존 정책과 표시 커서 v4를 재사용한다.

## 재현과 격리

검증 엔진은 설치를 변경하지 않고 복사한 Steam `4.7.2.stable.steam.ed1daf0bf`, 실행 파일 SHA-256 `12310c74bdda7dcd43f28e971f33047dcecadd436b68169d61ce41009006df38`다. 4.6.3 검증이나 엔진 채택 결과가 아니다. 새 TEMP 게임 복사본·실행별 APPDATA/LOCALAPPDATA를 사용한다. 사용자 세이브·Steam 설정·실행 중 사용자 Godot는 건드리지 않는다.

```powershell
./scripts/run_notebook_runtime_audit.ps1 -EnginePath <isolated-engine> -ProjectPath <TEMP-game> -EvidencePath <new-TEMP-evidence> -Suites legacy-feedback,producer-contract,chapter-one -RequireAuthored -TimeoutSeconds 1200
```

초기 검사 실패는 새 helper/test를 작성하는 과정에서 발견됐다. 첫 fixture는 JSON 수 정규화를 빠뜨려 설치가 거부됐고 정규화한 실제 loader 계약에 맞춰 수정했다. 이어 구형 marker의 허용 언어를 Godot의 `ko_KR/en_US` 입력과 맞추지 않아 실제 표시 저장이 거부되는 문제를 수정했다. 과거 문맥 추가 검사에서는 런타임 사전의 StringName 키를 JSON-safe 검사에서 잘못 거부하던 새 helper를 기존 사전 직렬화 규칙과 맞췄다. 실패 원자료도 보존하고 성공 결과로 덮어쓰지 않는다. 기존 제품에서 재현한 새 이슈나 전편 결함 해결 수로 집계하지 않는다.

처음 원자료 복사 래퍼가 receipt의 필드 이름을 잘못 조회해 비종료 오류를 출력했다. 올바른 `stdout_sha256/stderr_sha256`과 Stop 정책으로 보존된 전체 19세트를 재검증했고 모두 일치한다. 래퍼의 exit 0이나 복사 성공만으로 hash 검증을 인정하지 않는다. 본문 소스와 원본 로그는 변경하지 않았다.

## 전달 검증

코드·문서·원자료 79개만 develop `5d64799045b55b6eafea7ea4228fdef7d20e367b`에 커밋했다. 커밋 tree `1fc33b64d7d404fbf4d59697e6ba8058650bed84`는 사전 검증한 staging 아카이브와 같다. 복원본의 스크립트 264개 SHA·원자료 receipt 19세트·고유 trace 278경로·문서 425개/이슈 70개를 다시 대조했다. 실제 작업 폴더의 기존 사용자 수정 17개는 각 SHA를 보존하며 사용자 추가 파일·세이브·Steam 프로세스는 수정하지 않았다.

초기 아카이브 래퍼가 비동기 exec의 아직 없는 exit_code를 실패로 오인했다. 아카이브 자체의 실패 근거가 아니며 종료를 기다린 새 복원본으로 검증했다. push 뒤 원격 출력의 탭 구분을 잘못 파싱한 래퍼도 원격 불일치라고 출력했지만, 올바른 구분으로 다시 읽은 local/remote SHA는 위 커밋과 같다. 커밋·push를 중복 실행하거나 이력을 되돌리지 않았다. 이 orchestration 오류는 게임 결함·회귀 성공 수에 포함하지 않는다.
