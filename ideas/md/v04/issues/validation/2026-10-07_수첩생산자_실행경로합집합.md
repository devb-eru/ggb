- 기준: develop `c376f79`. T19c의 테스트 추적·집계 기반만 완료한다.
- 환경: Steam Godot 4.7.2 headless, 격리 APPDATA. 실제 Windows 입력 검사나 4.6.3 채택 근거와 구분한다.
- 원본: [집계 JSON](2026-10-07_수첩생산자_실행경로합집합.json).

## 수집 계약

테스트 전용 `notebook_runtime_audit.gd`는 `--notebook-producer-trace`에서만 실행한다. 커밋된 원장에서 생산자·내용 ID·의미 버전·노드·분기·문단·언어의 7필드 관찰을 수집한다. 아카이브 유효성과 authored 재렌더링을 확인하고, 동일 출처/entry UID의 불변 내용 변화를 오류로 기록한다. 보호 사유는 가변 필드이므로 불변 지문에서 제외한다. 제품 상태나 사용자 파일에 기록하지 않는다.

집계 도구 `scripts/audit_notebook_runtime_union.ps1`은 PowerShell 7에서 실행한다. 명시적인 stdout 경로별로 stderr와 완료 receipt를 요구하며, native exit 0·로그 SHA-256·PASS 표식·오류 유무를 확인한다. 알려진 인증서 저장소 경고만 허용한다. 로그는 JSON으로만 해석하며 실행하지 않는다.

세 실행의 카탈로그 29개 지문과 `res://scripts/**/*.gd` 260개 지문이 현재 입력 프로젝트와 일치해야 한다. 스크립트 집합 지문은 `6aab7b41899fc66e00c8b9bb405a8353fa4661b079af8bf2cc6882f385b7411d`다. 이는 씬·아트·실행 엔진 전체의 지문은 아니다. 코드/카탈로그 변경 뒤 이전 로그를 현재 실행 증거처럼 집계하면 거부한다.

## 증거와 재실행

`evidence/2026-10-07_runtime_union_{stay,chapter-surfaces,prologue-surfaces}.{out.log,err.log,run.json}`에 세 실행의 원본 및 receipt를 보관한다. 각 stdout·stderr는 receipt 해시로 대조한다.

```powershell
$base = 'ideas/md/v04/issues/validation/evidence/2026-10-07_runtime_union_'
$logs = @('stay', 'chapter-surfaces', 'prologue-surfaces') | ForEach-Object { $base + $_ + '.out.log' }
./scripts/audit_notebook_runtime_union.ps1 -TraceLogs $logs
./scripts/audit_notebook_runtime_union.ps1 -SelfTest
```

처음 집계 래퍼는 성공 JSON과 무관한 이전 `$LASTEXITCODE`를 검사해 실패로 표시했다. 재실행 결과 `ok=true/errors=[]`와 원본 receipt를 확인했다. 도구의 실패 결과를 숨기거나 성공 근거로 바꾼 것이 아니다.

- UI 제외/신규 unmapped/legacy 유입을 개별 호출의 발생 기준으로 수집한다. 원장 표본 수로 대체하지 않는다.
