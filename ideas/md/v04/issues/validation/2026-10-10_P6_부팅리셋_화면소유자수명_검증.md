## 3. 수정 계약

### P6

- 암전 시작 전에 화면 트리 세대, 부모 호스트·호스트 세대, 슬롯·기록 scope, coordinator와 요청 동일성을 캡처한다.
- `NormalResetTask.run(task)`의 정적 함수 인수로 RefCounted 작업을 강하게 유지한다. 화면·부모는 WeakRef로 조회한다.
- Node의 `await tween.finished`를 없애고 살아 있는 SceneTree 프레임에서 Tween·소유권을 확인한다. 색 적용 콜백도 동일 소유자일 때만 실행한다.
- 트리 이탈은 세대를 증가시키고 자체 pending·Tween·암전막을 폐기한다. 재진입해도 이전 작업을 되살리지 않는다.
- 만료된 작업은 새 상태/본파일/백업, 교체 UI·모달·fade를 변경하지 않는다. 살아 있는 소유자의 실제 저장 실패는 기존 명시 재시도로 이어진다.
- 성공 뒤 R1 표시와 reveal을 유지한다. reveal 은퇴를 검사하기 전에 R1 기록 writer를 정상 정리하여 다른 대사 작업의 수명과 혼동하지 않는다.

### Bootstrap

- `_reset_owner_generation`과 요청 동일성, coordinator·load_epoch를 검사한다. `_exit_tree`에서 pending 소유권을 폐기한다.
- `request_sleep_transition_async(slot, guard, completion) -> void`로 내부 호출 계약을 바꾼다. 결과 Dictionary를 Node에서 await하지 않는다.
- 실제 기다림은 `ResetHostTask.run(task)`의 강하게 유지되는 RefCounted 작업에 둔다. 이미 확정된 내구 영수증은 유지하고 만료 결과에는 `retired`를 표시한다.
- 부팅 완료 콜백은 살아 있는 동일 세대에만 캠페인을 연다. 실제 저장 실패는 기존 타이틀 오류 안내를 유지한다.
- 제품 호출부 두 곳(P6·부팅)을 함께 변경했다. ChapterOneController의 종료는 기본 화면 정리를 상위 호출하여 본편 c1b1 계약도 유지한다.

## 4. 독립 검사 분모

P6 상황: 정상, 화면 queue/free/detach/reenter/reparent, 호스트 queue/free/detach/reenter, coordinator 교체, 슬롯 교체. 부팅 상황: 정상, 호스트 queue/free/detach/reenter/reparent, coordinator 교체, epoch 교체.

각 실패 경계에서 마지막 내구 snapshot·본파일·백업·worker 시작 횟수를 보존해야 한다. 이미 idle이 확정된 complete 경계는 해당 영수증을 기준으로 삼는다. 정상 대조군은 정확히 day 1/idle에 도달하고, 만료 소유자는 새로운 캠페인을 열거나 교체 상태 안내를 덮어쓰지 않아야 한다. 실제 전환 후 일차·phase 좌표도 결과에 보존한다.

## 6. 남은 인수

ERR-0063/0064의 국소 수정·검증과 전체 목표는 구분한다. 별도 프로세스 종료/복귀, 최신 소스의 물리 수면 입력·마우스/키보드 전편 완주, 다른 동기 저장·초기 initialize, 전 22생산자/소비자의 독립 필수 분기, 정식 성능·엔진 채택/rollout과 전체 인수는 계속 남는다.
