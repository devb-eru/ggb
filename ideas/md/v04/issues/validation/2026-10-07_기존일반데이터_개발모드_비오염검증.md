- 기준 develop: `60f9f4390dd003c0d529ff2635d5aed92f8c1f7e`.
- 런타임: Steam Godot `4.7.2.stable.steam.ed1daf0bf`, Windows headless.

1. 기존 개발 회귀의 jump/resume/89개 체크포인트 및 F3 재선택 복사본 생성·로드를 실행했다.
2. 복사본을 실제 컨트롤러로 tree에 추가하고 수첩을 연다. 획득 자료를 고정하고 비동기 저장 완료 뒤 복사본 재로드에서 고정을 확인했다.
3. 실제 복사본 표시 위치 추적기의 live namespace가 development임을 별도로 단언한다.
4. 개발 엔딩 캡처를 갤러리 host로 열어 자료·임시 비교를 사용하고 live snapshot 불변을 확인했다.

## 발견과 해결

초기 실행은 저장 12/프로필 17을 채웠으나 프로필 비교가 실패했다. 정상 development 표시 위치 파일을 검사기가 일반 파일로 포함한 오탐과, 실제 개발 F3 복사본 표시 위치의 full namespace 파일 생성이 함께 있었다. 같은 복사본 수첩은 development였다. 저장 12개는 그때도 보존됐다.

별도 제품 오류 [ERR-0046](../items/GGB-ERR-2026-0046_개발F3복사본_표시위치namespace_분류누락.md)을 공통 namespace 정책으로 수정했다. 일반 표시 위치 fixture 12개도 추가했다. 테스트 비교기는 파일 경로·정확한 scope·스키마·체크섬을 확인한 정상 development 편의 파일만 분리한다. 갤러리 namespace는 실제 개발 갤러리 캡처 ID와 일치하는 수첩 파일만 허용한다. full/demo, 미등록·손상·예상 밖 파일은 보호 대상이다.

따라서 동일 `profile` 물리 폴더 아래 개발 파일 생성은 허용하지만 일반 논리 namespace의 추가·삭제·변경은 허용하지 않는다. 폴더 전체를 무조건 제외하지 않는다. 기존 잘못된 편의 파일은 자동 삭제/이관하지 않는다.

## 안전성 및 검증 과정의 실패

별도 marker 불일치·기존 프로필 canary의 두 거부 검사: 의도된 종료 1, 로그 외 파일 목록·내용 불변. 토큰 없는 기존 환경에 초기 데이터를 쓰지 않는다.

새 테스트 코드의 문자열 타입 추론 오류는 명시 String으로 수정했다. v2 옵션 누락 실행은 구형 archive에서 테스트 오류가 발생해, 초기 데이터 생성 전 명시 rollout 확인을 추가했다. 해당 실패 실행은 PASS 근거로 계산하지 않는다. PowerShell guard 도구의 변수 콜론 구문 오류도 실행 전 수정했으며 제품 오류와 분리한다. 최종 stderr에는 기존 루트 인증서 저장소 읽기 오류만 있고 스크립트 오류는 없다. 모든 테스트 자식은 종료됐다.
