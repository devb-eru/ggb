## 기준 실행과 진단

1. 최초 저장 경계 검사: 한영 42조건·607단언을 실행했으나 전체 native 1이다. 닫기 뒤 현재 화면의 후속 표시 저장까지 같은 `completed` phase에 포함되는데 ACK 유실 횟수를 무조건 1로 가정한 12단언이 실패했다. 이 시도를 통과로 계산하지 않는다. 후보 검사에서는 실제 트랜잭션을 수집해 닫기와 후속 표시를 구분하며, 별도로 게임 상태·선택/관찰 개수를 검사한다.
2. 재시도 집중 검사의 첫 시도는 `delegate`의 동적 반환값에 대한 지역 String 타입 추론 실패로 테스트 본문에 들어가지 못했다. 명시적 String 타입으로 보완했다. 제품 오류와 구분한다.
3. 타입 보완 후 원래 제품 코드를 대상으로 18조건·2,334단언을 실행해 전체 native 1이다. 실제 retry 버튼의 연결 메서드는 `_ep01_retry_finish`, bound argument는 1개였다. 정상 원래 retry는 성공했지만 완료 후 보관한 callable 및 교체 화면에서의 callable이 상태/파일/공개 기록을 변경했다. ERR-0077로 등록했다.

원본 실패 실행은 `ggb-ep02-boundary-dc024116839049c4b88e16ca19fda907`에 보존한다. 새로운 후보 실행을 위해 교체하기 전에 그 실행의 310 GDScript 지문을 대조하고 `source_scripts.zip`으로 원래 코드를 보관했다. 최초 42조건과 파싱 실패는 각각 별도 실행 루트에 남긴다.

## 후보 수정

- `_ep01_finish`가 오류 UI를 만들 때 원래 context 복사본, scope, 다음 모달 세대와 다음 대화 세대를 고정한다.
- `_ep01_retry_finish`는 실제 살아 있는 원래 모달인지 먼저 검사한다. 다른 슬롯·세션·epoch·화면 또는 완료 후 보관한 버튼이면 UI를 닫거나 저장을 시도하기 전에 반환한다.
- 정상 원래 버튼은 기존 완료 처리로 진행한다. 완료 내구 저장·효과 영수증·공개 기록 규칙을 생략하지 않는다.
- 공유 첫 장 controller의 변경이므로 집중 검사 외에 기존 시트·선택창·관련 캠페인 회귀가 필요하다.

## 현재 확인 결과

- 수정 후보에서 원래 retry는 완료하고, 완료 후 보관한 callable·동일 controller 재설정·다른 presentation·epoch/slot/session 교체 및 교체 후 새 presentation의 오래된 버튼은 snapshot/revision·슬롯 바이트·UI·공개 기록을 바꾸지 않는다. 실제 UI 연결을 검사하며 OS 입력으로 계산하지 않는다.
- 저장 경계의 한영 44조건은 각각 독립 fixture로 시작한다. 언어 변경 복귀를 포함한 조건도 시작 언어를 매번 원복해 한영 분모가 뒤섞이지 않는다.
- C4/J3의 닫기와 뒤따르는 실제 표시는 같은 `completed` phase에서 서로 다른 2~6개 저장을 사용했다. 각 ACK 유실 트랜잭션은 고유하며, 해당 사실을 44개 실제 snapshot/disk 쌍과 함께 별도 trace에 보관했다. 처음의 무조건 한 번 저장 가정과 구분한다.
- 선택형 기억 완료 EFF46의 정상 retry·ACK 복구와 복원 완료 EFF49의 버튼 수명 검사를 별도로 실행했다. 이 결과를 모든 비동기 대화·모달의 수명 인수로 확대하지 않는다.
- 실제 화면에서는 마우스로 P1 안내·사진 조사·일과 시작 확인·중앙홀 안내를 거쳐 P2 대응접실에 진입했다. 이 실행의 소스는 기존 격리 GUI 기준 `c4abc09e`이며, 후보 수정이 적용된 최신 source 310스크립트의 OS 검증으로 바꿔 기록하지 않는다.
