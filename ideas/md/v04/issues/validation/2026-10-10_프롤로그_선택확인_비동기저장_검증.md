## 1. 구현

1. 선택지 표시와 선택 확정을 `choice_options`, `choice_selected` 원자적 후보로 저장한다. 확인 모달도 `confirmation_options`, `confirmation_selected`로 같은 규칙을 적용한다.
2. worker에 보내는 상태는 분리 복제한다. 내구 성공 전에는 다음 대사·이동·수면·선택 후 행동을 실행하지 않는다. 진행 중 버튼을 비활성화하며 수동 callback도 차단한다.
3. 요청과 현재 서비스·scope·언어·방·일과·보류 단서·선택 캡처·토큰·문맥이 같은 경우에만 결과를 설치한다. 모달은 요청 객체와 generation까지 대조한다. 오래된 결과는 새 화면에 설치하지 않는다.
4. 실패 뒤 명시 재시도에서 같은 선택 토큰을 유지한다. 성공 후에만 단서·surface 보류 목록을 비우고 실제 후속 행동을 한 번 실행한다.
5. P4 질문 표시 직전의 별도 동기 `_save_progress()`는 async 옵션에서 실행하지 않는다. 차 준비 단계·생명 유지 전조 단서·질문 표시를 하나의 후보로 묶어 저장 실패 시 일부만 확정되던 경계를 제거한다. 일반 동기 기본 경로는 유지한다.

## 2. 언어 전환 복귀 오류

[ERR-0056](../items/GGB-ERR-2026-0056_보류선택_언어전환복귀_관찰충돌.md): 선택을 디스크에 저장한 직후 행동 전 종료하고 다른 언어에서 재확인하면 원문 언어가 달라 `NB_PRESENTATION_CONFLICT`가 발생했다. 원본 develop의 기본 동기 **v2** 경로에서도 별도 native 프로세스로 재현했다. 모든 legacy 게임 경로의 결함으로 확대하지 않는다.

순수 후보 생성기는 유효하고 관찰된 보류 커서·동일 질문/선택/토큰/출처를 먼저 확인한다. 현재 언어의 표시 descriptor·본문·화자도 `CONTENT.observe`로 검증한다. 이미 확정된 동일 의도만 기존 archive 관찰을 다시 append하지 않고 현재 언어의 커서를 설치한다.

동일성 비교에서는 검증된 세그먼트의 `captured_text`, `viewed_locale`만 제외한다. 콘텐츠 ID·버전·variant·변수·화자·세그먼트·발생·장소·세션·보호/공개 정보는 모두 같아야 한다. 원문·당시 언어·UID·archive revision을 바꾸지 않는다. 다른 장소/발생/콘텐츠 또는 완료 커서는 엄격 충돌 검사를 우회하지 못한다. 동기와 비동기 후보가 같은 규칙을 사용하며 공통 writer의 충돌 규칙은 수정하지 않는다.

집중 검사에는 순수 후보 10조건, 실제 UI 22조건, 선택 실패/교체 64조건, 모든 답변 20조건, 같은 프로세스의 새 컨트롤러 복원 16조건, 선택 의도 동일성 12조건, 대용량 8조건이 포함된다. 152 합계를 별도 native 48실행과 혼동하지 않는다.

별도 프로세스 검사는 같은 격리 프로필을 순차 사용한다. seed는 후속 행동 직전 보류 선택을 저장하고 종료한다. resume는 다른 언어에서 명시 재확인해 내구 후 행동을 한 번 실행한다. 세 번째 프로세스는 원래 언어로 답변을 읽기 상태에서 복원하고 전체 snapshot·UID·커서 토큰 불변을 확인한다. `verify_response`는 프롤로그 전체 또는 대사 읽기 완료를 뜻하지 않는다. HEADLESS의 실제 UI 버튼 callback과 디스크/프로세스 검증이지 물리 마우스·키보드 입력은 아니다.

## 4. 실패 이력 보존

- 초기 focused는 검사 스크립트 타입 추론 오류였다. native 성공으로 세지 않으며 정확한 격리 프로세스만 확인 후 종료했다.
- 타입 수정 후 140조건 실행에서 P4 `options_fail`, `options_replace` 한영 네 조건이 실패했다. 단서·진행 동기 저장 분리를 수정했다. 그 뒤 초기 140 PASS는 언어 복귀 수정 전 소스이므로 최종 152의 근거로 재사용하지 않는다.
- 최초 native 복귀와 별도 진단은 정확한 `NB_PRESENTATION_CONFLICT`를 보존한다. 같은 실패 프로필의 수정 후 성공은 원인 분리용이며 최종 동일 소스 48실행에 포함하지 않는다.
- 원본 develop 동기 seed 성공/resume 실패는 오류 재현 증거이며 제품 PASS가 아니다.
- 첫 최종 프로세스 묶음의 P1 resume는 동기 행동이 모달을 닫은 뒤 검사기가 토큰을 읽어 생긴 검사 코드 오류였다. 토큰을 클릭 전에 읽고 이후 archive의 정확한 의도를 별도로 확인하도록 수정한 뒤 새 프로필에서 48실행을 다시 수행했다.
- 이어진 독립 감사에서 live 정수와 JSON 로드 실수의 원시 직렬화 hash 차이를 발견했다. 저장 값의 정확한 비교는 native 검사에서 통과했지만 교차 프로세스 hash의 전제가 잘못되었다. hash 입력을 JSON round-trip으로 정규화하고 새 프로필 48실행을 다시 수행했다. 기존 48개 원자료·당시 검사 코드는 `archive/numeric-hash-attempt/`에 보존하며 최종 48실행에 중복 집계하지 않는다. 정규화 hash는 저장 값 비교를 보조하며, native의 `same_persisted_value` 검증을 대체하지 않는다.
- 과거 소스/검사 도구를 최종 소스와 혼합하지 않는다. 실패 원자료와 필요한 과거 소스를 `archive/`에 보존한다.

## 5. 성능과 남은 범위

대용량 8개는 HEADLESS n=1 복합 내구 저장 표본이다. 시작 비용 약 48~209ms, 내구 반환 약 1.51~5.22초, worker 진행 197~672프레임이다. 프레임 진행은 비차단 worker의 국소 근거이며 실제 UI p95·메모리·저장 응답 예산 인수가 아니다. [ERR-0027](../items/GGB-ERR-2026-0027_대용량_수첩_표시검색저장_지연.md)은 계속 진행 중이다.

단독 `_save_progress()`·일반 surface flush·타이틀·리셋·다른 본편 저장, 자연 프롤로그 전체의 비동기 경로, 전 생산자 필수 호출, Windows 전편 입력·DPI/Alt+Tab/접근성, 정식 성능 측정과 제품 엔진 채택은 남아 있다. 기존 사용자 답변의 실제 게임 IME 다섯 국소 정상 조건은 [ERR-0042](../items/GGB-ERR-2026-0042_Windows_한글IME_음절유실.md)에 이미 기록했으며 이번 HEADLESS 실행이나 동일 답변의 재수신으로 중복 집계하지 않는다.
