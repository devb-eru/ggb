# 1장·공통 선택창 실행 경로 합집합

- 기준: develop `20b55b4`.
- 범위: T19d. 이전 T19c의 세 검사에 NP04·NP05·NP06 검사 세 개를 추가해 동일 소스의 실행 합집합을 만든다. 등록 문단 관찰을 필수 분기 전수 검증으로 확대하지 않는다.
- 실행 환경: Steam Godot 4.7.2 headless, 기존 게임과 별도인 TEMP 프로젝트, 검사별 APPDATA·LOCALAPPDATA. 4.6.3 후보의 물리 IME 결과나 엔진 채택 검증과는 별개다.
- 상태: T19d 완료. 여섯 검사·추적·합집합 PASS. T10/T19 전체 인수는 미완료다.
- [최종 집계 JSON](2026-10-07_수첩생산자_1장선택창_합집합.json).

## 보강 사항

`notebook_chapter_one_smoke.gd`, `notebook_chapter_one_notes_smoke.gd`, `notebook_modals_smoke.gd`에 공통 `notebook_runtime_audit.gd` 수집·출력과 추적 유효성 단언을 연결했다. 기존 테스트의 요구와 실패 조건은 삭제하지 않는다. 원장 획득/표시 소비 이후의 실제 관찰을 수집하며 새 콘텐츠 ID를 만들지 않는다.

집계기의 PASS 표식 검사는 두 기존 형태를 허용한다. 단독 `PASS` 및 bootstrap이 결과 Dictionary를 붙여 출력하는 `PASS {...}`다. 결과 Dictionary도 JSON으로 읽어 `ok=true/errors=[]`를 확인하며 잘못된 요약이나 여러 PASS 표식은 거부한다. `PASSENGER`, `PASS failed`를 거부하는 검사를 추가했다. 완료 receipt·로그 해시·스크립트 오류 검사 및 추적 보고서의 `suite_ok=true/errors=[]`는 그대로 요구한다.

새 실행기 `scripts/run_notebook_runtime_audit.ps1`은 여섯 검사 이름만 허용한다. 빈 목록·중복·다른 이름/대소문자를 거부한다. 사용자 프로젝트에서 실행하지 않도록 프로젝트가 TEMP 안에 있어야 하며, 증거 폴더는 새 TEMP 폴더여야 한다. 기존 증거·사용자 세이브를 덮어쓰지 않는다. 검사별 환경을 격리하고 자식 프로세스 하나씩 완료를 기다린다. 제한 시간 초과 때만 해당 자식을 종료하며 `completed=false` receipt를 남겨 성공 집계에 포함되지 않도록 한다.

stdout·stderr의 원본 바이트 해시와 native 종료 코드, 시작/종료 시각을 receipt에 보존한다. 프로세스 종료 0만으로 합격하지 않으며 집계기에서 PASS/추적 보고서/지문 검사를 추가로 수행한다. 인증서 저장소의 알려진 경고는 오류 예외로 유지한다.

## 발견한 집계 오류

[ERR-0049](../items/GGB-ERR-2026-0049_실행합집합_최신버전_중복집계.md)는 카탈로그별 최대 버전을 전역 최신 버전으로 오인한 오류다. NP06의 표식 v1과 v2를 모두 최신 요구로 세어 52개 대신 58개가 되었다. ID별 전역 최대 버전으로 수정하고 두 입력 순서·과거 버전 보존·최신 관찰만 현재 요구를 채우는 검사를 추가했다. 수정 후 22개 생산자의 최신 문단/언어 요구량이 독립 `audit_notebook_producer_inventory.ps1`의 최신 문단 수 × 2와 일치했다.

처음 독립 대조 래퍼는 `Where-Object union_latest -ne inventory_latest`로 오른쪽 열 이름을 문자열 상수처럼 비교해 오류를 표시했다. 두 열 값을 직접 비교하는 script block으로 고쳐 22행의 일치를 확인했다. 실패한 대조를 성공 검사에 포함하지 않는다. 기존 T19c 원본 JSON과 로그는 변경하지 않고 보고서에 한계를 추가했다.

## 재실행과 증거

`evidence/2026-10-07_runtime_union_expanded_{suite}.{out.log,err.log,run.json}`에 여섯 실행을 보관한다. 원본 로그는 Git 줄바꿈 변환 예외 대상이며 receipt 해시는 원본 바이트를 기준으로 한다.

원본 CRLF 로그를 처음 스테이징했을 때 Git 공백 검사에서 CR을 행 끝 공백으로 오인했다. 로그를 정규화하지 않고 해당 증거 경로에만 `cr-at-eol`을 추가했다. 기존 기본 공백 검사 항목은 그 경로에도 유지하며 코드·문서의 규칙은 바꾸지 않는다.

```powershell
$suites = @('chapter-one', 'chapter-one-notes', 'modals', 'stay', 'chapter-surfaces', 'prologue-surfaces')
# 기존 사용자 프로젝트가 아닌, 동일 소스의 새 TEMP 복사본을 지정한다.
./scripts/run_notebook_runtime_audit.ps1 -EnginePath $engine -ProjectPath $tempProject -EvidencePath $newTempEvidence -Suites $suites
$base = 'ideas/md/v04/issues/validation/evidence/2026-10-07_runtime_union_expanded_'
$logs = $suites | ForEach-Object { $base + $_ + '.out.log' }
./scripts/audit_notebook_runtime_union.ps1 -TraceLogs $logs
./scripts/audit_notebook_runtime_union.ps1 -SelfTest
```

첫 수정 전 도구 재현은 요약형 PASS 로그를 입력해 그 도구의 PASS 형식 제한에서 먼저 거부됐다. 최신 버전 오류의 재현으로 세지 않았다. 이후 단독 PASS를 출력하는 동일한 실제 stay 로그를 수정 전/후에 넣어 58→52를 확인했다. 완료를 기다리는 중 프로세스가 종료된 PID 조회 실패는 오류 검사를 통과한 증거로 삼지 않고 실제 세션 종료 코드와 receipt로 다시 확인했다.

## 남은 인수 조건

- 나머지 생산자 검사에 추적기를 연결하고 같은 소스 지문에서 전체 요구 범위를 다시 실행한다.
- 필요한 행동 분기 목록과 UI 제외/신규 unmapped/생산자별 legacy는 아직 미확인으로 유지한다. 각 suite의 기존 독립 부정 검사를 전체 전편 인수로 부풀리지 않는다.
- T10/T19 전체, 실제 전편 입력·성능·엔진 채택 인수는 계속 진행 중이며 rollout OFF를 유지한다.
