# 잔류 표시 원칙의 누락 조사와 수정 검증

## 감사 범위

기준 develop `74a2b91e695d59c83db594b60f5e331aaa87cf3c`. 계획서의 명시적 기록 생산자·서사 오브젝트/정적 표면 분류 규칙에 따라 네 본편 컨트롤러의 직접 `_set_status` 호출을 검색하고, 잔류 표시 원칙 버튼의 공급자·콜백·카탈로그·실행 테스트를 추적했다. 이 작업은 모든 UI 할당이나 간접 wrapper의 전수 완료가 아니다.

| 표면 | 기존 경로 | 판단/조치 |
| --- | --- | --- |
| STAY_MODE_NEUTRAL 라벨 | `_add_hotspot`만 호출 | 기억·결정 보존이라는 서사 규칙. 실제 보이는 NP19 표면으로 기록 |

## 제품 수정

- 신규 `NB_STAY_APPEARANCE_NEUTRAL_LABEL`: 화면에 보이는 안내만 기록.
- 신규 `NB_STAY_APPEARANCE_NEUTRAL_DETAIL`: 실제 버튼을 눌러 상태줄에서 본 설명만 기록. 화면 열기나 선택 방식 변경으로 상세를 자동 공개하지 않는다.
- 상세 설명의 `S5`를 이미 확인한 진실/현재 기억의 공개 표현으로 변경. 아직 모르는 원인·연구원 정보를 추가하지 않는다.
- 기존 공통 surface writer의 원자 저장·receipt·재시도 버튼 사용. generation/live scope/정확한 node 검사, 새 클릭과 재그리기 구별.
- 외형 정책·기억·관계·지식 ledger·엔딩 결정·대사 커서 불변. 기록·검증된 surface receipt만 추가될 수 있다.
- 기존 stay 118개 ID의 정의를 원본 develop과 구조 비교해 변경 0, 신규 ID 두 개만 확인. 과거 미분류 상태줄을 역검색·소급 매핑하지 않는다.

`--notebook-stay-neutral-only`를 빼고 새 동일 코드/카탈로그를 실행했다. 양언어 기억/외형/자율 원칙, 전달·식탁 관계 분기, 자리, 문장 쓰기, 재시도/공개 경계와 크레딧 제외 등 기존 suite에 새 status 검사를 포함했다.

## 실행 안전성과 한계

Steam Godot 4.7.2, Windows headless, GUID 임시 APPDATA·임시 프로젝트 사용. 사용자 실제 저장은 건드리지 않았다. 각 자식은 종료했고 정상 stderr는 기존 루트 인증서 저장소 읽기 오류뿐이다.

중간 집중 실행은 테스트가 `render_entry`의 `entry.text` 대신 반환 최상위 `text`를 읽어 script 오류가 있었다. suite가 PASS를 출력했더라도 해당 실행은 통과 근거에서 제외했다. 필드를 수정하고 최종 집중/전체 실행은 exit 0·PASS·script 오류 없음 세 조건으로 확인했다.

카탈로그에 이미 등록한 원고와 미실행 분기는 다른 범위다. 이 suite가 열거하지 않은 필수/반복 조건, 전편 EXCLUDED_UI/UNMAPPED 분류, ERR-0026 전체, 실제 OS 입력·성능·4.6.3 채택은 미완료다. rollout 기본 OFF는 유지한다.
