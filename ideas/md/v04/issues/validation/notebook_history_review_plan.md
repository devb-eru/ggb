# 장별 대화 기록 검토와 통합 수첩 시스템 계획

구현 착수 이후의 실제 수정·검증 상태는 [구현 현황](notebook_history_implementation_status.md)을 따른다. 아래 검토의 `미구현/NOT_RUN` 문구는 계획 작성 당시의 기준이며, 현재 구현 전체가 완료됐다는 뜻도 아니다.

## 1. 검토 범위와 결론

- 기준 커밋: `develop`의 `7bb4b7e8c0fb8a9b6206eac5631e999f86c05c19` (`test`).
- 목적: `메뉴 → 대화 기록`의 문제를 확인하고, 대화·단서·기록을 편하게 재열람하는 수첩 시스템을 계획한다.
- 이번 산출물: 정적 코드 검토, 권장 설계, 단계별 구현 계획, 인수 조건. 게임 코드·Resource·저장 데이터·기획 정본은 수정하지 않는다.
- 검토 환경: 기준 커밋과 추적 파일이 일치하는 별도 작업 디렉터리. 원본 작업 폴더의 미커밋 번역·씬·UID는 기준에서 제외한다.
- 검증 한계: 실제 게임 실행이나 키보드 플레이테스트를 수행한 결과가 아니다. 코드에서 직접 확인한 결함과 실행 측정이 필요한 위험을 구분한다.

구현 순서는 **기존 기록 접근 복구·최소 사건 캡처 → 식별·공개·저장 계약과 생산자 매핑 → 공통 수첩 → 자료 연결·비교 → 대화 중 열람·전체 인수**다. 저장 실패·접근성·성능은 마지막에만 검사하지 않고 매 단계에 포함한다. 장별 분류는 유지하되 수첩의 여러 필터 중 하나로 둔다.

이번 개정은 [재검토 보고서](notebook_history_plan_followup_review.md)의 `NB-P01~18`을 설계에 반영한다. `PLAN_RESOLVED`는 계획의 모순·누락을 보완했다는 뜻이며 게임 결함 수정이나 실행 검증 완료가 아니다. `NB-R01~10`의 구현 상태는 여전히 `미구현 / 실행 미검증`이다. NB 식별자는 문서 내부 ID이며 공식 GGB-CNF/ERR 발급을 뜻하지 않는다.

사용자가 확정한 범위는 [GGB-DEC-2026-0012](../../../../../docs/decisions/GGB-DEC-2026-0012_통합_수첩_범위와_기록_보존.md)에 보존한다.

| 결정 | 이번 범위 | 제외·유의 사항 |
| --- | --- | --- |
| 자유 메모 | 자료 고정, 사건에서 작성한 가설의 조회 | 개인 자유 입력·초안·삭제 복구는 후속 기능. A1·SUBJECT 입력은 기존 사건 그대로 유지 |
| 보존 | 최근 일반 대사 2,000개 + 보호 기록 + 기존 미분류 기록 | 전체 합계 2,000개가 아님. 승인된 차기 정책이며 현재 코드·기획 정본 동기화는 구현 2단계 선행 작업 |
| 비교 | 여러 자료를 묶어 담고 두 개씩 교체해 열람 | 세 자료 동시 판정·자동 정답 조합 없음 |

이 문서에서 신규 필드·서비스명·상수는 구현용 제안이다. 현재 스키마에 이미 존재한다고 가정하지 않는다. 범위·보존 결정 외 기존 제품 계약을 자동으로 대체하지 않는다.

## 3. 확인된 문제와 수정 방향

### NB-R01 / P1 / 기존 저장의 대화가 조회에서 사라짐

- 위치: [prologue_controller.gd](../../../../../game/scripts/prologue/prologue_controller.gd) 2135~2153행, [dialogue_repository.gd](../../../../../game/scripts/systems/dialogue_repository.gd) 98행.
- 원인: `chapter_id` 없는 과거 기록은 `LEGACY`로 묶지만 탭 생성용 `chapter_order`에는 `LEGACY`가 없다. 미등록 장 ID도 그룹만 만들어지고 접근할 탭이 없다.
- 발생 조건: 업데이트 이전 슬롯, 분류 정보 없는 기존 기록, 알 수 없는 장 ID. 기록이 저장에는 남아도 화면에서는 비어 있는 것으로 보일 수 있다.
- 대처: `전체`와 조건부 `이전·미분류 기록`을 제공한다. 알려진 사건 ID로 확실히 판별 가능한 기록만 이관하고, 본문 키워드나 현재 진행도로 과거 장을 추측하지 않는다.
- 완료 조건: 과거 기록만 있는 슬롯에서도 모든 정상 기록이 조회되며, 분류 불명 기록을 버리거나 새 기록으로 다시 append하지 않는다.

### NB-R02 / P1 / 장 이름 문자열 6개 미등록

- 위치: [prologue_controller.gd](../../../../../game/scripts/prologue/prologue_controller.gd) 2137~2142행, [dialogue_repository.gd](../../../../../game/scripts/systems/dialogue_repository.gd) 43~52행, [text_registry.json](../../../../../game/data/registries/text_registry.json).
- 확인: `CH1_HISTORY_CHAPTER_PROLOGUE`, `_1`, `_2`, `_3`, `_4`, `_LEGACY`가 문자열 레지스트리에 모두 없다. 코드 참조만 존재한다.
- 결과: 조회 함수의 대체 경로에 따라 `[CH1_HISTORY_CHAPTER_1]` 같은 내부 ID가 버튼 이름으로 반환된다.
- 대처: 레지스트리와 한국어·영어 카탈로그를 같은 변경에서 등록한다. UI가 요구하는 키의 존재를 검사한다. 예: `프롤로그 / Prologue`, `1장 / Chapter 1`, `이전·미분류 / Earlier / Unclassified`.
- 완료 조건: 모든 장·빈 상태·오류 상태에서 내부 ID가 플레이어 화면에 노출되지 않는다.

### NB-R03 / P1 / 서사 장 구분과 저장 분류 불일치

- 위치: [black_mirror_session.gd](../../../../../game/scripts/systems/black_mirror_session.gd) 51~63행, [basement_session.gd](../../../../../game/scripts/systems/basement_session.gd) 84~87행.
- 원인: C5 또는 J3 진행을 기준으로 3장으로 바꾸고, BasementSession에서 처리한 모든 대화를 4장으로 저장한다. 실제 세션은 D0~D4, D5·D6, E 관계 구간, F 구간과 엔딩까지 담당한다.
- 결과: 일지 복원 단계와 실제 챕터를 혼동한다. D0·관계 대사를 4장 필터에서 찾아야 한다.
- 대처: 클래스명이 아닌 **발화가 발생한 사건·노드의 장 정보**를 캡처한다. P는 프롤로그, A·B는 1장, C·J3·D0~D4는 2장, D5~E6은 3장, F0 이후는 4장으로 대응한다. 엔딩은 4장 안의 조건부 하위 분류로 둔다.
- 전환 주의: 사건 완료 후 상태가 다음 사건으로 바뀌어도 마지막 대사는 원래 사건에 남아야 한다. 재방문 대사는 최초 장소의 장이 아니라 실제 발화 사건에 귀속한다.
- 완료 조건: J3 마지막 대사, D4 결과, D5 첫 대사, E6 마지막 고지, F0 첫 대사의 분류를 개별 확인한다.

### NB-R04 / P1 / 일부 기록 오류가 전체 조회를 가림

- 위치: [dialogue_repository.gd](../../../../../game/scripts/systems/dialogue_repository.gd) 66~103행, [prologue_controller.gd](../../../../../game/scripts/prologue/prologue_controller.gd) 2131~2133행.
- 원인: 저장소는 유효 항목과 오류를 함께 반환하지만 UI는 `ok=false`이면 유효 항목을 표시하지 않고 종료한다.
- 발생 조건: 미등록 대사 ID, 잘못된 변수, 형식 오류 한 건이 정상 기록과 함께 있을 때. 유효 스냅샷이 로드된 뒤의 표시 오류도 포함한다.
- 대처: `일부 기록을 표시하지 못했습니다` 안내와 정상 목록을 함께 제공한다. 오류 건수·재시도와 진단 ID를 제공하되 원본을 자동 삭제하지 않는다. 스냅샷 자체가 손상된 경우의 저장 복구 절차는 우회하지 않는다.
- 완료 조건: 정상 2개+오류 1개 fixture에서 정상 2개는 읽을 수 있고, `기록 없음`으로 오표시하지 않는다.

### NB-R05 / P1(검증 차단) / 기존 회귀 테스트가 새 구조와 충돌

- 위치: [chapter_one_smoke.gd](../../../../../game/scripts/tests/chapter_one_smoke.gd) 360~367행.
- 확인: 테스트는 `_modal_body.get_child(2).get_child(0)`을 본문 Label로 가정한다. 새 UI의 2번 자식은 장 버튼 컨테이너이며 그 첫 자식은 Button이다. 정상 기록 조회 검증에서 잘못된 캐스팅이 발생하는 구조다. 부분 오류에서도 정상 내용을 보여야 한다는 기존 기대와 NB-R04가 충돌한다.
- 대처: 의미 있는 노드 이름 또는 조회용 인터페이스로 본문을 찾고, 기존 읽기 전용·정상 항목 보존 검증을 유지한다. 장 선택·미분류·기존 저장·빈 기록·한영·포커스 테스트를 추가한다.
- 한계: 이번 검토에서는 테스트를 실행하지 않았다. 위 결론은 코드의 노드 구성과 테스트 접근식 대조에 근거한다. 문서 CI 통과를 게임 UI 테스트 통과로 취급해서는 안 된다.

### NB-R06 / P2 / 재열람 위치와 최초 포커스 처리 미흡

- 위치: [prologue_controller.gd](../../../../../game/scripts/prologue/prologue_controller.gd) 2196~2248행, 2343~2346행.
- 확인: 매번 첫 번째 기록 있는 장을 선택하고 장 변경마다 스크롤을 0으로 되돌린다. 최초 포커스는 활성 여부와 관계없이 첫 장 버튼을 지정한다. 선택 표시에는 `button_pressed`를 쓰지만 토글 설정과 전용 선택 스타일은 보이지 않는다.
- 영향: 최신 대화 확인까지 반복 탐색이 필요하다. 프롤로그 기록이 없는 슬롯의 초기 포커스와 선택 장 표시는 런타임 확인이 필요하다. 전체 키보드 사용 불가로 단정하지 않는다.
- 대처: 슬롯별 마지막 필터·장·항목·스크롤 앵커를 기억한다. 메뉴의 대화 기록 첫 진입은 최신 대화, N키 첫 진입은 최근 단서로 구분한다(9.1절). 유효한 선택 버튼에 포커스를 두고, 없으면 목록 또는 닫기에 둔다. 선택 상태는 텍스트·아이콘·명시적 버튼 상태로 표시한다.

### NB-R07 / P2 / 원문 문자열 저장으로 구조적 검색·현재 언어 표시가 어려움

- 위치: [dialogue_history_writer.gd](../../../../../game/scripts/systems/dialogue_history_writer.gd) 4~14행, [chapter_one_session.gd](../../../../../game/scripts/systems/chapter_one_session.gd) 397~398행.
- 확인: 실제 화면 문장을 단일 `CH1_HISTORY_TRANSCRIPT`의 `variables.text`에 넣고, 화자는 모두 `SYSTEM`으로 두며 표시 이름을 변수에 저장한다. 사건 ID·실제 화자 ID·선택 ID가 기록에서 빠진다. 이 구조는 `7bb4b7e` 이전부터 존재한다.
- 영향: 현재 언어로 바꾸어도 저장 당시 본문은 번역되지 않는다. 화자·사건 필터와 단서 출처 연결을 정확히 만들기 어렵다.
- 정정(NB-P18): [basement_session_smoke.gd](../../../../../game/scripts/tests/basement_session_smoke.gd) 1772~1795행은 언어 변경 전후 **저장된 항목의 불변성**을 검사한다. 새 화면에서도 영어만 표시하라는 요구가 아니므로 ID 기반 현지화와 충돌하지 않는다. 실제 차이는 현행 문자열 저장 방식과 승인된 ID 저장 계약이다. 원본 보존 검사는 유지하고 현재 언어 렌더링 검사를 따로 추가한다.
- 대처: 새 기록은 원본 `line_id`, 안정적인 화자·선택·사건 ID, 선택 당시 분기 변수로 표시한다. 과거 transcript는 원문과 `당시 표시 언어`를 보존한다. 이전 문자열을 새 ID로 억지 변환하거나 현재 관계 상태로 과거 대사를 재생성하지 않는다.

### NB-R08 / P2 / 기록 상한·보호와 대용량 조회 계획 미구현

- 위치: [dialogue_history_writer.gd](../../../../../game/scripts/systems/dialogue_history_writer.gd) 7~22행, [prologue_controller.gd](../../../../../game/scripts/prologue/prologue_controller.gd) 2144~2149행·2237~2243행.
- 확인: 매번 전체 스냅샷을 설치·저장하고 모든 대화를 append한다. 2,000개 관리나 `protected` 구분이 없고, 조회는 전체 기록 렌더링·복제 후 장 본문을 하나의 Label로 합친다. 상한 부재는 기존 구조의 문제다.
- 위험: 장시간 반복 시 저장·조회 비용이 커진다. 이번 검토에서는 지연이나 메모리 수치를 측정하지 않았다.
- 대처: 먼저 보존 이유와 잘라내기 규칙을 확정하고, 50개 단위 페이지 조회·캐시를 도입한다. 저장 원자성은 유지한다. 성능을 이유로 내구성 있는 기록을 저장 전부터 성공 처리하지 않는다.
- 추가 의존성: [ending_gallery_pages.gd](../../../../../game/scripts/systems/ending_gallery_pages.gd) 76~84행은 과거 transcript의 실제 본문을 검색해 몸 재관찰 여부를 판단한다. prune 또는 ID 전환 전에 이 사실을 별도 영구 열람 상태로 옮겨야 갤러리 내용이 사라지지 않는다.

### NB-R09 / P2 / 장 메타데이터의 검증·이관 계약 누락

- 위치: [state_snapshot_validator.gd](../../../../../game/scripts/systems/state_snapshot_validator.gd) 98~130행, [dialogue_repository.gd](../../../../../game/scripts/systems/dialogue_repository.gd) 98행.

- 대처: 과거 누락 허용, 새 기록 enum 검증, 알 수 없는 값 보존·미분류 표시를 구분한다. 버전·북마크 같은 키를 UI에서 즉석으로 추가하지 않는다. 저장 schema·검증기·writer·fixture를 묶어 변경한다.
- 완료 조건: 구형 슬롯을 여러 번 불러와도 중복·삭제가 없고, 새 필드가 저장 검증 실패를 일으키지 않는다.

### NB-R10 / P2 / 수첩과 대화 기록의 탐색 단절

## 4. 권장 수첩 구성

### 4.1 정보 구조

상위 분류를 `단서 / 대화 / 기록 / 인물` 네 개로 묶는다. 현재 기획의 정보 구분은 아래처럼 하위 필터로 보존한다. 이 재배치는 제안이며 구현 전 문서 09·16과 메타 UI 계약을 동기화한다.

| 화면 | 제공 정보 | 기본 정렬·필터 |
| --- | --- | --- |
| 단서 | 관찰, 가설, 검증, 실패 원인, 다음 조사에 쓸 정보 | 최근 획득·내용 갱신순; 상태, 장소, 사건. 정보 수명 표시는 14.3절 공개 조건 적용 |
| 대화 | 실제 본 대사·표시된 질문·선택 결과 | 세션은 최신순, 세션 내 문장은 실제 순서; 공개된 장·사건·화자·반복 정보만 필터 제공 |
| 기록 | J1~J5, 연구 기록 원문, 진단·인증 자료 | 최근 획득·내용 갱신순; 일지/문서/시스템, 공개 출처, 확인한 복원 단계 |
| 인물 | 만난 인물, 공개된 발언·사건·연구원 기록 | 실제 만난 순서; 공개 정보만 표시 |

상단 공통 기능: `검색`, `최근 추가`, `책갈피`, `현재 조사 관련 자료`. 이 기능들을 추가 상위 탭으로 늘리지 않는다. 미획득 기록의 제목·개수·잠긴 항목은 기본적으로 노출하지 않는다.

`관찰/가설/검증/인증`은 정보의 상태이며, 화면 탭과는 다른 축이다. 출처 인증과 내용 검증도 별도 표시한다. 예: `시스템 출처 확인 / 원인 해석은 가설`.

### 4.2 기본 화면

```text
수첩                         검색 [             ]   책갈피   닫기
단서 | 대화 | 기록 | 인물
현재 조사 관련 자료     최근 추가     필터: 장 / 장소 / 출처

목록                                  상세
주방의 규칙적인 진동 [관찰][영구]       관찰 요약
손잡이를 왼쪽으로 돌린 기억 [관찰]      실제 들은 말 또는 읽은 원문
...                                   출처 / 장소 / 발견 사건
                                      연결 자료 / 책갈피 / 비교에 담기
```

- 단서는 `요약 → 원문 → 출처 → 관련 기록` 순서로 읽는다. 요약은 작성된 콘텐츠를 사용하고 원문에 없는 진실을 생성하지 않는다.
- 목록은 한 번에 50개 이하로 조회하고 `이전/다음 페이지` 버튼을 제공한다. 긴 본문만 독립 스크롤한다. 키보드 사용자를 위한 명시적 페이지 버튼을 유지한다.
- 큰 글자나 좁은 화면에서는 목록과 상세를 한 화면씩 전환하고 `목록으로`를 제공한다. 200%에서도 탭과 닫기 버튼이 화면 밖으로 밀리지 않는다.
- 최초 진입·재진입은 9.1절의 호출 경로별 정책을 따른다. 퍼즐에서 열면 관련 자료 바로가기를 강조하되 기존 필터를 무단 변경하지 않는다. 최근 열람순은 선택 정렬이며 조회 중 재정렬하지 않는다(6절).

### 4.3 대화 화면

1. 사건 발생 회차별 세션을 목록에서 선택한다. 제목·장소·인물·반복 라벨은 당시 및 현재 공개 범위 안에서만 표시한다(13.2·14.3절).
2. 해당 세션 안에서는 대사를 시간순으로 읽는다. `마지막으로 본 대사`, `이전 발언`, `다음 발언`으로 이동한다.
3. 실제 재청취는 같은 날이어도 새 발생 UID를 갖는다. 저장 재시도·재렌더링·수첩 재열람은 새 기록을 만들지 않는다. 접기 조건과 세션 경계는 13.2절을 따른다.
4. 화면에 제시된 질문과 실제 선택한 답을 구분한다. 선택하지 않은 답변·후속 대사는 생성하지 않는다. 표시된 선택지 원문을 보존하는 기존 동작은 정답 선택 기록과 혼동하지 않게 표시한다.
5. `관련 단서`를 누르면 같은 수첩 안의 해당 카드로 이동하고, 뒤로 가면 원래 대사와 스크롤 위치로 돌아온다.
6. `이전·미분류 기록`은 실제 미분류 기록이 있을 때 제공한다. 현재 장으로 재분류하지 않는다.

### 4.4 단서와 비교

- 단서 카드에는 제목, 사실 요약, 출처, 장소, 발견 순서, 정보 수명, 검증 수준, 원문 링크를 둔다.
- 영구 정보가 남아도 관련 물리 상태가 리셋됐다면 `기록은 유지 / 현장 상태는 초기화`로 구분한다. 과거 관찰 시점과 현재 상태를 섞지 않는다.
- 비교 자료 묶음에는 여러 개를 담고 동시에 두 개를 표시한다. 초기 권장 한도는 12개이며 B4/C5/D4 세 자료를 모두 담을 수 있어야 한다. 좌·우 자료 선택, 자리 교환, 제거 버튼을 제공하고 드래그는 보조 조작으로만 둔다. 묶음 저장과 원문 보호는 13.3절의 같은 슬롯 트랜잭션을 사용한다.
- 열람용 비교에서는 정오답 판정·배선 변경·일지 복원·인증이 발생하지 않는다. 기존 C3 양 비교나 F0 자료 중첩처럼 게임 판정이 있는 도구는 별도 사건 화면으로 돌아가 실행한다.
- 이번 범위는 **기존 가설 조회와 자료 고정**이다. 개인 자유 메모 작성은 제공하지 않으며 초안·삭제 복구 UI도 만들지 않는다. 주인공이 A1/SUBJECT 사건에서 직접 쓰는 행위는 별도 게임 입력으로 유지한다. 자료 고정이나 열람은 `verified`로 승격하지 않는다.
- 반증된 가설은 삭제하지 않고 `반증됨`과 당시 근거를 보존한다. 일반 필터에서는 접어 표시한다.

| 자료 유형 | 열람 기능 | 금지 사항 |
| --- | --- | --- |
| 텍스트·다중 페이지 문서 | 공개된 페이지 목록, 원문 스크롤, 출처 복귀 | 아직 안 본 뒷면·확장 본문을 페이지 수·검색으로 예고 |
| 이미지·A1 손글씨 | 확대/축소·이동·기본 위치, 획·압흔의 작성된 설명 | 그림만으로 단서 전달, 미래 해석을 대체 설명에 추가 |
| 벡터·파형·도면 | 단독 확대, 선/문양 범례, 공개 구간 텍스트 설명 | 정답선 자동 강조, 판정용 회전·중첩·배선 입력 |

확대와 이동은 뷰어 상태로만 저장한다. 버튼으로 모든 조작을 제공하고 키보드 이동은 자료 영역에 포커스가 있을 때만 소비한다. 200%·720p에서는 두 자료를 A/B 전환해서 볼 수 있게 하며 같은 두 선택을 유지한다. 수첩을 닫으면 기존 퍼즐의 미확정 회전·배선·재료량·선택을 원래대로 복귀시킨다.

## 6. 검색·신규·책갈피 규칙

### 검색

- 검색 범위는 **실제 표시했거나 사건 writer가 재열람 가능으로 확정한 segment**로 먼저 제한한 뒤 제목·본문·공개 출처명·공개 장소명에 적용한다(14절). 소지만 한 문서·처음 읽을 권한만 가진 뒷면은 검색 대상이 아니다.
- 현재 선택한 범위 안에서 검색하며 결과에 범위를 표시한다. 결과 없음 화면에서 `획득한 전체 기록에서 검색`을 별도 제공한다.
- 내부 ID, 미공개 연구원 실명, 미래 챕터 제목, 숨은 플래그는 검색·자동완성·결과 건수에 사용하지 않는다.
- 한글 IME 조합 중 Enter가 결과를 선택하거나 메뉴를 닫지 않는다. 조합 종료 후 약 200ms 지연 검색을 권장한다.
- 현재 언어의 정상 기록을 검색하되 과거 transcript는 원문 언어로도 검색할 수 있게 한다. 결과에는 `당시 한국어 기록`처럼 명시한다. 번역 불가를 기록 없음으로 처리하지 않는다.
- 공개된 원문 안에서만 검색하고 일치 위치로 이동한다. 정규식·자연어 답변 생성은 첫 구현 범위에 넣지 않는다.

### 목록 안정성

- 서로 다른 필터는 AND, 같은 필터 안의 다중 선택은 OR로 결합한다. 검색 기본 범위는 현재 상위 탭이다. 전체 검색 전환은 명시적으로 수행한다.
- 하나의 결과는 `(자료 UID, 내용 버전, segment)` 단위다. 단서 카드와 출처 대화는 별개 결과지만 같은 대화의 중복 링크는 건수를 늘리지 않는다.
- 조회 시작 시 `query_revision`과 정렬 키·UID 목록을 고정한다. 상세 읽기로 신규가 해제되거나 새 항목이 생겨도 현재 목록과 선택은 이동하지 않는다. 배지와 `새 기록 있음`만 갱신한다.
- 상세에서 목록으로 돌아오거나 새로고침할 때 목록을 갱신한다. 선택 UID가 없으면 기존 정렬 키의 다음 항목, 없으면 이전 항목, 모두 없으면 빈 상태의 필터 해제 버튼에 포커스를 둔다. 빈 마지막 페이지는 이전 유효 페이지로 보정한다.
- 앵커는 배열 인덱스가 아니라 UID·segment·본문 내 위치다. 페이지 경계는 안정적 정렬 키+UID 커서로 저장한다. 언어/검색/정렬 변경은 새 조회이며 존재하는 선택 UID는 유지하되 이전 캐시 건수를 재사용하지 않는다.

### 신규 표시

- 새 항목과 기존 항목의 정보 갱신을 구별한다. 단순 목록 진입으로 모두 읽음 처리하지 않는다.
- `신규`는 해당 항목 상세를 직접 열면 해제한다. 이는 편의용 열람 상태이며 실제 사건의 `observed`·`verified`·필수 읽기 판정과 다르다.
- 이미 공개된 원문의 UI 펼침 여부와 아직 읽지 않은 segment의 최초 공개 증거는 분리한다. UI의 신규 해제는 최초 공개·일지 복원·현실 수첩 필수 읽기를 대신하지 않는다.
- 본문이 갱신되면 갱신 revision을 기준으로 신규 표시를 다시 부여한다. 화면 전환이나 언어 변경으로 신규 알림을 반복 생성하지 않는다.

### 책갈피

- 단서 카드 또는 대화 한 줄을 고정하고, 출처로 바로 돌아갈 수 있게 한다. 책갈피는 슬롯 간 공유하지 않는다.
- 최대 50개를 초기 권장값으로 둔다. 초과 시 기존 책갈피를 해제할 수 있는 목록을 제공하고 조용히 제거하지 않는다.
- 책갈피가 가리키는 대화는 일반 기록 정리로 유실되지 않게 보호한다. 원본 기록은 복제하지 않고 namespace·불변 UID·내용 버전으로 참조한다. sequence는 정렬 전용이며 참조 키로 쓰지 않는다.
- 해제해도 일지·핵심 관계·최종 선택 등의 기본 보호 이유는 유지한다. 보호 이유를 여러 개 관리한다.
- 책갈피·보호 이유는 같은 슬롯의 원자 저장 대상이다. 성공 전 `저장 중`, 실패 시 `저장되지 않음 / 다시 시도`를 표시한다. 필터·스크롤·신규 배지만 비필수 편의 저장으로 분리한다(13.3절).

## 7. 데이터와 책임 분리 계획

아래 필드는 설계안이다. 현재 스냅샷에 즉시 추가할 수 있다는 뜻이 아니다.

| 데이터 | 권장 필드 | 담당·수명 |
| --- | --- | --- |
| 표시한 대화 | entry_uid, sequence, line_id, content_version, variant_id, speaker_id, event_id, node_id, chapter_id, occurrence/session ID, entry_kind, choice_id, viewed_locale, safe_variables, visible_segments, captured_text, protection_reasons | DialogueHistoryWriter 확장; 슬롯 영구. 상세는 13절 |
| 정보 항목 | knowledge_uid, knowledge_id, revision_uid, category, epistemic_state, provenance_state, typed_source_refs, content_version, lifetime, acquisition/disclosure 증거 | 기존 정보·사건 writer가 정본; 개정 이력 보존. 없는 과거 순서는 미상 |
| 고정 자료 | bookmark_refs, comparison_refs, protection_reasons, metadata_revision | 슬롯 원자 저장. 조회가 아니라 명시적인 기록 메타데이터 명령 |
| 열람 UI | last_section, filters, selected_uid, scroll_anchor, seen_revisions, view_transform | 슬롯·run·분기별 sidecar. 유실돼도 본문·권한·책갈피는 유실되지 않음 |

- `chapter_id`는 사건 표시 직전에 확정하며 컨트롤러 상속 구조에 의존하지 않는다. 장소명과 인물명은 당시 공개 수준을 함께 보존한다.
- `safe_variables`는 당시 공개된 대사 분기를 표시하는 허용목록 값이다. 관계 수치·숨은 의도·미래 이름을 통째로 캡처하지 않는다. 현재 관계 상태로 과거 내용을 다시 결정하지 않는다.
- 이미 있는 `knowledge_entries`, `failure_knowledge`, `event_history`를 다시 작성하는 중복 데이터베이스를 만들지 않는다. 기존 구조에서 조회용 카드로 변환하는 어댑터를 둔다.
- 새 `NotebookQuery`와 `NotebookPanel`은 제안 명칭이다. Query는 공개 범위 필터·페이지 조회만, Panel은 포커스·레이아웃만 담당한다. 기존 사건 writer는 최초 정보 공개를, 별도 기록 메타데이터 명령은 책갈피·비교 보존을 처리하되 모두 기존 StateWriter/SaveManager 직렬 트랜잭션을 사용한다.
- 장별 컨트롤러는 현재 사건과 취득 자료 참조만 전달한다. 프롤로그 컨트롤러를 모든 수첩 로직의 소유자로 계속 확장하지 않는다.
- UI 열람 상태는 저장 namespace·run·분기와 결합한다. 참조 존재뿐 아니라 UID·버전·공개 범위를 검증하며 다른 분기의 같은 sequence에 연결하지 않는다. 구체적 복원/복제 규칙은 13.1·15절을 따른다.
- 저장 실패 시 메모리의 편의 상태가 임시일 수 있음을 안내하고 진행·관계·퍼즐을 롤백하지 않는다. 반대로 실제 대사 영속 저장 실패의 기존 재시도·롤백 계약은 유지한다.

## 8. 보존·이관 정책

1. 구형 transcript는 삭제 없이 `legacy_snapshot` 읽기 경로로 제공한다. 언어·화자·사건을 알 수 없는 필드는 알 수 없음으로 남긴다.
2. 이미 저장된 잘못된 `chapter_id`도 사건 근거가 없으면 자동 수정하지 않는다. `전체`에서 접근을 보장하고 기존 분류가 미확인임을 표시한다. 새 기록부터 정확한 사건 매핑을 적용한다.
3. 현재 상태는 기본 runtime schema 1이고 기록 컨테이너에 exact-key 제약이 있다. 저장 컨테이너·마이그레이터·validator·백업 복구를 동시에 설계한 뒤 새 스키마 버전을 확정한다. 보기 UI만 바꾸는 단계는 저장 schema를 변경하지 않는다.
4. 사용자 승인 정책은 **보호 이유 없는 normal 최근 2,000개를 별도로 유지**한다. 보호·기존 미분류는 이 숫자에서 제외하고 별도 목록/페이지로 모두 보존한다. 전체 합계 2,000개 계약과의 차이는 DEC-0012 및 12절에 명시하며, 코드 적용 전 정본을 동기화한다.
5. 과거 기록은 이관 후에도 일괄 normal로 변경하지 않는다. 단순히 신형 schema로 변환했다는 이유로 미분류 기록을 prune하지 않는다. 새 normal만 순번 오름차순으로 정리하며 실패·출처·핀 등 보호 이유의 합집합을 우선 계산한다.
6. 중요한 단서 원문·인증 근거는 일반 대화 보존 한도와 독립적으로 남는다. 일반 기록 정리는 퍼즐 진행 가능성을 줄이지 않는다.
7. 갤러리의 본문 검색 의존(NB-R08)을 영구 열람 증거로 이관한다. 로그가 정리돼도 이미 본 엔딩 장면이 사라지지 않아야 한다.
8. 동일 대사의 실제 재청취와 같은 화면 재렌더링을 구분한다. 전자는 새 순번, 후자는 중복 append 금지다.

9. 예: normal 2,001 + protected 2,001 + legacy 10,000개라면 보호 없는 가장 오래된 normal 한 건만 정리한다. normal의 보호 승격은 일반 창의 가용량을 늘리며, 마지막 보호 해제 후에는 최신 normal 2,000개 기준에 따라 다음 정리 트랜잭션에서 오래된 항목이 제거될 수 있다. 해제 UI는 이 가능성을 알린다.
10. 순번과 UID를 재배정하지 않는다. 보존 이유 추가·해제·새 대사 기록·prune는 같은 슬롯 잠금을 거쳐 직렬화한다. 공간 부족은 저장 실패와 재시도로 드러내며 보호·legacy를 조용히 삭제하거나 성공 처리하지 않는다.
11. `별도 보관`은 우선 논리적 분류·페이지 조회를 뜻한다. 첫 이행은 기존 단일 스냅샷 원자 저장을 유지하며 별도 비내구 캐시에 본문을 옮기지 않는다. 17절 대량 성능 인수에 실패하면 출시를 보류하고 저장 구조 분할을 별도 설계한다. 성능 문제를 기록 폐기로 해결하지 않는다.
12. 개수의 단위는 저장된 관찰 entry다. 한 줄 대사는 한 건, 한 번 표시한 선택지 묶음은 한 건, 선택 확정은 별도 한 건이다. 보호 entry는 모두 일반 창에서 제외한다. 세션 제목/출처 메타는 남은 entry가 있으면 유지하고, 일반 대사가 일부 정리된 세션에는 해당 사실을 표시한다. 남은 선택 결과가 인용하는 질문·선택지 원문에는 출처 보호를 적용한다.

### 9.2 입력 소비와 중단 경계

- 기존 N키 재지정과 화면 수첩 버튼을 모두 지원한다. 메뉴의 `대화 기록`은 같은 화면의 대화 탭으로 바로 진입한다.
- Tab/Shift+Tab은 활성 컨트롤만 순환한다. Enter/Space로 확정하고, PgUp/PgDn은 현재 본문을 스크롤한다. 방향키 사용은 텍스트 입력·IME와 충돌하지 않도록 영역별로 처리한다.
- 입력은 IME 조합/텍스트 편집 → 최상위 팝업·확대 뷰어 → 링크 상세/비교의 복귀 스택 → 검색 해제 → 수첩 → 호출 화면 순으로 한 계층만 소비한다. Esc로 IME를 취소한 프레임은 다른 계층에 전달하지 않는다. 상세에서 목록 복귀를 먼저 처리하고 다음 Esc로 검색을 해제한다. 검색에 포커스가 있으면 편집 취소가 우선이다.
- 검색창 n/N은 문자다. 텍스트 편집 중 N 단축키를 실행하지 않는다. 편집 밖 N은 최상위 수첩에서만 닫기로 동작한다. Enter/Space/Esc의 동일 press와 release를 복귀 화면에 전파하지 않으며 IME 확정 뒤 새 입력이 있어야 결과를 연다.
- 대화·선택 중 조회 허용은 확장 단계에서 도입한다. 대사 인덱스·선택 포커스·선택 미확정 상태를 캡처하고 읽기 중 자동 진행을 정지한다. 닫기의 Enter가 원래 선택으로 전파되지 않게 한다.
- 원자 저장·장면 전환 중에는 완료 직후 열거나 사용 불가 이유를 짧게 안내한다. 큐에 남은 열기 요청이 새 슬롯에 실행되면 안 된다.
- B2 타이머는 현재도 모달이 열리면 퇴장 처리를 미루지만 남은 시간을 정확히 동결하는 구조는 아니다. 통합 수첩에서는 입력·타이머·음향 정지 사유를 별도로 보존하고 원래 상태로 복귀시킨다.
- 화면 포커스 상실·복귀가 이미 걸린 수첩 일시정지를 해제하면 안 된다. 선택·타이머·UI 잠금 각각의 사유를 함께 검사한다.
- 색 제거 모드에서도 출처명·문양·선 패턴이 남는다. 감각 효과는 장식이며 텍스트 본문은 흔들리거나 점멸하지 않는다.
- 1280×720 및 1920×1080, 100/150/200% 글자, 한국어·영어에서 버튼 겹침·본문 잘림을 검사한다. 화면 읽기 지원은 실제 엔진·보조기기 연결을 테스트한 뒤 지원 범위를 선언한다.

| D5 파열·관찰 필수 연출 | 현재 연출의 안전 경계 이후 허용 | 필수 관찰을 스킵하지 않음. 별도 접근성 일시정지를 차단하지 않음 |
| EDC 최종 확인 | 자료 열람 가능, 결정 저장 중은 대기 | reality/stay 어느 쪽도 미리 선택하지 않음 |
| 현실 수첩·엔딩 | 현장 열람과 과거 조회 분리 | 메뉴에서 field_read/필수 조사/엔딩 해금 불변 |

일시정지 사유는 집합으로 관리한다. 수첩을 닫아도 Alt+Tab·다른 모달의 정지는 남는다. 효과음 재생을 과거 조사 이벤트처럼 다시 발생시키지 않으며, 오디오 복귀도 기존 메뉴 일시정지 계약을 따른다. UI 전체 문자열은 번역하고 직접 화면 읽기 지원은 제품 1.0 필수가 아닌 별도 검증 항목으로 남긴다.

## 13. 식별·내용 버전·저장 책임

### 13.1 불변 식별과 조회 범위 (NB-P02)

| 개념 | 제안 계약 |
| --- | --- |
| `entry_uid` | 실제 관찰 한 건의 128-bit 무작위 불변 ID. 번역·정렬·재로드·이관 재시도로 재발급하지 않음 |
| `sequence` | 해당 기록 계통 안의 표시 순서. 과거 복귀 시 숫자가 재사용될 수 있으므로 참조 키·중복 방지 키로 쓰지 않음 |
| `source_origin_id` | 원 기록 계통 식별. 새 게임에서 발급, demo import/보관본/분기 복제는 원 관찰의 출처값 보존 |
| `branch_id` | 새로운 게임 분기 식별. F3 재선택·과거 백업 복귀·다른 슬롯 복제 시 새 값, 기존 관찰 UID는 보존 |
| 조회 scope | 저장 namespace(`demo/full/development/gallery`) + 슬롯 또는 보관본 ID + run_id + branch_id. 현재 scope의 snapshot에 실제 포함된 UID만 조회 |
| `load_epoch` | 로드·슬롯 전환마다 증가하는 런타임 취소 토큰. 이전 검색·예약 열기·저장 callback을 새 화면에 적용하지 않음 |
| 영구 참조 | `{kind, source_origin_id, uid, content_version, segment_id}`. 종류는 dialogue/knowledge/document/hint 등이며 sequence만으로 대체 탐색하지 않음 |

- 한 줄을 실제 표시하기 직전에 UID·발생 정보와 `presentation_token`을 만들고 저장 성공까지 같은 토큰을 재사용한다. writer는 토큰의 기존 커밋을 확인해 중복 append를 막는다. 화면 재그리기나 실패 후 같은 저장 재시도는 새로운 관찰이 아니다.
- 중간 저장에는 진행 중 발생/세션과 마지막 표시 토큰을 포함한다. 앱 재시작 후 같은 줄 재개는 이어 쓰고, 이전 선택 지점에서 새 답을 실행한 경우만 새 관찰 UID를 만든다.
- 기존 UID를 가진 entry는 새 슬롯에 복제해도 내용이 같은 관찰이다. 다만 참조는 현재 scope의 포함 여부와 공개 증거를 다시 검사하므로 원본 슬롯의 미래 기록에 접근하지 못한다.
- UI sidecar는 scope별로 분리한다. 과거 로드·분기 복제에서는 미리 읽었던 배지·검색·비교 표시 상태를 가져오지 않는 것을 기본으로 하고, 본 snapshot에 저장된 책갈피/비교 참조만 검증 후 유지한다.
- 기존 run_id가 없는 구형 원본은 이관 매니페스트에 원본 해시와 source_origin_id를 고정한다. legacy UID는 해당 출처+원 배열 위치+원 sequence+정규화한 원 항목 해시로 결정한다. 같은 원본 재이관은 같은 매핑, 서로 다른 백업은 증명된 공통 매핑이 없으면 별도 출처로 취급한다. 비슷한 본문을 근거로 합치지 않는다.
- 알 수 없는 참조는 `이 저장에서 확인할 수 없는 기록`으로 표시한다. 다른 분기의 같은 sequence나 최신 내용으로 연결하지 않는다. 새 게임·삭제는 다른 슬롯의 원본이나 갤러리를 삭제하지 않는다.

### 13.2 사건 회차와 내용 이력 (NB-P06·P07·P18)

| 필드 | 생성·유지 규칙 |
| --- | --- |
| `event_occurrence_id` | 사건 진입/재발생 때 생성. 같은 날 재방문도 별도 발생. 장면 재렌더링·저장 재시도는 동일 값 |
| `conversation_session_id` | 연속 대화 시작에서 생성. 메뉴·수첩 일시정지는 세션 유지. 대화 종료 뒤 다른 조사/힌트/대화는 별도 세션 |
| `entry_kind` | dialogue, options_presented, choice_confirmed, choice_cancelled, document_segment, hint_revealed. 취소는 실제 기록 대상 취소가 발생한 경우만 저장 |
| `line_id + content_version + variant_id` | 당시 표현의 의미·분기 고정. line_id만으로 현재 관계 분기를 재계산하지 않음 |
| `visible_segments / safe_variables` | 실제 공개한 segment/선택지 ID와 공개된 치환값만 저장. 숨은 선택지·관계 수치·개발 표시명 제외 |
| `captured_text / viewed_locale` | 표시한 공개 본문의 안전한 fallback. 새 ID 기록도 당시 버전이 없을 때만 사용하며 정본 의미를 대체하지 않음 |
| `knowledge revision` | 같은 카드 갱신은 새 revision_uid와 source_refs로 추가. 최신 요약과 과거 원문을 분리하고 이전 기록을 덮어쓰지 않음 |

반복 접기는 완료된 세션의 line/version/variant·공개 segment·표시 질문·확정/취소 결과·안전 변수의 의미가 모두 같은 경우에만 허용한다. 서로 다른 답, 다른 관계 반응, 새 힌트가 있으면 접지 않는다. 접기는 조회 표현일 뿐 저장 삭제나 횟수 합산 저장이 아니다. 발생별 출처와 실제 순서를 펼칠 수 있어야 한다.

의미가 바뀐 문장은 새 ID 또는 content_version을 발급하고 구버전을 함께 배포한다. 맞춤법·동일 의미 번역 교정은 번역 담당의 호환 판정표에 기록한 경우만 같은 의미 버전으로 제공한다. 현재 언어 번역이 없으면 당시 원문과 언어를 표시한다. 구버전·원문 모두 없으면 `보관된 본문을 표시할 수 없음`과 진단 정보를 보여 주고 최신의 더 자세한 본문을 대신 넣지 않는다.

J1~J5는 현재 복원 단계의 최신 단일 문자열로 과거를 재구성하지 않는다. 단계별 관찰·일지 revision을 고정하고 F1에서 확인한 편집 이력은 새 출처 주석으로 연결한다. 과거에 연구원 실명이 안 보였다면 당시 원문은 표면 이름을 유지하고, 현재 공개된 인물 카드 링크만 추가할 수 있다.

원본 불변 테스트는 언어 변경 전후 저장된 UID·변수·원문·공개 segment의 동등성을 계속 확인한다. 현재 언어 조회 테스트는 그와 별도로 수행한다. legacy 원문을 새 번역문으로 덮어쓰거나 원문 보존 테스트를 삭제하지 않는다.

### 13.3 쓰기 권한과 저장 실패 (NB-P01)

| 동작 | 소유자 | 영구 변경 가능 범위 | 실패 시 |
| --- | --- | --- | --- |
| 검색·페이지·재열람·확대 | NotebookQuery/Panel | 없음. sidecar의 필터·앵커·신규 배지만 변경 | 편의 위치 미저장 안내, 본문·진행 유지 |
| 책갈피/비교 자료 추가·제거 | 기록 메타데이터 명령 → 기존 StateWriter/SaveManager | 참조 목록·보호 이유·메타 revision만 | 성공 표시 금지, 동일 명령 재시도 |
| 대사 최초 표시 기록 | DialogueHistoryWriter | 공개 관찰·발생/세션·순번·보호 메타 | 기존 저장 실패 복구와 다음 대사 차단 유지 |
| 문서/힌트 최초 공개 | 해당 사건/정보 writer | 공개 증거·자료 revision·필요한 기록 | 공개 성공·신규 획득으로 확정하지 않고 재시도 |
| 필수 조사·복원·인증 | 본편 사건 writer | 해당 사건이 명시한 게임 상태 | 기존 게임 규칙. 수첩 Query에서는 호출 금지 |

책갈피·비교 추가는 `명령 생성 → 슬롯 잠금과 현재 revision 확인 → 공개 대상 검증 → 참조+보호 이유 함께 추가 → 전체 후보 snapshot 검증 → 원자 저장 → 성공 UI` 순이다. 오래된 revision이면 현재 snapshot에서 의도를 재검증하며 이전 snapshot 전체를 덮어쓰지 않는다. 해제도 같은 절차로 해당 보호 이유만 제거한다.

저장 중에는 해당 버튼에 `저장 중`을 표시하고 중복 명령을 막는다. 실패하면 기존 커밋 상태로 되돌리고 `저장되지 않음 / 다시 시도`를 보여 준다. 명령 ID로 중복을 판별하며 결과가 불명확하면 디스크의 커밋 여부를 확인한 뒤 재시도한다. 슬롯 전환 시 미완료 명령은 해결하거나 명시적으로 취소하고 다른 슬롯에 재실행하지 않는다.

prune는 동일 잠금 안에서 확정된 보호 이유의 합집합을 다시 계산한다. 저장 대기 중 메모리 핀을 이미 저장된 핀처럼 취급하지 않는다. 일반 저장 실패 때문에 최신 게임 진행 전체를 과거 메타 snapshot으로 롤백하지 않으며, 기존 writer의 실패 복구는 **자신이 설치한 revision**에만 적용한다.

NB-Q08에서는 조회에 snapshot 전체 동등성을, 고정 명령에는 변경 경로 허용목록을 검사한다. 허용목록 밖의 물리 상태·관계·진행·힌트 공개·최종 선택·field_read가 바뀌면 실패다.

### 13.4 출처와 보존 이유 (NB-P05)

| 참조 소비자 | 보호 방법 | 제거·복귀 시 |
| --- | --- | --- |
| 단서·실패·반증된 가설 | 인용 entry에 `knowledge_source:<revision_uid>` | 반증됐어도 이전 근거 보존. 단순 UI 숨김으로 보호 해제 금지 |
| 인물 카드·연구원 기록 | `person_source:<revision_uid>` 또는 배포된 document 버전+공개 증거 | 미고백 의도는 링크 자체 생성 금지 |
| 일지·파형·인증 자료 | 영구 콘텐츠 버전+취득/표시 증거. 대화 인용 부분은 추가 보호 | 물리 리셋과 독립, 옛 버전 보존 |
| 책갈피·비교 묶음 | 각각 `bookmark:<id>`, `comparison:<id>` | 명시적 제거가 성공하면 해당 이유만 제거 |
| 갤러리 | 보관본 snapshot과 본문 증거를 자기 완결적으로 보존 | 현재 슬롯 prune에 의존하지 않음 |
| 열람 중 상세·뒤로가기 | 런타임 조회 lease 또는 고정 조회 snapshot | 창이 열린 동안 정리 안내로 갑자기 교체하지 않음. 앱 종료 후 지속 보존은 보장하지 않음 |

prune 전 역참조 검사를 수행하고 durable 참조가 남은 항목은 삭제 후보에서 제외한다. 배포 콘텐츠 문서는 본문 버전과 공개 증거를 함께 조회한다. 자산 경로만 알면 누구나 읽는 공용 링크로 만들지 않는다. 필수 자료의 누락은 진단 오류이며 퍼즐을 해결한 것으로 우회하지 않는다.

정말 정리된 비필수 일반 대사의 낡은 UI 앵커는 `보존 기간이 지난 일반 기록`으로 안내한다. 제목·본문을 몰래 복원하거나 같은 순번에 연결하지 않는다. UI 앵커만을 영구 보호 이유로 삼아 모든 일반 대사가 보호되는 부작용도 피한다.

### 14.1 다섯 상태의 분리 (NB-P04)

| --- | --- | --- |
| acquired | 물건/자료를 얻음 | 이미 공개된 제목·표지 정보까지만. 모든 본문 열람 권한 아님 |

### 14.2 최초 읽기와 재열람 계약

이번 범위의 수첩은 **재열람 전용**으로 시작한다. 처음 조사할 문서는 기존 현장/사건 화면으로 돌아가 읽는다. 수첩 안에서 처음 읽어야 하는 예외를 추후 추가하려면 segment별 `first_read_owner`·허용 상태 변경·실패 복구를 생산자 매핑에 등록해야 한다. 단순 상세 버튼을 사건 완료 함수에 직접 연결하지 않는다.

| 예시 | 최초 공개 소유자 | 재열람 한계 |
| --- | --- | --- |
| 일반 문서 앞/뒷면 | 현장 조사 action | 앞면만 표시했다면 뒷면 텍스트·이미지·페이지 수·스니펫 숨김 |
| J1~J5 복원 | 단계별 일지 사건 | 확인한 조각/revision만. 수첩에서 배열 완료나 다음 복원 처리 금지 |
| 인물 관계 기록 | 해당 관계 사건의 발언·기록 획득 | 현재 bond/alert로 새 대사 생성 금지. 이리스 미고백 내용 추측 금지 |
| A1·F0-E 자기 작성 | 기존 자기 작성/인증 사건 | 실제 쓴 내용만 조회. 비교·핀으로 입력 확정하지 않음 |
| 현실 물리 수첩 | field_notebook의 현장 action·다음 색인 | 표시한 페이지/확장만 조회. field_read·FIELD_FINISH 해금 금지 |
| 갤러리 | 선택한 엔딩의 보관 snapshot | 다른 엔딩/현재 슬롯에만 있는 사실을 병합하지 않음 |

최초 표시가 저장 실패한 경우 다음 조사·페이지 진행을 기존 복구 규칙에 맞춰 멈추고 재시도한다. 화면을 봤지만 저장되지 않은 내용을 영구 보관 완료라고 표시하지 않는다. 그 사실의 기록 재시도와 게임 조사 완료 명령은 구분해 중복 보상을 막는다.

| 진행 증거 | 허용 라벨 | 숨길 라벨 |
| --- | --- | --- |

필터에는 현재 공개 가능한 기록이 있는 장/인물/장소만 표시한다. 전체 장 수와 미래 빈 탭은 노출하지 않는다. 실제 화자 ID는 내부 정렬용이고 표시는 별도 disclosure 정책을 통과한다. 과거 세션의 당시 이름은 바꾸지 않고 현재 알려진 인물로 연결되는 라벨은 별도로 구별한다. legacy의 잘못된 chapter를 확신할 수 없으면 미분류로 접근시키되 원 필드는 보존한다.

### 14.4 단계형 힌트 (NB-P10)

H1~H5의 첫 공개는 해당 퍼즐의 명시적 `다음 생각 정리 읽기` action이 맡는다. `(puzzle_id, hint_content_version, stage)`별로 실제 요청한 최대 단계와 각 segment의 공개 증거를 저장한다. 표시 전 더 높은 단계 본문을 검색 색인이나 추천에 넣지 않는다.

수첩의 `도움 기록`은 이미 공개한 힌트만 제공한다. 다음 단계가 필요하면 기존 퍼즐의 요청 UI로 돌아가고, 수첩 재열람은 요청 횟수·진행·관계를 바꾸지 않는다. 저장 실패는 같은 공개 명령으로 재시도하며 높은 단계로 건너뛰지 않는다. H1만 본 슬롯은 재로드/검색/언어 변경 뒤에도 H1만 재열람할 수 있어야 한다. 기존 힌트 문구/단계 자체는 이번 계획에서 바꾸지 않는다.

## 15. 저장 형식별 이관과 복구 (NB-P03)

현재 `SCHEMA_VERSION=1`, `DESIGN_REVISION=v0.4-state-r12`와 exact-key 검증을 그대로 둔 채 UI에서 임의 키를 추가하지 않는다. 구현 2단계에서 새 runtime schema/기록 컨테이너 버전/validator/fixture를 같은 변경으로 발급한다. 설계상 필드 이름을 배포 버전으로 오인하지 않는다.

공통 절차:

1. 입력 형식을 먼저 식별하고 해당 구형 규칙으로 **원본 직렬화 checksum과 헤더**를 검증한다. JSON을 재직렬화한 뒤 구형 checksum을 비교하지 않는다.
2. 검증된 원본 바이트와 해시·버전·이관 매핑을 보존한다. 원본을 in-place 변환하지 않는다. 서로 다른 형식의 손상 데이터를 강제로 progress로 해석하지 않는다.
3. 복사본에 결정적 UID·legacy 래퍼·공개된 증거만 추가한다. 없는 과거 화자·사건·발견일·일지 이력을 만들어내지 않는다. 현재 진행도를 과거 공개 증거로 사용하지 않는다.
4. 신형 구조·참조·유일성·공개 범위를 검증하고 새 checksum을 계산한다. 저장 공간/권한 실패는 원본에 영향 없이 종료한다.
5. 기존 원자 저장 방식으로 후보를 승격한다. 기존 `.bak` 외에 이관 전 백업을 보존해 다음 정상 저장으로 덮어쓰지 않는다. 미완료 임시 파일은 커밋 증거가 없으면 무시한다.
6. 이관 후 재읽기·검증이 끝난 시점에 완료 처리한다. 같은 원본+마이그레이터 버전 재실행은 같은 관찰 매핑이며 본문/순번/UID 중복이 없어야 한다.

| 입력/진입 경로 | 처리 | 반드시 보존·검사할 것 |
| --- | --- | --- |
| 현재 progress | 구형 검증 → 사본 변환 → 신형 검증 → 원자 승격 | 새 일반 창 정책 적용 전 legacy 보호. 현재 run 유지 |
| progress backup | 별도 구형 reader로 검증. 복원 선택 시 새 branch로 승격 | 손상된 현재 파일과 합치지 않음. 미래 분기 sidecar 가져오지 않음 |
| F3 재선택 `.json/.bak/.tmp` | 커밋된 재선택 원본만 이관, 사용 시 새 branch 생성 | 최종 결정 전 상태·권한 보존, 후속 엔딩 기록 역유입 금지, tmp 단독 채택 금지 |
| demo → full import | demo 원본 보존, 변환한 사본을 빈 full 슬롯에 저장 | 저장 namespace 분리, 원 관찰 UID/출처 보존, full의 새로운 분기/대상 정보 명시 |
| 엔딩 갤러리 | 원 payload/checksum/hash 파일명 그대로, 구형 snapshot의 읽기 어댑터로 조회 | 파일 ID·기존 메타 참조 불변. 조회 시 원 파일 덮어쓰기 금지 |
| 개발 체크포인트 | `developer_checkpoints` 데이터/fixture 버전을 명시하고 development scope로 변환 | 실제 플레이/갤러리와 격리. 개발용 지름길을 본편 취득 증거로 수입 금지 |
| 미래 schema/알 수 없는 design revision | 지원 버전 안내 후 거부, 원본 바이트 그대로 보존 | 새 게임으로 덮어쓰기·버전 숫자만 낮추기 금지 |

갤러리는 이번 설계에서 **불변 원본+읽기 어댑터**를 채택한다. 캐시는 payload hash·adapter 버전·locale·공개 정책 버전으로 구분하며 언제든 재생성할 수 있다. 갤러리 현재 언어 표시는 보관 당시 variant와 공개 증거만 사용한다.

기존 `_body_repeat_seen`의 raw transcript 검색은 이관 시 해당 원본에서 명확히 증명되는 재관찰만 `observed_fact`로 추출한다. 새 기록은 관찰 action에서 사실을 함께 저장한다. 증거가 불명확한 legacy는 raw 원문 어댑터를 유지하고 새 사실을 추정하지 않는다. 이 의존성을 제거하기 전에 관련 원문을 prune하지 않는다.

시험은 각 행마다 정상·누락 선택 필드·잘못된 checksum·반복 실행·변환 중 종료·용량 부족을 포함한다. 현재/백업 모두 손상되면 `기록 없음`으로 위장하지 않고 기존 복구 UI로 연결한다. 새 schema 이후 구형 실행 파일 사용에는 명확한 호환 불가 고지를 둔다.

## 16. 기록 생산자와 콘텐츠 공급 범위 (NB-P15)

### 16.1 대응표 작성 규격

다음은 **생산자 경로 단위의 조사표**다. 신규 문장별 ID 발급·번역·카드 원고 제작을 완료했다는 뜻이 아니다. 개발자는 각 경로의 실제 표시 호출을 등록하고, 기획은 공개 segment·요약·보존 이유를, 번역 담당은 의미 버전/한영 키를 검수한다. 한 문자열을 역검색해 문장 ID나 과거 장소를 추측하지 않는다.

구현 2단계의 매핑 행 필수 필드:

`producer_id / source_file:callsite / event_id / node_id / action_or_variant / content_id / content_version / speaker_id / location_source / entry_kind / disclosure_owner / visible_segment_ids / knowledge_ref / protection_reasons / localization_key / mapping_status / owner`

`mapping_status`는 `AUTHORED_ID`, `LEGACY_SNAPSHOT`, `EXCLUDED_UI` 중 하나다. 새 본편 기록은 `AUTHORED_ID`가 원칙이며 구형 이관만 `LEGACY_SNAPSHOT`을 허용한다. 버튼 글자·설정 안내처럼 기록하지 않을 UI는 제외 이유를 남긴다. raw 문장이 필요한 과도기 예외는 명시적으로 등록하고 최종 인수 전 해소한다.

### 16.3 누락 검출과 담당 산출물

- 정적 검사: 모든 history writer 호출, `_note`/notebook 직접 쓰기, 힌트/문서 표시, 선택 모달, 갤러리 소비 경로를 위 생산자와 대조한다. 해당 함수명 검색만으로 완전성을 주장하지 않고 실제 호출 연결과 직접 데이터 쓰기도 확인한다.
- 실행 검사: 프롤로그~두 엔딩, 관계 미완료/완료, 실패/리셋, 모든 힌트 단계에서 발생한 `(producer, node, variant, segment)`를 매핑과 대조한다. 미실행 분기는 `NOT_COVERED`, 누락은 `UNMAPPED`로 보고한다.
- 출력: 생산자 수, 작성 ID 수, legacy 수, 의도적 제외 수, 미매핑 수, 미실행 분기 수, ko/en 누락 수를 구분한다. 현 문서의 22개 그룹을 문장 매핑 100% 완료 수치로 쓰지 않는다.
- 새 코드/콘텐츠가 ID·공개 소유자·보존 등급 없이 기록 writer를 호출하면 개발 검증에서 실패시킨다. 최종 인수에서는 신규 미매핑 0, 필수 분기 미실행 0, 내부 ID 화면 노출 0을 요구한다.
- 콘텐츠 산출물: 공개 범위별 제목/요약, 문서 앞뒤/단계별 본문, 이미지 대체 설명, 출처 라벨, 힌트 ID, 의미 변경 이력. 엔진 담당 산출물: 관찰 컨텍스트·스키마·검증기. QA 산출물: 경로별 커버리지/보존/누출 결과.

## 17. 성능과 접근성 측정 계약 (NB-P17)

### 17.1 조회 순서와 캐시

`활성 scope·snapshot 확인 → 공개 segment 필터 → 최소 메타 색인 → 검색/정렬 UID 선택 → 최대 50개 행의 표시 문자열 → 선택 상세 본문` 순으로 처리한다. 기존 `render_history`로 전량 번역·복제한 뒤 50개만 그리는 구현은 인수 실패다. 검색 색인은 공개된 segment만 점진적으로 생성하고 색인 준비 중임을 알린다. 준비되지 않은 결과를 `없음`이라고 단정하지 않는다.

캐시 키에는 namespace/run/branch/load_epoch·snapshot 기록 revision·locale·콘텐츠 버전·공개 정책 revision·query 조건이 포함된다. 슬롯 전환·로드·언어 변경·내용/공개 범위 변경은 영향받은 캐시를 무효화하고 비동기 결과도 키가 맞을 때만 적용한다. 표시 이름과 검색 키워드에 숨은 값이 남지 않도록 원문 접근 전에 공개 필터를 적용한다.

큰 이미지와 전체 본문은 선택한 자료만 로드하고 비교 동시 표시 두 개 외에는 썸네일/메타만 유지한다. sidecar 손상은 기본 UI 위치로 복귀하고 본문/핀은 슬롯에서 재구성한다. 첫 단일 snapshot 구현에서 파싱·복제·저장 비용도 계측하며 저장 파일 분할이 필요하면 별도 설계/이관 검증 없이 도입하지 않는다.

정확한 입력 fixture는 고정 seed·본문 바이트 수·내용 해시와 함께 저장하고 시험마다 같게 사용한다. 숨은 뒷면 키워드와 H2~H5를 검사 미끼로 포함하되 공개 색인에는 없어야 한다. 32KiB는 시험 부하이며 콘텐츠 제작 한도나 숨은 원문 잘라내기 기준이 아니다.

### 17.3 측정 방법과 잠정 합격선

[Windows 성능 예산](../../../../../docs/technical_performance_budget.md)의 LOW-IGPU/LOW-DGPU/MID/HIGH-DPI 역할과 실제 CPU/GPU/RAM/SSD·드라이버·Windows·Godot/export/renderer/commit을 함께 기록한다. 장비가 없으면 `NOT_COVERED`다. 아래는 측정 전 예산이며 통과 결과가 아니다.

| 지표 | MID 잠정 목표 | LOW 잠정 목표 | 측정 경계 |
| --- | ---: | ---: | --- |
| 수첩 냉간 첫 화면 | p95 200ms | p95 400ms | 게임 snapshot 로드 완료 후 수첩 입력부터 첫 유효 목록·포커스. 별도로 앱/슬롯 로드 시간 기록 |
| 웜 페이지/필터 | p95 100ms | p95 150ms | 입력부터 안정된 목록과 포커스 |
| 검색 | p95 400ms | p95 600ms | 조합 종료 이후 입력부터 검색 완료; 200ms debounce 포함, 최초 색인 비용도 포함 |
| 입력 포커스 | 100ms | 150ms | 기존 성능 예산과 동일. 250ms 이상은 P1 |
| 저장 커밋 | 300ms | 750ms | 실제 영속 성공까지. 비동기 진행 표시, UI 1초 정지는 P1 |
| 전체 RAM peak | 1.5GB | 2GB | 기존 게임+수첩 합계. 수첩 열기 전/최대/닫은 뒤 증분도 별도 보고 |

각 fixture·locale·장비 조합에서 프로세스 재시작으로 cold 20회, 동일 프로세스 warm 100회 계측한다. 운영체제 디스크 캐시까지 비웠는지는 별도로 기록한다. p95는 정렬한 값의 `ceil(0.95*n)`번째 값으로 보고하고 평균·최대·첫 회도 남긴다. 검색은 일치/불일치/긴 한글·영어/권한 없는 키워드로 나눠 잰다. 로드·색인·번역·레이아웃·저장 구간을 분리 계측한다.

50회 열고 닫기 뒤 캐시 상한과 메모리 회수를 확인하고 60초 입력 프레임 캡처·Alt+Tab 5회를 수행한다. 큰 fixture에서 목표를 초과하면 오류/계층/구간을 명시하고 출시 차단 또는 근거 있는 예산 개정을 결정한다. 예산을 맞추기 위해 내구성·미분류 보존을 낮추지 않는다.

접근성은 실제 720p/1080p, Windows 배율과 게임 글자 100/150/200%, ko/en, 마우스 전용·키보드 전용·색 제거로 검사한다. 확대/자료 교체/책갈피 오류/검색/복귀까지 포함한다. 화면 읽기 직접 지원은 별도 지원 여부가 확정되기 전 성공으로 표기하지 않는다.
