## 2. 재현과 수정

[ResetCoordinator](../../../../../game/scripts/systems/reset_coordinator.gd)의 `_commit_and_save`는 저장 실패 응답을 받으면 무조건 메모리를 rollback했다. 실제 파일 쓰기 후 응답만 유실돼도 디스크는 진행된 단계, 메모리는 이전 단계가 되었다. 초기 D6 한영/두 경로의 재시도 4건은 E1 진입과 새 아침/기상 기록 단언에 실패했다.

실패 응답 시 동일 슬롯·트랜잭션의 커밋을 `confirm_snapshot_commit`으로 조회하고 영속 snapshot의 정확한 일치까지 확인하도록 수정했다. 일치하면 이미 저장된 단계로 인정한다. 실제 미저장·다른 snapshot·확인 API 미지원은 기존 실패 반환 및 rollback 경로를 유지한다. 기존 장 진행 저장의 검증 패턴을 따르며 schema나 리셋 규칙을 바꾸지 않았다.

## 3. D6 검사

[notebook_fracture_smoke](../../../../../game/scripts/tests/notebook_fracture_smoke.gd)의 실제 선택 처리 메서드를 사용했다.

1. 휴식 질문/답변 기록은 허용하되 경로 선택 게임 저장을 거부한다.
2. 선택 답변 하나만 남고 휴식 경로·물리 상태·파열 상태는 적용되지 않는다.
3. 테스트 슬롯에서 load하고 controller를 재생성해 같은 답변 토큰과 미실행 상태를 복원한다.
4. 취소는 경로를 선택하거나 잠들지 않는다. 시도 답변은 그대로 남긴다.
5. 재시도는 응답 유실에도 선택한 휴식 경로만 저장하고 타이머를 시작한다.
6. 타이머 끝의 실제 리셋 저장도 한 번 거부한다. 선택 경로와 기존 물리 상태가 유지되고 실패 안내/재시도 상태가 된다.
7. 다시 시도할 때 리셋의 성공 응답을 유실시켜도 E1에 도착하고 하루가 한 번만 증가하며 기상 기록을 획득한다.
8. 원래 답변은 중복되지 않고 오래된 callback은 추가 수면을 실행하지 않는다.

타이머는 headless에서 2초씩 직접 진행시켰다. 실제 Windows 입력이나 실제 시간 기반 연출 검수와 다르다.


## 6. 검사 자체 수정과 한계

초기 비교기는 영수증이 없는 정상 휴식 화면에도 surface receipt를 요구했다. 영수증이 어느 쪽에라도 있으면 기존 엄격 검증을 적용하고, 양쪽 모두 없을 때만 append된 관찰·counter 외 archive 메타데이터 및 모든 게임 상태가 동일함을 검사하도록 보완했다. 관찰 검증을 생략하거나 게임 필드를 지워 통과시킨 것이 아니다.

추가 foundation 검사 작성 중 slot 변수 타입 추론 오류를 발견해 String을 명시했다. 해당 import는 중단됐고 의존 테스트를 실행하지 않았다. 최종 패키지는 다시 import/export해 검증했다.

이번 실행은 같은 프로세스 내 디스크 load/controller 재생성, 저장 실패 주입이다. 실제 전원 차단, OS 프로세스 강제 종료, Windows 입력·성능 인수를 대신하지 않는다. D5 시각 focus·안내 타이밍과 전체 전환 조합, 다른 생산자의 미검증 요구는 ToDo에서 유지한다.
