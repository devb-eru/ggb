# 혼합 기록 저장 보존 검증

- 기준: develop `7665e15`.
- 관련 요구: NB-Q12 / NB-AQ15, 전체 ToDo T26.
- 기존 `notebook_archive_smoke.gd::_validate_retention`은 일반 2,001개, 보호 2,001개, legacy 10,000개의 혼합 정리를 이미 검사한다. 이를 새 구현 성과로 중복 집계하지 않는다.
- 이번 추가는 `notebook_migration_smoke.gd::_validate_retention_commit(true)`의 실제 격리 저장 경계다. 기존 소규모 검사는 그대로 유지한다.

## 검사 절차

1. 일반 2,001개와 보호 2,001개, legacy 10,000개를 구성한다.
2. 가장 오래된 일반 기록에 책갈피를 붙여 정리를 유예하고 격리 슬롯에 기록한다.
3. 정상 로더로 설치한 snapshot과 디스크 바이트를 보관한다.
4. 마지막 책갈피 해제 저장을 거부한다. 메모리와 파일이 모두 원래 상태인지 검사한다.
5. 같은 해제 요청에서 저장은 성공하되 응답 유실을 주입한다. 확정 저장을 확인한 뒤에만 성공을 인정하는지 검사한다.
6. 일반 기록은 2,000개, 보호 기록은 2,001개, legacy는 10,000개가 남는지 확인한다. legacy 원문과 식별자는 설치한 원본과 비교한다.
7. 정리된 참조는 다른 기록으로 대체하지 않으며 순번을 다시 매기지 않는다. 저장 후 재로딩 snapshot은 메모리와 동일해야 한다.

## 테스트 데이터 주의점

초기 fixture는 legacy 원본과 외부 순번을 다르게 구성했고 화자 필드가 없었다. 각각 실제 형식 계약에 맞게 수정했다. 임의 추가 필드의 숫자는 JSON에서 실수로 읽힐 수 있으므로 저장 정리 전후의 원문 비교 기준은 정상 로더가 설치한 snapshot이다. 이 과정의 fixture 실패를 제품 결함으로 집계하지 않는다.
