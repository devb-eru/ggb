## 원인과 영향

기준 develop `30a376b`의 로더는 `f3_reselect.json`, `.tmp`, `.bak` 순으로 검사한다. checksum·상태·run이 유효한 `.tmp`를 발견하면, 이름 변경을 통한 승격이 완료되지 않았는데도 재선택 원본으로 반환한다. `create_f3_reselect_slot()`은 이를 받아 실제 플레이 가능한 새 분기를 만든다. 정상 백업이 있어도 미확정 임시 파일을 먼저 채택한다.

capture는 임시 복사→검증→기존 대상 백업→이름 변경으로 완료한다. 임시 내용의 유효성과 커밋 완료는 서로 다르다. 계획의 “커밋된 원본만 이관, tmp 단독 채택 금지” 계약과 충돌한다.

## 수정과 재현

- [x] 실제 SaveManager에서 F3 완료 본편 + 내용이 다른 정상 checksum의 tmp만 준비해 단독 읽기·복사 분기 생성을 재현했다.
- [x] 정상 bak를 추가해도 tmp 내용이 선택되는 문제를 재현했다.
- [x] 읽기 후보를 확정된 본파일과 bak로 제한했다. tmp를 삭제·덮어쓰거나 자동 승격하지 않는다.
- [x] 수정 전 새 회귀의 세 단언 FAIL, 수정 후 동일 단언과 기존 migration/save-safety suite PASS.
- [x] 실제 F3 capture/복사본 진입·중단·재개를 포함한 reselect-presentation 366개 PASS.
- [x] 조회 전후 tmp 바이트 불변 확인. 정상 구형 F3의 UID 보존·새 branch 분리·원본 불변 검사도 유지.
