## 문제

기본 실행점은 연습 씬에서 `scenes/main/main.tscn`으로 분리됐지만 현재 main은 엔진 버전 경고만 수행하는 빈 bootstrap이다. `project.godot`에 autoload가 없고 `game/data/`에는 `.gitkeep` 외 실행 Resource가 없다. 다음 production 최소 경로가 아직 존재하지 않는다.

```text
EventManager
→ StateWriter
→ GameState revision
→ SaveManager
```

또한 runtime schema 1의 새 게임·정상 리셋·손상 복구 fixture와 `export_presets.cfg`가 없다. 따라서 V0 경로 검사는 통과해도 진행 상태 소유권, 원자 커밋, 저장·백업·재개와 Windows 실행은 증명되지 않는다.

## 권장 해결안

1. `GameState`, `EventManager`, `SaveManager`를 autoload로 만들고 책임을 문서 17과 동일하게 제한한다.
2. 일반 시스템 `StateWriter`가 등록된 경로·타입·writer 권한·revision·불변식을 검사한 뒤에만 snapshot을 교체하게 한다.
3. 읽기 전용 `EventDefinition` Resource 한 개와 registry를 연결해 단일 사건의 시작→원자 커밋→완료 신호를 검증한다.
4. `schema_version=1`, `design_revision=v0.4-state-r12` 새 게임 fixture를 만들고 tmp→검증→backup→main 교체를 구현한다.
5. 정상 fixture, 손상 primary·정상 backup fixture, future schema 거부 fixture를 자동 실행한다.
6. Windows debug export preset과 재현 명령을 추가하되 인증 정보는 저장소에 넣지 않는다.

## 완료 조건

- [x] UI·씬이 GameState 내부 Dictionary를 직접 쓰지 못한다.
- [x] 선언되지 않은 state path와 stale revision 쓰기가 거부된다.
- [x] 사건 완료의 복수 영구 효과가 하나의 transaction으로 적용된다.
- [x] 저장 뒤 재로드 snapshot이 동등하고 손상 primary는 backup으로 복구된다.
- [x] Godot 4.7 headless import·GDScript parse·Resource load가 통과한다.
- [x] Windows debug export가 깨끗한 사용자 환경에서 실행된다.
