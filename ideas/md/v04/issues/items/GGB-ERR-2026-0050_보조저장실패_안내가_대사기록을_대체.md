# GGB-ERR-2026-0050: 보조 저장 실패 안내가 대사 기록을 대체

| 항목 | 값 |
| --- | --- |
| 유형 | 오류 ERR |
| 심각도 | 중간 |
| 해결 상태 | OPEN |
| 작업 상태 | READY |
| 우선순위 | P2 |
| 담당자 | Codex |
| 목표 마일스톤 | `FULL_00_CONTENT_COMPLETE` |
| 최초 확인 | 2026-10-07 |
| 영역 | F3 / 보조 저장 / 표시와 수첩 생산자 |

## 재현과 영향

기준 `962a8c8`, Steam Godot 4.7.2, 신규 TEMP 프로젝트 및 별도 APPDATA에서 실제 F3 장치 조사와 최종 확인 버튼을 실행했다. 본편 저장은 실제 SaveManager에 성공시키고 `capture_f3_reselect`만 실패시킨다.

- 한국어/영어 두 조건 모두 EDC에 도달하고 최종 결정은 `unset`이다. 본편 진행 저장 실패가 아니다.
- `BasementSession._commit`은 성공한 본편 결과의 `text`를 보조 사본 저장 오류 안내로 교체하고 `notebook_feedback`을 삭제한다.
- `BasementController._feedback`은 이 성공 결과를 일반 대사로 표시한다. 안내가 `CH1_HISTORY_TRANSCRIPT`의 신규 `unmapped` 행 1개로 저장된다.
- 원래 표시해야 할 `F3_OPEN` authored 행은 0개다. 영어에서도 한국어 시스템 안내가 그대로 나타난다.
- 같은 함수의 크레딧 감상 기록 실패 처리에도 동일한 결과 교체가 있다. 크레딧은 history 비활성 구간이므로 같은 신규 미매핑 증상으로 단정하지 않는다. 원래 피드백 보존과 UI 안내 분리는 별도로 검사한다.

이는 [구형 체크포인트 마지막 피드백 예외](../validation/2026-10-07_수첩생산자_거울지하파열힌트_합집합.md)와 다르다. 기존 기록의 조회가 아니라 새 본편 성공 행동에서 발생한다.

## 해결안

1. 저장 성공 결과의 원 대사, 명시 콘텐츠 descriptor와 발생 전 문맥을 유지한다.
2. 보조 사본/감상 기록 실패는 별도 UI 경고 키로 전달하고 현재 언어로 상태 영역에 표시한다. 본편 대사 writer나 새로운 콘텐츠 ID에 넣지 않는다.
3. 보조 저장 실패 때문에 본편 저장 성공을 실패로 바꾸거나 이미 저장한 진행을 되돌리지 않는다.
4. 한영 F3에서 정상/보조 실패 모두 authored `F3_OPEN`을 정확히 한 번 기록하며 신규 시스템 `unmapped`는 0이어야 한다. 실패 경고의 표시, 실제 저장·재로드·최종 선택 미정 상태도 확인한다.
5. 크레딧 두 엔딩의 보조 실패 및 성공 경로, 일반 모드/개발 수첩 모드와 기존 final suite를 회귀한다.
