## 문제

연습 씬의 현재 배경은 `background.gd`의 `background_index=1`이 소유하지만 `key.gd`, `drawer.gd`, `lock.gd`도 각각 초기 배경과 표시 상태를 별도로 추정한다. 또한 네 스크립트가 `$"../node"` 형제 경로에 직접 결합돼 있다.

현재 index 1에서는 값이 우연히 일치하지만 시작 배경이나 노드 이름·구조가 바뀌면 첫 신호가 발생하기 전 다음 문제가 생길 수 있다.

- 서랍·열쇠·자물쇠의 초기 표시가 실제 배경과 다르다.
- 노드 이름 변경이 런타임 경로 오류로 이어진다.
- 연습 코드를 production 예시로 복사할 때 상태 소유권과 의존성 문제가 전파된다.

기본 실행점과 production 코드에서 격리돼 있으므로 즉시 제품 진행을 막지는 않는다. 이 때문에 상태는 `DEFERRED`로 두되 production 코드가 이 파일에 의존하면 즉시 `OPEN`으로 전환한다.

## 권장 해결안

다음 둘 중 하나를 선택한다.

1. production 최소 상호작용 fixture가 만들어지면 연습 씬과 전용 PNG·GDScript를 삭제한다.
2. 보존 가치가 있으면 부모 controller가 초기 snapshot을 한 번 배포하고, 각 노드는 export된 `NodePath` 또는 명시적 주입으로 의존성을 받게 한다.

어느 경우든 production scene이 루트 연습 스크립트를 preload·instantiate하지 않는 정적 검사를 유지한다.

## 완료 조건

- [ ] production 파일에서 `signal_practice`와 전용 스크립트 참조가 0건이다.
- [ ] 보존 시 초기 배경을 바꿔도 첫 프레임 표시가 일치한다.
- [ ] 보존 시 노드 이름 변경이 하드코딩 형제 경로 오류를 만들지 않는다.
- [ ] 삭제 시 Git 이력과 이 문서로 과거 목적을 추적할 수 있다.
