# GGB-ERR-2026-0078: 초기 전체 화면의 창 모드 덮어쓰기와 화면 잘림

| 항목 | 값 |
| --- | --- |
| 유형 | 오류 ERR |
| 심각도 | 높음 |
| 해결 상태 | VERIFIED |
| 작업 상태 | DONE |
| 우선순위 | P1 |
| 담당자 | Codex |
| 목표 마일스톤 | `FULL_00_CONTENT_COMPLETE` |
| 최초 확인 | 2026-11-05 |
| 영역 | StartScreen 초기 디스플레이 / Windows 창 위치 |

## 문제

사용자가 실제 화면에서도 오른쪽 인벤토리와 하단 안내가 잘리고 중심이 우측·하단으로 치우친다고 확인했다. 격리된 자연 진행 슬롯의 복사본에서 같은 현상을 재현했다. 단순 캡처 잘림으로 처리하지 않는다.

원래 코드는 자식 StartScreen의 `_ready()` 안에서 초기 디스플레이 설정을 즉시 적용한다. 초기 윈도우 구성 시점과 겹쳐 borderless 프로필인데도 이후 `MODE_WINDOWED`가 남고 전체 화면 크기를 가진 창이 화면 원점에서 벗어난다. 강제 창 옵션 유무 모두 재현했다.

- 강제 옵션 있음: 창 모드 0, 크기 `2560×1600`, 위치 `(89,55)`.
- 강제 옵션 없음: 창 모드 0, 같은 크기, 위치 `(629,359)`.
- 두 경우 논리 뷰포트 `1920×1200`, 최상위 UI 원점 `(0,0)`과 인벤토리 경계는 뷰포트 안이다. UI 전체를 임의로 좌측·상단 이동할 문제가 아니다.

## 조치와 검증

- [x] 사용자 제보와 실제 격리 게임에서 잘림 재현.
- [x] 읽기 전용 측정으로 창·뷰포트·UI 경계를 분리하고 옵션 유무 비교.
- [x] `_apply_initial_display()`에서 첫 process frame까지 대기한 뒤 유효한 화면에만 기존 backend 설정을 적용하는 국소 수정.
- [x] 후보의 mode 3, 위치 `(0,0)`, native 크기 확인.
- [x] 진단 스크립트 없는 정상 메인 씬 실행에서 실제 이어하기 클릭. 인벤토리 6칸과 하단 수첩·대화기록 버튼이 모두 표시됨을 확인.
- [x] 실제 시작 순서를 통과하는 native 회귀: 원본 70확인/4실패/native 1, 후보 5조건/758확인/native 0.

- [ ] develop 전달: 전체 ToDo의 전달 항목에서 커밋과 원격 SHA 확인을 분리 추적.
