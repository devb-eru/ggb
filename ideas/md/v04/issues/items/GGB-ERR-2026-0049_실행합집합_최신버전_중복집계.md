# GGB-ERR-2026-0049: 실행 합집합 최신 버전 중복 집계

| 항목 | 값 |
| --- | --- |
| 유형 | 오류 ERR |
| 심각도 | 중간 |
| 해결 상태 | VERIFIED |
| 작업 상태 | DONE |
| 우선순위 | P2 |
| 담당자 | Codex |
| 목표 마일스톤 | `FULL_00_CONTENT_COMPLETE` |
| 최초 확인 | 2026-10-07 |
| 영역 | 테스트 도구 / 실행 경로 합집합 / 최신 의미 버전 |

## 원인과 영향

`scripts/audit_notebook_runtime_union.ps1`은 각 카탈로그에서 가장 높은 버전을 `$latest`에 추가했지만 다른 카탈로그에 같은 ID의 더 높은 버전이 있을 때 이전 키를 제거하지 않았다. `chapter_one_notes_v1.json`의 표식 v1과 `self_mark_v2.json`의 v2가 모두 최신 요구 문단으로 집계됐다. NP06의 최신 문단/언어 요구가 실제 52개 대신 58개로 표시됐다.

등록 정의/게임 기록/원문에는 오류가 없고, 7필드 실행 경로 자체의 중복 제거도 이 원인으로 변하지 않는다. 문제가 있는 값은 최신 요구량 및 최신 누락 목록이다. 과거 버전 관찰은 역사적 근거로 보존해야 하며 최신 요구를 채운 것으로 세면 안 된다.

## 해결

`Add-CatalogDefinitions`에서 ID별 최대 버전을 카탈로그 전체에 걸쳐 선택한다. 낮은 버전은 definitions에 유지하되 latest 집합에서 제거한다. 카탈로그 읽기 순서가 v1→v2 또는 v2→v1이든 결과가 같아야 한다. 콘텐츠·카탈로그·게임 원장은 수정하지 않는다.

## 검증

- 두 카탈로그 순서의 정의 2개/최신 1개를 확인하는 자체 검사 PASS.
- 과거 v1 관찰은 유효 경로로 유지되지만 최신 v2 문단을 채우지 않음 PASS.
- v1/v2 관찰을 함께 집계할 때 경로 2개와 최신 언어 1개를 구분함 PASS.
- 동일한 실제 stay 실행 로그와 현재 카탈로그를 수정 전/후 도구로 읽어 NP06 최신 요구량 58→52를 재현했다. 수정 전 도구는 당시 develop 파일 그대로 TEMP에 복사했으며 원본 로그를 수정하지 않았다.
- 22개 생산자의 최신 문단/언어 요구량이 독립 카탈로그 도구의 최신 문단 수 × 2와 일치했다. [수정 전후 근거](../validation/evidence/2026-10-07_runtime_union_latest_versions.json).

[후속 검증](../validation/2026-10-07_수첩생산자_1장선택창_합집합.md)에 전체 합집합 결과를 연결한다. 이 집계 오류만 VERIFIED이며 전편 인수 완료가 아니다. [기존 T19c 보고서](../validation/2026-10-07_수첩생산자_실행경로합집합.md)의 여러 버전 ID에 대한 최신 요구량·누락 목록에는 이 한계가 있다. 기존 raw 로그/receipt와 고유 926경로의 역사적 근거는 그대로 보존한다.
