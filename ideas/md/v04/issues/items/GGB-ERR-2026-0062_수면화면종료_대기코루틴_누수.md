## 재현과 원인

첫 화면 소유자 guard 수정 후보는 176조건의 행동 단언이 통과하고 native 0으로 종료했으나 ObjectDB 누수 경고가 남았다. 즉시 삭제·삭제 예약·분리 경로를 한영 8조건으로 다시 검사하자 `GDScriptFunctionState` 4개와 `_run_campaign_sleep_async`의 고아 이름이 확인됐다. Node에 소속된 await가 완료 전에 Node가 제거되면 대기 체인이 정상 회수되지 않았다. 단순 guard는 오래된 결과의 반영을 막을 뿐 대기 자체의 수명을 보장하지 않는다.

RefCounted 작업 객체로 옮긴 첫 중간 후보도 명시적인 강한 참조가 없어 정상 대조군 두 조건 실패와 대기 누수가 발생했다. 이 중간 후보를 합격 코드나 배포 근거로 사용하지 않는다.

## 조치와 검증

`CampaignSleepTask.run(task)` 정적 대기 함수의 인수로 작업 객체를 강하게 보유한다. 화면은 WeakRef와 유효한 완료 Callable로만 조회하고 세대·세션·슬롯·서비스가 같은 소유자에게만 결과를 전달한다. 화면 멤버의 수면/D6 함수는 await하지 않는다. owner가 사라져도 worker의 취소·내구 영수증 회수와 세션 종료는 완료되고 작업 객체는 함수가 반환할 때 해제된다.
