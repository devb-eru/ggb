## 재현과 영향

기준 develop `7b7fe369`의 격리 사본에서 정상·파열 리셋의 `reset_completed` 구독자가 GameState를 즉시 제거하면 `_commit_step_async`의 반환값 구성에서 해제된 객체의 `revision`에 접근한다. 스크립트 오류 뒤 빈 결과가 전달된다. 삭제 예약된 GameState나 저장 서비스, 트리에서 분리된 저장 서비스를 완료 구독자가 만든 경우에도 완료 성공으로 처리한다.

완료 신호 전에 `idle` 단계는 이미 저장되었다. 실패를 이유로 해당 단계를 되돌리거나 새 리셋을 시작하면 안 된다. 중단되어야 할 것은 폐기된 문맥의 후속 기상이다. epoch/revision/외부 guard 변경은 기존 루프의 다음 검사에서 이미 거부되었으며, 그 성공을 새 결함으로 계산하지 않는다.

## 조치

`game/scripts/systems/reset_coordinator.gd`에서 완료 신호 뒤 `_reset_async_live`를 다시 확인한다. 살아 있는 GameState와 트리 안의 저장 서비스 모두 삭제 예약되지 않아야 한다. 무효 문맥은 `NB_COMMAND_SCOPE`로 종료하고, 확정된 완료 영수증·일차·영구 데이터를 보존한다.

- [x] 기존 코드의 즉시 제거·삭제 예약·서비스 분리 실패 재현.
- [x] 완료 콜백 뒤 scope 재검사와 서비스 생존 검사 추가.
- [x] 새 주 객체의 내구 결과 재로딩 및 idle 영수증의 재리셋 방지 확인.
- [x] 같은 최종 소스 전체 지정 회귀·독립 검사 완료: 9native, 독립 6,576확인·6반례 거부.
