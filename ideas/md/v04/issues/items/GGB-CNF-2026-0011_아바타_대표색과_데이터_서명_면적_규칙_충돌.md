## 문제

문서 `02`는 캐릭터 아바타 대표색을 머리카락·귀·꼬리·의상 등에 사용하는 넓은 팔레트로 정의한다. 개정 전 문서 `16`은 고딕 필터에서 “서명은 의상 전체가 아니라 5~12% 면적의 장식으로 제한한다”고 적어 다음 두 해석을 동시에 허용했다.

- 캐릭터의 파란 머리·주황 꼬리처럼 넓은 대표색 면이 금지된다고 해석.
- 캐릭터 대표색 전체가 곧 퍼즐 판독용 데이터 서명이라고 해석.

첨부 샘플 캐릭터 시트는 머리카락·꼬리·의상에 큰 색면을 사용하므로 이 모호성이 실제 캐릭터 제작과 직접 충돌한다. 마라 1의 빨강과 일부 캐릭터의 붉은 눈이 시스템 오류색으로 오인될 위험도 함께 발생한다.

## 채택 해결안

화면의 색을 다음 네 계층으로 분리한다.

```text
아바타 대표색
≠ 데이터 서명색
≠ UI 의미색
≠ 환경 보정색
```

- 아바타 대표색은 머리·귀·꼬리·의상 큰 면적에 사용할 수 있다.
- `5~12%` 제한은 고딕 세계의 오브젝트·장치에 배치하는 시스템 판독용 데이터 서명 표식에만 적용한다.
- 데이터 판정은 색상값이 아니라 `signature_id`를 사용한다.
- 캐릭터의 빨강은 오류 의미가 아니며 오류는 프레임 단절, 오류 코드, 복구 행동을 병기한다.
- 장식, 데이터 서명, 조작 가능 핫스폿은 외곽선·커서·행동 동사로 분리한다.
- 샘플의 다중 배색안은 기존 확정색을 바꾸지 않고 형태 참고로만 사용한다.

## 해결 체크리스트

- [x] `5~12%` 제한 대상을 시스템 판독용 서명 표식으로 한정함.
- [x] 캐릭터별 대표색·데이터 서명 노출 위치를 분리함.
- [x] 캐릭터 빨강과 시스템 오류의 구분 규칙을 추가함.
- [x] 샘플 시트의 채택·참고·보류 요소를 구분함.

- [x] `01`, `02`, `06`, `11`~`15`, `17`, `00`, `README`, `18`에 후속 계약을 동기화함.

## 회귀 방지 규칙

1. 캐릭터 대표색 HEX와 데이터 서명 HEX를 같은 리소스 필드에 저장하지 않는다.
2. 아바타 색면 비율을 `5~12%`로 제한하지 않는다.
3. 색이 보인다는 이유만으로 오브젝트를 조작 가능 상태로 만들지 않는다.
4. 캐릭터의 빨강·검정·흰색에 성공·실패·선악 의미를 자동 부여하지 않는다.
5. 접근성 색 교체값을 `signature_id`나 퍼즐 판정값에 쓰지 않는다.
