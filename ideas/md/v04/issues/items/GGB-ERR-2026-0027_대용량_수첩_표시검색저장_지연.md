## 발생 위치와 재현

네 고정 fixture를 한영 각각 headless cold 1회/warm 3회 계측했다. 아직 장비 등급과 실제 입력 p95 인수는 아니다. 다만 현재 동기 처리 경로에서 초 단위 지연이 재현되어 출시 전 해결 대상으로 등록한다.

## 부분 해결 결과

L10000 첫 검색은 약 8.96~8.98초에서 2.84~2.90초로 줄었고 N2000은 약 1.35초에서 0.50~0.56초로 줄었다. 이것은 표본 1개씩의 탐색 비교이며 보장값이 아니다. 저장은 유의미하게 개선되지 않았고 대용량 표시/검색도 예산 초과 위험이 남아 있다.

같은 날짜의 저장 후속에서는 schema 2에 불필요한 이관 digest와 반복 payload 정렬/복제를 제거했다. 앞선 조회 개선 코드 대비 L10000의 저장 세 표본 최대값은 약 3.35초에서 2.74~2.78초로 줄었다. 원래 인코더와 서명 바이트·체크섬이 일치하며 구형 기록의 결정적 이관 ID도 보존한다. 저장은 아직 동기식이고 예산을 초과하므로 상태는 IN_PROGRESS다. [보고서 7절](../../../../../docs/notebook_performance_validation.md#7-저장-직렬화와-복구-안전성-후속)에 새 원자료를 분리했다. 함께 발견한 백업 손실은 독립 오류 [ERR-0028](GGB-ERR-2026-0028_손상된_본파일이_정상_백업을_덮어씀.md)로 해결·검증했다.

최근 일반 대사 2,000개, 보호·기존 미분류 별도 보존과 비교 묶음 12개/동시 두 개를 유지한다. 성능을 이유로 기록을 버리거나 과거 원문을 재생성하지 않는다. 저장 성공 전에 메모리 상태만 성공으로 보이게 하지 않는다.

2026-10-05 후속에서는 명령의 중복 슬롯 조회를 제거하고, 실제 파일 바이트의 SHA-256이 같을 때만 검증된 소형 표시 요약을 재사용하도록 했다. L10000의 불변 슬롯 재조회 6개 표본은 약 562~610ms에서 31~40ms로 감소했다. 캐시는 최대 8개이며 본문/snapshot을 보관하지 않는다. 변경 후 최초 조회는 약 611~671ms, 실제 저장은 최대 약 2.72초로 여전히 느리다. 저장·로드·백업 검증은 캐시를 사용하지 않는다. [별도 검증과 원자료](../validation/2026-10-05_수첩_슬롯요약_재검증.md)를 남겼으며, 비동기 저장 완료나 성능 인수로 세지 않는다.

## 해결 순서

2026-10-05 추가 후속으로 수첩 책갈피·비교 고정/해제의 후보 준비를 worker로 분리했다. 실제 파일 승격 전 슬롯·revision·로드 세대·호스트와 파일 지문을 다시 확인하고, 디스크 성공 뒤에만 GameState를 설치한다. 닫기는 완료를 기다리며 실패 시 재시도/취소를 제공한다. 비동기 저장 269개와 실제 호스트 375개 자동 검사를 통과했다. [구현 경계와 검증 기록](../validation/2026-10-05_수첩_비동기고정저장_검증.md), [단일 표본 원자료](../validation/2026-10-05_수첩_비동기고정저장_계측.json)를 남긴다.

이는 수첩 참조 명령의 준비 단계에 한정된다. 최종 L10000 headless 표본의 시작 처리는 약 137ms, 완료 처리는 약 489ms이고 성공 후 UI 재구축 비용은 별도다. 본편 대화·사건 저장은 여전히 동기식이며, 최초 표시·검색·실제 Windows 입력과 장비별 성능 인수도 미완료다. 상태를 RESOLVED로 올리지 않는다.

1. 첫 화면의 검증·복제·정렬·레이아웃을 각각 계측한다. 신뢰 경계를 넘는 불필요한 중복만 제거하고 슬롯/분기/언어 전환 stale 결과를 차단한다.
2. 공개 segment 색인에 프레임 시간 예산을 적용한 현재 수정의 실제 입력 성능을 측정한다. 부분 결과를 최종 빈 결과로 표시하지 않는다.
3. 저장에 동일 snapshot의 불변 복사·직렬화된 작업 소유권·명확한 영속 성공/실패 경계를 설계한다. worker를 쓰더라도 GameState/Node 접근과 콘텐츠 캐시 초기화는 스레드 안전성을 먼저 검증한다.
4. 미래 버전 슬롯, 손상 본파일, 백업 복구, 쓰기 실패, 중단, 동시 저장, 로드/분기 전환 중 완료 콜백을 모두 회귀한다. 별도 파일 분할은 이관 설계 없이 도입하지 않는다.
5. 고정 입력 hash를 보존한 cold 20/warm 100 및 실제 Windows 입력·RAM 검증으로 인수한다. 미보유 장비는 NOT_COVERED다.

## 완료 조건

2026-10-05 필터 수집 후속에서는 서로 다른 세션이 늘어날 때 배열 중복 탐색이 제곱 비용으로 커지는 부분을 사전 기반으로 교체했다. 표시 순서는 유지하며, 불변 비검색 결과만 최대 4개 재사용하고 부분 검색 결과는 캐시하지 않는다. L10000의 기존 반복 수집 3개 표본 약 931~1,087ms가 최종 첫 수집 약 230ms, 이후 재조회 약 0.5~0.8ms로 바뀌었다. 전체 첫 표시 약 1.27초와 최초 검색 약 2.66초는 여전히 남는다. [검증 보고서](../validation/2026-10-05_수첩_필터항목_수집_검증.md)와 [전후 원자료](../validation/2026-10-05_수첩_필터항목_수집_계측.json)에 단일 cold/3회 warm 탐색 결과와 정식 인수의 차이를 명시했다.

- [x] 결정적 fixture·재현 명령·원시 시간·내용 해시를 저장한다.
- [x] 정렬/검색의 좁은 수정과 보존·접근 제한 회귀를 수행한다.
- [ ] 대량 최초 표시/검색의 실제 입력 지연 예산을 만족한다.
- [ ] 기록 손실 없이 영속 저장과 UI 반응 예산을 만족한다.
- [ ] 장비별 cold 20/warm 100, p95/최대/첫 회, 메모리 증분/회수와 프레임을 검증한다.
- [ ] 긴 문서 200%·한영·IME·마우스·키보드 실제 조작을 검증한다.

현재 기능 검사 PASS와 탐색 계측만으로 RESOLVED/VERIFIED로 올리지 않는다. 개발 rollout은 기본 비활성을 유지한다.

## 변경 이력

검색 색인 후속에서는 상세용 링크·참조 복제·시각 자료 조회를 생략하고 본문 검증과 공개 문자열 투영을 상세 화면과 공유했다. 같은 네 fixture의 첫 검색 탐색 표본은 약 475/1,768/918/554ms에서 404/1,370/793/477ms로 바뀌었다. 구형 손상 행 이후 검색·한영 공개 필드 동일성·stale 거부와 기존 공개 제한을 회귀했다. [검증과 한계](../validation/2026-10-05_수첩_검색색인_투영_검증.md)를 별도로 남기며 단일 표본을 성능 인수로 세지 않는다. 상태는 IN_PROGRESS다.

같은 날짜의 첫 목록 후속에서는 모든 참조 키의 사용자 비교 정렬을 숫자 기준 묶음 정렬로 교체했다. 기존 대화/최근/인물 순서, 이전 수첩 음수 순번, 공개 문단 순서와 UID 앵커를 유지한다. N2000/L10000/P2001/LONG에서 첫 목록 모델 조회의 탐색 표본이 각각 약 32/194/68/30ms에서 6/47/13/8ms로 감소했다. 모델 시작부터 패널까지는 약 513/986/769/532ms가 남으며, 이 계측에는 호스트 슬롯 확인·실제 입력 비용이 포함되지 않는다. [정렬 검증 보고서](../validation/2026-10-05_수첩_숫자순서_정렬_검증.md)에 범위와 원자료를 구분했다. 정식 성능 인수와 전체 완료 상태는 바꾸지 않는다.
