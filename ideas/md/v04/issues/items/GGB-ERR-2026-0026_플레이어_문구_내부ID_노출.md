## 문제와 원인

내부 기록 키와 이벤트 단계 ID가 사용자용 문장에 직접 포함되어 있다. 저장 키가 존재한다는 사실 자체는 오류가 아니다. 아래 표는 실제 표시 원고나 동적 표시 문자열에 들어가는 경우만 구분한다. 정적 검색 결과만으로 모든 UI·저장·조회 경로를 실행했다고 주장하지 않는다.

## 보존해야 할 경계

- `SUBJECT`, `SYSTEM`, `CUSTODIAN`, `RESIDENT`, `CREATOR`는 실제 권한 퍼즐의 명칭이므로 일괄 제거하지 않는다.
- 저장 키, content ID, 이벤트 ID, 문서 출처 참조와 개발자 패널 ID는 그대로 유지한다.
- 이미 보관한 버전 1의 captured text와 번역을 새 문구로 덮어쓰지 않는다. 과거 원문 속 ID는 보존 대상이며 신규 플레이 문구의 노출과 별도 집계한다.
- 문자열 정규식으로 본문을 사후 삭제하거나, 현재 상태를 읽어 과거 기록을 재구성하지 않는다.
- 한글 조사 바로 앞의 ID는 단순 `\b` 경계 검색이 놓칠 수 있다. 동적 변수 값과 실제 표시 결과를 검사하고, 검색 결과 0만으로 승인하지 않는다.
- 기존 버전 생성 스크립트를 현재 원고로 다시 실행해 출시/보관 카탈로그를 덮어쓰지 않는다. 새 원고는 별도 버전에 추가한다.

## 이번 수정

다섯 완료 안내를 이름 기반 연구 기록 안내로 바꾸고 `relationship_labels_v2.json`에 같은 content ID의 버전 2를 추가한다. `_queue_relationship_surface`가 COMPLETE에만 명시적 버전 2 descriptor를 연결한다. 다른 관계 화면은 기존 표시 경로를 유지한다. 기록 획득 키·관계 보상·선택·정답에는 변화가 없다.

후속으로 `record_labels_v2.json`에 J4 합성 문서 1개, 인덱스 발화 5개, 현실 인계 확인창과 획득 문서 각 1개의 버전 2를 추가했다. 인계 출처는 고정된 다섯 명 순서의 mask enum으로 저장하고 한영 이름으로 표시한다. 기존 기록 본문이나 출처 키를 이름으로 치환하지 않는다.

구 확인창 재개를 검토하면서 공통 모달 표시/복원 경로가 정의 조회 버전을 1로 고정한 것도 수정했다. 실제 descriptor의 버전을 사용한다. 현실 수첩 읽기 확정은 실제로 저장된 질문의 버전·문장·변수·발생/대화/표시 토큰을 확인한 뒤 그 문서를 획득한다. 표시하지 않은 토큰은 변경 없이 거부한다. 요약 재열람은 확장 문서를 낮추지 않고 동일한 확장 문서 재열람도 중복 revision을 만들지 않는다.
