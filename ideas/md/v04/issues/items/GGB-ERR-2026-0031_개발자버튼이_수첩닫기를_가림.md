## 재현

debug full + notebook-v2의 새 게임에서 수첩을 열고 오늘의 일과 상세를 선택한다. 오른쪽 위 닫기 버튼을 실제 마우스로 클릭하면 수첩 대신 개발자 메뉴가 열린다. Escape로 개발자 메뉴를 닫았으며 시점 이동·저장 덮어쓰기는 실행하지 않았다. 수첩 키보드 Escape 복귀는 별도로 통과했다.

## 원인과 영향

`developer_panel.gd::_ready()`는 `CanvasLayer.layer = 100`, `PROCESS_MODE_ALWAYS`인 개발자 실행 버튼을 우측 상단에 상시 둔다. 수첩의 같은 위치 닫기와 겹쳐 클릭을 먼저 받는다. 개발자 도구를 생성하는 debug 실행의 입력·시각 인수를 방해한다. release 사용자에게 같은 현상이 발생한다고 일반화하지 않는다. release에서는 해당 패널이 제거되지만 이번 실행에서 release 패키지를 검증한 것은 아니다.

## 권장 해결안

1. 수첩·갤러리 수첩 등 전면 기록 UI가 입력을 소유하는 동안 개발자 실행 버튼을 숨기고 키보드 포커스에서도 제외한다. 다른 위치로 옮기는 것만으로 충돌을 회피하지 않는다.
2. F10 유지 여부를 명시한다. 유지할 경우 열기·닫기 때 수첩 입력 중단과 기존 포커스 복귀를 보장하고, 개발 시점 이동은 기존 격리 슬롯 정책을 유지한다.
3. host 종료·타이틀 복귀·창 포커스 변경·오류 경로에서도 실행 버튼 상태가 복원되는지 검사한다.
4. 수첩 닫기 좌표의 실제 클릭으로 원래 대화가 그대로 복귀하는지 재검증한다. 일반 대사 진행·시점 이동이 함께 발생하지 않아야 한다.
5. 엔진 회귀와 실제 Windows 마우스 검증 후 VERIFIED로 변경한다. 코드를 수정하고 자동 회귀를 통과한 현재는 RESOLVED이며 실제 재입력을 기다린다.

## 적용한 수정

- 일반 수첩과 갤러리 수첩 host가 성공적으로 열릴 때만 `notebook_input_hosts` 런타임 그룹에 등록한다. 닫기·트리 제거 시 해제하며 저장 데이터에는 기록하지 않는다.
- 개발자 패널은 열람 중 실행 버튼을 숨기고 마우스·포커스 대상에서도 제외한다. 직접 호출과 F10 모두 개발자 창을 열지 않는다. F10은 소비하지 않아 수첩의 재지정 탐색 키로 계속 사용할 수 있다.
- `notebook_input_observers` 알림으로 정상 열기·닫기는 같은 호출에서 반영한다. 닫힘 대기 중에는 입력 소유권을 유지한다. 소유자 파괴·슬롯 교체 등 host 종료는 프레임 확인으로 복구한다.
- 최종 자동 회귀에서 일반 host 335개, 갤러리 189개를 포함한 query 및 타이틀 검사를 통과했다. 겹침 좌표 클릭, F10 차단/복원, F10 재지정 입력, 일반/갤러리 host 생명주기와 생성 전 개발자 UI의 안전한 갱신을 포함한다. Windows 잠금 해제 후 실제 마우스 재검증이 필요하다.
