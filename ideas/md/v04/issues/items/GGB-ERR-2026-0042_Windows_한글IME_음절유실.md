# GGB-ERR-2026-0042: Windows 한글 IME 음절 유실

| 항목 | 값 |
| --- | --- |
| 유형 | 오류 ERR |
| 심각도 | 높음 |
| 해결 상태 | OPEN |
| 작업 상태 | READY |
| 우선순위 | P1 |
| 담당자 | `Codex` |
| 목표 마일스톤 | `FULL_00_CONTENT_COMPLETE` |
| 최초 확인 | 2026-10-06 |
| 영역 | Windows / Godot 4.7.2 / LineEdit / 수첩 검색 |

## 재현과 영향

develop `9cc6f22`의 격리 게임 검색칸에서 물리 한/영 전환 후 `오늘`을 조합하면 `늘`만 남는다. 사용자가 직접 Ctrl+A, 오늘, Enter를 입력해도 동일하다. 완성 문자열 주입 검증과 별개의 실제 IME 입력 오류다.

동일 실행 파일의 별도 최소 프로젝트에서도 사용자 직접 입력으로 재현했다. 기본 LineEdit 하나와 text_changed/text_submitted 로그만 사용하며 게임 autoload, 수첩, 검색 갱신 및 저장 코드가 없다. 로그의 마지막 확정 문자열은 `늘`이다. 따라서 수첩 코드만의 원인으로 볼 수 없다. 엔진과 이 PC의 Windows IME 간 문제는 확인했지만 정확한 원인 줄, Windows 빌드/IME 버전별 범위 및 다른 엔진 버전의 정상 여부는 아직 확정하지 않았다.

자세한 환경·근거·재현 프로젝트 코드는 [실기 검토](../validation/2026-10-06_두자료비교_및_IME조합_실기검토.md)를 참조한다.

추가 [공식 런타임 비교](../validation/2026-10-06_한글IME_공식런타임_비교.md)에서 같은 최소 프로젝트를 공식 `4.7.2.stable.official.ed1daf0bf`로 실행해도 사용자 물리 입력의 앞 음절이 사라지고 로그에 `IME_SUBMIT "늘"`이 남았다. 공식 `4.6.3.stable.official.7d41c59c4`에서는 사용자와 로그 모두 `오늘` 정상 확인, 추가 연속 한글/한영 전환/확정 후 편집 세 조건도 정상 확인했다. 두 진단 프로세스는 종료했다. Steam 배포판만의 문제가 아니며 동일 PC의 최소 재현에서 버전 차이를 확인했다. 임시 게임 복사본의 import/migration/host/기본 기반 검사와 PCK 생성은 통과했지만 실제 수첩 IME·배포/전체 호환·정확한 원인/수정·엔진 채택은 미완료다. 설치된 제품 엔진을 변경한 것은 아니다.

## 해결 계획

사용자는 4.6.3 후보의 실제 게임 IME·전체 호환을 검증한 뒤 개발·빌드 기준 채택을 검토하는 경로를 선택했다. 이 후보의 기본/수첩 모드 자동 캠페인과 재선택 366개는 PASS이며 이전 격리 4.7 슬롯 복사본의 실제 이어하기·수첩과 물리 입력 다섯 국소 조건(연속 한글/한영 전환/확정 후 편집/조합 취소/포커스 복귀)도 사용자 정상 확인을 받았다. 모든 검사 프로세스는 종료했고 원본 격리 main/bak를 보존했다. 제품 엔진/빌드 계약 채택과 넓은 호환·입력 인수는 남아 있어 OPEN을 유지한다.

1. 동일 PC·동일 최소 프로젝트에서 공식 Godot 비교 런타임의 물리 조합을 검사한다. 정상 후보가 있으면 실제 게임의 파싱/내보내기·입력·저장 호환 회귀 후에만 버전 변경을 채택한다. 현 프로젝트 및 사용자의 Steam 설치를 먼저 교체하지 않는다.
2. 버전 비교에서 정상 후보가 없으면 Windows IME 조합 확정과 다음 조합 시작의 엔진 이벤트 순서를 계측해 상위 엔진 수정 경로를 검토한다. 추정만으로 GDScript에서 음절을 복원하지 않는다.
3. 수정 후보의 실제 수첩에서 오늘/오늘의 일과, 연속 한글, 한영 전환, 조합 취소, Backspace, 중간 삽입, 검색 실행, Escape, 포커스 이탈과 재진입을 검사한다. 자료 비교 및 저장 복귀도 회귀한다.
4. 미수정 동안 T22/한글 IME 인수와 기본 rollout OFF를 유지한다. 완성 문자열 입력이나 headless 통과로 이 이슈를 닫지 않는다.

Windows 입력기 설정을 자동으로 바꾸거나, 마지막 조합 미리보기를 무조건 본문에 붙이거나, 매 입력마다 검색칸 text를 재설정하는 우회는 적용하지 않았다.
