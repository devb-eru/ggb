## 원인

기준 develop `288c003`. `_validate_save_text`는 알 수 없는 design revision을 `ERR_SAVE_DESIGN_REVISION`으로 거부하지만 호출부는 미래 schema만 특별 보호했다. 따라서 미지원 main을 손상으로 취급해 bak로 우회하거나, 저장/수첩 고정/F3 capture/이전 F3 정리에서 파일을 덮거나 지울 수 있었다. 슬롯 요약도 호환 불가로 표시하지 않았다.

## 수정

- `_is_incompatible`에서 미래 schema와 미지원 design revision을 함께 분류한다. 개별 오류 코드는 유지한다.
- 일반 저장의 main/bak/tmp, 이관·복구, 슬롯 요약, F3 capture/읽기/정리, 구형 원본 보존과 비동기 수첩 worker에 같은 판정을 적용한다.
- F3 정리는 지원하지 않는 design을 만나면 세 후보 모두 보존하고 `WARN_RESELECT_DESIGN_PRESERVED`를 반환한다.
- 확정 main의 순수 읽기·요약은 관계없는 tmp를 채택하지 않는다. 올바른 main의 읽기까지 일괄 차단하지 않는다.

## 검증

`notebook_migration_smoke._validate_unknown_design`: progress 저장/읽기/요약 × main/bak/tmp 아홉 조건, F3 capture/읽기/정리 × main/bak/tmp 아홉 조건. checksum을 다시 계산한 미지원 design fixture를 사용했다. `notebook_async_save_smoke`에는 main/bak 미지원 design의 두 실제 worker 조건을 추가했다.

- 수정 전 migration에서 덮어쓰기·복구 우회·정리 삭제·요약 오분류를 재현했다. 수정 전 host는 비동기 두 조건에서 거부/오류/메모리/파일 불변 단언 8개 실패.
- 수정 후 migration PASS(기존 save-safety 138개 포함), 재선택 366개 PASS, 기본 모드 집중 242개 PASS, host 548개 및 비동기 저장 303개 PASS. 서로 다른 검사 총수를 전체 인수율로 합산하지 않는다.
- Godot 4.7.2 격리 headless PCK. import 34.4초, export 9.3초, migration 13.9초, reselect 31.3초, 기본 집중 8.9초, host 63.8초. 종료 코드 0과 PASS 확인. SCRIPT/파싱 오류 없음. Windows 인증서 저장소 읽기 경고는 별개다.
- 비동기 검사는 단독 CLI가 없고 `--notebook-host-smoke`에 포함된다. 최초 잘못된 `--notebook-async-save-smoke` 실행은 검사되지 않은 대기 프로세스였으며 식별 후 종료했다. 그 실행을 PASS/제품 실패 근거로 계산하지 않는다.
