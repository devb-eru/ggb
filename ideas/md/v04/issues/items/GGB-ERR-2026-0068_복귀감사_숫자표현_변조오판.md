## 재현과 원인

최초 PowerShell 독립 검사가 `Second process altered completed gameplay snapshot`으로 native 1을 반환했다. 저장 전후 snapshot을 재직렬화한 문자열로 비교하여 `90`과 `90.0`을 다른 값으로 취급했다. 132좌표의 leaf 대조에서 2,296개 차이가 모두 Int64/Double 표현 차이였으며 실제 값 변경·문자열/구조 차이는 0개였다.

제품의 `StateSnapshotValidator.same_persisted_value`는 JSON이 untyped 배열의 정수를 실수로 바꾸는 경우를 이미 정확한 값 비교로 처리한다. 이번 오류는 새 증거 검사기의 오판이며 게임의 저장 값 변경으로 해석하지 않는다.

## 수정 기준

JSON 파서로 읽은 dictionary 키·array 순서/길이·문자열/Boolean/null을 재귀 비교한다. 문자열과 키는 ordinal 비교로 원문 코드 단위를 보존하며 Unicode 정규화 동등성도 허용하지 않는다. 숫자는 유한한 값의 정확한 동등성만 허용한다. int/float 교차 비교에서 절댓값 `2^53` 이상은 거부하고 근사 오차 허용이나 정수 반올림은 사용하지 않는다.

- [x] 최초 감사 native 1·실행 검사 소스·봉인 지문과 전체 숫자 차이 진단 보존.
- [x] 구조적 비교로 132좌표·9회귀를 재감사, 독립 56,660확인 PASS.
- [x] 숫자 표현 양성 및 값 변경/문자열/Boolean/null/정밀도·Unicode 원문 반례 14조건.
- [x] 기존 native·일차·관계·원문 변조 6반례 계속 거부.
- [x] develop `8298eaccd43a2f6c8ce55d36ca35a567ec4ece7d` 선택 전달·동일 tree 독립 56,660확인·464문서/87이슈·원격 SHA 일치.

제품 265개 스크립트와 최종 Godot 실행 결과는 변경하지 않는다. 첫 실패 봉인과 보완 후 봉인을 구분하여 기록한다.

## 후속 판독 보완

숫자 비교 보완 뒤 기준 native 1의 `run.result.json`을 찾으려던 감사도 중단됐다. 이 파일은 성공 child에서만 생성되는 출력이므로, 기준 실패는 실제 stdout의 단일 JSON 요약과 receipt의 native 1로 판독한다. 실패를 PASS로 바꾸거나 없는 성공 파일을 생성하지 않는다. 내장 migration의 명시적인 null 외부 harness도 제품 소스 지문으로 구분했다. 세 차례 감사 실패의 소스·receipt·봉인 지문은 `before-independent`/`before-independent2`/`before-independent3`에 구분해 보존한다.
