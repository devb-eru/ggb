## 문제

문서 06의 P2에는 대응접실에서 클릭하는 부드러운 천, 거친 솔, 물병, 스패너, 세 창, 반복하는 새와 기준 시계 예고가 정의돼 있었다. 그러나 문서 15에는 `M1_PARLOR` 절과 해당 상태별 반응이 없어 다음 구현 정보가 유실됐다.

- 도구 초회·반복·무효 사용 문구.
- 세 창의 부분 청소와 LOCAL RETRY 상태.
- NORMAL_RESET 뒤 물리 복원과 관찰 지식 유지의 경계.
- 새 관찰을 무시한 경로와 영구 관찰 기록 조건.
- P2 시계 예고에서 B3-A 탁본으로 넘어가는 우선 라우팅.
- 드래그 제거·비색상·무음 접근성 대체.

같은 원인으로 P3의 세 책과 서재 경계, P4의 차 도구, P5의 날씨 비교 대상도 canonical 부모 한 행으로만 축약돼 자식 클릭별 반응 계약이 부족했다.

## 원인

공통 오브젝트 문서와 Godot 구조가 62개 canonical `object_id`만 전수 검사했다. 한 사건 안에서만 상태를 갖는 확대 화면 부품·공간 핫스폿은 제작 인벤토리에 존재했지만, 전역 유일한 `interaction_part_id`, reaction fallback, event writer 경계가 없었다.

또한 P2 원문은 `물병`을 사용하지만 제작·CNT 인벤토리 일부가 `물대야`로 기록해 동일 소품을 서로 다른 형태로 의뢰할 위험이 있었다.

## 해결

1. 문서 15에 `M1_PARLOR` P2 상호작용 묶음을 추가했다.
2. 도구 4종, 창 3종, 반복 새, 시계 예고, 선택 ambient와 남쪽 이중문의 `interaction_part_id`를 정의했다.
3. 창 상태·오답·LOCAL RETRY·NORMAL_RESET·숏컷·D5 이후 반응을 분리했다.
4. P3·P4·P5의 자식 클릭을 같은 규칙으로 전수 상세화했다.
5. 문서 17의 `ObjectReaction`에 `interaction_part_id`, `production_id`와 part registry·resolver fallback을 추가했다.
6. 문서 04·05에 ID·위치·writer·핫스폿 배치를 동기화했다.
7. 제작 인벤토리와 CNT 의뢰에서 P2 소품을 `부드러운 천·거친 솔·작은 물병·스패너`로 통일했다.
8. B3 외부 서고 시계 canonical ID 문제는 본 오류에 섞지 않고 기존 `GGB-CNF-2026-0018`에서 계속 추적한다.
