## 원인과 영향

기준 develop `26bce2d`의 F3 capture는 `f3_reselect.json`만 미래 버전인지 확인한다. 이후 progress를 `.tmp`에 복사하고 기존 F3를 `.bak`에 복사하기 때문에, 두 보조 파일에 더 새로운 저장 형식이 있으면 해당 데이터를 덮어쓴다. 읽기에서 tmp를 채택하지 않도록 한 ERR-0036과 달리 이번 문제는 쓰기 전 보호의 누락이다.

미래 버전 파일은 현재 실행 파일이 해석하지 못하는 사용자 데이터다. 임시 파일이라는 이름만으로 삭제/덮어쓰기를 허용하지 않는다. 지원되지 않는 데이터가 있으면 호환 오류로 중단하고 모든 기존 파일을 유지한다.

## 수정과 범위

- [x] `capture_f3_reselect`의 첫 복사 전에 본파일·tmp·bak 모두 `_read_and_validate`로 검사한다.
- [x] 어느 후보든 `ERR_SAVE_FUTURE_SCHEMA`이면 기존 오류를 그대로 반환한다. 후보를 자동 변환·삭제·이름 변경하지 않는다.
- [x] 저장 헤더 schema, 대화 기록 schema, 지식 원장 schema 각각 999를 주입하고 세 파일 위치와 교차한 아홉 fixture를 검사한다.
- [x] 실패 시 progress·F3 본파일·tmp·bak 네 파일 바이트가 전부 동일한지 검사한다.
- [x] 정상 F3 capture/복사/복귀와 기존 이관·저장 안전성 검사는 유지한다.
