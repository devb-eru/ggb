## 원인과 영향

기준 develop `aef5c51`. 대상 save의 최종 승격이 실패하면 `progress.tmp.json`과 디렉터리가 남는다. 다음 가져오기는 디렉터리 존재만으로 슬롯을 제외하므로, 정상 progress가 없는데도 본편 슬롯을 점유한다. 원본 거부 검사와 달리 실제 후보 쓰기 이후 발생하는 문제다.

## 수정

- 대상이 없는지 검사한 뒤 디렉터리 생성으로 새 슬롯을 확보한다. 이미 존재하는 디렉터리는 정리 대상으로 삼지 않는다.
- 가져오기별 고유 transaction ID를 사용한다. 실패 응답이 와도 실제 확정 main의 transaction과 snapshot이 일치하면 성공 응답 유실로 복구한다.
- 실패 시 main/bak가 없고 미래 schema/미지원 design이 아닌 경우에만 미확정 후보를 정리한다. 유효한 후보의 transaction/slot이 다르면 보존한다.
- 디렉터리는 비재귀적으로 제거한다. 다른 파일·하위 디렉터리를 지우지 않는다. 정리가 불가능하면 원래 오류를 유지하고 `WARN_IMPORT_CLEANUP`, `incomplete_slot_id`를 반환한다.
- 이미 확정된 저장을 삭제하거나 demo 원본을 수정하지 않는다. 제품의 명시적 재가져오기 정책은 유지한다.

## 검증

`notebook_migration_smoke._validate_demo_target_failure`는 실제 저장의 `_promote_temporary` 경계에 `ERR_CANT_CREATE`를 주입한다.

1. 수정 전: 대상 디렉터리 해제와 후보 제거 단언 3개 실패. 격리된 테스트 슬롯에서 재현했다.
2. 수정 후: 실패 오류 유지·후보/빈 디렉터리 제거, 다른 `keep.txt` 보존과 정리 미완료 보고를 확인했다.
3. 실패 원인을 제거한 다음 정상 재시도·원 관찰 개수·원본 바이트/현재 GameState 불변을 확인했다.
4. 실제 저장 완료 후 응답만 실패하도록 바꾼 별도 manager에서 transaction/snapshot 확인을 통해 성공을 복구하고 확정 슬롯의 재읽기를 확인했다.
