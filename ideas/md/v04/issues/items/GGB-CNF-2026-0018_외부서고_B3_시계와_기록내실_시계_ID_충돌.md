## 문제

B3-A는 `M1_LIBRARY_OUTER`의 멈춘 벽시계를 중계 시계로 사용한다. 반면 공통 오브젝트 정본은 `OBJ_LIBRARY_RECORD_CLOCK`을 `M1_LIBRARY_INNER`에서 에드가의 귀환과 압박을 알리는 기록 시계로 정의한다. 기존 ART·CNT 버티컬 슬라이스 의뢰서는 외부 서고 B3 시계에도 `OBJ_LIBRARY_RECORD_CLOCK`을 연결했다.

이 상태로 제작·구현하면 다음 문제가 발생한다.

- 하나의 `object_id`가 두 location에 존재한다.
- B3 퍼즐 컨트롤러가 기록 내실 시계를 잘못 열 수 있다.
- 외부 시계의 open·rubbing·solved 상태와 내실 시계의 접근·귀환 예고 상태가 한 state pack에 섞인다.
- reset과 hotspot resolver가 어느 공간의 물리 상태를 복원할지 결정할 수 없다.
- ART·CNT 팀이 서로 다른 시계를 같은 에셋으로 제작할 수 있다.

## 과거 임시 격리

- ART r2는 외부 서고 시계를 `ART_PUZ_B3_A_PANEL`의 납품 부품 `VSART_LIB_CLOCK_HOUSING`으로 관리한다.
- `VSART_*`는 정식 runtime ID나 저장 키로 사용하지 않는다.
- `ART_OBJ_LIBRARY_RECORD_CLOCK`은 이번 ART 버티컬 슬라이스 요청에서 제외한다.
- 회색조 blockout과 형태 설계는 진행할 수 있으나 runtime export·Godot 연결은 본 이슈 해결 뒤 수행한다.

## 권장 해결안

1. `OBJ_LIBRARY_RECORD_CLOCK`은 `M1_LIBRARY_INNER`의 경계·귀환 예고 오브젝트로 유지한다.
2. 외부 서고 B3 중계 시계에 `OBJ_LIBRARY_OUTER_CLOCK`을 새로 발급한다.
3. 에셋 매니페스트에 `ART_OBJ_LIBRARY_OUTER_CLOCK`을 추가하고 B3-A의 diegetic housing 상태를 연결한다.
4. `04`, `05`, `08`, `09`, `15`, `17`에서 위치·역할·저장 수명·fallback을 동기화한다.
5. ART·CNT 의뢰서와 request register가 새 ID를 참조하도록 갱신한다.
6. 정적 검사에서 동일 canonical `object_id`의 복수 기본 location을 차단한다.
