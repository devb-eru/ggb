## 문제

`project.godot`에는 `[input]` 섹션과 1920×1080 기준 viewport 크기가 없고, main scene에는 키보드 포커스와 방·메타 UI 내비게이션의 최소 노드가 없다. stretch 방식만 기록돼 있어 1280×720, Windows 배율 200%, 키보드 전용 진행을 검사할 출발점이 없다.

연습 씬의 `Button.pressed` 연결은 개별 버튼 클릭을 보수한 것이며 production 입력 계약을 대신하지 않는다. 현재 상태에서는 다음 문제가 예상된다.

- 마우스와 키보드가 동일한 confirm·cancel·조사 동작을 공유하지 않는다.
- 화면 크기와 DPI에 따라 포커스 표시·팝업·하단 텍스트가 잘릴 수 있다.
- `Alt+Tab` 복귀 입력이나 포커스 상실 중 입력이 미확정 선택으로 전달될 수 있다.

## 권장 해결안

1. `interact_confirm`, `ui_cancel`, `notebook_toggle`, `inventory_toggle`, `focus_next`, `focus_previous` 등 1.0 필수 action을 InputMap에 등록한다.
2. 마우스 클릭과 키보드 confirm이 하나의 `InputRouter → InteractionRouter` 경로로 합류하게 한다.
3. 1920×1080 기준 viewport와 1280×720 최소 레이아웃을 프로젝트 설정과 root UI에 명시한다.
4. 포커스 ring, 팝업 복귀 object ID, 포커스 상실 입력 정지를 최소 UI fixture로 만든다.
5. 100%, 150%, 200% Windows 배율과 UI 200% 조합을 자동 스크린샷·수동 키보드 경로로 검증한다.

## 완료 조건

- [ ] 모든 필수 동작에 마우스·키보드 입력이 있다.
- [ ] 한 번의 confirm이 한 대상과 한 사건 요청만 소비한다.
- [ ] 1280×720·UI 200%에서 확인·취소·핵심 텍스트가 보인다.
- [ ] 포커스 상실과 복귀 입력이 선택을 확정하지 않는다.
- [ ] 키보드만으로 최소 사건 fixture를 완료한다.
