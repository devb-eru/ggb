# GGB-ERR-2026-0069: 지하 통합 검사의 수첩 준비 완료 대기 누락

| 항목 | 값 |
| --- | --- |
| 유형 | 오류 ERR |
| 심각도 | 중간 |
| 해결 상태 | OPEN |
| 작업 상태 | READY |
| 우선순위 | P2 |
| 담당자 | Codex |
| 목표 마일스톤 | `FULL_00_CONTENT_COMPLETE` |
| 최초 확인 | 2026-10-11 |
| 영역 | BasementSessionSmoke / 통합 수첩 준비·닫기 / 후속 UI 검사 |

## 확인된 내용

기상 출처 후보를 대상으로 추가 실행한 개발 수첩 지하 통합 검사는 native 1, 13,543개 실행 단언 중 실패 목록 38개를 반환했다. 메뉴의 대화 탭·최신 원문, 관계 선택창의 기록·미룸, 현실 필드 수첩 이동과 엔딩 후 기록 열람이 포함된다. 필드 수첩 검사는 아직 없는 `EXIT_STATUS_POWER` 버튼을 읽어 null 객체의 `pressed` 스크립트 오류를 발생시켰다. 실행 단언 수는 완전한 통과 분모가 아니다.

검사기의 `_history_text()`는 수첩을 연 직후 모델·탭을 읽으며, `_close_history()`는 `request_close()` 뒤 완료 대기 없이 다음 모달을 조작한다. 비동기 준비 또는 닫기 중 `_notebook_is_open()`이 유지되면 실제 선택 기록의 live guard가 후속 선택을 거부할 수 있다. `_validate_field_notebook()` 역시 화면 전환 후 버튼 존재·완료를 확인하지 않고 다음 버튼을 직접 읽는다. 이는 코드상 확인된 검사 경계 누락이며, 38개 증상 전체가 이 원인 하나로 해결된다고 아직 단정하지 않는다.

같은 PC·엔진의 수정 전 `b4db188` 기준본도 native 1/13,543개 실행 단언으로 끝났으며 실패 38개의 순서·문구가 후보와 모두 같다. 기준본의 최종 결과와 후보의 실패 목록은 [기상 출처 검증](../validation/2026-10-11_기상출처_침실정본화_검증.md)에 보존·대조한다. 이 문제는 새 기상 출처 수정의 합격이나 이전 소스의 지하 PASS로 덮어쓰지 않는다.

## 권장 조치

1. 수첩 열기·모델 준비·닫기·대사 커서 내구 저장의 실제 완료 조건을 제한 시간 안에서 기다리는 공통 검사 helper를 사용한다. 단순 고정 프레임 추가나 강제 모드 OFF로 해결하지 않는다.
2. 다음 모달을 열기 전에 원래 호출 메뉴로 복귀했는지와 수첩이 닫혔는지 확인한다. 실패하면 해당 단계에서 명확히 중단하고 null 버튼의 후속 오류로 전파하지 않는다.
3. 실제 관계 옵션·취소 원문, 상태 불변·stale callback 거부, 필드 필수 읽기/물리 출구 조건 등 기존 의미 단언은 유지한다. 준비 완료 뒤에도 실패하는 항목은 제품 오류로 별도 분리한다.
4. 같은 고정 제품 소스의 기본/개발 수첩 모드와 한영 지하 전체를 재실행한다. 실행 모드·소스·검사기·native 종료·실패 목록을 영수증에 기록하고 독립 검증한다.

ERR-0052는 과거 특정 읽기/재검토 경로의 닫기 대기를 해결한 근거로 유지한다. 이 항목은 이후 공통 비동기 흐름에서 남은 메뉴·후속 모달·필드 전환 경계를 추적한다. 아직 제품 입력 오류의 해결이나 전체 지하 회귀 성공으로 표시하지 않는다.
