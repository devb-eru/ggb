## 확인 사실

`chapter_one_smoke.gd::_validate_view`에서 번역 뒤 거절·J2 대화, 시계·J1·메뉴 복귀의 기록 개수/비기록 상태 불변 등 8개 단언이 실패했다. 이번 드래그 안내 수정 전 controller로 대조해도 같은 8실패, native 1이다. 이번 수정으로 생긴 회귀라고 단정하지 않는다.

검사 실행은 `--headless --chapter-one-smoke --ggb-dev-full --ggb-dev-notebook-v2`이며 OS 입력 검사가 아니다. `--notebook-require-authored`는 이 정식 대조에 사용하지 않았다. 원본과 후보는 같은 나머지 소스·검사·데이터를 사용하고 공통 prologue controller만 다르게 했다.

## 대처

- [x] 수정 전/후의 동일 8실패와 종료 코드 보존.
- [ ] 최신 작성 시트의 실제 안내→선택·번역 재표시와 구형 fixture 가정을 분리한다.
- [ ] 실패 지점에서 snapshot의 정확한 변경 필드·공개된 행 ID와 저장 상태를 채집한다.

- [ ] 독립 재현·해결 후 동일 headless 회귀를 다시 통과시킨다.

현재는 제품 오류인지 검사 가정 오류인지 미확정이다. 전체 1장 회귀 PASS나 전체 인수 완료로 기록하지 않는다. 관련 원자료와 실행 경위는 [검증 기록](../validation/2026-11-05_마우스검사제외_및_드래그안내_검증.md)을 따른다.

## 읽기 전용 후속 진단

두 실행 모두 8실패 뒤 `chapter_one_smoke.gd:371`의 `null.text` 접근 오류가 있다. 통합 수첩을 연 뒤 구형 `_modal_body/HistoryTranscript`를 읽기 때문이다. 프로세스가 종료됐다는 receipt의 `completed`를 이 함수 이후 모든 검사가 수행됐다는 뜻으로 사용하지 않는다.

`_expect_only_history_added()`가 history만 제외하고 전체 snapshot을 비교하지만, 최신 표면 기록은 영수증을, 모달 열기·닫기는 재개 커서를 함께 저장한다. 같은 fixture에서 실제 stage와 다른 J1·J2·시계 표면을 직접 빌드해 미처리 batch가 누적되는 경로도 확인했다. 따라서 기록 +1/+3 기대는 독립 표면 flush와 실제 변경 필드 확인 없이 채택하지 않는다. 이 진단만으로 실제 중복 공개 가능성을 배제하지도 않는다.

권장 수정은 fixture별 기준점·flush 분리, 허용된 영수증/완료 커서의 좁은 검증과 통합 수첩 조회 경로 적용이다. 신규 관찰의 content/node/locale/token 및 정확한 snapshot changed_paths를 먼저 확보한다. `event_local_states` 전체를 제외하거나 원래 시트를 바꿀 근거는 없다.
