## 문제

문서 15에서 공통 오브젝트를 상세화하면서 신규 ID와 first·repeat 수명 주기가 생겼지만, 이벤트 레지스트리·공간 지도·Godot 데이터에는 동일 계약이 없었다.

- 구현자가 문서 15의 문구에서 임의 ID를 만들 가능성이 있었다.
- 같은 사물이 문서마다 다른 위치·역할로 생성될 수 있었다.
- 첫 조사 이력을 NORMAL_RESET에서 지울지 영구 보존할지 저장 기준이 없었다.
- 엔딩 required·optional 조사와 일반 first·repeat 이력이 섞일 수 있었다.
- AMBIENT 반응이 관계·퍼즐·최종 선택을 잘못 쓸 가능성이 있었다.
- 사용인 신체 오브젝트의 동의·이동 위치 계약이 데이터에 없었다.

## 채택 해결안

일반 오브젝트 57개와 사용인 신체 오브젝트 5개를 canonical 대상으로 등록하고 책임을 분리한다.

```text
04: ID·role·허용 쓰기
05: location·hotspot
15: 반응 문구·감각
16: 접근성 표시
17: Resource·resolver·save·migration
```

핵심 데이터:

```yaml
object_reaction_memory:
  persistent_seen: []
  per_state_seen: []
object_reaction_runtime:
  loop_counts: {}
  last_reaction_by_object: {}
  pending_reaction_id: null
```

- `interaction_role` 8종을 정의한다.
- selector 순서는 event context, object state, world phase, knowledge, owner overlay, visit state, fallback이다.
- NORMAL_RESET은 loop 상태만 지우고, POST_BROKEN_REST는 현재 상태를 유지한다.
- 엔딩 Set은 일반 반응 이력과 분리한다.
- `bond`, `alert`, 핵심 완료, 기록 획득, `final_decision`, `puzzle_result`를 공통 금지 쓰기로 둔다.
- 저장 스키마를 12로 올리고 v11 이하 변환 규칙을 정의한다.

## 회귀 방지 규칙

1. canonical ID 추가·삭제는 문서 04·05·15·17을 같은 변경 단위로 갱신한다.
2. 반응 리소스가 registry에 없는 object_id·location_id를 참조하면 빌드 검사를 실패시킨다.
3. 일반 first·repeat 이력과 엔딩 required·optional Set을 합치지 않는다.
4. servant object는 `owner_id`와 `requires_consent=true`를 반드시 가진다.
5. schema 12 이전 세이브에서 불명확한 first 반응은 재생할 수 있지만 진행 보상을 다시 적용하지 않는다.
