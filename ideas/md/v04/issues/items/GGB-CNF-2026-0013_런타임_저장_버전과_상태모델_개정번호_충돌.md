## 문제

제품 계약은 첫 배포 저장을 `schema_version=1`, 기획 상태 모델을 `design_revision=v0.4-state-r12`로 분리한다. 그러나 활성 v0.4 문서에는 `schema 9~12 migration`, `from_schema: 10`, `to_schema: 12` 예시가 남아 실제 출시 전에 존재하지 않은 런타임 형식 열두 개를 구현하도록 오해할 수 있었다.

## 채택 해결안

- 최초 배포 런타임 저장은 schema 1만 사용한다.
- r12는 상태 모델 개정 번호로만 기록한다.
- migration 파이프라인과 `1→2` 로그 예시는 실제 schema 2가 배포될 때부터 적용한다.
- 첫 배포 QA는 schema 1 저장·로드, backup 복구와 profile v1 fixture를 검사한다.
- 과거 이슈의 schema 12 문구는 당시 기록으로 보존하되 상위 결정의 대체 주석을 둔다.

## 회귀 방지 규칙

1. `schema_version`과 `design_revision`을 같은 표나 숫자 축으로 합치지 않는다.
2. 배포되지 않은 runtime schema의 migrator를 완료 조건으로 요구하지 않는다.
3. 첫 출시 전 `from_schema` 값이 1보다 큰 fixture를 현재 계약으로 추가하지 않는다.
