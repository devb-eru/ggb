## 문제와 재현

archive는 정수 값인 `content_version: 1`과 JSON 숫자 표현 `1.0`을 모두 정상 버전으로 허용한다. 그러나 기존 배열의 Dictionary 비교는 두 참조를 다른 값으로 볼 수 있었다. 동일 출처·관찰 UID·종류·segment·내용 버전의 출처 링크를 숫자 표현만 달리해 추가하면 중복 검사에서 통과했다.

기준 develop `6505b3f`에 새 검사만 추가한 변경 전 PCK에서 `equivalent reference is still a duplicate: numeric`이 실패했다. 이는 archive API 수준에서 재현한 동일성 오류이며 실제 사용자 세이브 손실을 재현했다는 뜻이 아니다. 저장/로드 단계의 숫자 정규화가 이후 중복을 드러내 후보를 거부할 수 있으므로, 후보 생성과 검증 단계부터 같은 의미의 참조를 일관되게 처리해야 한다.

## 수정 방향

- 참조 식별은 종류·출처 계통·UID·정수 의미의 내용 버전·공개 segment로 구성한다. Dictionary 키 순서는 무관하며 소수·bool·문자열·비유한 값·정확성 범위 밖의 실수 버전을 유효 버전으로 바꾸지 않는다. 기존 정수형 버전의 허용 범위를 새로 축소하지 않는다.
- 책갈피/비교 참조의 추가·해제·재시도와 출처 링크의 중복 병합에 같은 식별 규칙을 적용한다. 다른 소비자, UID, 버전, segment는 합치지 않는다.
- 지식 revision의 출처 중복·소유 관찰·보호 링크 대조 및 획득 재시도도 같은 규칙을 사용한다.
- 잘못된 중복 archive를 읽기 과정에서 조용히 수정하지 않는다. 오류를 반환하고 기존 저장 복구 계약을 유지한다. 저장 schema와 기존 조회/sidecar 키 형식은 바꾸지 않는다.

## 검증 결과

- 정수/실수와 키 순서만 다른 참조: 각각 단독으로는 유효, 같은 모음에 중복 저장하면 거부.
- pin 추가 재시도는 revision 불변, JSON 재로드 후 해제는 정확히 해당 참조만 제거.
- 한 트랜잭션의 같은 출처는 한 번만 보호, 다른 소비자는 별도 보호, 동일 획득 재시도는 새 관찰·revision을 생성하지 않음.
- `resolve_many`의 반환 복사본을 수정해도 다른 결과나 원본 archive가 바뀌지 않음.
- 실제 카탈로그의 600개 개정 기록, 601개 관찰, 1,285개 출처 링크 및 15종 손상 그래프의 검증·불변성.
- 조회, 이관/저장 복구, J4 다중 segment, 한영 대사와 저장 재개 회귀.

위 항목 모두 수정 후 PCK에서 PASS했다. `NOTEBOOK_ARCHIVE_SMOKE`는 변경 전 실패했던 숫자 중복을 거부하고, 참조 명령·반환 소유권 검사를 통과했다. `NOTEBOOK_KNOWLEDGE_SMOKE`는 고정 그래프와 15종 변조 및 획득 재시도를 통과했다. migration의 저장 안전성 46개, query 주 검사 1,411개와 하위 검사, host 301개, J4 문서 140경우, 세 종류 표시 커서의 새 프로세스 seed/resume/completed 및 기존 모드 foundation/history도 통과했다. 패키지 해시·명령·시간·미검증 범위는 연결한 실행 근거에 구분했다.

성능 개선은 [ERR-0027](GGB-ERR-2026-0027_대용량_수첩_표시검색저장_지연.md)과 별개로 추적한다. 이 이슈 해결만으로 실제 Windows 입력·IME·성능 인수나 전체 계획을 완료하지 않는다.
