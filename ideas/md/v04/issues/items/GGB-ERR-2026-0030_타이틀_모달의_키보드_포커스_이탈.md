## 재현과 원인

기준 develop `e5d5407`의 격리된 새 프로필에서 새 게임을 열고 첫 실행 설정창의 글자 크기에 포커스가 있을 때 `Shift+Tab`을 누른다. 설정창 뒤쪽의 데모 저장 가져오기 버튼으로 포커스가 이동한다. 실제 Windows 입력과 화면의 포커스 테두리로 확인했다. 배경 버튼을 실행하지 않았으므로 세이브 가져오기나 손실이 발생했다고 주장하지 않는다.

`_open_modal()`은 모달 표시와 초기 포커스만 지정했다. 배경 메뉴가 키보드 탐색에 남아 있었고, 정적 모달의 Tab 순환도 닫혀 있지 않았다. `set_input_suspended(false)` 또한 모달 여부와 무관하게 전체 버튼을 다시 활성화했다.

## 수정

- 활성 모달의 자손만 마우스·키보드 입력 대상이 되도록 범위를 갱신한다. 숨겨진 모달과 배경 메뉴는 포커스를 받지 않는다.
- 보이는 활성 컨트롤의 트리 순서로 Tab·Shift+Tab 순환을 구성한다. 갤러리 표시·페이지 변경 및 가져오기 표시 시 갱신한다.
- 키 설정과 화면 미리보기 패널의 자체 동적 순환은 유지한다.
- 일시 중단 전 포커스를 복구하되 숨김·비활성 버튼은 제외한다. 모달을 닫으면 기존 메뉴 입력을 복원한다.
- 갤러리의 스크롤 읽기 영역도 입력 범위에 포함한다. 씬 파일·저장 schema·퍼즐 규칙은 변경하지 않는다.

## 검증

- 실제 Windows: 글자 크기 → `Shift+Tab` → 설정 적용, `Tab` → 글자 크기 순환. 드롭다운 Enter/Escape 정상. 키보드만으로 빈 슬롯 새 게임 진입.
- 엔진 입력 회귀: 첫 실행 경계, 열 종류 모달의 Tab/Shift+Tab, 배경 제외, 중단·복귀, 닫기 후 복원. 기존 키 재지정·화면 미리보기·갤러리 페이지 이동·가져오기 검사 포함 `START_SCREEN_SMOKE: PASS`.
- foundation/history의 v2·기존 모드 및 수첩 host 301개 회귀 PASS.

전체 캠페인 실제 입력·IME·장비별 DPI 인수를 완료한 것은 아니다. 별도 발견인 [ERR-0031](GGB-ERR-2026-0031_개발자버튼이_수첩닫기를_가림.md)은 이 수정으로 해결되지 않는다.
